# 区分待服务请求与已完成动作，只把实到事件写回

[[研究前沿/面向决策的履约建模/01-论文原文与精读/ICUScenario/精读|共用服务队列里，何时把一次行动写回个体历史]]

## 输入、输出与运行时点

个体轨迹历史、待执行请求、共享容量和事件日历 → 下一次状态输入、排队负担与终态。

生成请求后交给公共队列排序。若需服务确认，只在任务完成时按实际时间回写；终态清理排队项。用同一冻结状态模型分别运行闭环写回和固定轨迹回放，区分生成轨迹和排队执行对输出的影响。 [原文中的定义或流程](https://arxiv.org/html/2611.08392v1#Sx4.SSx9)
