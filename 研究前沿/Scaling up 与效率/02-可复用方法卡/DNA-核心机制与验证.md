# DNA｜每层都更新用户长历史，怎样跟多候选共享算力？

来源：[[研究前沿/Scaling up 与效率/01-论文原文与精读/DNA/精读|原文精读]]

## 输入、输出与最小采用流程

每层候选 token 单独读共享行为 S；请求 token U 读 S 后再由 S 读 U 完成候选无关的深层更新（式12）。同一请求可共用更新后的长历史，不跨请求复用，保持候选读独立。
