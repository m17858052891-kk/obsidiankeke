# 检索与归档规则

## 目标与调度

每日 11:00，Asia/Shanghai。任务服务模型迭代与前沿方法感知，三个方向分别检索，按论文与创新模块的价值和证据归档。每个方向 README 中的关键词和查询是可维护的检索配置；修改范围时同步更新方向入口和定时任务。

## 检索策略

- 每个方向分别执行“直接相关”和“跨领域方法”两条检索路线。逐条短查询，不把所有关键词强制 AND；同义词可以分批 OR，中文和英文均检索。
- 优先近期论文、会议研究、研究团队/企业公开技术文章、开源代码及数据集发布。重点查 arXiv、OpenReview、会议/出版社网站、作者主页、官方研究博客、官方仓库；OpenAlex、Crossref、DBLP、Semantic Scholar 可作发现和元数据交叉核验。
- 不强制限定网约车、已有业务模型、当前数据、已上线或独立可插拔模块。原领域可信效果、明确机制和合理的模块相关性均可构成研究价值。通用领域新方法须说明与该方向的具体联系。
- 按新颖性、问题价值、证据质量、解释清晰度、潜在复用价值选取，不以引用数、机构名或当前接入成本作为单一门槛。
- 理论、公开基准、受控对照、组件消融、整体系统和线上实验分别标注。系统收益不得归到未经单独检验的模块。理论工作可入库，但不宣称已经验证业务效果。
- 三个方向先完成候选发现，再做精读，避免一个方向挤占其他方向。取消每日总篇数及每方向篇数上限；按创新价值、机制清晰度和可信效果证据决定精读数量，不凑数。每天先检查已有待精读队列，与新候选按价值、证据及等待时间共同排序，持续处理旧队列。只因原文不可访问、证据待核实或执行实际中断等具体原因保留待处理，并记录下一步；不因达到篇数或固定阅读预算而入队。理论与有价值的负面结论同样可收录。
- 脚本或 API 不可用时使用可用网页检索并回到一手来源核验。记录哪些来源失败，不能把检索失败当成没有论文。

## 时间与去重

- 每个新方向首次检索最近 90 天，后续滚动 7 天并优先最近 24 小时。中断时补查上次成功扫描以来的遗漏。
- 历史重要论文可作为背景或补充，明确写原始日期，不冒充新消息。首次提交、版本修订、会议发表和检索时间分别记录。
- 用 arXiv ID、DOI、规范标题、仓库 URL 去重；旧文新版本先比较实质差异。一个方向的失败不阻止其他方向完成。
- 全局运行记录位于 `研究前沿/_运行记录/state.json`。区分发现、核验、待精读、已归档、已播报，不用单一状态混同。已有 2026-11-04 uplift 播报记录已迁入，待补精读的记录仍应处理。
- 先检查全库现有笔记和附件。已有精读通过索引复用，不移动或覆盖已有手写内容。

## 三类归档

### 论文原文与精读

每篇新论文在所属方向的 01 目录内建立独立论文目录，放精读正文及 assets/source、assets 下的原文和图表。可访问的 PDF/HTML 尽量保存，至少保留已核验官方链接；下载失败时标记“仅链接已核验”，不得声称已经本地保存原文。

精读优先覆盖问题、核心流程、重要模块、关键公式/图表、主实验、模块证据和边界；明确阅读深度与未覆盖部分。仅读摘要的记录标“摘要级筛选”，不得称完整精读。已有完整精读继续复用其覆盖清单。

### 可复用方法卡

精选论文提取有研究价值、能解释其方法链条的模块，不设每篇方法卡数量上下限，依论文实际内容和证据决定。模块可以是表示、网络结构、损失、训练步骤、数据融合、校准、优化器、求解器、评估方法或工程机制。耦合模块保留共同训练/共同接入依赖，不能为了拆卡虚构独立有效性。

每张卡写明输入输出、机制、关键公式或伪代码、训练与推理时点、原领域效果及来源定位、代码入口（核验不到则写未知）、适用条件、潜在迁移方向。将“原论文事实”“迁移推断”“本地验证”分开。与当前项目不匹配但有研究价值的卡照常归档。

### 实验假设与结果

有具体可检验想法时建立候选假设，标记“待设计/未运行”；没有合适假设时不凑实验。实验字段包含来源模块、假设、最小改动、必要数据、基线、主指标、约束、预算和失败判据；未确认内容用待确认。

当前定时任务负责检索、精读、归档和候选假设，不自动训练模型、不启动 GPU 任务、不改变生产代码。真实结果必须关联运行时间、数据划分、配置、代码版本和日志。论文效果不得填成本地结果。重复实验需要固定评价，避免测试集泄漏，并保留失败和不确定结论。

## 维护规则

- 采用库内已有 type/topics/status/aliases 属性；status 表示笔记维护状态，实验是否运行使用 experiment_status 等独立字段。
- 论文、方法、实验各用稳定 ID，并互相链接。索引由原笔记/方法卡生成，不维护第二份独立方法事实库。
- 跨目录 Obsidian 链接使用相对库根的完整路径。新增笔记必须进入所属类型索引；附件存该笔记的 assets。
- 更新已有内容时保留用户手写注释和历史结论，追加新证据及版本变化，使用可回读的原子写入并检查链接、附件与公式。
- 公开检索只使用公共关键词，不把库内业务文档、实验数字、内部链接或代码原文发送给外部检索服务。
- 写入失败时不要记录为已归档；保留待写入状态并说明具体问题。无重要新增只更新运行记录；有新增在当前聊天按方向给出中文摘要和 Obsidian 位置。旧队列补完可以报告新增精读成果，但不得冒充新发表论文。

## 每日怎样更新读者导航

三个方向的 README 依次放入门材料、长期研究问题和检索配置。关键词和查询仍按原有标题读取。新的研究结论可以补充到明确相关的路线，说明适用前提和证据；每天的篇数、检索说明和增量明细进入当天运行记录。

- 每个方向有精读、方法、实验三份完整索引。只在分类 README 的 `<!-- 自动索引开始 -->` 与 `<!-- 自动索引结束 -->` 之间，按该页已有问题分组补入新条目、更新已有条目的标题或状态。按目标路径去重，核对所属目录全部正文都能从该区到达。跨方向与库内其他目录的复用、手写判断和旧资料链接在标记外另行保留。
- 历史目录见 [[研究前沿/_运行记录/README|历次检索与精读]]。报告写入、正文与附件核验后，在“批次目录”两端标记之间按日期倒序更新；同一报告只出现一行，候选核验附在对应批次。将“最近一期”的标记区更新为最近一次已完成的批次链接。补录旧批次时按报告日期排序。总览直接显示历史页的“最近一期”，日期明细只在历史目录维护。
- 遇到扫描中断，保留上次完整批次的入口，对待核材料继续使用待处理队列。读者个人的勾选独立处理，即使这次检索没有重要新增也照常读取。

## 我的近期先读

[[研究前沿/00-总览#我的近期先读|当前三个位置]] · [[研究前沿/_运行记录/我的已读|已读与备注]]

每天 11:00 的既有日报读取总览中已保存的勾选。未勾的条目与随手写的文字保留原位；已勾的条目先连同备注、精读链接、版本及上海日期记入“我的已读”，再在腾出的位置补一篇。当日材料照常入库，首页最多展示三篇。用户若在备注里明确写了想看什么，可据此调整后备顺序。勾选本身只表示读完，未勾表示继续保留。

1. 日报开头运行 `python3 "/Users/didi/keke/keke/研究前沿/_运行记录/工具/近期先读.py" --archive-only`，先归档、腾位。没有新增也要执行；遇到中断仍优先处理本地已保存的勾选。命令按论文的稳定 ID 和已读版本去重。写入失败保留现场，修复或重试后再报告。
2. 合格后备存入 `_运行记录/近期先读候选.json`，按编辑推荐顺序排列。每条的 `id`、`version`、`canonical_note` 按已核实的 `state.json` 登记；`question` 写读者的问题，`reason` 写值得读的理由，`evidence` 写原研究的证据和适用条件。优先选能改变一个判断、比较两种做法或解释失效条件的材料。可按阅读价值补充后备。校验 JSON 后再替换文件。
3. 扫描结束后若有值得推荐的新材料，先完成精读、核验并登记，然后更新后备池。无论本次检索有无新增，结束时运行 `python3 "/Users/didi/keke/keke/研究前沿/_运行记录/工具/近期先读.py"` 填补空位。已有未读不被新候选挤走；缺少合格后备时允许空位。已读论文再次修订只有在出现实质变化、确有重读价值时，才用新版本及 `revision_note` 说明变化。
4. 总览三个位置、记录元数据和“我的已读”由同一工具合并写入。日报其他步骤不重写总览或已读页。检查可运行相同命令并加 `--dry-run`。关闭、重跑、同日补录都不应重复入档；个人反馈与业务文字仅在本地使用。

### 用最近七天的研究聊天选下一篇

每天 11 点按上海时间回看运行时刻往前七天内的 Codex 聊天。用聊天历史工具分别列出活跃与已归档的聊天，按更新时间翻页查到窗口起点，再打开相关研究对话，按实际发言时间读取窗口内用户提出的问题。标题和摘要用于定位。用户希望继续追的问题、反复提到的具体难点，以及对对照实验的要求，都可以帮助选文。日报自己的推荐、助手举的例子和勾选状态不计作用户兴趣，单次验收问题按其原意理解。

在已完成精读并核实证据的候选里，优先选能回答近期问题、检验某个收益解释，或与已读材料构成清晰对照的论文。明确写下的阅读意愿优先于从聊天推断的兴趣。把优先候选移到可补位条目的前面，在它的 `reason` 里写清最近关心的问题，以及论文中哪个比较能帮助判断；`evidence` 保留论文的验证范围。填位前每天重新判断。找不到可靠关联或历史访问受限时，照常按研究价值补位，访问缺口记入当期运行记录。

聊天只供本地选文使用。候选理由和批次记录只写可公开表述的研究问题与方法，不复制聊天原文、身份、内部项目细节或聊天链接。公开检索继续使用三个方向的公共关键词。
