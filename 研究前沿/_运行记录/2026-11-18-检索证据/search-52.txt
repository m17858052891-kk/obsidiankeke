## Compute-Optimal Models​

A compute-optimal model is a model configuration that achieves the lowest possible training or validation loss for a given computational budget.

The important phrase is for a given computational budget.

There is no single model size or dataset size that is optimal for every training run. The optimal configuration changes depending on how much computation is available.

For a small compute budget, a relatively small model trained on a limited amount of data may be the best choice. For a larger compute budget, both the model size and the training dataset can be increased.

The objective is not to build the largest possible model. It is to obtain the best possible model performance from the available computation.

### Understanding the Optimization Problem​

Suppose we want to train a language model with the lowest possible validation loss.

We can represent the objective conceptually as:
    
    `
    
    Minimize: Model Loss
    
    Subject to: Training Compute ≤ Available Compute Budget

Because of the potential tension between making a good set recommendation and asking an informative choice query, we explore the connection between the two. # Scaling Laws

## Definition

> Scaling Law
> 
> A scaling law is the empirical regularity that model quality (e.g. loss, accuracy) improves predictably and monotonically as you increase three resources — data, compute (FLOPs), and parameters — with no early plateau. For LLMs this is the central reason “bigger = reliably better.” Classical recommenders historically did not exhibit this: past a point, enlarging them barely helped. The thesis of modern Generative Recommendation (and especially LRMs) is that recommendation can be made to follow a scaling law — by reframing the stream of user actions as a token stream and using architectures (notably HSTU) built for very long histories.

## Intuition

> Why recommenders used to plateau
> 
> A classical discriminative recommender learns a scoring function f(user,item) over a fixed candidate pool. Stacking more layers or features gives diminishing returns: the supervision signal (a single clicked item per example) and the fixed output space cap how much extra capacity can help. --------------------------------------------------------------------------------

  * Problem: pointwise conversion-rate (CVR) prediction (binary classification) in large-scale ad ranking; training loss is BCE over observed conversions.
