# 方法名称与所解决的问题

## 价值与适用问题

先用两三句写明什么时候值得用、需要的输入、会改变哪个输出。说明原作者给了整套系统对照还是单独检验了这一模块，并链接一条可与它比较的路线或方法。

## 结构化属性

- module_id：稳定 ID，建议 paper_id + 模块名
- source_papers / versions / source_locations：原论文与节/公式/表/代码入口
- problem / mechanism / input / output：问题、机制与接口
- evidence_types：理论 / 组件消融 / 整体离线 / 线上 / 作者描述
- treatment_type：如适用，二元/多值/连续/组合/序贯
- minimum_adoptable_unit / dependencies：最小采用单元与耦合依赖
- data_requirements / assumptions：数据与假设
- potential_applications：潜在迭代方向，允许跨领域
- local_validation：未验证；后续链接真实实验

## 具体怎么做

用有因果顺序的步骤解释计算过程、优化目标，以及训练和推理时点；给必要公式/伪代码与原文定位。

## 原论文的效果证据

明确模块是否被独立检验。未独立消融时写“仅有整套系统结果”，不可把整体收益全部归因于此模块。

## 迁移推断与限制

将原领域事实和本地推断分开。未知代码、接口、延迟、数据写待确认。
