# KnowFeat：自动生成特征时，哪些门控必须由执行器实际检验？

[[模型反馈与特征发现/论文笔记/KnowFeat|来源精读]]

## 接口与计算

- 输入：结构化知识、允许使用的字段/算子与训练/验证数据。
- 输出：候选特征、可追溯卡片、实际验证结果及失败反馈。
- 流程：知识以模式、规则、指标、专家等结构资产进入 Agent；每个候选登记代码、输入列、推理来源，经过执行、统计质量、模型效用三级验证。失败记忆反馈生成器，另对部分单独无增益候选做前向组合；搜索预算按语义维度调整。
- 训练/推理依赖：控制器执行门控而非仅接受 Agent 自述；最终测试窗口永不进入搜索反馈。


候选 → 注册代码/来源 → L1 执行 → L2 统计 → L3 独立模型效用 → 接受或反馈。

## 最小采用单元及耦合

先复用注册—执行—反馈和冻结测试边界；不硬搬原 IV/KS 阈值。

L2 单变量筛选可能漏掉组合有效特征，噪声百分位不是自适应多次搜索的 FDR 保证。L3 文字的 train-test 搜索切分和最终 frozen test 要分清，来源可追溯不等于事实正确。
