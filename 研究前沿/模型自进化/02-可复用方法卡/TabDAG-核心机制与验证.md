# TabDAG｜怎样约束自动造特征，减少无效试验和时点泄漏？

来源：[[研究前沿/模型自进化/01-论文原文与精读/TabDAG/精读|原文精读]]

## 输入、输出与最小采用流程

用有类型 DAG 约束特征构造。输入允许使用的字段、时点及算子清单；提议器提交局部 JSON diff，结构、时点及可执行校验通过才计入评估，输出可复跑的变换图。

## 原文效果与依赖

§5、附录 F 表 11：固定 LLM、引擎和 100 次已评估候选预算，失败率局部 DAG 20.1%，自由 Python 27.9%，整图 JSON 27.1%；4,549 个提议有 1,558 个提前过滤。 定位：§5、附录 F 表 11。测试排名差异经多重比较不显著；实验按已评估候选对齐，无法证明节约总成本或提高预测。

## 首个验证

预分单履约预估的自动特征搜索。固定学习器、算子、LLM、特征时点、总预算与时间外测试；比较自由脚本和带时间/拟合范围校验的 DAG，计入早期拒绝、训练失败及有效改动。 失败判据：若失败只是前移，或每 GPU 小时有效试验没有改善，或未来段 LogLoss、校准退化，不采纳。
