核查日期：2026 年 11 月 7 日（Asia/Shanghai）。本库服务于“遇到问题时怎样选工具、怎样验收、失败后怎样换路”，优先展开目标定义、方法研究、数据监督、训练诊断和实验判断。模型架构、数据规模、训练平台、业务阈值均未知，因此所有接入建议都是条件化方案。

优先选择：复用已有问题拆解与论文检索 Skill，用 SQL 或数据契约程序核查数据，用现有训练框架产生预测、梯度和性能证据，用现有实验平台记录结果。LLM 适合整理竞争假设、检索代码、生成受约束的分析脚本和解释结果；数值计算、权限边界、统计检验和上线决策需要程序或人承担。不要先搭一个全自动科学家，再寻找它能解决的问题。

当前最有价值的试点是一个离线证据包：固定样本、成熟标签、两版预测、配置与日志，通过数据检查和切片复现一宗已知问题。只有它提高结论正确性或减少有效实验成本，才值得接 MCP 和自动编排。多数重点工具本次达到“已检查源码或技能文件”；没有任何工具在你的目标业务上得到效果验证。

## 阅读与证据规则

本库依次提供问题能力地图、环境盘点、问题分类工具卡、条件组合、三个端到端流程、最小验证计划和排除记录。工具卡的示例是核实过接口的待试方案，不代表本次已执行；出现示例数据、阈值或预算时均不代表你的实际业务。

| 层级 | 本库采用的含义 | 不能据此推断 |
|---|---|---|
| V0 仅发现线索 | 搜索或目录出现名称 | 工具存在完整实现、可运行 |
| V1 已读官方文档 | 打开维护者文档或官方 README | 接口与文档完全一致 |
| V2 已检查代码或技能文件 | 读过实际接口、脚本、SKILL.md 或关键源码 | 依赖可在你的环境安装、业务有效 |
| V3 已运行最小示例 | 明确记录输入、运行范围、结果 | 完整系统可靠、生产规模可用 |
| V4 已验证目标业务场景 | 在你的数据或真实工作流上完成该项能力验收，结果可为有效或无效 | 自动推广到其他模型、周期、人群 |

本次 V3 的范围很窄：GitHub 连接器成功读取公开仓库；本机技能检索 CLI 完成查询；一个外部 Skill 的纯函数被离线探测。它们均不构成模型迭代业务验证。没有安装依赖、启动训练、变更已有配置、读取业务数据、调用生产分析或对外发布。

| 类型 | 识别依据 | 典型条目 |
|---|---|---|
| S 可安装 Agent Skill | 实际 SKILL.md；检查脚本、资源与依赖；指令型与带脚本型另分 | project-solution-paths、hypothesis-generation、HF train-sentence-transformers |
| M MCP API 或连接器 | 有调用接口和外部数据/操作能力；不是推理方法本身 | GitHub、HF MCP、MLflow MCP、Optuna MCP、GrowthBook MCP |

同一项目可同时包含 D 和 M，但每部分的证据分别标注。普通仓库不自动算 Skill；读取日志的 MCP 不自动具有梯度诊断能力；传统工具无需接 LLM 才能使用。

四种收益单独记账：A 分析更快（净人工分钟）；B 分析更正确（盲测正确率、误报、漏报）；C 实验更高效（同预算有效区分假设数、无效运行占比）；D 最终模型或业务更好（独立未来数据、线上随机实验和护栏）。A 不能证明 B，A/B/C 不能代替 D。本轮不承诺任何 D 类收益。

### 检索与选择边界

检索按问题展开，再用维护者官网、GitHub 官方 release/tag、关键源文件、测试和实际技能目录逐项核对。检索词覆盖 scientific hypothesis/statistical skills、paper agents、label issues、time leakage、data drift、per-sample gradients、training MCP、experiment tracking、A/B statistics、off-policy evaluation、continuous learning 和 quantization。榜单、社区文章和 Star 数仅用于发现，不作为准入证据。

优先深查能直接消费现有产物、暴露失败、替代明确人工步骤的工具。研究概念、面向 LLM 输出质量而非预测模型的评测工具、依赖未知生产权限的平台降级。版本记录只表示本次实际可核实的发布或源码快照；官网与源码不一致处保留差异。未取得精确版本的辅助候选明确写“未锁版本”，不称为截至当日最新。此检索是有边界的选型研究，不声称穷尽所有商业产品或内部私有技能。

## 全链路问题能力地图

### 1 业务增长停滞或代理指标与目标错位

表现可能是 AUC 增长、CTR 增长，但成交、长期留存、履约或净收益不变。竞争原因包括标签只代表中间行为、分母改变、模型覆盖太小、决策规则未利用新分数，以及不同群体间收益转移。需要先固定决策对象、评价单位、时间窗口、可控动作和业务护栏，再看分数变化究竟改变了哪些动作。

LLM/Skill 能把现象展开为竞争假设、列证据缺口；SQL 能重算漏斗与分母；人必须确认目标之间的取舍、代理有效性和实验可行性。不存在仅凭一段业务描述就证明代理标签正确的工具。

### 2 论文新方法有效但无法迁移

竞争原因包括额外数据、更强 backbone、更多预算、不同负采样和评测集、模块耦合，以及论文代码与正文不一致。需要按“改哪里、信息从哪来、预算是多少、移除模块后如何”比较，保留线性/树模型、现网模型或强公开基线。工具负责查找、取证、定位实现；迁移判断仍需固定数据和预算复现。

### 3 数据与监督产生假信号

同样的指标下降可能来自概念变化、标签还未成熟、处理时点穿越、重复曝光、类别配比、候选覆盖或数据管线变更。要区分 event time、available time、label observed time、training cutoff；针对用户/请求/实体建切分。未曝光条目不自动是负例，未发生转化不自动是真负例。

表结构契约、全量 SQL 和时间连接检查先行；噪声检测、漂移报告和切片工具帮助找值得复核的子集。真实标签、成熟等待窗、曝光机制和人工标注仍是判断假负例的依据。删除高损失样本可能恰好删除稀有人群和最有价值的困难样本。

### 4 新特征或扩容没有收益

先区分特征未送达、缺失/截断、信息冗余、有效样本不足、模型不用、优化没学到、任务冲突，以及下游排序不敏感。观测包含逐样本预测、分组特征可用率、分任务梯度、参数更新量、曝光频次与训练/服务性能。仅有总 loss 或 attribution 排名不够。

PyTorch 能算梯度和记录算子；Captum 提供局部归因；BackPACK 提供支持模块上的逐样本导数；平台 MCP 读取训练记录。梯度饥饿、捷径学习、负迁移和扩容失效必须用对照干预验证，不能由一张热图命名根因。稀疏 embedding 要按触达次数看更新，不能与稠密层直接比较平均范数。

### 5 实验结果无法决定下一步

原因可能是同时改动太多、样本/预算不一致、看了结果再选切片、指标分母错误、统计单位错误、多个比较或提前停止。实验平台存储事实，调参工具分配预算，统计引擎按设计计算；它们不能替代正确的识别设计。成功应区分“排除了一个假设”“找到有效改动”“证明业务收益”，失败也应导向明确的停止或换路。

### 6 模块实现或训练复现失败

可能来自张量接口、数据排序、loss reduction、AMP、随机性、依赖版本和资源争用。Agent 阅读代码并生成差异；固定小批次、手算/数值梯度、基线重跑和性能剖析检验。优先保留现有训练入口，不迁移整个平台；大规模自主改代码、调参、解释结果要避免同一 Agent 同时充当评委。

### 7 离线预测提升没有变成线上决策收益

竞争原因包括候选集不同、分数只做单调缩放、融合权重抵消、预算/容量约束、分流失衡、曝光偏差、训练服务不一致、系统干扰与新颖效应。需要请求级候选和排序回放、模型服务版本、实验分配与曝光日志、成熟业务标签。先查动作变化率，再谈因果收益；没有 propensity 和支持性不能可靠估计未执行策略的价值。

### 8 模型过时或刷新成本过高

分布漂移、标签延迟、冷启动、缓存陈旧、周期性需求变化、serving 特征延迟都可表现为模型过时。分开记录特征分布、成熟标签性能、模型/特征/缓存年龄和服务成本。Evidently 做批次证据，River 可作为流式基线，训练与回放平台比较刷新周期。漂移告警不自动触发训练；量化或序列压缩必须同时重测校准、排序与 P95/P99 延迟。

| 模型迭代问题 | 所需能力 | 优先候选 | 输入 → 可交接输出 | 能暴露错误的验证 |
|---|---|---|---|---|

## 三套条件化组合

### 组合一 低成本起步

**适用条件：** 单个模型或小团队，有离线导出能力，无需换训练平台。第一轮只选择问题定义、数据检查和一个明确的诊断工具。

使用已有 project-solution-paths → SQL/pandas断言（规则需要复用时加Pandera）→ 固定预测表的分群指标 → 现有训练框架的梯度/参数差分 → JSON/CSV实验账本。论文检索复用paper-search与GitHub；需要跨批次可视报告再加Evidently。没有PyTorch时保留原框架等价梯度/日志路径，不为本库迁移。

首轮不需要新的MCP服务、向量库、全自动Agent或云训练。可选LLM只接脱敏摘要，原始行/梯度留在本地或已有内网计算环境。预计准备投入以1–3人日为上限做一个历史故障回放，真实数据准备可能更久；未提供环境前不承诺工期。若同等覆盖下不能减少净排查时间，保留确定性检查，撤掉LLM解释层。

### 组合二 已有训练与实验平台的增强

**适用条件：** 已有MLflow、W&B或内部平台和SQL仓库，run数据完整。三个平台不同时上。

保留训练入口、存储和A/B平台；增加统一manifest及样本级预测导出。训练短窗采集torch诊断；Evidently/Cleanlab只在触发问题时运行。日志优先SDK批量导出，有稳定只读MCP才接自然语言检索；实验平台结果导出给统计复核，不由Skill刷新快照。Optuna仅在重复超参试验确实占成本时加入；Optuna trial_number映射到同一个run_id，避免双重账本。

产物：可追溯比较表、明确采样覆盖的诊断摘要、异常复核队列和下一实验单。首轮投入先设单个模型/20–50次历史runs/一个实验快照的边界，2–5人日为规划上限而非报价。若权限、字段缺失或指标语义不一致，先修manifest，不扩展Agent能力。

### 组合三 工程接入较多的完整组合

**适用条件：** 多模型、多任务、持续刷新和复杂决策，需要统一血缘、回放和分工。已有前两组真实验收证据，且有人维护平台。

内网数据/特征血缘和成熟标签作事实源 → 数据契约与切分门禁 → 版本化方法模块库 → 沙箱训练执行 → 受控梯度/性能采样 → 实验账本与预算调度 → 候选/排序/约束决策回放 → A/B统计与护栏 → 成熟标签监控/刷新策略。LLM只选择已批准的能力和解释证据；工具注册需声明读写能力、输入schema、预算和幂等键。RD-Agent仅作为离线候选生成器，评估器和最终保留集放在它不能修改/看到的边界外。

组合不必在一个框架内实现。统一数据契约比统一Agent框架更关键；MCP只解决访问，不解决指标语义。以`run_id + data_snapshot_id + metric_contract_hash + code_commit`贯穿，长表和模型留对象存储，仅传引用与校验值。异步任务超时要保留状态，不无界重试；同一运行用幂等键阻止重复训练。任何跨工具摘要都必须携带事实来源和未覆盖部分。

工程成本包括身份/权限、任务队列、对象存储、审计、重试、依赖镜像、数据质量、独立统计审查、GPU与服务容量。这里不把各单工具PoC人日相加成项目报价；在拿到模型规模、集群、数据血缘和平台约束前，需要专项估算。完整组合的准入条件是它解决一个前两组无法低成本解决的重复问题，不能只因架构完整而建设。

## 工具之间如何交接而不丢信息

以下为本库设计的建议契约，均不是第三方统一标准；需一个显式适配器将实际输出映射到契约。格式校验通过只证明字段一致。

| 产物 | 最低必要字段 | 生产者与消费者 | 失败处理 |
|---|---|---|---|
| problem_spec | decision_unit、业务目标、代理指标、分母、窗口、可控动作、护栏、未知项 | 人/目标Skill → 所有诊断 | 缺目标/分母不比较模型 |
| evidence_manifest | snapshot_id、路径/URI、hash、row_count、时区、code/ref、schema版本、来源、权限范围 | 数据导出程序 → 工具适配器 | hash/行数不符隔离该产物 |
| prediction_table | row_id/request_id、event/available_time、label_observed_at、maturity、y、p、class_order、weight、split、model/checkpoint、slice | 训练评估程序 → Cleanlab/Evidently/回放 | 未成熟保持unknown；错位直接失败 |
| method_card | paper_id/version、来源页段、代码commit/入口、问题、假设、baseline、改动接口、额外数据/预算、耦合与未核项 | 检索/PaperQA/模块库 → 实验设计 | 无证据字段不自动生成实现承诺 |
| diagnostic_report | 输入hash、检查定义、方法参数、覆盖/采样、分子分母、统计量/区间、原始结果引用、unknown、验证层级 | 数值程序 → LLM/人 | 不能用空结果代表无问题 |
| gradient_stats | run/step/task/param_group、loss缩放、AMP状态、ID触达数、范数/方向、实际更新、采样范围 | 训练instrumentation → 诊断 | 未触达与未采集分开；不补零 |
| experiment_spec/result | hypothesis_id、对照/负对照、固定条件、预算、主指标/护栏、统计单位、停止规则、run映射、实际结果与偏离 | 人/实验Skill → 训练/统计 → 决策 | 不可比结果保留，不进入排名 |
| decision_record | 支持/反对/未知证据、继续/停止/换路、原因、需人确认项、下一最小实验 | 证据汇总 → 负责人 | 失败结果与不确定性不得删去 |

**防止重复与错误传播。** 同一快照和指标定义共用一次计算结果；不要让Evidently/Deepchecks/自研脚本各自以不同默认值重新定义“漂移”。PaperQA输出引用回到原文，模块库保存原文锚点而非二手摘要链。MLflow和W&B选择已有一种作为run事实源；MCP每次只取明确范围，返回抽样必须标coverage。任何LLM生成的数值由程序复算，不能在下游被当作已验证事实。

## 三个端到端场景

### 场景一 新特征无收益

**先收集。** 特征定义/可用时点/覆盖率、训练与服务代码commit、特征join统计、old/new相同样本预测、成熟标签、候选列表、训练step与参数组、损失缩放/采样配置、按人群指标。先确认“无收益”是点估计接近0、区间过宽、还是业务指标不动；缺逐样本数据则先做导出规格，不猜根因。

| 顺序 | 工具与产物交接 | 人的判断与下一分支 |
|---|---|---|
| 1 定义比较 | project-solution-paths产problem_spec；SQL重算分母 | 确认要提高的决策与覆盖；不同split先停止比较 |
| 2 检查送达 | SQL/Pandera检验as-of、缺失、特征版本；产quality_report | 若大量缺失/穿越，先修数据再重跑；不继续解释梯度 |
| 3 定位谁受影响 | 固定预测表→分群logloss/校准/排序动作变化；Evidently做可比报告 | 只有低覆盖切片有效：先估覆盖规模，不贸然全局扩容 |
| 4 检查学到了什么 | torch记录特征组/任务梯度、实际更新和稀疏触达；Captum组消融 | 零梯度区分detach、未入optimizer、未触达、已收敛；归因仅为证据 |
| 5 区分竞争原因 | 生成experiment_spec：现有baseline、只修管线、特征置乱负对照；有证据再比较移除竞争特征/调任务权重 | 每次只改变目标因子，固定数据/候选/预算；人工确认扰动合法 |
| 6 记录与决策 | 原平台/MLflow记录run，统计程序做配对/按用户或请求聚类比较；产decision_record | 修管线有效则收敛该原因；F单独有效联合无效再查冗余/优化；区间宽则补功效，不宣布无用 |

预算对照需同时报告同训练步数和同计算预算两种问题，不能把更长训练的收益归给特征。多任务冲突需有“干预冲突处理后改善”的证据；负夹角本身不足。若严格配对、多seed和未来成熟集仍无实质改善，停止投入该特征，改查标签信息量或候选瓶颈。

### 场景二 离线涨线上不涨

**先收集。** 两版服务模型/特征/融合规则版本；线上分配、实际曝光、候选与位置、最终动作；请求级两模型分数；实验主指标分子分母、用户/请求聚类关系、观察窗、成熟标签、预算消耗和护栏。AUC涨并不保证top-K改变；分数单调变化可保持AUC却改变融合后决策。

| 顺序 | 工具和交接 | 可区分的解释与决策 |
|---|---|---|
| 1 保证同一问题 | 数据审计+manifest查线上线下标签、时间、候选口径 | 标签/候选不同先修评估，不把差异归为模型泛化 |
| 2 回放决策 | 确定性ranking replay读固定候选和规则；输出top-K重合、交换、动作/预算变化与切片 | 分数变但动作没变，改检查融合/阈值/约束敏感性；不继续盲调AUC |
| 3 核实验健康 | 现有平台/GrowthBook只读结果；统计脚本核SRM、跨桶、日志缺失、迟到转化、分母 | SRM或数据契约失败时不给winner；SRM通过也要核日志 |
| 4 解释效应 | 检查效应区间、MDE、运行周期、护栏、多重比较；预定子群均值差优先 | 区间宽继续收集至预设终点；区间排除有意义提升则停止；护栏破坏则不晋级 |
| 5 条件扩展 | 有真实识别条件才做EconML异质性或OPE；以独立数据/预注册设计验证 | 无propensity/overlap不产生反事实收益；供需干扰需适当集群/时段设计与残留效应检查 |

产物从prediction_table/replay_report/experiment_snapshot交给decision_record，所有结论附snapshot时间与统计设置。GrowthBook分析Skill不能在此链路偷偷POST刷新。排序偏好interleaving若可用只辅助比较，不代替完整业务A/B。没有完整候选/曝光日志时，下一步是设计采集或受控实验，而不是用LLM估计缺失收益。

### 场景三 模型快速过时

**先收集。** 预测时点、模型训练/发布时间、特征更新时间、缓存年龄、事件时间、标签观察时间与回补曲线；滚动窗口样本/预测、渠道/用户/item构成；训练与服务资源消耗。比较同标签年龄的cohort，不能拿昨日未成熟CVR与上月成熟CVR直接比较。

| 顺序 | 工具与产物 | 决策分支 |
|---|---|---|
| 1 分离新鲜度来源 | SQL/Pandera核标签成熟与feature/cache age | 若特征/缓存陈旧而模型没变，先修数据时效；若标签未成熟先等待/建延迟观测方案 |
| 2 定位变化 | Evidently固定季节可比窗 + 成熟标签分群性能 | 只有X漂移无性能下降先观察；X不变但性能下降查条件关系/标签定义 |
| 3 时间回放 | 现有训练执行器按历史可用数据重放：现有刷新周期、缩短窗口/周期、增量更新的条件候选 | 每个模拟时点禁止未来标签；固定总算力预算并记录重训耗时/可服务时点 |
| 4 比较方案 | MLflow/原平台记录质量-年龄-费用表；轻量流式分类可选River作研究baseline | 新模型若只短期好而灾难遗忘，保留回放/混合样本对照；不是见漂移就训练 |
| 5 预算与上线准备 | Profiler定位训练/服务成本；确有瓶颈再试蒸馏、量化、共享计算/缓存 | 量化测尾延迟与校准；蒸馏看教师年龄；缓存看命中与过时损失；人选择Pareto方案 |

输出refresh_policy_candidates与decision_record，明确触发指标、成熟标签需求、冷却期、资源上限和回退模型。没有真实标签时只能验证监控与回放实现，不能承诺概念漂移检测成功。若更频繁刷新在同预算下不优于简单固定周期，停止复杂持续学习，保留固定周期加告警人工检查。

## 最小验证计划

这是一份待执行计划，不是本次已经跑过的实验。优先用历史已定位问题和合成负例；无需首轮准备全量业务库。

| 阶段 | 准备样本和先试工具 | baseline与固定条件 | 继续条件 | 停止或换路 |
|---|---|---|---|---|
| 0 契约 | 一份指标定义、1个模型版本和匿名字段表 | 现有负责人确认的口径 | 分母、时点、标签成熟、ID可对齐 | 缺失先补导出，不安装诊断平台 |
| 1 数值与拒错 | 20–50行手工夹具；SQL/Pandera；时间/重复/NULL负例 | 同规则手算与SQL | 规则正负例完全符合预期，错误定位可读 | 库无新增覆盖就用现有程序 |
| 2 已知故障回放 | 一宗已修故障、两版预测/成熟标签；torch或已有日志导出 | 人工历史结论遮蔽后盲测，固定快照 | 能定位已知问题且不给正常低频/收敛误报 | 缺关键观测则补埋点，不加LLM推断 |
| 3 检索与解释 | 20–50 runs/10题，或10篇论文/20题；只选一条链 | 人工UI/原文；相同信息与时间上限 | 关键数值/引用可追溯，净人工时间下降 | 幻觉/错对齐即降为原始证据检索 |
| 4 数据疑点增量 | 例：200条固定预算盲审，含loss/随机/Cleanlab各自候选并去重 | 同时间外预测，审阅者不见来源 | 相比最强简单baseline提高确认率/成本效率 | 不优于loss就不养新工具 |
| 5 真实实验价值 | 一个预注册改动、独立未来成熟集，必要时线上A/B | 同代码/预算/候选/seed组/统计单位 | 结论更可靠或每个有效实验成本降低；业务收益另测 | 只增加试验量、时间或选择偏差就停 |

20–50行和200条是起步夹具/审阅预算示例，不是统计充分性保证。真实样本量依据基准发生率、聚类设计、MDE、方差、覆盖率与错误代价确定。多seed用于训练稳定性，不能替代线上随机化样本量；1000次模拟的覆盖检查也要报告Monte Carlo误差。

每次必须保存：固定版本/依赖锁、输入hash、命令/实际schema、stdout/结构化输出、异常、时长、CPU/GPU小时、内存、下载/存储量、LLM输入输出token、重试与人工分钟。语法检查、读取README、`--help`成功均不等于能力示例通过。能力V4可以是业务场景下分析正确或提效的验证；最终模型/线上收益仍需独立对应证据。

**全成本计算口径。** `一次性数据整理与接入人时 + 复核人时 + 所有成功/失败运行的计算费 + 模型调用费 + 平台/存储/传输费 + 维护摊销 + 误报处理成本`。API/云GPU实际合同与硬件未知，不列虚构单价；开源免费只表示许可证/本地使用不强制订阅，算力与人工并不免费。先测“每个确认问题成本”“每个有效实验成本”，再决定是否规模化。

## 缺口和排除记录

| 能力或候选 | 本次状态 | 原因及下一步 |
|---|---|---|
| 梯度饥饿/冲突/稀疏更新自动根因 | 未找到经过目标业务验证的通用成品 | torch等提供测量；需要loss口径、触达次数、实际更新和干预对照；优先封装测量契约 |
| 业务代理标签与长期目标一致性 | 无可靠自动证明工具 | 需要真实长期结果、因果/实验设计和业务价值判断；不要让LLM给一致性分数代替证据 |
| 延迟反馈、假负例、多行为监督 | 通用质量库仅覆盖部分 | 明确曝光与成熟窗口、删失/缺失机制、任务分母；先SQL cohort和成熟holdout，再研究纠偏 |
| 样本价值与定向采样/标注 | 没有在本目标上核实可直接投产的组合 | 先随机/分层/高loss/不确定性四类简单分配，在同标注与训练预算下对照；Cleanlab分数不是训练价值 |
| 普通数据分析聊天Agent | 非优先 | 若不能导出SQL、样本对齐、统计设置和失败记录，无法承担严谨模型判断；保留自然语言入口不委托数值结论 |
| 通用LangChain/LlamaIndex等编排框架 | 不作为问题解决工具排名 | 框架本身不提供业务诊断；当前用简单脚本和manifest已可连接，出现明确编排瓶颈再评估 |
| LLM judge、RAG评测、Weave tracing | 不直接替代CTR/CVR模型评测 | 可测Agent回答质量或LLM trace；不产真实成熟标签、曝光纠偏或梯度根因 |
| HF LLM/vision训练技能 | 本轮只看目录，非重点准入 | 用户并未声明训练语言/视觉基础模型；需要时再读实际对应SKILL和脚本，不按仓库名推荐 |
| hypothesis-generation中文validator | 已暴露局部失败 | 修复Unicode归一化并复测，否则只借结构与人工审查 |
| W&B MCP当前候选部署、MLflow MCP experimental | 有源码但接入条件不等于稳定产品 | 版本/传输/只读控制单独验收；SDK导出是后备 |
| Optuna MCP读取已有study | 只读选择流程缺口 | 用SDK只读适配或导出；不为了读数据调用可能创建study的工具 |
| GrowthBook分析Skill | 只读声明与刷新动作不一致 | 禁用写接口、仅读已有快照并保留时间，不自动刷新 |
| OBP旧发布 | 业务相关、工程兼容待验证 | 先在隔离环境验证旧依赖和OPE假设；缺propensity则停，不以其他估计器绕过 |
| RD-Agent及自主科学家主张 | 有实现的研究候选或更低证据概念 | 需隔离执行、独立评估、预算与泄漏诱饵；没有本业务收益证据，不优先 |
| 量化、长序列压缩、共享计算、缓存 | 量化辅助工具到V1，其余多需项目实现 | 先Profiler/回放定位瓶颈；逐样本质量、校准、新鲜度、端到端尾延迟共同验收 |

**辅助效率候选。** River的`DriftRetrainingClassifier`可用已到达标签监测错误、维护后台分类器；当前只读官方API为V1、未锁release，不是深度推荐模型即插即用刷新器。[River官方API](https://riverml.xyz/latest/api/drift/DriftRetrainingClassifier/) ONNX Runtime量化需匹配算子与硬件，可能不加速，先以现网模型压测。[ORT官方文档](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html) OR-Tools只在目标值、约束已知时求解；预测不是因果收益，FEASIBLE不等于OPTIMAL。[OR-Tools官方例](https://developers.google.com/optimization/mip/mip_example)

## 值得自行封装的 Skill 规格

只设计，不创建或安装。先复用已有Skill和平台；只有同一手工步骤在几次问题中重复出现并通过验收，再封装。数值算法仍放独立程序，Skill只负责流程和契约。

### 规格一 标签与时点审计

**职责：** 将标签成熟、特征as-of和切分语义转成已审核检查；不估计未观测真标签，不自动改样本。已有数易/SQL治理若覆盖完整，只增加契约，不另建Skill。

**输入输出：** problem_spec、字段/时间血缘、样本快照引用、归因/观察窗、split与采样规则 → quality_report、违反规则的row_id引用、maturity cohort表、unknown清单。输入需给event/available/observed三类时点；缺失不能自行推断。

**依赖和步骤：** 只读SQL或DataTools已授权查询；Pandera用于本地小表。读取契约→校验源/权限/快照→先做计数与键对账→时间/成熟/重复/覆盖检查→与基准对账→输出带hash结果。禁止自动安装、配置、全表无限扫描、修改标签。

**验证与失败：** 用未来特征、等时边界、跨窗归因、时区、合法重复、无变化六类夹具；与SQL金标逐行比。超配额/错环境/缺时点返回blocked_for_evidence，保存已完成检查；不能变成“无异常”。下一步补血缘或人工复核。

### 规格二 训练信号审计

**职责：** 对受限训练副本采集真实梯度和参数更新，区分未计算、未触达、计算为0与更新被跳过；不自动宣称梯度饥饿/负迁移根因，不自动调学习率或修改结构。

**输入输出：** code_commit、checkpoint、fixed batch、loss/task定义、optimizer参数组、AMP/分布式设置、采样预算 → gradient_stats、update_stats、Profiler摘要、数值自检、coverage和兼容错误。

**依赖和步骤：** 原框架autograd优先，torch.func条件使用；BackPACK仅明确支持的模块。先读训练step与loss reduction→解析toy对齐→短窗采样→按任务/频次/参数组聚合→与step前后参数差分交叉检查→给出最多几个区分实验候选。稀疏ID需排除padding，重复索引按实际稀疏格式合并，优化器与embedding支持单独验证。

**验证与失败：** detach、漏optimizer、lr=0、AMP skip、相反任务、重复ID、正常低频和已收敛负例；固定batch和缩放口径，对比朴素autograd及真实更新。发现不支持算子、静默缺梯度或开销超预算则停止，退回选层hooks/更新差分，不为通过测试改变真实训练语义。

### 规格三 实验结果与下一轮决策

**职责：** 汇集可比较结果，识别健康/功效/口径问题，映射回假设与下一实验；不改快照、不自动选winner/发布模型。已有A/B平台只需加导出与解释模板时，不构造新统计引擎。

**输入输出：** experiment_spec、manifest、固定统计设置、结果JSON、健康检查与原始引用 → readout、支持/反对/未知假设、decision_record和下一最小实验草案。输出每个数值带计算来源。

**依赖和步骤：** 原平台/MLflow/W&B受限SDK或只读MCP、现有统计程序/GrowthBook stats。先验证schema/hash→核split/分母/窗口/随机单位→健康gate→读取或独立复算区间→标多重比较/探索性→检查护栏→给继续/停止分支。禁止GrowthBook自动POST快照，禁止用Optuna create_study装载只读账本。

**验证与失败：** A/A、有效正负效应、SRM、events/users混淆、旧快照、无功效、非独立单位、无可行候选；与统计人员金标盲测。任一严重口径问题应输出无法判断；工具错误不得由LLM补数字。无收益时按假设矩阵选择补观测、换干预或停止，而不是默认再调参。

### 规格四 方法卡到实验单的薄适配

**职责：** 复用research-tech-broadcast现有模块协议，将经人工确认的module_id和真实系统接口映射为受限实验单。不要修改原论文记录来存实验收益，也不另做一个通用论文Agent。

**输入输出：** method_card/模块记录、目标代码入口、baseline、数据/预算/部署约束 → 改动位置、固定条件、最小模块消融、正负对照、风险与experiment_spec。缺张量尺寸或训练条件写unknown。

**依赖和步骤：** GitHub/本地代码只读、现有项目问题Skill和协议校验。核原文与commit→检查额外数据/预算→列耦合依赖→选择最小改动→写判据和回退；实现留给已授权的后续工作。

**验证与失败：** 有独立消融、只有整体结果、缺代码、强耦合、额外标签五类金标。不能把整体收益归给单模块；发现接口不匹配就退回方法比较，不强行生成代码。若纯模板足够，保留模板，不安装新Skill。

## 最终复核记录

1. 重点条目均提供实际官方来源/本地技能快照与版本信息；辅助候选的未锁版本明确保留。Skill和仓库、MCP与算法分开分类。
2. 所有重点最小示例都注明执行状态。没有把语法检查、源码推导、公开仓库读取或函数probe提升为整工具/业务验证。
3. 重点卡包含具体问题、分工、输入输出、落点、失败、全成本、示例、baseline/正负例验收及替代。重复功能建议只保留一条权威实现。
4. 关键文档与代码差异已记录：中文validator、Deepchecks边界/分母、Evidently参数/分箱、HF默认发布、GrowthBook刷新、Optuna只读缺口、MCP版本状态。
5. 工具可用性与收益证据分开；省时、正确性、实验效率和业务收益分别验收。V4描述的是被验证的具体业务能力，不自动代表线上模型收益。
6. 三个场景均有证据收集、交接产物、人工判断和失败后的路线；缺标签/血缘/propensity时明确停止相关推断。
7. 本次未安装、未改配置、未训练、未接生产、未发送消息或云端发布。只生成本地研究交付物。后续最优试点所缺信息为：训练框架、现有实验平台、可导出的逐样本字段和一个历史已知故障；这些不阻碍本次条件化选型。


## 目标定义和方法研究工具卡

### R1 已有 project-solution-paths

**结论与证据。** 优先复用的指令型 S，V2；实际读过本地 SKILL.md 和六条思考路径，无独立脚本、无语义化版本、无单独测试套件。快照哈希见环境盘点。它是结构化工作方法，不是自动诊断或统计计算器。

**具体用途与分工。** “新特征离线无收益”时，LLM 根据当前训练到排序的链路列出竞争原因，选择能改变下一步决策的检查；工程师确认真实接口，分析程序计算证据，业务负责人确认目标。最小接入是在实验立项前增加一页问题卡，保留原 SQL、训练和实验流程。

**输入输出。** 输入业务目标、现有链路、可改模块、已有证据和约束；输出问题定义、候选原因、针对性改动、固定条件、继续/停止条件。建议转成后文 hypothesis_matrix 与 experiment_spec 契约；这是本库建议的适配输出，不是此 Skill 原生 JSON API。

**最小使用任务。** 在支持当前 Skill 的 Agent 中指定：“使用 project-solution-paths。现象：加入特征 F 后离线 AUC 未变；已知：F 在线可用率未知。目标：提升完成转化。请先列能区分管线、冗余与优化问题的证据，不假定模型架构，给出最小检查和结果分支。”预期产物是竞争假设与检查优先级，不应该直接建议换更大模型。

**前提、失败和成本。** 无代码与日志时只能形成诊断计划；业务链错误会把所有后续工作带偏。无第三方部署成本，但长上下文、LLM调用与领域专家复核有成本。不同模型/提示会导致假设集合变化，维护应记录模型、提示和输入快照。

**验收。** 用一宗已知管线故障、一宗真实冗余特征和一个仅有汇总指标的不足信息案例；对比工程师原问题卡，固定输入证据、时间上限与模型版本。盲评原因覆盖、无依据断言数、实验可区分性、人工修订分钟及调用成本。硬门槛：不能虚构架构/数据，不能把缺证据说成已定位；在正确性不降的情况下减少净复核时间才保留。若重复给泛化清单，退回人工问题卡，不再叠加更多 Agent。

**替代组合。** 与下项 hypothesis-generation 大量重叠；不建议串行生成两份假设再相互总结。可以只借用后者的记录契约，用现有 Skill 负责思考、确定性校验负责字段完整。

### R2 K-Dense hypothesis-generation

**结论与证据。** 带脚本的 S，主体 V2；已读完整 SKILL.md、预测矩阵模板和 validator。声明版本 2.4，源码快照 a92663a0214b3b9fa1ba6b958284ffd919c00a0c，Python 3.11+、MIT。适合需要持久化假设/负对照记录的团队，该版本预测矩阵validator对纯中文expected文本存在已定位的比较缺陷。来源：[实际技能文件](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a92663a0214b3b9fa1ba6b958284ffd919c00a0c/skills/hypothesis-generation/SKILL.md)、[预测矩阵验证器](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a92663a0214b3b9fa1ba6b958284ffd919c00a0c/skills/hypothesis-generation/scripts/validate_prediction_matrix.py)。

**具体用途与工作方式。** 例如把“多任务模型新任务上线后老任务下降”转成容量竞争、梯度冲突、样本配比和标签变更四类候选；每个候选写独立的预测与反驳条件。LLM 起草，stdlib 脚本检查引用、字段和自相矛盾，研究者选择实验。脚本不验证科学真伪，不做假设自动排名。

**输入输出与接入。** `matrix.csv` 的实际字段包括 prediction_id、hypothesis_id、rival_hypothesis_ids、conditions、observable、expected_if_focal、expected_if_rivals、falsifier、indeterminate_result、boundary_conditions、measurement_ids、negative_control_ids、analysis_ids、uncertainty；可选 hypothesis JSON 作交叉引用。输出 JSON 包含 valid、errors、warnings、prediction_count、status。放在实验单提交前校验，与已有项目问题卡对接。

**核实过的最小调用。** 待安装/审阅副本准备好后，在技能根目录：

```bash
python3 scripts/validate_prediction_matrix.py matrix.csv
# 需要验证跨对象ID存在性时，再提供通过schema的记录
python3 scripts/validate_prediction_matrix.py matrix.csv --record hypothesis_record.json
```

示例输入应至少含 H1“任务梯度方向相反”、H2“只是样本比例变化”，分别声明固定采样后的预期和反例。返回 `VALID_FOR_HUMAN_REVIEW` 只表示结构检查通过，不能写成假设成立。未传--record只检查矩阵内部约束；要声称交叉引用通过，还须检查record_cross_check_performed=true。Skill版本2.4与输出schema_version=2.0为不同维度。本次未执行完整CLI。

**实际暴露的失败。** 验证器用 `[^a-z0-9]+` 归一化 expected 文本。我们只对这一纯函数做了本地探测：英文“feature gradient increases”与“feature gradient unchanged”保留差异；中文“新特征梯度明显增大”与“新特征梯度保持不变”都变成空字符串；按已读validate_matrix分支，两者将触发FOCAL_AND_RIVAL_EXPECTATIONS_IDENTICAL错误。未执行CSV解析或完整validator。此探测达到 V3 的仅是函数行为，完整 Skill 仍为 V2。中文自动验收应暂缓，先修复/替换该比较或人工检查；英文绕行仅可用于验证定位，不能忽略维护成本。

**成本与边界。** 核心脚本本地执行、无额外模型/API依赖；Agent本身的调用和专家复核仍需预算。维护包括多文件 schema、模型输出格式及中文适配。字段完整不能阻止一个科学上无效的负对照；不应让结构 validator 给出“科学正确”的徽章。

**验收。** 正常输入、重复ID、自己列为对手、焦点与对手同预测、纯中文不同预测、文字完备但机制不可辨识六类夹具；对照人工审阅与简单 schema 校验，固定版本和输入。计字段错误召回、误报率、语义问题漏报、耗时和审核成本。结构负例应全部按定义拒绝，正常中英文不得误拒；语义判断保留人工。不达标就停用该 validator，复用本机问题卡或只用基础 schema。

### R3 paper-search 加 GitHub 连接器

**结论与证据。** 本机 paper-search 是 S（带 Python 脚本），研究来源为外部 API；GitHub 是 M。本地脚本 V2，GitHub 公开读取 V3。Skill无语义化版本，用内容哈希识别；连接器服务版本未对用户暴露，以本次 schema 为准。官方标准也将技能定义为指令/资源包，不是执行效果保证。[Agent Skills 格式](https://agentskills.io/home)、[Codex 技能文档](https://learn.chatgpt.com/docs/build-skills)。

**具体用途。** 研究延迟反馈、假负例或多任务冲突时，检索论文元数据，再核查作者链接的实现，提取方法假设、改动位置、负采样、split、baseline和预算。程序负责召回/API获取，LLM负责对齐条件，人读关键实验和消融。先产方法卡，再由独立实验设计步骤生成实验单。

**输入输出。** 输入 query、起止年、每源结果上限、来源列表；程序函数返回按来源分组的论文dict（title/authors/year/abstract/url/venue/citation_count/publication_date/source）。CLI输出面向人，不能把stdout直接当JSON；结构化串联需调用函数或写显式适配器。GitHub输入规范仓库URL或 repo/path/ref，输出内容和来源。建议保存论文ID、原文页码、commit、文件路径、假设、接口与消融证据，而不是只有摘要。

**最小调用与接入。** 下面是本地已核实参数的待试命令，不表示本次已联网跑完论文搜索：

```bash
python3 /Users/didi/.codex/skills/paper_search/scripts/search_papers.py \
  --query "delayed feedback conversion prediction" \
  --start-year 2014 --end-year 2026 --max-papers 5 \
  --sources arxiv open_alex crossref
```

现有 GitHub fetch 参数是 `{"url":"https://github.com/Future-House/paper-qa/blob/v2026.08.12/src/paperqa/docs.py"}`，本次已成功返回源码。它只证明读取能力，不能证明论文实现正确。最小接入保留当前浏览器/文献管理器，以方法卡附加代码入口。

**失败、规模和成本。** 聚合器捕获来源错误并返回空列表；CLI可正常结束但实际检索失败，不能以进程退出码作完整性验收。缺失或不可解析的发布日期会被日期后过滤保留，不能宣称结果严格全在时间窗。model_knowledge 只是Skill要求的模型回忆补充，不是脚本可调用来源；CLI choices 无此选项。元数据可能重复、引用数滞后，作者链接不等于代码经过复现。OpenReview有可选依赖，来源可能需要凭据/限流；检索、全文整理和代码审阅成本通常高于一次API查询。未测试本机各API权限与网络。

### R5 PaperQA

**结论与证据。** A，V2。适合对一个可控论文集进行带来源的问答与证据综合；不是全网论文获取权或业务实验Agent。核实 release v2026.08.12、Python>=3.11、pyproject、Docs源码和测试目录；未运行、未配置模型。来源：[版本](https://github.com/Future-House/paper-qa/releases/tag/v2026.08.12)、[依赖](https://github.com/Future-House/paper-qa/blob/v2026.08.12/pyproject.toml)、[Docs接口](https://github.com/Future-House/paper-qa/blob/v2026.08.12/src/paperqa/docs.py)、[官方说明与局限](https://github.com/Future-House/paper-qa/blob/main/README.md)。

**具体用途与分工。** 输入几篇延迟反馈/多任务论文，提问“收益是否来自额外标签或更大预算，哪些消融能支持模块独立有效”。解析器提取文本，向量/索引检索候选片段，LLM总结证据并回答；研究者核对公式、表格和来源支持程度。若只读两三篇，现有Agent逐篇原文核对可能更便宜。

**输入输出与接入。** 输入合法取得的PDF/文本及问题、LLM/embedding配置；`Docs.aadd`添加文档，`Docs.aquery`返回PQASession（回答、contexts等），可被适配成方法卡。增加于全文阅读阶段，不替代论文元数据检索和代码复现。文件虽在本地，所选云LLM/embedding可能收到文本；“本地运行”不等于“数据不出本地”。

**核实过的最小示例。** 在已准备好受控模型配置的Python异步上下文中，以下接口与固定tag一致；示例文件需自行准备，本次未运行：

```python
from paperqa import Docs
docs = Docs()
await docs.aadd("papers/method_a.pdf")
await docs.aadd("papers/baseline.pdf")
session = await docs.aquery("哪些实验分别控制了数据、模型容量和训练预算？找不到则明确说明。")
print(session)
```

**成本与失败。** 解析、embedding、检索重排、证据总结和回答可能多次调用；多模态/长PDF再增加费用。索引缓存可减少重复嵌入，但原文更新需失效重建。成本试算应计文档数/页数、嵌入token、回答次数、并发、重试和人工引用核验。官方FAQ承认内部论文获取能力/许可与开源实现不同，不能把论文里完整系统的表现外推到此部署。公式抽取错、缺全文、来源选择偏差和生成引用错误都可能发生。

**验收。** 固定10篇可公开全文、20个专家问题，其中含无答案、互相矛盾、表格取值及“只有整体结果”的负例；baseline为普通关键词检索+人工阅读或当前Agent。双人盲评引用支持率、答案正确率、证据召回、无答案拒答、净时间和全成本；关键结论引用必须逐项可追溯。若引用不支持答案，停止自动沉淀，只保留检索片段供人阅读；若只更快但错得更多，不升级。文献问答通过不等于推荐模型效果提升。

### R6 Hugging Face train-sentence-transformers

**结论与证据。** 带参考文档和训练脚本的S，V2；仅在文本/语义召回、两阶段检索重排适合时试用，不将其等同于通用推荐预估训练。SKILL最后变更commit为020194918dc4a27d5a5d9a154b6b56cc2bd21364，所查CrossEncoder模板最后变更3ac5910959e2b9fae3aea94badcc3b280781c9c2；无单独语义化release。来源：[技能文件](https://github.com/huggingface/skills/blob/020194918dc4a27d5a5d9a154b6b56cc2bd21364/skills/train-sentence-transformers/SKILL.md)、[实际训练模板](https://github.com/huggingface/skills/blob/3ac5910959e2b9fae3aea94badcc3b280781c9c2/skills/train-sentence-transformers/scripts/train_cross_encoder_example.py)。

**任务与分工。** 当召回文本语义匹配差或top-K相关性不足，Agent选择bi-encoder、CrossEncoder、SparseEncoder或MultiVector路径，读取对应loss/evaluator/训练模板；确定性训练器挖掘负例、训练并评估；人验证标注、候选与部署成本。最小落点是一个现有召回/重排模块的离线对照，不搬迁CTR/CVR主模型。

**输入输出。** query/document正对或query/document/label；训练/验证按query或时间隔离；候选生成策略与基线checkpoint。模板产checkpoint、训练log、evaluator指标和VERDICT。它的WIN是固定阈值规则，不是统计显著或业务成功。同一NanoBEIR用于baseline、早停/选checkpoint和最终VERDICT，属于开发集结果；业务验收需另设不参与选择的最终query/时间留出集。这与pair行切分不保证query隔离是两项独立限制。

**核实过的最小调用。** 模板已有 `SMOKE_TEST`开关，准备兼容依赖后可执行：

```bash
SMOKE_TEST=1 python scripts/train_cross_encoder_example.py
```

此模式把训练裁到1 step并跳过Hub push，但仍可能下载公共模型/数据、挖掘负例和运行evaluator；已有固定缓存时直接复用，smoke与正常路径共用目录，不能保证只处理小缓存。应在任务专属空缓存副本试验；本次没有运行。依赖声明Python>=3.10、sentence-transformers[train]>=5.0、datasets、accelerate、trackio；实际模板还用 `use_faiss=True`，FAISS等可选依赖需额外核查，声明范围不是已测兼容矩阵。

**代码暴露的边界。** 默认模板用英语公共数据与NanoBEIR评测；pair行随机切分不能保证query隔离，不能直接当业务时序验证。训练参数直接设 `bf16=True`，不是每台硬件都支持；硬负例缓存需绑定模型和数据快照，否则复用旧负例。smoke关闭Trackio并跳过push；正常运行默认在结尾尝试push Hub并使用Trackio，成功受认证/权限影响；内部数据使用前必须把外发行为做成显式策略，本次没有执行。因为这些问题，暂不建议原样运行在业务数据上。

**成本与验收。** 主要成本是相关性标注、负例挖掘、GPU、检索索引重建、rerank延迟与模板维护。固定语种、query集合、候选、预算和种子；对比现有BM25/双塔/重排器，测Recall@K、nDCG、按query bootstrap不确定性、P95延迟、索引大小和标注/训练成本。负例包含相同query跨split、多个真相关文档被当负例、无相关答案、非英语与重复文档。只有隔离正确且目标指标/预算满足预先门槛才继续；若收益依赖query泄漏或公共基准迁移失败，停止，先改数据与验证。

**替代与组合。** 和现有训练平台可衔接checkpoint与逐query预测，避免再建一份不可对齐的Trackio/MLflow记录。无需语义模块时排除该Skill；传统LR/GBDT与现有排序模型更直接。HF MCP仅提供Hub检索、文档、Jobs等外部能力，官方资料已读为V1，本机未连接，不把“可调Jobs”当成“懂你的训练”。[HF MCP官方能力](https://huggingface.co/docs/hub/en/agents-mcp)。

| 重复 / 覆盖不足 | 曝光键精确重复、跨 split 交集、用户/item/session 覆盖；embedding 近邻 | Pandera / Deepchecks 精确检查；Cleanlab 近重复 | 相同 item 多次真实曝光不是应删除的重复；近重复也不等于可合并 |
| 线上 / 训练分布漂移 | 固定参考窗、按渠道/日期/人群分层的统计量与漂移分数 | Evidently | 漂移不等于效果下降，不等于根因；概念漂移可能在边际特征不变时发生 |

建议固定数据接口：`snapshot_id, row_id, impression_id, request_id, user_id_hash, item_id_hash, event_time, feature_available_at, label_deadline, label_snapshot_time, click, conversion, sample_weight, split, channel, model_version`；模型侧另有按 `row_id` 对齐的时间外概率与 embedding。此表是**推荐的试验契约，不是任一工具的原生完整 schema**。

### 1. Pandera：把数据生成规则变成确定性断言

**适用场景。** 新版本 CVR 训练集增加 7 日转化窗口后，检查成熟截止时间、特征可见时间、唯一曝光键、标签取值与权重是否合法；在任何模型训练前输出违反约束的样本。其优势是业务规则可写成 Python 检查，失败可定位到列、规则、样本。官方 [DataFrame Schema 文档](https://pandera.readthedocs.io/en/stable/dataframe_schemas.html) 已读。

**输入 → 输出 / 接口。** pandas DataFrame + `DataFrameSchema` / `Check` → 成功时返回验证后 DataFrame，失败时 `SchemaError` 或 `SchemaErrors`；`lazy=True` 汇集多项错误。本文仅核实 pandas 路径。程序负责规则计算；LLM 可起草规则并解释 `failure_cases`；人批准时间口径、分母和断言，不允许 LLM 在报错后自动放宽阈值。

**代码实查。** [API container.py](https://github.com/unionai-oss/pandera/blob/v0.35.0/pandera/api/pandas/container.py) 核实 `checks, unique, coerce, strict, drop_invalid_rows` 和 `validate(lazy,inplace,sample)`。 [后端 container.py](https://github.com/unionai-oss/pandera/blob/v0.35.0/pandera/backends/pandas/container.py) 核实 dataframe checks 的逐项执行、异常转为错误结果，以及联合唯一性调用 `DataFrame.duplicated`。这能证明已声明规则如何执行，不能证明未声明问题不存在。

**最小接入。** 未来获准试验时使用隔离环境锁定 `pandera[pandas]==0.35.0` 及依赖，Python 要求 [>=3.10](https://github.com/unionai-oss/pandera/blob/v0.35.0/pyproject.toml)。只把导出的测试 DataFrame 送入 schema；保留原始数据，不启用自动 coercion、删行或列过滤；输出错误明细与审计摘要。无需训练、LLM API 或联网服务。本次没有安装。

**最小调用示例（签名 / 语义核实，未执行）。**
```python
import pandas as pd
import pandera.pandas as pa

df = pd.DataFrame({
    "impression_id": ["a", "b", "c"],
    "event_s": [100, 200, 300],
    "feature_available_s": [90, 190, 310],
    "label_deadline_s": [400, 500, 900],
    "snapshot_s": [800, 800, 800],
    "conversion": [0, 1, 0],
})
schema = pa.DataFrameSchema(
    {
        "impression_id": pa.Column(str),
        "event_s": pa.Column(int),
        "feature_available_s": pa.Column(int),
        "label_deadline_s": pa.Column(int),
        "snapshot_s": pa.Column(int),
        "conversion": pa.Column(int, pa.Check.isin([0, 1])),
    },
    unique=["impression_id"],
    checks=[
        pa.Check(lambda d: d.feature_available_s <= d.event_s,
                 name="feature_visible_at_impression"),
        pa.Check(lambda d: d.label_deadline_s <= d.snapshot_s,
                 name="label_window_mature"),
    ],
    coerce=False,
)
try:
    schema.validate(df, lazy=True)
except pa.errors.SchemaErrors as exc:
    print(exc.failure_cases)
```
这是原创的业务规则示例。按规则推导，第三行违反两项时间断言；**未把这个推导冒充运行结果**。真实业务还要检查快照的 ingestion lag、回补策略和时区，不能只靠一个 label deadline 字段。

**边界与误用。** 无时间血缘就无法发现“字段数值看起来正常但用了未来”。联合唯一键选成 user-item 会误删重复真实曝光。只验证随机 sample 不能保证全量无单条泄漏。全局比例 / cross-table join 要自写约束；大量关系验证可留在 SQL/Spark。空表、缺列、NULL、时区、整数溢出都应显式纳入 golden cases。

**总成本。** 开源本地路径无软件订阅费和必需 token 费；主要是规则设计/评审、全量扫描 I/O、DataFrame 内存和错误明细存储。代码 `inplace=False` 默认为复制语义，应计入峰值内存。未来试验计划预留 1–2 人日定义首批 10–20 条规则（估计，非实测）；运行 CPU 秒、RSS、扫描行数、明细大小均待 V3 测量。维护成本在业务时间窗和上游字段变化。

**验收卡。**
- 能力：可重复定位泄漏时间、未成熟标签、重复键和标签域错误。Baseline：现有 SQL / pandas assert 相同规则，不能拿“没有检查”当 baseline。
- 固定条件：同一快照、键定义、时区、观察窗、NULL 语义、行顺序、schema 与依赖 hash；全量小 fixture 及固定 10 万/100 万行合成扩展。
- 正例：各单独植入 1 个未来可用特征、1 个未成熟行、1 个重复曝光键、1 个非法标签；负例：边界等时、同 user-item 不同曝光、成熟零转化、合法 NULL（若规则允许）。
- 指标：逐规则 TP/FP/FN、失败 row_id 集合与 baseline 一致率、异常类型覆盖、wall time / CPU / peak RSS、每百万行成本、人审分钟。硬约束 golden fixtures 要求 100% 命中且 0 误报；这只是小样本正确性门槛。
- 继续：同等覆盖比现有脚本减少重复代码、错误可定位且满足团队运行预算；停止：只生成更漂亮报告但不增加覆盖，或全量开销不可接受。替代：成熟 SQL/Spark 断言 + 结构化错误；多数据源组织级质量治理可选 GX。

### 2. Deepchecks：显式检查 train/test 污染

**适用场景。** 比较两版 CTR 数据切分，检查训练是否含测试曝光 ID，测试是否早于训练最后时刻。官方 [日期泄漏示例](https://docs.deepchecks.com/stable/tabular/auto_checks/train_test_validation/plot_date_train_test_leakage_overlap.html) 已读。这里仅选择相关检查，不以一键 full suite 替代业务切分审计。

**输入 → 输出 / 接口。** 两个 `deepchecks.tabular.Dataset`，声明 `index_name`、`datetime_name`、特征/标签 → `CheckResult.value`（比例）及条件结果，可选展示。LLM 负责选择检查、把结果连回切分版本；程序计算交集和时间比较；人定义应隔离的实体及何种重叠合法。

**代码实查。**
- [DateTrainTestLeakageOverlap](https://github.com/deepchecks/deepchecks/blob/0.19.1/deepchecks/tabular/checks/train_test_validation/date_train_test_leakage_overlap.py) 默认最多抽样 1,000,000 行、seed=42；计算的是 `test_time < max(train_time)`。**相等时间不算泄漏**，也没有自动考虑标签成熟窗/embargo。
- [IndexTrainTestLeakage](https://github.com/deepchecks/deepchecks/blob/0.19.1/deepchecks/tabular/checks/train_test_validation/index_leakage.py) 默认最多 10,000,000 行；分子是**重合的唯一 ID 数**，分母是测试样本行数。测试 ID 若非唯一，不能把这个值解释为泄漏行率。
- [Dataset.sample](https://github.com/deepchecks/deepchecks/blob/0.19.1/deepchecks/tabular/dataset.py) 把请求样本数截到数据长度；构造 Dataset 会复制 DataFrame。[TrainTestCheck.run](https://github.com/deepchecks/deepchecks/blob/0.19.1/deepchecks/tabular/base_checks.py) 支持 `with_display=False`，本例无需模型。

**最小接入。** 未来独立环境锁定 `deepchecks==0.19.1` 及实际能工作的依赖锁文件，不修改训练环境。输入离线 train/test 导出；先用 Pandera/SQL 保证 index 唯一，再指定不小于数据长度的 `n_samples`，输出 machine-readable value 与补充严格时间断言。没有确认新 Python / pandas 组合兼容，不能宣称当前环境已就绪。

**最小调用示例（已核对 0.19.1 源码，未执行）。**
```python
import pandas as pd
from deepchecks.tabular import Dataset
from deepchecks.tabular.checks import (
    DateTrainTestLeakageOverlap, IndexTrainTestLeakage,
)

train = pd.DataFrame({
    "event_id": ["a", "b"],
    "event_time": pd.to_datetime(["2026-01-01", "2026-01-03"]),
    "x": [1.0, 2.0],
})
test = pd.DataFrame({
    "event_id": ["b", "c"],
    "event_time": pd.to_datetime(["2026-01-02", "2026-01-04"]),
    "x": [3.0, 4.0],
})
tr = Dataset(train, index_name="event_id", datetime_name="event_time",
             features=["x"], cat_features=[])
te = Dataset(test, index_name="event_id", datetime_name="event_time",
             features=["x"], cat_features=[])
n = max(len(train), len(test))
date_check = DateTrainTestLeakageOverlap(n_samples=n)
date_check.add_condition_leakage_ratio_less_or_equal(0)
id_check = IndexTrainTestLeakage(n_samples=n)
id_check.add_condition_ratio_less_or_equal(0)
for check in [date_check, id_check]:
    result = check.run(train_dataset=tr, test_dataset=te, with_display=False)
    print(result.value)
```
按所读实现，两项 value 应均为 0.5；这是源码推导，未运行。若业务要求 `max(train_time) < min(test_time)` 且有 7 天 embargo，必须另写该严格断言，不能把当前日期 check 改名后当作完成。

**边界。** 两个框架日期无交叠不能排除 join 未来特征、target encoding 全量 fit、曝光归因跨窗。用户跨 split 是否合理取决于要评估“新用户泛化”还是“未来已有用户”；ID check 不能代替实验设计。采样会漏单例泄漏；大规模场景推荐 SQL 精确交集作权威结果。

**总成本。** 本地无必需服务/token 费；主要是两表复制、抽样、set 交集内存、适配 Dataset、较旧 release 的依赖验证与维护，AGPL 许可记录也需在部署方式明确时评估。计划试验 1–2 人日（估计）；全量交集可移到仓库计算只回传聚合。不要为两条集合/时间断言建立复杂服务。

**验收卡。**
- 能力 / baseline：对齐手写 SQL `INTERSECT`、pandas 唯一键交集和严格时间检查；固定数据、index 语义、sample cap、seed、时间窗、时区。
- 正例：精确重合 ID、早于训练最大时刻的测试行、跨窗 session；负例：互斥 ID、同用户合法跨日、时间恰相等（本工具不会告警，应被严格业务断言捕获）、训练样本少于默认 cap。
- 指标：工具 value 与其**实际定义**一致率、业务规则覆盖、采样漏检率、失败可解释性、wall time / RSS / 成本；测试重复 ID 时必须标出分母差异，不能报“正确泄漏行率”。
- 继续：在已有断言之外形成可复用的报告/条件集，并通过小样本全覆盖；停止：默认采样掩盖关键泄漏、结果被误解，或只有两条已存在 SQL 能力。替代组合：Pandera + 精确 SQL 切分断言，必要时只保留 Deepchecks 报告层。

### 3. Evidently：比较固定参考与当前样本的分布

**适用场景。** 排序模型离线 AUC 下滑，先检查最近批次在渠道、设备、样本权重、预测分数和已成熟标签上是否变化，再定位需要进一步验证的人群。官方明确将无标签时的 feature/prediction drift 视作代理信号，不能当真实效果。[Data Drift 文档](https://docs.evidentlyai.com/metrics/preset_data_drift)

**输入 → 输出 / 接口。** reference/current DataFrame 或 `Dataset`，显式 `DataDefinition`、列类型、方法、阈值 → `Report.run` 的 Snapshot；`dict()` / `json()` / 本地 HTML/JSON 可导出。LLM 负责拟定分层、汇总告警；程序计算统计量；人决定参考期、季节性可比性及行动阈值。本例只使用统计指标，不启用 LLM judge、cloud workspace 或付费 descriptor。

**代码实查。** [DataDriftPreset](https://github.com/evidentlyai/evidently/blob/v0.7.23/src/evidently/presets/drift.py) 接收 `columns, method, per_column_method, threshold, drift_share`；默认漂移列占比阈值 0.5。[PSI](https://github.com/evidentlyai/evidently/blob/v0.7.23/src/evidently/legacy/calculations/stattests/psi.py) 比较 `psi >= threshold`，默认 0.1。重要细节：[分箱代码](https://github.com/evidentlyai/evidently/blob/v0.7.23/src/evidently/legacy/calculations/stattests/utils.py) 在数值参考列唯一值 >20 时，用 reference+current 合并值按 Sturges 生成 bins；尽管函数 docstring 写 reference quantiles，实际代码不是这个口径。不要和团队历史固定 bins PSI 直接判“数值不一致就是 bug”。

官方 [Report 页面](https://docs.evidentlyai.com/docs/library/report) 有 `DataDriftPreset(column=...)` 的例子；指定版本构造签名是 **`columns`**。本文按源码写例，避免复制文档笔误。Snapshot 的 `json` 是方法，本文用源码明确支持的 `dict()`。[Report 源码](https://github.com/evidentlyai/evidently/blob/v0.7.23/src/evidently/core/report.py)

**最小接入。** 未来隔离环境锁定 `evidently==0.7.23`；使用本地两个固定导出快照，显式列映射，选择少量数值/类别列，指定方法与阈值后生成本地报告。每个业务切片分开运行以免总体分布掩盖子群。当前未核实所有 metric 对 sample_weight 的一致支持，因此本方案把权重当待检查列，**不宣称漂移分数已经是加权统计**。

**最小调用示例（已核对 0.7.23 API，未执行）。**
```python
import pandas as pd
from evidently import DataDefinition, Dataset, Report
from evidently.presets import DataDriftPreset

ref = pd.DataFrame({"device": ["app"] * 50 + ["web"] * 50})
cur = pd.DataFrame({"device": ["app"] * 90 + ["web"] * 10})
definition = DataDefinition(categorical_columns=["device"])
reference = Dataset.from_pandas(ref, data_definition=definition)
current = Dataset.from_pandas(cur, data_definition=definition)
report = Report([
    DataDriftPreset(columns=["device"], method="psi", threshold=0.1)
], include_tests=True)
result = report.run(current_data=current, reference_data=reference)
print(result.dict())
```
该类别例可独立手算 PSI 作 baseline；无零频类别，绕开平滑边界，避免把最小例变成复杂分箱测试。真实验收仍须补新类别、零频、NULL 和数值分箱测试。

**边界。** 边际分布不变时条件关系可能改变；分布变了也可能模型性能不变。参考窗、样本量、重复曝光和季节周期改变会改变检测率。默认 50% 列漂移规则可能漏掉唯一关键特征，也可能因大量无关字段报警。百万级样本 p-value 容易显著，不宜自动宣布“必须重训”。应同时看效应量、成熟标签下的指标和固定切片。跨多列/多切片的告警预算与多重检验控制由集成方设计。

**总成本。** 该本地统计路径无必需订阅/token 费；主要是两快照 I/O、逐列统计、报告体积、方法校准和报警处置工时。默认自动选方法会引入迁移解释成本，因此锁定方法更利于回归。计划首轮 1–3 人日定义参考窗、切片与告警预算（估计）；计算时间、RSS、每批误报处理成本需实测。云/LLM功能不在本次成本与推荐范围。

**验收卡。**
- 能力 / baseline：类别 PSI 与独立 NumPy 实现对照；数值 PSI 必须一致分箱和零频平滑；同时比较已有分布监控。固定参考/当前时间窗、采样、列类型、类别集合处理、方法、threshold、版本。
- 正例：设备从 50/50 到 90/10、某一重点切片分数整体平移、新类别涌入；负例：同一数据重排、相同分布多次重抽样、合法节假日参考窗、仅标签关系改变而 X 边际不变（应承认覆盖不足）。
- 指标：数值误差、检测率、无漂移告警率、关键列/切片覆盖、延迟、wall time / CPU / RSS、每批报告大小和人工复核分钟。手算 fixture 要求误差 <=1e-8；在预注册样本量、最小变化幅度与重复次数的模拟分布组上，考虑Monte Carlo误差后的初始目标TPR>=90%、FPR<=5%（工程建议，需按业务代价调整，不是工具保证）。
- 继续：在固定告警预算内比现有监控更早或更精确定位变化，且能用成熟标签复核；停止：告警无法映射到行动、频繁季节误报，或统计口径不可与 baseline 对齐。替代：已有 SQL 分布摘要 + SciPy / NumPy 检验 + 本地报告；Deepchecks 有相邻检查，但不要维护两套不同默认阈值。

### 4. Cleanlab / Datalab：把疑似标签问题排成人工复核队列

**适用场景。** 在标签已成熟、按时间隔离产生预测的 CVR 样本中，发现低标签质量或 embedding 近重复候选，供排查埋点、归因、重复样本、异常渠道；不是自动改标器。官方 [Datalab quickstart](https://docs.cleanlab.ai/stable/tutorials/datalab/datalab_quickstart.html) 要求样本外概率或表征。

**输入 → 输出 / 接口。** 带 label 的 DataFrame/dict + N×K 样本外概率，可加 N×D feature/embedding 或 CSR kNN 图 → `lab.find_issues(...)` 写入对象状态；用 `get_issues("label")`、`issue_summary`、`get_info` 读取。概率列必须按 Datalab 类名排序、逐行严格对齐；二分类不能只给一列正类概率。LLM 生成原因假设和复核摘要；程序产出分数、候选及统计；人结合最终标签/业务日志决定是否错标及如何处理。

**代码实查。**
- [Datalab API](https://github.com/cleanlab/cleanlab/blob/v2.9.0/cleanlab/datalab/datalab.py)：`find_issues` 返回 None，结果储存在对象；不同 issue type 的 score 不能直接横向比较。
- [LabelIssueManager](https://github.com/cleanlab/cleanlab/blob/v2.9.0/cleanlab/datalab/internal/issue_manager/label.py)：提供 pred_probs 时调用 CleanLearning 标签检测；只提供 features 时会构建 kNN 概率并做去自身调整。**这种去自身并不等于推荐场景按时间/用户无泄漏的评估协议**，本方案要求外部提供经过审计的时间外概率。
- [NearDuplicateIssueManager](https://github.com/cleanlab/cleanlab/blob/v2.9.0/cleanlab/datalab/internal/issue_manager/duplicate.py)：基于近邻距离与全体最近邻距离中位数的相对阈值，默认 threshold=0.13、k=10；结果依赖 embedding、距离与样本组成，不是精确业务键重复。

**最小接入。** 未来隔离环境锁定 `cleanlab[datalab]==2.9.0`；首轮只选 `issue_types={"label": {}}`，只喂授权的成熟样本、明确 class order 的时间外概率和 row_id，不重新训练模型、不自动删改标签。第二轮有明确近重复定义再添加 embedding 与 `near_duplicate`。生产量级先估算 N×K 与 N×D 存储；需要 kNN 时记录建图成本与准确性。

**最小调用示例（已核对 v2.9.0 API，未执行）。**
```python
import numpy as np
import pandas as pd
from cleanlab import Datalab

## 仅构造接口 smoke-test 数据；这些手工概率不是实际 OOF 证据。
labels = np.array([0] * 10 + [1] * 10)
pred_probs = np.array([[0.95, 0.05]] * 10 + [[0.05, 0.95]] * 10)
labels[[0, 10]] = 1 - labels[[0, 10]]
data = pd.DataFrame({"row_id": range(20), "conversion": labels})

lab = Datalab(data=data, label_name="conversion")
lab.find_issues(pred_probs=pred_probs, issue_types={"label": {}})
issues = lab.get_issues("label")
print(issues.sort_values("label_score").head())
print(lab.issue_summary)
```
该例只演示已核实调用，不承诺精确检出数量。真实接入必须保存预测生成协议：每行未参与该次模型/特征变换拟合，训练数据严格早于预测观察期，label window 与 embargo 一致；如有 group 约束同时遵守。标准随机 k-fold 不可默认用于有时间依赖的推荐数据。

**概率与采样准入。** 记录诊断快照目标总体、原始与采样正率、采样概率和概率校准集。负采样分布上的概率不能不经检查直接当原曝光总体概率；显式sample_weight列不表示Cleanlab会自动纠偏。特征预处理、target encoding、校准器及超参选择均不能用被诊断期标签。需先在独立成熟校准集检查概率质量，再解释标签疑点。

**边界。** 点击/转化天然随机、正类极稀疏；“预测高但标签0”常常是合法负例。低分可能来自模型欠拟合、失准、分布偏差或少数群体，而非错误标签。没有成熟最终标签时不能区分延迟正例与真负例，更不能由 LLM 补真值。多行为 task 不应只因 Datalab 支持 multilabel 就直接套用；曝光空间和采样权重也可能不满足普通分类数据假设。不能据此自动删去难例并宣称 AUC 提升具有业务意义。

**总成本。** v2.9.0 仓库许可已核为 Apache-2.0；不要沿用旧版本许可印象。开源本地 label 路径无必需付费服务/token，但**时间外预测生成、embedding/kNN、人工复核**通常才是主要成本。已有合格预测时计划 2–4 人日完成对齐与首轮盲审设计（估计）；没有预测则须另计多次训练/推理、GPU小时、存储及等待。复核预算按 K×单样本分钟计，而非仅记录函数耗时。

**验收卡。**
- 能力 / baseline：固定 top-K 人工复核预算，比较随机抽样、模型 loss 排序、`1-p(y)` 排序、已有业务规则；不能只证明“能输出低分样本”。
- 固定条件：同一成熟快照、相同时间外概率、同一模型/校准/类顺序、seed、row_id、采样权重处理、embedding版本；盲审不给审阅者工具分数，复核分歧有仲裁。
- 正例：人工植入已知反转标签、重复数据且标签冲突、受控埋点异常；负例：真实难负例、罕见人群、未曝光 item、不同成熟年龄但并非错标、校准偏移模型。合成反转检出好只能支持 V3，不证明业务噪声发现能力。
- 指标：precision@K、已知错误 recall、相对各baseline增益及按独立用户/请求或时间块重采样的bootstrap CI（与baseline联合比较，不能把相关曝光当独立行）、分人群误报/覆盖、结果稳定性、每个确认问题的人审分钟、训练/推理/建图/CPU/RSS/token总费用；修正后在独立成熟 holdout 看 logloss/AUC/校准及业务指标，不能在发现集自证。
- 继续：预注册预算下 top-K 确认问题率较最强 baseline 的增益下界>0，少数群体未被系统性误伤，且单位确认问题成本可接受；停止：仅复制模型不确定性、依赖泄漏预测、人工确认不足、或指标提升只来自删除难例。替代：成熟标签规则 + loss/self-confidence 排序 + 盲审；精确重复先用键/哈希，只有语义近重复才需 embedding 检测。

本稿未发现能对推荐模型的梯度饥饿、多任务冲突、稀疏更新问题可靠完成“自动取证—区分根因—干预验证”的通用现成工具。应写成**未找到经过本业务验收的端到端能力**，不能声称行业不存在任何研究工具。

### 问题到证据的能力地图

| 问题 | 最低证据 | 工具分工 | 必做区分/干预 |
|---|---|---|---|
| 新特征无收益 | join 命中率/缺失/时间穿越检查，逐样本预测，分群指标 | 数据检查由现有管线；Captum 看使用；torch 看梯度/更新；日志工具关联配置 | 完全没送进模型、重复信息、标签噪声、训练不足、竞争/抑制分别设实验 |

### T1 — PyTorch torch.func + Profiler

**场景与输入输出。** 输入为模型/损失代码、参数和 buffers、固定诊断 batch、任务定义、训练步骤。`functional_call` 配合 `grad` 和 `vmap` 得到参数字典的逐样本梯度；逐任务梯度通常直接对同一次前向的各任务 loss 求 `autograd.grad` 更易与真实训练一致。Profiler 输出算子时间、shape、内存及执行 trace。梯度只观测反向传播，实际更新还要比较 step 前后参数并检查 optimizer/AMP；Profiler 只提供执行证据。[逐样本梯度教程](https://docs.pytorch.org/tutorials/intermediate/per_sample_grads)、[Profiler API](https://docs.pytorch.org/docs/2.15/profiler.html)

**传统方法与 LLM 分工。** PyTorch 计算梯度、夹角和时间；确定性脚本对齐 ID、聚合分群、做数值校验；LLM 负责生成采样脚本草案、解释证据和提出下一项消融。任何“根因”结论需回链到统计、代码位置与干预结果。

**接入与版本。** 在离线训练副本增加短窗口采样；只取代表层/embedding 行/若干任务，避免保留全量 B×P 梯度。官方 release 最新查询结果为 **v2.15.0，2026-10-28**；这不构成升级建议，应沿用业务已固定且兼容的 PyTorch。已读取 tag 下 `torch/_functorch/apis.py`、`functional_call.py`、`torch/profiler/profiler.py`，确认 `grad`、`vmap`、`functional_call` 和 trace 接口。[release](https://github.com/pytorch/pytorch/releases/tag/v2.15.0)、[函数变换源码](https://github.com/pytorch/pytorch/blob/v2.15.0/torch/_functorch/apis.py)、[functional_call 源码](https://github.com/pytorch/pytorch/blob/v2.15.0/torch/_functorch/functional_call.py)、[Profiler 源码](https://github.com/pytorch/pytorch/blob/v2.15.0/torch/profiler/profiler.py)

**待跑最小例（未执行）。** 这个例子检验数值正确性，不检验业务诊断能力：

```python
import torch
from torch.func import grad, vmap

w = torch.tensor([0.2, -0.3], dtype=torch.float64)
x = torch.tensor([[1., 2.], [3., 0.], [0., 1.]], dtype=torch.float64)
y = torch.tensor([1., 0., -1.], dtype=torch.float64)
def one_loss(w, x, y):
    return (x.dot(w) - y).square()
g = vmap(grad(one_loss), in_dims=(None, 0, 0))(w, x, y)
manual = 2 * (x @ w - y)[:, None] * x
assert g.shape == (3, 2)
torch.testing.assert_close(g, manual)

with torch.profiler.profile(
    activities=[torch.profiler.ProfilerActivity.CPU]
) as p:
    with torch.profiler.record_function("toy_diagnostic"):
        vmap(grad(one_loss), in_dims=(None, 0, 0))(w, x, y)
print(p.key_averages().table(sort_by="self_cpu_time_total", row_limit=10))
```

**边界与已知限制。** `vmap` 对副作用、数据相关 Python 控制流、`.item()`、动态 shape 等存在限制；不能为了“能跑”随意把真实 training mode 改成 eval 后仍称真实训练梯度。batchnorm、dropout、自定义 autograd、稀疏 embedding、分布式/编译后模型要逐项对照。Profiler 的 shape/stack 跟踪有开销，trace 中慢不等于不开 profiler 时同等慢。[函数变换限制](https://docs.pytorch.org/docs/2.15/func.ux_limitations.html)、[自定义 autograd 扩展](https://docs.pytorch.org/docs/stable/notes/extending.func.html)

**稀疏更新的额外口径。** padding_idx不贡献lookup梯度可属正常；COO梯度统计应合并重复ID（coalesce），不要将全表densify。区分grad=None、零梯度、momentum/weight decay与实际step。max_norm可在forward原地修改权重，应分别记录forward前后、backward后和optimizer step后。sparse optimizer支持和实际vmap路径需单独验收；dense toy成功不能外推。[Embedding行为](https://github.com/pytorch/pytorch/blob/v2.15.0/torch/nn/modules/sparse.py)

**全部成本与预估。** 使用现有 PyTorch 无独立服务订阅；成本包括工程接入、额外反向/显存、短 trace 存储、离线训练重放、兼容适配、解释/复核人力及可选 LLM token。若真保存 FP32 全梯度，粗略仅数值存储就为 `4×batch_size×参数数` 字节（例如 B=32、P=10^8 约 12.8 GB，未含激活/optimizer），必须采样或聚合。已有训练脚本的单机 PoC 估计 1–3 人日；自定义稀疏/分布式适配另算。均为工程规划估算，非实测报价。

**验收与继续/停止。** 固定线性解析例、普通 MLP、两任务共享塔、稀疏 ID toy 四个套件；和朴素逐样本反向/解析值比较（FP64 初始容差 1e-6）；注入 detach、漏 optimizer、lr=0、相反任务、低曝光 ID、正常收敛等正负例。逐任务梯度需在相同 loss reduction/AMP unscale 口径比较；分别报告异常定位正确率、负例误报、层/任务覆盖、每窗口耗时/显存/样本数。试点预算建议≤3 人日；若代表算子不能数值对齐、不能区分正常低频零梯度、或采样窗口开销超预设上限且不可降低，停止扩展，退回逐层 autograd/hook。通过只是 V3，V4 还需真实失败案例的干预验证。

**替代组合。** 简单任务先 `torch.autograd.grad` + 参数差分 + CSV/已有日志；需逐样本方差且受支持模型可试 BackPACK；Profiler 已证明是系统瓶颈后才评估 compile、量化或导出。

### T3 — Captum（特征与样本归因）

**场景与输入输出。** 新特征无收益时，检查模型是否使用它、在哪些人群/样本上依赖它；输入模型 forward、特征样本、target、合理 baseline 与 feature group mask；输出逐输入归因。`IntegratedGradients.attribute(..., n_steps, internal_batch_size, return_convergence_delta=True)` 提供归因和积分近似 delta；`FeatureAblation.attribute(..., feature_mask, perturbations_per_eval)` 输出把组替换为参考值后的输出变化。[IG 文档](https://captum.ai/api/integrated_gradients.html)、[分组消融文档](https://captum.ai/api/feature_ablation.html)

**分工与接入。** 传统算法执行积分/扰动；统计代码分群聚合与敏感性复核；LLM 整理异常样本和设计消融。排序模型须先明确定义解释的是单 item score、pairwise margin 还是 listwise loss；ID 输入不能对整数 ID 求梯度，应使用 embedding/layer attribution 或合法的特征组扰动。保留原模型，仅在离线快照评估。解释“已训练模型怎样预测”不等于训练时删除该特征后的模型收益。

**版本与代码。** 官方 release 为 **v0.9.0，2026-04-17**，Python≥3.10、PyTorch≥1.13；旧 `captum.insights` 被移除，FeatureAblation/FeaturePermutation 跨输入 tensor 的联合归因变为默认行为，跨 tensor 的 mask ID 要检查，不能假定旧代码不受影响。已读 v0.9.0 `integrated_gradients.py`、`feature_ablation.py`。[release](https://github.com/meta-pytorch/captum/releases/tag/v0.9.0)、[IG 源码](https://github.com/meta-pytorch/captum/blob/v0.9.0/captum/attr/_core/integrated_gradients.py)、[FeatureAblation 源码](https://github.com/meta-pytorch/captum/blob/v0.9.0/captum/attr/_core/feature_ablation.py)

**待跑最小例（未执行）。**

```python
import torch
from captum.attr import IntegratedGradients, FeatureAblation
def score(x):
    return 2 * x[:, 0] - 3 * x[:, 1]
x = torch.tensor([[4., 5., 7.]])
expected = torch.tensor([[8., -15., 0.]])
a, delta = IntegratedGradients(score).attribute(
    x, baselines=torch.zeros_like(x), n_steps=32,
    internal_batch_size=8, return_convergence_delta=True)
b = FeatureAblation(score).attribute(x, baselines=0)
torch.testing.assert_close(a, expected)
torch.testing.assert_close(b, expected)
assert delta.abs().max() < 1e-5
```

**边界与已知问题。** baseline 不合理会导致离开数据分布；相关/冗余特征可互相替代；IG delta 小只代表所用积分的 completeness 近似，不能证明解释符合业务因果。Captum FAQ 明确部分基于 hooks 的方法对 functional 激活、模块复用和 JIT 有限制。检索到尚开放的 `sensitivity_max` mixed-baselines 错误报告 #1944 与 bare-Tensor 输出错误报告 #1938；这是用户报告，不据此断言本稿 IG/ablation 均受影响，新增稳定性指标前需复现。[FAQ](https://captum.ai/docs/faq)、[issue #1944](https://github.com/meta-pytorch/captum/issues/1944)、[issue #1938](https://github.com/meta-pytorch/captum/issues/1938)

**全部成本与预估。** BSD-3-Clause、无工具订阅费；主要是 PyTorch forward/backward、n_steps×样本规模、特征组扰动次数、显存和脱敏样本存储、业务 baseline/mask 设计、人工复核、可选 LLM token。IG 的成本大致随积分点数增长，ablation 随特征组数增长；用 internal batching 控制峰值而非假设免费。单模型 PoC 1–3 人日；若要业务有效反事实则成本更多。

**验收与继续/停止。** baseline 为手工线性解析/逐组置换脚本。固定正例为已知信号、故意错接特征、目标分群依赖变化；负例为纯噪声、重复强相关特征、未曝光 ID。先通过解析 toy；再在固定 1,000 个脱敏样本、3 个合理 baseline 上比较归因、top-k 排序稳定性、分组扰动输出差；记录覆盖、耗时/显存与 token。归因发现必须用删除/重训/替换的独立验证支持。若改 baseline 就反转结论、分组不合法、或和重训方向持续矛盾，则停止把它作为选特征依据，仅保留解释证据。

**替代组合。** 对树模型或不方便反向的模型，先业务分组 permutation/ablation + 离线 retrain；Captum 不是必需依赖。与 torch 梯度采样结合能区分“模型当前没用”和“训练管线没更新”，仍不能自动归因。

### T4 — BackPACK（梯度方差与曲率的定向补充）

**场景与输入输出。** 已确认优化信号有问题后，量化样本间梯度差异、噪声或局部曲率。对模型和 loss `extend(...)` 后，在 `with backpack(BatchGrad())` 内 backward，可从参数的 `grad_batch` 取 `[batch, *parameter_shape]`；还有 `SumGradSquared`、`Variance`、`BatchL2Grad` 及 GGN/Hessian 扩展。数学计算由库执行，LLM 只整理统计与候选实验。[扩展 API](https://docs.backpack.pt/en/master/extensions.html)

**版本与接入。** 最新 GitHub release 查询为 **1.7.1，2024-11-15**；package 名为 `backpack-for-pytorch`，Python≥3.9、torch≥2.2.0，MIT；最新 release 较早，应核业务版本兼容，不能由依赖下限推出已验证 PyTorch 2.15。已核 tag 1.7.1 `BatchGrad` 实现、module extension map、pyproject/changelog。在线 docs 页标题仍显示 1.2.0，存在文档版本标注与 release 不同的问题，应优先以固定 tag 源码/测试为准。[release](https://github.com/f-dangel/backpack/releases/tag/1.7.1)、[源码](https://github.com/f-dangel/backpack/blob/1.7.1/backpack/extensions/firstorder/batch_grad/__init__.py)、[依赖](https://github.com/f-dangel/backpack/blob/1.7.1/pyproject.toml)

**待跑最小例（未执行）。**

```python
import torch
from backpack import backpack, extend
from backpack.extensions import BatchGrad
torch.manual_seed(7)
model = extend(torch.nn.Linear(2, 1))
loss_fn = extend(torch.nn.MSELoss(reduction="sum"))
x, y = torch.randn(3, 2), torch.randn(3, 1)
with backpack(BatchGrad()):
    loss_fn(model(x), y).backward()
for p in model.parameters():
    assert p.grad_batch.shape[0] == 3
    torch.testing.assert_close(p.grad_batch.sum(dim=0), p.grad)
```

下一步必须再与朴素逐样本反向逐元素对比；仅 sum 一致不足以证明每个样本都正确。`mean` reduction 会带 `1/N` 缩放，不能与未经缩放的 torch.func 单样本梯度直接比较。

**稀疏表的明确限制。** BackPACK 1.7.1 的 Embedding 导数要求 `padding_idx=None`、`max_norm=None`、`scale_grad_by_freq=False`、`sparse=False`；其他配置抛 NotImplementedError。实现构造依赖整个词表大小的dense delta，大词表开销不能按触达ID数估算。真 `sparse=True` 推荐Embedding不进入该工具首轮；用真实训练autograd/hook与参数差分，不通过改配置让测试通过。[固定版本Embedding实现](https://github.com/f-dangel/backpack/blob/1.7.1/backpack/core/derivatives/embedding.py)

**边界与已知问题。** 单样本梯度假设 loss 能按独立样本相加，training-mode batchnorm 混合样本时需重新定义量。官方支持列表分一阶与二阶，不能以“nn.Module 支持”泛化到任意自定义/Transformer/稀疏模型。开放 issue #346 询问 LLM 支持，#350 涉及 weighted CE 的二阶量，#344 报告 ResNet 的 DiagHessian 模块不支持；属于兼容性线索，不是本稿已复现结果。[支持层](https://docs.backpack.pt/en/master/supported-layers.html)、[#346](https://github.com/f-dangel/backpack/issues/346)、[#350](https://github.com/f-dangel/backpack/issues/350)、[#344](https://github.com/f-dangel/backpack/issues/344)

**全部成本与预估。** 无订阅费；库依赖与升级维护、hook/graph 适配、额外反向和内存、完整 B×P 梯度存储、二阶计算、人工校验及可选 LLM token 均计入。优先 BatchL2Grad/Variance 等统计而非长期保存全梯度，但实际是否节省必须量测。普通受支持网络 PoC 1–2 人日；复杂稀疏/共享权重/自定义算子可能需要数日以上，设上限而非持续补洞。

**验收与继续/停止。** baseline 为朴素 autograd 和 torch.func。固定 Linear/MLP/实际代表层；sum 与 mean 两种 reduction；故意 unused parameter、正常低频 embedding、training-mode BN 负例；数值误差、层覆盖、显存、墙钟记录。预算建议 2 人日，代表算子不支持或默默缺梯度则停止；若只需要范数/夹角且 torch.func 已足够，不新增依赖。业务 V4 还需证明方差或曲率信息改进了干预决策。

**替代组合。** 首选 torch.func/常规 autograd；只有需要 BackPACK 特有二阶量且支持良好时才引入，不同时叠加两套 hook 作为默认基础设施。

### T5 — Microsoft RD-Agent（自主实验执行的研究候选）

**类型与场景。** 独立 LLM 应用，包含研究/开发/执行/反馈循环；不是一个现成通用 Skill，也不是只读 MCP。可研究自动完成已限定的数据科学任务、特征工程和模型调参。不要用“会写 PyTorch”替代“会诊断梯度机制”，也不能用项目 README 的 MLE-bench 成绩推算推荐模型线上收益。[官方仓库](https://github.com/microsoft/RD-Agent)、[数据科学场景文档](https://rdagent.readthedocs.io/en/latest/scens/data_science.html)

**输入输出及分工。** 输入任务说明、训练/开发数据、合法特征、指标定义、时间/算力/尝试上限、独立评估器及 LLM backend；输出假设、实现代码、实验日志、候选模型/特征和评分。LLM 提假设与写代码；执行器训练；固定评估器打分；人类把守数据切分、目标和最终效果。工具可循环优化已暴露的评估指标，因此业务保留集必须由外部独立评估，不能反复把最终测试集喂回 agent。

**版本与实际接口。** 官方 release 为 **v1.0.0，2026-09-23**。已读该 tag `rdagent/app/cli.py` 与 `app/data_science/loop.py`，CLI 真实存在 `data_science`、`general_model`、`llm_finetune` 等命令；`data_science` 有 `--competition`、`--loop-n`、`--step-n`、`--timeout`、`--checkout/--no-checkout`。源码说明 loop/step 上限缺省时可持续运行，必须显式限预算。README 某处仍给 `general_model <paper URL>`，但 v1 CLI 参数名为 `report_file_path`，release 也强调文件上传约束，显示应核实际接口而非照抄宣传例。[release](https://github.com/microsoft/RD-Agent/releases/tag/v1.0.0)、[CLI 源码](https://github.com/microsoft/RD-Agent/blob/v1.0.0/rdagent/app/cli.py)、[循环源码](https://github.com/microsoft/RD-Agent/blob/v1.0.0/rdagent/app/data_science/loop.py)

**接入与待跑最小例（未安装/未配置/未执行）。** 需单独 Linux/Docker 工作区和显式 LLM backend 配置；先以官方自定义数据格式准备公开小型 tabular fixture，保留独立 holdout 与评估脚本；只在隔离环境运行拟定命令：

`toy-fixed-split` 是需要自行准备的 fixture 名，不是仓库自带数据集。应先通过该固定版本 `--help` 与时间解析测试确认参数，再试一次受限 loop。此例只是最小接入规格，不能标成已跑通。官方自定义数据流程本身需要数据准备脚本、description、submission 格式和评估脚本。[自定义数据指南源码](https://github.com/microsoft/RD-Agent/blob/v1.0.0/docs/scens/data_science.rst)

**边界与已知问题。** 生成代码会运行并使用算力；用户未授权时不能在现有环境直接尝试。v1 release 包括执行/归档/UI 身份验证加固，当前开放 issue 中仍有 workspace 路径、错误处理等报告；开放状态不代表固定版本一定有漏洞，需按 tag 复现。真实约束是执行隔离、评估数据隔离、失败/重试预算与可复现日志。对本项目先验、稀疏 ID 和多任务机制没有开箱保证。[v1 release](https://github.com/microsoft/RD-Agent/releases/tag/v1.0.0)、[issue #1473](https://github.com/microsoft/RD-Agent/issues/1473)、[issue #1475](https://github.com/microsoft/RD-Agent/issues/1475)

**全部成本与预估。** MIT，无项目许可证订阅费；需 LLM 推理和 embedding token、GPU/CPU 训练与失败重试、容器镜像/数据存储、评估器搭建、隔离设施、日志审阅、实验复现与版本维护。总成本公式：`工程人时 + 审阅人时 + Σ(模型token费用) + Σ(训练/重试机器小时×单价) + 存储/平台费`。不要引用其特定量化论文“低于10美元”的结果作为推荐模型预算。单任务受限 PoC 估计 3–5 人日准备，不含正式训练；先限定 3 次候选/单次30分钟/每日模型费用上限，由真实计量决定下一阶段。

**验收与继续/停止。** baseline 为人工工程师+现有编码 Agent+固定3次实验预算，保持同数据/模型初始点/硬件/种子/LLM预算。正例：有已知可修 bug、可预见收益的交互特征；负例：标签置乱、伪特征、数据泄漏诱饵、无益扩容。正确性需能复现代码与分数、无使用隐藏标签、产物完整；覆盖看诊断任务完成率；效率看首次有效实验时间、每有效候选人时/机器时/token；模型效果看独立 holdout 和关键切片，多 seed 后报告均值与方差。若只会增加实验量却不减少总成本、收益不超同预算 baseline、泄漏/越界或无限重试，则停止。仅公开 benchmark 不能越过 V4。

**替代组合。** 现有编码 Agent 执行人工制定的实验矩阵 + 只读日志 MCP + torch/Captum 数值工具，通常更适合先建立可信诊断闭环；以后再评估把假设生成交给 RD-Agent。

### 执行与效率补充（非本轮重点卡）

- **torchao**：传统量化/稀疏库，官方当前页面显示 0.17，核到文档 V1，未核 release/源码、未运行。`quantize_` 配合 `Int8DynamicActivationInt8WeightConfig` 等是具体接口；适用模型/设备后端决定收益，prototype 与稳定接口要区别。它解决算力/显存成本，不直接解决新特征无收益。[推理工作流](https://docs.pytorch.org/ao/stable/workflows/inference.html)
- **ONNX Runtime quantization**：传统部署优化工具，V1。官方文档给出校准/量化、精度损失调试与执行后端约束；某些硬件可能无加速甚至变慢。只有 Profiler 与真实 serving benchmark 显示瓶颈匹配后，才比较 FP32/BF16 与量化版的逐样本输出差、AUC/NDCG/校准和端到端 P95。[量化与性能边界](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)

每次工具 PoC 固定记录：能力目标、可运行 baseline、数据/split/commit/seed、正例/负例、期望数值/判断、样本/层/任务覆盖、工具与模型版本、实际耗时/显存/CPU/GPU小时/token/平台费、人工分钟、失败重试、继续或停止决策。将“工具算对了”“LLM 解释有证据”“修复在 holdout 有收益”“线上收益”分四步验收，不合并。

## 实验设计、结果解读与排序决策：只读工具评估

证据截止：2026-11-07。研究动作仅浏览官方文档、GitHub release、指定 tag 源代码和测试；没有安装依赖、启动 MCP、修改配置、读取企业数据或连接生产。以下示例是**经文档/源码核对但未在本机执行的验收方案**。所有主卡最高 V2；不能写成 V3“跑通”，更不能写成 V4“业务有效”。

证据阶梯：V0 搜索线索；V1 打开官方原文；V2 固定版本的接口/实现/测试核对；V3 在隔离环境真实运行最小例并保存日志；V4 在授权业务数据或真实工作流上，按冻结baseline验证某项能力和成本；验证结果可以有效，也可以无效。必须标明所验证的是分析速度、正确性、实验效率、离线模型效果还是线上收益。V3 的 toy 成功不证明 V4。

### 建议顺序与问题边界

|优先级|组件|真正解决的问题|类别与研究结论|
|---|---|---|---|
|P1|MLflow Tracking + 官方 MCP|找回每次实验的数据、代码、候选集、指标口径与失败记录；缩短对比排查时间|传统软件 + 官方 MCP，V2；优先只读实验账本，不能靠它验证因果收益|
|P1|GrowthBook stats + 官方 experiments skill/MCP|A/B 设计约束、结果健康检查与可追溯解释|传统统计引擎 + 官方 Skill + 官方 MCP，均 V2；最适合“读已计算结果”，不要自动刷新/上线|
|P2|Optuna core；MCP 后置|在固定预算下搜索排序超参/融合权重，记录有效/失败 trial|传统优化程序 + 官方 MCP，V2；核心库先试，MCP不是搜索质量来源|

离线涨、线上不涨时，先固定评估目标/分母/时间窗，检查训练及标签泄漏、候选集合变化、打分校准与最终排序变化、曝光和随机化单位、延迟转化成熟度、SRM与跨桶污染；再问功效、异质性、竞争/供需干扰。AUC/LogLoss/NDCG 衡量不同问题；对曝光样本的拟合进步未必改变 top-K，更不等于增量收益。SRM 是报警器：通过 SRM 不证明日志正确，失败后也不能用 CUPED、重加权或 LLM 解释“救活”错误数据。这个排查顺序是本报告的工程判断，须由指标负责人复核。

### 卡 1：MLflow — 实验账本与只读比较

**适用场景与分工。** 对“模型 B 的离线收益来自哪次特征/样本/候选变更”“相同 split 下最稳且可部署的 5 次 run”做证据检索。程序保存并读取 run/metric/artifact；LLM整理比较表、标出不可比项并提出下一步假设；人决定指标契约、上线门槛及实验范围。不可由 LLM改写历史指标或根据最大单次指标自动晋级模型。Tracking 官方定义包含参数、代码版本、指标与产物，不会自动保证你记录了数据版本/业务口径：[Tracking 原文](https://mlflow.org/docs/latest/ml/tracking/)。

**版本/接口实证。** 固定 [v3.18.0](https://github.com/mlflow/mlflow/releases/tag/v3.18.0)，2026-11-04，commit `ba41106d110b67096384da12b6b85473457598db`；Apache-2.0。官方 MCP仍标 experimental，最低 3.5.1，但不应据此把所有新工具写成从 3.5.1 就存在。v3.18.0 [MCP server.py](https://github.com/mlflow/mlflow/blob/v3.18.0/mlflow/mcp/server.py) 明确注册 experiments/runs/models/deployments 等分类；`MLFLOW_MCP_TOOLS="experiments,runs"` 是工具分类过滤，**不是只读授权**。这些分类含 create/delete/restore；不要仅设置分类就称安全只读。[官方 MCP 文档](https://mlflow.org/docs/latest/genai/mcp/)

已对照 [experiments.py](https://github.com/mlflow/mlflow/blob/v3.18.0/mlflow/experiments.py)、[runs.py](https://github.com/mlflow/mlflow/blob/v3.18.0/mlflow/runs.py) 及 schema 生成器核实：

|MCP 工具|实参|真实返回/限制|
|---|---|---|
|`search_experiments`|`view` 默认 `active_only`；`max_results` 整数可省|文本表格，不是保证结构化 JSON|
|`get_experiment`|`experiment_id` 或 `experiment_name` 二选一；`output="json"`|JSON 内容位于工具文本输出；包含 tags、位置等|
|`list_runs`|`experiment_id:string` 必填；`view` 可省|文本列表；此封装未提供 filter/max_results 参数，不适合大规模扫库|
|`describe_run`|`run_id:string` 必填|run info/data 的 JSON 文本；不是全量 metric history|

最小只读调用（**调用形状示例，不是本会话已注册工具**）：

```json
{"name":"get_experiment","arguments":{"experiment_id":"<已知测试实验ID>","output":"json"}}
{"name":"describe_run","arguments":{"run_id":"<已知测试run ID>"}}
```

批量比较建议程序用 `MlflowClient.search_runs(experiment_ids, filter_string, order_by, max_results, page_token)` 和 `get_metric_history(run_id,key)`，只把选定结果交给 LLM；不要假设 MCP 的 `list_runs` 等于 Python搜索 API。最小接入是现有导出快照/测试 Tracking Server + 经服务端 ACL 验证的只读身份 + 客户端读取工具 allowlist；若没有既有 MLflow，可先统一本地 JSON/CSV 实验 manifest，不必为聊天另起一套服务。

**输入/输出契约。** 输入至少有 run_id、code SHA、数据/特征/标签版本、时间 split、候选集版本、指标定义哈希、随机种子、训练预算、NDCG/LogLoss/校准/分群指标、预测与特征计算延迟、线上实验ID。输出比较表每一项带 run_id 和证据字段；口径或 split 不同须标“不可直接比较”，缺失记 unknown。训练日志和模型 artifacts 默认不整包传入 LLM。

**部署、数据流、成本与边界。** 自托管可把 SQL 元数据、对象存储 artifacts 保留内部；MCP/SDK读取的文本会继续进入 LLM上下文，因此只读不等于不外传。只读权限不能仅靠 prompt；应在测试身份上实际拒绝写入并检查审计。`mlflow mcp run` 是本地进程路径，别臆造远端 `/mcp` 自动可用；[远端 MCP feature request](https://github.com/mlflow/mlflow/issues/25798) 也说明传输部署应分开核实。成本为元数据DB/对象存储/服务运维 + ETL规范 + 网络/LLM tokens；大模型权重/全量预测不要逐轮读。3.18 release含数据库迁移注意事项，本次不升级任何服务。替代：已有 W&B/内部平台有合格账本则复用；组合：Optuna产 trial→MLflow run；GrowthBook experiment_id→同一 manifest。

**V3→V4 验收设计（建议阈值，非已达成结果）。**

- 固定条件：冻结 20–50个脱敏 runs、同一个 schema、同一 LLM/model/prompt/温度/输入上限；10个问题对比“人工查 UI/导出表”baseline，重复3次；人工金标独立制定。
- 正例：相同split找符合延迟约束的最佳run；追溯特征变更；取 metric history而非只读最后值。负例：指标同名异义、数据版本缺失、时间split不同、artifact不存在、权限拒绝、旧快照。
- 正确性：关键数字与 SDK导出100%一致；所有数字可追溯；所有故意不可比样本被阻止直接排名；写工具调用0、生产访问0。覆盖不足时不能凭“10题全对”扩权。
- 成本/耗时：记录每题p50/p95耗时、调用数、输入输出tokens、拉取字节、人工复核分钟；建议知识检索试点在准确性不退化下中位耗时降≥30%才继续。
- 继续：可追溯与权限测试全过，至少复现一段历史排查。停止：遗漏关键不可比条件、输出无来源数值、需要广泛写权限才能完成只读问题。业务收益另经线上实验，检索省时不等于CTR上涨。

### 卡 2：Optuna — 固定预算的超参/权重试验

**场景/分工。** 校准层参数、模型超参、规则融合权重的离线搜索；避免LLM凭经验在高维空间随意试值。人定义搜索域、约束、时间切分与总GPU预算；Optuna sampler选择trial，训练评测程序计算指标；LLM检查搜索空间遗漏、汇总失败模式/敏感性。候选集和测试集必须固定；LLM不计算损失、不把业务test集反复喂给搜索。

**证据/版本。** [core v5.0.0](https://github.com/optuna/optuna/releases/tag/v5.0.0)，2026-09-07，commit `01ddd17ab9f36c3d2817aed9afe376e1cb047d35`；MIT。5.0更换默认sampler配置，多目标默认改为TPE；显式记录sampler/seed而非依赖默认行为。另有官方 [optuna-mcp v0.2.0](https://github.com/optuna/optuna-mcp/tree/v0.2.0)，2025-11-10，commit `1396061e9b0372a67832048f24f3697c4058e1f2`，MIT。这是官方MCP，但不是只读分析器，也不是独立LLM优化模型。

**接口与实际最小路径。** Core `create_study`→`study.optimize(objective,n_trials,timeout,n_jobs)` 或 ask/tell；输入分布与单/多目标函数，输出 `FrozenTrial`、states、params、objective values、Pareto集合。官方 [最小二次函数例](https://optuna.readthedocs.io/en/v5.0.0/tutorial/10_key_features/001_first.html) 可在将来的隔离已装环境改成明确seed版本：

```python
import optuna
def objective(trial):
    x = trial.suggest_float("x", -10, 10)
    return (x - 2) ** 2
study = optuna.create_study(direction="minimize",
    sampler=optuna.samplers.TPESampler(seed=7))
study.optimize(objective, n_trials=100, n_jobs=1)
print(study.best_params, study.best_value)
```

这验证调用链和目标方向，不验证CTR收益，也不保证复现网页上的随机输出。真实接入只需将 objective换成已经可复现的现有训练/评估入口；离线延迟不能直接冒充线上p99，最后仍需独立压测。

[MCP源码](https://github.com/optuna/optuna-mcp/blob/v0.2.0/optuna_mcp/server.py) 已核实的 schema：`get_all_study_names()`→StudyResponse列表；`create_study(study_name:string,directions?:[minimize|maximize])`创建或`load_if_exists=True`装载；`ask(search_space:dict)`→trial_number/params；`tell(trial_number:int,values:float|list[float])`写完成值；`get_trials()`→CSV字符串；`best_trial()`/`best_trials()`→结构化trial。`ask`分布形状示例为 `{"x":{"name":"FloatDistribution","attributes":{"step":null,"low":-10.0,"high":10.0,"log":false}}}`，不是自然语言范围。

严格只读能力有缺口：current study初始为None，`get_trials`依赖它，官方通过`create_study`设定；没有核实到独立只读`load_study` MCP工具。只有已配置存储时 `get_all_study_names {}` 可作为直接只读探针；不要为“选study”调用潜在创建操作。优先用现成CSV/JSON导出或受限 SDK `load_study`适配器，或只在一次性本地副本验证完整MCP。原README一处SQLite配置示例缺逗号，不能原样复制；本次不生成安装配置。

**规模/成本/边界。** core可内存起步；并行使用合适持久存储，官方FAQ不推荐SQLite支撑高并发；固定seed仍不能消除异步调度的不确定性。[FAQ](https://optuna.readthedocs.io/en/v5.0.0/faq.html) v5 `Trial.report/should_prune`仍不支持多目标，不能同时承诺多目标Pareto+内置逐步pruning，需明确实现策略。[v5 trial源码](https://github.com/optuna/optuna/blob/v5.0.0/optuna/trial/_trial.py) 排序任务时过早prune会偏爱早熟但最终差的配置。

官方 [MCP依赖](https://github.com/optuna/optuna-mcp/blob/v0.2.0/pyproject.toml) 要求Python≥3.12，并含torch、plotly、kaleido等；比core重，且`optuna>=4.2.1`无上界不等于已证明与5.0全部兼容。依赖体积、渲染环境、CPU/GPU训练、失败重跑、存储、人力复核和LLM tokens均计成本；用MCP逐个编排每次训练可能只增加时延。内部训练数据留程序环境，仅分布与摘要进入LLM。替代：低维空间先与等预算随机搜索比较；已有Ray Tune/内部调参器则不因MCP重复建设。组合：Optuna负责搜索，MLflow保存版本与产物。

**完整验收。**

- Baseline：同总墙钟/GPU时预算的随机搜索 + 当前人工最佳配置，trial数作为结果；另做等trial数对照并报告实际耗时；冻结训练/验证/最终测试时间段、候选集合、机器、并行度、指标和预算。至少5个seed，报告分布及失败trial，不只展示单个最好值。
- 正例：二次函数方向正确；人工最佳配置预置后可检索；可恢复试验记录；约束内Pareto可复算。负例：NaN/失败/OOM、目标方向反了、重复配置、延迟超标、无可行点、最后测试集泄漏、把multiobjective传给`should_prune`。
- 正确性：目标值逐trial与独立评测一致；计数/状态/预算一致；任何违反硬约束配置不得进入候选；pruning策略需在小规模“不剪枝”对照验证不丢最终优胜。
- 耗时成本：真实训练秒/GPU时、sampler开销、失败率、重试次数、LLM参与次数、存储字节；算总成本而不是只测建议参数用时。
- 继续：验证集提升跨seed稳定，最终留出测试与护栏不退化，并在固定预算下优于随机基线才进入影子/线上实验。停止：优势只来自多跑预算、泄漏或固定一次seed；采样成本高过节省；业务日志不支持候选策略评估。best_value不是业务验证；固定业务holdout上的受控搜索验证与线上因果收益分开记录。

### 卡 3：GrowthBook — 统计结果、实验 Skill 与只读 MCP

**场景与真实分类。** 用于“这个实验当前能否解释”“总体不显著是否因为功效不足或口径错误”“主指标/护栏如何共同决策”。传统 stats engine计算；官方Skill规定流程；MCP取现有结果；LLM组织结论、限制和下一步；人预注册主指标/MDE/最小运行周期/随机化单位/停止规则并作上线决策。不是独立LLM统计应用，也不能用生成式模型代替置信区间、p值或SRM。

**固定版本。** 主仓库 [v5.2.0](https://github.com/growthbook/growthbook/releases/tag/v5.2.0)，2026-11-03，`0bd125f5a1df8dcde5b1dd1996bc0bc7e1b1e73d`；`packages/stats`在MIT部分，enterprise目录另受商业许可。[LICENSE](https://github.com/growthbook/growthbook/blob/v5.2.0/LICENSE) 官方 [MCP v2.2.0](https://github.com/growthbook/growthbook-mcp/tree/v2.2.0)，2026-10-06，commit `51eae8b01b697571e47083e6ebf3757d5ab604bf`，MIT；其 [agent-skills.lock.json](https://github.com/growthbook/growthbook-mcp/blob/v2.2.0/agent-skills.lock.json) 固定Skill commit `7a84f338fe217b20641cdc5c01b5b37f0b950527`。Skill源码也是MIT。MCP、Skill与stats分别版本化，主产品升级不能证明客户端包同步升级。

**schema/最小只读读取。** [v2.2.0 tools.ts](https://github.com/growthbook/growthbook-mcp/blob/v2.2.0/src/tools.ts)实际四工具：

|工具|输入|输出及语义|
|---|---|---|
|`growthbook_list_skills`|`{}`|名称/描述的JSON文本|

官方 [experiment-analyze](https://github.com/growthbook/skills/blob/7a84f338fe217b20641cdc5c01b5b37f0b950527/skills/experiments/references/experiment-analyze.md)给出了实际结果路径：

**关键发现：Skill写着Reads only，但步骤会写。** 固定commit的analyze子技能在快照过期或缺失时会POST `/api/v1/experiments/{id}/snapshot`，再轮询新快照；会产生状态变化与仓库计算成本。本任务只读范围必须覆盖这一步：仅GET已有结果并注明过期；缺快照就返回“未获得可解释结果”，不刷新。另有旧文章把2.x写成三个工具`growthbook_call_api`，不能照搬；以这里已核实tag四工具为准。

**最小统计计算例（未运行）。** 可在未来隔离环境使用固定主仓库stats源码；不假设它有稳定独立PyPI发行API。以下改写自 [官方频率学测试](https://github.com/growthbook/growthbook/blob/v5.2.0/packages/stats/tests/frequentist/test_tests.py)，输入为**随机化单位汇总**，不是把每次曝光当独立用户：

```python
from dataclasses import asdict
from gbstats.models.statistics import SampleMeanStatistic
from gbstats.frequentist.tests import FrequentistConfig, TwoSidedTTest
a = SampleMeanStatistic(sum=1396.87, sum_squares=52377.9767, n=3407)
b = SampleMeanStatistic(sum=2422.7, sum_squares=134698.29, n=3461)
r = asdict(TwoSidedTTest([(a, b)],
    FrequentistConfig(difference_type="relative")).compute_result())
print(r)
```

官方测试的5位舍入expected为`0.70732`，区间`(-0.03526,1.44989)`，pValue `0.06191`。这些是**上游fixture预期，非本机执行记录**。不要把absolute和relative两种差异用同一标准误公式硬比。[统计定义](https://docs.growthbook.io/statistics/details) 序贯检验与固定终点检验的口径不同；多指标/分群探索需多重比较控制；CUPED需要合格处理前协变量，不能修补坏随机化。[序贯](https://docs.growthbook.io/statistics/sequential)、[CUPED](https://docs.growthbook.io/statistics/cuped)

**部署/权限/全成本。** 最小试点复用历史导出的结果JSON；有现成GrowthBook才连接测试租户只读OAuth/受限PAT。官方MCP支持Cloud OAuth与自托管stdio/HTTP；本地包Node≥18。业务仓库→SQL聚合→GrowthBook服务快照→MCP→LLM上下文；字段裁剪、实验范围限制和仓库只读身份都必要。自托管仍有DB/容器/备份/安全升级成本；Cloud价格/Enterprise功能需实际套餐确认；refresh会产生warehouse扫描与等待。MCP与Skill不能把收费/私有beta功能变成免费可用。[MCP原文](https://docs.growthbook.io/integrations/mcp)

**排序专属增补：interleaving暂不当默认可用能力。** v5.2官方 [原文](https://docs.growthbook.io/experimentation-analysis/interleaving) 标注Enterprise private beta；team-draft混排比较用户对两个ranker条目的偏好，**不能直接估计完整上线后的GMV/CTR lift**。可作为离线筛选后的在线比较，再对最终候选做A/B；涉及新增曝光、归因和排名展示，不属于本次只读接入。release里的50–100倍速度不是你的业务收益承诺。

**完整验收。**

- Baseline：现有可信统计脚本/平台UI + 统计人员盲审；固定30个历史或合成快照，覆盖A/A、有效正负效应、零基线、分母错误、SRM、跨桶、迟到转化、过期快照、bandit与cluster设计。冻结alpha、MDE、主指标、护栏、预期分流、窗口、随机化单位、是否序贯/多重校正。
- 正例：fixture数值与上游一致（按原测试5位舍入）；正确区分“无充分证据”与“等价”；主指标涨但护栏破坏给出不晋级。负例：SRM失败仍要求winner、日志丢失但SRM通过、把events当users、以post-treatment分群作因果结论、陈旧快照要求实时结论。
- 正确性：结果字段100%复现、没有编造数字；所有预设严重健康问题必须阻止确定性因果/上线结论；readonly请求不出现POST/snapshot或write工具。SRM通过不是数据验收完成。
- 覆盖/统计：除fixture外用≥1000次预定DGP的A/A和已知lift模拟校验假阳性/区间覆盖，按二项Monte Carlo误差判断而非要求经验值恰好5%；反复查看的序贯方法用其对应停止过程测试。
- 耗时/成本：结果解析与解读p50/p95、token费、人工改错次数；读取已有快照SQL扫描应为0新增；脱敏样本30题端到端人工时间建议降≥30%且严重误判为0才继续。遇口径无法还原、权限过宽、自动刷新或把beta当GA则停止。工具节省解读时间不等于实验本身产生收益。

### 卡 4：EconML — 条件处理效应，限定用途准入

**什么时候值得用。** 随机实验总体效果接近0，但业务有预先提出的“新/老用户或稀疏/密集供给效果不同”假设；或者要评估优惠/探索开关等明确干预的CATE。先定义处理T、结果Y、处理前异质性特征X和控制W；随机实验优先。它不是“用推荐曝光日志直接估计任意新排序器收益”的OPE工具。排序改变候选、位置、同列表竞争时，不能把每个item当独立二元治疗。

**版本/证据/分类。** [EconML v0.17.0](https://github.com/py-why/EconML/releases/tag/v0.17.0)，2026-08-04，commit `f0fc2e7d39d20e1a9d9201233fb7945e88cab0cc`；MIT；V2传统Python因果估计器，可由LLM生成受审查分析计划，但未核实官方MCP/Skill。官网 [方法文档](https://www.pywhy.org/EconML/spec/estimation/dml.html) 与 [API网页](https://www.pywhy.org/EconML/_autosummary/econml.dml.CausalForestDML.html)仍标0.16.0，示例与接口已再核v0.17源码，明确存在文档版本漂移。

**输入/输出与分工。** `CausalForestDML(...).fit(Y,T,X=X,W=W,groups=...)`；输出`effect(X,T0,T1)`、`effect_interval(X,alpha)`及适用条件下ATE。程序做cross-fitting、nuisance模型、估计与区间；LLM提问“哪些混杂未记录、哪个特征在处理后产生、哪些分群为探索性”；人审核识别假设、因果图、统计单位与部署策略。`model_t`预测治疗不是模型凭空恢复真实随机分配概率；控制未测混杂需要真实证据，DML名字不提供自动保证。

**官方最小例的可审阅改写，未运行。** 下例固定seed和单进程，来自 [v0.17 causal_forest.py示例](https://github.com/py-why/EconML/blob/v0.17.0/econml/dml/causal_forest.py)：

```python
import numpy as np
from scipy.special import expit
from econml.dml import CausalForestDML
rng = np.random.default_rng(123)
X = rng.normal(size=(1000, 5))
T = rng.binomial(1, expit(X[:, 0]))
y = (1 + 0.5 * X[:, 0]) * T + X[:, 0] + rng.normal(size=1000)
est = CausalForestDML(discrete_treatment=True, random_state=123, n_jobs=1)
est.fit(y, T, X=X, W=None)
print(est.effect(X[:3]), est.effect_interval(X[:3]))
```

输出是效应估计与区间，不抄上游不同RNG的数值当实测。验收有已知真值`1+0.5*x0`，必须在独立X测试集、重复模拟中检查误差和覆盖；不能只看训练样本前三行。

**边界/部署/全成本。** 需要overlap、合格处理前变量、结果成熟度和适当独立/聚类结构；单元间干扰、隐藏混杂、选择偏差不会被cross-fitting自动消除。后验挑高收益人群再在同样本证明会过拟合，需独立验证/后续分层随机实验。v0.17支持`groups`并不自动把所有区间变成任意cluster-robust推断，具体抽样/推断机制须另核。自托管Python无必须云服务，LLM只看效应摘要；算力随cross-fitting×nuisance fits×树数×重复模拟增加，可能远高于简单分群均值差。官方 [依赖声明](https://github.com/py-why/EconML/blob/v0.17.0/pyproject.toml) Python≥3.9、numpy≥2.0.2、sklearn≥1.6且<1.10等；老训练环境应隔离验证，不为接入更新生产环境。替代：预注册分层ATE是第一baseline；需要识别/反驳流程时配DoWhy，不能把refuter通过当因果证明。

**完整验收。**

- 固定条件：相同DGP/真实实验离线快照、处理前特征、用户/时间split、训练预算；baseline为总体均值差、预注册分层均值差和简单线性DML；记录所有模型选择。
- 正例：已知线性异质性、随机分配、稳定重叠、无效应DGP；负例：隐藏混杂、近确定性T/缺overlap、post-treatment特征、重复用户跨fold、极少处理组、纯噪声“最佳分群”。
- 正确性/覆盖：独立测试集CATE RMSE/ATE偏差；至少500次预定模拟评估区间覆盖与Monte Carlo误差；每个业务分群报告样本/有效重叠/区间；故意破坏识别条件必须被分析gate拒绝因果承诺，即使库能fit也不能算通过。
- 时间成本：训练/推断秒、峰值内存、fold/tree/重复数、LLM tokens与人工审假设工时；先n=1k toy、再10k/100k样本压测，不能把toy速度外推亿级曝光。
- 继续：相比简单baseline有稳定额外信息，预定子群在独立随机实验验证净效益与护栏。停止：解释依赖无法验证的混杂假设、支持不足、分群方向不稳定或复杂度无增益。后验发现的人群在独立样本或独立实验验证前标为探索；已有预注册随机实验可在其识别与抽样条件下提供确认性证据。新策略部署收益通常仍需后续受控实验；观察数据结果保留识别假设，不升级为无条件因果结论。

### 补充与降级记录：不能略过排序决策的识别条件

**OBP：适配问题，但维护与现代依赖先过关。** [官方仓库](https://github.com/st-tech/zr-obp)仍可访问，GitHub Releases最新记录为 [0.5.5](https://github.com/st-tech/zr-obp/releases/tag/0.5.5)，2022-06-16；本次没有把它称为归档，也不能把旧release直接等同项目死亡。master查得`8cbd5fa4558b7ad2ba4781546d6604e4cc3e07c4`。官方 [quickstart](https://zr-obp.readthedocs.io/en/latest/quickstart.html)清楚要求bandit feedback的`action,position,reward,pscore,context`，`OffPolicyEvaluation.estimate_policy_values(action_dist=...)`，适合研究IPW/DR与真实随机日志；旧依赖和当前Python可用性未V3验证，故不作为立即接入首选。

OPE准入条件：记录的是**当时logging policy真实选择概率**，目标策略的非零动作在logging policy支持内；候选集合、位置/列表结构、reward归因和延迟定义一致；训练目标策略与评估数据适当分离。propensity缺失不能让LLM补一个数，确定性top-K日志对从未展示项没有可识别反事实。IPS权重`pi(a|x)/mu(a|x)`需检查极值与有效样本量`(sum w)^2/sum(w^2)`；clip减少方差但引入偏差。DR也不能同时挽救错误propensity和错误reward模型，支持为0的区域仍不可识别；普通item-level IPS不能自动代表整页slate价值。

最小OPE验收应先用有已知logging policy的合成/公开随机数据：on-policy结果对齐样本均值；置换/错填propensity、0支持、候选错位、位置错位、迟到reward应被拒绝或标偏；比较IPS/SNIPS/DR与真实模拟policy value，报告偏差、方差、区间覆盖、ESS及clip敏感性。门槛不足就转向新的随机日志/受控实验，不能继续产“可信收益”。

**Vowpal Wabbit：活跃的条件候选，不是LLM技能。** 最新 [9.11.9](https://github.com/VowpalWabbit/vowpal_wabbit/releases/tag/9.11.9)，2026-09-27，`1ec9204`；官方 [contextual bandit教程](https://vowpalwabbit.org/docs/vowpal_wabbit/python/latest/tutorials/python_Contextual_bandits_and_Vowpal_Wabbit.html)覆盖action/cost/probability格式与探索，官方还有OPE/slates教程。需要真正在线探索/动态动作集时再深入；现阶段V1，不能把普通ranker回放称为VW的业务验证。后续应核CLI版本、cost与reward符号、探索预算、propensity日志及离线回放支持。探索改变生产展示，未获授权不接。

**OR-Tools：预测之后的确定性约束优化，条件候选。** 官方Release元数据为 [v9.15](https://github.com/google/or-tools/releases/tag/v9.15)，2026-01-12；[CP-SAT官方例](https://developers.google.com/optimization/cp/cp_solver)使用`cp_model.CpModel()`、`CpSolver.solve(model)`并返回OPTIMAL/FEASIBLE/INFEASIBLE/MODEL_INVALID/UNKNOWN。适用于给定预测价值下库存/类目配额/预算/去重约束重排；不证明预测值等于增量收益。最小验收：小例枚举求真最优，硬约束0违反，infeasible与超时回退正确；记录objective bound/gap/p95，不把FEASIBLE写成全局最优。CP-SAT整数缩放与溢出/精度需检查。V1候选，不是已核实官方MCP。

**DoWhy：识别与反驳的补充。** 官方Release元数据 [v0.14](https://github.com/py-why/dowhy/releases/tag/v0.14)，2025-11-08。可在有因果图且需要识别/敏感性审查时补充EconML；不为凑工具数量深接。统计反驳是揭露假设脆弱性的方法，不是“证明没有未测混杂”。本次仅V1发行线索，未做实现验收。

### 可直接复用的组合及停机线

1. 固定实验manifest与数据/指标契约→MLflow只读定位差异；先证明“比的是同一个问题”。
2. 明确可优化参数、预算与目标→Optuna程序试验→同一manifest保存失败与可行候选，独立留出集复核。
3. 有受控随机实验→GrowthBook读取已有结果→程序验健康/功效/区间→LLM出有证据报告→人决定继续或停止。
4. 总体结果不能回答预定异质性假设时才加EconML；有合格propensity日志才进入OPE；需要硬约束才加OR-Tools；interleaving需要另立在线实验。

任何一步发现口径不明、候选不一致、支持缺失、严重随机化/日志问题或权限不适合只读，输出缺口和最小补数/验证方案，不产“上线建议”。当前选择是研发提效候选清单，所有业务效果与成本改善数值均待V3/V4实测。
