# Repetition Mismatch：小预算选出的数据配比为何不能直接放大

**先判断是否值得试：**如果少量高质量/成熟标签反复采样、大量普通数据不断更新，而小实验偏好的配比放到大预算后失效，先对齐各源重复率。本文改变的是**选择配比的代理实验**，不增加模型模块，也没有证明更多唯一信息无用。最值得迁移的结论是：相同域比例不代表相同训练问题。

原题：*Repetition Mismatch: Why Data Mixture Experiments Don't Scale and How to Fix Them*。Kevin Zhou、Lisa Alazraki、Marek Rei（Imperial College London），Kris Cao（Cohere）。[官方元数据](https://arxiv.org/abs/2606.07597)确认首次公开 **2026-05-29**，所读 v2 **2026-09-03**；不能按2606编号误记六月。官方页 Comments 为 EMNLP 2026 Main Conference，本记录未独立核会议程序。[所读PDF](https://arxiv.org/pdf/2606.07597v2) · [作者代码](https://github.com/kevinzhou497/data-mixing-language-models)。阅读正文§1–7、Limitations及附录A–G、表1–16；不声称运行代码或完成全网撤稿调查。

## 动机：数据量增加时，究竟增加了什么

假设高质量域只有1亿token，普通域足够大。在固定域比20%下，总训练量从5亿加到40亿，高质量域会从1次变成8次，普通域却仍可提供新样本。小实验测到的是“20%高质量新信息”；大实验测到的是“20%高度重复的信息”。若仍用同一比例，重复的边际收益和过拟合程度改变了目标函数。

文中竞争解释包括模型容量不同、训练步数不同、学习率不同、高质量域与验证集相近，以及真正的重复率失配。作者固定每组模型大小，跨token预算比较，因此**主要不是用小模型预测大模型**。各模型30M–1.17B分别做独立配比实验，再看容量如何影响控制重复率的有效性。将其写成“用30M找1.17B最优mix”会直接误读。

## 方法：在代理实验里保持每源重复次数

输入是若干固定数据源、目标训练量T*、候选配比m及目标模型。输出为选定域比例，之后按该比例跑完整目标训练；模型结构、next-token交叉熵和推理路径都不改。对大小n_i的数据源，目标期望重复率是

$$r_i=\frac{T^*m_i}{n_i}.$$

代理预算缩成aT*，如果仍用全部n_i，重复率变成ar_i。Repeat-aware同时将该源文档池缩成约an_i：

$$r_i^{proxy}=\frac{aT^*m_i}{an_i}=r_i.$$

按文档截取，token数不完全同比，因此文中232M/234M、936M/935M等略有不同。§4称使用原数据前1/S文档，预处理seed42；不能自行改写为每个实验独立、严格分层的随机抽样。FineWeb池足够大，在实验中都未完整重复；保持有限高质量域的重复动态是核心。

流程为：设a∈{1/16,1/8,1/4,1/2}；在每个horizon按batch级token比例训练一组mix；通常以.05间隔扫描，得到该horizon的最优区域；单horizon直接转用其mix，多horizon用线性回归外推。对照也扫描mix，但保留完整原始池，让重复率随预算自然变化。论文称对照为“Scaling Laws”，实际是**从训练token数与最优重复次数做线性外推**，不是实现并击败所有已有数据混合法则、DoReMi或RegMix。

repeat-aware的干预同时减少唯一文档量与训练步数。这是有意为之：用更小的支持集重现目标重复状态。因此它不能保证完全隔离所有因素；子样本是否保留主题/群体支持、优化是否已到对应阶段，都要核验。没有额外可训练参数或冻结模块，训练完成后的模型部署成本不变；新增成本是抽样、各源唯一量/重复率审计和代理训练网格。

## 数据、目标与预算必须一起读

WikiText训练116,881,107token，PubMed抽摘要约120,000,060token；FineWeb-10BT约100亿token。前两源各取131,072token作评估，**不在FineWeb或实际下游任务评估**；三源实验等权平均WikiText与PubMed的验证交叉熵。PubMed先留约1%文档作验证，再构建小验证集；全流程tokenizer为GPT-2 tiktoken。

模型为modified nanoGPT，RoPE，隐藏二维矩阵用Muon，其余embedding/末层用AdamW；30M、124M、345M、757M、1.17B五档。batch128、序列256、最后约29%训练步线性衰减学习率。多数网格试三个对数间隔学习率；757M/1.17B及较小模型最长预算因资源限制只试一个。因此不能说全部配置同等充分调参。A100/H200，1.17B固定两worker并用梯度累积保证跨机器batch序列一致。

主网格每配置单seed42。补充仅对1.17B PubMed两方法各五配置跑seed42/43/44，最大loss范围.0085；这不是对整张mix最优位置的多seed重估。目标horizon两源约3.74B/3.84Btoken，三源约3.79B，远小于现代万亿token预训练。

**成本分母纠偏：**表5的6.2%、18.7%、43.7%、93.7%是累计horizon的 **tokens per run / target tokens per run**。一个horizon包含多个mix×学习率训练，不能宣传“总共6%目标训练成本就能找mix”或“一次训练解决”。附录E明确须乘run数，且假设两方法每horizon sweep次数一样。§C.3却允许自适应停止、跳过某些中间比例；没有完整账本证明所有真实run数相同。可保留“减少所需horizon”的结论，真实GPU小时收益需另外记录。

表1中的.05是扫描粒度/作者的保守比较规则，不是统计置信区间。附录bootstrap只反映同一个已训练模型在验证文档上的抽样不确定性，不能替代训练seed不确定性；将loss的seed范围与mix比例误差直接比较，也不构成同单位的统计检验。

## 原文内部不一致与证据降权

PDF第14页视觉核验：表3的757M WikiText目标mix为(.85,.15)，表4同一目标写(.80,.20)，表1单horizon控制误差.05更符合前者。该冲突不靠自行挑数解决。本笔记引用757M三源与1.17B两源主结论，保留757M两源精确最优值待作者/代码澄清。多horizon线性外推并不保证比直接转用mix更稳：即使前两horizon很接近，后续最优重复次数改变也可能被外推放大，表1的三horizon退化应单独验证而非被平均掉。

表6 repeat-aware补种子使用.85比例，而表4的1.17B PubMed前三horizon最优比例为.95；所以它验证局部训练稳定性，不验证整段最优mix稳定性。表16在.75处出现明显非单调抬升；结合§C.3首次出现局部U形就停止的规则，不能把每次搜索写成有保证的全局最优。所谓“optimum”应理解为报告网格/探索范围内最佳。

## 收益链：缺少哪一环就不能迁移

1. 固定mix扩token → 稀缺域重复率升高、普通域仍有新信息。[结构事实]；真实日志的近重复、用户重复、标签回流是否等同文档重复属于[迁移推断]。
2. 改变重复率 → 验证loss曲线最优mix漂移。[实验证据：图2、表1/3/4]；重复的边际收益下降/容量不同导致过拟合是[作者解释]，没有独立记忆量/梯度冲突测量完成因果中介证明。
3. 同比缩小唯一池与预算 → 多数较大模型的最优区域更稳定。[实验证据]；对30M和三源单horizon失败，说明唯一样本支持和优化进度仍有作用。
4. 稳定的proxy选择 → 以较少horizon找到目标预算的好mix。[实验证据且预算有上述分母限制]；→推荐业务NE/校准/收入改善是[缺证据]，不能把领域验证loss最优直接当上线多目标最优。

“更多数据不再有效”在此更精确地说是：**更多采样次数并未增加对应源的唯一信息，且改变了各源边际价值**。它不支持删除真实新颖数据，也没有证明四次重复是一切任务统一阈值。作者观察小模型目标最优重复可达约24，大模型约5，这仍只适用于本文域与目标。

## 接入位置、组合与最小版本

保留主训练模型、样本标签和最终目标，只在offline配比选择阶段新增统计与repeat-aware代理组。推荐中的域可以是成熟转化、弱行为、合成、历史回放、探索流量；先确认域标签目标相容。若数据跨日刷新，重复次数须基于固定example/实体时间窗定义，不能用总行数除数据表大小代替。

与 [[D01_FROST_真实梯度锚定过滤]]/[[D02_TATC_条件样本价值]] 组合时，过滤改变了每域唯一池和实际采样率，要重算重复率；不能把选择前的mix当最终mix。与 [[D05_BestOfN_标签生成改变目标]] 组合时，标签生成策略会改变比较分布，重复率匹配也无法修正目标错配。历史DoReMi可作为选择器，repeat-aware可作为其代理实验控制；论文没有实际验证二者联用，不能承诺叠加。

最小可行试验：固定目标模型和预计训练预算，选两个机制清楚的域，做3–5个mix、两个proxy预算；分别用完整池和同比缩小池。先看mix排序能否对齐，再对少量预测mix做目标预算锚点。记录每个run实耗与唯一量，若支持集损失太大则提高proxy比例或分层抽样，不直接上线改配比。

## 可证伪实验单 A：配比漂移来自重复率还是支持集与学习进度

- **假设：**小预算选错mix的主要原因是稀缺域重复率未匹配。
- **改变：**同一目标模型下交叉设置proxy预算a与稀缺域唯一池大小b，形成r∝a/b；包含完整池b=1、同比缩池b=a、以及同r不同(a,b)组。固定域比例网格、标签、优化器、目标验证集、batch、学习率策略；LR另做小邻域对照，避免相同schedule强行不公平。
- **baseline/负对照：**未控制重复率的同预算proxy、完全无重复的充足域对照、不同文档/用户分层抽样seed；用随机重复而非只重复难例隔离课程效应。
- **中间/最终指标：**每域唯一覆盖、真实/近重复次数分布、train–validation gap、各mix排序Kendall相关；最终为目标预算选中mix的regret与时间外NE/校准/业务约束，而不只比例距离。
- **支持：**等r的最优区域比等token更稳定，变化主要出现在稀缺域，且保留支持后仍成立。**推翻/停止：**等r仍随唯一覆盖强烈漂移、无重复对照同样失败，或调LR即可消除差距；转查覆盖、优化阶段和目标差异，不强推repeat-aware。

## 可证伪实验单 B：早期省预算能否跨容量与多业务目标成立

- **假设：**在足够容量及覆盖下，重复率控制以更少搜索成本找出业务目标近优mix。实验前用独立pilot确定容量/覆盖达标标准、近优regret容忍和业务护栏，避免事后把所有失败解释成“不够大”。
- **改变：**两档目标容量分别独立运行两源/三源选择。分两套比较：机制组固定mix/LR候选网格、目标训练量、可用数据和最终复核次数，比较单/双horizon并如实报告成本差；效率组固定总GPU小时，让各selector自行分配horizon/网格预算，与常规网格/历史mix/DoReMi或RegMix式选择比较。效率组不再同时固定候选数。两组都固定mix边界，选择不得看最终时间外测试，计入全部成功/失败run及selector自身成本。
- **负对照：**只优化高质量源验证loss的selector，与预先注册的业务加权/最差域约束selector对照；增加普通域测试，查“最佳”是否只是验证域倾斜。
- **中间/最终指标：**选择稳定性、每域误差、重复簇覆盖、全部失败run的tokens/GPU小时；最终业务加权regret、长尾校准、成本–效果曲线。目标锚点多seed，分别bootstrap样本与报告训练seed。
- **支持：**达标容量/覆盖组在相同总搜索成本下regret更低且各约束不退，机制组也支持重复率路径。**推翻/停止：**预先达标组同成本仍不胜常规搜索，直接反驳其在该条件下的效率价值；低容量/三源单horizon失败用于界定边界，不单独反驳“足够容量”条件命题。若好源loss改善却普通域或业务退化，停止推广并修目标；必要时提高horizon，不把有限设置结果写成普适规律。
