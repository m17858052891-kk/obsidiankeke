# 1. 痛点：传统生成模型为什么“不会排序”？

在标准的生成模型训练中，默认采用的是**最大似然估计（MLE）**。只要模型生成的词和历史日志里的搜索词一样，模型就不会受到惩罚。

但在真实的电商场景中，用户的行为是有“价值高低”之分的：

- **场景 A：** 用户搜了“手机壳”，但看了两眼就划走了（只有曝光，没有点击）。
- **场景 B：** 用户搜了“苹果15手机壳”，不仅点击了商品，还下了单（发生了购买）。

在传统的 MLE 视角下，只要系统猜中了“手机壳”和“苹果15手机壳”，它得到的奖励是一样的。这就导致模型在生成下拉提示词时，倾向于生成那些**宽泛、平庸但安全的高频词**，而不是那些能真正切中用户痛点、促成交易的精准词。

# 2. 核心机制：行为即奖励 (Behavior as Reward)

为了解决这个问题，OneSug 引入了 RWR 策略。它的核心逻辑是：**将用户的漏斗行为转化为量化的奖励分数（Reward）。**

系统不再一视同仁地对待所有真实搜索日志，而是根据该 Query 最终引导的用户行为，赋予不同的权重：

|**用户行为 (Behavior)**|**业务价值**|**奖励权重 (Reward Score)**|
|---|---|---|
|**仅曝光 (Impression)**|极低|趋近于 0|
|**点击 (Click)**|中等|$R_{click}$ (例如 1.0)|
|**加购 (Add to Cart)**|较高|$R_{cart}$ (例如 2.0)|
|**购买 (Order)**|极高|$R_{order}$ (例如 5.0)|

当系统收集到这些带权重的日志后，就会在模型训练（微调）阶段进行干预。

# 3. 数学本质：加权损失函数

在具体的算法实现上，RWR 将上面定义好的奖励分数 $R$ 直接融合到了模型的损失函数（Loss Function）中。

传统生成模型的损失函数是为了最小化预测词与真实词之间的差异：

$$\mathcal{L}_{MLE} = - \sum_{t=1}^{T} \log P(y_t \vert{} y_{<t}, X)$$

而在 RWR 策略下，损失函数被改造为加上了奖励权重：

$$\mathcal{L}_{RWR} = - R \cdot \sum_{t=1}^{T} \log P(y_t \vert{} y_{<t}, X)$$

这个公式看似简单，但威力巨大。它告诉模型：

如果你猜对了一个最终让用户**下单**的词（$R$ 很大），你得到的梯度更新鼓励会极其强烈；如果你猜对了一个仅仅被**曝光**的废词，你几乎得不到什么奖励。

# 4. 最终效果：让训练更偏向高价值行为

经过 RWR 策略训练后的 Decoder，在面对用户的输入前缀时，它的“脑回路”发生了根本性的变化。

当使用 Beam Search（集束搜索）生成多个候选词时，模型计算出的概率分布不再是纯粹的“语言学概率”，而是“包含了商业转化预期价值的综合概率”。

因此，当用户敲下“shou”时，模型不仅能生成“手机壳”、“手链”、“手套”，它还会因为 RWR 的训练记忆，自动把那个根据当前用户画像预测出**最有可能促成点击甚至下单**的词，在概率打分上顶到最高，从而自然而然地排在下拉列表的第一位。

这是一种 Reward-Weighted Learning：它让模型更偏向产生历史上关联高价值行为的 query，但不等于“完美识别真实偏好”。奖励设计可能受曝光、位置、库存和延迟反馈影响；若奖励只反映短期转化，也可能伤害多样性、探索和长期满意度。因此应搭配去偏、校准、约束及线上实验评估。
