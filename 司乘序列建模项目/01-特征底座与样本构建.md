# 司乘双边序列：特征底座与样本构建

> 本文回答一个前置问题：模型中的“乘客历史序列、司机历史序列、静态特征”从哪里来，以及它们如何严格对齐到一个预测样本。
>
> 已确认的是“事件—宽表—序列”的建设思路、Attempt 粒度和历史回查优化；下文示例字段与张量形状用于说明接口，真实 schema 以 SQL/特征配置为准。

## 1. 为什么不直接使用统计特征

历史订单次数、取消率、均价等统计特征会压缩时间顺序、相邻行为、时空上下文和事件间关联，也容易让冒泡—发单—应答—履约链路分散在不同表中。序列底座的目标是保留原子事件及其时间关系，并为后续模型提供统一、可回溯的样本输入。

## 2. 三层数据链路

~~~text
事件层 Event
  冒泡 / 发单 / 应答 / 取消 / 完单 / 价格及上下文事件
                ↓
宽表层 Enrich
  以 Attempt 为主键，补齐订单、司乘、时间、空间、价格、状态字段
                ↓
样本层 Sample
  以 prediction_time 截断历史，为当前任务样本拼接 passenger_seq、driver_seq、x_static 和标签
~~~

### 2.1 Event：保留可追溯的原始行为

建议至少保留 `event_time`、稳定事件 ID、关联 `attempt_id/order_id`、主体 ID、事件类型和当时可得的上下文字段。`order_id` 在发单前可能为空，因此应以能够覆盖整条漏斗的 Attempt（及可用时的 `trace_id`）承接事件，而不是只按完单订单建序列。

### 2.2 Enrich：围绕 Attempt 补齐而非建一个万能训练宽表

Attempt 宽表负责把分散事件和订单维度对齐，例如当前漏斗状态、预估距离、接驾距离、价格、供需、时间/空间上下文和阶段性结果。它是序列元素与样本静态特征的共同来源；不同预测点/任务仍须在样本层重新按可用时间裁剪。

### 2.3 Sample：以预测锚点构造训练或推理样本

对每个预测时点 `prediction_time`：

1. 取得该时点可观测的当前 Attempt/订单静态字段；
2. 过滤所有 `event_time < prediction_time` 且线上理论可获得的历史行为；
3. 按乘客 ID、司机 ID 分别取最近 N 条，并按 `(event_time, stable_event_id)` 稳定排序；
4. 截断、补齐并生成 mask、相对时间/位置字段；
5. 在标签定义允许的未来窗口取 D/O/OD 标签。标签不得反哺特征。

这一步把“司乘序列建设”与“模型输入”真正接起来。

## 3. 唯一模型输入契约

~~~text
sample = {
  anchor: {attempt_id, prediction_time},
  passenger_seq: [L_p, F_p],
  driver_seq:    [L_d, F_d],
  x_static:      [F_s],
  p_mask, d_mask,
  role/type ids, position or relative-time features,
  labels: {y_D, y_O, y_OD}   # 训练期存在，推理期不存在
}
~~~

| 输入块 | 来自哪一层 | 在模型中扮演什么 |
|---|---|---|
| `passenger_seq` | 乘客历史 Attempt/事件 | 乘客 S-token 序列 |
| `driver_seq` | 司机历史 Attempt/事件 | 司机 S-token 序列 |
| `x_static` | 当前 Attempt/订单、画像、上下文 | 非序列 NS-token 或 PEPNet 先验输入 |
| `mask/time/role` | 样本组装阶段 | 区分补齐位、行为顺序、司机/乘客角色 |
| `y_D/y_O/y_OD` | 标签回流 | 多任务训练目标，不能作为当前时刻输入 |

### 3.1 已确认的一版特征规模

补充材料给出的序列 baseline 输入共 `343` 维：`143` 维数值/类别特征 + `200` 维双边序列特征。后者由乘客和司机各 `10 笔订单 × 10 特征` 组成。数值块包括：`n_sparse=10`、`n_dense=61`、`n_serial=35`、`n_nonserial=35`、`n_binary=1`、`n_poso=1`。

需要保留一个实现待确认项：材料一处写“PLE 有 poso、PEP 无 poso”，另一处又写 baseline 去掉 poso。因此 `poso`（28 天内完单数）是否进入每个具体 run，必须以实验配置为准；不能把 `343` 维写成所有 PEP/OneTrans 实验的固定输入。

## 4. 一个字段如何走到模型

以“历史接驾距离”为例：历史 Attempt 中记录 `pickup_distance`，在样本构建时仅保留预测锚点前的值；它作为乘客或司机历史事件的字段 Embedding，与价格、距离、结果、时间差等共同融合为一个历史 token。当前订单的接驾距离则属于 `x_static`，会以静态 token/先验特征形式进入模型。两者由 OneTrans 在统一 token 空间中交互，而不是预先聚合为一个“历史平均接驾距离”。

## 5. 防穿越与线上一致性

- 时间条件：历史事件早于 `prediction_time`，并考虑事件落库/特征可用延迟。
- 排序条件：同一时间戳使用稳定 ID 打破并列，保证训练、验证、推理一致。
- 标签隔离：完单、取消等未来结果只能作历史事件的已发生字段或当前样本的 label，不能提前写入当前特征。
- 线上一致性：离线、召回/过滤、排序阶段必须复用同一截断窗口、排序、缺失值和 padding 口径。

## 6. 大规模历史回查

针对亿级样本与长历史范围 join 导致的笛卡尔积膨胀，可按“`主体 ID + 时间戳` 预排号 → 当前样本锚点截断候选区间 → 回表补全字段”的方式处理。这样先缩小候选历史，再拿宽表字段，而不是让所有当前样本与全量历史做范围 join。
