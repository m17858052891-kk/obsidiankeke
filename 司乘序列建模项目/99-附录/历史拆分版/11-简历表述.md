# 简历表述

> 仅在内容确为本人参与、能够解释并可接受深挖时使用“搭建/完成/负责”等表述；否则改为“参与/调研/复现/离线探索”。

## 推荐项目标题

**司乘履约双边行为序列建模（离线实验）**

## 一页简历版本

- 基于既有 PLE 多任务架构来源，构建“事件—Attempt/订单宽表—双边历史序列”离线特征链路；以预测锚点截断历史，并采用“主体 ID + 时间戳”预排号与回表策略缓解亿级历史范围 Join 膨胀。
- 以 PEPNet + Positional Self-Attention 作为司乘序列 baseline，编码乘客/司机历史订单并通过 EPNet/PPNet 实现场景与任务个性化；进一步探索 OneTrans 的统一序列—静态特征交互。
- 在 PEP × OneTrans、epoch=9 离线实验族中，相较 `pep-seq`，OD/O/D AUC 分别 `+0.82pp/+2.74pp/+6.61pp`；完成长度、时空字段、Batch Size 与任务输入方式消融，发现 O 任务对窗口、时空字段和训练协议更敏感。

## 更稳健的弱责任版本

- 调研并复盘基于 PLE/PEPNet 的司乘履约序列化方案，梳理事件—样本构造、双边 PosSA baseline、OneTrans 统一 token 交互及离线实验边界。
- 基于实验记录分析 D/O/OD 指标差异、O 任务低增益的消融结果，以及 Batch Size、序列长度和时空特征的混杂因素。

## 不建议写

- “线上履约率/CR 提升”：当前没有线上验证。
- “OneTrans 相对 PosSA 提升 6.61pp”：严格对照是 `pep-seq`。
- “长度 20 全局最优”：只在一组 6 月配置中对 O/OD 更好。
- “端到端上线 PEPNet × OneTrans”：当前资料不支持。
