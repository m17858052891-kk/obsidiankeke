# 司乘履约双边序列建模：项目总览与导航

> 面试时先从 [[主线-PEPNet×OneTrans/00-当前模型架构总览]] 讲当前模型；本文只保留项目背景、PLE 基座来源与实验资料导航。

> 范围：本文件夹记录**离线**的司乘序列建模方案和实验；不把离线 AUC 直接写成线上业务收益。

## 1. 项目一句话

面向订单履约预测，将冒泡、发单、应答、取消、完单等历史事件整理为乘客/司机双边序列，解决统计特征压缩历史、司乘链路割裂的问题；以 **PEPNet + Positional Self-Attention** 作为主序列建模 baseline，并探索 OneTrans 的统一特征交互能力。

### 1.1 起点：线上 PLE base 的离线序列化改造

补充材料将 PLE 称为“线上 base 模型抽取”的架构来源。本项目据此构造 `PLE base` 离线对照，并依次验证 PLE + 序列、PEPNet + 序列以及 OneTrans 方案。这里的“线上”仅说明基座来源；本文档中的 AUC 全部来自离线训练/验证集，不表述为线上模型指标或线上收益。

## 2. 业务、任务与指标口径

| 记号 | 含义 |
|---|---|
| D | 乘客履约 |
| O | 司机履约 |
| OD | 司乘履约率 |

离线评估指标为 `valid_d_auc`、`valid_o_auc` 和 `valid_od_auc`。业务上，材料将司乘应答后取消率（CAA）作为 DO 价值，乘客侧以呼叫完单率（CR）为目标，司机侧以未来时间窗收入为目标。原始业务目标是 CR `+0.2pp`、乘客取消率 `-0.5pp`、`2.5km+` 接驾距离占比 `-5%`；这些是目标，现有记录未给出线上验证结果。

## 3. 一条主链路

~~~text
历史原始事件
  → Attempt/订单宽表补全
  → 以 prediction_time 为锚点构造任务样本
  → passenger_seq + driver_seq + x_static + mask/时间信息
  → Embedding / Tokenizer
  → PEPNet + Positional Self-Attention（主序列 baseline）
      或 PEPNet × OneTrans（统一交互探索）
  → D / O / OD 任务头
  → 分实验族、分 baseline 解读离线 AUC
~~~

这里的关键边界是：**事件—宽表—序列**负责生产模型可消费的样本；模型只消费已经完成时间截断和防穿越的张量，不直接消费泛化的离线宽表。

## 4. 当前可确认的结论

1. `PEPNet + Positional Self-Attention` 是当前项目叙事中的主序列建模 baseline：对乘客、司机各 10 笔订单序列进行位置自注意力编码后接入 PEPNet。
2. 在 `pep-seq → pep-seq-onetrans` 的 epoch=9 实验族中，OneTrans 相对 `pep-seq` 的 AUC 变化为：OD `+0.82pp`、O `+2.74pp`、D `+6.61pp`。
3. 在 `ple-seq → ple-onetrans` 的 epoch=9 实验族中，OneTrans 主要提升 D 和 OD，O 基本持平略降。
4. O 任务的低增益已做过塔拆分、序列过滤、塔输入拆分、长度/时空字段和 Batch Size 排查；现有证据不支持简单归因为“多任务权衡”或“序列噪声”。
5. 序列长度、时空字段和 Batch Size 对结果影响显著，尤其 Batch Size=256 有较强正向现象；但当前记录还不足以把全部收益因果归因于某一个模块。

## 5. 不能直接下的结论

- `pep-seq` 的内部序列编码器未在材料中明确，不能断言它就是 `PEPNet + Positional Self-Attention`。
- 不同日期、epoch、batch size、特征集合和模型命名的 AUC 不能横向排序为“项目全局最优”。
- 离线 AUC 不等于线上业务目标已达成。
- PEPNet、OneTrans 在本项目中的确切 token 顺序、层数、loss 权重和工程调用顺序需以代码/配置为准。
