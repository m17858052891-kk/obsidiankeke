# 非 Hot 100 — 普通数组

> 这些题不属于正式 Hot 100，但仍有较高面试价值。

## 面试手撕：先递增后递减数组中不重复元素的个数

### 题目

给定一个先严格递增、后严格递减的数组，返回其中不同元素的个数。

要求：

- 时间复杂度 $O(n)$；
- 额外空间复杂度 $O(1)$。

例如：

```text
输入：[1, 2, 4, 7, 6, 4, 2]
输出：5
不同元素为：1、2、4、6、7
```

### 先澄清题目条件

面试时先问一句：

> “先递增后递减”是严格单调，还是允许相邻元素相等？是否一定存在两段？

下面的主解法假设数组是严格山峰数组：存在峰值下标 `peak`，使得：

```text
nums[0 ... peak]       严格递增
nums[peak ... n - 1]   严格递减
```

单调递增数组和单调递减数组也可以作为退化情况处理。

### 核心观察

数组可以拆成两个升序序列：

```text
左半段：nums[0], nums[1], ..., nums[peak]
右半段反向：nums[n-1], nums[n-2], ..., nums[peak+1]
```

峰值只放在左半段，避免重复处理。

问题于是变成：**不使用额外数组，合并两个升序序列，并统计并集大小。**

这和归并排序的 merge 非常相似：

- 左边较小，消费左指针；
- 右边较小，消费右指针；
- 两边相等，说明同一个值在上升段和下降段各出现一次，同时消费；
- 每消费一个新值，答案加一。

### 图解

```text
原数组：  1  2  4  7  6  4  2
下标：    0  1  2  3  4  5  6
峰值：             7

左升序：  1  2  4  7
右反向：  2  4  6

归并过程：
1 vs 2 → 取1，count=1
2 vs 2 → 相等，同时取，count=2
4 vs 4 → 相等，同时取，count=3
7 vs 6 → 取6，count=4
右侧结束 → 取7，count=5
```

### Python 代码

```python
def count_distinct_bitonic(nums):
    n = len(nums)
    if n == 0:
        return 0

    # 1. 找到峰值。严格递增后严格递减时，第一次下降前的位置就是峰值。
    peak = 0
    while peak + 1 < n and nums[peak] < nums[peak + 1]:
        peak += 1

    # 2. 合并两个升序序列：
    #    左侧从 0 向 peak 走；右侧从 n-1 反向走到 peak+1。
    left = 0
    right = n - 1
    count = 0

    while left <= peak and right > peak:
        if nums[left] < nums[right]:
            left += 1
        elif nums[left] > nums[right]:
            right -= 1
        else:
            # 同一个数在山峰两侧各出现一次，只计一次。
            left += 1
            right -= 1
        count += 1

    # 3. 某一侧剩余的值本身严格递增，因此每个都是新值。
    count += peak - left + 1
    count += right - peak

    return count
```

### 逐步执行

对 `[1, 2, 4, 7, 6, 4, 2]`：

```text
peak = 3，nums[peak] = 7
left = 0，right = 6

nums[left]=1 < nums[right]=2
消费左侧1，count=1，left=1

2 == 2
同时消费，count=2，left=2，right=5

4 == 4
同时消费，count=3，left=3，right=4

7 > 6
消费右侧6，count=4，right=3

右半段结束；左边还剩峰值7
count=5
```

### 正确性说明

循环开始时，`nums[left]` 与 `nums[right]` 分别是两个尚未处理的升序序列中的最小值：

- 如果左值小，它不可能在右侧剩余部分中出现，因为右侧剩余值只会更大，所以可以安全计数并移动左指针；
- 如果右值小，同理移动右指针；
- 如果相等，两边代表同一个值，同时跳过且只计一次；
- 一侧耗尽后，另一侧剩余部分严格递增，所以每个剩余元素都是新的不同值。

因此算法恰好对并集中的每个值计数一次。

### 复杂度

- 找峰值最多扫描 $n-1$ 次；
- 双指针阶段每次至少移动一个指针，总移动次数不超过 $n$；
- 时间复杂度：$O(n)$；
- 只使用 `peak`、`left`、`right`、`count`，额外空间复杂度：$O(1)$。

### 面试口述版

> 我先找到峰值，把原数组看成左侧正向升序和右侧反向升序两个有序序列。然后用归并双指针统计并集：哪边小就移动哪边，相等时两边同时移动但只计一次。一侧结束后，另一侧因为严格单调，剩余元素全部直接计数。找峰和归并都是线性扫描，时间 $O(n)$，只用常数个指针，空间 $O(1)$。

### 如果允许相邻重复怎么办？

若题目是“先非递减、后非递增”，同一侧也可能连续重复，例如：

```text
[1, 2, 2, 5, 5, 3, 3, 2]
```

此时每次选出当前最小值 `value` 后，要在左右两侧把所有等于 `value` 的元素一起跳过，再让 `count += 1`。峰顶平台的边界也要单独定义。面试中可以先写严格单调版本，再说明如何通过“跳过连续相等值”扩展。
