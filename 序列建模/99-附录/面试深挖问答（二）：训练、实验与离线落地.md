# 司乘序列面试深挖问答（二）：训练、实验与离线落地

> **事实边界**：本项目目前是离线探索。以下关于指标、训练和工程的回答，只基于已有离线实验记录；没有线上 A/B、线上时延、QPS 或业务收益时，不能把“预期做法”说成“已验证结论”。未在工程配置中确认的超参数，以“需要回查代码/配置”为准。

本文承接 [[面试深挖问答（一）：业务、样本与架构]] 的 Q1–Q57，从 OneTrans 的效率设计开始，继续回答训练、实验和离线落地问题。

## 一、Pyramid 与 KV Cache：先讲清楚它们解决什么

### Q58. OneTrans 为什么还需要 Pyramid，而不是把所有 token 原样堆到最后？

OneTrans 把多个域的行为 token 放进同一个因果注意力空间后，历史越长，注意力计算和显存都随 token 数快速增长。Pyramid 的目的不是“创造更多信息”，而是将较早、细粒度的历史逐层压缩为更少的摘要 token，把计算重点保留给最近、最可能影响当前决策的行为。

可以把它理解为看司机近 20 次行为：最近几次接驾距离、取消、收益变化保留得细；更早的十几次不一定逐条展开，而压成“近一段时间偏好远单、收益波动较大”一类摘要。这样做的前提是早期细节对当前任务的重要性较低；这不是无损压缩。

### Q59. Pyramid 的压缩对象和输出分别是什么？

输入是前一层的 token 表示，而不是原始 ID 本身。一个压缩模块把相邻或局部的一组历史表示聚合，输出更短的一串 summary token；后续层在“近期细粒度 token + 更早的摘要 token”上继续建模。具体采用何种 pooling、卷积或可学习聚合，必须以 OneTrans 论文和项目实现为准，不能自行断言某一种算子。

### Q60. Pyramid 会不会把关键的早期行为压掉？如何回答这个风险？

会，这正是它的主要取舍。若某个很早发生但影响长期偏好的事件被压平，模型可能损失信息；因此需要用不同序列长度、不同压缩率和不压缩版本做消融，并按长尾用户、低频司机等人群切片。当前项目可说“采用分层压缩以控制长序列成本”，但不能说“已经证明完全无信息损失”。

### Q61. 为什么序列变长后，注意力成本会成为瓶颈？

对长度为 \(L\) 的标准自注意力，\(QK^\top\) 需要构造 \(L\times L\) 的相关性矩阵，单层核心复杂度约为 \(O(L^2d)\)，其中 \(d\) 是隐藏维度。长度从 20 增至 40，不只是 token 翻倍，注意力项大约变为四倍；所以“加长序列”必须同时讨论收益、显存和训练吞吐。

### Q62. KV Cache 在这里缓存的是什么？

每层注意力中，历史 token 经线性投影得到的 Key 和 Value 可以复用。因果推理时计算新 token，只需生成它自己的 Query/Key/Value，再用新 Query 与历史缓存的 Key 计算注意力，并对历史 Value 加权；无需为全部历史 token 重算投影。

### Q63. KV Cache 能否跨用户、跨请求直接复用？

通常不能。缓存对应某个具体样本、具体用户或会话的历史上下文，换用户或换序列便失去语义；它的典型收益来自同一条自回归序列逐 token 生成时的复用。若服务端复用跨请求缓存，还需要严格保证用户、特征快照、模型版本和过期条件一致；当前项目没有可引用的线上缓存实现，不能声称已经这样做。

### Q64. 如果面试官问“Pyramid 和 KV Cache 的关系”，怎么答？

两者解决不同阶段的问题。Pyramid 通过减少有效 token 数降低模型本身的序列计算量；KV Cache 在因果逐步推理时避免对既有 token 重复计算。前者是表示/模型结构层的压缩，后者是推理执行层的复用，可以同时使用。

### Q65. 如何证明 Pyramid 或 Cache 真有用？

离线应分别报告：相同训练预算下的 AUC、LogLoss 或任务指标；相同硬件和 batch 下的显存、step time、吞吐；以及不同长度下的曲线。Cache 更应看在线式逐步推理的端到端耗时；如果尚未做对应 benchmark，正确表述是“原理上可降低重复计算，项目尚未形成可对外声明的时延数据”。

## 二、多任务训练：损失怎样传回模型

### Q66. 这个多任务模型的总损失可以怎样写？

概念上可写为

$$
\mathcal L = \sum_{k\in\{D,O,OD\}} \alpha_k\,m_k\,\mathcal L_k,
$$

其中 \(\mathcal L_k\) 是任务 \(k\) 的损失，\(m_k\) 用于屏蔽该样本没有标签的任务，\(\alpha_k\) 控制任务权重。共享 Embedding、共享序列层和任务相关的 PEPNet 参数都会接收对应梯度；最终使用的损失类型、权重和 mask 逻辑必须按项目训练脚本确认。

### Q67. 为什么不能只用一个 OD 标签训练所有任务？

OD 表达双方匹配后的联合结果，但它不能替代司机侧或乘客侧的独立信号。比如订单未成交可能由乘客价格敏感、司机接驾距离过远或供需同时变化造成；只训 OD 会把这些机制混在一个标签里。D/O 辅助任务提供了更细的监督，但任务是否应共训仍需由离线消融验证。

### Q68. 标签缺失时为什么要 mask，而不是补 0？

“没有标签”与“标签为 0”不是一回事。若一个任务在该样本上不可定义却被补 0，模型会收到错误的负样本梯度；mask 的作用是让该任务不对该样本反传。反过来，若业务定义上确实可观察到失败事件，它才是合法的 0 标签。

### Q69. 任务样本量差异很大时，怎么避免大任务淹没小任务？

可从三处处理：采样上控制每个 batch 的任务构成；损失上设置任务权重或动态权重；诊断上分别查看各任务的梯度范数和验证集指标。不能只看总 loss，因为总 loss 降低可能完全来自样本最多的任务。具体使用哪一种是实现选择，当前材料未给出固定方案。

### Q70. 怎么判断多任务发生了负迁移？

做单任务与多任务的可比对照：固定数据切分、特征、训练预算和随机种子，分别观察 D/O/OD 的离线指标；再看不同任务梯度余弦相似度、任务头 loss 和分人群指标。如果加入某任务后另一个任务稳定下降，且不是训练不稳定造成，才有“负迁移”的证据。

### Q71. PEPNet 和 PLE 都是在解决多任务问题，它们的分工差别是什么？

PLE 的核心是通过共享专家、任务专家和门控路由解决“哪些网络容量应共享”；PEPNet 通过 EPNet/PPNet 让特征表示和隐藏层计算随个体/域条件自适应。前者更偏专家级共享结构，后者更偏个性化条件调制；两者可以是替代关系，也可以结合，但不能仅凭名称就断言项目同时采用了所有机制。

### Q72. 如果 D 指标显著提升、O 或 OD 变差，优先看什么？

先确认不是评估和样本口径问题：三个任务的样本量、正负比例、标签时点和数据切分是否一致。随后检查任务权重、共享层梯度冲突、任务特有特征是否被过度共享，以及某个任务是否在更容易的样本上“刷高”了 AUC。不能为了单一 D 指标直接牺牲联合任务；应按业务目标确定可接受的 Pareto 取舍。

### Q73. D→O 与 O→D 的交叉影响该怎样解释？

如果统一序列真的学到了供需和双方交互，D 侧和 O 侧任务可能互相提供有效上下文；但相关提升不等于证明模型学到了因果影响，也可能来自公共的时空、订单难度或样本筛选信号。需要移除某一侧序列、只保留静态共享特征等消融，才能区分“共享环境”与“跨侧序列”贡献。

### Q74. batch size 从 256 扩大为 1024，走一个 step 是否等价于原来走四个 step？

不等价。大 batch 的梯度是在 1024 个样本上的一次平均，小 batch 连续四步会在每一步更新参数，后几步的梯度是在已更新参数上计算；再加上 Adam/Adagrad 的动量、二阶矩和学习率调度，轨迹也会不同。只有使用梯度累积、且中间不更新参数时，才更接近大 batch 的一次更新。

### Q75. 为什么要关注 warmup、学习率和梯度裁剪？

序列模型与多任务模型早期梯度方差通常较大，学习率过高容易使共享底座被某个任务迅速拉偏；warmup 让模型先进入稳定区间，梯度裁剪限制极端 batch 的更新幅度。它们是常见稳定手段，而不是当前项目已验证优于所有设置的结论。

### Q76. 如何区分“模型能力不够”与“训练方式不对”？

先做诊断而非继续堆参数：训练集和验证集都差，可能是特征、标签、优化或容量不足；训练集很好而验证集差，更像过拟合或时间分布偏移；增加训练步数、调学习率后指标大变，说明优化仍是瓶颈；多种训练配方都饱和且特征/标签无新增信息，才更像模型上限。结论应来自控制变量实验。

## 三、离线实验：怎样证明改动可信

### Q77. PEPNet × OneTrans 相比 pep-seq 的离线增益是什么？

当前实验记录中，pep-seq-onetrans 相比 pep-seq 的 AUC 为：OD 从 0.7421 升至 0.7503，O 从 0.7339 升至 0.7613，D 从 0.8036 升至 0.8697。这证明在该离线数据、样本处理和训练配置下，新结构有更高的区分能力；它不等价于线上转化、完单或收益提升。

### Q78. 如何设计公平的 baseline 对比？

固定训练/验证/测试切分、标签口径、特征可用时点、样本过滤、训练轮数或早停规则；只改变一个待验证模块。还要核对参数量和训练预算：若新模型参数、batch 或训练时长大幅增加，则“结构更好”的结论不充分。

### Q79. 为什么序列长度实验不能只写“越长越好”？

历史越长会增加潜在信息，也会引入过期行为、噪声和更高优化难度。当前记录里长度 20 优于 10、30、40，说明该数据和配置下存在收益—噪声—成本的平衡点；不能把 20 视作任意业务、任意模型的通用最优长度。

### Q80. 6 月和 12 月（或不同时间段）数据对比应如何解读？

不同月份的季节性、城市供需、策略版本和样本分布都可能变化。若某个时间段表现更好，先检查标签定义、样本量、特征覆盖和训练/测试时间顺序；只有控制这些因素后，才能讨论模型对分布变化的鲁棒性，不能把月份差异直接归因于架构。

### Q81. 参数量增加后指标提升，怎么证明不是“纯堆容量”？

做容量匹配对照：给 baseline 增宽/增深到相近参数量，或把新模型缩小到相近参数量；同时报告参数量、FLOPs、显存和训练时间。若结构改动在等容量下仍稳定赢，且关键消融能解释增益来源，才更能说明结构设计有效。

### Q82. 为什么“司机/乘客完全拆开”可能不如统一 OneTrans？

完全拆开先在各自域内压缩，再做有限融合，可能使供需、订单难度和双方时序关系过晚相遇。统一因果 token 流让不同域 token 更早发生注意力交互；但这仍是结构假设，必须以“统一但无跨域 attention”“分流后融合”等消融支撑。当前记录只表明统一版本离线优于该拆分版本。

### Q83. 加入时空特征后为什么可能提升，也可能回退？

时空特征可解释需求、供给和接驾难度，是双方共享的强上下文；但高基数格子、稀疏长尾、时间泄漏或过强的城市/时段捷径也会造成过拟合。应检查特征可用时点、缺失率、时间外推表现，并观察是否只在少数城市或高频样本上提升。

### Q84. 为什么过滤规则、正负样本比例、batch size 都会改变结论？

它们会改变训练分布和优化噪声。过滤可能移除难样本，采样比例改变分类先验和梯度构成，batch size 改变更新频率及优化器状态；所以一次“模型提升”必须伴随完整样本与训练配置，才能复现和解释。

### Q85. 一个合格的消融实验表应该至少包含什么？

至少列出：移除或替换的模块、其余设置是否不变、每个 D/O/OD 任务的指标、参数量/训练成本、结果波动（多随机种子时更好）及结论边界。例如移除跨域 attention、移除 PEPNet、改序列长度、改静态 token 注入方式，分别验证各模块的边际贡献。

### Q86. 为什么不能只报告一个 AUC？还需要看什么？

AUC 衡量整体排序区分能力，却不反映概率是否校准、业务关注区间是否提升或资源成本。应至少补充 LogLoss/校准情况、不同城市/供需/活跃度切片、训练推理成本；若未来有对应决策，也要定义与业务目标一致的离线排序或收益代理指标。当前项目不应伪造尚未记录的指标。

### Q87. 随机种子与时间切分为什么重要？

深度模型的随机初始化、shuffle 和负样本会带来波动；时间序列任务更要防止随机切分把未来模式泄漏到过去。至少应保持训练早于验证/测试，并在资源允许时报告多 seed 的均值和方差；单次最优点不足以证明稳定提升。

### Q88. 哪些结论目前最不该说得过满？

不应把离线 AUC 增益说成线上业务收益；不应把统一序列的相关性提升说成发现了真实因果机制；不应把一次长度/月份/采样实验推广为通用规律；也不应声称某种 PEPNet 或 OneTrans 细节已按论文完整复现，除非代码和配置可核验。

## 四、离线数据与“准备上线”：必须区分事实与方案

### Q89. 当前项目的数据链路应该怎样从一个预测样本构造？

离线构造的基本顺序是：确定样本锚点与预测时刻；只取该时刻之前可见的司机、乘客、订单和时空特征；按实体和时间回查历史行为；排序、截断、padding 后 token 化；最后按任务生成标签并做时间切分。核心原则是每个特征都要能回答“在预测时刻是否已知”。

### Q90. 离线序列和线上序列怎样保证一致？

当前尚未上线，因此这是上线前必须验收的设计问题，而不是已完成事实。应统一特征定义、时间窗口、排序方向、截断规则、缺失值和字典版本；用同一批请求把离线回放结果与服务侧结果逐字段对账，并对关键特征建立新鲜度与空值监控。

### Q91. 历史回查为什么容易出现笛卡尔积膨胀？

如果每个目标样本都直接 join 一个实体的大量历史行，亿级目标样本乘以长历史候选会产生巨量中间结果。例如每个订单回查 100 条司机历史和 100 条乘客历史，粗暴双侧 join 就会放大到乘积级别。正确思路是分别在实体侧裁剪候选，再按样本锚点回填，避免先把两侧历史相互展开。

### Q92. “ID + 时间戳预排号、锚点截断后回表”为什么能降低开销？

可先在司机/乘客维度按时间预排序并生成序号；对每个订单锚点，只定位其之前固定窗口或最近 \(K\) 条记录的序号区间，再回表取该小段历史。这样 join 的候选从“该实体全历史”缩至“有限区间”，中间数据量约由全历史长度降到 \(K\) 或时间窗大小；具体收益仍取决于分布和执行引擎，需要压测证明。

### Q93. 缺失历史、冷启动或异常 token 怎么处理？

可使用 padding token、缺失标记和静态/上下文特征作为退化输入，并确保 attention mask 不让 padding 参与有效计算。冷启动不是简单补零：还要在离线评估中单独切出无历史或短历史人群，确认模型不会把“缺失”误学成某种偏好。当前是否已有这套服务策略，需要以实现为准。

### Q94. 序列特征怎样序列化给模型？

训练侧通常将每个事件编码为定长字段向量或 token ID 组合，并同时存储时间、位置、类型、mask 和长度；batch 内通过 padding 对齐。无论使用 TFRecord、Parquet、Hive 表还是线上 protobuf，关键是字段 schema、词表/分桶版本和 token 顺序不能漂移；具体存储格式不是当前文档可确认的事实。

### Q95. 如果以后要做推理时延优化，应优先看什么？

先测端到端分解：特征读取与序列组装、Embedding lookup、注意力计算、网络层、序列化和 RPC 各占多少。对短序列，特征服务往往比模型更先成为瓶颈；对逐 token 因果解码，KV Cache 才更有价值。当前没有线上时延数据，不能给出“已经达到多少毫秒”的答案。

### Q96. 线上监控应观察哪些，但当前能否说“已监控”？

上线后应监控特征空值/延迟、序列长度分布、token 覆盖率、预测分布、校准、各城市与人群切片、服务时延和资源使用，以及与旧模型的分桶对照。当前是离线探索，只能说这是预上线监控清单，不能说这些监控已经部署。

### Q97. 若未来出现离线高、线上低，第一轮排查顺序是什么？

先查数据一致性和泄漏：训练/服务特征口径、时间可见性、序列排序、字典/分桶、缺失处理；再查流量和样本分布漂移；最后才讨论模型或策略本身。尤其序列任务中，一个未来事件混入历史就能让离线指标虚高，因此应优先做逐样本回放对账。

## 五、追问与复盘：把项目讲得诚实且有判断

### Q98. 这个项目最核心的创新点是什么？

不是简单把更多特征塞进模型，而是把司机、乘客和双方联合任务放进同一时序建模问题：PEPNet 用条件化方式适配个体差异，OneTrans 让跨域行为在统一因果 token 流中交互。离线结果支持该组合在当前实验设置下优于 pep-seq；创新的价值仍需进一步的消融、成本评估和线上验证。

### Q99. 如果从简单 MLP 迭代，你的合理路径是什么？

先建立可复现的静态特征 MLP 与严格时间切分；再验证单侧短序列是否带来稳定增益；随后引入统一序列和跨侧交互；最后再考虑个性化调制、层次压缩和更长历史。每一步只新增一个核心变量，保留可回滚 baseline，避免无法判断收益来自哪里。

### Q100. DIN、SASRec 与这里的方案各自适合什么？

DIN 擅长围绕当前候选对历史做目标注意力，适合候选明确的兴趣匹配；SASRec 用因果 Transformer 建模单实体行为序列；本项目的 OneTrans 重点是司机、乘客、订单/上下文等多域 token 的统一交互。选择并非谁绝对更强，而取决于任务是否有明确候选、是否需要跨主体时序关系及资源约束。

### Q101. 如何避免模型只学到“城市、时段、价格”这种捷径？

这些变量本身可能是真实有效上下文，问题在于模型是否只靠它们而忽略行为机制。可做去除/置乱特征消融、跨时间/跨城市验证、按相同城市时段分层比较序列增益，并检查极端依赖特征的 SHAP/注意力不能作为因果证据，只能作诊断。若移除后整体崩塌，说明需审视泛化风险。

### Q102. 如何评估低频司机、低频乘客和长尾城市？

按历史长度、活跃度、城市规模、供需紧张度和订单类型分桶报告 D/O/OD 指标、覆盖率和校准。统一序列可能对高频用户更有利，也可能因共享上下文帮助冷启动；不能只报告平均 AUC。长尾样本量小还应附置信区间或至少说明波动风险。

### Q103. 发现特征分布漂移后，模型应怎样迭代？

先定位漂移来自数据缺失、业务策略变化还是季节性，再判断标签关系是否也漂移。轻度特征漂移可通过更新统计量、词表/分桶或重训处理；若标签机制改变，需要重新定义训练样本和离线评估窗口。任何重训都要回到时间外验证，而不是只看随机验证集。

### Q104. 如果只允许做下一轮三个实验，你会优先做什么？

第一，补齐“静态、单侧序列、双侧统一序列、去 PEPNet”的等预算消融，定位增益来源；第二，做严格时间外与城市/历史长度切片，检验泛化；第三，测序列长度与压缩策略的指标—成本曲线，明确可部署边界。三者分别回答“为什么有效、是否稳健、是否可用”。

### Q105. 面试官追问“为什么不直接上线”，如何回答？

因为当前证据仅来自离线 AUC 等建模实验，尚不足以证明线上业务收益、时延可接受性和特征一致性。上线前至少要完成时间外验证、特征回放对账、模型成本压测、灰度与守护指标设计；这不是保守，而是把离线相关性和线上策略价值分开验证。

### Q106. 面试官问“你个人最主要的贡献”，如何避免说空话？

按可复核产物讲：明确自己负责的样本锚点/序列构造、某个 PEPNet 或 OneTrans 模块、训练脚本、消融设计或结果分析；说明提出了什么假设、如何控制变量、结论是什么、结论边界是什么。若无法确认某段代码归属，应说“参与并理解”，不要把团队工作泛化成个人主导。

### Q107. 用一分钟怎样收束整个项目？

“这是一个离线的司乘双边序列建模探索。我们以 D、O、OD 三个任务为监督，先保证特征只使用预测时刻可见的信息，再把司机、乘客和上下文行为 token 放入统一的因果序列中，通过 PEPNet 做个性化条件调制、通过 OneTrans 做跨域交互。当前离线记录显示 pep-seq-onetrans 在三项任务 AUC 上优于 pep-seq；但它还不是线上结论，下一步重点是补全消融、时间外稳健性和成本验证。”

### Q108. 项目中最容易被质疑的地方是什么？

一是特征时间泄漏与样本口径，二是新模型是否仅因参数/训练预算更大而获益，三是离线 AUC 能否迁移到线上，四是长序列成本是否可接受。主动讲出这些边界，并给出对应验证设计，比回避更能体现建模判断力。

### Q109. 如果被问到未记录的 hidden size、head 数、损失权重或特征字段，怎么答？

不要猜。可以先解释该参数影响什么，再明确“我会以当前训练配置/代码为准确认具体值”；例如 head 数影响多子空间关系建模与显存，任务权重影响梯度平衡。面试中宁可把机制讲对，也不要编造不可核验数字。

### Q110. 本文档的最终边界是什么？

它用于帮助从业务、样本、架构、训练、实验到预上线验证完整讲清离线探索；它不替代代码、特征字典和实验配置，也不授权将任何预期方案写成既有线上事实。所有需要精确数字的回答，都应在面试前再与实现和实验日志核对一遍。

## 六、工程细节与风险：继续往下追问时怎么答

### Q111. 原始数据至少要有哪些主键，才能可靠拼出双边序列？

至少要能定位实体和事件时刻：司机 ID、乘客 ID、订单/尝试 ID、事件时间、事件类型；若涉及供需和地理上下文，还要有城市、区域/格子与相应快照时间。主键不是为了“多 join”，而是为了让每条历史行为都能在样本锚点之前、且归属到正确实体。

### Q112. 订单的多个事件（发单、应答、取消、完单）应该拆成多条 token 还是合成一条？

取决于预测时点和任务。若这些事件的发生顺序与间隔本身有信息，可拆成事件 token，并带 event type 与时间差；若任务只需订单级总结，合成订单 token 更节省长度。两种都必须保证预测时刻之后的事件不会进入输入；当前项目具体选择应按 schema/代码确认。

### Q113. 双边序列的时间如何对齐？

不能简单把司机第 \(i\) 条和乘客第 \(i\) 条硬对齐。通常先对每一侧按真实发生时间排序，再以当前订单锚点截取历史，并通过相对时间、绝对时间桶和当前订单上下文让模型理解它们的先后关系；若最后合入统一 token 流，则再按全局事件时间排序并采用因果 mask。

### Q114. 什么是这类项目最隐蔽的数据泄漏？

最常见的是把结果态字段混入预测态：例如完单后的真实时长、最终价格、取消后的状态、未来窗口统计量，或在数据 join 时没有限制事件时间。另一类是随机切分导致同一实体的未来行为帮助预测过去。防泄漏的核心不是看字段名，而是逐字段检查“在该预测时刻能否被系统观察到”。

### Q115. 高基数 ID、连续值和缺失值各怎么进模型？

ID 类特征通常查 embedding；连续值可归一化/分桶后做数值投影或 embedding；类别缺失和数值缺失要保留显式 missing 标记，不能让缺失与合法的 0 混淆。具体分桶边界、词表大小、共享方式是训练配置，不应在没有代码依据时报出固定数字。

### Q116. 一个 batch 在模型里的张量形状大致是什么？

可把它描述为：静态特征为 \([B,F]\) 或 embedding 后的 \([B,F,d]\)，序列为 \([B,L,F_s]\) 或 token 表示 \([B,L,d]\)，同时配有 \([B,L]\) 的有效位 mask 和因果 attention mask；任务头输出通常是 \([B]\) 或 \([B,1]\)。\(B\) 是 batch size、\(L\) 是截断长度、\(d\) 是隐藏维。真正的维度以实现为准。

### Q117. 为什么序列截断不应只保留“最近 K 条”？

最近性通常有效，但不总等于重要性：低频用户的 K 条可能覆盖很长时间，高频用户却只覆盖很短时间；关键异常或周期性行为也可能在更早位置。更稳妥的做法是在离线中比较按最近 K、按时间窗口、最近+代表性采样等策略，并按活跃度切片，而不是先验断言一种截断必然最佳。

### Q118. 如果某一侧历史为空，统一模型会不会失效？

不应失效。输入层应使用该侧的空序列/padding mask，同时让模型仍能利用另一侧历史、静态特征和当前上下文；训练集也要覆盖这种样本，否则模型可能只在“双侧都有丰富历史”的理想样本上有效。是否真的稳健，需要单独报告空序列人群的离线结果。

### Q119. 这个项目的“创新”如何与已有 PEPNet、Transformer、OneTrans 区分？

不要把引用已有结构说成算法原创。更准确的说法是：针对司乘双边、多任务、时空订单场景，将个性化网络与统一因果序列交互进行组合并做离线验证；你的贡献应落在具体问题建模、特征时点、样本构造、结构适配和严谨消融上。论文方法的原创性与项目落地创新是两个层次。

### Q120. 为什么不先用简单 MLP 或传统统计特征就结束？

MLP 与统计特征是必要 baseline：它们成本低、可解释性较强，也用于判断复杂模型是否真的带来增益。继续做序列模型的理由是统计聚合会丢掉事件顺序、间隔和跨侧交互；但只有在等口径离线实验中出现稳定增益，复杂结构才有正当性。

### Q121. 为什么不是直接用 DIN 或 SASRec？

DIN 需要一个明确的 target/candidate 表示来对历史做目标注意力，SASRec 更自然地对应单实体的下一个行为序列。司乘问题同时存在司机、乘客、订单和环境 token，统一序列结构更方便表达跨域依赖；不过 DIN/SASRec 仍应作为对照或组件候选，不能因为任务复杂就跳过简单且强的 baseline。

### Q122. 模型会不会把司机和乘客的相关性误学成因果关系？

会。观测数据中的共同城市、时段、天气、供需、平台策略会同时影响双方行为，因此 attention 权重或 AUC 提升只能说明预测相关性，不证明“司机历史导致乘客行为”。该项目属于预测建模；若要回答因果问题，需要明确干预、处理变量、反事实估计和实验/准实验设计，不能混用表述。

### Q123. 如何检查模型对不同人群是否公平或稳健？

先定义业务上需保护或需保证覆盖的人群，例如低频司机、低频乘客、长尾城市、不同供需状态；分别比较 AUC、校准、召回/风险以及缺失率。发现平均指标提升但某类人群显著下降时，应回到样本覆盖、特征质量和任务权重，而不是只用全量平均值掩盖问题。

### Q124. 如果供需或平台规则变化，原模型还能直接用吗？

不能默认可以。策略、价格规则或供需结构变化会使特征分布甚至标签条件分布改变；需要用时间外窗口回测、漂移诊断和重训后对照来确认。特别是序列模型可能把旧策略轨迹学得很深，因此必须关注历史行为的时效性。

### Q125. 下一步怎样把离线探索推进为可信的上线候选？

顺序应是：补齐等预算消融和时间外/人群切片，确认增益来源与稳健性；完成离线回放与特征一致性校验；测成本和服务可行性；再设计灰度、对照和守护指标。每一步都在降低一种不确定性，不能直接从离线 AUC 跳到“应上线”。
