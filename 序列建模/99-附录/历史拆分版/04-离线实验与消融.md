# 离线实验与消融：PLE 基座的司乘序列化改造

> 本文只回答三个问题：离线对照是什么、改造后有什么现象、哪些结论可信。模型原理见 [[02a-已确认实现：PEPNet + Positional Self-Attention 序列基线]] 和 [[02-模型架构：PEPNet × OneTrans]]；所有原始表格、推导和 TODO 保留在 [[实验原记录-完整版本]]。

## 1. 实验起点与统一口径

补充材料将 PLE 称为“线上 base 模型抽取”的架构来源。本项目在离线侧以 `PLE base` 作为对照，分别尝试 PLE + 序列、PEPNet + Positional Self-Attention，以及 PEPNet/PLE × OneTrans。

这里必须区分两件事：

- **架构来源**：PLE 来自“线上 base 模型抽取”的描述；
- **实验结论**：下文 `valid_od_auc`、`valid_o_auc`、`valid_d_auc` 全部是离线训练/验证结果，不代表线上 PLE 指标或线上业务收益。

任务定义为：`D=乘客履约`、`O=司机履约`、`OD=司乘履约率`。

## 2. 先建立序列化 baseline

### 2.1 PLE base → PLE + Positional Self-Attention

在 2025 年 6 月和 12 月、序列长度 10、每笔 10 个字段、epoch=1 的表中，`PLE base` 是统一参考行。序列化后，D 和 OD 稳定上涨，O 出现下降：

| 数据集 | PLE base | PLE + PosSA 相对 PLE base |
|---|---|---|
| 2025-06 | OD `.7684` / O `.7643` / D `.8422` | OD `+1.07pp` / O `-1.08pp` / D `+3.30pp` |
| 2025-12 | OD `.7735` / O `.7696` / D `.8430` | OD `+1.12pp` / O `-2.74pp` / D `+4.02pp` |

这说明“直接在 PLE 上加入序列”并没有让三任务同向收益，尤其司机履约 O 存在明显权衡。

### 2.2 PEPNet + Positional Self-Attention：主序列建模 baseline

`PEPNet + Positional Self-Attention` 将乘客、司机各 `10×10` 历史订单分别编码，再用 EPNet/PPNet 完成场景、样本和任务级门控，是后续 OneTrans 叙事的前序 baseline。

同一组 PLE base 参照下：

| 数据集 | PEPNet + PosSA（实验 1）相对 PLE base |
|---|---|
| 2025-06 | OD `+2.12pp` / O `+0.15pp` / D `+4.89pp` |
| 2025-12 | OD `+1.88pp` / O `-0.85pp` / D `+3.97pp` |

结论：相较 PLE base，PEPNet + PosSA 在 D/OD 上更稳定，O 的收益仍依赖数据与设置。详细输入和结构见 [[02a-已确认实现：PEPNet + Positional Self-Attention 序列基线]]。

## 3. OneTrans 探索结果

### 3.1 PEP × OneTrans

下表回答“在 PEP 序列模型上接入 OneTrans 是否有效”。此处严格对照是 `pep-seq`，不是 PosSA：

| 配置（epoch=9） | OD AUC | O AUC | D AUC |
|---|---:|---:|---:|
| `pep-seq` | .7421 | .7339 | .8036 |
| `pep-seq-onetrans` | .7503 | .7613 | .8697 |
| 绝对变化 | **+0.82pp** | **+2.74pp** | **+6.61pp** |

统一 `pep-seq-onetrans` 同时优于 `-driver` 和 `-pass` 独立版本，支持当前设置下司乘共享交互优于完全拆分。

### 3.2 PLE × OneTrans

| 配置（epoch=9） | OD AUC | O AUC | D AUC |
|---|---:|---:|---:|
| `ple-seq` | .7149 | .7286 | .7500 |
| `ple-onetrans` | .7350 | .7258 | .7972 |
| 绝对变化 | **+2.01pp** | **-0.28pp** | **+4.72pp** |

`warmup-ontrans-8layer-ple` 在 epoch=2 时 D=.8109，但 O=.7102；它说明深层/预热可能优先加速 D 收敛，不能当作多任务整体最优结论。

## 4. 序列消融：O 为什么提升不稳定

### 4.1 序列长度与时空字段（2025-06、BS=1024）

| PEPNet + PosSA 配置 | OD | O | D | 相对 PLE base 的 O |
|---|---:|---:|---:|---:|
| L10 | .8017 | .7679 | .8915 | +0.36pp |
| L20 | **.8134** | **.7945** | .8979 | **+3.02pp** |
| L30 | .7948 | .7361 | .8977 | -2.82pp |
| L40 | .7851 | .7660 | .8820 | +0.17pp |
| L10 + 6 个时空字段 | .7974 | .7707 | **.9021** | +0.64pp |

L20 在这组 6 月配置里对 OD/O 最好，时空字段对 D 更明显；12 月未复现稳定的 O 正向，因此不能称作全局最优长度。

### 4.2 对 O 低增益的排查

| 假设 | 做法 | 结果 | 可得结论 |
|---|---|---|---|
| 多任务 trade-off | 单独拆 O tower | 无直接提升 | O 不升不能优先归因于 OD/O/D 的优化冲突。 |
| passenger 序列稀疏 | L10 且跨度 <10 天 | O=.7301，且样本从约 16384w 降到 1174w | 过滤受样本量/分布混杂；控制数量级后无增益。 |
| 序列对 O 是噪声 | O 不输入序列，或只训练 O | O=.7397 或 .7602，均未改善 | 硬切 tower 输入反而破坏共享信息。 |
| 优化超参 | 比较 BS=128/256/512/1024 | 记录显示 BS=256 有强正向现象 | 需固定 step、LR schedule、样本量后再确认机制。 |

因此，当前更合理的判断是：O 对序列窗口、字段内容、时空上下文和训练协议更敏感，而非单一的“序列无用”或“任务冲突”。

## 5. 可以对外说的结论与不能说的结论

可以说：

- 以线上 PLE base 的架构为起点，完成了离线司乘双边序列化改造与 PLE/PEP/OneTrans 对照；
- PEPNet + PosSA 是主序列建模 baseline，OneTrans 是统一交互方向；
- OneTrans 在 PEP × OneTrans、epoch=9 实验族内相对 `pep-seq` 带来 OD `+0.82pp`、O `+2.74pp`、D `+6.61pp`；
- 序列长度、时空字段、Batch Size 与任务输入方式是关键影响因素。

不能说：

- 离线结果等同于线上 CR、取消率或接驾距离收益；
- OneTrans 的 +6.61pp 直接相对 PosSA；
- L20 在所有数据或任务上最优；
- PLE/PEP/OneTrans 绝对 AUC 可跨月份、epoch、Batch Size 直接排名。

## 6. 后续严格实验

1. 固定数据、step、随机种子、学习率策略，比较 `PLE base / PLE+PosSA / PEPNet / PEPNet+PosSA / PEPNet+OneTrans`；
2. 对 BS=`128/256/512/1024` 固定总 step 和 schedule；
3. 分开控制序列长度、时空字段、乘客/司机来源和 D→O 表示交互；
4. 如进入线上阶段，再做序列一致性、时延和业务指标验证。
