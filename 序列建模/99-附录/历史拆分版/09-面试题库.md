# 面试题库

> 这份题库用于快速定位知识点；更长的追问见 [[面试深挖问答（一）：业务、样本与架构]] 与 [[面试深挖问答（二）：训练、实验与离线落地]]。

## A. 项目总览

### Q1：这个项目解决什么问题？

订单履约模型原本依赖静态与统计特征，历史行为被压缩且司乘链路割裂。项目把两侧历史订单构造成序列，在 PEPNet + PosSA baseline 与 OneTrans 统一交互方案上开展离线探索。

### Q2：D/O/OD 分别是什么？

`D` 是乘客履约，`O` 是司机履约，`OD` 是司乘履约率。它们共享司乘订单与上下文，但行为机制不同，因此需要多任务共享和个性化分支共同处理。

### Q3：PLE 和当前项目是什么关系？

材料将 PLE 标为“线上 base 模型抽取”的架构来源。本项目离线以 `PLE base` 做对照，不将离线 AUC 写成线上 PLE 或线上业务收益。

## B. 数据与序列

### Q4：为什么不用取消率、均值等统计特征？

统计特征损失行为顺序、时间间隔和时空上下文。序列让模型区分“最近一次长接驾取消”和“很久以前的一次取消”，并能结合当前价格、接驾距离和供需上下文判断相似性。

### Q5：如何避免序列穿越？

以 `prediction_time` 为锚点，仅取更早且当时可用的事件；标签和未来结果不进入当前输入；训练、验证、推理采用同一排序、截断和 padding 规则。

### Q6：序列的基本规模是什么？

一版 baseline 中，乘客和司机各取 10 笔历史订单、每笔 10 个字段；总输入记录为 343 维，但 `poso` 的启用状态因 run 而异，需要回查配置。

## C. PLE、PEPNet 与 PosSA

### Q7：为什么 PEPNet + PosSA 是 baseline？

它先独立编码司乘历史订单，再通过 EPNet/PPNet 按场景、样本和任务动态缩放，是当前项目主序列建模路线。它不是 OneTrans +6.61pp 的严格数值对照行。

### Q8：EPNet 和 PPNet 分别做什么？

EPNet 在底层表示上做场景级 gate；PPNet 在 OD/O/D 各任务网络的每层 hidden 上做任务级 LHUC gate。前者调节输入特征重要性，后者调节不同样本的有效网络通道。

### Q9：PLE 为什么去掉 gate？

材料记录的旧 gate 在不同场景下几乎都激活同一个共享专家，专家利用退化。去掉后让专家/特征有更完整的可达路径；具体效果仍应以对应消融 run 为准。

## D. OneTrans

### Q10：OneTrans 相比 PosSA baseline 改了什么？

PosSA 是先分开编码两条序列、再融合静态特征；OneTrans 将历史事件和当前订单/上下文统一 token 化，让序列内、跨司乘序列和序列—静态特征交互在同一骨干中进行。

### Q11：+6.61pp 相对谁？

严格相对 `pep-seq`：D 从 `.8036` 到 `.8697`。尽管项目叙事可把 PosSA 称为主 baseline，但未确认 `pep-seq` 的内部实现，所以不能把该差值直接说成相对 PosSA。

### Q12：为什么不完全拆 driver/pass 分支？

`pep-seq-onetrans-driver/pass` 都低于统一版本，说明当前设置下两侧历史和当前订单存在互补信息。优先保留共享 backbone，再用 role embedding、任务 gate 或 adapter 做软差异化。

## E. 实验与局限

### Q13：为什么 O 提升不稳定？

拆 O tower、移除 O 序列输入都没有改善，排除了简单任务冲突和纯噪声解释。L20、时空字段和 BS=256 在部分数据上有效，说明 O 更依赖窗口、特征与训练协议，尚未形成跨月稳定结论。

### Q14：Batch Size=256 为什么可能更好？

双边序列增加重复和高维特征，较小 batch 的梯度噪声可能起到正则化作用。但这只是解释假设，需固定 optimizer steps、LR schedule、样本量和随机种子验证。

### Q15：能说明线上收益吗？

不能。现有材料只支持离线 AUC；线上仍需完成序列一致性、延迟与 A/B/业务指标验证。
