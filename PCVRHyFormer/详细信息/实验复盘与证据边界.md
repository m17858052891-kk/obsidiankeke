# 实验复盘：证据、结论与待验证项

## 先给结论

本项目最值得保留的不是“堆更多模块”，而是三类对齐：

1. **ID 与统计值的语义对齐**：对严格逐位置配对的字段做 `Embedding(id)+Linear(stat)` 后再池化。
2. **请求与行为的时间对齐**：请求时段/星期与行为距请求时间差分别建模。
3. **候选与历史的软对齐**：516 在 Query Generator 内用候选物品做前置 Bilinear Target-Aware Pooling。

## 已验证的反例

- **盲目扩长序列不是收益来源**：更长历史会把弱相关、久远行为带入注意力和优化路径。
- **硬匹配不等于语义对齐**：覆盖率低、重复曝光或 ID 记忆会让 hand-crafted match 在时间分布变化时失效。
- **ID 当数值计算没有语义**：类别 ID 的乘积、差值等操作应避免。
- **乘法融合不一定更强**：若统计值尺度不稳，会直接压制 ID 表征与梯度；加法残差式融合更稳。

### 硬匹配特征到底怎么做

该特征属于历史后续实验，并非当前 516 的前置候选感知 Query。它对候选 `item_id` 与某一路历史序列的指定字段做逐位置**精确相等**判断；核心 pair 是：

```text
candidate item_id ↔ seq_c.fid47
```

即判断用户历史中是否出现过当前候选广告本身。对第 $t$ 个历史位置：

$$
M_t=\mathbb{1}[x_t=i_{\mathrm{item}}]
$$

随后将逐位置布尔匹配汇总为三个手工统计值：

$$
c=\sum_tM_t,\qquad
r=\min_{t:M_t=1}b_t,\qquad
\rho=\frac{c}{L}
$$

实际送入模型的是：

```text
[log(1 + 匹配次数), 最近匹配时间桶 / 总桶数, 匹配次数 / 序列有效长度]
```

无匹配时，最近匹配时间使用“最远时间”的 sentinel。该 3 维统计值经零初始化的线性层投影为 64 维残差，并加在 HyFormer 主干最终输出上：

$$
o_{\mathrm{final}}
=
o_{\mathrm{HyFormer}}
+
W_{\mathrm{match}}
\,[\log(1+c),r/B,\rho]
$$

因此它并不是真正的 DIN Attention：没有学习每个行为位置的权重，也不认识“不同 ID 但语义相近”的商品；它只是显式编码“是否见过同一候选、见过几次、最近何时见过”。该 pair 的历史覆盖率约为 10.87%，大量样本落入无匹配 sentinel，容易形成 ID 记忆和缺失模式偏置。留档注释显示该方案从约 `0.826` 回退至 `0.820`。

## 下一轮实验的最小矩阵

固定数据切分、随机种子、训练轮数、参数量和优化器，只变一个因素：

| 实验 | 变化 | 要回答的问题 |
|---|---|---|
| E0 | mean-pool Query Generator | 干净主干基线 |
| E1 | E0 + 前置 bilinear pooling | 候选感知前置是否有效 |
| E2 | E0 + 后置 residual DIN | 前置与后置的公平比较 |
| E3 | E1 + 同 fid 加法融合 | 静态语义对齐的独立收益 |
| E4 | E3 + 时间桶 | 时间对齐的独立收益 |

每个实验至少记录：代码 hash、完整配置、数据/schema hash、验证切分、AUC、LogLoss、分桶指标、checkpoint 与训练日志。

## 汇报中的反常识洞察

> 信息更多不等于模型更强。对 PCVR 来说，关键不是把所有历史和匹配规则塞进模型，而是让候选相关性、时间新鲜度和字段配对关系以正确的时机进入模型。软对齐通常比硬编码匹配更稳健。
