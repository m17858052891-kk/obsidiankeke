# Pyramid 序列压缩：从逐层缩短到候选感知筛选

## 结论先行

Pyramid 不是“一开始就截断序列”，而是一种**逐层缩短序列计算范围**的策略：

> 低层广泛读取完整历史；高层只持续更新少量、更高价值的 Token，把计算集中在更深的交互与抽象上。

之所以叫 Pyramid，是因为随网络深度增加，参与更新的序列 Token 数越来越少，形状像金字塔：

```text
第 1 层：████████████████  512 个 Token
第 2 层：████████          256 个 Token
第 3 层：████              128 个 Token
```

它特别适合“序列很长，但并非所有行为都值得在每一层重复建模”的场景。

---

## 1. 先用 8 条行为理解 Pyramid

假设用户有 8 条历史行为：

```text
1：很久前浏览纸巾
2：很久前浏览洗衣液
3：浏览手机
4：浏览耳机
5：浏览手机壳
6：加购手机
7：最近浏览手机
8：最近浏览 iPhone 配件
```

### 1.1 普通 Transformer

普通多层 Transformer 会在每一层都处理全部 8 条：

```text
第 1 层：[1][2][3][4][5][6][7][8]
第 2 层：[1][2][3][4][5][6][7][8]
第 3 层：[1][2][3][4][5][6][7][8]
```

优点是每条行为都能被反复更新；缺点是远期、重复或低价值行为也会占用同样的 Attention、FFN 和显存预算。

### 1.2 Pyramid

Pyramid 则让低层看全量，高层逐步缩短：

```text
第 1 层：[1][2][3][4][5][6][7][8]
第 2 层：            [5][6][7][8]
第 3 层：                    [7][8]
```

直觉是：

- 第 1 层负责从完整历史中识别局部关系和基础证据；
- 第 2、3 层不再对所有旧行为反复投入同等计算；
- 高层把容量集中在更可能影响当前决策的少量行为上。

因此，它不是“旧行为永远没用”，而是“旧行为不再在每层都拥有同等更新预算”。

## 2. OneTrans 中的 Pyramid Stack 到底怎么做？

OneTrans 的 Pyramid Stack 更精确地说是：**每层只让一部分 S Token 发出 Attention Query，但仍对完整序列计算 Key / Value。**

设该层输入有 $L$ 个序列 Token，选取 $L'$ 个后部位置组成保留集合 $\mathcal Q$：

$$
\mathcal Q=\{L-L'+1,\ldots,L\}
$$

只有 $i\in\mathcal Q$ 的 Token 产生 Query：

$$
q_i=W_i^Qx_i,\qquad i\in\mathcal Q
$$

但 Key / Value 仍由完整序列生成：

$$
K=[k_1,\ldots,k_L],\qquad V=[v_1,\ldots,v_L]
$$

保留下来的 Token 可以读取全量历史：

$$
x_i'=
\mathrm{Attention}(q_i,K,V),
\qquad i\in\mathcal Q
$$

Attention 后，仅保留 $\mathcal Q$ 对应的输出，下一层的序列长度由 $L$ 变成 $L'$。

### 2.1 它和“直接删掉前面的行为”不一样

在第 2 层只保留 `[5][6][7][8]` 为 Query 时：

```text
[5][6][7][8]：继续更新自己的表示
[1]~[8]：仍可作为 K/V，供保留下来的行为读取
```

也就是说，较早行为不再生成新的输出 Token，但仍可以作为证据被较晚行为读取。因此 Pyramid 是**逐层聚焦**，不是输入端的粗暴截断。

### 2.2 计算为什么会下降？

完整 Self-Attention 的主要成本约为：

$$
O(L^2d)
$$

若只保留 $L'$ 个 Query，而 K/V 仍为全长 $L$，Attention 成本近似变为：

$$
O(LL'd)
$$

当 $L'\ll L$ 时，后续层的 Attention、FFN 激活和显存都显著下降。OneTrans 以此让序列长度随层数收缩，并将更多资源留给更深的统一交互。[OneTrans 第 3.4 节](https://arxiv.org/html/2510.26104)

---

## 3. 一个容易混淆的点：这里的 Query 不是 HyFormer 的 Global Query

Pyramid 中说“保留部分 Token 发出 Query”，指的是 Transformer Self-Attention 的 $Q$：

$$
\mathrm{Attention}(Q,K,V)
$$

即每个行为 Token 是否继续向其他行为读取信息。

而当前 PCVRHyFormer 中的 8 个 Global Query，是由静态 NS Token 和候选感知摘要生成，用于在 Cross-Attention 中读取完整历史：

```text
Pyramid 的 Q：行为 Token 在域内 Self-Attention 中是否继续更新
HyFormer 的 Query：全局检索指令，去域内 K/V 中读取候选相关证据
```

两者都叫 Query，但层级和职责完全不同。

## 4. Pyramid、固定截断、可学习裁剪与可学习压缩的区别

| 方法 | 核心问题 | 保留哪些行为 | 是否动态依赖样本 | 典型风险 |
|---|---|---|---|---|
| 固定截断 | 最多输入多少条？ | 固定最近 $K$ 条 | 否 | 可能丢失很早但很强的行为 |
| Pyramid | 每层花多少算力？ | 随层数递减的一部分 Token | 通常否 | 固定保留规则未必等于真正重要性 |
| 可学习裁剪 | 具体保留哪几条？ | 打分后 Top-$K$ 行为 | 是 | Top-$K$ 离散选择可能不稳定 |
| 可学习压缩 | 如何将长历史浓缩？ | 多条行为合成少量摘要 Token | 是 | 可能过早丢失细节 |

### 4.1 可学习裁剪

可为每个行为 Token 打分：

$$
r_{m,t}=
\mathrm{MLP}
\left(
[h_{m,t};q_{\mathrm{item}};e_{\mathrm{time},m,t}]
\right)
$$

其中：

- $h_{m,t}$：第 $m$ 个域、第 $t$ 条行为的上下文表示；
- $q_{\mathrm{item}}$：候选商品表示；
- $e_{\mathrm{time},m,t}$：该行为距当前请求的时间表征；
- $r_{m,t}$：该行为是否值得进入更高层的分数。

随后保留 Top-$K$ 行为，或将分数转为 soft gate。前者选择明确但不可微、训练更不稳定；后者可微但不一定带来实际加速，因为 Token 数未真正减少。

### 4.2 可学习压缩

另一种方法不是选行为，而是用少量 latent Token 从长序列聚合信息：

$$
C=\mathrm{CrossAttention}(Q_{\mathrm{latent}},H,H)
$$

其中 $Q_{\mathrm{latent}}$ 的数量远小于序列长度。它将 512 条行为压成例如 32 个摘要 Token，再交给高层 Transformer 或 HyFormer Block 使用。

## 5. 为什么这比“直接加深、加宽、拉长序列”更值得尝试？

当前实验记录中，将序列扩展到 1024 后，分数从约 0.826 回退到 0.8255。这个结果不能证明 Pyramid 一定有效，但说明一个重要现象：

> 当前瓶颈可能不是“模型看过的历史不够多”，而是“新增历史中的噪声没有被有效筛选和分配计算预算”。

直接扩长序列会让每层都处理更多远期、重复或弱相关行为；直接加深/加宽则会把更多参数花在同一批噪声 Token 上。

Pyramid 的思路是：

```text
低层：完整历史，不轻易丢证据
中层：减少重复或低价值 Token 的更新
高层：集中建模候选相关、近期、有代表性的行为
```

这使“更长历史”与“有限计算预算”不再完全冲突。

## 6. 在当前四域 PCVRHyFormer 中如何改造？

不能直接照搬 OneTrans，原因是：

- OneTrans 使用统一 Causal Transformer；
- 当前模型是四域独立 Transformer，默认采用域内双向 Attention；
- 当前模型已有 request-to-event Time-Bucket 和前置候选感知 Query。

更适合当前模型的渐进式实验是：

```text
每域原始序列（最多 256 / 512）
        ↓
Block 1：完整域内 Transformer
        ↓
根据候选相关性、时间新鲜度、行为强度评分或压缩
        ↓
每域保留 / 压缩为 128~256 个 Token
        ↓
Block 2：在更干净的序列上继续 Sequence Evolution
        ↓
Global Query Cross-Attention + RankMixer
```

例如候选是 iPhone：

```text
原始 512 条历史
  → 高分保留：近期手机、耳机、配件、价格带相近行为
  → 低权重：很久前、低相关、重复过多的日用品浏览
  → Block 2：在压缩后的高价值行为上做跨域反馈后的再检索
```

### 6.1 最稳妥的第一版

建议先不要使用硬 Top-$K$。可先试：

1. Block 1 保留完整序列；
2. 在 Block 1 后按“时间新鲜度 + 前置 DIN 权重”进行软/规则化压缩；
3. 每域通过相邻窗口 pooling 或候选感知聚合，把 512 个 Token 压到 128 或 256 个；
4. 仅让 Block 2 使用压缩后的序列；
5. 保持 Query Generator、RankMixer、预测头不变。

这样改动边界清晰：验证的是“高层是否需要处理全部 Token”，而不是同时推翻整个 HyFormer 架构。

### 6.2 顺序口径必须先确认

OneTrans 的 tail Token 指输入排列中更靠后的 Token。只有当序列按“从旧到新”排列时，tail 才等于“最近行为”。

因此改造前必须确认当前四域序列的排序方向：

```text
旧 → 新：可将后部 Token 解释为近期行为
新 → 旧：近期行为在前部，不能机械保留 tail
```

并且当前模型使用双向 Attention，不能天然依赖 OneTrans 中“Causal Mask 会将信息逐渐汇聚到后部”的性质。若采用位置裁剪，必须先用消融验证；候选感知或时间感知评分通常更稳妥。

## 7. 建议的实验矩阵

| 实验 | Block 1 序列 | Block 2 序列 | 目的 |
|---|---|---|---|
| E0 | 完整 | 完整 | 当前基线 |
| E1 | 完整 | 固定最近 256 | 验证高层是否需要全长序列 |
| E2 | 完整 | 时间感知压缩至 256 | 验证新鲜度是否足够作为压缩依据 |
| E3 | 完整 | DIN 权重引导压缩至 256 | 验证候选相关性是否能指导压缩 |
| E4 | 完整 | 可学习 soft gate / latent 压缩 | 验证更强的可学习压缩是否值得复杂度 |

除整体 AUC 外，至少需要观察：

- 长序列用户与短序列用户的分桶指标；
- 高/低时间差行为的 Attention 或保留比例；
- 不同候选类目下的效果；
- 训练吞吐、显存、线上 P99 延迟；
- 压缩后是否出现某类高意图行为被系统性丢失。

## 8. 面试回答模板

> Pyramid 压缩不是在输入时粗暴删掉长历史，而是让低层先读取完整序列、在高层逐步缩短继续更新的 Token 数。以 OneTrans 为例，高层只保留一部分 Token 作为 Self-Attention Query，但完整历史仍可作为 Key/Value 被读取，因此早期行为仍能提供证据。它解决的是长序列中“每条行为在每一层都花同等计算”的低效问题。对于当前四域 HyFormer，我不会直接照搬按位置保留的 Pyramid，而会先在 Block 1 后利用时间新鲜度和候选相关性压缩每域序列，再让 Block 2 进行跨域反馈后的精读；这更符合 PCVR 的候选条件化特征。

## 9. 与当前模型的证据边界

- 当前 516 代码没有 Pyramid Stack、可学习裁剪或 latent 压缩；
- 历史“1024 长度回退”的记录只能说明盲目扩长序列未带来收益，不能证明任何 Pyramid 方案已经有效；
- 本文档是后续实验设计与面试推演材料，所有收益结论都必须以固定预算的消融结果为准。
