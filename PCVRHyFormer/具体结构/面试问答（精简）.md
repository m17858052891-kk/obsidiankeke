# PCVRHyFormer：核心 11 问

## 1. 项目要解决什么问题，baseline 是什么？

目标是多行为域广告 CVR 预估。baseline 以静态特征和多路行为序列为输入，但候选 item 对历史兴趣的影响注入偏晚、跨域融合不足。最终版本以静态 Token、四域序列编码、前置候选感知 Query、HyFormer 与 RankMixer 为主线。

## 2. 为什么静态特征 Token 化，而不是全部 Concat？

若一开始将所有静态 embedding 直接 concat 后交给 MLP，但字段会在第一层就被无差别混合；后续模块较难表达“候选 item 应主动查询用户哪部分画像、请求上下文应如何调制候选与历史的匹配”这种条件化关系。

Token 化后，模型可以让候选 Token 作为 Query，让用户/上下文 Token 或行为历史作为 Key/Value，按当前样本动态决定读取哪类信息。这是一种更有结构的归纳偏置，不是说 concat 一定不能用；在字段少、交互简单、延迟极紧的场景，concat + MLP 反而可能更合适。

**面试口述版：** Concat 是先混合再拟合，Token 化是保留字段身份后再让模型选择性交互。我们这里候选、用户和上下文之间存在明显的条件关系，因此希望候选能主动查询不同来源的信息，Token 化更适合 Attention/跨域融合结构。

## 3. 静态特征和行为序列如何联合建模？联合训练时怎样保证稳定？

**先校正问题：**“两类特征不同，为什么能收敛”这个前提并不严谨。语义不同本身不是收敛障碍；更有价值的讨论是，异构特征如何保留各自结构后联合建模，以及怎样避免尺度、梯度和数据质量问题导致训练不稳定。

静态特征和行为序列分别经过各自的 embedding/投影，映射到同一隐藏维度 $D$ 的可学习接口；之后 Attention 或 MLP 学习的是“在当前 CVR 目标下两类信息如何组合”，而不是要求二者原始含义相同。

可以把两类输入理解为两个信息源：

- 静态特征是样本发生时的**状态与条件**：用户画像、候选 item、请求上下文、统计特征；
- 行为序列是用户过去的**动态证据**：做过什么、何时做的、兴趣如何变化。

模型不会把原始 ID、价格、历史点击直接硬拼。我们先分别编码：

$$
z_{static}=\operatorname{Proj}_{static}(x_{static}),\qquad
H_{seq}=\operatorname{Encoder}_{seq}(x_{1:L}),
$$

其中 $z_{static}$ 被拆成用户、候选、请求等静态 Token；$H_{seq}$ 是各行为域经过序列编码后的历史 Token。它们维度相同只是为了可以做点积、Attention 和后续融合，**不代表它们被迫共享同一种语义**。就像多模态模型可让图像 token 与文本 token 交互，关键在于各自先有合适编码器，再由训练目标把它们对齐到任务需要的关系空间。

从优化角度看，最终损失是同一个 CVR Loss：

$$
\mathcal L=\operatorname{BCE}\big(y,\,f_{head}(\operatorname{Fuse}(z_{static},H_{seq}))\big).
$$

反向传播会沿融合层同时回传到静态 encoder 和序列 encoder。若某个静态字段或某段历史对预测无用，模型可以学到较小的融合权重/attention 权重；若二者组合有增量信息，梯度会同时调整两侧表示，使其在融合层中更容易被利用。因此“共同收敛”本质上是一个端到端可微计算图在同一损失下的联合优化问题。

例如，候选是“跑鞋”时，候选静态 Token 可以作为 Query 去匹配历史序列中“浏览运动袜、购买跑步装备”的表示；Attention 的 $q^Tk$ 学到的是“这个候选条件下，这条历史是否有用”。如果候选换成“手机”，同一段历史得到的权重就会不同。这正是静态上下文与动态历史共同拟合的价值。

Token 化保留字段边界与来源身份，让 Attention 学“用户、候选、请求、上下文、历史行为”之间的条件交互；若一开始全部 concat 后送 MLP，不同字段会过早混合，候选难以有选择地查询某一路历史信息。

真正可能让联合训练不稳的不是“语义不同”，而是优化条件不好，例如：静态数值尺度和稀疏 embedding 更新频率差异很大、序列过长造成梯度噪声、某一路特征过强导致另一分支被忽略，或 padding/时间穿越引入伪信号。我们的处理是：静态/序列先分支编码；用 token type、域、时间/位置表示保留来源；用 Norm 控制尺度；正确 mask；Embedding 与稠密主干分组优化；再通过候选感知 Query、Cross-Attention/HyFormer 做有条件融合，而不是无差别相加。

**面试口述版：** 我不会把它回答成“因为不同特征也能收敛”。更准确地说，静态特征提供当前状态，序列提供历史证据；它们各自先编码、保留字段和时间语义，再通过统一维度作为交互接口共同服务 CVR Loss。真正需要处理的是尺度差异、稀疏和稠密参数更新频率、padding/穿越及某一分支主导训练的问题，所以我们用分支编码、Norm、mask、分组优化与候选感知融合来保证联合训练稳定。

## 4. 为什么同 FID 的 ID 与统计值做逐元素加法？

ID embedding 给类别语义，统计特征提供该类别的数值状态。逐元素对齐再相加让同一维度保留“该类别在当前统计下的修正”，比直接拼接更轻，也比乘法更不易把任一方接近零的噪声放大。

## 5. 为什么四路行为序列分域编码？

不同域的行为语义、频率和时间分布不同。先独立编码避免高频域淹没低频域，再在 Query/HyFormer 阶段跨域交互；直接拼接会让位置、字段和行为类型的语义混杂。

## 6. Query Token 如何生成，为什么在此前加入 DIN？

多兴趣 Query 从各域历史表示中池化/生成。前置 DIN 让候选 item 在 Query 形成阶段就对历史做软匹配，得到“与当前候选有关的兴趣 query”；若在 Query 形成后才加，候选只能修正已定型的泛化兴趣，信息进入太晚。

## 7. HyFormer 做了什么，为什么纯 DIN 不够？

DIN 擅长候选对历史的局部注意力，但缺少多 Query 兴趣演化、域内序列关系和跨域融合。HyFormer 在序列演化、Query decoding/boosting 中让多个兴趣 Query 与序列反复交互，因此能表示更复杂的兴趣结构；代价是参数和训练难度更高。

## 8. RankMixer 为什么不直接堆 MLP 或全局 Self-Attention？

MLP 的 token 交互偏弱；全局 Self-Attention 对所有 token 两两交互，成本高且可能引入无关噪声。RankMixer 以更受结构约束的 mixing 建模 query/token 交互，在表达力、参数和计算间折中。

## 9. 为什么扩长序列、加入硬 item-history match 反而回退？

更多历史会引入陈旧兴趣和噪声；硬匹配把“是否相同”当强规则，可能破坏语义相似但 ID 不同的软相关性，也容易在训练集记忆。实验更支持：候选、时间和字段语义应在正确阶段以软匹配注入。

## 10. 为什么 Embedding 用 Adagrad，稠密部分用 AdamW？

稀疏高频/长尾 ID 的更新频次差别大，Adagrad 对高频特征自动降低有效步长，对低频特征保留较大步长；Transformer、MLP 等稠密参数通常用 AdamW 获得更平稳的自适应优化和解耦 weight decay。
