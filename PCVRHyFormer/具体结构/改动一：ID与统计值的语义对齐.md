# 改动一：ID 与统计值的语义对齐

## 1. Baseline 是什么

baseline 中，离散多值特征与对应的稠密统计特征通常走两条独立路径：

```text
ID 列表 → Embedding → Mean Pool ─┐
                                ├→ 后续 Tokenizer / MLP
统计值列表 → MLP / Pool ──────────┘
```

这种写法能分别表达“用户出现过哪些 ID”和“统计值整体大小”，但会丢掉最重要的信息：**第 `j` 个统计值到底属于哪个 ID。**

例如：

```text
category_ids = [运动, 美妆]
freqs        = [20,   1]
```

分别池化后，模型只看到“运动、美妆都出现过，统计总量为 21”，却不再显式知道高频的是运动而不是美妆。

## 2. 改动：先在元素位置上融合，再池化

仅对满足以下前提的字段启用该改动：ID 数组与统计值数组长度一致、位置一一对应、统计值的业务语义确实属于对应 ID。

对每一个有效位置 `j`：

$$
h_j = E(id_j) + W x_j + b
$$

再做 mask 后的均值池化：

$$
h_{field}=\frac{\sum_j m_j h_j}{\sum_j m_j+\epsilon}
$$

其中 `m_j` 是 padding mask。`E(id_j)` 为离散 ID 的 Embedding，`W x_j+b` 将该位置的连续统计值映射到同一维度。

```text
(运动,20) → Emb(运动) + Linear(20) → h_1
(美妆, 1) → Emb(美妆) + Linear( 1) → h_2
                               ↓
                         Masked Mean Pool
```

## 3. 为什么采用加法融合

加法相当于残差式修正：即使统计值分支在训练初期尚未学好，ID Embedding 主路径仍能完整通过；统计值逐步学习如何修正对应 ID 的表示。它既保留位置语义，又不会强制统计值充当硬门控。

对比两个尝试过但不推荐作为主线的方案：

| 方案 | 问题 |
|---|---|
| 将统计值分桶后查 Embedding | 人为边界会损失连续性；桶边界附近不稳定 |
| 逐元素乘法 `E(id_j) ⊙ f(x_j)` | 数值尺度或接近零的门控会压制 ID 表征和梯度 |

因此这里的目标不是“做更强交叉”，而是先恢复被拆开的真实语义关系。

## 4. 代码层检查点

- 先在数据层断言两个列表长度一致；不一致的样本不能静默按错位位置融合。
- `padding` 的 ID、统计值和 mask 必须保持一致，避免统计值给 padding 注入非零信号。
- 连续统计值应先检查长尾、缺失值、量纲；必要时使用 `log1p` 或截断，但变换必须在线离线一致。
- 只对已确认配对的 fid 启用，不能因为两个数组长度相同就推断它们语义对应。

## 5. 如何做干净消融

| 实验 | 变化 | 要验证什么 |
|---|---|---|
| A0 | ID mean pool + stat 独立分支 | baseline |
| A1 | 逐元素加法融合 | 对齐关系是否带来收益 |
| A2 | 逐元素乘法融合 | 增强交互是否反而损伤稳定性 |
| A3 | 统计值分桶 Embedding | 连续值离散化是否值得 |

固定模型主干、随机种子、训练预算和数据切分；除 AUC 外，还要看不同统计值分位、冷 ID 和长尾 ID 分桶表现。

## 6. 面试表述

> 这不是普通的特征拼接优化。baseline 将 ID 与统计值分别池化后丢掉了位置配对关系；我改为先对同一位置的 ID 和统计值做加法融合，再池化，让模型保留“哪个实体对应多大强度”。我试过乘法和分桶，但前者容易受数值尺度支配、后者损失连续性，因此选择残差式加法作为更稳的表达。
