## 一页事实卡

| 项目 | 当前讲解口径 |
|---|---|
| 任务 | 单任务 PCVR 二分类，输出候选物品的转化 logit |
| 主干 | 4 路序列、2 层 HyFormer、RankMixer 全局 Token 融合 |
| 静态 Token | 3 用户 NS + 2 UE + 2 物品 NS + 1 请求时间 = 8 个，维度 64 |
| 初始 Query | 每域 2 个，共 8 个；由全部 NS Token 与本域候选感知摘要生成 |
| 候选感知 | 516 使用前置 Bilinear Target-Aware Pooling；item NS 均值作 Query |
| 时间 | 请求时段/星期周期编码 + 行为距请求的非均匀时间差分桶 |
| 训练 | BCEWithLogitsLoss；Embedding 用 Adagrad(lr=0.05)，其余参数用 AdamW(lr=1e-4, betas=(0.9,0.98))，全局梯度裁剪 1.0 |

## 证据边界

- 历史源码注释能确认约 `0.826` 是某一中间状态的参照分数，`0.8255` 是扩长序列后的回退结果。
- `516` 的前置 bilinear target-aware pooling 代码结构是自洽且可定位的；但仓库没有保留其与其他版本严格等预算对比的完整训练日志。
- 因此面试中可准确说“我采用/实现了 516 的前置候选感知结构，并将它作为当前主线”；不要把具体增益全部归因给该模块，除非补齐实验日志。
