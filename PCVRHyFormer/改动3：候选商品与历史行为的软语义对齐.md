# 核心结论：516 前置候选感知池化是当前最优

候选商品与历史行为的软语义对齐，最新结论应更新为：**516 版本的前置 DIN / Bilinear Target-Aware Pooling 优于后期 DIN residual 融合。**

这意味着，候选 item 不应该只在最终输出阶段作为补丁加入，而应该在 Query Generator 阶段就参与每一路行为序列的兴趣摘要生成。

# 1. 516 版本到底做了什么

代码中对应的是 `use_target_attn=True`。模型先由 item NS tokens 得到候选物品表示：

$$
e_{target}=\operatorname{MeanPool}(N_{item})
$$

再得到候选感知的兴趣向量：

$$
h^{target}_s=\sum_j a_{s,j}h_{s,j}
$$

这个 $h^{target}_s$ 会和展平后的静态 NS tokens 拼接：

$$
G_s=[N_{flat};h^{target}_s]
$$

最后通过每个行为域自己的 FFN 生成 Query tokens：

$$
Q_s^{(1)},Q_s^{(2)}=\operatorname{FFN}_s(G_s)
$$

所以 516 的本质是：**先用候选 item 过滤历史，再生成 Query，再进入 HyFormer。**

# 2. 为什么它优于后期融合

后期 DIN residual 的思路是先让 HyFormer 主干编码所有历史，然后在输出端再用候选 item 做一次 Cross-Attention 补充。这个做法安全，但候选语义进入得太晚。

516 的优势在于：

1. **早期降噪**：无关历史在进入主干推理之前就被降权，降低噪声在 Transformer / RankMixer 中扩散的机会；
2. **Query 从出生起就 target-aware**：后续两层 HyFormer 的 Cross-Attention 都围绕候选相关兴趣槽展开；
3. **双线性映射表达力更强**：$W_s$ 不只是点积相似度，而是在学习 item token 与 sequence token 的跨空间匹配；
4. **更符合 CVR 预测场景**：当前候选商品在请求时已知，先问“这个候选商品会唤醒哪些历史行为”更直接。

# 3. 与后置 DIN residual 的区别

| 方案 | 候选语义进入位置 | 主要作用 | 风险 | 当前判断 |
|---|---|---|---|---|
| 516 前置 target-aware pooling | Query Generator 前 | 先筛历史，再生成 Query | 需要 $W_s$ 学会跨空间匹配 | 当前最优 |
| 后置 DIN residual | 输出前 | 在主干表示上补候选相关信息 | 候选语义进入晚，可能补救不足 | 不再作为最优口径 |

后置 residual 的安全性来自保留主干路径，但这也意味着它更像“补丁”。516 则把候选感知变成主干兴趣提取的一部分。

# 4. 需要避免的误解

当前不要再沿用“激进替换”的旧口径。从代码看，516 的实现是 `BilinearTargetAttentionPooling + QueryGenerator`，是在生成 Query 之前完成候选感知池化，并没有在最终输出处强行替换主干表示。

更准确的表述是：516 用候选 item 对每一路行为序列做软选择，并把结果作为 Query 初始化依据。它优于后期融合，说明当前任务中“候选感知前置”比“输出端补残差”更有效。
