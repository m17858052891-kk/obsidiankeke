## 1. 硬匹配特征：把“是否见过同一候选”做成手工统计

### 1.1 当时具体怎么做

这不是当前 516 的前置候选感知 Query，也不是可学习的 DIN Attention；它是一个离线预计算的 **exact item-history match feature**。

核心配对为：

```text
candidate item_id ↔ seq_c.fid47
```

即拿当前候选广告的 `item_id`，与用户 `seq_c` 历史中 `fid47` 的每个位置做严格相等判断。若候选 ID 为 `12345`，历史为：

```text
[888, 12345, 456, 12345, 999]
```

则逐位置匹配结果为：

```text
[0, 1, 0, 1, 0]
```

形式化地，对第 $t$ 个历史位置：

$$
M_t=\mathbb{1}[x_t=i_{\mathrm{item}}]
$$

数据集再将这个布尔序列汇总成三个手工统计特征：

$$
c=\sum_tM_t
$$

$$
r=\min_{t:M_t=1}b_t
$$

$$
\rho=\frac{c}{L}
$$

其中 $c$ 是匹配次数，$r$ 是最近一次匹配的时间桶，$\rho$ 是匹配次数占该域有效序列长度的比例。实际输入模型的是：

```text
[log(1 + 匹配次数), 最近匹配时间桶 / 总桶数, 匹配次数 / 有效序列长度]
```

若没有任何 match，则“最近匹配时间”置为最远时间的 sentinel。最后，这 3 维特征经零初始化 Linear 投影为 64 维，并作为最终输出的残差：

$$
o_{\mathrm{final}}
=
o_{\mathrm{HyFormer}}
+
W_{\mathrm{match}}
\,[\log(1+c),r/B,\rho]
$$

零初始化意味着该残差在训练开始时为 0，理论上不会立刻扰动原模型；只有训练后权重偏离 0 才会开始使用它。

### 1.2 结果与回退原因

历史注释记录：仅启用这个核心 pair，AUC 仍从约 `0.826` 回退至 `0.820`。

最可信的原因不是“精确匹配一定无用”，而是这个具体特征在该数据上的泛化条件不成立：

- **覆盖率只有约 10.87%**：绝大多数样本没有匹配，模型实际更容易学习“是否命中”的稀疏模式，而非稳定的候选兴趣关系；
- **无匹配 sentinel 占比过高**：约 90% 样本接近同一个 `(0, 1.0, 0)` 模式，容易形成强烈的缺失分布偏置与校准漂移；
- **表达力太硬**：只认 `candidate_id == history_id`；iPhone 与手机壳、同类商品或不同广告版本都被视为完全无关；
- **可能存在时序边界风险**：若 `seq_c` 含有预测时点之后才可见的曝光/点击信息，训练中“见过同一广告”会成为捷径，但验证或线上关系未必保持；该风险需要靠严格的 event-time / availability-time 审计确认，不能直接断言已经发生泄漏；
- **注入位置偏晚**：它只作为最终输出残差，不能影响 Query 初始化和两层 Cross-Attention 的历史读取路径。

### 1.3 得到的结论

> “同一个 ID 是否出现过”可以是一个业务上直观的信号，但不能自动等价于可泛化特征。候选与历史的关系更适合由可学习的软匹配表达，而不是由低覆盖率的手工 equality 规则主导。

这也是当前 516 更强调前置 Bilinear Target-Aware Pooling 的原因：它对每个历史行为学习连续相关性分数，既可重视 exact match，也可利用类目、属性和行为表征上的近似相关性。详见 [[具体结构/改动三：前置候选感知Query初始化]]。

## 2. 为什么盲目拉长序列会造成泛化回退？

### 2.1 当时具体做了什么

稳定长度配置为：

```text
seq_a: 256
seq_b: 256
seq_c: 512
seq_d: 512
```

后续尝试并非只改一个数字，而是同时做了两件事：

1. 将原始序列最大长度扩到 `1024`，让模型看到更多早期历史；
2. 在每域 Token 化后、进入 HyFormer 前加入 LONGER 风格的 `InnerTrans` 压缩器。

`InnerTrans` 的做法是将相邻 $G=4$ 个 Token 分成一组，在组内做局部 Self-Attention，再将每组聚合投影成 1 个 Token：

```text
原始序列：1024 个行为 Token
       ↓ 每 4 个相邻行为为一组，组内局部 Attention + 聚合
压缩序列：约 256 个 Token
       ↓
进入原有 HyFormer 主干
```

它的设计目的很合理：在不大幅增加 HyFormer 主干计算的情况下，输入 4 倍更长的原始历史。

历史注释记录该“**InnerTrans + 长度扩展到 1024**”组合从约 `0.826` 回退至 `0.8255`，随后恢复为 `256 / 256 / 512 / 512` 的默认配置。

### 2.2 为什么可能回退

这次实验的结论应谨慎表述为：**更多原始历史加上局部压缩，没有带来净收益**。由于长度和压缩器同时改变，不能把回退完全归因于其中任一个。

可能机制包括：

- **远期历史本身信噪比低**：新增的 512～1024 区间更可能包含过期兴趣、偶然浏览和已失效偏好；
- **局部压缩可能误合并行为**：每 4 条相邻行为被聚合为 1 条，若组内混有不同品类、不同意图或强弱行为，细粒度候选相关证据会被混合；
- **当前任务更依赖近期候选相关性**：PCVR 中，近期行为与当前候选的语义匹配往往比更长的泛化历史更重要；
- **有限模型容量被重新分配**：新增历史并不免费。即使后续长度压回约 256，InnerTrans 仍需要先处理更多 Token，且会把更多噪声编码进下游 K/V；
- **时间对齐不是单纯加长即可解决**：已有 Time-Bucket 只能提供新鲜度条件，不能保证模型自动忽略所有低价值远期事件。

### 2.3 得到的结论

> 序列长度不是越长越好。扩长前应先验证新增区间是否有独立增益；若要处理更长历史，优先考虑候选相关、时间感知的压缩或筛选，而不是无差别地增加原始 Token。

这也是后续讨论 Pyramid、可学习裁剪与候选感知压缩的出发点：低层可保留更多历史，高层应把计算集中到近期、相关且有代表性的行为，而不是让所有远期行为重复参与每一层更新。详见 [[具体结构/Pyramid序列压缩：从逐层缩短到候选感知筛选]]。

## 3. 其他错误尝试：做法、结果与结论

| 尝试 | 当时怎么做 | 结果 / 风险 | 可迁移结论 |
|---|---|---|---|
| 低可信 category match pair | 根据小样本 vocab Jaccard 重合，将候选 item 的某些字段与序列字段做 exact match 统计 | 从约 `0.826` 降至约 `0.824` | ID 空间有重合不等于字段语义相同；没有业务实体证据，不应硬建 match pair |
| ID 直接数值交叉 | 尝试对类别 ID 做乘积、差值等数值操作 | 没有类别序号语义，风险高 | 类别 ID 应经 Embedding、点积/交叉网络，或有实体依据的 equality；不要把离散编码当连续数值 |
| ID 与统计值乘法融合 | 用统计值直接缩放 ID Embedding | 注释显示不如加法融合，且数值尺度会直接调制表示与梯度 | 对严格对齐的 ID+统计值，`Embedding(ID) + Linear(stat)` 更像稳定的残差修正；乘法应有充分归一化与消融证据 |
| 可学习乘法时间衰减 | 将行为 Token 乘以随时间桶衰减的系数 | 未优于仅加 Time-Bucket Embedding | 时间信息更适合作为可学习条件/attention bias；直接缩小整个 Token 易破坏内容语义 |
| `FiLM(label_type)` | 尝试以 `label_type` 生成 FiLM 调制 | 被识别为标签泄露后删除 | 任何 condition 都必须在预测时可得；标签或其强代理变量不得进入特征调制路径 |
| 过度堆叠后续模块 | 在较晚版本叠加 EMA、label smoothing、R-Drop、LAIN、额外池化等 | 部分缺少独立、等预算日志；不能归因给单个模块 | 不要将多个未隔离改动一起写成“最优模型贡献”；固定主干做单因素消融 |

### 3.1 当前可安全讲的三条正向结论

1. **语义对齐优于形式匹配**：同 fid 的 ID 与统计值在位置级对齐后再融合，有明确业务语义；仅按 ID 相等或 vocab 重合做规则，泛化风险更高。
2. **信息质量优于信息总量**：1024 长历史并未带来收益，说明关键不是堆更多行为，而是控制行为的新鲜度、相关性和压缩方式。
3. **软候选相关性优于硬编码捷径**：候选感知 Attention 让模型自己学习“哪条历史在当前候选下更有用”，比固定的 exact match 规则更适合表达相似商品和跨属性关联。
