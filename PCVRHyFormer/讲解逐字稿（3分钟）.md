
“我做的是一个多行为域的 PCVR 预估项目：给定用户画像、候选物品和四路历史行为，预测这次点击最终发生转化的概率。

一共有四组静态特征和四组序列特征，把用户的离散/稠密特征、候选物品、请求上下文压缩成 8 个静态 Token，把四路历史行为分别编码成动态序列；

瓶颈不在于继续加宽网络，而在于三类信息没有对齐：第一，部分离散 ID 和统计值描述同一个实体，却在模型里被拆开处理；第二，序列有顺序，但没有真正表达行为距离当前请求有多久；第三，模型知道用户历史是什么，却没有在足够早的阶段回答‘哪些历史和当前候选物品有关’。

所以我做了三件核心事。

第一是特征语义对齐。对于严格一一对应的 ID 数组和统计值数组，我们先在每个位置做 `Embedding(id)+Linear(stat)`，再池化。这样模型保留的是‘哪个 ID 对应哪个强度’，而不是分别得到一个 ID 均值和一个统计均值。我们试过分桶和乘法融合，但都不稳定：分桶损失连续性，乘法容易受数值尺度控制，所以最后保留加法残差式融合。

第二是时间双尺度建模。请求侧将小时和星期做周期编码；行为侧把每条记录距当前请求的时间差分到非均匀时间桶，并加到对应行为 Token 上。这样模型同时知道‘用户做过什么’和‘这件事是两分钟前还是两周前发生’。

第三是最关键的候选感知前置。四路多字段行为先编码成完整的 64 维序列 Token。然后用候选物品的 Token 表示，对每一路历史做双线性 target-aware pooling，先形成和当前候选相关的域兴趣摘要；这个摘要与 8 个静态 Token 共同生成每域两个 Query。也就是说，Query 从初始化开始就是 candidate-aware 的，而不是先学习一个泛化用户兴趣、最后再补一次匹配。

之后进入两层 HyFormer。每层先在域内用 Transformer 编码完整历史，再让 Query 用 Cross-Attention 回读本域序列，最后把 8 个 Decoded Query 和 8 个静态 Token 放进 RankMixer 做跨域、动静态融合。第二层使用第一层已经融合了其他域和静态画像的 Query，再次读取本域历史，完成一次条件更充分的二次检索。

最后，8 个 Query 拼接后经轻量 MLP 输出 PCVR logit，训练使用 BCE。优化上我们把高基数 Embedding 交给 Adagrad，把 Attention、MLP 和投影层交给 AdamW；因为两类参数的梯度稀疏性完全不同。
