
“我做的是一个多行为域的 PCVR 预估项目：给定用户画像、候选物品和四路历史行为，预测这次点击最终发生转化的概率。

一共有四组静态特征和四组序列特征，把用户的离散/稠密特征、候选物品、请求上下文压缩成 8 个静态 Token（Concat 是先混合再拟合，Token 化是保留字段身份后再让模型选择性交互。我们这里候选、用户和上下文之间存在明显的条件关系，因此希望候选能主动查询不同来源的信息，Token 化更适合 Attention/跨域融合结构），把四路历史行为分别编码成动态序列；

瓶颈不在于继续加宽网络，而在于三类信息没有对齐：第一，部分离散 ID 和统计值描述同一个实体，却在模型里被拆开处理；第二，序列有顺序，但没有真正表达行为距离当前请求有多久；第三，模型知道用户历史是什么，却没有在足够早的阶段回答‘哪些历史和当前候选物品有关’。

所以我做了三件核心事。

第一是特征语义对齐。对于严格一一对应的 ID 数组和统计值数组，我们先在每个位置做 `Embedding(id)+Linear(stat)`，再池化。这样模型保留的是‘哪个 ID 对应哪个强度’，而不是分别得到一个 ID 均值和一个统计均值。我们试过分桶和乘法融合，但都不稳定：分桶损失连续性，乘法容易受数值尺度控制，所以最后保留加法残差式融合。

第二是时间双尺度建模。请求侧将小时和星期做周期编码；行为侧把每条记录距当前请求的时间差分到非均匀时间桶，并加到对应行为 Token 上。这样模型同时知道‘用户做过什么’和‘这件事是两分钟前还是两周前发生’。

第三是最关键的候选感知前置。四路多字段行为先编码成完整的 64 维序列 Token；当前最大截断长度依次为 `seq_a=256、seq_b=256、seq_c=512、seq_d=512`。这里的截断由数据加载器直接保留上游序列的前 `256/512` 个位置且不重排，因此保留的是否为最近行为取决于上游数据的排序约定。然后用候选物品的 Token 表示，对每一路历史做双线性 target-aware pooling，先形成和当前候选相关的域兴趣摘要；这个摘要与 8 个静态 Token 共同生成每域两个 Query。也就是说，Query 从初始化开始就是 candidate-aware 的，而不是先学习一个泛化用户兴趣、最后再补一次匹配。

之后进入两层 HyFormer。每层先在域内用 Transformer 编码完整历史（先让每条行为结合该域其他历史，学习连续浏览、兴趣迁移、加购等上下文关系，得到更有语义的完整序列表示。  后续 Query 再基于当前候选，从这些“已理解上下文”的行为 Token 中检索相关证据，而不是直接对孤立行为做加权），再让 Query 用 Cross-Attention 回读本域序列，最后把 8 个 Decoded Query 和 8 个静态 Token 放进 RankMixer 做跨域、动静态融合。第二层使用第一层已经融合了其他域和静态画像的 Query，再次读取本域历史，完成一次条件更充分的二次检索。

最后，8 个 Query 拼接后经轻量 MLP 输出 PCVR logit，训练使用 BCE。优化上我们把高基数 Embedding 交给 Adagrad，把 Attention、MLP 和投影层交给 AdamW；因为两类参数的梯度稀疏性完全不同。

## 追问逐字稿：原始 HyFormer 与 RankMixer（约 90 秒）

“原始 HyFormer 想解决的问题，是传统推荐模型把长序列建模和静态特征交叉拆成两个串行阶段：先把行为序列压缩，再与用户、候选和上下文特征做融合。这样一旦序列被过早压缩，后面的特征交叉就没法再回到完整历史里补证据。

所以原始 HyFormer 的第一步，是把用户、候选、上下文等非序列特征 Token 与序列的全局均值摘要拼起来，通过多个 FFN 生成少量 Global Query。注意，原始版本的候选 item 会通过静态特征进入 Query FFN，但不会在 Query 初始化阶段逐位置筛选历史。接着 Query 对完整序列的 K/V 做 Cross-Attention，完成 Query Decoding；再将解码后的 Query 和静态 NS Token 一起送入 RankMixer，完成 Query Boosting。下一层复用这个已经融合过的 Query，再回去读取长序列，于是形成‘检索—融合—再检索’的闭环。

我当前的改造主要发生在 Query 初始化：将原始的序列均值摘要替换为候选感知的双线性 pooling。也就是说，候选不只是间接地进 Query FFN，而是先对每路历史做软筛选，再影响后续两层的检索方向。

RankMixer 在这里承担的是全局 Token 融合，不负责替代长序列 Attention。输入是 8 个从四域历史中取证后的 Query，加上 8 个用户、候选和上下文 NS Token，一共 16 个 Token。当前留档未发现 Query 或 NS Token 数量扩展的正式对照实验，因此不能把“16 个 Token 最优”作为结论。它会把每个 64 维 Token 切成 16 个 4 维子空间；对同一个子空间位置，收集所有 16 个 Token 的对应片段，拼成 64 维后经共享 FFN 混合，再写回各 Token。这样既做了跨 Token 的信息交换，也保留了每个 Token 的语义槽位。

如果直接将 16 个 Token 展平后接大 MLP，字段身份会在第一层被无差别混合，参数也会明显增多；RankMixer 保留 Token×Channel 的二维结构，参数更高效。相比全局 Self-Attention，它不需要 QK Softmax 的两两竞争，结构更规整、实现更适合高吞吐的 token mixing。但在我们这里只有 16 个全局 Token 的场景里，Self-Attention 的计算其实不大，所以我不会说 RankMixer 一定更好或主要是为了省算力；它的核心价值是结构归纳偏置和参数效率。严格比较仍应做同预算的 RankMixer、MLP、Self-Attention 消融。”

## 追问逐字稿：失败实验与反思


第一个是硬匹配特征。当时我们想把一个非常直观的信号直接交给模型：候选广告的 `item_id` 是否在用户历史序列里出现过。具体做法是将候选 ID 和 `seq_c` 中对应字段逐位置做 exact match，然后提取三个手工统计：历史中出现过几次、最近一次出现距当前请求多远、以及匹配次数占整个序列的比例。最后通过一个零初始化的线性残差加到 HyFormer 输出上。

但结果从约 0.826 回退到 0.820。后来复盘发现，这类特征的覆盖率只有约 10.87%，绝大多数样本都是无匹配；同时它只认完全相同的 ID，无法表达相似商品、同类目或不同版本广告之间的软相关。它很容易让模型学习到‘是否出现过同一广告’这个脆弱捷径，而不是稳定的候选—历史语义关系。所以我们没有继续强化规则匹配，而是转向前置的候选感知 Attention：让模型学习当前候选下，哪条历史值得读。

第二个是盲目拉长序列。默认长度是 `256 / 256 / 512 / 512`；我们曾经将原始历史上限扩到 1024，并在 HyFormer 前加入 LONGER 风格的 InnerTrans：每 4 个相邻行为先在局部做 Attention，再压成 1 个 Token，希望在不显著增加主干计算的情况下引入更多历史。这个组合最终从约 0.826 回退到 0.8255。

这里我不会把原因简单归结为‘长序列无效’，因为长度和压缩器是同时改的；但它至少说明新增的远期历史没有产生净增益。可能一部分是过期兴趣和弱行为噪声，另一部分是局部压缩把不同意图的相邻行为混在了一起，损失了候选相关的细节。

这两个反例让我最后形成的判断是：推荐模型不是信息越多、规则越直接越好，关键是候选相关性、时间新鲜度和字段语义要以正确方式进入模型。也因此当前主线优先采用软匹配、时间对齐和完整序列上的 Query 检索。”
