# 一、业务背景与目标

“我介绍一下这个多行为域 CVR 预估项目。

这个任务的目标，是根据用户画像、候选物品以及用户在多个业务域里的历史行为，预测当前候选物品的转化概率。

模型最初的baseline已经有很不错的表现。继续迭代时发现，瓶颈已经不在简单增加网络宽度或者堆叠 Transformer 层数，而在三个更具体的问题上：

第一，离散特征和统计特征虽然描述的是同一个实体，但在进入模型后丢失了对应关系；第二，模型知道用户做过什么，却没有充分理解这些行为发生在什么时候；第三，用户兴趣建模和当前候选物品之间的关联不够直接。

所以后面的优化思路不是继续无脑扩模型，而是围绕‘特征语义对齐、时间语义对齐和候选物品对齐’做了三项核心改造。”

# 二、整体架构概述

“我先快速讲一下模型主干，后面再展开三个核心改动。

输入侧一共有四类静态信息：用户离散特征、用户稠密特征、物品离散特征以及当前请求时间。

这些特征经过 Embedding 和 MLP 投影以后，被压缩成 8 个静态 NS Tokens。具体包括 3 个用户离散 Token、2 个用户稠密 Token、2 个物品 Token 和 1 个请求时间 Token，每个 Token 是 64 维。

动态行为侧有 4 路历史行为序列。每一路先做字段级 Embedding，再把同一个行为位置上的多个字段拼接并投影到 64 维，同时叠加该行为距离当前请求时刻的 Time-Bucket Embedding。

接下来是 MultiSeqQueryGenerator。它会把 8 个 NS Tokens 展平，然后分别提取四路序列的全局表示。每个序列域通过两套独立 FFN 产生两个兴趣 Query，所以四个域一共生成 8 个 Query Tokens。

这些 Query 和序列进入两层 HyFormer Block。每层都包含三步：先做域内序列 Transformer，再由 Query 对本域序列做 Cross-Attention，最后把 Decoded Query 和静态 NS Tokens 放进 RankMixer，完成跨域和动静态信息融合。

第二层 HyFormer 会拿着第一层已经融合过其他域信息的 Query，重新读取各自的行为序列。也就是说，它不是简单重复，而是一个‘读取行为—交换信息—带着全局上下文再次读取行为’的迭代推理过程。

最后，把 8 个 Query 拼接成 512 维向量，投影到 64 维，再叠加候选物品感知的 DIN 残差，经过 MLP 输出最终的 CVR logit。”

# 三、三个最核心的 S 级改动

# S 级改动一：离散特征与稠密统计的元素级语义对齐

“第一个改动发生在输入层，我认为这是整个项目里最扎实的一项特征工程。

当时我们发现，部分用户特征同时包含一个离散 ID 数组和一个稠密统计数组，并且两个数组在元素位置上是一一对应的。比如第 \(j\) 个类别 ID，对应第 \(j\) 个类别的频次或者统计值。

原来的处理方式，是对离散数组做 Embedding Pooling，对统计数组单独做 MLP，最后再融合。这个方法的问题是，一旦分别池化，模型只知道用户有哪些类别，以及整体统计量是多少，但不知道哪个统计值属于哪个类别。

所以我们改成了逐元素融合。对于每个位置，先计算：

$$

h_j=Embedding(id_j)+Linear(stat_j)

$$

然后再对有效位置做 Masked Mean Pooling。

这个改动的核心价值，是在进入主干之前保留了 `category_j ↔ statistic_j` 的语义对应关系。

这里我们其实踩过两个坑。

第一个是把统计值分桶后也做 Embedding。这个方案会引入额外的离散边界，而且连续统计值在分桶边缘会产生不连续变化，最终 AUC 反而下降。

第二个是乘法融合，也就是：

$$

Embedding(id_j)\odot f(stat_j)

$$

直觉上乘法交互更强，但它的问题是，一侧如果数值很小或者尺度不稳定，会直接把另一侧的信息抑制掉，梯度也更容易被统计值的分布控制。

最后保留加法融合，是因为它本质上是一种残差式设计。即使统计分支早期没有学好，原始 ID Embedding 仍然能完整通过；统计信息则以增量的方式逐渐修正语义表示。

这个地方如果面试官有兴趣，我还可以继续展开，我们是怎么识别哪些 fid 具有严格位置对应关系，以及如何在数据层做长度一致性校验的。”

# S 级改动二：请求时间与历史行为时间的双尺度建模

“第二个改动是时间语义对齐。

原始模型虽然保留了行为顺序，但顺序并不等于时间。比如两个用户都有 20 条历史行为，一个用户可能在最近一小时内密集发生，另一个用户可能分布在过去一个月里。如果只有位置编码，这两类用户的活跃状态很难被区分。

所以我们从两个尺度建模时间。

第一个尺度是当前请求时间。我们把时间统一到线上业务时区，然后用小时和星期的 sin/cos 周期编码，生成一个独立的 Request-Time Token。它描述当前请求发生在一天和一周中的什么位置。

第二个尺度是每条行为相对当前请求的时间差：

$$

\Delta t_j=\max(t_{\text{request}}-t_{\text{event},j},0)

$$

我们把时间差离散成多个非均匀 Time Buckets，再把时间 Embedding 直接加到对应的行为 Token 上。

这样，每个序列 Token 同时表达‘用户做了什么’以及‘这件事距离当前预测时刻有多久’。

在 Query Generator 里，我们除了保留普通 Mean Pool，还增加了一条时间感知的 Pooling View，让近期行为可以获得更高权重。与此同时，四个行为域的 Mean Pool 会再生成一个共享的 Cross-Domain Context，表示用户整体的活跃状态。

这里也有一个反例。我们曾经尝试直接用指数时间衰减乘在整个行为向量上，但没有带来收益。原因是乘法衰减不仅削弱时效性，也同时损失了行为内容本身。后来我们把时间作为额外 Embedding 或 Attention Bias，而不是直接破坏原始内容表示，训练会稳定很多。

关于时间特征，工程上还有一个非常关键但容易忽略的问题，就是离线与线上 timestamp 的时区、单位和序列排列方向必须完全一致。这部分我们后来专门增加了数据断言。”

# S 级改动三：从早期替换式 Attention，演进到晚期零初始化 DIN 残差

“第三个改动，是让用户历史兴趣与当前候选物品发生显式对齐。

最初的 Query Generator 只使用静态画像和序列 Mean Pool。它可以学到用户一般喜欢什么，但没有直接回答一个更关键的问题：用户的哪些历史行为与当前候选物品相关？

我们第一版方案是在 Query Generator 阶段，用候选物品表示对每个行为域做 Bilinear Attention，然后直接用 Attention Pooling 替换 Mean Pool。

这个方案从理论上是合理的，但实际比较不稳定。核心原因是，Item NS Token 和 Sequence Token 来自不同的特征投影路径，训练早期不一定已经位于同一个语义空间。如果直接替换 Mean Pool，一旦 Attention 没学好，原有稳定信息就被破坏了。

所以最终版本采用了更稳健的晚期残差 DIN。

具体来说，在两层 HyFormer 完成序列编码以后，用 Item NS Tokens 作为 Query，把四路最终行为序列拼接起来作为 Key 和 Value：

$$

H_{\text{DIN}} = CrossAttention \left( Q=N_{\text{item}}, K=H_{\text{all}}, V=H_{\text{all}} \right)

$$

DIN 输出经过池化和 Linear 投影后，以残差方式加入 HyFormer 主干输出：

$$

h_{\text{final}} = h_{\text{HyFormer}}+ W_{\text{DIN}}h_{\text{DIN}}

$$

这里有一个比较有意思的工程细节：我们把 \(W_{\text{DIN}}\) 做了零初始化。

这样在训练刚开始的时候：

$$

h_{\text{final}}=h_{\text{HyFormer}}

$$

整个模型严格等价于原来的稳定基线。随着训练进行，DIN 分支才逐渐学习候选物品和历史行为之间的匹配关系。

所以它相对于早期替换式 Attention 的优势是：基础路径不受影响，新增模块只提供增量信息；从梯度角度看，也避免随机初始化的 Attention 分支一开始就扰乱主干分布。

这是我们在项目里反复使用的一条经验：对于已经比较强的推荐模型，新模块优先以零初始化残差接入，而不是直接替换经过验证的主路径。”

# 四、HyFormer 第二层到底做了什么

“这里我再重点解释一下第二个 HyFormer Block，因为这部分经常会被追问。

第一层开始时，每个 Query 主要由当前域的 Mean Pool 和静态画像生成，它对其他行为域的了解还比较有限。

第一层首先对四路序列分别做 Transformer Encoder，然后 Query 对本域序列做 Cross-Attention，从长序列中选出与当前兴趣槽位相关的行为。

接下来，四个域的 8 个 Decoded Query 与 8 个 NS Tokens 一起进入 RankMixer。

RankMixer 会把 Token 维度和特征子空间重新排列。以 16 个 Token、64 维为例，每个 Token 被拆成 16 个四维子空间，然后交换 Token 轴和子空间轴，再经过共享 FFN。

因此，第一层输出的 Query 已经不再只是单域 Query，而是同时携带：

- 本域历史行为信息；
- 其他行为域的兴趣信息；
- 用户静态画像；
- 候选物品信息；
- 当前请求场景信息。

第二层拿这些已经完成跨域融合的 Query，再次对各自行为序列做 Cross-Attention。

它实际上是在执行一次条件更充分的二次检索：第一层回答‘这个域里有哪些重要行为’，第二层则回答‘在结合其他行为域、用户画像和候选物品之后，这个域里哪些行为应该被重新关注’。

第二层完成后，再经过一次 RankMixer，形成更高阶的跨域交互。

所以两层 HyFormer 的本质不是简单堆深，而是一种迭代式兴趣推理。”

# 五、晚期融合、损失函数与训练策略

“最终模型只使用第二层输出的 8 个 Query 做预测。

我们将它们拼接成 512 维表示，投影到 64 维，再加入 DIN Residual，最后通过两层 MLP 输出单个 CVR logit。

损失函数使用的是单任务 BCEWithLogits：

$$

\mathcal L= -\frac{1}{N}\sum_i \left[ y_i\log\sigma(z_i)+(1-y_i)\log(1-\sigma(z_i)) \right]

$$

这个任务没有额外引入复杂的多任务损失，主要原因是当时的目标指标就是单一 CVR AUC。我们希望先把收益归因到表征和特征对齐，而不是让多任务权重成为新的混杂变量。

优化器方面，我们没有对全部参数使用默认 Adam。

高维稀疏 Embedding 使用 Adagrad，学习率是 0.05；Transformer、MLP 和 LayerNorm 等稠密参数使用 AdamW，学习率是 \(10^{-4}\)，并将 beta2 调整为 0.98。此外使用常数学习率和最大范数为 1.0 的梯度裁剪。

这么做主要是因为稀疏 ID 和稠密网络的梯度统计差别很大。关于双优化器、Weight Decay 以及为什么最终没有保留 Cosine Scheduler，如果有兴趣我可以再详细展开。”

# 六、结果与反思

“最终，在同一套评估口径下，模型从 0.8255 的基线提升到大约 0.826，绝对提升约 0.0005。

这个数字看起来不大，但在已经比较高的 AUC 基线上，继续获得稳定提升并不容易。更重要的是，这次提升没有依赖简单扩大模型，而是来自更合理的特征语义和候选感知机制。

项目里最反常识的发现，是更多、更显式的信息不一定更好。

我们曾经把序列长度从 256/512 扩展到 1024，并加入序列压缩模块，结果从约 0.826 回落到 0.8255。说明更久远的行为并没有提供额外 CVR 信号，反而增加了噪声和优化难度。

更极端的是，我们发现候选 item 与某一路历史字段存在 exact match，于是手工构造匹配次数、最近匹配时间和匹配比例。这个特征业务含义非常直观，但结果从约 0.826 降到 0.820。

后来复盘发现，这类硬匹配特征覆盖率很低，而且训练集和验证集中的重复曝光关系可能发生漂移。它会让模型过度依赖少数强规则，反而降低泛化能力。

因此我最后形成的一个判断是：推荐系统中的语义对齐并不是越显式越好。相比硬编码 exact match，更稳健的方式是让 Attention 学习软匹配，并通过零初始化残差控制新增分支对主干的影响。

如果继续优化这个项目，我不会优先增加模型深度，而会重点做严格时间切分下的 cold-user、cold-item 和 OOV 分桶评估，确认收益究竟来自可泛化的行为模式，还是来自高基数 ID 记忆。”

# 高频深水区追问

# 1. 为什么使用 RankMixer，而不是让所有 Query 和 NS Tokens 再做一次 Self-Attention？

回答思路：

“主要是计算效率和结构约束。

Self-Attention 是数据相关的两两交互，表达能力更强，但会增加 QKV 投影和注意力计算。RankMixer 通过无参数的 reshape-transpose 完成 Token 与通道子空间重排，再用共享 FFN 做非线性交互，成本更低。

它的缺点是要求 `d_model` 能被总 Token 数整除，而且交互模式不如 Attention 灵活。所以我们的取舍是：序列内部和 Query-to-Sequence 使用 Attention，固定数量的全局 Token 融合使用 RankMixer。”

# 2. 为什么 DIN 要放在后面，并采用零初始化残差？

回答思路：

“因为候选物品 Token 和行为 Token 一开始不在天然对齐的语义空间里。

早期直接用候选 Attention 替换 Mean Pool，会让尚未收敛的匹配结果控制主干输入。晚期 DIN 使用的是已经经过两层 HyFormer 编码的行为表示，语义更成熟；残差接入则保留基础路径。

零初始化保证训练起点严格等价于基线，使新增分支只学习基线无法解释的剩余信息，本质上降低了模型升级风险。”

# 3. 如何证明时间特征的收益不是数据泄露？

回答思路：

“我会从特征时间边界、数据切分和线上一致性三层验证。

第一，所有行为时间必须早于或等于请求时间，负时间差直接统计并报警；第二，验证集必须使用严格的未来时间窗口，而不是随机切分；第三，离线和线上使用同一时区、时间单位、Bucket 边界和序列排序方向。

另外还要分别报告 seen-ID 与 unseen-ID AUC。如果时间特征只在 seen-ID 样本提升，很可能仍然是在辅助记忆，而不是学习到了可泛化的时间规律。”
