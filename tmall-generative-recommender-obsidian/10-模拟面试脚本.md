# 10 模拟面试脚本

## 1 分钟项目介绍

我做的是一个基于协同 Semantic ID 和 HSTU 的电商生成式推荐原型，数据来自天池 Tmall 用户行为日志。问题是商品规模大，直接预测 item ID 输出空间很大，而且 item ID 本身没有结构。我的做法是先按照 click、收藏、加购、购买的行为强度，以及时间距离和序列位置，构造稀疏的 item-item 加权共现图；再用 Weighted Item2Vec 学习 item embedding。之后通过 RQ-VAE 风格的残差量化，把每个 item 表示成 3 个离散 code，并用 collision token 解决 code 冲突。推荐模型把用户历史 SID、行为和时间输入 HSTU-style 序列编码器，使用 teacher forcing 逐级生成目标 SID，推理时用前缀约束 beam search 只保留有效商品路径。最终通过 HR/NDCG、coverage、多样性和 collision rate 做离线评估。

## 3 分钟项目介绍

我的项目可以拆成“协同表示、离散地址、序列生成”三部分。

第一部分是协同表示。Tmall 日志里同一用户相邻发生的行为可以形成 item-item pair，但不同行为和不同时间距离的信息量不同，所以我使用行为权重、时间衰减、位置衰减和用户活跃度惩罚构造稀疏共现边。为了避免百万级商品形成 dense 矩阵，只保留每个 item 的 top-N 邻居，再用稀疏 Item2Vec 学习连续 embedding。

第二部分是 Semantic ID。输入 item embedding 经过 encoder 后，用多个 codebook 对残差逐级量化：第一个 code 表示粗粒度部分，后面的 code 逐步补充残差。当前用 3 级、每级 256 个 code。多个 item 可能发生碰撞，所以追加 collision token，并建立 item 到 SID、SID 到 item 和 SID 前缀树的映射。

第三部分是生成式推荐。历史行为的 SID code、行为类型和时间差共同构成输入。HSTU-style block 用相对位置/时间偏置建模行为间关系，用 pointwise SiLU 和 gated residual 完成更新。解码器按 code level 自回归预测目标 SID。训练用 teacher forcing，推理用 prefix-constrained beam search，避免生成无效 SID。生成候选后还需要过滤已看 item，必要时接传统召回和 ranker。

这个项目目前是离线原型，SID 和推荐模型分阶段训练，还没有宣称线上指标、端到端联合训练或真正冷启动解决方案。

## 5 分钟追问路线

### 面试官追问“为什么不是 ItemCF”

ItemCF 可以直接提供相似商品候选，稳定且可解释；我的项目保留了 ItemCF/共现作为协同信号，但进一步学习 item embedding、量化成 SID，再让序列模型生成结构化候选。它不是要完全替代 ItemCF，而是探索在大 item 空间中的生成式候选能力。

### 追问“为什么不是直接 item softmax”

直接 softmax 的类别数随商品数增长，且 item ID 没有结构。SID 将商品拆成多个小词表的 code，模型先生成粗粒度 code，再生成细节 code，参数和搜索空间更可控，也能共享 code 前缀。

### 追问“RQ-VAE 是不是 VAE”

严格说当前代码是 RQ-VAE 风格的残差量化自编码器，不包含标准 VAE 的高斯采样和 KL 项。核心是 encoder、多个残差 codebook、decoder，以及 reconstruction/codebook/commitment loss。

### 追问“怎么证明不是热门度收益”

需要和 Popularity baseline 比较，并报告 popularity 分桶、tail recall、coverage 和推荐列表集中度。若只提升 HR 但 coverage 降得很明显，说明可能只是更强地推荐热门 item。

### 追问“你最大的不足是什么”

当前输入是预聚合序列，不是 notebook 内直接处理原始 13 亿行；此外训练是分阶段的，collaborative SID 对冷启动有限，HSTU 也是参考结构的简化实现。下一步会先补时间 OOT、数据血缘、代码本利用率和 cold-start content 分支。
