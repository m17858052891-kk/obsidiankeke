# 00 项目总览

## 1. 项目定位

原始数据包含用户、商品、行为和时间四类信息：`User_id`、`Item_id`、`Action`、`Vtime`。本项目将用户的点击、收藏、加购、购买行为组织成按时间排序的序列，预测用户下一步可能交互的商品。

核心改造是把“在数百万商品中直接做 item 分类”改成“生成一个由多个离散 code 组成的商品 Semantic ID”。模型先生成 code 序列，再通过 SID 表查回商品，因此推荐任务具有生成式推荐的形式。


## 3. 3 分钟版本

原始问题是：Tmall 的商品空间非常大，直接用 softmax 预测 item ID，输出层和候选空间都随商品数增长；同时，普通 item ID 没有结构，模型很难利用商品之间的协同关系。

我的方案拆成三层：

1. **协同表征**：按照行为类型、时间距离、行为位置和用户活跃度给 item-item 共现加权，避免把所有共现都当作同等强度；再用稀疏 Item2Vec 学习 item embedding。
2. **Semantic ID**：以 item embedding 为输入做残差量化。第一级 code 表示粗粒度区域，后续 code 逐步拟合残差。3 个 code 的笛卡尔积提供较大的商品地址空间，若多个商品仍落到同一个 code，就追加 collision token。
3. **生成式推荐**：把历史行为的 SID、行为类型和时间信息输入 HSTU-style 编码器。解码器按 `code_0 → code_1 → code_2 → collision` 逐级预测，每一级都以上一级真实/已生成 code 为条件。推理时不允许生成训练中不存在的 SID 前缀，并过滤用户已经看过的 item。

这个项目的价值不是单纯换了一个 Transformer，而是把协同过滤信号、离散商品表示、序列建模和结构化生成连接起来。

## 4. 5 分钟版本的逻辑

### 为什么不直接用 item ID

item ID 是无语义的离散索引。直接预测 item ID 有两个问题：

- 输出空间大，参数量和计算量随商品数增长。
- 商品之间的相似性无法在输出空间中自然共享。

Semantic ID 把 item 表示成多个 code。相近商品如果在 embedding 空间相近，通常会共享部分前缀；生成模型可以先决定大方向，再逐步细化。

### 为什么共现图不能直接当 SID

共现图是训练协同表示的原始信号，不是最终的离散编码。直接把共现矩阵的行号或邻居编号当 SID，无法保证 code 的层级结构、可扩展性和生成约束。项目采用“共现 → Item2Vec → RQ-VAE”的两步表征学习。

### 为什么使用 HSTU

项目希望处理较长的用户行为序列。HSTU-style block 使用相对位置/时间偏置和 pointwise SiLU 形式的归一化替代传统 Softmax 注意力中的概率归一化，并通过门控更新输出。它保留了序列交互能力，同时减少了长序列建模中的部分开销。面试时应说“参考 HSTU 的结构实现”，不要声称与论文或线上版本逐算子完全一致。

### 为什么要约束 beam search

普通 beam search 可能生成一个训练中没有出现过的 code 组合，无法映射回商品。项目把有效 SID 建成前缀树：每一步只允许生成存在于 `sid_prefix_next` 中的 code；完整 SID 再映射到 item，并过滤已交互商品。
