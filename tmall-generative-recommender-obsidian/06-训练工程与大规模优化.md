# 06 训练工程与大规模优化

## 1. 三阶段训练

当前代码采用清晰的离线 pipeline：

```text
阶段 A：行为日志/序列 → 加权稀疏共现 → Item2Vec item embedding
阶段 B：item embedding → RQ-VAE tokenizer → item SID 表
阶段 C：历史 SID 序列 → HSTU encoder + SID decoder
```

分阶段的优点是容易定位问题：先看 embedding，再看量化质量，最后看推荐效果。缺点是阶段之间目标不完全一致，RQ-VAE 优化的是重构误差，而推荐模型优化的是 next-item likelihood。

## 2. 关键超参数

| 模块 | 参数 | 当前示例 | 含义 |
|---|---:|---:|---|
| 共现 | window | 3 | 最大行为距离 |
| 共现 | max neighbors | 200 | 每个 item 保留邻居数 |
| Item2Vec | dim | 32 | 协同向量维度 |
| Item2Vec | negatives | 16 | 每个正 pair 的负样本数 |
| RQ | levels | 3 | code 层数 |
| RQ | codebook size | 256 | 每层 code 数 |
| HSTU | beam size | 50 | 解码保留路径数 |
| HSTU | branch top-k | 32 | 每个 prefix 扩展分支数 |

这些数值是原型配置，不代表最佳结果。简历中只写“经过消融确定”的参数，前提是确实做过对应实验。

## 3. 内存和计算

### 不能做的事情

- 不能建立完整 dense item-item 矩阵。
- 不能把 13 亿行日志一次性放入 pandas。
- 不能对所有商品每步 dense 更新 embedding optimizer。
- 不能在 beam search 中展开完整的 `K^L` 笛卡尔积。

### 应该做的事情

- 读取必要列并压缩类型。
- 按用户/时间分片。
- 共现 pair 只保留稀疏边和 top-N 邻居。
- Item2Vec 使用 sparse embedding + SparseAdam。
- SID 解码使用 prefix tree 约束分支。
- 使用 padding mask、batch padding 和 mixed precision。

## 4. 训练稳定性

- 梯度裁剪防止 Item2Vec 或 decoder 梯度爆炸。
- 对比/相似度训练前做 L2 normalization。
- 对 RQ-VAE 监控 codebook 使用率，防止 collapse。
- 对生成 decoder 使用 label smoothing，减少过度自信。
- 保存 `item_id ↔ SID`、codebook、embedding、模型 checkpoint 的版本号。

## 5. 产物版本管理

推荐将以下产物绑定同一个 `sid_version`：

```text
sid_version
 ├─ item2vec_embeddings
 ├─ rq_codebooks
 ├─ item_to_sid
 ├─ sid_to_items
 ├─ sid_prefix_next
 └─ hstu_decoder_checkpoint
```

如果只更新 codebook 而不更新 decoder，旧模型输出的 code 可能已经没有同样的含义。线上更新需要兼容策略、回滚策略和覆盖率监控。

## 6. 常见故障定位

| 现象 | 可能原因 | 检查方式 |
|---|---|---|
| Item2Vec loss 不降 | pair 权重/负采样错误 | 看 pair 分布、正负 score |
| code 使用集中 | codebook collapse | 看每级熵和 top code 占比 |
| 生成大量 invalid SID | 无约束或 SID 表不一致 | 检查 prefix tree 与 sid table |
| HR 提升但 coverage 下降 | 热门偏置 | 看 item popularity 分桶 |
| 预测候选不足 | OOV/seen filter/碰撞过多 | 看各过滤阶段计数 |
| 训练指标高、OOT 低 | 时间泄漏或漂移 | 改 temporal split |
