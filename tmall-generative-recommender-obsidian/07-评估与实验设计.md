# 07 评估与实验设计

## 1. 基本指标

给定用户历史 `h`、真实下一商品 `y` 和推荐列表 `R_K`：

### HR@K

$$
HR@K=\frac{1}{M}\sum_{m=1}^{M}\mathbf{1}(y_m\in R_K)
$$

衡量 top-K 是否命中。

### NDCG@K

$$
NDCG@K=\frac{1}{M}\sum_m\frac{\mathbf{1}(y_m\in R_K)}{\log_2(rank(y_m)+1)}
$$

同样命中时，越靠前得分越高。

### Coverage

$$
Coverage@K=\frac{|\cup_u R_K(u)|}{|I_{eval}|}
$$

衡量推荐列表覆盖了多少不同商品。HR 高但 coverage 很低，通常代表模型过度集中于热门商品。

### 多样性

如果有类目，可以统计推荐列表中不同类目数或 intra-list diversity。当前项目的类目主要用于报告和多样性分析，不是 collaborative SID 的主要输入。

## 2. 必做 baseline

至少包含：

1. Popularity：检验是否只是热门度收益。
2. ItemCF：检验协同召回的直接效果。
3. item-ID HSTU/Transformer：检验 Semantic ID 的增益。
4. metadata SID + HSTU：检验内容/类目 SID 与协同 SID 的差异。
5. collaborative RQ-VAE SID + HSTU：最终方案。

每个 baseline 应尽量共享数据切分、历史长度、候选过滤和评估代码，否则结果不公平。

## 3. 必做 ablation

| 消融项 | 目的 |
|---|---|
| 去掉行为权重 | 看 click/collect/cart/purchase 权重是否有效 |
| 去掉时间衰减 | 看新鲜度信号是否有效 |
| 去掉活跃度惩罚 | 看超活跃用户是否主导共现 |
| Item2Vec → 随机 embedding | 验证协同表征的作用 |
| 单级 VQ → 多级 RQ | 验证残差量化与组合空间 |
| 不加 collision token | 观察冲突对映射率的影响 |
| 普通 Transformer → HSTU-style | 验证序列编码器差异 |
| greedy → beam | 验证搜索策略 |
| 无 prefix constraint | 统计 invalid SID 比例 |
| 不同序列长度 | 观察长期噪声与复杂度权衡 |

## 4. 评估切分

更接近线上的是：

```text
train: 较早时间窗口
valid: 后续时间窗口
test : 更晚时间窗口
```

还应报告：

- 热门/中频/长尾 item 分桶结果。
- 新用户与老用户结果。
- 短序列用户与长序列用户结果。
- 有 SID 的 target 覆盖率。
- OOV target 比例。
- beam 解码平均候选数和 invalid rate。

## 5. 结果如何才有说服力

不能只报一个 HR@10。至少应形成：

```text
效果：HR/NDCG
覆盖：catalog coverage、tail recall
结构：SID collision rate、code usage entropy
成本：训练时间、显存、推理耗时、平均 beam 分支数
```

如果 HR 提升是以 coverage 大幅下降换来的，不能直接下结论说模型更好；要结合业务目标和候选池质量分析。

## 6. 统计严谨性

可使用多次随机种子或 bootstrap 估计置信区间，至少报告均值和方差。对时间数据，重点是不同时间窗口的稳定性，而不是只看一次随机 split。
