# 01 数据与样本构造

## 1. 原始字段

| 字段        | 含义                              | 建模用途          |
| --------- | ------------------------------- | ------------- |
| `User_id` | 用户标识                            | 按用户聚合行为       |
| `Item_id` | 商品标识                            | 序列 token、预测目标 |
| `Action`  | click / collect / cart / alipay | 行为强度和输入特征     |
| `Vtime`   | 行为时间                            | 排序、时间差、时间衰减   |

原始数据规模约为 13.3 亿行，不能直接用 pandas 全量加载。工程上应采用分片读取、列裁剪、类型压缩、按用户或时间分区聚合，并将中间结果保存为 Parquet。

## 2. 行为编码

当前 notebook 假设：

```text
click   -> 1
collect -> 2
cart    -> 3
alipay  -> 4
```

代码中的协同行为权重为：

```text
click=1.0, collect=3.0, cart=5.0, alipay=8.0
```

面试时必须补一句：**需要以数据集真实 Action 编码和数据字典为准，行为权重是超参数，会通过验证集和消融实验确定。** 如果上游编码相反，所有权重都会错位。

## 3. 从行为日志到序列

对每个用户：

1. 按 `Vtime` 升序排序。
2. 形成 `(item_id, action, time_gap)` 三元组序列。
3. 用历史前缀预测下一个 item。
4. 训练输入最多保留最近 `MAX_SEQ_LEN` 个行为。
5. 左侧 padding，使 batch 内张量形状一致。

若用户序列为：

```text
[A, B, C, D]
```

则可以构造：

```text
history=[A, B, C], target=D
```

训练时历史中的 item 也会被映射为它们的 SID；target 则映射为目标 item 的 SID。

## 4. 时间特征

当前代码保留 `time_gap`，并在模型中通过时间 embedding 和相对时间偏置使用。需要确认它的单位：秒、分钟、小时，还是离散 bucket。若 `time_gap` 的单位改变，`TIME_DECAY_SCALE=20` 的解释也要改变。

推荐做法是将时间拆成多个稳定特征：

- 距离上一次行为的时间差：反映兴趣新鲜度。
- 小时、星期、节假日：反映周期性。
- 序列内相对位置：反映近期行为更重要。
- 用户活跃度：反映行为稀疏程度。

## 5. 标签和防泄漏

目标是“下一个真实发生的交互”，不是随机从用户历史中抽一个 item。切分时要保证：

- target 发生时间晚于 history 中所有行为。
- 共现和 Item2Vec 训练不能使用验证/测试未来行为，否则会产生时间泄漏。
- 线上场景更应使用按时间的 out-of-time split，而不是随机 user split。

当前项目若沿用随机切分，面试时应坦诚说明：**这是快速验证原型的切分方式，生产评估会改成按时间滚动切分。**

## 6. Padding、mask 和 OOV

- `PAD_ID=0`，真实 item/SID code 从 1 开始偏移。
- HSTU 使用 padding mask，防止模型读取补齐位置。
- causal mask 保证位置 `t` 不能看到未来位置 `>t`。
- 预测 target 如果不在训练期 SID 表中，属于 OOV。
- collaborative SID 对冷启动商品天然不友好，因此 OOV 不能被包装成“已解决冷启动”。

## 7. 面试回答模板

**问：为什么要把行为类型作为输入，而不是只使用 item 序列？**

答：点击、收藏、加购和购买表达的意图强度不同。如果只看 item，模型无法区分“快速浏览”和“高意向行为”。因此我将行为类型作为独立 embedding，并在共现阶段使用行为权重；不过这个权重不是因果强度，只是可验证的建模先验。

**问：如何避免数据泄漏？**

答：所有用户序列先按时间排序，target 必须严格晚于 history；SID 学习、Item2Vec 和共现统计也应只用训练窗口。当前 notebook 是原型实现，若用于正式结论，我会改为时间 OOT 和滚动窗口评估。
