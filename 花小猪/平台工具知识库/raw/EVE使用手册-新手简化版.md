1、什么是策略算法平台EVE
作为滴滴自研的一站式业务策略算法中台，EVE覆盖策略迭代的各个生命周期，从特征的加工、管理、上线到模型的训练、管理、部署再到实验的AB分流、策略构建、效果评估。EVE融合了网约车多个策略算法研发团队技术积累，沉淀为集团级通用平台，由策略中台FT负责维护。
EVE读作伊娃，取自电影《机器人总动员WALL·E》中女主角机器人的名字。
1.1、EVE提供的服务
模型训练：通过封装XGBoost、SparkML，提供可视化训练平台，能够用拖拉拽的方式生成DAG图，完成模型训练，并记录所有中间元数据、配置、代码。
模型管理：提供统一的模型注册，组件化、pipeline式的模型上线，支持例行训练。并提供在线预测服务。
特征管理：提供统一的特征注册，训练样本提取，一键特征上线，特征质量监测。并提供在线特征服务。
策略管理：提供模块化、配置化、可视化的动态策略生成，与模型、特征打通。
流量管理：基于Google的层域流量模型，提供流量管理，支持复杂的实验与多种评估方法（评估暂未上线）。
1.2、平台架构

策略算法中台EVE，整体架构如图所示，底层依托于多个基础平台 / 组件，大数据主要是通过数梦依赖Spark进行离线数据处理与模型训练。集成了Spark ML、XGBoost等机器学习框架，通过鲁班集成了TF、PyTorch。集成了Apollo的实验能力。

功能上按照特征中心、模型中心、策略中心进行组织。

特征中心
特征中心与DUFE是不同团队自建，一般一个算法团队只会使用其中一个进行注册上线。
特征中心根据策略算法迭代的需求，提供以下三种基本能力：
训练样本生成：配置化的方式支持样本提取任务，为模型训练提供输入。
特征生产：特征的加工、存储、推送能力。
特征访问：根据模型访问所有依赖特征的能力。
模型中心
模型中心包含三部分：
模型开发pipeline：提供了一套成熟的可视化模型开发pipeline，由组件库、DAG编排、调度模块组成。
模型仓库：用于管理模型，记录了模型文件、版本、依赖的特征、算子配置、模型评估信息等。
在线推理：深度模型和非深度模型推理服务
策略中心
策略中心主要解决工程、算法协作开发的问题，工程抽象好主流程，业务策略改动可以交由算法自行开发
模型和特征属于比较通用的功能模块。策略部分和业务模式比较相关，主要是解决以下的问题：
算法RD变更在线策略往往需要提需求到工程RD，其中的沟通和等待成本，降低了策略迭代效率。
Apollo提供了单个随机分流实验的分流、评估功能，但在实验 / 流量复杂的业务中，实验间的关系往往用hard code维护，算法在协作时无法看清流量，导致错配错改。
1.3、策略模型迭代流程介绍
数据准备阶段：包括特征的加工生产与采集、Label标注与获取
模型开发阶段：包括特征工程、模型训练、模型评估
serving阶段：把特征、模型推到线上，在线实验分流，并为每个分流实现策略处理，包括访问特征服务与模型服务，策略的前后处理
效果评估阶段：用分流日志、业务指标数据，结合各种评估方法，得出模型策略的业务效果

2.1、实验列表
点击右侧模型实验菜单，进入个人实验列表页。
项目实验列表：可以查看自己已创建的实验、自己所属项目空间的实验、自己被授权的实验，这些实验按照创建时间降序排列。
列表项中展示了实验名，实验描述，实验状态等信息，并且可以对实验进行修改负责人、删除、克隆和查看的操作。

示例实验：系统提供的示例实验，可以预览或复制的实验模板。
点击实验名称，可以预览实验（只读模式）可以查看组件各项结果，但不能编辑操作。
点击复制实验，可以将示例实验复制到个人实验下（拷贝组件属性），可供个人进行编辑运行等操作。
点击详情，可以查看实验描述。
创建实验
点击右上角“+新建实验“**按钮，创建新实验。
在弹框中，填写自定义实验名称、所属项目和实验描述


保存实验
实验进行各项配置操作之后需要保存才能在下一次进入后查看。
点击画布下方**“保存”**按钮进行保存。
同时平台提供“复制”功能，即点击画布下方**“另存为”**按钮，在弹框中输入副本的名称，点击确定即可复制实验（复制了该实验下各个组件的关系和配置参数，复制后的实验副本处于未运行状态）。可以在实验列表中查看。

2.2、实验工作台
界面左侧：组件列表，可以进行点击拖动，将组件加入绘图区。
界面中间：绘图区域
组件间操作：拖动，连接，删除等；组件右键菜单操作。
绘图区缩放，布局整理。
下方菜单：另存为，保存，运行（正常运行，重新运行），删除等。
界面右侧：属性区
未选中任何组件时，显示当前实验的信息，包括实验名称，实验描述，运行状态（未运行，运行中等），更新时间等

点击组件时，显示对应组件属性，可以进行属性编辑，查看等操作。

组件操作
1.拖动添加组件
点击组件列表上任一项，拖动到右边绘图区，即可添加组件。

2.连接组件 组件下方的节点为输出槽，上方的节点为输入槽。输出槽的点能连接输入槽的点。
点击组件上的节点，向外拖动线，其他组件上显示绿色的点表示可以连接。将线拖动到目标组件的节点上，紫色表示连接成功，红色表示不能连接。

3.右侧菜单介绍 在任意组件上点击右键，将弹出该组件的右键菜单。根据组件状态和实验整体状态不同，右键菜单能操作的选项不同

复制：复制组件和右侧属性。
删除：删除组件。
运行当前任务／从当前任务开始运行／运行到当前任务：根据不同指令运行实验。
查看运行信息：查看实验运行信息。
查看日志：查看运行日志。
组件说明
相关组件较多，建议从示例实验和已有实现中学习相关组件使用用法，具体组件说明见组件说明
运行实验
在绘图区内连接好组件关系并且配置好组件参数后，可运行实验。 运行前需要校验组件配置，当校验无误时即可开始运行实验。
有两种运行方式：
1.点击画布下方运行菜单进行运行：

选择运行：正常运行实验。即已完成状态的组件不重新执行。
选择重新运行：从头运行实验过程。
2.通过组件右键菜单运行，有三种运行方式：

运行当前任务
从当前任务开始运行
运行到当前任务
停止实验
实验处于运行状态，可点击绘图区下方的终止按钮停止实验。

2.3、模型训练
Eve2.0平台web界面主要分为中央绘图区、右侧属性区、左侧组件列表区等几个区域。中央绘图区用于设计实验处理流程，属性区用于配置组件的详细参数，组件列表展示了所有的特征工程、算法相关的处理组件。
使用Eve调研平台构建一个模型需要以下几个步骤：
用户个人中心数梦信息配置
准备数据
创建实验
构建实验DAG
运行并查看结果


准备数据
Eve调研平台的数据来源有三种：
个人数据：用户可以从本地或者hdfs上的数据上传到Eve调研平台，目前不推荐这种使用方式，已经将上传按钮隐藏。 
公共数据：公共数据由管理员上传，用户有可读权限，在实验中可以使用公共数据。
业务数据：业务数据的获取依赖个人信息配置中的hadoop账户，hadoop账号能够访问的hive表，都可以在实验中作为数据源。

创建实验
用户可以创建空白实验，也可以从示例实验中的模板按模板创建实验，建议新用户从示例实验中按模板创建实验，可以快速学习一个实验如何构建。 

构建实验DAG
从组件区拖动组件放到中央绘图区，在右侧对每个组件进行参数配置，然后将组件按照工作流程进行连线，一个典型的实验由数据源准备、数据和特征处理、模型训练和模型预测环节构成。 

运行并查看结果 
当实验DAG构建完成或者只构建一部分时，都可以运行实验，运行的方式有如下几种：只运行选定组件、运行到选定组件、从选定组件开始运行以及运行整个实验。既可以添加一个组件运行一步，又可以全部构建完整体运行，可以根据任务的复杂程度选择合适的方式。 

 每个组件运行后，会显示出已完成的状态，这时点击组件在右侧属性区可查看组件的输出。 


 最终模型训练完成并进行预测和评估后，可以查看模型的评估报告

示例：


模型格式(export_model)
原生模型文件信息保存目录：不同模型框架，保存的模型文件内容可能不太一样
Tensorflow: 保存savedModel文件,文件名称统一为：saved_model.pb及variables
Pytorch: 保存torchscript文件, torchscript文件统一命名为：model.pt

配置文件(model.conf)
作用：描述模型的框架类型、框架版本、输入和输出tensor格式等信息
{
  "framework": "Pytorch|Tensorflow",  //模型所用框架 
  "frameworkVersion": "1.7.1",  //模型框架版本
  "modelFormatType":"SavedModel | TorchScript",  // 模型保存格式
  "inputNames": ["input_1", "input_2"], // 模型输入 tensor name
  "inputTypes":["DT_FLOAT","DT_FLOAT"],   // 模型输入 tensor data type, 顺序和 inputNames 匹配
  "inputShapes": [[-1, 2], [-1, 3]], // 模型输入 tensor shape, 顺序和 inputNames 匹配
  "featureOrder": ["feature1_1", "feature1_2", "feature2_1", "feature2_2", "feature2_3"],// 特征顺序, 决定标量特征在 tensor 中的顺序
  "signatureKey": "xxx"   // Tensorflow模型才有
  "tensorFeatures": ["input_3"]    // 有向量特征时才有，tensor 特征, 特征名必须和 tensor 名一致, 不做拼接, 直接将特征反序列化为同名 tensor
}

3.2、容器部署
适用场景
当前功能介绍：通过平台界面将模型部署到鲁班DDL在线服务
深度学习模型
需要容器化能力的服务
相比旧版鲁班部署的优势：
不需要鲁班部署后再来平台配置一次了，节省操作步骤
可直接部署平台训练产出或导入的模型，一站式操作
相比集群部署的优势：
1. 集群部署仅支持 tf2.0，容器部署可以支持更新的版本 
2. 容器部署资源隔离，业务间不会相互影响
3 .集群部署是混部，受单机内存限制，仅能支持很小的模型
前提条件
当前项目已绑定鲁班账户，且有机器资源。绑定方式可参考文档的‘使用前提’章节
模型仓库中有模型可以部署。有两种方式：
实验训练产出模型：深度模型训练可参考使用手册
上传模型：可参考模型导入文档

5、定期更新
参照前述文档，应该已经可以训练并部署模型了。在实际生产中，往往需要使用最新的数据不断的迭代模型，以便学习到符合当下情况的模型。针对这类情况 EVE 提供了模型定期更新功能。
非增量训练，模型定期更新为使用相同的建模参数 + 最新的数据训练出一个新的模型。
模型定期更新包括模型训练 -> 模型导出（到模型仓库）-> 评估检查 -> 部署上线 四个主要步骤。
5.1、训练基础模型
参考 QuickStart，手工配置一个模型并成功完成训练。

一般来说，配置定期更新训练希望每次执行训练时可以按一定规则自动框定一批数据，为此 EVE 在自定义 sql 组件支持日期变量，配合定期更新使用。
配置训练参数
在训练页面，参数配置部分，指定一个或多个变量，变量类型需要为 time（其他变量不会随定期更新自动变化）。
在自定义 sql 组件中使用变量框定训练数据。
如 select a, b, c from db.table where dt <= '${BIZ_DATE_LINE}' and dt >= date_add('${BIZ_DATE_LINE}', -2)
新版实验使用的是数梦变量，参考数梦即可。使用手册

5.3.2 配置更新策略
名词解释
分组项目：同一个训练产出的模型，在同一个部署内都配置了定期更新，会放在一个分组项目中一起执行训练、上线。
回调配置
模型定期训练、部署成功之后，支持回调配置的 http 地址，通知本次部署情况。
调度配置
模型定期训练的时间、周期等。

其他配置
自动重试：模型定期更新 pipeline 失败，支持重试 N 次，此处配置 N。
关联的训练 ID：
置空/0：使用模型导出时，保存的训练的 DAG 图，每次定期更新时会复制该 DAG 图，修改需要重新训练、导出、部署一个新的基础模型，并基于此模型重新配置定期更新。
配置一个关联实验（即训练页面 url 中 https://ether.intra.xiaojukeji.com/labs/{id} 的 id），定期更新时会优先使用复制此训练 DAG 图，而不是模型导出时的 DAG 图，主要用于快速修改定期更新训练 DAG 图。（此 DAG 图产出的模型语义和线上模型是否一直由配置人保证，比如关联的实验产出的模型只有 30 个特征，线上模型有 40 个特征，新产出模型覆盖线上模型会导致不一致）
训练中导出该模型组件的 uuid：和关联的训练 ID 配合使用，用于告知系统关联的训练 ID 代表的 DAG 中，哪一个组件可以产出模型用于线上部署。

部署配置
部署开关：产出模型后是否部署
部署时创建新版本：
是：创建一个新的部署 version
否：覆盖原有模型，不创建新 version（一般模型访问需要指定 version，创建新 version 需要配置回调，由上游系统感知新产生的 version）

评估标准配置
只有通过评估检查的模型，才会部署到线上。

SQL 使用参数配置
用于配置自定义 sql 中的时间参数，每次定期更新会自动变化，用户按规则框定训练数据。
