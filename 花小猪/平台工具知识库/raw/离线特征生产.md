# 离线特征生产

# 一、核心解决的问题

离线特征生产链路，基于离线 Hive 表生产特征，并同步到在线存储，供在线服务查询使用。平台能力主要体现在：

1、SQL 特征计算：对于计算逻辑较为简单的特征，可在平台上配置 SQL 实现特征生产；

2、特征质量检查：特征计算完成后，可配置对特征进行质量检查，包括行数校验、空值率校验、空值率环比校验等；

3、特征同步：已生产好的特征会同步到在线存储，供业务通过 Dufe 查询使用；

4、特征注册：平台会自动注册 Dufe 特征，一旦数据同步任务完成，则可在模板中引用新注册的特征。

- 自动切换

	- Fastload 生成新版本后立即切换。。

- 定时切换

	- fastload 生成新版本后，延迟到 cron_time 再发起切换；如果当前时间已经超过当天 cron_time，则会立即切换

### 2.2.3 Spark 配置

- spark参数参考：

一般minExecutors和maxExecutors是调整比较多的，driver.memory和executor.memory一般不需要特别调整，除非批次报错out of memory

一万条以内的数据规模，minExecutors=10，maxExecutors=20 足够了。比如城市维度的特征数据等

千万级别的数据规模，minExecutors=100，maxExecutors=200 左右

### 2.2.4 特征前缀、特征主键与是否打包

- 每个同步任务会生成一张表（table），表中结构为 key-field-value结构（hash），其中特征前缀和特征主键用于拼接key，比如特征前缀为AAA，特征主键为 driver_id，那么key会被拼接为AAA\_${driver_id1}, AAA\_${driver_id2}... 

- 主键唯一性保证。**Hive表内主键需要唯一。**

	- 例子：如果我们的hive表的主键是订单id+城市，但是我们sql查出来的主键是订单，那这个就会导致订单的key会有重复可能，建议大家可以仔细确认下，是否符合预期。

	- ![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1779265245109/pUkIn0IGQ5BLuRrfncElA/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20260529%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20260529T072852Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=5673ec34b8742a52179a2a6cddd7f058792cf3cda1b29ad3d2519a1e9c691f7c)

- 特征：上述 table-key-field-value 结构中，field为特征名，value为特征值。

- 是否打包：是否打包是平台内部的存储优化，**不影响用户配置和使用特征**。

### 2.2.5 SQL

- **==SQL 中对特征命名有特殊要求（参考如下截图）==**

![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1779191774019/ciCv_tKKoofUGSR-aiUcG/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20260529%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20260529T072852Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=6a4837d1eb0e6e50da25f9c573db77ee50f20ed028c4ac7ad5b0d98992644b59)

- **特别注意⚠️：**SQL 中的特征列名必须根据前文 **2.1.5** 所选“**特征标签**”添加对应前缀，前缀规则如下：

	- odt\_(地点类), i\_(输入类), s\_(供需类), b\_(冒泡类), d\_(司机类), p\_(乘客类), o\_(订单类）

- 例如，特征标签选择“地点类”，Hive 表中的原始特征列为 city_feature，特征主键为 city_id，则 SQL 中需要将特征列命名为 odt_city_feature，主键列保持 city_id 不变：

```SQL
select
      city_id,
      city_feature as odt_city_feature
  from dbname.tablename
  where dt = 'param_year-param_month-param_day';
```

- 前缀命名只适用于特征列，不适用于主键列。主键列不要额外添加前缀，否则会增加模板参数，影响线上特征获取。

	- 例如，司机维度的主键应保持为 driver_id，不建议命名为 d_driver_id。在线特征通过模板提取时，主键需要作为参数传入；如果同一含义的主键同时存在 「driver_id」 和 「d_driver_id」，模板中就需要分别传入两个参数，造成冗余。

### 2.2.6 依赖tag与偏移量

![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1779244875726/14jrAawFi7wV-xrxh5cau/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20260529%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20260529T072852Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=b04d5ee057f6144c6bc220bed02286726be4265d6179e5bf1a1917072c399b2f)

- tag：含义同数梦tag，只有tag条件满足，任务才会触发执行。**一般情况下，SQL中查询哪些表，tag就设置这些表**。

	- 离线任务运行在数梦中，只有当依赖的tag就绪时，此任务才可能运行。**年月日为依赖的hive库表分区偏移量**。

- 霸王花交易定价需要有对应依赖tag的hdfs权限：<https://pam.data.didichuxing.com/role/apply?type=project>

![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1779330975212/CunRMVLit_mB405KdL1Hj/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20260529%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20260529T072852Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=0c4073d2637594dd5fddb2feab1f7e4d6859328928a00b2ffc9929170ef1c2ff)

- 偏移量：代表sql中日期参数的偏移量， 一般与tag偏移量相反

	- 若为0，则sql中日期参数被替换为当前日期(当前日期为20201109,sql中param_year-param_month-param_day被替换为2020-11-09);

	- 若为1，则sql中日期参数被替换为t-1日(当前日期为20201109,sql中param_year-param_month-param_day被替换为2020-11-08) 以此类推

## 2.3 质检配置

![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1779183095057/T2uTFG8EO0nkywhbVoHmi/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20260529%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20260529T072852Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=2a831e246e4421c30d089648291dfa24b03ad5a40a0ce0b3be75d3fc5562f9ce)

- 数据质检：SQL执行完成之后，会对结果进行质量检查，只有质量检查成功之后，才会触发后续 fastload 任务执行。

- 数据质检的两种方式：行数校验、空值率检测

	- 空值率：空值行数占总行数的比例。空值率大于设置的阈值会触发报警。
