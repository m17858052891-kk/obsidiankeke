对应文件：config.yaml（管理参数），config.py（存放统计的归一化参数） 统一配置: 使用 config.yaml 统一管理  模型超参、训练参数和导出参数，理论上使用者每次模型训练都可以在yaml配置中完成模型选择和参数配置 ，不需要在训练主程序中改动，具体配置内容如下： 训练配置（train_config）：包含流程开关（train，compute_normalization）、训练超参（epoch, batch_size, learning rate, weight_decay）、随机种子（seed） 模型配置（model_config）：定义任务数（num_tasks）、特征维度（E_NUM, C_NUM） 、embedding维度（ embed_dim ）以及指定的模型类名 model_name 输出配置（export_config）： 指定 ONNX 导出的输出节点名称 output_names，需与 num_tasks 严格对应。 参数存储： config.py 用于持久化数据层计算出的归一化统计量（E_MAX, C_BASE 等），供模型初始化直接读取。 B. 数据层 对应文件：main.py，utils.py ( get_normailization ), config.py 归一化参数计算： 调用  get_normailization 扫描全量训练数据，计算归一化参数 计算  E_MAX, E_MIN（稀疏特征的最大/最小 ID，用于确定 Embedding 表大小） 计算  C_BASE (1%分位点) 和 C_SCALE (99%分位点) 归一化参数结果储存： 计算出的统计量动态会更新到  config.py 中（E_MAX, E_MIN, C_BASE, C_SCALE），后续模型初始化时可以设置 compute_normalization=False，可以 直接读取这些值 C. 模型层 对应文件：models/__init__.py,  basic_layers.py, Embedding_layers.py,... 采用工厂模式管理深度学习架构，支持灵活插拔和复用：在  models/ 目录下封装了不同的深度学习算法，并通过配置文件指定模型结构。 主要包含以下三部分： 注册机制  ( __init__.py)：维护模型注册表 MODEL_REGISTRY，根据 yaml 配置名动态实例化对应模型（如 DCN, MMOE）。 基础组件 ： basic_layers ：封装 MLP、Cross Network 等通用算子。 Embedding_layers ：实现场景特征处理及通用 Embedding 逻辑。 模型库 ：集成 DCN、MMOE、双塔等常用模型 模型需要自己定义 compute_loss 计算方法；对于多任务模型，支持输出loss以及每个头的辅助loss D. 训练引擎 多任务指标管理：根据配置的  num_tasks 动态初始化指标容器，自动计算并记录每个 Task 的 Loss 及主指标。 可视化 监控：利用 TensorBoard 记录 Loss/AUC 的变化趋势及参数分布直方图，实时监控模型状态。 E. 模型导出 功能：适配工程化上线需求， 将模型导出为通用 ONNX 格式 。 多任务适配：模型  forward 输出为 Tuple 格式 ，配置文件需严格定义 num_tasks 及 output_names，确保导出节点与下游推理服务对齐。 参考工程侧对模型输出格式的要求 ： 模型返回值协议标准化 F. 部署 模型部署SOP： https://cooper-vpn.xiaojukeji.com/docs2/document/2202931551107 ： 使用方法介绍 配置参数：编辑  config.yaml，设置模型名称（如 DCN）、任务数量（架构可以适配单任务和多任务的模型）、训练超参（epoch, lr）以及特征维度（E_NUM, C_NUM）。 运行训练：执行  python main.py 并传入数据路径及特征列名。首次运行会自动计算并保存归一化参数至 config.py，后续直接复用。 监控进度：通过控制台日志查看 Loss/AUC，或使用 TensorBoard 可视化训练曲线和参数分布。 获取模型：训练过程中自动保存验证集效果最好的  model_weights.pt 权重文件（若无验证集则保存最后一个epoch的权重文件） 导出部署：确保  yaml 中配置了对应的 output_names，将模型导出为通用 .onnx 格式以供工程上线
