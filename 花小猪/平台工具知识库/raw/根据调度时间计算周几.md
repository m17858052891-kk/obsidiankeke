其中，PRESTO_SQL、DiSQL和SPARK_SQL均为基于SQL语句查询的引擎
SPARK_SQL最语法接近Hive SQL的引擎，对各种语法的支持最为全面；其缺点是在后台实现上是Spark将Hive SQL转换成MapReduce任务部署在server节点上进行分布式计算，再回传结果给client，速度较慢；
Presto是由 Facebook 推出的一个基于Java开发的开源分布式SQL查询引擎，适用于交互式分析查询；
DiSQL是我司自研的SQL查询引擎
PRESTO_SQL和DiSQL速度非常快，甚至可以实现秒级的结果速查，但仅适用于语法简单、查询数据量小的任务，复杂语法支持度低 ->http://wiki.intra.xiaojukeji.com/pages/viewpage.action?pageId=160142946

模型层次
英文名
中文名
含义
APP
Application
应用数据层
提供差异化的数据服务、满足业务方的需求；在该层级实现报表（数易、邮件报表）、数据产品、或者其他分析主题的需要。
DM
Data Market
数据集市层
以业务分析主题场景出发，整合多个数据域数据，建立业务主题分析宽表，用于满足业务查询、OLAP分析等需要。
DWM
Data Warehouse Model
汇总数据层
基于数据域的划分，以分析的主题对象为建模驱动，基于上层的应用和产品的指标需求，构建公共粒度的汇总指标事实表，以宽表化手段来物理化模型。一般采用加强指标的维度细化，更多采用宽表化手段构建公共指标数据层，提升公共指标的复用性，减少重复加工。
DWD
Data Warehouse Detail
明细数据层
该层的主要功能是基于主题域的划分，面向业务主题、以需求为驱动设计模型，完成数据整合，提供统一的基础数据来源。在该层级完成数据的清洗、重定义、整合分类功能。依据维度建模理论，采用一些维度退化手法（冗余或打标），将维度作为属性退化到事实表中，减少事实表与维表的关联，提高数据的易用性。
DIM
Dimension
维度层
该层主要存储简单、静态、代码类的维表，包括从OLTP层抽取转换维表、根据业务或分析需求构建的维表以及仓库技术维表如日期维表等。
ODS
Operational Data Store
操作数据层
该层级主要功能是存储从源系统直接获得的数据。实现某些业务系统字段的数据仓库技术处理、少量的基础的数据清）、生成增量或全量数据表。

命名规范
kflower_strategy.{方向名(trade/price/growth/pbd/public/other)}_{模型分层(dwd/dim/app/...不同分层定义见下文}_{数据域(pas/dri/trd/...不同数据域见下文)}_{自定义命名标签(自己起的对本表的极简英文描述)}_{时间周期}

方向名
trade：交易策略
price：价格补贴策略
growth：增长策略
pbd：PBD相关
pricing：基础定价
pubilc：公共使用
other：其他不能归类的方向

上下游关联与Tag
点击调度配置，

根据任务重要程度配置基线，选择spark引擎版本（pyspark任务则为python和spark版本）
调度周期根据需要选择天级别或者其他级别



上游依赖代表本任务应当在哪个任务的哪个分区运行完（对应tag产生）后，才开始运行
tag指的是任务完成的标志，不是具体的分区数据
比如，你想运行的周期任务在11月1日的运行，依赖于上游某表产出10月31日分区的任务执行完毕，则配置该表为上游依赖，偏移量为0 0 -1
偏移量的设置可参考 http://wiki.intra.xiaojukeji.com/pages/viewpage.action?pageId=198706662

同时，你的这个任务运行完当天的分区，应当产出一个tag给到下游，请添加到“调度产出”中


如果是sparksql任务，一般情况下，上游依赖和下游产出，都可以通过“自动解析依赖”解析出来，但需要自己check一下偏移量
值得注意的是，pyspark任务和shell任务可能是隐式地依赖某些任务，则千万注意自己添加好对应的依赖与产出。

调度重跑
假如我们修改了某任务的计算逻辑，需要重新计算并产出历史某个区间的数据刷入线上，就需要在调度系统中重跑任务
可以在该任务页面右上角点击“前往调度”

也可以在调度系统(https://schedule.data.didichuxing.com/v5/cycle/task?projectId=1143)中搜索到所需重跑的任务

在任务页面点“重跑”

选择要回溯的日期，注意调度时间与实际产出分区时间的关系
例如调度时间为2023.11.06 00:00:00，则实际计算并产出的分区是T-1即2023.11.05

注意，如果有下游关联的任务因为本任务的数据变化了而也需要回溯重跑，请选择级联回溯子孙任务，在本任务完成后会根据任务间的树顺序依次勾联发起下游任务的回溯重跑（如下图示）

制作数据集
想要创建图标，需要先创建数据集，在“工作台”——“数据集”中选择“创建数据集”——“Hive”

其中，“拖拽表”适用于表间关联关系非常简单，完全不需要额外语句的Hive SQL
除此种情况之外，选择“自定义SQL”即可。注意，这里仅支持原生Hive SQL语法，如果有不支持的语法，可以现在数梦上创建周期调度任务，将数据写入hive表中，再在这里创建数据集

注意数易的变量与数梦有一些不同，比如调度前一天在数梦中是${BIZ_DATE_LINE}，在数易中是$[YYYY-MM-DD - 1D]，可参考左侧边栏的“提示”
SQL写好后，右上角点击确认SQL进入字段编辑
需要配置哪些字段是维度（比如日期、城市等在SQL中你放在group by中的字段），哪些字段是指标，以及指标具体的格式、数值的处理方式等


维度和指标都配置好后，配置权限和加速

其中权限自己根据需要配置即可

加速的意思是类似数梦周期调度一样，配置固定什么周期运行一次帮我们自动化产出数据集的数据

“全量覆盖”适用于每次运行，都是跑从过去的某天到调度的时间这整个时间段的数据写入缓存
“分区追加“适用于每次运行，是跑过去一天的数据写入缓存
如果数据表是每天更新，且每天跑昨天一天的数据的，选择分区追加即可
其他加速方式，具体可参考https://cooper.didichuxing.com/knowledge/share/page/EQLrTDoz010P
选择完后，下方注意配置本数据集任务所依赖的库表，及与依赖的上游的时间位移关系
