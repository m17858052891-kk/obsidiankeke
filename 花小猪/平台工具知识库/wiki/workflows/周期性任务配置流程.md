# 周期性任务配置流程（kflower_strategy）

## 目标

基于离线 Hive 表生产的特征，通过周期性任务同步到线上存储，使模型在线可以使用离线创建的特征。

## 全流程概览

```
1. 数梦周期性任务准备 → 2. DUFE 离线特征生产 → 3. 上线验证
```

---

## Step 1: 准备 kflower_strategy 周期性任务

### 入口

kflower_strategy 项目空间：https://studio.data.didichuxing.com/?projectId=1143

### 操作步骤

1. 在项目空间下准备离线 Hive 表的特征 SQL
2. 确保特征名称具备可读性
3. **先注释掉写表代码** → 点【测试运行】
4. 测试通过后 → 恢复写表 → 点【发布】
5. 发布成功后 → 发链接给组内同学 review
6. Review 通过后 → 冒烟测试（点【执行】或【重跑】指定日期）

### 权限申请

**必须**为霸王花交易定价申请 Hive 表对应的 HDFS 权限：
https://pam.data.didichuxing.com/role/apply?type=project

## Step 2: DUFE 离线特征生产

### 入口

https://dufe-v2.intra.xiaojukeji.com/new-task → 右上角【新增任务】

### 2.1 基本信息

| 配置项 | 填写要求 |
|-------|---------|
| 任务名称/描述/使用场景 | 体现业务场景和任务用途 |
| 接口人 | 3 人（组内同学为主） |
| 部门 | 花小猪 |
| 任务级别 | 默认 P1 |
| 任务告警人 | 多个实际关注人员 |
| Odin 告警组 | `kflower_dups_dict` |
| 执行时间与 SLA | 按业务场景配置（见下方 SLA 说明） |
| 是否定时切换 | 默认"否"=自动切换 |

### 2.2 任务配置

#### Dict 集群

根据业务场景选择。

#### 数梦项目

选择 `kflower_marketplace`

#### 基线选择

见下方 [[#SLA 与基线配置]]

#### Spark 参数

| 数据规模 | minExecutors | maxExecutors |
|---------|--------------|--------------|
| 万条以内（如城市维度） | 10 | 20 |
| 千万级别 | 100 | 200 |
| 亿级以上（如乘客 P 维度） | 200 | 300 |

> driver.memory 和 executor.memory 一般不需要调整，除非报 OOM。

#### SQL 语句

**示例：**
```sql
SELECT
    city_id,
    city_avg_lumian_dis_answer_7d AS odt_city_avg_lumian_dis_answer_7d,
    city_avg_lumian_dis_answer_14d AS odt_city_avg_lumian_dis_answer_14d,
    city_avg_lumian_dis_finish_7d AS odt_city_avg_lumian_dis_finish_7d,
    city_avg_lumian_dis_finish_14d AS odt_city_avg_lumian_dis_finish_14d
FROM kflower_strategy.city_avg_eda
WHERE dt = 'param_year-param_month-param_day'
```

**命名规则：**
- 特征列加类型前缀：`odt_`(地点)、`i_`(输入)、`s_`(供需)、`b_`(冒泡)、`d_`(司机)、`p_`(乘客)、`o_`(订单)
- **主键列不加前缀**（如 `city_id` 保持原样，不要写成 `odt_city_id`）

> 主键列加前缀会导致模板中需要多传参数，造成冗余。

#### 偏移量

- 0 = SQL 日期参数替换为当天
- 1 = 替换为 T-1 日
- 一般与 tag 偏移量相反

#### 特征前缀与主键

- 特征前缀 + 主键 → 拼接为 Key（如前缀 `AAA`，主键 `driver_id` → Key = `AAA_123456`）
- **主键必须唯一**

#### 依赖 Tag

- SQL 中查询哪些表，tag 就设置这些表
- 年月日为依赖的 Hive 库表分区偏移量

#### 是否打包

默认"否"。

### 2.3 质检配置

- 行数校验
- 空值率检测（空值行/总行数 > 阈值时报警）
- 质检通过后才触发 Fastload 任务

### 2.4 工单流转

1. **预览**：验证 SQL 正确性
   - 失败原因：HDFS 权限不足 → 回到 Step 1 申请权限
   - 失败原因：内存超限 → 联系管理员跳过（@yuhaotian @tidusfengxinjie）
2. **特征信息填写**：写中文特征名（完整表达含义），检查英文名与列名一致
3. **审批**：两层审批（直属上级 + 管理员）
4. **上线**：点击【上线】后自动执行 HDFS + Fastload 任务
5. **等待完成**：Fastload 执行完成 = 特征生产完成

## Step 3: SLA 与基线配置

### 基线等级

| 等级 | 适用场景 | 特点 |
|------|---------|------|
| L2 | 普通任务 | 普通优先级 |
| L7 | 重要任务 | 较高优先级 |
| L8 | 重保任务 | **电话报警** |

### 预设基线列表

| 基线 ID | 基线名 | 保障时间 | SLA 时间 | 适用场景 |
|---------|-------|---------|---------|---------|
| 32229 | L2_保障5_SLA6 | 05:00 | 06:00 | 动调依赖的策略特征（早高峰前就绪） |
| 31944 | L2_保障9_SLA10 | 09:00 | 10:00 | 一般策略特征（时效性不高） |
| 31946 | L2_保障15_SLA16 | 15:00 | 16:00 | 下午场景 |
| 32231 | L7_保障5_SLA6 | 05:00 | 06:00 | 重要任务-早高峰 |
| 31940 | L7_保障9_SLA10 | 09:00 | 10:00 | 重要任务-上午 |
| 31942 | L7_保障15_SLA16 | 15:00 | 16:00 | 重要任务-下午 |
| 32233 | L8_保障5_SLA6 | 05:00 | 06:00 | 重保-早高峰 |
| 31936 | L8_保障9_SLA10 | 09:00 | 10:00 | 重保-上午 |
| 31938 | L8_保障15_SLA16 | 15:00 | 16:00 | 重保-下午 |

> **选择建议**：不要参考历史批次完成时间（不一定合理），应按业务场景合理选择。特殊需求可自建基线。

### 定时切换说明

- Fastload 生成新版本后，延迟到 `cron_time` 再切换
- 如当前时间已超过当天 `cron_time`，则立即切换
- 根据任务完成时间和业务数据可用时间选择切换时间
