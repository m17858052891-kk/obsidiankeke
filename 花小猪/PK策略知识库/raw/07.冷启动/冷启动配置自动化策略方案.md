[商家冷启动自动化配置BRD](https://cooper.didichuxing.com/docs2/document/2202670456277)

# 一、背景

目前商家冷启动需要通过多方人工手动配置，所涉及的团队多、流程环节长，容易出错；各方单点支持，遇到同学请假或者疏忽，容易漏配。

# 二、收益判断

1. 减少出错，24年H1出现过两次配置问题（漏配置、单点支持导致延迟配置）

2. 减少人力消耗

# 三、需求说明和功能点

## 需求说明：

1. 算法同学每周产出所有城市维度冷启动参数

2. 交易系统自动读取新开城商家标识，获取该城市冷启动参数

3. 自动对新开城商家执行冷启动策略14天

4. 可根据运营同学要求，手动操作，中途停止冷启动策略

覆盖范围：花小猪端新开城

# 四、策略方案

流程如下：

1. 策略维护by城市开城商家list，暂定T-180至T-13有冒泡流量的商家

2. 线上根据该商家是否在开城商家list中，判断是否触发冷启动策略

3. 若触发，则读取冷启动特征表；若不触发，则进入正常流程

	1. 冷启动特征表由策略产出，保证该特征组合对应的PK打分在T-1处于中游

4. 判断该司机的历史14天完单数>n（n分城市可配置）

	1. 是：使用该司机自身特征

	2. 否：使用替换特征

		1. 若手动冷启动生效，则司机id替换为配置的司机id

		2. 否则，司机id替换为对应城市id

# 五、监控配置

1. 司机替换特征的分位数p（t-1）+ 非替换特征的中位数（t-1）得出的打分（t-1）【打分策略给】以及分位数（t-1），用于判断替换特征的最优分位数是否合理

2. 司机替换特征的分位数p（t-1）+ 非替换特征的中位数（t-1）得出的打分（t-1）【打分策略给】以及分位数（t），对比a可以用于判断替换特征的最优分位数是否受时间影响，当天累计平均打分分位数（t）需工程建设

3. by冷启动商家，当天实时司机的替换特征的分位数p（t-1）+ 非替换特征的实际值（t）得出的打分（t）以及分位数（t），对比b可以用于判断商家打分分位数过高或过低是否由于非替换特征（距离等）的影响，当天累计平均打分分位数（t）需工程建设

4. 【策略给】历史接驾距离的中位数

5. by商家当天实时司机纬度接驾距离平均值

6. 注意：自动化冷启动上线后，即完单>n的司机使用自身特征，所有的监控数据 只取 被替换的司机

**报警**

当1中打分分位数偏离45分位数时触发报警，当1未偏离，3偏离时触发通知

# 六、效果评估方案

- 预期收益：

	- 提高人效

	- 减少人工出错的case

# 七、监控和日志

by小时，对所有分单召回和PK举手司机的相关信息落表

1、是否命中开城商家list（0：未命中，即新开城；1：命中，即已开城）

2、该司机的历史完单数（对于新开城商家，等价于该司机的历史14天完单数）

3、是否触发冷启动策略以及类型（0：未触发，即历史14天完单数>n；1：触发自动化冷启动，即填充城市id；2：手动冷启动，即手动填充司机id）
