# 履约率

履约率（也称完单率、CR / Completion Rate）是 PK 决策系统中最核心的评估指标。它衡量的是**司乘匹配后是否成功完成订单**。

## 定义

| 术语 | 含义 |
|---|---|
| **完单** | PK 胜出后，司机成功接到乘客并完成行程 |
| **未完单** | PK 胜出后订单失败，包括司机拒单、司机取消、乘客取消 |
| **履约率** | 完单数 / (完单数 + 未完单数) |
| **CR** | 成交率，平台级别的订单完成率 |

## 在 PK 系统中的角色

[[花小猪/PK策略知识库/wiki/entities/PK模型.md|PK 模型]]的预测目标就是**胜出完单概率**：
- 正样本 = PK 胜出后完单的司乘对
- 负样本 = PK 胜出后未完单的司乘对

因此，履约率既是模型的训练目标，也是线上效果的核心评估指标。自 V4 Deep&Wide 最终评审起，线上放量已把完单和 CR 从“必须增长”调整为“不显著负约束”，主要收益转向交易效率。

## 影响因素

| 因素 | 影响方向 | 说明 |
|---|---|---|
| [[花小猪/PK策略知识库/wiki/concepts/接驾距离.md]] | ↓ 距离越大，履约率越低 | 最强影响因子 |
| 司机历史取消率 | ↓ 取消率越高，履约率越低 | |
| 乘客历史取消率 | ↓ 取消率越高，履约率越低 | |
| 等待时间 | ↓ 等待越久，乘客越容易取消 | 与 [[花小猪/PK策略知识库/wiki/entities/PK窗口.md|PK 窗口]]策略相关 |
| 供需匹配度 | ↑ 供需平衡时履约率更高 | |

## 关键数据点

- LR 模型 vs XGB：平台完单 ==-0.13%==，宏鹄完单 ==+10%==
- 毛利因子引入：完单 ==-0.12%==，毛利率 ==+0.15pp==
- V1 动态窗口：通过延长等待降低乘客取消来提升履约率

## 与其他指标的权衡

履约率常需与其他业务指标进行权衡：
- **履约率 vs 毛利率**：置换比约 1:1
- **履约率 vs 应答时长**：PK 窗口越长匹配越优但等待越久
- **履约率 vs 接驾距离**：模型倾向选近距离司机，但可能牺牲其他目标

## 范式转变：从"目标"到"约束"

> [!info] 2026 Q2 新范式
> [[花小猪/PK策略知识库/wiki/entities/约束履约率最小化接驾距离策略.md|V5 约束-最小化策略]] 将 PK 打分目标从"最大化履约率"改为"**约束履约率不显著负，最小化[[花小猪/PK策略知识库/wiki/concepts/接驾距离.md|接驾距离]]**"。

| 范式 | 公式 | 履约率角色 |
|---|---|---|
| 旧（V0-V4）| `max E[f]` | 优化目标 |
| **新（V5）** | `min E[d]  s.t.  E[f] ≥ 0.998·E[f^0]` | **约束条件**（允许下降 ≤ 0.2%）|

> [!note] V4 是过渡版本
> V4 的模型打分仍是 `α·f_p + (1-α)·f_d`，但最终放量决策已经采用“完单/CR 不显著负 + ETP/司机接驾时长改善”的约束式业务目标。V5 的区别是把约束进一步显式写进 `λf-d` 打分本身。

V4 最终 0.9:0.1 组：人均完单 -0.16%（不显著）、CR +0.03pp（不显著）；80% 放量复验为完单 -0.05%（不显著）、CR +0.01pp（不显著）。

PK 分形态变化：

```
旧：PK 分 = α·f_p + (1-α)·f_d
新：PK 分 = λ·f − d           (λ ≈ 5340，即 5.34m 距离 ↔ 0.1pp 履约率)
```

**思路**：平台 CR 已达高位，继续在 CR 上做边际优化空间小。但接驾距离 / ETP / 司机接驾时长仍有显著优化空间。从单目标最大化转为多目标约束优化。

### 模型预测目标也变了

V5 同步将履约率建模从"双任务"升级为"3 分类"：

```
旧：P(is_o_finish | X)  +  P(is_d_finish | X)  ←  存在协变量偏移
新：P(司机取消 | X) + P(乘客取消 | X) + P(完单 | X)  ←  多分类直接建模
派生：乘客履约率 = P3 / (P2 + P3)
     司机履约率 = P3 / (P1 + P3)
```
