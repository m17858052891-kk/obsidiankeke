# 约束履约率最小化接驾距离策略

> **2026 Q2 启动的 PK 范式重构方案**：将 PK 打分目标从"最大化履约率"改为"约束履约率不显著负、最小化接驾距离"，并配套升级模型为多域多专家 3 分类网络。

业务 owner & 策略 owner：董听；优先级：P1；状态：V1.0 评审"建议拆分" → V1.1 重写。

## 1. 范式转变（核心动机）

| 维度 | 旧范式（V4 Deep&Wide）| 新范式（约束-最小化）|
|---|---|---|
| **优化目标** | `max E[f]`（最大化履约率）| `min E[d]  s.t.  E[f] ≥ C·E[f^0]`（约束 CR 不负，最小化接驾距离）|
| **PK 打分** | `α·f_p + (1-α)·f_d` | `λ·f − d`（拉格朗日松弛形式）|
| **建模任务** | 双任务（is_o_finish + is_d_finish）| 3 分类（司机取消 / 乘客取消 / 完单）|
| **模型结构** | Deep&Wide（4 模块拼接）| 多域多专家（EPNet Gate + 多 Expert）|
| **可解释来源** | Wide 子模块 LR | LR 蒸馏深度模型软标签（≥80%，城市×商家≥95%）|

> [!info] 为什么转变？
> 平台 [[花小猪/PK策略知识库/wiki/concepts/履约率.md\|CR]] 已达高水位，继续在 CR 上做边际优化空间小。但是 [[花小猪/PK策略知识库/wiki/concepts/接驾距离.md\|接驾距离]] / ETP / 司机接驾时长 仍有显著优化空间，且这正是交易团队关心的"交易效率"指标。范式从单目标最大化转为**多目标约束优化**。

## 2. 数学建模

### 2.1 优化问题（V1.1 by 订单）

```
min   d_j
s.t.  f_j ≥ C · max_k f_k,    C = 0.998
```

- $i$ 订单下标，$j$ 司机下标
- $f$ 模型预估履约率，$d$ 接驾距离
- $C = 0.998$：允许胜出司机相对最高履约率司机的履约率下降 ≤0.2%

> [!note] V1.0 → V1.1 的关键调整
> V1.0 使用**全局总和约束** `Σf_ij·x_ij ≥ C·Σf^0_ij·x^0_ij`（履约率作为预算分配），但被评审拒绝（朱正丹："全天履约当作资源做优化问题需要讨论"）。V1.1 改为 **by 订单约束**，每个订单独立判断。

### 2.2 解法对比

| 解法 | 思路 | 问题 / 结论 |
|---|---|---|
| **解法一：硬约束** | by 订单直接判断 `f_j ≥ 0.998·max_k f_k` | ❌ 司机陆续举手，无法在线知道 max f_k；可选司机仅 0.56% 订单，整体降距 <1m |
| **解法二：拉格朗日松弛 + 全局 λ** | 离线求解全局 λ，PK 分 = `λf − d` | ✅ **最终采纳**，离线模拟 λ=5340 时，距离 -20m (-1.21%)，CR -0.14pp |

### 2.3 拉格朗日推导

拉格朗日函数（V1.1 by 订单形式）：

$$\mathcal{L}(j, \lambda) = d_j + \lambda(C \max_k f_k - f_j) = \lambda C \max_k f_k + (d_j - \lambda f_j)$$

对偶问题求 min 等价于 `max_j (λf_j − d_j)`，因此：

$$\boxed{\text{PK 分} = \lambda f - d}$$

### 2.4 λ 的物理含义与求解

- **λ 是"履约率值多少接驾距离"的兑换比例**（量纲：米/履约率）
- 离线测算：**λ = 5340 ≈ 5.34m 接驾距离 ↔ 0.1pp 履约率**
- 求解流程：
  1. 历史数据上对每个订单 i 求 λ_i（使硬约束被满足的最小 λ）
  2. 对所有 λ_i 排序，取 x% 满足率分位（默认 90%）的 λ_x

| 训练 / 验证 | 时间区间 |
|---|---|
| Train（求 λ）| 2026-03-24 ~ 2026-03-30 |
| Valid（模拟）| 2026-03-31 ~ 2026-04-06 |

## 3. 履约率模型升级（多域多专家 + 3 分类）

### 3.1 旧模型问题：协变量偏移

V4 Deep&Wide 的双任务建模存在**样本选择性偏差**：

| 子任务 | 训练样本 | 推理空间 | 偏差 |
|---|---|---|---|
| 乘客履约 `P(Y=完单 \| 司机未取消, X)` | 司机未取消的样本 | `P(Y=完单 \| X)` | 缺失"恶劣天气+远距离"等司机高取消订单的特征拟合 |
| 司机履约 `P(Y=完单 \| 乘客未取消, X)` | 乘客未取消的样本 | `P(Y=完单 \| X)` | 同上对称问题 |

### 3.2 新模型：3 分类多任务

将订单状态建模为**互斥 3 类**：

```
P1 = P(司机取消 | X)
P2 = P(乘客取消 | X)
P3 = P(完单 | X)         (P1 + P2 + P3 = 1)
```

派生指标：

```
乘客履约率 = P(乘客履约 | 司机履约) = P3 / (P2 + P3)
司机履约率 = P(司机履约 | 乘客履约) = P3 / (P1 + P3)
履约率 f  = α · 乘客履约率 + (1 − α) · 司机履约率,   α = 0.9
```

### 3.3 模型结构（多域多专家）

| 组件 | 设计 | 灵感来源 |
|---|---|---|
| **多域** | 是否连环派 × 派单模式（全指派/半指派/抢单）× 时段 × 长短单 × 供需 | EPNet Gate NU |
| **多专家** | 多个并行 Expert，gate 决定权重 | [[花小猪/PK策略知识库/wiki/models/PLE多任务模型.md\|PLE]]、PEPNet |

> 与 [[花小猪/PK策略知识库/wiki/proposals/01-sparse-moe-多商家差异化建模.md]] 的 MoE 设计同源，但本方案的 gate 输入是**域特征**（连环派/派单类型/时段）而非商家身份。

### 3.4 评估指标：OvR Macro AUC

```
AUC_A = AUC(司机取消为正样本)
AUC_B = AUC(乘客取消为正样本)
AUC_C = AUC(完单为正样本)
Macro AUC = (AUC_A + AUC_B + AUC_C) / 3
```

预期 AUC +3pp（相对当前 Deep&Wide）。

### 3.5 可解释性：LR 蒸馏

「可解释」定义：对相同订单 o 的两个司机 (i, j)，若深度模型与 LR 模型的打分排序一致 `(v_{i1}-v_{j1})·(v_{i2}-v_{j2}) ≥ 0`，则 LR 可解释该 pair。

- 用 LR 蒸馏深度模型在训练集上的预测概率（软标签）
- 整体可解释率目标：≥ **80%**
- 城市 × 商家维度可解释率目标：≥ **95%**（评审建议）

## 4. 工程改造

| 改造点 | 说明 |
|---|---|
| **PK 分计算** | 由"两项履约率加权"改为"模型直接产出 P1/P2/P3 + 策略包装" |
| **PK 分公式** | `PK分 = α·P3/(P2+P3) + (1-α)·P3/(P1+P3) − (1/λ)·d` |
| **λ 配置** | 1/λ 从 hive 表读取，**by 城市维度，天级别**（V1.0 是小时级 + 熔断，V1.1 简化为天级别，划掉熔断机制）|
| **配置方式** | dufe（V1.0 候选过 apollo，V1.1 确定 dufe）|
| **日志** | 模型日志包含 履约率 f、PK 分、λ |

> [!warning] V1.1 取消的设计
> V1.0 设计的"小时级 hive 表 + 城市维度熔断（CR 跌幅超阈值降级为最大化 f）+ PID 反馈控制"在 V1.1 中**全部划掉**。原因可能：(1) 小时级保产太困难 (2) 评审建议拆两期，先验证基础模型。

## 5. 实验方案

### 5.1 流量与周期

| 项 | 设置 |
|---|---|
| 流量端 | 花小猪端 |
| 品类 | 自营 + 鸿鹄 |
| 分单场景 | 全部 |
| 实验方式 | 乘客分流（7 天）+ 时间片实验（14 天）|
| 评估指标 | 完单、CR、应答后乘客取消率、ETP、司机接驾时长 |

### 5.2 PID 分流（4 组拆解）

| 组 | 模型 | 1/λ | α | 含义 |
|---|---|---|---|---|
| 对照 | Deep&Wide | 0 | 0.9 | 当前线上 |
| 实验 1 | **新模型（3 分类）** | 0 | 0.9 | 仅模型升级，目标不变 |
| 实验 2 | Deep&Wide | hive | 0.9 | 仅打分目标升级，模型不变 |
| 实验 3 | **新模型** + hive | hive | 0.9 | 完整方案 |

> [!tip] 拆解的目的
> 通过 PID 实验区分**模型升级**与**目标重构**各自的贡献，对应朱正丹评审建议"拆分两期"。

### 5.3 时间片实验

对照（线上 LR 或 Deep&Wide）vs 实验（完整方案），每小时翻转。

## 6. 收益预估

|---|---|---|
| 完单 / CR | 不显著负 | 约束条件 |
| ETP + 司机接驾时长 | ==-0.5%== | 主要收益 |

## 7. 与现有体系的关系

### 7.1 接续 Wide&Deep 的下一代

| 代际 | 模型 | 目标公式 | 状态 |
|---|---|---|---|
| V0-V3 LR | LR | f_p · α + f_d · (1-α) | 全国 5% |
| V4 Deep&Wide | Wide&Deep | 同上 | 当前线上实验中（2026-04 v1.2 CR+0.17pp）|
| **V5 约束-最小化** | **多域多专家 3 分类 + λf-d** | **min d s.t. f ≥ C·max f** | 待实验 |

- **[[花小猪/PK策略知识库/wiki/proposals/04-偏好对齐-DPO-IPA.md]]**：本方案不直接是 DPO，但同样体现"从拟合 CR → 优化更广义体验"的思路。

## 8. 风险与开放问题

> [!warning] AI 评审提出的关键风险（V1.0）
> 1. **帕累托边界假设过理想**：「完单率 vs 接驾距离」未必是清晰凸面 → V1.1 改为离线遍历 λ + 二分法
> 2. **λ 缺乏在线自适应**：恶劣天气 / 爆单 / 节假日下历史 λ 可能失效
>    - V1.0 解：每周更新 + hive 小时表 + 熔断 + PID
>    - V1.1 解：**简化为天级别 hive 表，取消熔断**（待评估线上稳定性）
