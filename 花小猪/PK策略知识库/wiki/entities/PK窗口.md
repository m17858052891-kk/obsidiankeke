# PK 窗口

PK 窗口是聚合 PK 系统中用于收集举手司机的时间窗口。窗口的长度直接影响两个关键目标的权衡：
- **更长窗口** → 更多候选司机 → 更优匹配质量
- **更短窗口** → 更快应答 → 更低乘客取消率

## 核心机制

有运力举手时，系统保留 [[花小猪/PK策略知识库/wiki/entities/PK模型.md|PK 打分]]最高的"当前胜者"。窗口结束时，当前胜者胜出并获得订单应答资格。

## 策略演进

### 静态窗口（基线）

- PK 窗口固定 ==4 秒==
- 窗口内所有举手司机参与 PK，4 秒结束时打分最高者胜出
- 简单可靠，但无法适应不同场景的供需差异

### 动态窗口 V0（线上策略）

- **核心逻辑**：若当前举手运力是 4 秒内预估[[花小猪/PK策略知识库/wiki/concepts/接驾距离.md|接驾时长]]最短的概率 > ==0.95==，则提前结束 PK 窗口
- **收益来源**：减少应答时间 → 司机更快周转 → 系统效率提升
- **适用条件**：高概率已获得最优司机的场景

### 动态窗口 V1（扩量失败）

双向动态调整，窗口范围 ==0-8 秒==：
- **提前结束**：若当前胜者预估[[花小猪/PK策略知识库/wiki/concepts/司乘取消.md|乘客取消]]率 < ==0.09==，即刻结束
- **延长等待**：若 4 秒时当前胜者预估乘客取消率 > ==0.45==，延长至最多 8 秒
- **状态**：实验评估后扩量失败

> [!warning] V1 扩量失败
> V1 策略在实验中表现出一定改进，但未能通过全面扩量评审。具体失败原因需查阅实验评估文档。

### 强化学习方案（优化中）

将 PK 窗口控制建模为**马尔可夫决策过程（MDP）**：

| 要素 | 设计 |
|---|---|
| **状态空间** | PK 时间戳 + 订单特征 + 胜者/败者特征 |
| **动作空间** | 结束 PK / 继续等待 |
| **奖励函数** | 基础奖励 + 完单奖励 - 等待时间惩罚 + PK 分改善 |

> **核心思路转变**：从完单概率的预测转变为**等待价值**的设计和学习 — 不再问"当前胜者够好吗"，而是问"继续等待的期望价值是否为正"。

## 决策条件总结

| 条件 | 来源 | 举手模式 |
|---|---|---|
| 乘客单勾自营 | TopOne 提前停止 | — |
| 滴滴举手 + 同步配置 | 同步举手直接返回 | 同步 |
| 非滴滴 + 非 TopOne | 动态 PK 窗口 | 异步 |
| 流量端 ∈ [同程, 腾讯出行] | FIFO 先到先得 | — |
| 预分单 | FIFO 先到先得 | — |
