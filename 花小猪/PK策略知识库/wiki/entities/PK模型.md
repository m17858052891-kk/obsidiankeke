# PK 模型

PK 模型是聚合平台 PK 决策系统的核心打分模型。当前线上 V4 Deep&Wide 分别预测乘客履约率与司机履约率，以 0.9:0.1 融合后排序；上线决策以完单/CR 不显著负为约束，主要优化乘客 ETP 和司机接驾时长。

## 预测目标

**正样本**：PK 胜出后完单的司乘对
**负样本**：PK 胜出后未完单的司乘对（包括司机拒单、司机取消、乘客取消）

## 模型演进路线

```
XGBoost（初始） → LR 可解释模型（2024-2026） → V4 Deep&Wide（2026-07 推全） → OneTrans / 个性化（规划）
```

### XGBoost 阶段

- **[[花小猪/PK策略知识库/wiki/concepts/AUC.md|AUC]]** = ==0.7345==（PBD 端验证集）
- 40+ 特征，涵盖订单、司机行为、乘客行为、地理位置
- 重要特征 Top5：送驾距离（4037）、城市（3188）、商家 ID（3084）、发单时间（2875）、[[花小猪/PK策略知识库/wiki/concepts/接驾距离.md|接驾距离]]（2582）
- **问题**：模型不可解释，商家无法理解胜率变化原因

### LR 可解释模型（2024 重点）→ [[花小猪/PK策略知识库/wiki/entities/PK可解释模型.md]]

- 从 XGB 过渡到逻辑回归：`y = sigmoid(w1*x1 + w2*x2 + ... + wk*xk)`
- 核心改进：特征筛选精简、司乘取消率合并、==接驾距离权重放大到 2 倍==
- 分多个版本迭代（V1-V3），逐步优化连环派场景、半指派模式和绕路比特征

### V4 Deep&Wide（当前线上）

- **双任务**：分别预测乘客履约与司机履约，最终权重 0.9:0.1
- **Deep**：乘客画像、供需画像；**Wide**：保留司机和司乘差异化原始特征的线性可解释性
- **全国 PID**：乘客 ETP -1.64%、司机接驾时长 -2.41%、接驾距离 -60.32m，完单/CR 不显著负
- **放量**：2026-07-03 推全；下一步为 Q3 OneTrans 序列特征、Q4 乘客个性化

## 兜底机制

当 Ether 模型服务请求失败时，使用距离公式兜底：
```
EtherValue = 0.881 - 0.0432 * PickUpDis / 500.0
```

## 关键指标

| 指标 | 说明 | 当前水平 |
|---|---|---|
| AUC | 离线模型区分力 | V4 乘客 0.701、司机 0.825、综合 0.683；不能单独决定上线 |
| 乘客 ETP / 司机接驾时长 | 当前主要收益指标 | V4 全国 PID：-1.64% / -2.41% |
| 绝对胜出率 | 各商家在 PK 中的胜率 | 滴滴 62.19%, 宏鹄 30.34% |
| 平台完单数 | 核心在线指标 | 实验评估基准 |
