# 策略方案：统一缩放范式 — 模型规模扩展策略

## 1. 方案概述

### 1.1 一句话摘要

基于腾讯统一缩放范式的发现（多任务模型性能遵循幂律缩放），系统性探索 PK 模型在参数量、训练数据量、特征维度上的缩放规律，制定长期的模型规模扩展路线图。

### 1.2 方案定位

| 维度 | 说明 |
|---|---|
| **目标模块** | PK 全链路模型（打分 + 窗口 + 因子）|
| **核心问题** | 当前模型规模选择缺乏理论指导，依赖经验试错 |
| **技术来源** | 腾讯统一缩放范式（2025）：R² > 0.9 的幂律缩放 |
| **预期收益** | 明确"多大的模型能带来多少收益"，指导资源投入决策 |
| **实施周期** | 8-12 周（实验密集型）|
| **建议时间窗口** | 2027 Q2+（长期储备方向）|

---

## 2. 背景与动机

### 2.1 缩放定律（Scaling Laws）概述

缩放定律揭示了模型性能与资源投入之间的幂律关系：

$$L(N, D) = a \cdot N^{-\alpha} + b \cdot D^{-\beta} + c$$

其中：
- $L$ = 模型损失（越小越好）
- $N$ = 模型参数量
- $D$ = 训练数据量
- $\alpha, \beta$ = 缩放指数（越大意味着扩大规模收益越大）
- $a, b, c$ = 拟合常数

**腾讯的关键发现**（2025）：
- 在推荐系统的统一多任务架构下，**生成式损失和对比学习损失均严格遵循幂律缩放**
- 拟合度 ==R² > 0.9==
- 含义：扩大模型规模能**同时且可预测地**提升多个任务的性能

### 2.2 PK 系统的规模现状

| 模型 | 参数量 | 训练数据量/天 | 特征维度 | AUC |
|---|---|---|---|---|
| LR | ~30 | ~500 万 | ~15 | 0.756 |
| Wide&Deep | ~100K | ~500 万 | ~40 | 0.683(综合) |
| PLE | ~1M | ~500 万 | 165 | 0.779 (OD) |
| DQN | ~500K | ~500 万 | 200+ | — |

**关键疑问**：
- 从 30 参数（LR）到 1M 参数（PLE），AUC 仅从 0.756 到 0.779（+2.3pp）
- 继续扩大到 10M、100M 参数，AUC 能提升多少？
- 还是存在"天花板"效应（PK 场景的信息上界）？
- 训练数据从 14 天扩展到 90 天，收益是否显著？

### 2.3 为什么现在就要规划

虽然实施优先级低，但**缩放实验需要尽早启动**，原因：
1. 指导其他方案的架构决策（MoE Expert 该多大？骨干网络该多宽？）
2. 明确投入产出比（避免盲目堆参数）
3. 发现 PK 场景的"信息天花板"（如果存在的话）

## 3. 技术方案

### 3.1 三维缩放实验

```
                    模型参数 (N)
                        │
                        │  实验: 固定 D 和 F，变化 N
                        │  N ∈ {1K, 10K, 100K, 1M, 10M}
                        │
    训练数据 (D) ────────┼──────── 特征维度 (F)
                        │
   实验: 固定 N 和 F      │      实验: 固定 N 和 D
   D ∈ {1d, 3d, 7d,     │      F ∈ {15, 40, 80, 165, 300}
        14d, 28d, 90d}   │
```

#### 维度 1：模型参数缩放

| 实验 | 参数量 | 架构 | 说明 |
|---|---|---|---|
| N-1K | ~1K | 浅层 MLP [64→1] | 极简基线 |
| N-10K | ~10K | MLP [128→64→1] | 小模型 |
| N-100K | ~100K | Wide&Deep 级别 | ==当前线上级别== |
| N-1M | ~1M | PLE 级别 | 当前最大模型 |
| N-10M | ~10M | 宽 PLE + MoE | 扩展实验 |
| N-100M | ~100M | 超大 DNN | 探索天花板 |

**固定条件**：D=14d，F=165（PLE 全特征集）

#### 维度 2：训练数据缩放

| 实验 | 数据量 | 时间跨度 | 说明 |
|---|---|---|---|
| D-1d | ~500 万 | 1 天 | 最少数据 |
| D-3d | ~1500 万 | 3 天 | — |

#### 维度 3：特征维度缩放

| 实验 | 特征数 | 特征集 | 说明 |
|---|---|---|---|
| F-15 | ~15 | LR 核心特征 | 最小特征集 |
| F-40 | ~40 | Wide&Deep 特征 | 中等特征集 |

| F-165 | 165 | ==PLE 全集== | 当前最大 |
| F-300 | ~300 | 全集 + 新增交叉特征 | 扩展 |
| F-500 | ~500 | 全集 + ID embedding | 极限扩展 |

**固定条件**：N=1M（PLE），D=14d

### 3.2 缩放定律拟合

对每个维度的实验数据，拟合幂律曲线：

```python
import numpy as np
from scipy.optimize import curve_fit

def scaling_law(x, a, alpha, c):
    """幂律缩放: L = a * x^(-alpha) + c"""
    return a * np.power(x, -alpha) + c

def fit_scaling_law(x_data, loss_data):
    """
    拟合缩放定律
    
    Args:
        x_data: 缩放变量（参数量/数据量/特征数）
        loss_data: 对应的模型损失（或 1-AUC）
    
    Returns:
        params: (a, alpha, c)
        r_squared: 拟合度
    """
    popt, _ = curve_fit(scaling_law, x_data, loss_data, 
                         p0=[1.0, 0.5, 0.1],
                         bounds=([0, 0, 0], [np.inf, 2, 1]))
    
    # 计算 R²
    y_pred = scaling_law(x_data, *popt)
    ss_res = np.sum((loss_data - y_pred) ** 2)
    ss_tot = np.sum((loss_data - np.mean(loss_data)) ** 2)
    r_squared = 1 - ss_res / ss_tot
    
    return popt, r_squared

# 示例：参数量缩放
N = [1e3, 1e4, 1e5, 1e6, 1e7, 1e8]
loss = [1 - auc for auc in [0.65, 0.72, 0.756, 0.779, ?, ?]]  # 待实验填充

params, r2 = fit_scaling_law(N, loss)
print(f"L = {params[0]:.4f} * N^(-{params[1]:.4f}) + {params[2]:.4f}")
print(f"R² = {r2:.4f}")

# 预测：需要多少参数才能达到 AUC 0.80？
target_loss = 1 - 0.80
N_required = (target_loss - params[2]) / params[0]) ** (-1/params[1])
```

#### 产出 3：PK 场景信息天花板评估

如果缩放曲线的常数项 $c$ 较大（如 $c > 0.15$，即 AUC 天花板 < 0.85），说明：
- PK 场景存在**不可减少的预测误差**（aleatory uncertainty）
- 继续扩大模型规模收益递减
- 应将重心转向**特征工程**（降低 $c$）而非**模型扩展**（提升 $\alpha$）

## 4. 实验设计

### 4.1 完整实验矩阵

| 维度 | 实验组数 | GPU 时间（估） | 数据准备 |
|---|---|---|---|
| 参数缩放 (N) | 6 组 | ~30 GPU·h | 无额外 |
| 数据缩放 (D) | 6 组 | ~50 GPU·h | 需扩展数据窗口 |
| 特征缩放 (F) | 6 组 | ~30 GPU·h | 需特征扩展 |
| 交叉验证 (N×D) | 6×6=36 组 | ~300 GPU·h | 全量交叉 |
| **总计** | ~54 组 | ~410 GPU·h | — |

### 4.2 指标体系

| 指标 | 用途 |
|---|---|
| AUC (各任务) | 精度衡量 |
| 1 - AUC (loss proxy) | 缩放定律拟合 |
| R² | 幂律拟合度 |
| α (缩放指数) | 扩大规模的边际收益率 |
| c (不可约误差) | 天花板估计 |
| 训练时间 | 成本衡量 |
| 推理延迟 | 工程约束 |

### 4.3 成功标准

| 条件 | 标准 |
|---|---|
| **拟合度** | 至少一个维度的 R² ≥ 0.9 |
| **可行动性** | 能明确回答"下一步模型该多大" |
| **天花板发现** | 确认或排除天花板的存在 |

## 7. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| **幂律不成立** | 中 | PK 场景可能不遵循缩放定律 | 分段拟合，或使用其他函数形式 |
| **天花板过低** | 中 | 意味着扩大规模无意义 | 转向特征工程 + 数据质量优化 |
| **实验成本过高** | 低 | GPU 资源消耗大 | 缩减交叉实验规模，只跑关键组合 |
| **特征扩展困难** | 中 | F>165 需要新特征建设 | 先用 ID embedding 自动扩展 |
| **结论无法行动** | 中 | 拟合出来但不知道怎么用 | 结合工程约束（latency/cost）给出明确建议 |
