# 策略方案：Dual-Encoder 异构场景建模

## 1. 方案概述

### 1.1 一句话摘要

构建双编码器架构，为连环派与非连环派场景分别建立独立的特征编码空间，通过物理隔离消除两种场景下[[花小猪/PK策略知识库/wiki/concepts/接驾距离.md|接驾距离]]等关键特征的语义混淆，提升 PK 模型整体精度。

### 1.2 方案定位

| 维度 | 说明 |
|---|---|
| **目标模块** | PK 打分模型 / PLE 多任务模型 |
| **核心问题** | 连环派与非连环派的接驾距离物理含义完全不同，共享编码空间导致特征语义混淆 |
| **技术来源** | Dual-Encoder 异构编码框架（arXiv 2505.24281, 2025）|
| **预期收益** | AUC ==+0.3~0.8pp==（尤其是连环派子集）|
| **实施周期** | 4-5 周 |

---

## 2. 背景与动机

### 2.1 连环派 vs 非连环派的根本差异

[[花小猪/PK策略知识库/wiki/concepts/连环派.md|连环派]]是指司机在完成当前订单途中接到下一个订单的分单模式，与非连环派在多个关键维度上存在本质差异：

| 维度 | 非连环派 | 连环派 |
|---|---|---|
| **接驾距离含义** | 司机当前位置 → 乘客上车点（确定性高） | 司机完成当前订单终点 → 下一乘客上车点（==不确定性大==，依赖 ETA 预估） |
| **司机状态** | 空闲，立即出发 | 正在执行订单，到达时间不确定 |
| **响应速度** | 实时响应 | 延迟响应（完成当前单后）|
| **取消行为** | 直接取消 | 可能因当前订单超时间接导致取消 |
| **样本占比** | ==60-70%== | ==30-40%== |

### 2.2 当前 PLE 的处理方式与局限

当前 [[花小猪/PK策略知识库/wiki/models/PLE多任务模型.md|PLE 模型]] 通过以下方式处理连环派差异：

| 机制 | 实现 | 局限 |
|---|---|---|
| `is_serial` 特征 | 0/1 标记是否连环派 | 仅在输入层区分，embedding 空间仍共享 |
| Expert 分组 | 5×3 组（连环派/非连环派/共享） | 软隔离，Gate 仍可混合路由 |
| 司机特征四场景隔离 | 连环派×半指派 四象限分别统计 | 仅特征层面隔离，模型表征层仍混合 |
| 保序回归校准 | 不同场景分别校准 | 后处理，未解决表征层问题 |

**核心问题**：

> 当 `接驾距离 = 3000m` 这个特征值出现时，在共享 embedding 空间中它被映射到**同一个向量**。但在非连环派场景下这意味着"司机需要开 3km 去接人"，在连环派场景下则意味着"预估司机完成当前单后再开 3km"——不确定性、对取消率的影响完全不同。

### 2.3 数据佐证

来自 [[花小猪/PK策略知识库/wiki/concepts/接驾距离.md]] 的分析：
- 接驾距离是 PK 模型中==权重最大的特征==（LR 中放大 2 倍）
- 连环派中接驾距离对 CR 的影响系数与非连环派存在显著差异
- 将接驾距离按连环派/非连环派分别统计后 AUC 有提升

## 3. 技术方案

### 3.1 整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        原始输入特征                               │
│  [订单] [司机] [乘客] [供需] [接驾距离] [is_serial] [半指派]       │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                    ┌──────────▼──────────┐
                    │   场景路由 (硬路由)   │
                    │  if is_serial == 1   │
                    └────┬────────────┬────┘
                         │            │
              ┌──────────▼──┐  ┌─────▼───────────┐
              │ Encoder_S   │  │  Encoder_N       │
              │ (连环派专属) │  │  (非连环派专属)   │
              │             │  │                  │
              │ 接驾距离     │  │ 接驾距离          │
              │  → ETA不确定 │  │  → 实际路线距离   │
              │ 司机状态     │  │ 司机状态          │
              │  → 执行中    │  │  → 空闲           │
              │ 取消模式     │  │ 取消模式          │
              │  → 间接取消  │  │  → 直接取消       │
              └──────┬──────┘  └────────┬─────────┘
                     │                  │
                     └────────┬─────────┘
                              │
                    ┌─────────▼─────────┐
                    │  Encoder_Shared   │
                    │  (共享通用编码器)  │
                    │                   │
                    │  城市、时段、      │
                    │  供需比、商家ID    │
                    └─────────┬─────────┘
                              │
                    ┌─────────▼─────────┐
                    │   Concat + Fusion │
                    │  [S/N] ⊕ [Shared] │
                    └─────────┬─────────┘
                              │
                    ┌─────────▼─────────┐
                    │  Prediction Tower │
                    │  → 完单概率        │
                    └───────────────────┘
```

### 3.2 三编码器设计

#### Encoder_Serial（连环派专属编码器）

| 属性 | 值 |
|---|---|
| **输入特征** | 接驾距离(ETA估算)、当前订单剩余时间、当前订单终点到新乘客距离、司机连环派历史完单率、连环派取消率 |
| **隐藏层** | [128, 64] |
| **输出维度** | 32 |
| **激活函数** | ReLU + LayerNorm |

**关键设计**：接驾距离在此编码器中结合 ETA 不确定性特征（如预估到达时间方差），形成"不确定距离"的专属表征。

#### Encoder_Normal（非连环派专属编码器）

| 属性 | 值 |
|---|---|
| **输入特征** | 接驾距离(实际)、司机空闲时长、直线距离vs路线距离比、非连环派历史完单率、非连环派取消率 |
| **隐藏层** | [128, 64] |
| **输出维度** | 32 |
| **激活函数** | ReLU + LayerNorm |

**关键设计**：接驾距离在此编码器中结合路线确定性特征，形成"确定距离"的专属表征。

#### Encoder_Shared（共享编码器）

| 属性 | 值 |
|---|---|
| **输入特征** | 城市ID、时段、供需比、商家ID、订单价格、乘客历史特征 |
| **隐藏层** | [256, 128] |
| **输出维度** | 64 |
| **激活函数** | ReLU + LayerNorm |

**设计原则**：只编码与场景无关的通用特征，不包含任何与接驾距离/连环派相关的特征。

### 3.3 特征分配矩阵

| 特征类别 | Encoder_S | Encoder_N | Encoder_Shared |
|---|---|---|---|
| 接驾距离 | ✅（ETA 语义） | ✅（实际语义） | ❌ |
| 是否连环派 | — (隐含) | — (隐含) | ❌ |
| 当前订单信息 | ✅ | ❌ | ❌ |
| 司机历史（连环派） | ✅ | ❌ | ❌ |
| 司机历史（非连环派） | ❌ | ✅ | ❌ |
| 司机历史（通用） | ❌ | ❌ | ✅ |
| 乘客特征 | ❌ | ❌ | ✅ |
| 供需特征 | ❌ | ❌ | ✅ |
| 城市/时段 | ❌ | ❌ | ✅ |
| 商家 ID | ❌ | ❌ | ✅ |

### 3.4 路由机制

与 MoE 的 Gate 软路由不同，Dual-Encoder 采用**硬路由**：

```python
class DualEncoderModel(nn.Module):
    def __init__(self):
        self.encoder_serial = EncoderSerial(...)    # 连环派
        self.encoder_normal = EncoderNormal(...)    # 非连环派
        self.encoder_shared = EncoderShared(...)    # 共享
        self.tower = PredictionTower(input_dim=32+64, output_dim=1)
    
    def forward(self, features):
        # 共享编码（所有样本）
        shared_repr = self.encoder_shared(features['shared'])
        
        # 硬路由：根据 is_serial 选择编码器
        is_serial = features['is_serial']  # [batch_size, 1]
        
        serial_repr = self.encoder_serial(features['serial'])    # 连环派特征
        normal_repr = self.encoder_normal(features['normal'])    # 非连环派特征
        
        # 场景表征 = 硬选择
        scene_repr = torch.where(
            is_serial.bool().unsqueeze(-1),
            serial_repr,   # is_serial=1 → 用连环派编码
            normal_repr    # is_serial=0 → 用非连环派编码
        )
        
        # 拼接 + 预测
        combined = torch.cat([scene_repr, shared_repr], dim=-1)  # [batch, 96]
        output = self.tower(combined)
        return output
```

### 3.5 与现有 PLE 的对比

| 维度 | 当前 PLE（软隔离） | Dual-Encoder（硬隔离） |
|---|---|---|
| **隔离粒度** | Expert 组级别 | 编码器级别 |
| **共享程度** | Gate 动态决定（可能混合） | 仅 Shared Encoder 共享 |
| **接驾距离处理** | 同一 Scalar2Vec 编码 | 两套独立编码 |
| **参数量** | ~1M（5×3 Expert） | ~200K（3 Encoder + Tower） |
| **跨场景迁移** | 有（通过 Gate） | 仅通过 Shared Encoder |
| **可解释性** | Gate 权重可分析 | 场景归因明确 |

## 4. 与 [[花小猪/PK策略知识库/wiki/concepts/半指派.md|半指派]]的联合建模

当前 PLE 使用连环派×半指派的四象限隔离特征。Dual-Encoder 可自然扩展为**四编码器**：

```
              连环派                     非连环派
         ┌──────────────┐          ┌──────────────┐
半指派    │ Encoder_S_H  │          │ Encoder_N_H  │
         │ (连环+半指派) │          │ (非连环+半指派)│
         ├──────────────┤          ├──────────────┤
非半指派  │ Encoder_S_F  │          │ Encoder_N_F  │
         │ (连环+全指派) │          │ (非连环+全指派)│
         └──────────────┘          └──────────────┘
```

> [!warning] 四编码器风险
> 四象限切分后每个编码器的训练数据会减少到总量的 15-30%。建议 Phase 1 先验证双编码器（连环派/非连环派），Phase 2 再考虑四编码器扩展。

## 5. 实验设计

### 5.1 离线实验矩阵

| 实验组 | 架构 | 隔离方式 | 目标 |
|---|---|---|---|
| **Baseline-PLE** | PLE 5×3 Expert | 软隔离（Gate） | 复现基线 |
| **Baseline-WD** | Wide&Deep | 无隔离 | 对比基线 |
| **Exp-A** | Dual-Encoder (2+1) | 硬隔离 | ==主实验== |
| **Exp-B** | Quad-Encoder (4+1) | 硬隔离（四象限） | 扩展实验 |
| **Exp-C** | Dual-Encoder + PLE | 硬隔离 + 多任务 | 融合实验 |
| **Ablation-1** | Dual 去掉 Shared | 纯硬隔离 | 验证 Shared 价值 |
| **Ablation-2** | 单 Encoder + is_serial | 软标记 | 验证硬隔离必要性 |

### 5.2 评估指标

| 指标 | 权重 | 分析维度 |
|---|---|---|
| **全局 AUC** | 核心 | 必须提升 |
| **连环派子集 AUC** | ==关键== | 预期提升最显著 |
| **非连环派子集 AUC** | 关键 | 应不降 |
| **接驾距离分段 AUC** | 辅助 | 距离远段预期提升 |
| **排序一致性（vs LR）** | 监控 | 保持可解释性 |

### 5.3 成功标准

| 条件 | 标准 |
|---|---|
| **必须满足** | 全局 AUC ≥ Baseline + 0.3pp |
| **理想目标** | 连环派子集 AUC ≥ Baseline + 0.5pp |
| **不可接受** | 非连环派子集 AUC 下降超过 0.2pp |

## 6. 实施计划

### 时间线

```
W1:   数据分析 — 连环派/非连环派特征分布差异量化
      特征分配矩阵确认
W2:   模型开发 — Dual-Encoder + Shared + Tower
      训练 pipeline 搭建
W3:   主实验 — Exp-A/B 跑通 + Baseline 对比
W4:   消融实验 + 融合实验(Exp-C)
W5:   结果分析 + 方案确认 + 上线决策
```

## 7. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 连环派样本不足（30-40%） | 中 | Encoder_S 训练不充分 | 数据增强 + Shared Encoder 兜底 |
| 硬隔离丧失跨场景迁移 | 中 | 非连环派经验无法帮助连环派 | Shared Encoder 保留通用知识 |
| 特征分配不当 | 中 | 关键信号被错误路由 | 消融实验验证每个特征的最优归属 |
| 推理分支增加 latency | 低 | 线上延迟 | 两个 Encoder 可并行计算 |
| 四编码器数据稀疏 | 高 | 最小象限不足 15% | Phase 1 先验证双编码器 |

## 8. 后续扩展

| 方向 | 描述 | 依赖 |
|---|---|---|
| 四编码器（连环派×半指派） | 四象限完全隔离 | 双编码器验证成功 |
| Dual-Encoder + MoE | 场景编码器内部再做商家 MoE | [[花小猪/PK策略知识库/wiki/proposals/01-sparse-moe-多商家差异化建模.md\|MoE 方案]]落地后 |
| 动态路由替代硬路由 | 学习连环派概率做软切分 | 数据分析显示"半连环派"场景存在时 |
| 接驾距离专属 embedding | 仅对接驾距离做异构编码，其他特征共享 | 消融实验发现仅距离贡献时 |
