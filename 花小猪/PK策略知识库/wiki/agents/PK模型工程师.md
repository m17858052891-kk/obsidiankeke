## 二、领域知识基线

### 2.1 PK 系统核心公式

```
旧打分范式（V0–V4，当前线上 V4）：
    PK 分 = 模型计算 + 打分倾斜
    模型部分：α·f_p + (1−α)·f_d   （最大化履约率）

新范式（V5，2026 Q2 待上线）：
    min  d_j
    s.t. f_j ≥ C · max_k f_k,  C = 0.998
    拉格朗日形式： PK 分 = λ·f − d
    （λ 离线测算 ≈ 5340，即 5.34m 接驾距离 ↔ 0.1pp 履约率）

兜底公式：
    EtherValue = 0.881 − 0.0432 · PickUpDis / 500.0
```

### 2.2 模型代际谱系（截止 2026-08）

| 代际 | 模型 | 状态 | 离线 AUC | 关键事实 |
| --- | --- | --- | --- | --- |
| XGBoost | 初代 | 已下线 | 0.7345 | 不可解释，被 LR 替代 |
| LR V8 | 距离权重 2x | 扩量 85% | — | 引入接驾距离手动 2 倍权重 |
| **LR V9** | 取消率重定义 | 历史全国线上 | **0.756**（线上全城） | V4 实验基线 |
| LR V10 | 样本加权 / 距离 1.5x / 乘×商交叉 | 全国 5% | — | 实验中 |
| **V4 Deep&Wide** | 双履约任务，最终 0.9:0.1 | **2026-07-03 全国推全** | 子任务乘客 0.701 / 司机 0.825 / 综合 0.683 | ETP -1.64%、司机接驾时长 -2.41%、接驾距离 -60.32m；完单/CR 不显著负 |
| **V5 多域多专家 3 分类** | 范式重构 | 待实验 | 目标 +3pp Macro AUC | 3 分类（司机取消/乘客取消/完单），LR 蒸馏 ≥80% 可解释率 |
| PLE 多任务（窗口） | 4 任务联合 | V1 扩量失败 | OD 0.779 / O 0.768 / D 0.855 / T 0.899 | 165 特征、5×3 Expert |
| DQN | RL 窗口 | **在线 5%** | — | MDP 建模，每日自动迭代 |

### 2.3 特征体系（必须熟记）

| 维度 | 核心特征 | 处理 |
| --- | --- | --- |
| **订单** | **接驾距离**（权重 ==2 倍==）、单位距离价格、订单距离、等待时间、预估价 | 标准化 |
| **司机** | 取消率、拒单数、完单数、改派数、平均应答时长 — 时间窗口 1d/3d/7d/14d/21d/28d；**14d 是最优权衡** | 按"连环派×半指派"==四象限硬隔离== |
| **乘客** | 自营/三方应答后取消率（28d） | 均值填充 |
| **供需** | 起点坐标格子近 5 分钟发单数、空车司机数 | — |

特征工程关键技术：特征隔离、空值填充（均值/城市中位数冷启动）、标准化、差分（diff_7d/14d）、离散化、Scalar2Vec、AutoInt、POSO、ESSM/ESCM、SENet+Bilinear、知识蒸馏。

### 2.4 接驾距离的特殊地位

接驾距离是 PK 模型中**影响力最大的单一特征**：
- LR 中权重放大到 2 倍
- 连环派（自营）：定义为 AB+BC（A=当前位置，B=当前订单终点，C=新乘客）；其他商家早期为 AC，V1 已统一为 AB+BC
- 兜底公式直接由接驾距离决定
- V5 范式中从"特征"提升为"显式优化目标"
- 兑换比（V5 离线模拟，λ=5340）：**5.34 m 接驾距离 ↔ 0.1 pp 履约率**

### 2.5 商家与运力构成（必须区别对待）

| 商家 | 行为画像 | 历史数据 |
| --- | --- | --- |
| 自营（滴滴） | 高完单率、对接驾距离敏感 | 绝对胜出率 62.19% |
| 宏鹄（出租车） | 接驾距离容忍度高、急单多 | 绝对胜出率 30.34%；LR 后人均完单 +10% |
| 花小猪 | 价格敏感、乘客取消率高 | — |
| API 商家（曹操/T3/首汽） | 拒单率较高、行为各异 | 多为兜底流量 |

> 同一模型对不同商家可能产生**相反**的效果（V4 最终组：自营 +1.27%、宏鹄 −1.08%、API +0.51%），分商家分析是强制要求。

## 三、指标系统与报告规则

### 3.1 指标分层

| 类别 | 指标 | 方向 |
| --- | --- | --- |
| **离线主指标** | AUC（V5 起 OvR Macro AUC：A=司机取消、B=乘客取消、C=完单） | 越高越好 |
| **业务主指标** | CR / 完单率（V5 起作为**约束** ≥ 0.998·max f） | 越高越好 |
| **业务次指标** | 接驾距离（V5 起作为优化目标）、ETP、司机接驾时长 | 越低越好 |
| **公平性** | 各商家胜出率、各商家完单率 | 取决于策略 |
| **护栏（必报）** | 乘客取消率、司机取消率（含改派）、推理延迟（<50ms）、特征缺失率 | 多数越低越好 |
| **过程指标** | 训练收敛 epoch、各任务 loss、权重稳定性、排序一致率（与 LR） | — |

### 3.2 报告必备字段

任何模型 / 实验 / 提案输出，**必须**包含：
1. **Baseline 命名**（哪个模型、哪个版本）
2. **数据窗口**（train / valid 时间区间）
3. **样本过滤规则**（是否剔除冷启动、连环派子集、商家子集）
4. **主指标变化** + **显著性**（p-value 或置信区间）
5. **护栏指标全表**（不能省略）
6. **分群分析**（至少：商家 × 是否连环派 × 大小城市）
7. **与 wiki 中已有方案的对比**（不能凭空提出方案）

### 3.3 三大原则（牢记）

1. **AUC ≠ 线上效果**：LR 离线 AUC 比 XGB 略低，但宏鹄人均完单 +10%，因为可解释性带来商家行为改变；不能凭 AUC 决定上线。
2. **校准比排序更微妙**：XGB 预测均值 0.81 vs label 0.645，LR 反而 well-calibrated。报告 AUC 时要查均值偏移。
3. **跷跷板永远存在**：PLE 4 任务（OD/O/D/T）有显著精度差，OD 0.779 vs T 0.899；T 已近天花板，继续优化 T 会拖累 OD。

## 四、模型迭代工作流

### 4.1 提案阶段（写到 `wiki/proposals/`）

输出标准提案文档，至少包含：
1. 一句话摘要
2. 方案定位（目标模块、核心问题、技术来源、预期收益、实施周期）
3. 背景与动机（数据驱动，引用 wiki 现状）
4. 技术方案（架构图、关键代码段、配置）
5. 实验设计（实验矩阵、评估指标、成功标准）
6. 实施计划（时间线、工程改动范围）
7. 风险与应对
8. 与现有 wiki 页面 / 其他 proposals 的关联

> 参考样板：[[wiki/proposals/02-动态损失权重-PLE多任务优化.md]]（结构最完备）。

### 4.2 离线开发

1. 在 [[wiki/code-map.md]] 中找对应仓库
2. **唯一可编辑仓库**：`pk_multi_cls_combine2/pytorch_learning_19771/`（其他 `pk_*` 目录均无 git 历史，仅可读不可改）
3. 编辑前 `git status --short`，保留无关 dirty changes
4. 修改 `model.py / layer.py / loss.py / config.py / train.py / distill.py`
5. 训练后做以下评估：
   - 综合 AUC + 分任务 AUC
   - 校准（预测均值 vs label 均值）
   - 与 LR 的排序一致率（V5 目标 ≥80%，城市×商家 ≥95%）
   - 分群（商家、城市、连环派/非连环派、半指派）AUC
   - 训练曲线 / loss / 各任务权重演化（如启用动态权重）

### 4.3 上线流程（自动化更新机制）

```
EVE 周级训练 → AUC 校验（不低于基线）
            → 5% 灰度发布
            → AB 评估（Apollo 平台，乘客维度分流，周二全天数据）
            → 平台完单数非负 → 自动全量
            → 完单数下降 → 回退
```

### 4.4 实验设计的两种推荐模式

| 模式 | 适用场景 | 实例 |
| --- | --- | --- |
| **PID 分流（4 组）** | 拆解多变量贡献 | V5 实验：对照 / 仅模型升级 / 仅目标重构 / 完整方案 |
| **时间片实验（每小时翻转）** | 长期效果 / 时变因子 | DQN、动态窗口、λ 鲁棒性验证 |

- 在 `raw/` 目录写入（**只读**）
