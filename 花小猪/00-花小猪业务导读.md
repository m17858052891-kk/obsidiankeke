# 花小猪业务导读

一单车能否完成，取决于一连串决定。乘客看到价格和车型后决定是否发单，商家决定向哪些司机播单，司机举手后平台决定再等多久、选谁接单。读一项策略时，可以先问两个问题。**它改变了谁的哪个决定？这个环节的改善，最后有没有带来更多完单？** [[花小猪/新人串讲：乘客侧链路与平台联合决策V3-V4（整理版）#2.3 发单后的平台交易主时序|查看发单后的完整时序]]

## 两个都叫 V4 的版本

**乘客侧平台联合决策 V4** 出现在发单前。它处理盒子价格、折扣和默勾选择。串讲记录截至 **2026-08-31** 的状态为 V3 主框架使用 V3.3 阈值，V4 处于建设验证阶段。[[花小猪/新人串讲：乘客侧链路与平台联合决策V3-V4（整理版）#10.1 总体状态|乘客侧版本对照]]

**聚合 PK 模型 V4** 出现在司机举手后，用于候选排序。更新于 **2026-08-06** 的 PK 综述记载，V4 Deep&Wide 于 **2026-07-03** 推全。「PK 模型版本」和下面实验里的「PK 窗口策略版本」分别对应候选打分与停止等待两个决定。[[花小猪/PK策略知识库/wiki/overview|聚合 PK 系统与模型演进]]

## 司机已经举手，还要不要再等？

延长窗口可能等到接驾更近、履约概率更高的司机，也会让乘客多等一会儿。先沿着**举手 → 窗口结束 → 平台选司机 → 应答 → 取消或完单**看机制，再带着同一组指标读下面四份原报告。[[花小猪/PK策略知识库/wiki/entities/PK窗口|PK 窗口如何工作]] · [[花小猪/PK策略知识库/wiki/sources/02-PK动态窗口策略|策略演进与原始资料]]
