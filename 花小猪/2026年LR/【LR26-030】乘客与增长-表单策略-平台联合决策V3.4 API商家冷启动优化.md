## 1 背景

API 商家进入特价盒子/幸运盒子的目标，是在平峰获取额外流量，同时不影响盒子外份额，与平台最大化完单的目标不一致。

历史冷启动方案对 2025 年 12 月后特价盒子/幸运盒子开城的 API 商家做长期保护：命中保护名单后，会忽略该商家对 CR 的贡献，具体来说，将 呼叫完单贡献置 0，将商家完单贡献置负无穷。在CR模型中，呼叫完单贡献用于计算累计呼叫完单率，商家完单贡献用于计算商家完单概率。该方案能够避免新进盒子初期 acc_CR 模型高估盒子内 CR，从而影响商家盒子外份额；但长期保护的问题在于，会对开城很久的商家持续压制其完单贡献，随时间推移越来越低估盒子的 CR，丧失决策最优性，带来默勾偏多、盒子份额降低、默勾接受度降低等问题，进一步影响平台完单。

本次优化将长期强保护调整为分阶段保护，希望在修复平台完单的同时，尽量减少商家负面体验。

预期的完单收益链路为：不再忽略开城超过 14 天的 API 商家完单贡献 -> 特价盒子 CR 预估值更高、更准 -> 最大化完单下最优决策偏向少勾，默勾更精准 -> 人均冒泡、人均呼叫、默勾接受度提升 > CR折损 -> 完单提升。

| 阶段 <br> | 保护策略 <br> | 策略含义 <br> |
| --- | --- | --- |
| 开城第 1-14 天 <br> | 强保护，`protect_weight = 0` <br> | 延续旧方案保护，优先保障新开城初期商家盒子外份额 <br> |
| 开城第 15-28 天 <br> | 弱保护，权重线性恢复 <br> | 逐步释放盒子内贡献，降低策略切换体感 <br> |
| 开城第 29 天起 <br> | 不保护，`protect_weight = 1` <br> | 恢复模型原始输出，释放盒子内完单增量 <br> |

## 2 目标 & 约束

- 策略目标

	- 大盘人均完单提升

	- 全年大盘人均完单+1.5%

- 约束指标项

	- 本策略约束：商家负向体验不明显，扩量过程中及全量后无商家进线。需要放量过程中持续观察

	- 表单策略约束：拉齐花业务补贴率，默勾接受度、幸运盒子完单份额不显著负

## 3 技术方案

### 3.1 冷启动保护状态表

策略使用 `kflower_strategy.plft_cold_start_product_list_v2` 作为冷启动保护状态表，覆盖以下两类商家品类：

- 尚未开城、未来开城后需要保护的 API 商家品类；

- 已开城、且开城时间仍在 28 天保护生命周期内的 API 商家品类。

关键字段包括：

| 字段 <br> | 含义 <br> |
| --- | --- |
| `dt` <br> | 日期分区 <br> |
| `city_id` <br> | 城市 id <br> |
| `product_id` <br> | 商家 id <br> |
| `product_name` <br> | 商家名称 <br> |
| `level_type` <br> | 品类，105-特价盒子，107-幸运盒子 <br> |
| `is_open` <br> | 当前分区视角下是否已开城，0-未开城，1-已开城 <br> |
| `open_city_date` <br> | API 商家在该城市、该盒子品类的新开城日期 <br> |
| `open_age_days` <br> | 开城第几天，`datediff(调度日, open_city_date) + 1` <br> |
| `strong_protect_days` <br> | 强保护天数，默认 14 <br> |
| `weak_protect_days` <br> | 弱保护最后一天，默认 28 <br> |
| `protect_stage` <br> | 保护阶段，`not_open` / `strong_protect` / `weak_protect` <br> |

分区保留逻辑为：未开城商家持续保留；已开城商家在 `1 <= open_age_days <= weak_protect_days` 时保留；`open_age_days > weak_protect_days` 后可从表中移除。

### 3.2 开城识别

从每日冒泡明细中识别首次开城日期。为了避免测试 case、脏数据或极低量试探冒泡被误识别为真实开城，只有当 `open_bubble_value > X` 时，才认为该商家在对应 `city_id + product_id + level_type` 下真实开城。

```text
valid_open_bubble = open_bubble_value > X
open_city_date = min(dt) where 商家在该 city_id + product_id + level_type 出现有效冒泡
open_age_days = datediff(dt, open_city_date) + 1
```

### 3.3 恢复权重

工程在线读取最新可用分区，并按当前请求日期 `biz_date` 计算线性恢复权重：

```text
if is_open == 0:
    protect_weight = 0
else:
    online_open_age_days = datediff(biz_date, open_city_date) + 1
    weak_days = weak_protect_days - strong_protect_days + 1
    if online_open_age_days > weak_protect_days:
        protect_weight = 1
    else if online_open_age_days <= strong_protect_days:
        protect_weight = 0
    else:
        protect_weight = (online_open_age_days - strong_protect_days) / weak_days
    protect_weight = min(max(protect_weight, 0), 1)
```

默认配置下，开城第 1-14 天强保护，第 15-28 天弱保护线性恢复，第 29 天及以后恢复为 1。权重为 1 时，后处理结果等价于不保护，举例如下：

假设商家 T 日开城：

| 日期 <br> | online_open_age_days <br> | protect_weight <br> |
| --- | --- | --- |
| T <br> | 1 <br> | 0 <br> |
| T+13 <br> | 14 <br> | 0 <br> |
| T+14 <br> | 15 <br> | 1/15 <br> |
| T+20 <br> | 21 <br> | 7/15 <br> |
| T+27 <br> | 28 <br> | 14/15 <br> |
| T+28 及以后 <br> | 29 <br> <br> | 1 <br> |

### 3.4 acc_CR 后处理

构造 acc_CR 模型特征保持不变；获取模型输出后，仅对命中保护状态表的 API 商家和对应盒子品类做后处理。未命中保护名单的商家品类、盒子外品类、非 API 商家均不做处理。

`cr_trace` 是呼叫完单贡献，可直接按权重缩放：

```text
cr_trace_after = cr_trace_raw * protect_weight
```

`cr_cp` 是 softmax 前的多分类 logit，不能使用 `cr_cp_raw * protect_weight`。本方案使用 logit 空间的概率折扣，该处理等价于将受保护盒子品类的 softmax 分子从 `exp(cr_cp_raw)` 调整为 `protect_weight * exp(cr_cp_raw)`，使盒子品类概率随保护权重逐步恢复。

```text
if protect_weight == 0:
    cr_cp_after = -inf
else:
    cr_cp_after = cr_cp_raw + ln(protect_weight)
```

### 4.5 商家维度保护期分布

分析实验期内，各城市×商家处于哪个保护阶段：

- **无保护期**：旧冷启动表中有、新冷启动表中没有（已退出保护窗口，开城 29 天+）

- **强保护期**：新冷启动表中 `protect_stage = 'strong_protect'`（开城 1-14 天）

- **弱保护期**：新冷启动表中 `protect_stage = 'weak_protect'`（开城 15-28 天）

| 品类 <br> | 旧方案保护阶段 <br> | 新方案保护阶段 <br> | 城市×商家数 <br> |
| --- | --- | --- | ---: |
| 特价盒子 <br> | 长期保护 <br> | 无保护期（29天+） <br> | 294 <br> |
| 特价盒子 <br> | 长期保护 <br> | 强保护期（1-14天） <br> | 81 <br> |
| 特价盒子 <br> | 长期保护 <br> | 弱保护期（15-28天） <br> | 11 <br> |
| 幸运盒子 <br> | 长期保护 <br> | 无保护期（29天+） <br> | 1 <br> |

旧方案对所有商家均为长期保护，新方案按开城时长分为三档，新旧差异体现在：

- **无保护期（294个特价盒子 + 1个幸运盒子，占76%）**：新旧差异最大。旧方案持续压制这批商家的 CR 贡献，新方案完全放开，是本次实验的主要影响群体。

- **弱保护期（11个特价盒子）**：新方案逐步退出保护，旧方案仍全量压制，差异处于过渡中。

- **强保护期（81个特价盒子）**：新旧方案均做保护处理，行为一致，无差异。

### 4.6 分阶段影响验证

新冷启动对平台规模和商家体验的影响因开城阶段不同而分化：

| 阶段 <br> | 平台规模 <br> | 商家体验 <br> |
| --- | --- | --- |
| 0-14 天 <br> | 无冷启动 &gt; 新冷启动 = 旧冷启动 <br> | 旧冷启动 = 新冷启动 &gt;&gt; 无冷启动 <br> |
| 15-28 天 <br> | 无冷启动 &gt; 新冷启动 &gt; 旧冷启动 <br> | 旧冷启动 &gt; 新冷启动 &gt; 无冷启动 <br> |
| 29 天后 <br> | 无冷启动 = 新冷启动 &gt; 旧冷启动 <br> | 旧冷启动 ≈ 新冷启动 ≈ 无冷启动 <br> |

实验期内特价盒子 **76%的城市×商家已开城超过 29 天**，实验组实际行为约等于无冷启动（76%）+ 新冷启动强/弱保护（24%）。

本次实验主要验证“29 天后”这一行的效果，点估计方向与预期一致，但平台规模收益未达到显著：

- **平台规模**（预期：新冷启动 > 旧冷启动）：人均完单不显著 **+0.25%**

- **商家体验**（预期：旧冷启动 ≈ 新冷启动）：API 完单份额 **-0.54pp**（显著），API 以特价盒子完单份额 **+0.35pp**（显著），默勾接受度点估计 **+1.22pp**（显著性不判断）。API 总份额轻微下降，符合退出保护后盒子外份额小幅回落的预期。
