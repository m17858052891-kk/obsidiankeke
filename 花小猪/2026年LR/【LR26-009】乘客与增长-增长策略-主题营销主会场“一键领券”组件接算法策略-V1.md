# 一 背景

- 营销主会场一键领券组件发券策略历史一直由人工配置，无法做到P维度的个性化发券，对于用户呼叫的牵引效果相对触顶

- 希望将一键领券组件接入算法，有效控制补贴效率，提升钱效。目标是在拉齐补贴率下，大盘人均呼叫相对提升0.1%～0.2%。

- 先前于01.26～02.08完成了一版[RCT实验](https://cooper.didichuxing.com/knowledge/2199610335356/2206463446448)，本次需要基于此次RCT实验产出P维度的“一键领券”组件算法发券策略

## 3.2 建模方式

- 目标：最大化呼叫量

- 样本：每条去重曝光一条样本

- 假设：折扣影响用户当天的呼叫量，折扣深度越深，呼叫量越高

	- 折扣是否影响领券率、膨胀率假设在直接预测呼叫量时已经cover

	- 由于当前一键领券组件只发两张券，所以我们认为该组件最大牵引能力为两单呼叫，即使用户当天呼叫数>2,我们仍认为其中只有两单是受到一键领券组件发券的牵引

		- 此假设对于高呼叫数的人群(呼叫数>2)会存在一定uplift预估折损，但在rct实验数据中，而当日呼叫数>2用户所对应的曝光样本仅占总训练样本的比例<10%

	- 只有在用户当天发生了领券行为后，其呼叫数才会被认为是受牵引的有效呼叫。如果用户当天多次曝光，且前n次曝光无领券行为，则这部分无领券的曝光的呼叫数label将被强制置0

- treatment: V1版本treatment选择首单券和次单券的膨胀前折扣(first_coupon_pre, second_coupon_pre),参考[rct实验](https://cooper.didichuxing.com/knowledge/2199610335356/2206463446448)配置中的信息，共配置了5种膨胀前首次单折扣组合\[98,95\],\[95,90\],\[90,85\],\[85,80\],\[80,75\]

- 规划求解：

	- 优化目标： $$\max\limits_Zf(Z)= \sum \limits_{ij} call_{ij}*z_{ij} \approx \sum \limits_{ij} (bcr1_{ij}+bcr2plus_{ij}*2)*z_{ij} =  \sum \limits_{ij} (marg1_{ij}-marg2_{ij}+marg2_{ij}*2)*z_{ij} = \sum \limits_{ij} (marg1_{ij}+marg2_{ij})*z_{ij}$$

	- 约束： 

		- $$\sum\limits_{ij}cost_{ij} *z_{ij} \le \sum\limits_{ij}gmv_{ij}*z_{ij} * subsidy\_rate$$

		- $$\sum\limits_{j}z_{ij} = 1$$

## 3.3 弹性模型构造

Model V0
[图表02 · 源文件](附件/LR26-009/图表02.json) · [在 Cooper 查看图形](https://cooper.didichuxing.com/knowledge/2199610335356/2207596402237)

- 建模难点：

	- 二分类输出的uplift model对于回归任务适配性差，模型直接预测呼叫数的具体数值的可行性需额外验证

	- 当前离线评价指标同样为对数值回归型的uplift任务做适配

- 解决办法

	- 输出改造：

		- $$p1\_0 ......p1\_j$$:模型在不同treatment组下预测的$$p(call=1)$$

		- $$p2\_0 ......p2\_j$$:模型在不同treatment组下预测的$$p(call>=2)$$

	- 输出设计动机：

		- 拆分呼叫数绝对数值为适配当前二分类输出的uplift model的输出形式

		- 模型输出形式可用当前离线评估指标进行评估

### 3.3.1 Model V0.5

[图表03 · 源文件](附件/LR26-009/图表03.json) · [在 Cooper 查看图形](https://cooper.didichuxing.com/knowledge/2199610335356/2207596402237)

- 输出说明：

	- $$p1\_0 ......p1\_j$$:模型在不同treatment组下预测的$$p(call>0)$$

	- $$p2\_0 ......p2\_j$$:模型在不同treatment组下预测的$$p(call>1 | call>0)$$

- loss设计：

	- 问题：除head1直接学习$$p(call>0)$$，可直接设置label为$$y_{1} = I(call\_cnt>0)$$之外；后续输出头学习的均为条件概率，仅设置$$y_{2} = I(call\_cnt>1)$$不足以监督条件概率

	- 解决方案：给head2之后的输出头，设置条件域mask，即对于任意label $$y = I(call\_cnt>n)$$，其对应的条件域mask为$$m = I(call\_cnt>n-1)$$

	- loss改造:

		- 设每条样本为$$(x_{i},t_{i},y_{i},m_{i}), i= 1, ......, N$$，treatment空间为$$\tau$$，head数为K

		- 模型对于每个treatment $$t \in \tau$$都输出一组概率$$\hat p_{i}(t) = (\hat p_{i1}(t),\hat p_{i2}(t),......\hat p_{iK}(t))$$

		- 定义factual 取值 $$\hat p^{\mathrm{fact}}_{ik} := \hat p_{ik}(t_i)$$

		- factual loss定义为$$L_{\mathrm{factual}}^{\mathrm{masked}} = \frac{ \sum_{i=1}^{N}\sum_{k=1}^{K} m_{ik}\,\ell_{\mathrm{bce}}\!\left(\hat p^{\mathrm{fact}}_{ik},\, y_{ik}\right) }{ \sum_{i=1}^{N}\sum_{k=1}^{K} m_{ik} }$$

		- 总loss为：$$L^{\mathrm{masked}} = \lambda_{\mathrm{factual}}\,L_{\mathrm{factual}}^{\mathrm{masked}} + \lambda_{\mathrm{imb}}\,L_{\mathrm{wass}}$$

- 对比V0版模型(模型两个输出头分别预测p(call =1), p(call >= 2))的优势：

	- V0版本在输出无显示约束的情况下，可能面临学习到的两个head输出之和>1，即模型预测$$\hat p(call =1 ｜x)+\hat p(call >= 2 | x) > 1$$，不满足p(call =1 | x)+p(call >= 2 | x)<=1的约束

	- V0.5由于从head2往后，预测都为条件概率，因此模型输出层面不用担心与上述约束的冲突

	- 基于V0.5的条件概率输出，可通过以下公式计算实际呼叫数的预测概率：

		- $$p(call = k | x) = \begin{cases} 1-p_{1} & \text{ if } k=0\\ (1-p_{k}) {\textstyle \prod_{j=1}^{k-1}p_{j}}   & \text{ if } 0< k < K\\ {\textstyle \prod_{j=1}^{K}}p_{j} & \text{ if } k = K \end{cases}$$

		- 对于呼叫数预测概率求和可得：$$\sum_{k=0}^{K}p(call = k | x) = (1-p_{1}) + \sum_{k=1}^{K-1}({\textstyle \prod_{j=0}^{k-1}}p_{j} - {\textstyle \prod_{j=0}^{k}}p_{j}) + {\textstyle \prod_{j=0}^{K}}p_{j} = 1$$，即最终所有呼叫数预测值的概率之和一定为1

- 存在问题：

	- 由于mask的存在，对于人均呼叫数较低的现状，head2及之后的输出头经过mask后所剩的样本数量相比于head1明显减少，模型学习难度增加。

	- 输出层来自单独的预测头，无结构化输出，在连乘计算marginal probability的时候，容易放大误差

### 3.3.2 Model V1

[图表04 · 源文件](附件/LR26-009/图表04.json) · [在 Cooper 查看图形](https://cooper.didichuxing.com/knowledge/2199610335356/2207596402237)

- 输出说明：

	- $$marg1\_0 ...... marg1\_j = p1\_0 ......p1\_j$$:模型在不同treatment组下预测的$$p(call>0)$$

	- $$marg2\_0 = p1\_0*p2\_0, ...... marg2\_j = p1\_j*p2\_j$$:模型在不同treatment组下预测的$$p(call>1)$$

- loss设计：

	- 由于当前模型输出已经是marginal probability，因此不再需要mask，label可正常设置为$$y_{1} = I(call\_cnt>0)$$，$$y_{2} = I(call\_cnt>1)$$

	- V0.5中的输出$$\hat p^{\mathrm{fact}}_{ik} := \hat p_{ik}(t_i)$$当前只作为中间层

	- 新的输出由$$\hat p^{\mathrm{fact}}_{ik}$$通过连乘得到：$$\hat m_{i1} = \hat p^{\mathrm{fact}}_{i1},\hat m_{i2} = \hat p^{\mathrm{fact}}_{i1}\hat p^{\mathrm{fact}}_{i2},......$$

	- 则当前的marginal loss直接使用原本的BCE loss为$$L_{\mathrm{factual}}^{\mathrm{marginal}} = \frac{1}{N}\sum_{i=1}^{N}\sum_{k=1}^{K} \ell_{\mathrm{bce}}(\hat m_{ik}, y_{ik})$$

	- 总loss仍为$$L^{\mathrm{marginal}} = \lambda_{\mathrm{factual}}\,L_{\mathrm{factual}}^{\mathrm{marginal}} + \lambda_{\mathrm{imb}}\,L_{\mathrm{wass}}$$

- 对比V0.5的优化：

	- V0.5在模型输出条件概率后，仍然需要通过条件概率连乘得到marginal probability后，再去计算每个呼叫数对应的概率

	- V1相当于将连乘得到marginal probability的操作同样嵌入到了模型结构中，此改造有以下优点：

		- 每个输出头都可以通过全量样本进行训练，不会存在部分输出头由于mask后样本量过少学习困难的问题

		- 连乘引入结构化的输出，避免了独立输出时的误差放大

## 4.2 实验结论

### 4.2.1 对比空白组

![](附件/LR26-009/039.png)

- 结论：

	- 三个策略组拉齐C补率下对比空白组，**算法组人均呼叫涨幅最大**(显著**+2.29%**)，**ROI最高**(GMV ROI = 2.5， 呼叫ROI = 0.17)

	- 算法组vs人工旧策略(人工不膨胀)，GMV ROI相对**+20.51%**(2.07->2.5)，呼叫ROI相对**+11.75%**(0.15->0.17)

	- 算法组vs人工新策略(人工膨胀)，GMV ROI相对**+9.30%**(2.28->2.5)，呼叫ROI相对**+7.21%**(0.16->0.17)

- 分组结果：

	- 无领券组：GMV ROI 8.70，呼叫 ROI 0.52；呼叫显著 + 0.53%，完单显著 + 0.55%，GMV显著 +0.74%

	- 旧策略组：GMV ROI 2.07，呼叫 ROI 0.15；呼叫显著 + 1.99%，完单显著 + 2.04%，GMV显著 +2.25%

	- 领券膨胀组：GMV ROI 2.28，呼叫 ROI 0.16；呼叫显著 + 2.09%，完单显著 + 2.18%，GMV显著 +2.50%

	- 算法组：GMV ROI 2.50，呼叫 ROI 0.17；呼叫显著 + 2.29%，完单显著 + 2.36%，GMV显著 +2.80%

- 折算A框城市日均大盘呼单增量：

	- 无领券组呼单增量 **1.9w**

	- 旧策略组呼单增量 **7.2w**

	- 领券膨胀组呼单增量 **7.6w**

	- 算法组呼单增量 **8.3w**

ps. A框城市圈选：

	- 圈选逻辑：呼单top10+呼单 ROI >4 +核心城市+行业增长城市+（战略收缩+其他城市）∩（缺C、BC平衡）
