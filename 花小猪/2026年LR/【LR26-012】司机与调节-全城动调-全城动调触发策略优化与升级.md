## 一、背景

全城动调的业务目标是不可提前预知的实时差供需场景中，通过司机乘客同幅涨价，一方面抑制过剩需求，另一方面牵引司机出车，以此提升成交率 CR。

现有触发逻辑为根据 **XGB模型预测未来15\~75分钟的预估CR** 与 **低CR阈值** 的大小进行判断，当**XGB预测CR < 低CR阈值，则触发【全城动调】，反之则不触发**。

但当前模型的覆盖场景仍存在局限性，未覆盖场景主要分为2种：

（1）特殊场景覆盖不足：模型训练数据偏常态、且模型更新周期太长、无法及时适配随淡旺季或节假日供需情况的变化，导致预测偏差较大。

（2）模型异常无兜底：完全依赖模型预测值，无降级机制，模型错误时策略失效，无法及时止损。

因此，针对当前存在的这两种场景，我们希望对当前触发策略进行优化，同时探索当模型不可用时适合的降级策略。

## 二、策略方案

### 2.1 正常触发策略优化

针对 当前XGB模型的同周期特征存在Bug、以及 业务方在节假日或平时对于高低CR Badcase率的侧重点不同 这2个问题，我们提出以下方案：

#### 2.1.1 现存问题修复

（1）新增天气特征

当前模型未纳入降雨/降雪特征，导致极端天气下预测较差。本次新模型增加以下特征：

| 特征名 <br> | 含义 <br> |
| --- | --- |
| `cy_hourly_precipitation_1` <br> | 未来1小时降水量 <br> |

（2）离线特征修复（假设当日为第T天）

| 问题 <br> | 修复方案 <br> |
| --- | --- |
| DOD/WOW特征未剔除节假日影响 <br> | 若T-1为节假日则往前推1天，若T-7为节假日则往前推7天，以此类推，直至为非节假日 <br> |
| 缺失22:45\~23:59时间段特征 <br> | 为保证线上XGB一天24h都可以正常获取特征，需补全22:45\~23:59时间的相关特征。 <br> |

特殊说明（关于22:45~23:59时间段同周期特征）
【表现】由于 22:45 之后同周期特征（如 DOD 特征）的统计值，依赖天级别产出的上游表，无法获取当日实时数据，导致统计窗口缺少当日 00:00 之后的数据，时间越接近 23:59，同周期特征的统计偏差会逐步增大。且 XGB 新模型 Top4 特征均为同周期特征，模型对此类特征较敏感，因此出现预测值偏低。

【举例】当日23:45输入的昨日同周期特征dod_finish_15_30，表示昨天23:45之后未来15min\~未来45min的完单数，在统计时理论上应该是今天00:00\~00:30的完单数，但是这个数据在当日我们是无法获取到的，因为上游表当日产出的数据是昨天的分区，所以导致当日23:45时刻dod_finish_15_30 = 0，对于越靠近23:59，统计值越不准确。但是对于22:45之前这类特征统计值准确，也刚好在动调触发和生效时间内。

【建议】目前链路来看，不建议22:45之后继续触发动调，后续如有延长动调触发时间的需求，可以尝试用近似值代替的方案进行预测，评估MAE是否在可接受范围内。

（3）同周期特征读取分区修正（假设当日为第T天）

| 项目 <br> | 当前（错误） <br> | 修正后 <br> |
| --- | --- | --- |
| 第T天的DOD特征 <br> | 离线产出T-1分区全部特征数据 ，线上读取T-1分区 → 实际取到第T-2天数据 <br> | 离线产出T-1分区全部特征数据、以及T分区DOD特征数据，线上读取第T分区 → 取到第T-1天数据 <br> |
| 第T天的WOW特征 <br> | 离线产出T-1分区全部特征数据 ，线上读取T-1分区 → 实际取到第T-8天数据 <br> | 离线产出T-1分区全部特征数据、以及T分区WOW特征数据，线上读取第T分区 → 取到第T-7天数据 <br> |

#### 2.1.2 偏置调整

业务方在节假日或平时对于高低CR Badcase率的侧重点不同，希望能灵活调整不同时期的触发情况。因此，我们考虑在模型预测值上引入偏置 normal_trigger_bias 调整，来调节低 CR 漏触发与高 CR 误触发之间的平衡。正常触发策略输入指标 predict_cr_add_bias = predict_cr + normal_trigger_bias，其中normal_trigger_bias为正常触发策略偏置项，优化后的正常触发策略如下：

```PlainText
                    ┌─────────────────────────────┐
                    │  输入：predict_cr_add_bias   │
                    │       low_cr_thres          │
                    └────────────┬────────────────┘
                                 │
                ┌────────────────▼──────────────────────┐
                │ predict_cr_add_bias <= low_cr_thres?  │
                └──────────┬──────────┬─────────────────┘
                      Yes  │          │ No
                           │          │
                ┌──────────▼──┐  ┌────▼───────┐
                │  触发 ✓      │  │ 不触发 ✗    │
                └─────────────┘  └────────────┘
```

### 2.2 降级策略

在无法可信地使用模型预测值时（如模型无法输出预测值、或者模型因特征异常等输出预测值异常等），根据 降级触发指标 反映当前实时供需状态，代替模型预测值判断是否触发动调。该策略可快速响应异常，但由于缺少未来预测能力，低 CR Badcase率会显著高于模型逻辑，因此仅作为异常兜底使用，不作为主逻辑长期运行。降级策略流程图如下：

```PlainText
                    ┌─────────────────────────────┐
                    │  输入：降级触发指标            │
                    │       low_cr_thres          │
                    └────────────┬────────────────┘
                                 │
                ┌────────────────▼──────────────────────┐
                │     降级触发指标 <= low_cr_thres?       │
                └──────────┬──────────┬─────────────────┘
                      Yes  │          │ No
                           │          │

                │  触发 ✓      │  │ 不触发 ✗    │

```

【小结】

（1）旧模型：由于训练数据久远，与评估数据存在分布偏移，导致预测 CR 整体系统性偏低，并不代表其预测能力更强。这种系统性低估一方面导致大量高 CR 场景被误触发动调，另一方面也使少数低 CR 场景的预测值恰好低于触发阈值，从而被召回。

（2）新模型：整体预测准确率优于旧模型，表现为 MAE 更低、预测曲线更贴近真实 CR 曲线，且高 CR Badcase 率明显降低。但新模型在少数低 CR 时段仍存在漏识别问题，且恰好集中在清明节期间，冒泡量级较日常更大，因此少数低CR漏触发case对整体低CR Badcase率产生了较大影响。（另外，对于如大同市、太原市、临沂市等城市，低CR冒泡占比本身很少但未被识别，就会显著拉高单城低CR Badcase率）

**（**3）引入偏置调整：从多个城市的预测曲线来看，新旧模型对 CR 走势的判断基本一致，但二者之间存在相对稳定的预测偏差。这也启发我们可以考虑在模型预测值上引入 bias 偏置调整，来调节低 CR 漏触发与高 CR 误触发之间的平衡。

#### 3.2.3 最终结果

因此，我们基于模型预测 predict_cr引入偏置项normal_trigger_bias，最终输入触发逻辑的 predict_cr_add_bias = predict_cr + normal_trigger_bias。
