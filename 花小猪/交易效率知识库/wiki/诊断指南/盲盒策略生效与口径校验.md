# 盲盒策略生效与口径校验

## 三层校验

1. **离线模型一致性**：用订单 ID 连接模型日志与 PK 日志，逐项比较特征、预测值和样本筛选口径。
2. **线上调用链**：验证距离过滤、模型调用、取消率阈值、盲盒展示与发券是否逐层生效，分别统计漏调和错出比例。
3. **业务结果**：只有前两层稳定后，才解释取消率、CR、完单和钱效；否则实验差异混入工程故障。

## 历史故障模式

- 时间参数错误使 `order_waiting` 特征异常，实验前已修复。
- 模型耗时约 170ms，高峰期下游超时；一度只在内蒙古机房切换 GPU，而工程仍调用华新园 CPU 实例。华新园部署新 GPU 模型后修复。
- “应出未出”曾约占 8%，开实验后降至万分之四。
- 连环派盲盒位置最初混用了地图与 API 的路面距离口径，切换 DOS 口径后验证无问题。

## 上线检查表

- 特征时间与单位是否一致；特殊缺失值是否统一。
- 分机房监控调用量、超时率和模型版本，不能只看总成功率。
- 抽样复算“距离大于 1km才调用模型”“预测取消率高于 0.27 全部出盲盒”等规则。
- 将策略判断、端上展示、发券和完单分别落表，避免用单一漏斗倒推生效。
- 变更距离口径后做订单级 diff，并保留无法对齐的 case。
