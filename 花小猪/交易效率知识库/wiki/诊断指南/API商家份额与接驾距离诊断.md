# API商家份额与接驾距离诊断

## 诊断问题

当接驾距离约束或 PK 调权后 API 商家份额变化，先判断是总效率变化、商家间份额迁移，还是不同举手距离结构被重新筛选。历史材料按实验/对照拆了 API 与非 API 的应答、完单和 GMV 份额，并补充各 API 的 only 举手接驾距离分布。

## 最小诊断表

| 层次 | 必看指标 | 解释边界 |
| --- | --- | --- |
| 平台 | 总应答、总完单、CR、GMV | 判断是否有净增量，不能由份额替代 |
| 体系 | API/非 API 的应答、完单、GMV 份额 | 识别结构迁移，三种份额需同向复核 |
| 商家 | 商家内份额变化与样本量 | 小样本波动不直接归因 |
| 距离 | only 举手的接驾距离分桶、远距离占比 | 与商家供给半径和城市基线联看 |
| 体验 | 接驾时长、司乘取消、改派 | 防止份额收益由体验恶化换取 |

实验/对照流量不对称时必须用份额或标准化指标，不能比较原始量。商家份额的分母要分别固定为应答、完单或 GMV 总量，三者不可混用；接驾距离需明确是举手时、胜出时还是最终应答司机口径。

## 历史分析信号

2025 年一周历史切片中，不同 API 商家的应答、完单和 GMV 份额变化方向不完全一致，且部分商家的远距离 only 举手占比差异较大。这只说明存在异质性和诊断价值；来源没有商家级置信区间，不能将点值变化判为策略效果或当前状态。

## 证据与隐私边界

复盘必须补齐样本量、SRM、置信区间/显著性、多重比较、配置版本、实验发布时间与回滚状态。原始 SQL、表名、商家标识、城市清单和细粒度点值属于敏感明细，不在 Wiki 复刻；材料中的“当前”仅指文档切片时点，不代表现网。
