# PEPNet与序列履约模型

> 模型家族与离线实验知识卡，不代表当前生产模型。来源更新日期未知；样本期与文档层级线索分别记录。

## 任务与数据契约

BRD联合预测司机履约、乘客履约、订单完单。序列实验文内定义OD=司乘履约、O=司机履约、D=乘客履约；其他材料的字母命名需单独核对。训练标签SQL、删失、负样本和服务映射待补。

序列实验输入343维：143数值、200序列；乘客与司机各10单×10特征，包含金额、取消、到达/接驾和连环派等历史信息。不能仅凭“订单dt前”认定无未来泄露，需检查事件级可用时间。

## 结构

- 数值归一化后Scalar2Vec；司乘序列reshape为10×10，位置Self-Attention编码。
- 连环派binary驱动EPNet，对连续/序列表征做逐维调权。
- 类别embedding驱动OD/O/D三路PPNet，每层个性化门控。
- 每任务双域输出头，总六塔，按binary取连环派或非连环派输出。
- 此结构来自具体序列文档，不将其等同于全部PEPNet实现或当前线上服务。

## B018：2026 PEPNet 与特征工程补充

- 数据构造页明确司机取前 1—7 天最近 20 单、乘客取前 1—180 天最近 20 单，不足以 `-9999` 补齐；包含 GMV、各类取消、应答/接驾、起终点和连环派字段。该页主要是 SQL/构造记录，不单独证明收益。
- PEPNet 消融在 2026-03 数据上反复比较 General、EP、PP 与六塔职责。实际 scale 复跑中，删除 PP 的平均 AUC 下降约 0.52pp、同时删除 EP/PP 下降约 0.59pp；但删除 EP 近似持平，说明 PP 贡献更稳定，不能笼统归因于所有门控。
- 167 字段阶段把 24 个 driver 特征放入 PP prior；门控诊断后以较低学习率和恒等正则为主线。多数 Gate 稳定化尝试只有小幅或不一致变化，不应选择性报告最佳单次结果。
- 特征交叉记录把历史统计候选从 1001 维筛到 416 维，最终选前 100 维；在各自最终 PLE/PEP 上，三任务平均 AUC 分别再提高约 0.50pp/0.24pp。OneTrans、HyFormer和多任务结构的结果仍是离线比较。
- LR26 汇总称最终单轮 PLE、多轮 PLE、多轮 PEP 相对其线上模型离线基线平均提高 4.33pp、4.62pp、4.85pp；放量章节明确“目前为离线实验”，还需工程特征、推理耗时和线上替换验证。

## B021：多任务基线、特征交叉与验证修复

- 2026-03-01～23 训练、03-24～30 测试的多任务汇总把 PLE 作为基线，线上结构复刻的 OD/O/D AUC 为 0.7269/0.7640/0.7199；后续 Torch、Gate 与 PEPNet 表格均是同批离线比较，不能写成线上替换结果。
- PEPNet 的 Gate 恒等正则是该批最稳定的训练方案，形成 `PEP01` 基线（OD/O/D 0.7456/0.7404/0.8237）。扩大 General/EP 的重复输入没有一致收益，说明 General、场景调制与个性化调制的职责边界需要保留。
- 显式交叉中，低秩 DCNv2 只提高 O，三层与全参数版本反而下降；SENet+Bilinear F1/F2 在三任务上均略高于同表基线，F1 为 0.7458/0.7414/0.8245；WuKong 只在 O、D 小幅提高。以上差异缺少重复实验与置信区间，不据此认定生产方案。
- 两份“特征交叉分享”正文基本重复，仅标题层级和临时图片签名不同；其 LR/FM/DCN/FiBiNET/WuKong 内容作为方法背景合并，不重复创建模型卡，也不把通用论文结论当业务实验。
- “验证 AUC 高于训练 AUC”排查发现验证循环只计算首个 batch，且训练两周、验证六天缺周四，周期不齐。修复为完整验证并对齐周期后，10 个 epoch 的 OD/O/D 均为训练 AUC 高于验证 AUC；这是一项评估管线修复，不是模型收益。

该批通用分享和排查页共有多张外链图片、结构图与运行日志未逐图解析；图片签名短期失效，关键结论仍需以可复现代码和固定报表复核。

## B030：序列 token 契约与 PLE 离线迭代

新特征处理页将每条历史订单编码为 20 维 token：5 个连续特征按训练集分位数分桶，5 个二值特征显式区分缺失/0/1，起终点则用两级 GeoHash embedding 融合。每类向量求和后除以 `sqrt(11)` 并 LayerNorm，司机、乘客各保留 20 笔，形成 `[B,20,20]` 输入 OneTrans。`answer_gap` 只对有效历史单计算，取消或无效时间进入缺失桶。

PLE 序列迭代表中，引入序列前 OD/O/D AUC 为 0.7445/0.7417/0.8203；引入序列、按有效样本数修改 loss 并训练 3 epoch、再修改 POSO 分桶后，表内最后一行为 0.7538/0.7527/0.8271。这是单页的离线递进记录，未提供多 seed、显著性、推理成本、线上 AB 或生产版本，不能外推为上线收益。

特征页的空间哈希、分桶边界与序列长度是具体实现契约，仍需与线上主键、观测时点、缺失值及版本化 schema 对齐。

## B019：特征契约、OneTrans 严格对照与设计边界

- PEPNet 取数页补齐了 PK 轮次、商家、场景、供需、司乘历史等字段到 General/EP/PP 路径的映射；新增司机先验进入 PP Gate 的意图是强化个性化表达。该页是数据契约，不证明模型增益或线上生效。
- OneTrans 最终同训练轮数对照中，1-block/2-block、9 epoch 的 Mean AUC 为 0.7811/0.7814，相对各自 baseline 为 +0.65pp/+0.68pp；叠加 FiBiNET 后为 0.7803，反而比 1-block 低 0.08pp，现有证据不支持继续增加该复杂度。
- “司乘履约-多任务学习”材料主要是 MMoE、PLE、POSO、PEPNet 论文与结构解读，缺少本业务同口径实验结果，因此只用于解释架构动机，不作为收益证据。

## B033：Luban 基线与序列论文候选

Luban 重训页给出一个尚未充分训练的 PEPNet baseline：epoch 3、batch size 16384、学习率 0.0001，并以验证集 O AUC 选模。表内 PEPNet 的 OD/D/O AUC 为 0.7461/0.8243/0.7413；同页 SENet-bilinear+context 为 0.7467/0.8256/0.7425。由于 PEPNet 尚未训练完全、Luban 与 EVE 环境不同，且缺少多 seed、训练预算和显著性，这只能作为新环境基线，不能认定 SENet 全面优于 PEPNet，更不能外推为线上收益。

论文分享页整理了三类尚未经过本业务验证的结构候选：

- OneTrans 将历史序列和非序列特征统一 token 化，并讨论按语义拆分参数、因果注意力和金字塔裁剪；
- HyFormer 用非序列特征生成 query，逐层读取序列 K/V 后再与非序列 token 交叉；
- TSAPE 用事件间隔序列、LSTM/CNN 和通道注意力补充时间节奏编码。

这些内容来自论文解读与图片化消融，不是本业务模型实验。原文链接指向 2025/2026 论文，但未提供复现代码版本、业务样本、推理成本或线上 AB；大量结构图和消融图未解析。与本页既有 OneTrans/HyFormer 离线记录关联时，只能作为设计动机，不能把论文结果移植为业务效果。

## B036：AutoFE、PLENet 与显式特征交叉

AutoFE 探索让大模型组合司机、乘客、POI、时段和距离段的历史统计，先生成 1001 维候选，再按缺失率和 XGB Gain 缩到 416 维。文档继续比较 Gain 前 100/200/300，并用小样本 LR 前向筛选；最终把 33 维和 100 维候选分别放入 PLE 验证。100 维版本的 O/D/OD AUC 由 0.7536/0.8263/0.7544 提到 0.7586/0.8315/0.7593，但没有多 seed、置信区间、线上特征成本或 AB，因此只是离线候选，不代表生产采用。

PLENet 以 2026-03-01～23 训练、03-24～30 验证，围绕连环派/非连环派 domain 和 O/D/OD 三任务做 Gate/Expert 消融。表内较好的 Gate-BN-v3 为 0.7417/0.8203/0.7445；删除 Gate、硬约束共享专家和防坍塌 loss 的收益并不一致，说明“缓解 Gate 坍塌”不自动等价于 AUC 提高。该页没有线上替换、服务延迟或校准结果。

特征交叉复现比较 DCNv2、SENet、WuKong 与 PLEv3-BN。不同 f0/f1 表中只有 DCNv2 略高，来源总结为相对强 PLE 基线的增益不足 1pp；同时部分初版表格存在空白。不能从单次最高值认定某交叉结构为最终方案，也不能跨不同特征布局直接排名。

AutoFE 原文含 2 个未解析流程图/图片；PLENet 与交叉实验缺少重复实验、参数量、推理时延和显著性。生成式特征的观测时点、泄露检查与线上 schema 版本仍待补齐。

## B037：多任务改进、OneTrans 复现与表示解耦

### 结构消融与离线结果

早期 PLE 改进记录分别消融任务塔、Gate 和特征交叉。删除任务塔明显受损，而 Gate 结构替换影响较小，说明任务私有转换层比单次 Gate 形式更关键。多 epoch 特征交叉表中，DCNv2 的 OD 最高达 0.80023，但三任务不均衡；SENet epoch 2 为 0.7995/0.7912/0.8670；对比+对抗版为 0.802212/0.790227/0.866211。列顺序依原文 OD/O/D 记录，不与其他批次横向排名。

来源总结认为 SENet 更均衡，对比+对抗对 OD/O 有改善但 D 可能受损。CAN 和 attention 方案曾出现 NaN loss，属失败记录，不应从候选表中删除。所有数值都是离线单次/少量轮次结果，缺少重复、显著性和线上证据。

### OneTrans：论文动机与业务复现分开

OneTrans 论文将序列/非序列特征 token 化，引入混合参数化、金字塔压缩和 KV cache。原文引用的 5.68% GMV 是论文外部结果，不是本业务证据。

业务复现表仅保留离线快照：PEPNet epoch 0 约为 0.7017/0.6977/0.8085，`driverseq+pep+onetrans` epoch 0 约为 0.7183/0.6982/0.8086；`pepnet+onetrans` 没有结果。PLENet 早期轮次的 OD 约 0.7194、O 约 0.7080，D 在后续轮次约 0.7904；`plennet+onetrans` 因资源被抢占没有完成。`ple+driverpass-seq+8layertower` epoch 0 约为 0.7189/0.7043/0.8020。这些实验训练轮数不等、存在缺失候选，不构成公平的最终对照，也没有推理成本或线上 AB。

### 对比/对抗 PLE：设计而非已复现结论

对比支路对同一样本做两次 dropout 得到两个 view，经 projection head 使用 temperature=0.1 的 InfoNCE，仅用于训练。对抗支路在共享交叉表示上加梯度反转层（GRL）和二分辨别器，用来将共享表示与任务私有表示解耦。

该文档提供的是方案和伪代码，未提供完整复现结果；不将其与另一实验页的“对比+GAN”行自动视为同一实现。“敏感/场景标签”的定义、使用目的和合规边界仍需治理评审。

本批来源中的图片、附件、训练曲线与资源产物未完整解析；特征观测时点与泄露检查、参数量、时延、显存和服务成本也未报告。

## B058：序列建模目标与 OneTrans 汇总

独立序列建模汇总把司机、乘客历史序列同时送入 OneTrans，并比较 PEPNet 与 PLE 聚合。其目标 CR +0.2pp、乘客取消率 -0.5pp、2.5km 以上接驾距离占比 -5% 是规划目标，不是实验结论。

同页 9 epoch 表中，`pep-seq` 的 OD/O/D AUC 为 0.7421/0.7339/0.8036，`pep-seq-onetrans` 为 0.7503/0.7613/0.8697；司机单序列和乘客单序列版本均低于通用双序列版。另一组 batch size 1024 的表格中，序列与非序列版本各有任务增减，不能把单任务最高值概括为全面提升。该页总结的“pp”仍需按原始数值重算，并缺少多 seed、显著性、推理成本与线上 AB。

材料计划继续排查 O 任务、做特征消融并尝试 HyFormer；这些是 TODO，不代表已经执行或上线。与特征交叉分享重复的通用结构只作为方法背景，不重复计作新模型收益。

## B062：Embedding 与 OneTrans 接入设计

一份 embedding 设计页将司机、乘客历史序列分别编码为 `[B,10,10]`，做通道归一化并投影到统一维度；非序列特征经 Scalar2Vec 后与两类序列 token 拼接，再进入 OneTrans。文档中的 MultiOneTransBlock 使用可学习位置编码、因果注意力、残差和前馈层，堆叠后取末尾 10 个 token 与 EPNet/PPNet 融合。这是实现设计，不等于当前 PEPNet 主线已经采用。

材料提出去掉乘客序列、验证 OneTrans 交叉，以及移除 PLE/PEP 后直接接三任务头等消融，但正文未给可读结果、样本窗、随机重复、显著性、推理时延、服务版本或线上实验。多张结构图和结果图未解析，外置编辑器链接也不能作为可复现产物；因此只保留候选合同，不写成离线增益或上线事实。

## B068：Batch size 离线敏感性

Batch size 记录明确否定了第一轮曲线：训练与验证 batch size 同时变化，验证集不完整且只验证一个 step，因此该轮“结论不可信”，不能用于选参。后续表在 PEPNet+Positional Self-Attention 下比较 1024/512/256/128，OD/O/D AUC 分别为 `0.7903/0.7652/0.8739`、`0.7891/0.7654/0.8742`、`0.7833/0.7619/0.8647`、`0.7817/0.7593/0.8714`；无序列、batch 1024 的对照为 `0.7765/0.7630/0.8571`。

这些是单份离线表。原文称 batch size “无显著影响”，但没有随机重复、方差、检验方法或置信区间，故只能表述为 512 与 1024 在该表接近，较小 batch 的任务变化不一致。训练曲线图片未解析；样本规模、校准、吞吐/显存、服务版本、线上 A/B 和长周期漂移均缺失。

## B069：OneTrans 全序列快照与验证修复

`sequence-all` 保留了一组双序列离线快照：epoch 9 时，OneTrans+PEP 的 OD/O/D AUC 为 `0.7845/0.7692/0.8639`，PEP 对照为 `0.7617/0.7463/0.8520`；epoch 4 时两者的 OD 和 O 差异很小或不一致，D 也只有小幅差异。这说明训练轮次和选模时点会影响结论；没有多 seed、早停规则、显著性或同成本限制，不能把 epoch 9 的最高值解读为稳定增益。

`onetrans实验结果` 还记录了一次重要的评估修复：修复“只验证一个 batch”后，PLE 同 epoch 对照中 `ple-onetrans` 相对 `ple-seq/ple-no-seq` 的 OD 与 D 更高，O 基本持平；PEP 同 epoch 对照中 `pep-seq-onetrans` 为 `0.7503/0.7613/0.8697`，`pep-seq` 为 `0.7421/0.7339/0.8036`。修复前后数值不能混用，表内最优值也不是线上收益。Warmup+8 层方案仅训练 2 epoch 就提高 D，但 O 降低，应保留任务权衡而非只报告 D 的最高值。
