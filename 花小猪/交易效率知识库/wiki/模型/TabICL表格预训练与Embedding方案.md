# TabICL 表格预训练与 Embedding 方案

> 本页记录调研与候选方案，不代表内部模型已训练、指标已复现或服务已上线。

## 为什么考虑表格预训练

交易效率模型横跨完单、履约、取消、接受、时长、价格弹性、排序和多任务学习。来源将当前困难归因于任务差异、样本规模不均、欠拟合/过拟合并存，以及旧任务参数和经验难以迁移。候选方向是用跨任务预训练学习通用表格表示，再以少量目标任务数据适配，减少每个任务从零训练。

## TabICL 的机制假设

来源中的 TabICL 路线把表格的行列结构作为归纳偏置：

1. **列内分布感知 embedding**：把一列单元格视为集合，通过 Set Transformer 类机制提取分布信息，避免为每张表绑定不可迁移的特征专用参数。
2. **行间交互**：按行处理各列 embedding，用可学习的聚合 token 和注意力捕获跨列依赖，形成行级表示。
3. **数据集级 ICL**：将训练样本的行表示与标签作为上下文，对测试样本在一次前向过程中预测。
4. **合成预训练与课程学习**：调研方案使用结构因果模型生成预训练表格，并引入树模型归纳偏置；训练规模逐阶段增加。
5. **大类别和内存治理**：通过层次分类拆分多类别问题，并以 FlashAttention、动态批处理、激活卸载等方式控制推理内存。

上述内容是论文调研摘要。来源给出的基准性能、速度和显存数据没有在内部环境复现，不能作为选型结论。

## 内部候选任务合同

文档提出的预训练任务池包括：呼叫后的完单、取消、是否迟到、预打车特征、供需/时间特征，以及应答时间与接驾时间的交互。下游优先建议从司乘履约等较简单任务切入。

需要先统一的不是模型结构，而是数据合同：

- 完单、履约、取消等标签的观察窗口、互斥关系和缺失处理；
- 分类、回归、排序与多任务目标是否能共享 backbone，哪些必须使用任务专属 head；
- 任务难度分级与课程顺序；
- 通用任务和专用任务的采样配比；
- 城市、时间、静态列、行为序列等列集合，以及分块 embedding 的组合方式；
- 预训练后全量微调、参数高效适配或持续增量训练的选择。

## 建议的验证阶梯

1. **公开复现**：固定公开数据、版本、seed 和资源预算，先复现论文趋势，不把论文数值直接当验收线。
2. **内部可行性**：挑选标签清晰、数据量充足的履约/取消任务，建立 GBDT、单任务 DNN、现有 PLE/PEPNet 与 TabICL 候选的同口径基线。
3. **迁移价值**：比较从零训练与预训练初始化在收敛速度、低样本 AUC/LogLoss、校准和跨城市/跨时间泛化上的差异。
4. **工程约束**：评估训练成本、推理吞吐/P99、显存、特征缺失、列顺序敏感性、缓存和增量训练。
5. **线上前置**：只有离线可复现后，再补特征版本、模型注册、灰度、监控、降级和回滚合同。

## 已知风险

- 来源指出 TabICL 当前主要支持分类；回归与排序任务不能直接套用。
- RoPE 会引入列顺序，可能破坏表格理想的列置换不变性。
- 基准使用的 holdout、缺失值插补和类别信息处理会影响比较公平性。
- 表格基础模型推理仍可能慢于传统树模型；bagging/交叉验证可增益，但进一步增加成本。
- 内部任务的标签和特征语义差异可能大于公开表格，负迁移必须通过任务分组与消融验证。
