# 聚合PK决策与价值模型

> 来源是一份历史串讲与运行手册。配置名、阈值和“目前”描述均按写作时点保留，未核验当前线上状态。

## 决策位置

材料把交易链路中的竞争拆成五类：商家内部的多品类选择、单品类司机匹配和 Anycar-PK，播单后的 Duse-PK，以及平台应答阶段的聚合 PK。本页只覆盖最后一类：多个运力商司机举手后，在过滤、窗口和价值排序中选出应答司机。

## 候选过滤与窗口

历史链路先按取消/拉黑、换车、接驾距离和预分单约束过滤，再按流量端与订单类型选择 FIFO 或时间窗口 PK。正常正式单可采用动态窗口；预分单使用先到先得。多轮举手在已有品类胜出后会限制后续参与者，这使候选集和标签受到策略选择影响，不能把胜出样本直接视为自然分布。

## 价值模型与倾斜

基础 PK 分由模型计算和打分倾斜两部分构成：

- 模型服务失败时用接驾距离线性公式兜底；单输出 XGBoost 直接取一个价值分；多头深度模型对多个输出加权，并可同时提供动态窗口阈值。
- 历史冷启动方案按端区分 CP ID 或司机 ID 替代，并标注 14 天生效期。
- 倾斜可来自 CP、挑单、滴滴、全职/新司机或差体验治理；同一司机命中多个正向权益时取最大力度，差体验负向倾斜可覆盖正向倾斜。

因此最终排序分并非纯模型概率。评估模型校准、商家公平性或司机体验时，必须拆开基础分、倾斜、窗口和候选过滤，不能只用最终胜出率反推模型质量。

## 运行证据与改进假设

来源列出举手、决策重置、失败通知、预分单接受/拒绝及取消等接口，并登记业务、服务和离线日志监控。这证明历史链路曾有可观测合同，但不证明当前接口、配置或模型版本仍有效。

文末提出两个改进想法：乘客主动接受预分单时重新评估其与正式单司机的优先级，以及把连环派接驾距离拆成 AB、BC 两段以避免不同商家距离口径影响胜率。两者均为假设，未提供实现或实验结果。
