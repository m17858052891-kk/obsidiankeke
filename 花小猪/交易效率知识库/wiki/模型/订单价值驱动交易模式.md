# 订单价值驱动交易模式

> 这里的“订单价值”是司机接受概率的历史设计语义，不等同于长期 GMV、利润或 [[花小猪/交易效率知识库/wiki/模型/DO价值模型]]；当前线上使用情况未知。

## 历史问题

材料认为按品类固定优先级会造成两类错配：低价值特快订单被优先分配却更易取消，高价值特价订单因层级靠后拿不到合适运力；扩播、提前举手和连环派又常以固定距离/时段阈值切场景，难以适应城市与供需差异。

## 模型语义

候选特征包括非双开司机拒单、司机取消、诱导乘客取消、时空供需、订单里程在区域内的价值分位和城市。标签与训练细节未给出；输出被描述为“该订单被司机接受的统计概率”，更接近愿接分数而非财务价值。

## 策略映射

- 高分：全指派或半指派，并更积极使用连环派、扩播、提前举手。
- 中分：抢单。
- 低分：选单大厅，给司机更大选择权。

来源还举例把召回司机按价值排序后分批进入指派、抢单和选单，但没有给出排序是 DO 级还是 O 级、阈值、互斥关系和失败回退，因此不能直接视为线上合同。

## 历史交易模式规则与理想态

另一份历史讨论把无责半指派、有责半指派、抢单和极速指派按接驾距离、接驾金、连环派、顺路度、品类及司机开关组合。材料同时列出“高价值特价转半指派”“高价值半指派转全指派”等进行中事项，以及低价值降级尚未启动；这些是文档时点的规则/计划，不是当前配置。

讨论提出四种重构方向：删除半指派、保留半指派但删除提前举手、引入 API 商家多轮 PK、或自营拒单后进入司机取消/平台改派流程。其理想态是由订单价值唯一决定分单模式，品类只作为价值特征，并弱化极速开关。四种方向互有取舍，来源没有最终选型、实验结果或发布回执，不能合并成已实施方案。

公平性是重要边界：提前举手后若自营拒单，其他 API 商家可能已收到 PK 失败；多轮 PK 或改派流程只是候选解法。顺路单与选单大厅也被视为补充机制，不能直接按订单价值分层替代。

## 证据边界与待补

- 品类心智、应答速度和接驾成本之间的取舍是设计假设，未见实验结果。
- 需要补标签观察窗、样本选择、校准、城市迁移、公平性和各交易模式阈值。
- 需要区分司机愿接概率、取消风险、平台 GMV/利润与长期供需价值，避免同名“订单价值”混用。
- 原文无待解析图片；附件、实验 ID、发布和回滚记录均缺失。

## 后续链路讨论稿

另一份讨论稿尝试把最终交易模式拆成两条输入：司机在不同品类/场景下表达的愿接开关，以及平台基于治理、取消风险和订单价值施加的规则；多策略冲突时取“自由度更高”的播单模式。材料还讨论拒单次数用尽后的强制指派、部分无责场景不扣次数，以及低 CPM 不再单独转抢单、交由订单价值模型综合判断。

这些内容是遗留问题讨论，不是已经验收的规则合同。尤其“司机意愿与平台规则取自由度最大”可能与治理约束、司机沟通和一致性预期冲突；抢单是否保留也没有最终结论。原文决策链路由图片承载，快照虽保留图片数据但尚未解析，无法确认节点、优先级和回退。拒单额度、强制开关、订单价值版本、实验、灰度、发布和当前线上配置均待补。
