# PK司机历史特征合同

## 设计目标

历史重建将分散在多张离线表的 PK 司机特征汇总到统一数据集，并修正 `0` 与 `null` 混用、判责加权内置、扩播单过滤内置等问题。该合同适合做特征语义基线，但当前表名和线上服务是否仍有效待核验。

## 观察空间

统计链路是“司机胜出 → 拒单/应答 → 取消/完单”，`dt` 统一取胜出时间；胜出全集包含 PK 窗口胜出和有应答的预分单胜出。连环派与非连环派分别统计拒单、应答、改派、司机取消、乘客取消、客服关单和完单。

## 空值与原始口径

- 只有司机在对应时间窗、对应场景有胜出表现时才产生特征值，否则为 `null`，不能用 0 代替。
- 司机取消不再按判责加权；乘客取消不再预先排除扩播单。若模型需要变换，应在下游显式形成新特征。
- 14 天新旧同名特征绝对差异多数很小，但非连环派乘客取消数平均差异 0.1896，明显高于其他字段；需要确认这是移除扩播过滤的预期影响，而非数据错位。

## 上线核验

- 训练与在线特征必须声明窗口、场景、胜出定义、时区、延迟与缺失策略。
- 不得把 `null` 转 0 后再解释为“真实无行为”。
- 统一表的历史名称、生产 SLA、回补规则、主键唯一性和当前消费者待补。

## B035：判责特征的历史分析边界

2024-07-01～07-14 的分析记录，在司机取消订单中“恶意有责+错误有责”为 5.41%，乘客取消订单中为 0.13%；按司机被判责比例分箱后，历史取消率从无判责组的 0.139 单调升至最高分箱的 0.468，同时人均订单量随判责比例升高而下降。材料据此提出三类候选用法：将判责次数作为独立特征、调整判责对取消数的加重程度，或直接对 PK 分做负向倾斜。

这些是观察性分析和特征工程建议，不是训练后的增益或因果证据。订单活跃度、暴露量和司机选择可能同时影响判责率与取消率；原文图片未解析，也未给跨期验证、校准、缺失值处理及线上实验。当前生产是否仍将判责内嵌到取消数、是否已切换为独立特征，均需以线上 schema 核验。
