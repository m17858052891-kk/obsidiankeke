# MDP时空价值网络

## 目标

以神经网络近似司机在时间、位置状态下的长期价值，替代表格型 SMDP 在数千空间格与 288 个时间片组合上的稀疏表示。

## 数据与训练

- 状态使用时间与经纬度；材料中的基础网络为 MLP。
- 以 2 小时划分 episode，用 answer/finish 时间避免预估时间造成的转移倒挂。
- 按 5 分钟拆分衰减 GMV reward，补充 reward=0 的 idle 转移，并用 done mask 截断。
- 采用 Bellman/TD 与冻结 target 训练；材料也提出 MC return 作为待验证方向。

## 已知局限

- 一单即走司机比例高会形成低价值峰，历史分布可呈多模态。
- 季节、灾害、城市和时段漂移会造成旧价值表失准。
- 线上对 IPH+Hold 的结果随流量与时段变化，全量阶段未显示稳定正向，不能把局部提升当作模型收益。
- 图片中的曲线未解析，仅使用正文可核验结论。
- 早期材料还记录 reward shaping、跨时段衰减、状态重复更新与样本稀疏等实现风险，不能把迭代建议当作已落地修复。

## B031：表格型 MDP / SMDP 合同

- 司机状态是格子与时间片，动作是候选订单；边权候选为当前订单收益与终点未来价值之和 `r + γ^t V(s')`，轮空边用当前状态价值 `V(s)`。
- 原始设计以约 5 分钟为时间片，并把接驾、等待、送驾时长纳入状态转移。司机轨迹含有随机持有时长，因此材料将其视作 semi-MDP；该术语说明仍标注为个人理解，不能当作严格理论验收。
- 价值估计讨论 MC、TD/SARSA 两条路线。文中“上线后效果不明显”只说明早期版本未取得清晰效果，且没有同口径实验表，不能推导当前生产状态。

## B031：数据与实现修订

更新版代码链把状态起止从 `call_time + 预估时长` 改为 `answer_time → finish_time`，区分工作日/休息日，并依次完成轨迹解析、异常过滤、episode 切分、idle 补齐和反向 TD 更新。它同时记录了多项实现修订：不再用 GMV=0 的补充单直接更新、取消硬截 2 小时、修正 episode 反向传播的重复更新。

这些是历史代码说明，不是已复核的生产实现。源文暴露了内网脚本位置和手工删表头流程，但 Wiki 不复制可执行指令；版本提交、可复现环境、单测、训练产物和线上服务版本均待确认。

## B031：V2 数据契约与离线实验

- V2 建议用 `answer_time/finish_time` 定义时间状态，避免呼单到应答空档及预估时间造成的“单内套单”和时间倒流；空间输入从格子 ID 转为中心经纬度以适配神经网络。
- reward 假设 GMV 在行程时间片内均匀分布，对最后一个非整时间片单独处理；订单间补 idle 转移，并建议只以完单日口径纳入跨日改派订单。原文仍标记底层 SQL 逻辑待补充。
- 北京 3 月工作日约 150 万样本上的三层 MLP 比较了 5/10 分钟切片；`γ=0.87` 时训练 loss 约 133。曲线、早平晚高峰价值分布均在未解析图片中，且来源仍写有 “To be continued”，所以不能据此判断两种切片孰优或宣称离线验收通过。
- SMDP 补充页只列出 discounted reward 与 Bellman 同质更新的讨论提纲，没有完整推导或实验数值，记录为设计占位证据。

## 当前证据边界

本批材料覆盖模型定义、历史代码修订和离线探索，没有可核验的当前线上版本、AB 显著性、服务时延、实时更新频率或城市泛化结果。所有图片和外链附件尚未解析；数据中 GMV=0、跨日、改派、重叠订单、短单/长单和样本稀疏仍需统一口径复核。

## B042：北京历史仿真点估计

补充材料记录北京 2021-04-14 工作日仿真中 GMV `+1.19pp`、应答率 `+1.24pp`，4 月 17 日周末为 GMV `+2.00pp`、应答率 `+1.10pp`。来源把周末差异解释为冷热区更清晰、未来订单价值更确定，也认为加入未来价值更接近司机实际决策。

这些是外链仿真结果的正文摘要，缺少基线策略、样本量、随机种子、置信区间、复算表和线上实验；“周末效果更好”只能保留为历史解释假设，不能外推为稳定规律或当前线上收益。
