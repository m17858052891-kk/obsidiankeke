# B013 项目候选：API 多轮举手

> 2025 年历史需求方案，不代表 2026 已开发、实验或上线。

## 候选问题

历史链路允许自营和宏鹄在 PK 失败后再次举手，但 API 商家一次失败、半指派拒单或预分单被乘客拒绝后不能重试。候选能力允许 API 在这些节点再次上报司机，以补充后续应答机会。

## 历史测算与方案

- 文档用 2025-08-11 至 08-17 样本，以自营宏鹄二次举手获胜率 0.37% 作为 API 下限代理。
- 原文同时给出平台约 2.8 万单/天、API 约 5.6 万单/天的更高测算，依赖多呼占比、履约率等假设，不能视作实验收益。
- 需求覆盖 PK 失败、半指派拒单、预分单被拒三种再次举手触发点。

## 验证门槛

1. 实测 API 二次举手率、胜率和司机质量，不能直接套用自营宏鹄参数。
2. 防止重复举手、窗口拥塞和低质量远距离司机增加取消。
3. 同时观察平台 CR/完单、API 份额、自营宏鹄份额及公平性。

## 覆盖缺口

收益测算引用块未附完整复算脚本；原文只有实验设计，没有实验结果、工程回执或当前状态。

## B036：2026 V1 实验评估

### 机制与实验设计

V1 将再次举手机会扩展到 API 商家：API 司机 PK 失败、半指派拒单或预分单被乘客拒绝后可再次上报；半指派司机胜出后，PK 仍可在窗口内继续，直到更高分司机出现、司机接单/拒单或窗口结束。材料记录采用 PID 分流，AA 为 2026-04-20—05-03，AB 为 05-18—05-31，每组约 304 万 PID，覆盖 T3、享道、如祺的指定城市。

### 评估结果

- API 口径：完单量 `+1.6%`、应答率 `+0.30pp`、竞争成交率 `+0.27pp`，材料标注显著；单订单轮次司机数 `+19.7%`，API PK 胜率 `+0.87pp`（相对 `+1.53%`）；预估接驾距离 `-0.49%`、预估接驾时长 `-0.44%`，均被标注为显著。
- API 应答后乘客取消与司机取消为小幅负向且不显著。平台整体完单量 `+0.013%`、应答率 `-0.0024pp`、竞争成交率 `-0.04pp`，材料均未给出显著正向结论。
- 分商家表中 T3、享道、如祺的部分数值带负号，而正文却表述为“最优/显著正向”，符号或指标语义存在冲突；本页不代替原作者修正，也不据此给出分商家收益结论。

### 上线事实边界

材料据实验结果提出推全建议，但决策人、推全日期和实际流量均为空，也没有生产配置或发布回执。因此可确认的是“完成一次 V1 实验并形成建议”，不能确认已全量或仍在当前线上。

### 覆盖缺口

实验平台底表、显著性计算过程、城市清单附件及推全/回滚配置未解析；需补齐分商家符号冲突解释和生产回执。

## B040：LR26-024 复核

LR26-024 再次记录 V1 的完整链路：API 司机在 PK 失败、半指派拒绝或预分单被乘客拒绝后，可对同一订单继续上报其他司机；半指派胜出后 PK 也不立即终止。AA 为 2026-04-20—05-03，AB 为 05-18—05-31，每组约 304 万 PID，覆盖 T3、享道、如祺的接入城市。

复核文档给出 API 完单 `+1.6%`、应答率 `+0.30pp`、竞争成交率 `+0.27pp`，以及单订单轮次举手司机数 `+19.7%`、PK 胜率 `+0.87pp` 的显著结果；花小猪平台完单 `+0.013%`，应答率 `-0.0024pp`、竞争成交率 `-0.04pp`，均为不显著。它仍保留与前一来源相同的分品牌符号/文字冲突，并把推全决策人、实际日期与流量留空，因此只能确认实验评估与推全建议，不能确认生产推全。
