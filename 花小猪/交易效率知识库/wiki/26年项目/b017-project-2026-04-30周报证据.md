## 线上实验事实（限本周报时点）

### API 平台规范实验

4 月 15 日至 21 日的全国 PID 分流中，实验组 1 同时透传并生效平台规范，实验组 2 只透传，实验组 3 只生效。相对对照组，实验组 1 的单均预估接驾距离 `-36.5m`，但应答前取消率 `+0.31pp`、CR `-0.05pp`；实验组 1 相对实验组 3 的 API 人均完单 `+0.45%`。正文没有显著性、样本量和完整统计表，因此只保留点估计与分组定义。

### API 多轮举手实验

4 月 16 日至 22 日的全国 PID 分流记录：平台人均完单不显著正向，API 不显著 `+0.2%`，自营显著 `-0.4%`，滴滴显著 `+0.97%`。该结果提示商家间存在结构性迁移；后续仍需按哈啰、享道拆分，不能仅用 API 汇总值判断扩量。

### PK v2 实验

周报记录拟放量实验组 2：人均完单 `+0.09%`、CR `+0.17pp`、应答后乘客取消 `-0.2pp`，同时司机取消（含改派）`+0.36pp`。正文还观察到司机取消/改派次数与应答、乘客取消存在相关性。放量是计划而非已完成事实，且需回链正式 LR 核验显著性和护栏。

## 离线结果与方法风险

- 序列建模材料称 PEPNet 加序列特征在 BS=256 时多个 AUC 提升，但单独缩小 batch size 的基线出现 O/D 任务约 `-10pp`，说明收益不能脱离训练设置解释。
- OneTrans 在 PLE/PEP 的部分任务上给出 AUC 提升；同时发现验证流程只验证第一个 batch、数据采样非周期，曾造成验证集 AUC 高于训练集的错误结论。修正后的独立复验应作为采用前提。
- 端流量分发使用 LogMSE 后记录 RMSLE `0.63`、SMAPE 约 `87%`，比 MSE 方案的 `67%` 更差；当时仍处于离线目标和长尾损失调优阶段。
- 召回过滤模型“线上部署完成”只证明工程部署进度；一致性校验、阈值、拉长验证周期与 AB 实验仍在 todo，不能写成线上收益。
