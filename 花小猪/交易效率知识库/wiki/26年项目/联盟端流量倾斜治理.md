# 联盟端流量倾斜治理

> 三份材料记录 2025—2026 年联盟端渠道导量的策略、历史实验结果与后续配置；“放量节奏”只作为来源记录，不能据此确认当前仍在线或参数未变。

## 目标与机制

早期方案希望在 API 与渠道商家共同参与 PK 时，把部分 API 流量转给宏鹄。策略只对满足 PK 分和接驾距离阈值的宏鹄司机加倾斜，并区分模型打分与距离打分两种量纲：模型分为负值、距离分为正值，但两者都以“分数越小越易胜出”为排序方向。

候选实现先在宏鹄与 API 间应用倾斜得到组内第一，再用未加本次倾斜的分数与滴滴、自营候选比较，以避免直接覆盖其他交易逻辑。阈值按胜出司机 PK 分或接驾距离的历史分位数生成，倾斜量按 API 与宏鹄分差分位数计算，计划每周更新。它是历史配置算法，不是经过本地复算的当前生产合同。

## 历史实验与后续分支

### 2020 成本空间测算

早期材料先用时间片实验和模拟系统估计“确定性资源倾斜”的空间。原文记录大盘倾斜 5% 时整体 GMV `-0.74%`（不显著），高峰期 `-1.34%`（显著性待离线计算）；模拟中，北京全天向 10%—15% 人群绝对倾斜时 GMV 折损约 `0.5%`、目标人群 CR `+15pp`，高峰期向 10% 人群倾斜时 GMV 折损约 `5%`、目标人群 CR `+38pp`。这些结果来自不同方法、窗口和假设，不能互相合并，也不能当作现行收益。

材料指出当时线上可用抓手为匹配绝对优先、扩距离和一播多，连环派尚未支持。该能力描述和数值都是历史快照；实验链接、样本、SRM、显著性复算及成本口径未离线解析。

### 2022 倾斜治理源流

早期材料已经提出“显式倾斜应可透传解释、隐式倾斜需实验、长期倾斜要证明收益覆盖短期折损”的治理原则，并记录过距离、PK 窗口和新手保护等操作。由于关联效果页与图片未解析，且正文中的操作范围和期限属于历史快照，本页不保留细粒度城市和配置参数，也不据此推断后续沿用。

同期“精准派流量控制”方案用半小时时间片的三方应答份额误差驱动 PID，再把 PID 映射为自营司机距离修正量。历史参数写为 `kp/ki/kd=1.5/0.5/1.5`、距离上限 `500m`，并由城市运营配置目标份额；这些是 Apollo 可配的方案参数，不是当前配置。正文仅描述算法与待优化项，没有实验结果、稳定性、饱和/积分风up处理、发布回执或仿真验证。

### 2025-11 举手倾斜

十城乘客随机分流曾以 70% 对照、30% 实验验证渠道倾斜。来源记录 API 与宏鹄完单置换约 `100:95`，宏鹄约增加 `1.5 万单/日`，API 胜出且宏鹄举手的订单约有 `44%` 被腾挪；司机应答后取消（含改派）增加 `0.2pp`。这些是原文点估计，未附样本量、置信区间、完整大盘护栏和独立评估报告，不能简化成“无损”。

### 2026-08 API 必败分支

另一材料把实验组改成 API 与宏鹄共同 PK 时 API 必败，记录全国流量 50% 后再到 100% 的放量计划，并要求观察完单、CR、应答率、乘客应答后取消与商家份额。正文没有这些指标的实际结果、显著性、异常监控或回滚记录，因此只确认实验设计和计划节奏。

### 2026-08 距离约束分支

后续距离调整以乘客随机分流验证 `zy` 举手距离上限 `2800m`，记录 70% 对照、30% 实验和 2026-08-19 至 08-25 的计划周期。该页没有结果，无法判断距离约束是否修复取消上升、对渠道份额造成何种影响，或是否进入生产配置。

## 风险与验收

- API 向宏鹄腾挪并不保证最终由宏鹄胜出；两两 PK 链可能把份额转到滴滴或自营。早期材料明确缺少滴滴司机 PK 分，离线测算存在不可观测偏差。
- 周更阈值依赖打分分布稳定、历史窗口和日志完整性；需要记录配置版本、生成时间、城市打分模式和回滚参数。
- 必须同时验收平台完单/CR、应答后司乘取消、接驾距离、各商家份额和倾斜额度，不能只看渠道商家增量。
- 原始 BRD、工程文档、实验平台、配置与数仓链接未离线解析；图片、附件、生产 Apollo、放量回执、显著性和当前线上状态均待补。
