# API 小猪端交易能力补齐路线图

## 需求范围

历史需求把 API 与小猪端的能力差异拆为五类：预分单接入及品类拆分、API 运力进入特价/幸运盒子、多轮举手、举手行为与平台规则对齐、API 司机换车。它们分别作用于候选进入、流量场景覆盖、重复参与 PK、交互约束和履约修复，不应被合并成一个单点策略。

## 机制链路

- **预分单接入**：让满足条件的 API 运力更早进入分单候选，但需区分品类和运力适配规则。
- **盒子场景接入**：扩大 API 运力可参与的流量场景，效果受勾选、价格与履约约束影响。
- **多轮举手**：首次失败或预分单被拒后，用新的候选司机继续参与后续 PK；增量应与半指派等机制隔离评估。
- **举手规则对齐**：统一平台侧参与条件，避免不同端口因能力差异形成不可解释的机会差。
- **司机换车**：处理候选司机或车辆变化后的重新匹配与履约衔接，不能把“支持换车”直接等同于成交增益。

## 状态与证据边界

来源是一份 2025 年的待补充能力清单，其中的订单量、转化、ROI、接驾距离等数字是当时的测算或历史快照，不是已上线结果，也不代表当前规模。文档没有完整的上线记录、实验设计、样本量或显著性；各能力目前是否投产、覆盖哪些商家和城市均待核验。

本页不复制商家级城市、订单量和收益明细。若后续用于排期，应逐项补齐负责人、依赖、验收指标、灰度范围和回滚条件。
