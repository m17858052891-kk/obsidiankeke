# 交易漏斗分端口径合同

> 这组来源是历史指标与 SQL 合同，不是当前线上看板验收。SQL 中的日期、城市组、表名和产品编码均可能已变化；复用前必须与现行数仓和 owner 对齐。

## 统一漏斗

| 阶段 | 历史定义 | 率指标 |
| --- | --- | --- |
| 冒泡 | 小猪端按 `combine_trace_id_by_pid` 去重，排除等待应答页；自营一口价、特快、特价按三个品类计 | `ECR = 非改派呼叫订单数 / 去重冒泡数` |
| 呼叫 | 原始呼叫通常要求 `source_type <> 2`，排除改派；早鸟、短时预约与 PBD 是否排除随端口不同 | 应答前取消率 = 应答前乘客取消订单 / 呼叫订单 |
| 播单 | 播单日志是订单—司机 DO 粒度，一张订单可对应多位司机 | 播单率 = 播单订单 / 呼叫订单；拒单率 = 拒单订单 / 播单订单 |
| 应答 | 大盘业务口径多用非改派应答订单 | 应答率 = 应答订单 / 呼叫订单 |
| 完单 | 订单基表只保留最新状态；DO 标签只能把最终完单司机标为正例 | 完单率 = 完单订单 / 呼叫订单 |
| 应答后 | 乘客取消、司机取消和改派需沿原始需求链归一 | 双边取消率、改派率的分母通常为应答订单 |

这些公式只有在时间窗、端口、产品集合、去重键与改派处理一致时才能横向比较。

## 分端差异

### 小猪端大盘

小猪端有冒泡勾选数据，可拆默勾、加勾、反勾与等待应答页补勾。呼叫品牌数是单个订单内去重的 `product_2level` 数；自营三个品类单独计数。历史 SQL 明确提示：同一 `combine_trace_id_by_pid` 可能对应多个 `trace_id`，直接取各字段最大值可能拼出并不存在的品牌组合，这是待修复的去重缺陷。

### 三方漏斗

三方竞争呼叫指任一环节呼叫至少一个三方品牌；默勾、加勾、补勾三类应拆开。小猪端“客观呼叫”从竞争呼叫中排除被自营应答的需求；PBD 与 DD 主端对车企品牌、渠道和产品层级的纳入规则不同，不能直接复用小猪端分母。改派订单的完单归到最终完成服务的品牌一次。

### PK 漏斗

PK 指标有两个不同分母：发单到完单以呼叫订单为样本，PK 胜出到完单以胜出的订单—司机对为样本。小猪端历史日志用 `pk_type = 15`，PBD 示例用 `pktype = 17` 与渠道过滤；实验组还曾通过订单尾号拆成模型 PK、距离 PK 与 Hold。来源表中一处把“PK 胜出完单率”文字写成 `PK胜出数 / 完单数`，而 SQL 实际计算 `完单数 / PK胜出数`；本 Wiki 采用 SQL 方向，但保留该原文冲突。

## 改派与取消合同

- 原始订单 `source_type <> 2`；改派子单 `source_type = 2`，原单用 `is_td_reassign = 1` 标记曾改派。
- `cancel_type = 1/2/3/4/5` 分别表示应答前乘客取消、应答后乘客取消、应答后司机取消、客服关单与系统取消；`order_status` 是最终状态，两者不是同一维度。
- 业务 SQL 的应答后司机取消常用 `cancel_type = 3`，它倾向于只保留未继续改派的取消；若要“含改派”，需要沿原需求链识别 `order_status = 12` 等状态。
- `order_status = 5` 不等价于 `is_td_finish = 1`，因为订单基表记录最新状态，支付或跨日更新可能改变最终状态行。
- 两份交易指标来源版本非常接近，但短时预约字段分别写作 `is_short_book` 与 `is_short_book_flag`，且旧写法 `(is_short_book = 0 or null)` 不是可直接执行的布尔条件；必须按现行字段重写。

## 粒度与版本缺口

- 冒泡：`combine_trace_id_by_pid` / `trace_id`；呼叫：`order_id`；改派归一：`trace_order_id`；播单与 PK：`order_id + driver_id`。
- SQL 内含固定历史城市组、日期与实验哈希，不能作为通用生产查询。
- 图片、流程图、看板、外部 Wiki 和部分 SQL 依赖未解析；没有当前字段字典、调度版本、数据质量 SLA 或回溯测试。
- 历史文档把“业务 SQL”与“模型 SQL”并列，二者样本目标不同；业务指标和训练标签不得混用。
