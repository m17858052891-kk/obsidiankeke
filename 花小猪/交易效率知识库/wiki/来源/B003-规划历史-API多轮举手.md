# B003 来源摘要：API 多轮举手能力

## 来源定位

- 目录标题：`【LR25053】API多轮举手能力建设`。
- 原始正文：[knowledge-2206172524014.md](../../raw/cooper/knowledge-2206172524014.md)。
- 文档末尾含“2026.6 月正在引入其他 API 商家”的历史状态，当前状态需另行复核。

## 机制

- API 商家在 PK 失败或预分单被拒后，可以再次举手司机；旧链路中自营和宏鹄可再次参与，而 API 不可。
- PK 窗口结束时，若最高分是尚未确认的半指派司机，则等待其确认，或由后续更高分的已确认司机胜出。
- 实验通过三组拆分：组 1 同时开启两项能力，组 2 仅开启半指派胜出条件，对照组均不开启，以 `组1-组2` 识别多轮举手的附加效果。

## 实验记录

- 组 1 对对照：人均完单 +0.28%、GMV +0.26%、成交率 +0.10pp，正文标记显著。
- 组 1 对组 2：API 完单 +0.64%、阳光出行完单 +2.93%，正文标记显著；用于支持多轮举手的增量解释。
- 阳光参与 PK 数 +2.2%、PK 胜率 +0.34pp、PK 胜出数 +3.7%；需注意正文表格有一行列对齐异常，引用时以原文结论和可核对行共同为准。

## 状态与边界

- 文档写明阳光出行已推全，LR 后计划放量半指派胜出条件，并推进哈啰、享道接入。不能据此推断所有 API 商家当前都已接入。
- 多轮举手与半指派条件同时改变时，只有组 1 对组 2 才能近似隔离多轮举手增量；组 1 对对照是两项能力的合并效果。
