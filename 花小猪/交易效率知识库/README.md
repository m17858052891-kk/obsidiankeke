# 交易效率 LLM Wiki

交易效率 LLM Wiki 是面向网约车交易策略、算法和项目协作的结构化知识库。它围绕“从用户发起需求到订单成交”的完整交易链路，把分散在 Cooper、Git、项目方案、实验报告和复盘材料中的知识，整理为可检索、可追溯、可交叉引用的主题页面。

这套 Wiki 不是原始文档的简单汇总，也不把历史方案直接视为当前线上事实。每个主题尽量拆分为概念、机制、指标、模型、项目、实验、诊断和来源，并明确方案设想、离线结果、实验观察、线上事实之间的证据差异。

## 知识地图

交易效率关注的核心链路是：

> 呼叫与分发 → 召回 → 商家匹配 → 举手与平台 PK → 应答 → 接驾 → 到达与计费

改派、换车、取消等行为会让订单在链路中回流；连环派、扩播、预分单、升舱、Hold、供需折叠等策略则可能同时影响多个阶段。因此，阅读某个策略时需要同时核对它的决策位置、目标指标、约束条件和上下游影响。

- [指标](wiki/指标/index.md)：查询应答、成交、取消、接驾、供需和价值类指标的口径与解读边界。

## 适合回答的问题

这套 Wiki 可用于辅助回答以下类型的问题：

- 某个交易策略位于哪一环，改变了什么决策，影响哪些上下游？
- 某个指标的观察视角、样本范围、事件端点和常见误读是什么？
- 一个模型使用了哪些特征、目标和约束，有哪些离线或线上证据？
- 同一策略经历了哪些版本、实验、扩量和回滚，结论是否仍然有效？
- 2026 年项目与历史方案、模型和实验之间有什么继承关系？
- 指标异常时，应该先排查口径、配置、流量、模型还是链路机制？

建议先从 [知识总索引](wiki/index.md) 定位主题，再沿页面中的关联链接阅读模型、实验和来源页。遇到结论冲突时，以具体页面标注的时间、证据层级和来源为准。

## 证据与使用边界

- **规划不等于上线**：目标、里程碑和候选方案只代表规划状态。
- **离线不等于线上**：离线收益、回放结果和模型指标不能替代线上实验结论。
- **实验不等于长期事实**：实验观察需结合时间、城市、流量、版本和显著性判断。
- **历史不自动代表当前**：历史 LR、配置和策略结论必须经过新证据复核后才能用于当前决策。
- **未知信息不补造**：图片、附件、表格、外链或服务配置未解析时，页面会保留覆盖缺口。
- **来源可追溯**：Wiki 页通过来源标识和关联链接连接到 `raw/` 中的不可变快照。

本库适合知识检索、方案调研、实验回顾和问题诊断，不替代线上配置、监控平台、代码仓库或正式决策流程。

## 仓库结构

```text
.
├── wiki/           # 面向阅读和检索的结构化知识页
├── raw/            # Cooper、Git、表格和附件的不可变来源快照
├── _build/         # 增量任务账本、覆盖清单、检查脚本和批次报告
├── AGENTS.md       # Wiki schema、术语和维护约定
└── BUILD-REPORT.md # 当前覆盖、验收结果和已知缺口
```

## 维护方式

新增材料采用增量 ingest：保留既有来源身份和成功结果，只处理新增或明确要求补充的内容，并同步刷新相关主题页、来源页、索引和构建报告。维护规则见 [AGENTS.md](AGENTS.md)，当前覆盖与缺口见 [BUILD-REPORT.md](BUILD-REPORT.md)。
