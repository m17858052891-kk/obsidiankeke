# V1：动态播单阶段

## 版本概述

V1 是策略的核心转折点：将动播（缩播）和扩播**统一为一套自适应播单策略**，从"固定参数"走向"数据驱动的个性化"。目标是实现**订单维度**的动态播单。

## 核心框架

```
发单 → 供需判断 → 确定初始半径(动播/缩播) → 随时间扩播 → 最大半径
```

关键抓手：**动态播单半径**
- 高供需 → 缩播（小初始半径）→ 短接驾 → 低取消
- 低供需 → 不缩播/正常半径 → 保证应答率

## 子版本演进

### V1.0：基础框架

**核心改动**：
- 时间粒度从小时升级到**十分钟时间片**
- 供需计算融合实时+历史（各50%权重）
- 需供比替代供需比（调换分子分母）
- 区分空车和连环派的半径策略
- 支持 Apollo AB 实验（可按时间片分流）

**实验范围**：自营缩+扩半径；宏鹄缩半径（不超3km）

## 关键问题（Lowlights）

1. **全国统一参数**：相似供需格子配同一半径，忽略城市路网差异
2. **策播基于大盘统计**：未做到订单维度自适应触发
3. **宏鹄供需高估**：多商家运力打包计算导致过度缩播

## 从 V1 到 V2 的转变

V1 的核心是「自适应缩播 + 渐进扩播」，V2 将其颠覆为「大半径直接召回 + 模型过滤」。这是架构层面的范式转换。
