# V2 系列 — 召回策略优化

## V2.0 特殊场景配置

V2.0 需要管理大量特殊场景的播单配置（exempt分组）：

| 分组 | 场景 | 策略 |
|------|------|------|
| exempt_1 | level_type=107（lucky_box） | 2.5km，不扩播，不过滤 |
| exempt_2 | 腾讯端，部分城市 | 2.5km初始，2km+模型过滤 |
| exempt_3 | 百度端，部分城市 | 同上 |
| exempt_4 | 美团端，部分城市 | 同上 |
| tmp_exempt_hh_dd_pbd | 宏鹄滴滴端 | 3km初始，开新版扩播，2km+过滤 |
| exempt_shanghai | 上海（方舟行/悦道） | 各自独立配置 |

**配置复杂度**是 V2.1 整合动机的核心。

## V2.1：配置收拢 + 参数迭代

### 核心目标
**收拢 Apollo 配置，提高可维护性**。策略层面为参数优化。

### 关键改动

#### 1. 模型整合（5个 → 3个）

| V2.0 | V2.1 |
|------|------|
| 非连环派乘客取消模型 | 合并为统一乘客取消模型 |
| 连环派乘客取消模型 | (`recall_pas_cancel_v1_pas`) |
| 非连环派司机取消模型 | 合并为统一司机取消模型 |
| 连环派司机取消模型 | (`recall_driver_cancel_v2_dri`) |
| 应答前流失率模型 | 保持不变 (`cp_loss_model`) |

#### 2. 新增 ETA 约束
- V2.0 仅用 EDA（距离）做召回限制和过滤判断
- V2.1 新增 **ETA（接驾时间）**，取 ETA ∩ EDA 的交集

#### 3. 连环派过滤放松
- 新增"模型不生效"条件：当 ETA < 阈值 且 EDA < 阈值（已经很近），跳过模型过滤
- 连环派 GS：ETA < 2min 且 EDA < 1.2km → 不过滤
- 连环派 TP：ETA < 45s 且 EDA < 0.8km → 不过滤

#### 4. 非连环派过滤收紧
- 偏置项（bias）减小 → 过滤更严格
- 过滤公式：`取消率预测值 < 流失率 + 偏置项`
  - 偏置项越小 → 过滤越严
  - 偏置项越大 → 过滤越松

### 参数对比（GS-非连环派示例）

| 参数 | V2.0 | V2.1组a | V2.1组b |
|------|------|---------|---------|
| 召回EDA | 4.5km | 4.5km | 4.5km |
| 召回ETA | 无 | **6min** | **6min** |
| 司机偏置项 | 0.513 | **0.247** | **0.217** |
| 乘客偏置项 | 0.596 | **0.216** | **0.185** |
| 不过滤EDA | 2.35km | 2.35km | 2.35km |
| 不过滤ETA | 无 | **2min** | **2min** |

- 全国PID随机分流，自营
- 流量端：dd、pbd、小猪端

## 关键洞察

1. **策略本质是播单份额从非连环派向连环派腾挪**：连环派份额从17%暴增到42%
2. **非连环派质量显著提升**：过滤更严 → 留下的都是高质量配对 → C取消-2.7pp
3. **连环派质量下降**：过滤放松 → EDA变远 → 取消率上升
4. **B取消是核心代价**：+1.21pp 不可忽视，后续需收紧连环派过滤
5. **配置收敛是重要工程目标**：从5个模型到3个，大幅降低运维复杂度
6. **动态过滤机制**：每轮召回都调模型，随时间推移实现动态播单

## 后续方向

- 进一步收紧连环派过滤条件
- 全召回落表（解决数据稀疏问题）
- 通过调阈值达成放量目标
