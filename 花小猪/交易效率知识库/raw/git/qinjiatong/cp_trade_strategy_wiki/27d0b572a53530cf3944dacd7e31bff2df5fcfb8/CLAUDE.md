# 商家交易知识库 — Schema

本文件是知识库的「操作手册」，定义了 LLM 如何维护这个 wiki。

## 领域概述

本知识库记录**花小猪（滴滴出行）商家交易**方向的策略演进，核心主题为**商家召回策略**（播单策略），涵盖动播、扩播、分单过滤等子方向从 V0 到 V2+ 的迭代历程，包括策略方案、实验评估、指标变化和技术实现。

## 架构

```
商家交易知识库/
├── CLAUDE.md          ← 本文件：schema 层，定义约定和工作流
├── raw/               ← 原始文档层：不可变的源文件（策略方案、实验报告等）
│   ├── 商家召回策略V0/
│   ├── 商家召回策略V1/
│   └── 商家召回策略V2/
├── wiki/              ← Wiki 层：LLM 生成和维护的结构化知识页面
│   ├── index.md       ← 内容索引：所有 wiki 页面的目录
│   ├── log.md         ← 操作日志：时间序列的变更记录
│   ├── overview.md    ← 全局综述：策略体系总览和核心洞察
│   ├── concepts/      ← 概念页面：核心术语和机制的解释
│   ├── versions/      ← 版本页面：每个策略版本的总结和对比
│   └── sources/       ← 来源摘要：每篇原始文档的结构化摘要
└── llm-wiki.md        ← 方法论参考文档
```

## 约定

### 页面格式

每个 wiki 页面遵循如下结构：

```markdown
---
tags: [概念|版本|来源|综合]
sources: [相关原始文档路径列表]
created: YYYY-MM-DD
updated: YYYY-MM-DD
---

# 页面标题

正文内容...

## 相关链接

- [[相关页面1]]
- [[相关页面2]]
```

### 命名规则

- 概念页面：`wiki/concepts/{概念名}.md`（如 `动播策略.md`）
- 版本页面：`wiki/versions/{版本标识}.md`（如 `V1.0-动态播单.md`）
- 来源摘要：`wiki/sources/{原始文档名}-摘要.md`

### 链接规则

- Wiki 页面之间使用 `[[wiki/path/to/page]]` 互相引用
- 引用原始文档使用 `[[raw/path/to/source]]`
- 鼓励大量交叉引用，构建知识网络

### 指标术语标准化

| 缩写 | 全称 | 含义 |
|------|------|------|
| CR | 竞争应答率 | 竞争视角下订单被应答的概率 |
| C取消 | 乘客取消 | 应答后乘客主动取消 |
| D取消 | 司机取消 | 应答后司机主动取消 |
| 完单 | 完成订单 | 最终成功完成的订单 |
| 供需比 | 供需比 | 空闲运力数 / 未播订单数 |
| 需供比 | 需供比 | 发单数 / 空闲运力数（V1.0后使用） |

## 工作流

### Ingest（摄入新源文档）

1. 阅读 `raw/` 下的新源文档全文
2. 与用户讨论关键要点
3. 在 `wiki/sources/` 创建该文档的结构化摘要页面
4. 更新 `wiki/overview.md` 中的相关段落
5. 更新或创建相关 `wiki/concepts/` 和 `wiki/versions/` 页面
6. 更新 `wiki/index.md` 添加新页面条目
7. 在 `wiki/log.md` 追加本次 ingest 记录
8. 检查是否有跨页面需要更新的交叉引用

### Query（查询）

1. 阅读 `wiki/index.md` 定位相关页面
2. 阅读相关 wiki 页面综合回答
3. 如果回答产生了有价值的新综合/分析，建议将其保存为新 wiki 页面
4. 引用具体来源页面（用 wiki 链接）

### Lint（健康检查）

定期检查：
- 孤立页面（无入站链接）
- 过时信息（被新版本取代的旧结论）
- 概念提到但缺少独立页面的术语
- 缺失的交叉引用
- 版本间的矛盾结论

## 注意事项

- **永远不修改 `raw/` 下的文件**——原始文档是不可变的 source of truth
- Wiki 页面代表对源文档的理解和综合，不是简单复制
- 版本页面应突出每个版本相对前代的**改进点**和**遗留问题**（Lowlights）
- 实验结果使用具体数据，保留统计显著性标注
- 优先使用中文，专业术语保留英文缩写
