# PK知识库 — LLM Wiki Schema

> 本文档是 LLM 维护此知识库的操作手册。LLM 在每次会话开始时应阅读本文档，了解知识库的结构、约定和工作流程。

## 知识库概述

本知识库围绕**滴滴聚合平台 PK 决策系统**构建，涵盖 PK 模型、PK 窗口策略、冷启动、因子引入、实验评估等核心领域。目标是将分散的策略文档、实验报告和技术方案整合为一个结构化、互联的知识网络。

## 三层架构

```
PK知识库/
├── raw/                  # 原始素材层（只读）
│   ├── 00-07 项目文件夹   # 按项目组织的源文档
│   ├── 废弃/              # 已废弃方案
│   └── 实验评估/          # 独立评估报告
├── wiki/                 # Wiki 层（LLM 维护）
│   ├── agent-entry.md    # Agent 入口：阅读顺序、关键页面、搜索边界
│   ├── overview.md        # 全局综述
│   ├── index.md           # 内容索引
│   ├── log.md             # 操作日志
│   ├── entities/          # 实体页 — 具体的系统、模块、工具
│   ├── concepts/          # 概念页 — 抽象概念、指标、方法论
│   ├── models/            # 模型页 — 模型架构、版本、组件
│   ├── proposals/         # 策略方案页 — 可执行优化方案
│   ├── research/          # 研究分析页 — 方法综述与落地方向
│   └── sources/           # 来源摘要页（按需生成）
├── CLAUDE.md             # 本文档 — Schema 层
└── llm-wiki.md           # LLM Wiki 方法论参考
```

### 层的职责

| 层 | 所有者 | 规则 |
|---|---|---|
| `raw/` | 用户 | **只读**。LLM 从此读取但永不修改。这是信息的源头。 |
| `wiki/` | LLM | LLM 全权维护。创建、更新、删除页面，维护交叉引用和一致性。 |
| `CLAUDE.md` | 用户 + LLM | 用户与 LLM 共同演进。记录约定、工作流、领域规则。 |

## 页面格式约定

### Frontmatter

每个 wiki 页面必须包含 YAML frontmatter：

```yaml
---
title: 页面标题
type: entity | concept | source | overview | comparison | analysis
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources:              # 关联的 raw/ 源文件路径
  - raw/03. PK可解释模型/xxx.md
tags:
  - pk模型
  - 特征工程
related:              # 关联的 wiki 页面
  - wiki/concepts/履约率.md
  - wiki/entities/PK窗口.md
---
```

### 正文结构

- **开头**：一段简明的定义或摘要（2-3 句话）
- **主体**：按逻辑组织的详细内容，使用 `##` 分层
- **交叉引用**：使用 `[[wiki/path/to/page]]` wiki-link 格式
- **关键数据**：用高亮 `==数据==` 或表格呈现
- **矛盾/存疑**：用 `> [!warning]` callout 标记
- **待补充**：用 `> [!todo]` callout 标记

### 页面类型说明

| 类型 | 目录 | 说明 | 示例 |
|---|---|---|---|
| **entity** | `wiki/entities/` | 具体的系统、模块、服务、模型版本 | PK模型、PK窗口、冷启动系统 |
| **concept** | `wiki/concepts/` | 抽象概念、指标、方法论 | 履约率、接驾距离、特征工程 |
| **source** | `wiki/sources/` | 单个/多个源文档的结构化摘要 | （按需生成）|
| **overview** | `wiki/` | 全局综述，整合所有知识的鸟瞰图 | overview.md |
| **comparison** | `wiki/` | 对比分析页 | （按需生成）|
| **analysis** | `wiki/` | 用户提问生成的深度分析 | （按需生成）|

## 操作工作流

### 1. Ingest（摄入新素材）

当用户添加新的源文档到 `raw/` 时：

1. **阅读**源文档全文
2. **讨论**关键发现和要点
3. **创建/更新** wiki 页面：
   - 如果是新实体/概念 → 创建对应页面
   - 如果涉及已有实体/概念 → 更新对应页面，整合新信息
   - 标记新旧信息的矛盾之处
4. **更新** `wiki/index.md` — 添加新页面条目
5. **追加** `wiki/log.md` — 记录本次操作
6. **检查交叉引用** — 确保新页面与相关页面互链

### 2. Query（查询问答）

当用户提出问题时：

1. **先读** `wiki/agent-entry.md` 确认阅读顺序和搜索边界
2. **再读** `wiki/index.md` 定位相关页面
3. **深入阅读**相关 wiki 页面
4. **必要时**回溯 `raw/` 源文档获取细节
5. **回答**时引用具体页面和源文档
6. **有价值的回答**可以作为新页面存入 wiki（经用户确认）

### 3. Lint（健康检查）

定期（或用户要求时）检查 wiki 健康度：

- [ ] 页面间是否有事实矛盾？
- [ ] 是否有孤立页面（无入链）？
- [ ] 是否有提到但未创建的概念/实体？
- [ ] 交叉引用是否完整？
- [ ] frontmatter 格式是否规范？
- [ ] index.md 是否与实际页面一致？
- [ ] 是否有可通过搜索补充的知识空白？

## 领域知识要点

### 核心实体

- **PK 决策系统**：聚合平台从多个举手司机中选出胜者的机制
- **PK 模型**：预测司乘组合胜出完单概率的模型（XGB → LR → Deep）
- **PK 窗口**：收集举手司机的时间窗口（静态 4s / 动态 0-8s / RL）
- **冷启动**：新商家/新城市缺少历史数据时的特征替代方案
- **倾斜策略**：对特定商家或司机群体的打分加权调整
- **毛利因子 / 治理因子**：引入额外决策维度的策略

### 核心概念

- **履约率/完单率**（CR）：司乘匹配后是否完成订单
- **接驾距离**：司机接到订单后前往乘客的距离
- **连环派**：司机在完成当前订单途中接到下一个订单
- **半指派**：介于全指派和全抢单之间的分单模式
- **AUC**：模型离线评估核心指标
- **PK 打分 = 模型计算 + 打分倾斜**
