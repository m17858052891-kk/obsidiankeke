# 冷启动系统

冷启动系统解决新商家/新城市上线时司机缺少历史行为数据的问题。当司机在某城市近 14 天的完单数不足 n 单时，用**城市级中位数特征**替代个体历史特征，确保 PK 打分处于合理中间水位，不会因数据缺失导致异常高分或低分。

## 核心机制

| 要素 | 说明 |
|---|---|
| **触发条件** | 司机在目标城市近 14 天完单数 < n |
| **替代方式** | 用城市级中位数替代司机维度特征 |
| **生效期** | ==14 天==（到期后使用司机真实数据）|
| **目标效果** | 冷启动期间 PK 打分处于中位水平 |

## 冷启动方式（按端）

| 端 | 替换方式 | 说明 |
|---|---|---|
| PBD 端 / 滴滴端 | cp_id 替换 | 用已有商家的特征代替新商家 |
| 小猪端 | driver_id 替换 | 用已有司机的特征代替新司机 |

两种方式均与分单系统联动，确保分单和 PK 环节的冷启动一致。

## 自动化实现

冷启动配置已实现**全自动化**：

1. **周级参数生产**：自动计算各城市的中位数特征
2. **新商家检测**：自动发现新上线的商家/城市
3. **配置下发**：自动将冷启动参数写入线上配置
4. **监控告警**：冷启动城市的模型打分和胜率异常检测

## 宏鹄出租车冷启动

宏鹄在出租车品类的冷启动是一个重要案例：
- 监控城市包括：广州（乐满分出行）、哈尔滨（万顺叫车）、福州（天府小鹿）等
- ==2025-03-20== 决定全国放量
- 放量后持续监控 PK 打分均值和胜率变化

## 花小猪冷启动

花小猪端的冷启动配置自动化：
- 端到端自动化流程
- 支持自动检测新城市开服
- 14 天冷启动周期后自动退出
