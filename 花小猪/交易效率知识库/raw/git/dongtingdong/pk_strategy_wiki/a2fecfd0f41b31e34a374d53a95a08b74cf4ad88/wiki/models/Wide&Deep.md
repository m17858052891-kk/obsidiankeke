# Wide&Deep 模型

Wide&Deep 是 PK 可解释模型的 V4 结构升级，借鉴 Google Wide&Deep 框架，在保留司机排序特征线性可解释性的同时提升乘客、供需画像表达能力。该模型最终采用乘客履约:司机履约 = ==0.9:0.1==，并于 ==2026-07-03 完成 100% 流量放量==，是当前线上 PK 打分模型。

> [!info] 版本名
> “V4 Deep&Wide”“LR26-010”“策略文档 V1.0”与历史材料中的“深度模型 v1.2 / `pk_deep_explained_model v2`”指向同一条上线策略链路，分别是策略代际、评审编号、文档版本和模型实验版本。

## 动机

| 对比 | LR | Deep |
|---|---|---|
| AUC | ~0.735 | ~0.765 |
| 可解释性 | 权重透明 | 黑盒 |

LR 模型 AUC 比深度模型低 ~3pp，希望兼顾可解释性和精度。

## 架构设计

```
┌─────────────────────────────────────────────┐
│                 融合模块                      │
│     PK打分 = pas_weight × 乘客履约率          │
│            + dri_weight × 司机履约率           │
├──────────────────┬──────────────────────────┤
│  乘客履约率 LR    │    司机履约率 LR           │
│  (P+2+O+C+D')   │    (2+O+C+D)             │
├──────────────────┴──────────────────────────┤
│     Deep 模块            │   Wide 模块        │
│  乘客画像 → P维输出       │  订单特征(O维)      │
│  供需+订单 → 2维输出      │  司机特征(D维)      │
│  (不影响PK排序)          │  司乘特征(C维)      │
│                          │  (影响PK排序)       │
└──────────────────────────┴───────────────────┘
```

### 四大模块

| 模块 | 输入 | 作用 | 影响 PK 排序？ |
|---|---|---|---|
| **Deep** | 乘客画像 + 供需画像 | 高维非线性提取，优化权重学习 | 否 |
| **Wide** | 订单 + 司机 + 司乘特征 | 可解释排序依据 | ==是== |
| **输出** | Deep + Wide 拼接 | 两个子 LR：乘客完单率 + 司机完单率 | — |
| **融合** | 外部配置权重 | 线性融合：`pas_weight + dri_weight` | — |

### 特征空间

| 特征维度 | 特征 | 需建设？ |
|---|---|---|
| 订单特征 | 城市、呼叫时间、订单里程等 | 已建设 |
| 司乘特征 | 是否连环派、指派模式、接驾距离、预估价等 | 已建设 |
| 供需特征 | 格子近 X 分钟发单数、空车司机数等 | 已建设 |
| 司机特征 | 司机近 X 天（分场景）的拒单率、取消率、完单数等 | 已建设 |
| **乘客特征** | 乘客近 X 天应答后取消率、完单数、平均订单里程等 | ==需要建设== |

## 离线评估

### v1.2（距离/2 输入等效 2 倍权重）

| 目标 | Wide&Deep | LR | 增益 |
|---|---|---|---|
| 乘客履约率 | 0.701 | 0.675 | ==+2.6pp== |
| 司机履约率 | 0.825 | 0.788 | ==+3.7pp== |
| 综合 | 0.683 | 0.722 | ==-3.9pp== |

> [!warning] 综合 AUC 下降
> 虽然分别建模的子任务 AUC 均有提升，但融合后综合 AUC 反而下降。
> - v1.1 因距离权重不一致被叫停（LR 2 倍，Deep 未倍增）
> - v1.2 通过距离/2 输入等效 2 倍权重后差距从 -4.6pp 缩小到 -3.9pp

### 排序一致性（SENet 基准）

- [[wiki/models/组件技术.md#SENet|SENet]] 模型评估表明：==89.6%== 的司乘对排序与 LR 一致
- 53% 订单仅 1 个司机（无需排序），47% 有多司机参与排序

## 在线实验与最终决策

### 全国 PID 实验（2026-04-07 至 2026-04-13）

| 组别 | 乘客:司机 | CR | 接驾距离 | 决策 |
|---|---:|---:|---:|---|
| 实验组 1 | **0.9:0.1** | +0.03pp，不显著 | **-60.32m** | ==最终放量== |
| 实验组 2 | 0.8:0.2 | **+0.17pp，显著** | -52.65m | 未放量 |
| 实验组 3 | 0.7:0.3 | +0.10pp，显著 | -44.58m | 未放量 |
| 实验组 4 | 0.6:0.4 | +0.09pp，显著 | -33.10m | 未放量 |

> [!warning] “最优组”口径已变更
> 旧摘要按 CR 增益将 0.8:0.2 称为最优组；最终 LR 评审把完单和 CR 作为不显著负约束，优先选择交易效率收益，因此放量 0.9:0.1 组。

最终放量组相对 V3 LR：

| 指标 | 变化 | 说明 |
|---|---:|---|
| 人均完单 | -0.16% | 不显著 |
| CR | +0.03pp | 不显著 |
| 应答后乘客取消 | **-0.16pp** | 显著 |
| 应答后司机取消（含改派） | **+0.44pp** | 显著，主要风险 |
| 单均预估接驾距离 | **-60.32m** | 显著 |
| 单均预估接驾时长 | **-9.6s** | 显著 |
| 司机接驾时长 | **-2.41%** | 显著 |
| 乘客 ETP | **-1.64%** | 显著 |
| 自营 / 宏鹄 / API 人均完单 | +1.27% / -1.08% / +0.51% | 商家结构变化 |

### 时间片验证与推全

7 城时间片实验（2026-05-25 至 2026-06-07）显示：乘客 ETP -2.21%、司机接驾时长 -4.80%、完单 +0.27%、CR +0.14pp。之后按 30% → 80% → 100% 放量，2026-07-03 推全。

80% 流量评估保持稳定：司机接驾时长 -2.45%、乘客 ETP -1.81%、应答后乘客取消 -0.1pp、完单不显著 -0.05%、CR 不显著 +0.01pp。

### 工程配置

| 参数 | 含义 | 线上 LR | 深度模型 |
|---|---|---|---|
| model_type | 模型类型 | lr | deep |
| model_name | 模型名称 | pk_hxz_finish_rate_6 | pk_deep_explained_model |
| pas_score_weight | 乘客权重 | -1（不启用） | 0.9 / 0.8 / 0.7 / 0.6 |
| dri_score_weight | 司机权重 | -1（不启用） | 0.1 / 0.2 / 0.3 / 0.4 |

## 状态与路线图

| 项目 | 当前结论 |
|---|---|
| 线上状态 | ==V4 Deep&Wide 0.9:0.1 已于 2026-07-03 推全== |
| 放量标准 | 完单和 CR 不显著负；ETP + 司机接驾时长至少优化 0.1%；答后乘客取消 -0.1pp |
| 2026 Q3 | 加入司乘序列特征，升级 OneTrans |
| 2026 Q4 | 引入乘客个性化 |

机制上，V4 增大接驾距离权重占比约 22pp，换来距离与乘客取消改善；同时弱化司机拒单/取消特征，导致含改派司机取消上升。后续应加入“司机取消改派次数”特征，控制这一跷跷板。

## 下一代演进：约束-最小化范式（V5）

> [!info] 2026 Q2 启动的下一代方案
> [[wiki/entities/约束履约率最小化接驾距离策略.md|约束履约率最小化接驾距离策略]] 是 V4 Deep&Wide 之后的下一代方案，主要变化：

| 维度 | V4 Deep&Wide | V5 约束-最小化 |
|---|---|---|
| **优化目标** | 打分仍为 `α·f_p + (1-α)·f_d`；放量决策已改为约束完单/CR、优化 ETP 与接驾时长 | **约束 CR 不负，最小化接驾距离** PK 分 = `λf − d` |
| **建模任务** | 双任务（is_o_finish + is_d_finish）| **3 分类**（司机取消 / 乘客取消 / 完单），消除协变量偏移 |
| **模型结构** | Deep+Wide 拼接 | **多域多专家**（EPNet Gate NU + 多 Expert，类 PEPNet/PLE）|
| **可解释性** | Wide 子模块直接可解释 | **LR 蒸馏深度模型软标签**（80%+，城市×商家 95%）|
| **预期 AUC** | 综合 v1.2 = 0.683（-3.9pp vs LR 子任务）| ==+3pp== |
| **距离结果** | 最终放量组 -60.32m；80% 放量司机接驾时长 -2.45% | 离线模拟 -20m (-1.21%) @ λ=5340 |

V5 处理了 Wide&Deep 当前的两个痛点：
1. **协变量偏移**：双任务建模在过滤后的子集上训练，3 分类直接建模订单状态消除偏移
2. **可解释下降**：v1.2 综合 AUC -3.9pp，深度模型与 LR 排序一致性仅 89.6%；V5 用 LR 蒸馏达成 80%+ 可解释率
