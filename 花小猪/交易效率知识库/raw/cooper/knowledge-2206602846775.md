# 一、问题定义

### 推荐系统ID特点

==现代推荐系统中ID特征的几个特点:==

- **==高基数:==** ==在线内容平台每天都会产生大量的新内容, 这使得推荐系统中的ID特征数量是极其庞大的==

- **==曝光偏差:==** ==或者说是流行度偏差, 推荐系统中少量内容占据&构成了大多数用户的曝光与转化（头部效应，循环推荐）==

- **==生命周期短:==** ==比如短视频内容, 其在推荐系统中的从冷启到退场的生命周期可能非常短==

### ID Embedding做法

#### **（1）Individual Embedding 个体嵌入 (IE)​**​ 

- 含义：每个原始ID都被分配一个单独的嵌入表行。**由于系统资源的限制，这种方法在生产场景中并不现实。**

- **局限性**：

	- **资源消耗**：对于现代推荐系统中海量的item，给每个item学习一个单独的embedding向量会是极其耗费资源的。

	- **新冷样本**：更重要的是，由于长尾样本的数据稀疏性，对于长尾样本的embedding无法学习得很好。

#### **（2）Random Hash 随机哈希 (RH)​**​ 

==由于推荐系统的内容非常庞大, 业界会普遍使用 **随机哈希（**==**Random Hash）**==来完成**内容ID到Embed Tabel具体哪一行的映射过程, 以控制模型的大小**。==

- 含义：当嵌入表行数H远小于原始ID数量I时（即I ≈ a·H，a > 1），我们可以通过随机哈希将原始ID映射到有限的嵌入表行上，即 *f*RH​(*x*):=*h*(*x*)，其中 *h*(*x*):\[1..*I*\]→\[1..*H*\] 是一种标准哈希函数，例如**模哈希**​（modulo hash）。这种方法会导致随机的**哈希碰撞**​（hash collisions），平均碰撞因子为a（即平均每个嵌入表行对应a个原始ID）。

- **==局限性==**==：==

	- **==语义鸿沟==**==：两个内容几乎相同的item，它们的随机ID可能天差地别，**模型无法理解它们内容上的相似性**，无法将从其中一个学到的知识迁移到另一个，造成信息浪费；====可能两个完全语义不相似的ID都映射到了Embed Table的同一行, 导致embed的权重更新矛盾。==

	- **==冷启动困境==**==：====随机ID缺乏语义，导致模型难以泛化到新物品和长尾物品，冷启动问题严重==

#### （3）Content Embedding **==直接使用内容Embed==**

- **==含义==**==：使用多模态的内容Embedding(冻结)直接替换传统推荐系统的ID Embed==

- **==局限性==**==：==

	- ==这种方式ID Embed不再更新, 效果通常是大打折扣的。==

	- ==一方面是因为缺少了item-level的memorization, 另一方面也是内容空间和用户行为空间的不一致。==

#### ==（4）Semantic ID 语义ID（SID）==

**==目标是找到一种既能保留ID的记忆能力，又能引入内容语义以支持泛化的方法==**

形式上，语义ID被定义为一个长度为 m 的码字（Codeword）元组 (c₀, c₁, ..., cₘ₋₁)，其中每个码字来自一个独立的码本（Codebook）。一个理想的语义ID系统应具备以下关键属性

- ​**唯一性**​：能唯一标识一个物品。

- ​**语义相似性**​：内容相似的物品，其语义ID应有重叠的前缀。例如，ID为 `(10, 21, 35)` 的物品应与ID为 `(10, 21, 40)`的物品更相似，而非与 `(10, 23, 32)` 的物品相似。这为模型的泛化能力奠定了基础。

- ​**层次结构性**​：ID序列从前往后体现了从粗粒度（如品类）到细粒度（如具体属性）的语义层次

语义ID的生成本质上是将**高维、连续的物品内容嵌入（Content Embedding）**进行**离散化、量化**的过程。

层级语义表示，避免哈希碰撞

### **（3）基于语义 ID 的生成式检索**

- **序列构建**：按时间顺序整理用户的物品交互历史，对每个用户，将其交互按时间排序成 (item1,…,itemn)，将每个 item 展开为其 m 个 codewords，使输入序列为(c\_{1,0}, …, c\_{1,m-1}, c\_{2,0}, …, c\_{n,m-1})，seq2seq 模型的目标是生成item\_{n+1}​ 的 codeword 元组 (c\_{n+1,0}, …, c\_{n+1,m-1})

- **生成式预测任务**：将上述构建的物品序列，训练**seq2seq**模型直接**预测下一个物品的语义 ID**。

- **特殊情况说明**：由于生成式框架的特性，可能出现生成的语义 ID 与语料库中物品不匹配的情况，e.g.：如果物品库中只有 `(1, 5, 3)` 和 `(2, 4, 6)` 这样的 Semantic ID，模型有可能生成 `(1, 4, 6)`，这不是任何真实物品。==但作者在数据上的实验表明概率低（对于 Top-10 预测，invalid ID 比例约 0.1% − 1.6%），可通过增加 beam size 并过滤无效 ID 或使用 prefix matching（前缀匹配，利用层级 ID）等方法处理。==

## **==谷歌：使用语义ID提升推荐系统ID Embed泛化性 RecSys'24==** 

《Better generalization with semantic ids: A case study in ranking for recommendations》

<https://dl.acm.org/doi/10.1145/3640457.3688190>

==本文主要讨论的问题是：如何基于前面**层次化的语义ID将具体的一个内容映射到传统ID Embedding Table的具体某几行**(即某几个下标), 以形成语义IDEmbed表的映射关系。如果将所有出现过的语义ID看作语料, 这个过程其实就像是NLP的分词。==

N-gram（基于N-gram）和SPM（基于SentencePiece模型）是两种用于在推荐排序模型中适配和使用语义ID的具体方法。它们的目标是将语义ID序列（离散的整数代码）映射到可学习的嵌入中，从而在保持记忆能力的同时提升泛化性。

### （1） N-gram-based (基于N-gram的方法)

这种方法通过将语义ID序列中的代码按固定长度（N）进行分组来创建“子词”。

- **原理**：

	- 利用SID代码将其分为长度为N的子词。每个子词关联一个可学习的嵌入，从而捕获N-gram内的语义关系。

	- 物品的表示是通过对该物品中所有N-gram子词的嵌入求和来构建的。

- **具体例子**：

	- **Unigram (N=1)**：表示为单个代码的序列，例如  $$(c_v1), ..., (c_vL)$$。这会创建 L个子词。

	- **Bigram (N=2)**：由不重叠的代码对组成，例如$$(c_v1, c_v2), ..., (c_v{L-1}, c_vL)$$。这会创建 L/2 个子词。

- **嵌入表结构**：

	- 针对每个N-gram组学习一个单独的嵌入表。由于每个代码的基数为K，N-gram组的嵌入表包含 K^N 行。

- **优缺点**：优点是简单直观，缺点是基于预定义的N-gram大小进行固定分组，限制了适应特定语料库特征的能力；嵌入表的行数随N呈指数级增长，带来显著的内存负担。

### （2）SPM-based (基于SentencePiece模型的方法)

为了解决N-gram方法的局限性，文章提出使用SentencePiece模型（SPM），这是一种更自适应且高效的解决方案。

- **原理**：

	- 利用SPM根据展示物品的分布动态学习语义ID的子词。

	- 它允许动态长度的子词：将流行的、经常共现的代码自动组合为单个子词；而很少共现的代码则回退到unigram（单个代码）。

- **嵌入表结构**：

	- 学习一个单一的嵌入表，表中的每一行对应一个特定变长子词。

	- 可以在固定的嵌入表大小限制下，通过自适应地构建子词词汇表，来优化语义ID的表示。这使得可以在“泛化”和“记忆”之间进行显式控制。

- **自适应性与效率**：

	- **减少查询次数**：对于训练数据中的头部（常见）视频，SPM可以动态减少嵌入查询的次数，而平均查询次数与固定N-gram方法相当。

	- **性能表现**：在使用大型嵌入表时，SPM-SID的表现持续优于N-gram表示，特别是在针对冷启动物品的CTR/1D AUC指标上显示出更强的泛化能力。

### （2）效果比较

==论文对比了Individual embeddings、Random hashing、以及论文所提的前缀Semantic ID方法在不同热度Item下的表现==

> **个体嵌入 (IE)​**​ 每个原始ID都被分配一个单独的嵌入表行，即I=H，且嵌入查找函数定义为 *f*IE​(*x*):=*x*。尽管由于系统资源的限制，这种方法在生产场景中并不现实，但我们仍将其作为一个理想的基准模型进行说明。在评估阶段，对于在训练集中未出现过的ID，系统会将其映射到一个**随机初始化且未经过训练**的嵌入向量。

> ​**随机哈希 (RH)​**​ 当嵌入表行数H远小于原始ID数量I时（即I ≈ a·H，a > 1），我们可以通过随机哈希将原始ID映射到有限的嵌入表行上，即 *f*RH​(*x*):=*h*(*x*)，其中 *h*(*x*):\[1..*I*\]→\[1..*H*\] 是一种标准哈希函数，例如**模哈希**​（modulo hash）。这种方法会导致随机的**哈希碰撞**​（hash collisions），平均碰撞因子为a（即平均每个嵌入表行对应a个原始ID）。

> ​**语义ID (SemID)​**​ 项目的**内容嵌入**​（content embeddings）从一个**多模态**的（图像和文本）​**基础模型**​（foundation model）中提取。该基础模型在一个包含大量项目的数据集上，通过图像与文本的对齐目标进行**预训练**​（例如CLIP模型）。随后，使用过去三个月所有目标项目的内容嵌入来训练一个 ​**RQ-VAE**​（残差量化变分自编码器），其中设定码本长度L=3，码本大小K=2048。我们采用第4.2节中提到的**前缀3-gram参数化**方法，即 *f*SemId​=*p*∘*s*。
