# 离线仿真系统Code Review

本次实现的算法核心是一种**带逐日约束反馈的近似参数迭代算法**==：从已有城市参数出发，每小时维护三个乘子，通过真实数值计算选择OD及动作，修复GS司机容量冲突，再调整参数和小时预算，保存途中最好的结果。==

# ==1 数据粒度==

| **名词** <br> | **含义** <br> |
| --- | --- |
| O、D、OD <br> | 订单、司机、一个候选订单司机组合 <br> |
| Full / Half / Grab <br> | 同一OD的三种可选动作 <br> |
| 完整矩阵 <br> | 同一次匹配上下文的全部合法候选边，不能只留下部分OD后冒充完整矩阵 <br> |
| 矩阵键 <br> | `dt, service_city, hour, assignment_type, d_group, uu_id` <br> |
| 参数键 <br> | 当前为 `service_city, hour`；同小时由自营、鸿鹄及TP、GS共享 <br> |
| 验收键 <br> | `dt, service_city`；全天合并两类运力及TP、GS <br> |
| q <br> | 一个OD动作的有效权重：`r × a × (1-e)` <br> |
| f_hat <br> | 加权履约指标，不等于原始完单概率f <br> |

训练期为2026-09-01～09-07。**某小时只要在任一实际训练日期存在矩阵，就参与训练**；缺失日期、缺失小时不生成虚拟OD。没有训练数据的小时导出原城市参数，并标记回退来源。

# 2 目标、约束和模拟基线

## 2.1 优化目标

对最终选中的OD动作，用z表示是否被选中：

$$\displaystyle q=ra(1-e),\qquad \hat f=0.9\frac{f}{f+c}+0.1\frac{f}{f+d}$$

Full、Half的r为1；Grab使用`grab_r`。距离D使用米值，当前尺度为`D_cap=5000`。

$$W=\sum qz,\quad S_D=\sum qDz,\quad \hat F=\sum q\hat fz,\quad C_d=\sum qdz,\quad C_p=\sum qcz$$

城市目标是尽量降低：

$$\displaystyle J_c=\frac{S_{D,c}}{W_c}$$

## 2.2 逐日约束

$$\hat F_{t,c}\ge\hat F^{base}_{t,c}$$

$$C_{d,t,c}\le1.05d_{0,c}W_{t,c},\qquad C_{p,t,c}\le1.05c_{0,c}W_{t,c}$$

其中司乘取消率目标值为20260901-20260907真实播单OD的模型预测值在每个城市的对应播单动作下的平均预测概率。（后续比较评估时也用该目标值的105%作为约束上限，而完单量则用模拟基线的OD完单期望作为约束上限）

## 2.3 模拟基线

- TP：`do_feature_finish_rate_v2`降序贪心，订单司机各容量1。

- GS：订单侧使用该原始分，司机侧使用`log_gs_driver_str`，订单提议稳定匹配。

- 已选OD以Full作为基线动作，再计算q、f_hat和各项指标。

（1）每轮根据当前参数计算每条OD的三动作成本，先对同一OD的Full、Half、Grab取最低成本动作，再对同一订单已有的候选司机取最低成本。

$$Cost_i=q_i\left[ D_i-\rho +\mu_{d,h}(d_i-d_{\max}) +\mu_{p,h}(c_i-c_{\max}) -\mu_{f,h}\hat f_i \right]$$

与原Score的四参数等价关系如下，且Score = -Cost/D_cap

![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1793675406424/NyZbpcJsYAFWeuT5iRbC9/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T112224Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=8135587f3899d803a4dea96efc974e6d84a91053d677814b2f2e0baaaa55aeac)

（2）分阶段求解

- **阶段一：**每个O在所有已召回候选D中选择一个最低Cost的D及动作，不考虑司机容量，所以同一个司机可能被多个订单同时选中；

- **阶段二：**继承阶段一种的参数测算结果和小时预算，每轮依次进行：1）找出GS矩阵中被多个订单同时选中的司机；2）对发生冲突的完整GS矩阵，做容量为1的最小费用匹配；3）使用修复后的结果计算指标，继续更新参数。

==【stage_compare_solver.py中select()函数，计算每个矩阵最大匹配数量K，对冲突司机建立虚拟列，执行最少费用匹配，分配给虚拟列的O则是未匹配】==

（3）小时预算

业务要求完单量及司乘取消约束均逐日达标，不强制每小时都达到原基线，为了保证优化求解每小时参数的松弛性，下面为每个日期、小时维护预算：

$$\sum_h B^F_{t,h}=\hat F_t^{base},\qquad  \sum_h B^d_{t,h}=0,\qquad \sum_h B^p_{t,h}=0$$

计算小时残差，残差为正，表示该小时没有完成当前分配给它的任务；残差为负，表示还有余量。

$$r^F_{t,h}=B^F_{t,h}-\hat F_{t,h}$$

$$r^d_{t,h}=C_{d,t,h}-d_{\max}W_{t,h}-B^d_{t,h}$$

$$r^p_{t,h}=C_{p,t,h}-c_{\max}W_{t,h}-B^p_{t,h}$$

残差相加恰好恢复当天真正的约束残差，比如：$$\sum_h r^F_{t,h} =\hat F_t^{base}-\hat F_t$$，从而实现小时间调剂。

（4）AdaGrad更新三约束乘子

用归一化残差作为次梯度，并用AdaGrad进行梯度自适应更新。其中，用同城市每个小时训练日期种的最差值进行次梯度更新，保证下限稳定性。

==【分析：当残差==$$r^F_{t,h}$$==为正时，表示完单量没有满足小时预期，反馈到梯度更新中使==$$\mu_{h,F}$$==增大，从而提升履约贡献更大的OD的权重，反应到Cost中对应OD成本更小，从而更容易被选中】==

「AdaGrad：自适应梯度下降，根据累计更新次数逐步衰减后续更新梯度，实现稳定更新避免震荡」

（5）距离参数更新

每轮更新距离参考值$$\rho_{k+1}=0.7\rho_k+0.3\frac{S_D^k}{W^k}$$（保留70%的上一轮rho，避免震荡），每5轮重新分配该小时的预算：

【公式一：将约束乘子归一化，按小时约束权重相对分配；公式二：小时预算调剂，0.01为对应调剂步长；公式三：投影映射，避免小时预算总和不满足原全天基线】

分析：当残差为正时（约束没有满足预期），g为正，对应mu提升增加权重，在小时预算中，则适当减轻该小时预算（过程中预算B一直都在减少，但会通过`project_sum`二分搜索实现投影$$B_h^{new}=\operatorname{clip}(\widetilde B_h-\tau,\ 0,\ U_h)$$，从而调整每个小时预算，使总和不变。
