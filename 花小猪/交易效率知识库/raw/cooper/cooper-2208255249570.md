# 组织提效思考

Q：我是否还要参与实现的工作？

A：不要，否则会失控

那么，当人力不足时，需要判断优先级、只推进高优事项，不能兜底，否则会失控

# 一、机制

## 1.1 需求准入

1. follow部门BRD-策略评审流程，不单独承接私下需求

2. 占用主线以外的人力做，否则不做（7月前不承接任何非P0需求）

3. 必须有策略owner，且不是我

## 1.2 项目分层

不同的事情，管理方式不同

1. 简单执行类：周会听结论，无周会时需要填周报

2. 重点复杂项目：项目周会（PK+分单+DO建模）

3. 新人项目：mentor 带 + 我节点 review

4. 技术探索类：双周探索会（AI类）

5. 外部临时需求：进需求池

## 1.3 owner责任机制

每条主线明确owner，owner必须负责

1. 目标：这件事要影响什么指标/业务问题

2. 路径：准备怎么做，为什么这样做

3. 节奏：里程碑和实验计划

4. 风险：当前最大不确定性和依赖

5. 决策：需要我或跨团队拍板的事项

我不是owner！！！我的责任边界

1. 负责方向、取舍、资源、关键风险

2. owner 负责推进、方案细化、实验、协同

3. 我不接 owner 没推进完的实现

## 1.4 新人培养机制

1. 吴健（如果不是mentor）：制定试用期目标

2. mentor：每个新人绑定一个高阶或成熟同学

3. 任务包：前 4 周只做 1-2 周能闭环的小任务

4. 复盘：每周输出一个结论，而不是只报过程

5. 项目：mentor把控整体，拆解子任务；mentor需要对子任务有结果预期、check节点

	1. 新人需要follow整体节奏，完成子任务

mentor权责利

权：能够为新人指定、分配任务

责：负责新人产出

利：指导的产出辅助自己的项目目标达成

## 1.5 技术探索治理

我的看法可能跟老板不同，我需要保证DDO达成的前提下做额外投入

且降本的事情，每个人有参与即可，不用每件事都做，我判断整体效率是低的。降本工具本身只需要使用提效即可，不要自己造轮子

除非能明确给出 占用的人力 与 未来释放的人力（释放的人力可以做什么），需要判断性价比

1. 服务哪个主线问题？

2. 当前假设是什么？

3. 两周内验证什么？

4. 可复用产出是什么？

5. 停止条件是什么？

# 二、会议

周会

- 结论与风险

- 下周todo，是否影响节奏

- 不展开项目细节

项目周会：PK、分单、DO价值

- 决策质量和关键风险

- 阶段性目标

- 最大的不确定性

- 需要讨论的细节

- 下一阶段关键动作和节奏

- 需要我决策、背书或协调什么

新人项目会

- 新人的理解：这个任务要回答什么业务问题、当前产出能支持哪个决策

- mentor的反馈：数据、实验、结论是否可信

- 新人的想法：下一个 1-2 周最小闭环是什么

- 新人的卡点：是业务理解、方法，还是执行

技术探索会

- 探索假设是什么

- 服务哪个主线问题

- 本周期验证了什么

- 有没有可复用产出

- 继续、收敛还是暂停

one one

- 一个月内一周一次，转正前两周一次，转正后一月一次

- 不聊进度，聊人、方法和卡点

# 三、我的边界

应该介入的情况：

- 目标函数或策略方向不清

- 实验结论影响重大决策

- 跨团队依赖或冲突卡住

- owner 方法上卡住，需要你带一次框架

- P0 事故

- 阶段性milestone

不应该介入的情况：

- 没有 owner 的非主线实现：默认进需求池，我不承接

- 业务方说很急但没有收益、影响和截止窗口

- 别人排期失败后让你兜底实现

- 简单执行类任务的细节方案

- 和 PK、平台价值、分单无关的泛 AI 探索
