# 三、算法侧工作明细

> 本章逐个交付物说明：**开发目的 / 输入输出 / 评估方式**。  
> 5 个建模组件对应 V1.0 召回决策三路价值公式：
>
> \\text{value\\\_TP} = \\sigma\_{ij1}\\cdot(1-CAA\_{ij}) - \\lambda'\\cdot p\_{next}(j)\\text{value\\\_GS} = \\sigma\_{ij2}\\cdot(1-CAA\_{ij})\\text{value\\\_hold} = \\beta\\cdot(1-OCR_i)\\cdot E(\\text{finish})\_{\\text{baseline}}

### 3.1 σ — 竞争胜率模型（深度模型，G4）

**开发目的**  
V2.0 召回过滤体系**完全没有显式竞争胜率建模**，过滤规则 `max{BCAA,CCAA} < OCR` 只判断"应答了不比不应答差"，没判断"应答之后能不能赢 PK"，造成大量 PK 必输的无效播单（占用司机听单容量、拉长匹配距离）。σ 是 V1.0 相对 V2.0 的**最大增量项**，预测"已举手后该商家在聚合平台多商家 PK 中获胜"的概率，让决策区分"赢得了"与"赢不了"。

**输入 / 输出**

| 项 <br> | 内容 <br> |
| --- | --- |
| 任务类型 <br> | 二分类（举手后是否 PK 获胜）；输出 \\sigma\_{ijk}=P(\\text{PK获胜}\\mid\\text{已举手},i,j,k)，k\\in\\{TP,GS\\} <br> |
| 样本范围 <br> | 仅**已举手**的 OD 对；排除单商家无 PK 场景；TP/GS 均纳入，用模式特征区分 <br> |
| label <br> | 1 = PK 获胜（应答被聚合平台采纳）；0 = 被其他商家击败。来源：举手日志 + 聚合 PK 结果回流 <br> |
| 输入特征 <br> | 举手时间/速度、举手报价/ETP、商家维度（历史胜率/服务分/车型）、司机维度、竞争环境（同区域活跃商家数/竞对举手数/竞对 ETP 分布）、OD 维度、模式特征（TP/GS）、上下文（城市/时段/天气/热度） <br> |
| 输出接口 <br> | EVE 部署，σ\_TP / σ\_GS **双输出接口**，TP / GS 路径分别调用 <br> |

**评估方式**

- 离线：AUC

- 端到端模拟：完单中性 / 接驾改善方向正确

### 3.2 CAA — 应答后取消率模型（深度模型，G3）

**开发目的**  
V2.0 用 BCAA（司机取消）+ CCAA（乘客取消）两个独立 XGBoost，过滤规则 `max{BCAA,CCAA} < OCR + 偏置`，分城市人工调偏置项、维护成本高，且不直接服务于"完单最大化"。V1.0 合并为**单一深度 CAA 模型**，直接进入价值公式的 1-CAA 项（即"应答后真正能完单的概率"），减少线上调用与配置项。

**输入 / 输出**

| 项 <br> | 内容 <br> |
| --- | --- |
| 任务类型 <br> | 二分类（应答后是否取消）；输出 CAA\_{ij}=P(\\text{应答后取消}\\mid\\text{已应答},i,j) <br> |
| 样本范围 <br> | 所有**已应答（commit）**且达到完单/取消终态的 OD 对；剔除未结束订单、异常订单；平台强制取消单独打标 <br> |
| label <br> | 1 = 应答后完单前被取消（乘客 OR 司机，OR 合并）；0 = 应答后完单。来源：应答日志 + 取消/完单日志 <br> |
| 输入特征 <br> | OD 实时（接驾距离/ETP/送驾里程/路况）、司机维度（历史取消率/完成率/在线时长）、乘客维度（历史取消率/等待行为/用户分）、等待维度（已等待时长/轮次）、价格维度、上下文 <br> |
| 输出接口 <br> | EVE 部署，统一 CAA 单接口（合并方案）；fallback 为双任务头（BCAA+CCAA，决策时用 1-(1-BCAA)(1-CCAA) 包装为单输出） <br> |

**评估方式**

- 离线：AUC ≥ V2.0 BCAA+CCAA 联合等效；PR-AUC（尤其高接驾距离子集）显著优于 V2.0；ECE < 0.05（分城市）

- 合并 vs 双 head：观察司机取消子集 vs 乘客取消子集的校准差异，G3 上线前用离线指标拍板选型

- 端到端模拟回放：与 σ 联合下 TP/GS/Hold 比例符合预期

### 3.3 OCR — 订单流失率模型（深度模型，G2）

详见 [WIP/算法侧开发工作/召回V1.0模型/OCR建模/OCR建模文档.md](WIP/算法侧开发工作/召回V1.0模型/OCR建模/OCR建模文档.md)

**开发目的**  
OCR 是 value_hold 的核心因子——"不播单时订单存活到下一轮的概率"。V2.0 用 T 维度（仅订单视角）线性+对数公式，人工调系数；曾上线 ODTP-XGB 但**线上效果差于 T 公式**（因 60% 订单 10s 内完成播单，首末轮样本特征除等待时间外几乎无差异，模型难学）。V1.0 升级为 ODTP 维度深度模型，引入司机维信息打破"轮次差异=等待时长差异"瓶颈。

**输入 / 输出**

| 项 <br> | 内容 <br> |
| --- | --- |
| 任务类型 <br> | 二分类（本轮不播单时是否流失）；输出 OCR_i=P(\\text{流失}\\mid\\text{本轮不播单},i) <br> |
| 时间窗口 <br> | **一个轮次间隔（约 3 秒）**，非订单生命周期取消概率 <br> |
| 样本范围 <br> | 历史上某轮次**未被向任何司机播单**的订单（含召回失败/司机集合空/未参与匹配）；区分"未播单 vs 已播单未应答"只取前者 <br> |
| label <br> | 1 = 该轮到下一轮（\~3s）期间流失（乘客取消 OR 被他商应答）；0 = 存活到下一轮。来源：分单轮次日志 + 取消/应答回流 <br> |
| 输入特征 <br> | 订单已等待维度、订单基本信息（品类/价格/距离/时段）、当前供需状态、乘客耐心、竞争环境、订单内在属性（起终点热度等）、上下文 <br> |
| 输出接口 <br> | EVE 部署，OCR 接口；**保留 T 公式 feature flag 一键回退** <br> |

**评估方式**

- 离线：AUC 显著 > T 公式（阈值在 W2 后定）；PR-AUC 显著 > ODTP-XGB；ECE < 0.05（分城市/时段）

- 端到端模拟回放：完单中性 / 接驾改善方向正确；**深度模型必须在 AUC、PR-AUC、模拟完单率三方面均显著优于 T 公式才上线**

- Shadow（1 周）：分布稳定，与 T 公式无系统性偏差

- 兜底回退 ready：T 公式开关、残差模型（深度=T 公式+Δ）fallback

- ⚠️ 核心风险：样本删失（多数订单 < 3s 内被播单，无真实"未播单 3s"观测）→ 可选离散时间生存模型；W2 末锁定"二分类 vs 生存模型"选型

### 3.4 E(finish) — 期望完单分桶查找表（离线统计，G2）

详见 [WIP/算法侧开发工作/召回V1.0模型/E_finish建模/E_finish建模文档.md](WIP/算法侧开发工作/召回V1.0模型/E_finish建模/E_finish建模文档.md)

**开发目的**  
value_hold 需要"本轮不播，下一轮的期望完单 E(\\text{finish})\_i^{T+1}"。该项**递归定义**（下一轮又依赖再下一轮），直接建模 label 不稳定、复杂度高。V1.0 用**历史分桶频率统计量**近似——把相似场景的历史最终完单率直接作为 E(finish)，简单、可解释、迭代成本低。

**输入 / 输出**

| 项 <br> | 内容 <br> |
| --- | --- |
| 任务类型 <br> | 分桶频率统计（非模型训练，但按建模任务严谨度对待） <br> |
| 样本范围 <br> | 所有历史订单按**订单 × 轮次**展开（一个订单经历 N 轮贡献 N 条样本）；同一订单各轮 label 相同但桶位随轮次变化 <br> |
| label <br> | 1 = 该订单生命周期内最终完单；0 = 未完单（取消/流失） <br> |
| 分桶维度 <br> | 城市 × 时段（早高峰/平峰/晚高峰/夜间）× 供需档（3-5 档）× 已等待轮次（0,1,2,3,4+），约**数千个桶** <br> |
| 输出 <br> | E(\\text{finish})\_{\\text{baseline}}(\\text{city},\\text{slot},\\text{SD},\\text{rounds})\\approx P(\\text{最终完单}\\mid\\text{当前桶})；KV/内存查表，分单时 O(1) <br> |
| 更新频率 <br> | 每日离线 Spark/Hive 全量重算 <br> |

**评估方式**

- 桶规模符合预期（数千量级），无样本量过低的关键桶；维度退化兜底（city×slot×SD×rounds → … → 全局）覆盖所有 case

- 离线：四维分桶 vs 全局均值的端到端模拟完单率提升符合预期

- 在线查表延迟 < 1ms（P99）

- Shadow（1 周）：命中率 > 99%；统计值分布稳定（vs 上周 KL 散度 < 阈值，阈值【待策略补充】）

- 每日 pipeline 跑通，无失败/数据延迟告警

- ⚠️ 语义偏差：查表用"当前轮最终完单率"近似"T+1 起期望完单"，差一轮；若离线偏差大加轮次微调因子

### 3.5 β — hold 激进度系数（策略参数，G2 起、事后调）

详见 [WIP/算法侧开发工作/策略参数/β-hold激进度系数.md](WIP/算法侧开发工作/策略参数/β-hold激进度系数.md)

**开发目的**  
β 是 value_hold 的整体乘子，在**不重训模型**前提下用单一旋钮调节"完单 vs 接驾/ETP"的 Pareto 权衡（β>1 收紧召回更倾向 hold，β<1 扩张召回）。同时把 V2.0 分散的、需 by 城市维护的偏置项收敛为一个全局/少量分档系数，降低运维成本。

**输入 / 输出（配置参数，非模型）**

| 项 <br> | 内容 <br> |
| --- | --- |
| 配置形式 <br> | Apollo 配置项，热生效 <br> |
| 默认值 <br> | β = 1（实验期固定不动，保证 G2/G3/G4 收益干净归因） <br> |
| 粒度 <br> | 全局优先；必要时按城市/时段分档（`beta_by_city_time`，分档 ≤ 10 个，走配置评审） <br> |
| 候选扫描值 <br> | β ∈ {0.9, 0.95, 1.0, 1.05, 1.1} <br> |

**评估方式（调优时机：G4 跑完后）**

- 按 G4 vs Baseline 的 Pareto 落点决定方向：完单中性+接驾↓1% → 不调；完单↑但接驾↑/微降 → 调高 β；完单↓+接驾↓更多 → 调低 β

- 离线：用 G4 数据回放模拟不同 β 下 TP/GS/Hold 比例与模拟完单率，缩小线上扫描空间

- 线上：3-5 天短周期 AB，每轮 5-10% 流量

- 监控：β 偏离 \[0.8,1.2\] 人工 review；调整后 24h 完单率变化 > 1pp 回滚；TP/GS/Hold 比例漂移 > 5pp 告警

- 协同约束：调 β 前先确认 OCR（ECE < 0.05）/ E(finish)（命中率 > 99%）无系统性偏差，不靠 β 掩盖模型问题

### 3.6 λ' — TP 惩罚项系数（策略参数，G3 上线前调）

详见 [WIP/算法侧开发工作/策略参数/λ-TP惩罚项系数.md](WIP/算法侧开发工作/策略参数/λ-TP惩罚项系数.md)

**开发目的**  
原始惩罚项 \\lambda\\cdot p\_{next}\\cdot\\Delta CAA 中 \\Delta CAA 决策时刻不可观测，V1.0 把其均值效应吸收进超参 \\lambda'（\\lambda'\\approx\\lambda\\cdot\\mathbb{E}\[\\Delta CAA\]），惩罚项简化为 \\lambda'\\cdot p\_{next}。λ' 决定 TP 入口开放程度——值越大 TP 越收敛，越小越开放，直接影响"TP 入口放开"的收益兑现。

**输入 / 输出（配置参数，非模型）**

| 项 <br> | 内容 <br> |
| --- | --- |
| 配置形式 <br> | Apollo 配置项，热生效 <br> |
| 默认值 <br> | W4 离线调优后给出（先无默认，G3 上线前调出） <br> |
| 粒度 <br> | 全局优先 / 按城市分档 <br> |
| 参数空间 <br> | \[\\lambda\_{\\min},\\lambda\_{\\max}\] 对数尺度 5-10 个候选；与 p_next 半径 r、归一化方式**联合网格扫描** <br> |

**评估方式**

- 主指标：端到端模拟完单率（中性持平）、模拟接驾时长（↓）

- 观测指标：TP 决策比例（与产品对齐目标，如 < 30%【待策略补充】确认目标区间）、GS 比例、分城市/时段 TP 比例方差

- 联合扫描 (r, 归一化方式, λ')，选最大化模拟收益的组合；用 V2.0 + 已 ready 的 σ/CAA/OCR 做回放

- 上线前 sanity check：最优 λ' 不落在边界（避免过拟合）；TP 比例分布合理

- 实验期锁定不动；监控 TP/GS 比例与离线预期偏差 > 5pp、p_next 分布漂移告警

- 协同约束：σ 模型再训练后需重跑 λ' sanity check；σ 系统性偏差导致 TP 异常时先修 σ
