## 二、特征使用说明

本节介绍乘客和司机维度特征使用方法。

乘客特征特征是在【流量渠道】\*【运力类型】\*【是否连环派】叉乘维度下的统计值，若需要使用低维度下的统计特征，需要使用group by聚合。

例如统计乘客在【passenger_id】\*【是否连环派】维度下的【近7天累计完单应付金额】：

```PlainText
select 
    passenger_id, 
    is_serial_assign,
    sum(gmv_amt_7d) as gmv_amt_7d
from 
    kflower_strategy.pas_behavior_accum_df
where 
    dt = '{$BIZ_DATE_LINE}'
group by passenger_id, is_serial_assign
```

对于率值特征不可以直接通过group by聚合，例如统计乘客在【passenger_id】维度下的【近7天单均价格】：

```PlainText
select 
    passenger_id, 
    nvl(sum(gmv_amt_7d) / (case when sum(finish_cnt_7d) > 0 then sum(finish_cnt_7d) else 1 end), 0) as asp_amt_7d
from 
    kflower_strategy.pas_behavior_accum_df
where 
    dt = '{$BIZ_DATE_LINE}'
group by passenger_id
```

司机特征是在【流量渠道】\*【是否连环派】叉乘维度下的统计值，若需要使用低维度下的统计特征，需要使用group by聚合。

例如统计司机在【driver_id】\*【是否连环派】维度下的【近7天应答数】：

```PlainText
select 
    driver_id, 
    is_serial_assign,
    sum(answer_cnt_7d) as answer_cnt_7d
from 
    kflower_strategy.dri_behavior_accum_df
where 
    dt = '{$BIZ_DATE_LINE}'
group by driver_id, is_serial_assign
```

## 三、取数使用技巧

**1、尽量不要使用select \***

使用select \* 会影响SQL的执行效率，查询时可以使用需要查看的字段提效。

**2、order by 后面尽量加limit**

order by需要将所有结果放入内存中才能排序。

如果查询结果条数较多，不添加limit就会导致查询效率非常底，还会严重占用集群的内存资源。

**3、分区设置合理**

建议查询时间范围不要超过一周，查询三个月，半年，一年的时间跨度，查询会比较慢。

**4、year/month/day三分区查询优化**

通过concat_ws('-', year, month, day) = '${BIZ_DATE_LINE}'查询，先拼接字符串再比较，速度较慢。

通过直接命中分区优化提速：

```PlainText
where year  = substr('${BIZ_DATE_LINE}', 1, 4)
  and month = substr('${BIZ_DATE_LINE}', 6, 2)
  and day   = substr('${BIZ_DATE_LINE}', 9, 2);
```

**5、避免在where子句中进行表达式或函数操作**

| 反例 <br> | 推荐 <br> |
| --- | --- |
| where A / b = c <br> | where A = b \* c <br> |
| where substring(A,1,3)= 'abc' <br> | where A like 'abc%' <br> |
| where datediff(dt, dt2) = x <br> | where dt = date_add(dt2, x) <br> |
| where **function**(field) = x <br> | select ... <br>from ( <br>   select order_id, **function**(field) as new_field <br>   from table <br>) t <br>where new_field = x <br> |

where子句等号左侧应尽量避免表达式或函数操作，也可以再套一层子查询的方式在外层进行过滤，避免索引失效从而提升查询性能。

1.需要在SQL中将数据中的回车换行等特殊符号去掉，或替换成其他字符。下面的例子是使用regexp_replace函数将数据中的回车或换行替换成空（即删除）。其他字符的替换可以酌情处理

3.如果要把列col_sql_str中的双引号去掉，可以这样写：regexp_replace(col_sql_str, '"**'**, '')

## 四、特征准入规范

| 流程 <br> | 规范 <br> |
| --- | --- |
| 特征提案 <br> | 由提案人基于业务/模型需求提出新特征建设申请，需要明确： <br>应用场景与业务价值，定义计算逻辑 <br> |
| 特征评审 <br> | 由特征建设人和第三人对提案进行审核评估： <br>1. 是否具有必要性与可复用性 <br><br>2. 与现有特征是否冲突或重复 <br><br>3. 特征口径、数据来源、如何加工 <br><br> |
| 特征测试 <br> | 在对应测试表新建特征，生成测试表用于后续质量检查 <br> |
| 特征验证 <br> | 在测试数据上进行全面校验，包括： <br>零值率、空值率、异常值比例是否符合预期 <br> |
| 特征建设 <br> | 特征验证完成后，可以纳入生产表统一建设 <br> |
