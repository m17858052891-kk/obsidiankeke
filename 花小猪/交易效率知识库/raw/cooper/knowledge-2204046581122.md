# 1. 背景

> [周维度供需预测-策略方案](https://cooper.didichuxing.com/knowledge/2199610335356/2205702799803)

> BRD文档：<https://cooper.didichuxing.com/docs2/document/2205189065704> 密码: 758726

- **业务背景**：每周会基于全国及重点城市下周中以及周末的呼叫趋势，进行整周资源（如补贴）分配。

- **现有方法**：人工参考去年同期的呼叫趋势，预估下周涨幅。但主观性强，间隔周期长，且无法量化特殊事件和天气等影响因素。

- **预测任务**：未来14天，分城市（全国+Top50完单量城市）端内每日呼叫数。

**成果总结：**

- **模型调研与落地**：调研并落地了一种与数据频率无关、预测性能优秀的单变量时序预测基座模型。该模型通过架构和大量的预训练数据，实现多种周期性提取、历史相似序列对比，可有助于新的时序预测任务的效果粗估算。

- **供需预测模型效果提升**，Lagllama相较于Baseline：

	- **全国**：MAPE下降**26.5%**, 第一周同向性提升**3.33%**, 第二周同向性提升**37.8%**

	- **分城市**：MAPE下降约**15%**, 同向性的准确性和稳定性持平

- **业务目标不可行性分析**：针对“每次预测的分城市同向性都需大于80%”这一业务要求，通过充分的数据分析，以及引入外部特征，完成了不可行性证明。有效避免了进一步人力浪费。

# 2. 原文工作介绍

[Lag-Llama](https://arxiv.org/pdf/2310.08278)是一个Transformer Decoder-only架构的单变量概率时间序列预测基座模型.

## 2.1 自回归建模

**训练集：**D个**单变量**离散时间序列$$D_{train} = \{x^i_{1:T^i} \}^D_{i=1}$$, 其中$$T^i$$表示时间序列 i 的长度.  ($$D \geq 1$$)

**预测任务**：对每个序列，预测未来P个时间点的值.   ($$P \geq 1$$)

**测试集**：$$D_{test} =  \{x^i_{T^i+1:T^i+P} \}^D_{i=1}$$

**历史序列采样**：为避免完整历史序列差异过大，采用固定上下文窗口进行子采样，窗口长度记为C

**自回归建模：**给定该序列的历史观测值的采样，对P步未来值的联合分布进行自回归建模

## 2.2 分词方案：滞后特征 + 时刻特征

**动机**：

- 通用时序基座模型，需要支持**任意频率**（如秒、小时、日、周、或者混合频率等）的下游任务

- 由于不同数据集间采样频率差异大，且下游任务可能包含从未见过的频率组合，因此模型不能直接依赖频率信息。需要通过频率无关的**分词机制**实现泛化

**方案**：对每个时间步t，构建一个固定维度且与频率无关的token，包含滞后特征和时刻特征

1. **滞后特征 Lag Features**

	1. 根据预定义的滞后索引集合 $$\mathcal{L} = \{1, ..., L\} \subseteq N^*$$ 提取历史观测值。

	2. 当前时刻t，对应的滞后特征是$$\mathbf{k}_t \in \mathbb{R}^{|\mathcal{L}|}$$, 其中$$\mathbf{k}_t[j] = x_{t - \mathcal{L}[j]}$$

	3. 本文的滞后索引有82个，覆盖多种周期性。

## 2.3 模型结构

**总览**

- **基座模型**：[Lag-Llama](https://arxiv.org/pdf/2310.08278)是一个**Transformer** 架构的**单变量**概率时间序列预测**基座模型**，具有较强的**零样本和少样本泛化能力**。

- **自回归架构**：仅依赖历史目标值进行预测，**无需外生协变量（covariates）输入**。

- **LLaMA架构**：复用**LLaMA的结构**，但**未加载 LLaMA 预训练参数**，因此**无语义理解能力**，仅为时序建模工具。

- **输入本质**：将历史观测值本身视为“协变量”，通过滞后与时间特征构造 token。

### 2.3.1 Attention模块

- 复用Transformer-based LLaMA架构，包含M个Decoder层

- 所有token会经过一个**共享的线性投影层**后传入Attention模块。

- 在每个注意力层的query和key表示中，都采用了RMSNorm预归一化和旋转位置编码（RoPE）。

### 2.3.2 参数化分布预测头

- 模型不直接输出预测值，而是输出**下一个时间步的概率分布参数**$$\phi$$。

- 分布选择：

	- 采用**学生 t 分布**（Student’s t-distribution），希望模型简单易懂。

	- 因此预测头输出该分布对应的三个参数：**自由度**、**均值**、**scale，**并添加适当的非线性项以确保这些参数保持为正。

> 可以选用更具表现力的分布，例如normalizing flows和copulas，但可能会增加模型训练和优化的难度，当前以简洁鲁棒为优先。

### 2.3.3 预测与不确定性量化

- 采用贪婪自回归生成多条轨迹(sample paths），直至轨迹长度等于P ≥ 1。（实际我们选择每次生成100条轨迹）

- 基于这些样本，可以计算下游指标的不确定性区间。

### 2.3.4 输入标准化

为提升模型对不同量纲序列的适应性，采用**窗口级标准化**：

- 对每个单变量窗口，计算均值和方差： $$\mu_i = \frac{1}{C} \sum_{t=1}^{C} x_t^i, \quad \sigma^i = \sqrt{\frac{1}{C} \sum_{t=1}^{C} (x_t^i - \mu_i)^2}$$

- 将序列$$x^i_{1:C}$$标准化为  $$\tilde{x}_t^i = \frac{x_t^i - \mu_i}{\sigma^i}, \quad t = 1, \dots, C$$

- 同时将 μi 和 σi 作为**与时间无关的实值协变量**传入模型，为模型提供输入统计信息，称之为汇总统计信息。

- 但实际上，作者发现在预训练的时候用**中位数**和**四分位距**来标准化效果更好。

### 2.3.5 训练策略

为提升跨频率泛化能力，训练中采用以下策略：

- **分层抽样（Stratified Sampling）**：平衡不同序列长度与频率的数据。

- **Freq-Mix**：混合不同频率的数据进行训练。

- **Freq-Mask**：随机掩蔽频率信息，迫使模型学习频率无关表示。

## 2.4 训练目标

最小化未来P步预测分布的**负对数似然**，最小化预测分布参数与真实值之间的数值误差

$$\mathcal{L}(\theta) = -\sum_{i, T} \sum_{t=1}^{P} \log p(x^i_{T+t} \mid \phi_t, \theta)$$

## 3.2 训练目标

本文的优化目标除了原模型的数值准确性，还增加了同向性，因此最后的loss包含分布损失+趋势损失

$$\mathcal{L}(\theta) = -\sum_{i, T} \sum_{t=1}^{P} \log p(x^i_{T+t} \mid \phi_t, \theta) + \lambda \mathcal{L_{trend}}$$

> 这里的i可以看作城市ID

## 3.3. 同向性优化尝试

**背景**:

- Lag-Llama在**数值准确性**方面表现优异，但在**同向性**（如上涨/下跌/持平方向是否一致，具体定义见*3.1节*）方面仍存在不足。

- 同向性对于资源分配、运营决策具有重要意义，因此需要专门优化。

**结论**：尝试了三种优化方法，但均未有效提升同向性。

### 3.3.1 Loss中显式建模同向性

**现状**：使用呼叫数分布损失，仅优化预测分布与真实值之间的数值误差，未考虑趋势一致性。

**尝试方案**：在Loss中设计加入**趋势一致性项（trend loss）**

- 尝试相对**两周前/一周前/一天前**的相对增幅，效果均不好

- 因为同向性是三分类（涨、跌、平），所以还尝试过增加Trend Sign Loss

```Python
trend_pred = (pred_{t+M} - pred_{t+1}) / (pred_{t+1} + ε)
trend_true = (true_{t+M} - true_{t+1}) / (true_{t+1} + ε)
trend_loss = MSE(trend_pred, trend_true)

# 还增加过正负的trend_loss
if try_sign_loss: trend_loss += (torch.sign(trend_pred) != torch.sign(trend_true)).float()

total_loss = distribution_loss + λ * trend_l
```

**实验结果**：

- 当 λ 较小时，同向性无明显改善；

- 当 λ 增大时，**数值准确性和同向性同步显著下降**。也怀疑过都变差，可能因为和预训练数据集的数据分布差距太大

- 表明**趋势优化与数值精度存在优化冲突**，直接加权难以兼顾。

### 3.3.2 修改预测任务为“涨幅”

**动机：**

- Lag-Llama已经表现出优秀的数值准确性，希望转变为“涨幅”的数值准确性

- 且2.6.1节中展示出无法同时兼顾数值准确性和同向性，若直接预测涨幅，可能天然提升同向性。

- 业务侧实际使用的是**周环比涨幅**（而非绝对呼叫数）。

**理论优势：信息等价**，预测呼叫数 = (1+预测涨幅) \* 初始呼叫数 

**方案**：修改原预测任务**by天呼叫数**--&gt;**涨幅**

- **日涨幅**：$$\gamma  + \frac{(呼叫数_{t+1} - 呼叫数_{t}) }{ 呼叫数_{t} + \epsilon}$$

- **周涨幅**：$$\gamma  + \frac{(呼叫数_{t+7} - 呼叫数_{t}) }{ 呼叫数_{t} + \epsilon }$$

- **双周涨幅**：$$\gamma  + \frac{(呼叫数_{t+14} - 呼叫数_{t}) }{ 呼叫数_{t} + \epsilon}$$

> 示例：9月10日呼叫数为 300，9月17日为 600 → 周涨幅 = +100%。

> 加Theta是因为Lag-Llama只支持预测正值，实际的Theta选取是拍的5 or 10.

**实验结果：**三种涨幅形式下，**数值准确性与同向性均大幅下降**。

**可能原因**：

- 涨幅对**低基数场景极度敏感**（如 1 → 2 即 +100%），易受噪声干扰；

### 3.3.3 多变量模型尝试：引入外部特征

**方案**：

- 引入外部特征，构建多变量模型TimXer，试图捕捉异常事件对趋势的影响：

- 输入当天的外部运营日历（如马拉松、运营日历分级）和天气数据，返回一些特定事件/天气的分类

**结果**：引入任一或组合外部特征后，**模型效果（包括同向性）均劣于**仅使用日期特征的版本。

- **外部运营日历效果差**

	- 可能原因：只有2025-03-01之后的数据，训练数据特征缺失，数据覆盖不足

	- 可能方向：只用2025-03-01之后的数据训练

## 4.6. 不同评估周期结果分析

**概述**：

- 本节分析了Lag-Llama和Baseline在两个时间段：4–6 月（离线测试周期，T1）和 7–10 月（线上运行周期，T2）上的表现。

- Baseline 和 Lag-Llama 模型的稳定性都低。

**结论**：

- **数值准确性高**：Lag-Llama的分城市数值Error比Baseline低大约15%.

- **同向性**

	- 全国：Lag-Llama在T1和T2的同向性都比Baseline好。

	- 分城市：Lag-Llama在T1的同向性比Baseline好，在T2周期和Baseline略差。Lag-Llama同向性在第一周预估的比Baseline**差**的频率是61%，Lag-Llama同向性在第二周预估的比Baseline**好**的频率是60%

- **同向性稳定性持平**

	- Baseline同向性从T1到T2下降约 60%, Lag-Llama同向性从T1到T2下降约56%

### 4.6.3. 业务对模型性能和稳定性的**高要求**

[供需预测效果梳理](https://cooper.didichuxing.com/knowledge/2199610335356/2205581985107)

由于该模型直接用于资金分配决策，业务对模型性能和稳定性有着非常严格的要求：

- 典型目标如：“Top50城市同向性 > 90%，准确性 > 80%”。

- 在初期，我们对“同向性 > 90%”的理解是：在离线评估周期内（例如模型按天滑动预测未来14天，共进行 K 次预测），对于每个城市，其方向预测正确的次数应超过总预测次数的 90%（即 ≥ K × 0.9）。整体上，只要大部分城市在多数时间点方向正确即可。

- 然而，业务方的实际要求是：在**每一次**预测中（即每次滑动窗口输出的那一轮预测），都必须**至少有 45 个**（50 × 90%）城市的方向预测正确。换言之，同向性达标是以“单次预测”为粒度进行考核的，而非在整个评估周期内取平均。

这意味着模型必须在**每一次预测时，**都保持极高的跨城市一致性表现，对稳定性、鲁棒性和可控性提出了极高挑战。但对于黑盒模型而言，**无法保证在每次预测中都满足如此严格的同向性阈值**。
