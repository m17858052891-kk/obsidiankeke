# 背景

目前在宏鹄的分单过程中，系统会派给司机他能得到最高iph的订单， 但目前会存在以下的情况：

司机可选两个单：

- 第一个单iph更高但是pk失败了

- 第二个单iph更低但是pk可以成功

按照目前的分单系统，宏鹄会损失一个单，为了提升宏鹄的竞争CR，我们希望在分单时**考虑司机PK胜出的概率**。

# 预估收益：

- 宏鹄竞争CR = **+1.06pp**

- 宏鹄胜出率 = **+4.42pp**

# 收益测算

宏鹄司机可抢的订单满足的条件 ：

- pk胜出的司机不是宏鹄

- pk分数比胜出的司机更高

- 在当前轮次(分单论次)pk没胜出

- 可赶上pk窗口

$$宏鹄\Delta 竞争CR = \frac{min( 宏鹄司机可抢的订单,  PK失败的司机)}{宏鹄竞争呼叫} * 履约率 = \frac{min(2585501, 1010903)}{65203647}*0.69 = 1.06pp$$

$$宏鹄\Delta 胜出率 =  \frac{min( 宏鹄司机可抢的订单,  PK失败的司机)}{宏鹄竞争呼叫}  = \frac{min(2585501, 1010903)}{22865475} = 4.42pp$$

# 模型

模型v1： XGB

特征： 使用分单侧的特征 （P维度，D维度，订单维度特征），特征可以策略闭环产出，暂不用工程开发，由于特征数量较多，我们就不在此单列出。

任务：预测司机是否PK胜出

离线指标： AUC， ECE

实验链接 ： <https://ether.intra.hongyibo.com.cn/labs/new/13158>

```PlainText
select
    sum(nb_group * abs(confidence - accuracy) / nb_eletment)
from
    (
        select
            distinct group_,
            count(1) over(partition by group_) nb_group,
            count(1) over() as nb_eletment,
            avg(label) over(partition by group_) as accuracy,
            avg(score) over(partition by group_) as confidence
        from(
                select
                    probabilities_value.`values` [1] as score,
                    is_winner as label,
                    floor(probabilities_value.`values` [1] / 0.1) as group_
                from
                    kflower_strategy.ether_predict_13158_c19007513271344678_1721132290918_34186291672067415
            ) a
    ) b
```
