# 数据处理步骤与v_net训练

- 衰减后gmv (reward)total_dur = finish_time - answer_time  
iph = gmv \* 5 / total_dur (每5分钟聚合为一个独立的reward)  
surplus = gmv - iph \* (total_dur // 5)  
最后一个 surplus \* (gamma \*\* (total_dur / 5 - 1)) [(半衰期model)](https://baike.baidu.com/item/半衰期/288174?fr=aladdin)  
每个独立部分累加得到一个订单均匀处理后的gmv  
  

- 时间域处理对所有时间特征划分到每5分钟一个时间格子，共24 \* 12 = 288个时间段，编号为1 - 288；  
任意时间戳输入时，把所有时间特征拆分成hour/ minute/ second三个维度输入  
  

- 标记done_mask给定time_delta = 120min, 在每一个driver_id的所有records下标记done_mask：从每个订单的answer_time开始累加total_dur，  
当总时长不超过time_delta时，每条记录的done_mask为1，超过则标记为0并截断然后repeat这个loop；  
效果：  
![](https://s3-ep-inter.didistatic.com/didoc-upload-file-prod/1653034105158/860100242.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T102927Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=37c1c2bbe11ba0c77896df0f74b1760f7e0429af7302ccf489e1f7279b56b4c0)  
可以看到，对于一段时间内只有一条的订单记录done_mask都标记为0，对连续做单司机持续时长为超过两小时会自动拆分为两个episodes；  

- 制作idle司机订单补集

 经过done_mask标记切分后需要complement司机轨迹，因此要构造一个idle订单集；

 主要思路是对于在每个size大于1的episode内的，补足每一单之间司机的空跑状态转移，

 i.e.上一单的终止时空 == 当前**空跑单**的起始时空，下一单的起始时空 == 当前**空跑单**的终止时空，且naturally，所有idle orders的done_mask 为1

 可以看到，在每个episode内都填充了idle订单，且done_mask 为1 & reward 为0

- 输入模型训练集部分  
输入state为answer_time, answer_lng, answer_lat  
输出state为finish_time, dest_lng, dest_lat  
follow bellman update 并且使用done_mask做标记： v(s_t) = r + decline \* v(s_t+1) \* done_mask,  
其中decline = gamma\*\*(total_dur / 5)，这样与每个reward的衰减scale保持一致
