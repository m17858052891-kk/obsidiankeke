# 一、需求简述

## 1.1 问题与背景

- 平台聚合PK：为每一个订单选出一定时间内最好的司机，最好的定义：该OD完单概率（预测）最大

	- 预测OD完单概率受司乘两侧影响，乘客侧通常考虑接驾距离，司机侧通常考虑司机历史履约

- 问题

	- **当前考虑司机历史履约时未将不同派单模式区分开**，但是司机侧对全指派与半指派的自由度感知是不同的，且未来半指派模式会向司机透传可无责拒单

	- 现状未区分开全指派与半指派的历史履约，即一个司机历史拒单行为多，也会影响其在全指派模式下的PK得分

## 1.2 需求简述

**在平台聚合PK模型中，将不同派单模式的打分区分开**，即历史半指派的履约只会影响半指派模式订单的PK得分，历史全指派的履约只会影响全指派模式订单的PK得分

# 二、收益与目标

短期：通过优化平台交易模式，提升平台效率

长期：半指派履约与全指派履约隔离，给司机半指派自由度感知，长期提升司机留存

# 三、需求详细说明

1. 平台聚合PK模型中，如果本单派单模式是半指派，则以司机历史半指派履约行为进行考核打分；如果本单派单模式是全指派，则以司机历史全指派履约行为进行考核打分

	1. 即：如果司机半指派履约差，也就是拒单率高，但是司机全指派取消率低，其全指派订单的PK不受半指派拒单率的影响。

2. 需要建设全指派履约模型与半指派履约模型，且两个模型评价体系一致，打分可比。

# 五、实验方案

1. 实验渠道：花小猪流量端

2. 实验目标：验证平台聚合PK区分判单模式对交易效率的短期收益

3. 实验方案：乘客PID分流

4. 关键指标：

	1. 核心指标：平台CR、平台完单

	2. 观测指标：

		1. 不同派单模式应答占比

		2. 司机取消次数用完后的行为

		3. 商家份额变化

	3. 过程指标

		1. 司机拒单率、取消率

		2. 乘客取消率

5. 选城标准

	1. 全国实验，至少覆盖全国75%完单的城市
