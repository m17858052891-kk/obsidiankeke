**overview:**

基于wide&deep算法为订单30s内应答率构建深度模型。

由于在将模型运行到线上时，对于一些类别特征（譬如说：城市id，出发地/目的地）可能会==存在线上线下特征不一致的问题==，并且对于有些string类型的类别型特征，其在ether上无法进行有效的编码并且对于string类型无法直接送入tensorflow的embedding层进行embedding编码。

所以对于这些类别型特征需要记录其在训练集中见过的种类，==当线上数据进入时，需要对其进行编码，之后才可以送入深度模型中==。

我们在模型训练的过程中，保存了特定类别特征见过的种类（正如上述的城市id，出发地/目的地等等），对于在训练集中没见过的种类，会将其统一记为某个类别。

下面叙述关于将数据送入模型之前我们进行的数据预处理过程，其中涉及关于数据特征的划分，缺失值的处理，线上线下特征不一致，独热编码等问题。

**特征描述：**

**首先我们先将特征划分为以下四类，其中onehot型包含于类别型特征中。**

| **类型** <br> | **举例** <br> |
| :---: | :---: |
| 连续型 <br> | 周围若干circle的空车司机数/city_input_start_end_distance <br> |
| 类别型 <br> | 出发地目的地的一级地址 <br> |
| 布尔型 <br> | 订单是否为长/中/短距离 <br> |
| onehot型 <br> | 对city_id, input_hour等进行onehot所得到的特征 <br> |

**数据处理步骤**

1. 将数据中的特征分成四类，分别为(category, bool, onehot, dense)。每个特征类中具体包含哪些特征如2所示。

其中，onehot特征包含在category特征当中，在此处进行onehot的特征为==input_hour==, ==input_city_weekday==, ==start_city_id==

2. cat_feats/bool_feats/onehot_feats分别为：

```Python
# poi_type_bool是出发地和目的地的一级地址，包含在cat_features下
poi_type_bool = ['start_'+str(i)  for i in range(len(first_class))] + ['dest_' + str(i) for i in range(len(first_class))]
cat_features = ['input_hour','input_city_weekday','start_city_id','start_poi_type','dest_poi_type'] + poi_type_bool

```

其余的特征为dense特征

4. 缺失值填充

	1. dense型：缺失值填充为0

	2. cat/bool型：

		1. 对于进行onehot的特征：缺失值填充为-1

		2. 对于其余的特征，缺失值填充为'-1'

5. 测试集中的cat_features特征，如果其值在训练集中没见过，则将其进行转换

	3. 对于'input_hour','input_city_weekday',无需进行转换（因为该列不会出现这种问题）

	4. 对于'start_city_id': 如果其未出现在训练集中，将其标记为==356==（在训练集中出现次数最少的特征）

	5. 对于其他特征，若未出现在训练集中，则将其记为'-1'。

	6. 训练集中的特征出现的种类存储在附录\[3\]中的unique_dict.py中。

6. 将特征进行排列，依次为cat_features, bool_features, dense_features

7. 对dense_feats中的特依据MinMaxScaler方式进行转换，如下所示

$$x_{new} = \frac{x-\min}{\max-\min}$$

8. 将需要进行onehot的特征暂时转换为'str'，之后进行onehot（进行onehot编码的特征分别为=='input_hour','input_city_weekday','start_city_id'==）

9. 对=='start_poi_type', 'dest_poi_type'==特征进行label_encode，得到映射字典存储在==mapping_dict==中（附录\[2\]）。

10. 将经过上述转换后的数据送入模型进行预测即可。最终送入模型的特征维度为414维，其对应特征顺序如附录\[3\]中所示。
