# 匹配重构Review

**目标：**==在整体完单不负、司乘取消率不超过目标的前提下，降低PK胜出后的平均接驾距离，预期==**降低端内乘客ETP + 司机接驾时长1%。**

## **策略细节：**

- 问题定义：在一个分单轮次内，从全指派、半指派、抢单中为订单选择动作和司机，在整体完单量不负以及平均司乘应答后取消率不高于约束值的情况下，平均接驾距离最小化。

- 目标函数：根据问题定义可以分析出，我们需要通过非负拉格朗日乘子将完单量和平均司乘应答后取消率约束加入平均接驾距离最小化的目标函数，通过一系列变换后得到的目标函数如下：

## **模型训练：**

- 模型：三个独立预测模型，分别预测抢单概率、竞争胜率、司乘取消率；

> 为什么不设计成一个模型合并训练？

> 1）当前三个模型分别用于预测全指派/半指派/抢单场景下的rafdce，合并模型会比较复杂；

> 2）考虑后续单个模型独立维度与策略合并情况（与PK阶段司乘取消率模型合并），拆分成独立模型训练更有利于维护；

> 3）为解决工程上3模型\*3动作均输出，需要独立调取并缓存12个预测值，造成缓存压力大的问题，实际线上部署已优化为三模型离线独立训练+合并模型线上部署的形式。

- 模型结构：

	- 抢单概率模型：三塔＋DCNv2

	- 竞争胜率模型：DCNv2＋Action×Serial FiLM

	- 司乘取消率模型：DCNv2＋Action×Serial Adapter＋Masked Softmax

> （1）为什么DCNv2最适合当前模型？

> DCNv2的模型结构在本项目中设计为两层Cross+Deep部分，其中两层Cross主要用于学习特征交叉信息，Deep部分主要用MLP结构学习其他非线性关系。

> ------------------------------------------------------------------------------------------------------------------------------------------------------

> （2）抢单概率模型设计成三塔+DCNv2的理论依据？

> 三塔目前分为订单塔、司机塔、供需塔，每个塔内分别是独立的MLP结构，这样设计的原因在于：1）司机特征共计88个，会直接占据大部分输入表达，有利于控制后续交叉层规模；2）三塔结构有利于模型先分别学习订单、司机、供需表示，再学习它们之间的关系。三塔后连接DCNv2结构，主要用于抢单模型学习司机在不同订单、不同供需场景下的模式，通过DCNv2的特征交叉实现这种模式学习。

> （3）竞争胜率模型设计成DCNv2＋Action×Serial FiLM的理论依据？

## **参数离线测算：**

Score计算中，存在一些超参数，而这些超参数需要用到历史数据进行Replay求解，本项目实现的求解算法：**完整矩阵分层抽样 → 三动作OD打分 → TP/GS/RGS业务回放 → Dinkelbach更新θ → 对偶热启动λ → Sobol粗搜＋TPE精搜 → 五项约束筛选 → 分层回退 → 独立日期固定参数验证**。

### 测算细节：

（1）数据与求解粒度

Replay数据用2026-09-01～09-13召回OD矩阵数据并经过模型输出的rafdce补全特征，独立求解矩阵为date+city+hour+uuid+rgs_pair_match_flag（同一层级同一轮次的候选OD矩阵）

（2）三动作预测与Score计算

每个OD同时获取全指派、半指派、抢单模式下的rafdce，并计算$$Score_{ijk} = r_{ijk}a_{ijk}(1-e_{ijk}) \left[ \theta+\lambda_f\hat f_{ijk} -\frac{D_{ijk}}{D_{cap}} -\lambda_d(d_{ijk}-d_{0,c}) -\lambda_p(c_{ijk}-c_{0,c}) \right]$$

（3）OD内动作折叠

对每条OD分别计算三个动作Score，取最大Score的模式k作为派单模式。

（4）完整TP/GS/RGS回放

	- 全指派/半指派：（OD一一对应）

		- TP矩阵：按Score从高到低贪心匹配；

		- GS矩阵：OD打分用Score，DO打分用`gs_driver_str` ，执行GS稳定匹配算法；

	- 抢单：按Score降序，Top1 RGS近似；

（5）约束

五项约束分别为：有效PK量约束、加权履约约束、加权距离约束、司乘取消率约束，目标是最小化接驾距离

$$\hat F\ge\hat F^{base} \qquad \hat d\le d_0^{weighted} \qquad \hat c\le c_0^{weighted} \qquad MatchCount\ge0.95MatchCount^{base} \qquad W\ge0.95W^{base}$$

（6）基线构造

根据播单表获取实际播单flag和播单的派单模式，得到$$z_{ijk}^{base}$$，计算得到$$\hat F^{base},W^{base},MatchCount^{base}$$

（7）$$\theta$$更新

使用Dinkbach变换，$$\theta^{t+1} = 0.5\theta^t+0.5\frac{S_D}{W}$$，收敛条件为：$$|S_D-\theta W| \le 10^{-5}\max(1,|S_D|)$$

（8）$$\lambda$$对偶热启动

$$\lambda_d^{(t+1)} = \max\left( 0, \lambda_d^{(t)} +\eta_d\bigl(\bar d(z^{(t)})-d_{0,c}\bigr) \right)  \quad  \lambda_p^{(t+1)} = \max\left( 0, \lambda_p^{(t)} +\eta_p\bigl(\bar c(z^{(t)})-c_{0,c}\bigr) \right) \quad \lambda^{(t+1)} = \max\left( 0, \lambda^{(t)} +\eta_f\bigl(F^{base}-F(z^{(t)})\bigr) \right)$$

（9）粗搜+精搜

粗搜：按Sobol序列分散取点，得到几组lambda，分别计算出这几组lambda组合下的平均接驾距离、objective、几项约束值，本轮次不改变lambda只确定大致搜索范围；（确定一个精搜的范围，执行16次）

精搜：根据历史Trial结果有偏好的在表现更好的lambda组中自适应取点，在几组历史结果中循环20次，每次根据结果调整参数；

搜索目标：最小化$$Objective = AvgDistanceNorm + 1000\times TotalViolation$$，其中$$TotalViolation = \sum_m\max(0,V_m)$$。

$$\displaystyle V_f=\frac{\hat F^{base}-\hat F}{\hat F^{base}}\qquad  V_d=\hat d-\bar d_0,\qquad V_p=\hat c-\bar c_0\qquad  V_M=\frac{0.95M^{base}-M}{\max(M^{base},1)}\qquad  V_W=\frac{0.95W^{base}-W}{W^{base}}$$

**优化瓶颈点1：**理论上，通过搜索目标的公式可以推出允许违约一定程度不满足实现平均接驾距离最小化，但是代码实际实现中并不直接是拿obvjective最小的参数，反而优先级是：1）存在可行Trial，只在可行Trial中选择距离最小者；2）距离完全相同时，再以履约更高、λ总量更小打破并列；

**优化瓶颈点2：**从现有结果发现，代码并未从减少匹配量、司乘取消率的约束上实现代偿、降低平均接驾距离，这是因为测算时优先满足的是city\*hour的司乘取消目标，而非全天平均，这也造成当前优化余量较少

（10）分层搜索与回退

> 为什么取消率没有贴近临界值？

> 因为当取消率低于目标时就满足约束，且只有当“进一步缩短距离必然导致取消率上升”时，最优解才可能把取消率推到目标边界。当前问题还同时受到：离散OD选择、一单一司机容量、TP 贪心、GS稳定匹配、匹配量和W护栏、Full/Half/Grab动作折叠影响，所以指标不是连续变化的，也不一定存在恰好贴着取消率边界的匹配结果。

（1）分TP和GS测算离线参数的必要性
