# 1 背景

当前商家交易分单链路中，存在多类**调层**逻辑。调层本质是通过改变 OD 对的分单层级，影响其参与匹配的先后顺序。

当前典型调层包括：

	- **预分单调层**

	- **抢单调层**

	- **特快单调层**

	- **新乘客调层**

存在问题：

**1. 硬分层容易造成局部最优**

现在线上存在“指派先分、抢单后分”的硬分层逻辑。如果某个抢单 OD 对在全局视角下更优，但因为所在层级靠后，可能在前层司机资源被消耗后失去匹配机会。

**2. 不同调层逻辑口径不统一**

抢单、特快单、预分单、新乘客等调层来自不同业务诉求，生效系统和计算方式不完全一致，导致策略可解释性和维护成本较高。

**3. 与商家匹配联合决策目标不统一**

商家匹配联合决策希望基于统一 Score，在 全指派/ 半指派 / 抢单 等动作间比较 OD 价值。但硬调层会在 Score 生效前改变候选进入匹配的先后顺序，可能导致联合决策空间被提前压缩。

# 2 目标&约束

目标：取消无收益调层策略

约束：整体完单&CR不显著负，司乘应答后取消率不显著负向，小猪端单均预估接驾距离不显著上涨。

# 3 技术方案

## 3.1 问题发现

当前调层作用位置为：“==候选OD矩阵 → 特征补全与多级过滤 → 距离及模型计算 →== DO ==打分 → 调权 → 调层，生成 RgsPairMatchFlag → GS 匹配 → 播单==”，处于召回后、匹配前，同时作用于TopSpeed匹配与GS匹配。它的目的在于给部分策略倾斜的OD对建立比分数更高一级的匹配优先级，最终决策逻辑变为“**先按业务层级决定谁优先进入匹配，再在同一层内比较模型分**”，其中调层中多类策略分层情况如图所示：

可以发现，根据现有的调层逻辑，大致可生成“24 → 22 → 20 → 4 → 2 → 0 → -180 → -201“这几个层级，随着层级复杂，可能会造成增加匹配阶段的串行轮次和固定开销，且有可能带来局部最优问题。

当前调层中，新乘客、小猪特快、特快盒子命中后会加层，进一步数据分析可以发现，这些层级的实际完单占比约22%，却有可能带来以上时间开销及局部最优问题，故考虑后续交易效率全局优化及策略管理，拟对“新乘客、小猪特快、特快盒子”层级进行取消。

## 3.2 策略细节

关闭“小猪特快”、“特快盒子”、“新乘客”加层调层，减少匹配串行轮次耗时，降低局部最优风险。
