## 一、背景

1. 目前商家分单召回阶段非连环派和连环派的策略链路都为**固定召回半径(接驾时长)**+**应答后司乘取消率模型过滤**的机制；然而历史原因两套策略都需维护各自的Apollo配置参数和相关模型，不利于后续迭代运维，因此希望将Apollo配置和模型收拢至一套体系，方便后续策略的更新和维护；

2. 对于目前的Apollo配置，部分参数有缺失，如非连环派场景仅可通过半径进行召回，缺少接驾时间的限制，因此希望新增更多可配参数，加强策略的完整性和灵活性；

3. 同时订单价值模型也通过一套Apollo单独维护，希望将其也回收至当前Apollo内，且订单价值模型会与应答后司机取消模型拉齐；

## 二、收益链路

1. 本次需求核心目的是希望**将商家召回策略Apollo参数和相关过滤模型回收为一套配置**，极大便于后续运维；

2. 同时基于对连环派场景过滤阈值的动态优化，希望**实现商家分单全部场景应答前后漏斗的平衡**，最终提升商家完单；预期收益

   1. 自营商家大聚合完单+0.25%，应答后司乘取消-0.15pp；

   2. 宏鹄商家大聚合完单+0.1%，应答后司乘取消-0.1pp；

3. **最终放量标准**：商家完单不负向，应答后司乘取消率不显著上涨；

## 三、策略方案

1. ~~连环派和非连环派的召回策略收拢至共用一套Apollo参数~~：为防止参数量级过大，保留三套Apollo：

   1. 在当前Apollo配置基础上，**非连环派新增接驾时间参数(包括召回限制和模型生效限制)**，与连环派场景拉齐；**具体召回时取ETA&召回半径的交集**；

   2. **连环派新增模型过滤不生效接驾时间及距离配置**，并与目前其他可配参数迁移至新的Apollo中，实现对于接驾近的运力不进行模型访问和过滤；

   3. 当前Apollo上新增订单价值参数配置，即**将现有订单价值Apollo配置迁移至新版本中**，具体可配参数follow订单价值Apollo现状即可；同时订单价值模型也会回收至应答后司机取消模型；

   4. 同样支持GS和TP分单系统单独配置对应参数；

最终Apollo可配置参数形态为：

```plain
  "城市名": {
    "订单侧配置": {
      "非连环派订单初始召回ETA": 480,
      "非连环订单初始召回半径": 4500,
      "连环派AB段ETA": 660,
      "连环派BC段ETA": 660, 
      "连环派AC段ETA": 660
      "连环派AB段距离": 5000,
      "连环派BC段距离": 3000, 
      "连环派AC段距离": 5000
    },
    "司机侧配置": {
      "非连环派扩播起始时间": 20,
      "非连环派扩播终止时间": 30,
      "非连环派初始听单ETA": 360,
      "非连环派初始听单半径": 3000
    },
    "模型配置": {
      "非连环派模型生效ETA": 120,
      "非连环派模型生效半径": 2350,
      "非连环派司机过滤阈值偏置项": 0.513,
      "非连环派乘客过滤阈值偏置项": 0.596,
      "非连环派全指派阈值": 0.438,
      "非连环派半指派阈值": 0.475,
      "连环派司机过滤阈值偏置项": 0.453,
      "连环派乘客过滤阈值偏置项": 0.524,
      "连环派全指派阈值": 0.358,
      "连环派半指派阈值": 0.325,
    }
  }
```
**注**：**由于连环派司机必定在服务中，因此无法进行按照司机无单间隔进行扩播**；
2. 连环派和非连环派场景访问同一应答后司乘取消率模型：

   1. 策略进行线上模型的回收，基于多场景等思想对全场景统一建模应答后司乘取消，**连环派和非连环派场景都访问同一模型**；

   2. **连环派场景司乘对也会访问应答前流失率模型**，实现应答前后漏斗的平衡；两个场景仅过滤阈值的常数偏置项不同，最终每轮次的过滤阈值均为**订单流失率模型输出+Apollo配置的各自偏置项**；

通过以上两点，最终可实现：

   * 整个商家分单召回策略参数收拢至一套Apollo中，极大方便了后续的运维工作；

   * 将召回阶段的模型也精简为三个，对后续模型的迭代升级更加便利；

   * 模型连环派和非连环派两套Apollo配置先保留，待决定收拢至一套模型后再合并Apollo；
