# 1. 司机中心算法

## 1.1 算法

对[召回策略调研](https://cooper.didichuxing.com/cooper_gateway/metis/v1/knowledge/2199610335356/wikiFile/860100365.html?taskId=2199613477654) 中v2.1的版本试图改进，直接计算播单距离，而不是只计算相对比例。

```PlainText
优化目标实际上为最小化 空闲时长的期望 和 接驾时长的期望 之和：
```

 $min T\_{free} = min (\\bar T\_{wait} + \\bar T\_{pickup}) $   
  
首先假设周围只有一个司机，且并没有累积的订单或司机的情况（否则需要考虑比较复杂的争抢）。   
则：   
$\\bar T\_{pickup} = \\frac{R}{2v}$   
其中v为平均车速。   
假设新出现的订单和司机都服从时空上的均匀分布，密度分别为 $V\_{order}$ 和 $V\_{driver}$。   
其中，$V\_{order}$为单位时间、单位面积内的可接订单数，$R$为播单半径。   
$V\_{driver}$为单位时间、单位面积内新出现的空闲司机数，有完单和上线两种情况。   
司机能接到订单的概率为 $\\min(1,\\frac{V\_{order}}{V\_{driver}})$ // 司机争抢订单   
  
$\\bar T\_{wait} = t\_{order\\\_occur} / \\min(1,\\frac{V\_{order}}{V\_{driver}})$ // 几何分布，期望为1/p   
$\\bar T\_{wait} = \\frac{1}{V\_{order} \* \\pi (R/1.411)^2} / \\min(1,\\frac{V\_{order}}{V\_{driver}}) $ // 1.411因为面积用直线距离，但是接驾距离是路面距离   
$\\bar T\_{wait} = \\frac{1}{V\_{order}} \* \\frac{\\max(V\_{order}, V\_{driver})}{V\_{order} \* \\pi R^2/2}$ // 1.411平方约等于2   
  
对$T\_{free}$求导得到：   
if $V\_{order} > V\_{driver}$ ,   
$R=2\\sqrt\[3\]{\\frac{v}{\\pi V\_{order}}}$   
if $V\_{order} < V\_{driver}$ ,   
$R=2\\sqrt\[3\]{\\frac{v V\_{driver}}{\\pi V^2\_{order}}}$

## 1.3 最小密度

以播单距离3km为阈值，得到最小的订单量为（根据时空的车速会略有不同）：

![](https://s3-ep-inter.didistatic.com/didoc-upload-file-prod/1653033691399/860099880.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T103615Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=cc6340cb73f718a92b8b21f0e36ba3f20b2f0da98e47b07b25f04300f3330a67)

平均所需密度为：3 单/ (格子\*小时) — 每个格子的面积大概1.5km^2

所以**最小密度约为 2单/（平方公里\*小时）**

作为参考，朝阳区面积 470km^2，对应最小密度一小时1000单，平峰期正常情况一小时3w单左右；

平谷区面积 940km&2，对应最小密度为一小时2000单，平峰期正常一小时200单左右。
