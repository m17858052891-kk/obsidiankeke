# 召回反事实分析


# 1. 背景

**本文分析目的：**

- **找到能支持离线搜参的中间变量，能离线稳定复现合适的实验参数****——约束订单总召回率折损（文档5），补充hold低质量OD（文档4.1），补充召回高质量OD（文档4.2）**

- **提供策略迭代的依据****——证明 caa模型迭代为取消率和距离的加权、ocr模型约束和时间单调关系 的合理性和收益来源**

**本文分析口径：**

- **“反事实”口径：在对照组中每个OD✖️轮次可以得到其在新策略下的反事实召回结果，判断依据是线上日志落表的caa和静态的value_hold对比。**

O维度的召回：召回od数>0

O维度的hold：召回od数=0

```PlainText
labeled as (
    select
        *,
        case
            when actual_recalled_driver_cnt > 0 and experiment_recalled_driver_cnt > 0
                then 'A_KEEP_ORDER_RECALL'
            when actual_recalled_driver_cnt > 0 and experiment_recalled_driver_cnt = 0
                then 'B_NEW_ORDER_HOLD'
            when actual_recalled_driver_cnt = 0 and experiment_recalled_driver_cnt > 0
                then 'C_NEW_ORDER_RECALL'
            else 'D_KEEP_ORDER_HOLD'
        end as order_migration_type
    from order_level
),
```

OD维度的召回：该od召回行数>0

OD维度的hold：该od召回行数=0

```PlainText
-- 00 distinct OD 互斥四象限（标准标签口径）
-- 粒度：dt + order_id + driver_id，一行一个 OD。
-- 现状召回：完整轨迹任意一行 action in ('TP','GS')；否则为现状 HOLD。
-- 实验召回：完整轨迹任意一行 value_gs > 0.66 且该行不是 SAFE_HOLD；否则为实验 HOLD。

with source_data as (
    select
        dt,
        cast(order_id as string) as order_id,
        cast(driver_id as string) as driver_id,
        upper(action) as actual_action,
        cast(value_gs as double) as value_gs
    from kflower_strategy_dev.all_od_base_0822_0823_funnel
    where exp_group = 'control_group'
      and order_id is not null
      and driver_id is not null
      and upper(action) in ('TP', 'GS', 'HOLD', 'SAFE_HOLD')
),
od_level as (
    select
        dt,
        order_id,
        driver_id,
        max(case when actual_action in ('TP', 'GS') then 1 else 0 end)
            as actual_is_recall,
        max(case when value_gs > 0.66 and actual_action <> 'SAFE_HOLD' then 1 else 0 end)
            as experiment_is_recall
    from source_data
    group by dt, order_id, driver_id
),
labeled as (
    select
        *,
        case
            when actual_is_recall = 1 and experiment_is_recall = 1 then 'KEEP_RECALL'
            when actual_is_recall = 1 and experiment_is_recall = 0 then 'NEW_HOLD'
            when actual_is_recall = 0 and experiment_is_recall = 1 then 'NEW_RECALL'
            else 'KEEP_HOLD'
        end as od_migration_type
    from od_level
)
select
    od_migration_type,
    count(*) as distinct_od_cnt,
    count(distinct concat_ws('#', dt, order_id)) as distinct_order_cnt,
    count(*) * 1.0 / sum(count(*)) over () as distinct_od_ratio
from labeled
group by od_migration_type
order by case od_migration_type
    when 'KEEP_RECALL' then 1 when 'NEW_HOLD' then 2
    when 'NEW_RECALL' then 3 else 4 end
;
```

- 在对照组的样本（去重OD）分为四类：在对照组中是否召回✖️在新策略下是否会被召回，**核心关注 NewHold（召回转hold）和NewRecall（hold转召回）这两类OD的画像和O画像**。

# 2. 核心结论

**Learning**

- 对照组在反事实结果下的真实漏斗 表明新策略确实识别到了远距离、差履约的OD并进行hold，符合策略预期；

- 但是发现在连环派场景下「远距离、差履约」并不天然等价于「完单能力差」，反而是竞争能力（播单率、pk胜率）强的。这一结论在OD维度和O维度都成立。

- 应该把OD维度的召回画像更优作为目标（距离分布上希望在远距离上多hold，时间分布上希望在是逐步放开的趋势 ），O维度的召回率不下降xpp作为约束

- **目前在中间变量上体现的收益来源：**

	- **在已召回OD样本上hold画像（距离和实际漏斗）更差的一部分OD**

	- **NewHold样本现在在距离分布上的画像是符合预期的，更多hold在远距离**

	- **NewHold样本现在在时间维度的分布基本均匀，预期在迭代ocr模型后达到hold先紧后松的分布**

	- **50% 的NewHold是过滤住了冗余的OD（该O在该轮已经召回了别的OD）**

	- **20% 的NewHold是过滤住了不够近的OD，让该O在后续轮次等到了更近的D**

- **折损风险来源：**

	- **23% 的NewHold Hold住了唯一召回的OD，使得该O未被召回，降低O维度的召回率，进而可能折损完单；看下实际漏斗，如果本身质量差可以hold**

	- **Hold住一部分虽然距离更远履约更差、但是竞争漏斗质量更高的OD，可能折损完单；目前左边公式仅考虑应答后履约（或应答后履约和距离的加权），后续还是有必要考虑在播单阶段的胜出（是否only召回）和在pk阶段的胜出（是否only举手）**

	- **存在一部分订单被提前召回，反而提升了距离，与预期链路相反；（这部分的提前召回的caa和距离均不如后续召回的，是目前策略的不足；可能原因是现在的OCR没有做到前紧后松，ocr迭代后关注这项 预期要减少这部分更差的提前召回）**

## 4.1 NEW_HOLD 画像（真实漏斗质量）

- 本章只在对照组**现状实际召回**的 OD 中比较：新策略会继续召回的 `KEEP_RECALL`，以及新策略会改为过滤的 `NEW_HOLD`。

- 「NewHold」的部分是不是合理，判断标准不是 NEW_HOLD 自身表现高低，而是它在相同连环派类型、等待阶段和距离区间内，**真实漏斗是否稳定差于 KEEP_RECALL（在目前召回的OD中 新策略是否有效识别出需要hold的订单****）**。**离线模拟的目标应该是在能在O维度召回率不负的情况下，在现状召回OD中筛选出画像更差的一批OD做增量的Hold动作。**

### 4.1.1 总体画像

非连环派的NewHold画像是符合预期的，**在各环节的漏斗都比KeepRecall的部分画像更差，说明新策略成功多hold住了更差的OD**。

**反直觉的结论：****连环派NewHold部分虽然履约更低距离更远，但是完单贡献率并不更差，在播单、举手、获胜漏斗上这部分OD的表现都更好****。**

**==为什么履约和距离都更差反而在漏斗表现上会更好。猜测是，连环派本身出现在供需更差、缺司机的场景，所以即使履约更差但竞争胜率更好。==**

- **==获胜涉及和其他商家司机的pk--看下only举手比例==**

### 4.1.2 距离分桶

- 在全部8个距离桶中，**NEW_HOLD 的单 OD 完单贡献均低于 KEEP_RECALL；可以认为NewHold的是履约更差、距离更远的OD，符合预期**

- **NewHold更多作用于远距离分桶****，在远距离分桶上Hold增量大，在近距离分桶上Hold增量小，****这个趋势是符合预期的****。**

3km以上不能简单解释为“越远越无效”。3–4km和4km以上 NEW_HOLD 的单 OD 完单贡献率分别达到4.07%和4.44%，显著高于1.5–2.35km。**单 OD 完单贡献率随距离增加先变低再变高，应答后履约率随距离增加持续变差；==远距离完单能力反而提升可能是因为出现在差供需场景，播单率、获胜率更高==****。**

**远距离 NEW_HOLD 虽然取消风险高，但其中一部分司机非常容易进入播单并赢得竞争，现实完单机会不低。过滤这部分司机可以带来较大的距离改善，但也可能产生更明显的完单机会损失。**

- **连环派的每个距离分桶下履约更差、就更远的NewHold部分的OD，反而都是竞争漏斗质量更强、完单供需更高的。这和4.1.1中整体来看的结论一致。**

- **连环派远距离在新策略下被加大hold的比例更高，更多从recall转hold。**

### 4.1.4 NEW_Hold OD对应的 O分析

这组结果需要从“策略收益”和“订单风险”两侧同时解释：

- **56%的新增 HOLD 订单在同一决策轮次仍有其他实验可召回司机。**  这部分订单不会因为过滤锚点司机而立即失去全部候选，是当前最可信的安全替代空间。

- **49%****的新增 HOLD 订单同轮已有更近司机。（hold冗余司机）**  锚点司机平均距离2,258m，而同轮替代司机的平均最短距离仅1,019m，近约1,239m；这部分最能支持“过滤远距离、低质量召回并由更近候选替代”的距离收益机制。

- **20%****的订单只有在后续对照轨迹中才观察到召回司机。** **（后续等到更近司机，hold的住要收益来源）**

- **23%****的订单没有观察到任何替代司机。** 这14.67万单是策略的主要风险群体：如果实验真的过滤锚点司机，订单可能失去现实完单机会，应设置“至少保留一个候选”、供需保护或长等待放宽。**（风险，hold OD导致整个O无召回）**

因此，同轮更近替代率49.46%可以作为策略收益侧的核心中间指标；无替代风险率23.20%应作为完单护栏。

### 5.2 NEW_RECALL OD对应的 O分析

NEW_RECALL 可能对应三种完全不同的业务价值：

1. **同轮冗余候选**：**订单同轮已经召回其他司机**，新增 OD 只扩大候选池，不增加订单召回覆盖；

2. **提前召回**：**对照组同轮没有召回，但后续轮次会召回，新策略可能缩短等待时间**；

3. **新增覆盖**：**对照轨迹始终没有召回**，新策略可能挽回订单，也可能只是新增无效播单。

```SQL

order_context as (
    select
        a.dt,
        a.order_id,
        a.anchor_driver_id,
        a.anchor_wait_time,
        a.anchor_distance_m,
        a.anchor_caa,
        a.anchor_ocr,
        a.anchor_is_serial_order,
        count(distinct case
            when s.wait_time = a.anchor_wait_time
             and s.actual_action in ('TP', 'GS')
            then s.driver_id end) as same_round_actual_recalled_driver_cnt,
        count(distinct case
            when s.score_ts > a.anchor_score_ts
             and s.actual_action in ('TP', 'GS')
            then s.driver_id end) as later_actual_recalled_driver_cnt,
        max(case
            when s.score_ts > a.anchor_score_ts
             and s.driver_id = a.anchor_driver_id
             and s.actual_action in ('TP', 'GS') then 1 else 0
        end) as same_od_later_recalled,
        min(case
            when s.score_ts > a.anchor_score_ts
             and s.actual_action in ('TP', 'GS') then s.lumian_dis
        end) as later_min_recalled_distance_m,
        max(s.is_answer) as observed_order_answered,
        max(s.is_finish) as observed_order_finished
    from anchor a
    inner join source_data s
      on a.dt = s.dt
     and a.order_id = s.order_id
    group by
        a.dt, a.order_id, a.anchor_driver_id, a.anchor_wait_time,
        a.anchor_distance_m, a.anchor_caa, a.anchor_ocr, a.anchor_is_serial_order
),

labeled as (
    select
        *,
        case
            when same_round_actual_recalled_driver_cnt > 0
                then 'A_SAME_ROUND_ALREADY_RECALLED'
            when later_actual_recalled_driver_cnt > 0
                then 'B_RECALLED_IN_LATER_ROUND'
            else 'C_NO_OBSERVED_RECALL'
        end as incrementality_type
    from order_context
),
```

# 5. O 维度画像分析

前述分析以 OD 为主，适合判断哪些司机被新增 HOLD 或新增召回，**但一个订单通常包含多个司机、多个决策轮次**。**NEW_HOLD 和 NEW_RECALL 也可能同时发生在同一个订单内，因此 OD 迁移规模不能直接等同于订单收益或损失。**

O 维度将数据压缩到 `dt + order_id`，重点回答三个问题：

1. 新策略是否让现状已经召回的订单**失去全部可召回司机**；

2. 新策略是否让**现状完全未召回的订单获得至少一个可召回司机**；

3. 对新旧策略都能覆盖的订单，候选池规模、首次召回时点和最短召回距离如何变化。

### 6.1 O维度召回率

口径

O维度的召回：召回od数>0

O维度的hold：召回od数=0

```PlainText
    select
        *,
        case
            when actual_recalled_driver_cnt > 0 and experiment_recalled_driver_cnt > 0

            when actual_recalled_driver_cnt > 0 and experiment_recalled_driver_cnt = 0
                then 'B_NEW_ORDER_HOLD'
```

- **订单维度的净召回比例下降2.8pp****，会带来完单折损风险。****O维度净召回损失主要发生在非连环派（4pp），原因是去除了近距离不过滤规则。连环派O维度净召回损失仅0.4pp。**

从两个条件集合内部看：
