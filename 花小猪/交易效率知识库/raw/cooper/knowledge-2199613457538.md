# 背景描述

目前派单引擎的分单策略主流程为： 召回 → 价值 → 倾斜 → 匹配 → (改派)。价值模块，顾名思义为计算召回得到的匹配对的“价值”。在GS匹配中，我们将价值拆分成司机视角和乘客视角，司机视角采用订单iph，乘客视角采用接驾距离。

而**如此计算司机侧价值，仅仅考虑了当前一轮的匹配，没有考虑长远利益。**例如，在某一次匹配中，司机A有两个可选订单a和b，而a订单iph > b订单iph，因此GS匹配会优先考虑订单a。但是有可能订单b的终点是更热的地区，接到大单的概率更大，例如火车站、飞机场等等，而a订单的终点也许是偏远地区。这种情况下显然b订单带来的未来价值要大于a订单，因此，基于此提出MDP价值计算，来改进原有价值计算方式。改进目标就是，提升司机IPH，进而提升平台GMV和毛利率。

# 问题建模

马尔可夫决策过程(MDP，Markov Decision Process)通常用于对顺序决策问题进行建模。

![](https://s3-ep-inter.didistatic.com/didoc-upload-file-prod/1653034041706/860100207.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T104122Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=55e071eb95026257c3078046691f743dcf61d92a0e4bfe2d9afad14d35d52251)

将司机视为MDP中的agent，MDP中的state定义为司机所在的格子id以及当前时间，MDP中的action为每个状态下可选的订单。由此，**可将司机一天的行为状态用MDP来表示，同样每一action带来的订单价值之和就是一整天的收益**。

借助MDP，要解决的问题就可以表示成

 $ \\pi ( s, A ) = \\ argmax \_ { a \\in A } \\ r_a + \\gamma V ( s' ) $ ，$ s' = MDP(s, a) $

其中，s表示当前状态，包括时间和格子，a表示订单，A表示当前状态s下可选择的订单集合，a是在A集合中的一个订单，s'表示当前状态s下选取某一订单a跳转的下一状态，PI是由历史数据得到的策略，V是在某个状态下采取某个动作得到的奖励期望。

上式的**含义就是在每个状态下选取价值最大的动作，贪心求解使得司机最终一天的总收入最大化**。

# 问题求解

## 蒙特卡洛（MC）求解

将问题抽象成上式以后，只需求解价值函数V。由于可以借助历史数据，故采用蒙特卡洛(MC)的方法求解。

假设一个司机一天的MDP轨迹表示如下：

 $ S \_ { 1 } , A \_ { 1 } , R \_ { 2 } , S \_ { 2 } , A \_ { 2 } , \\ldots S \_ { t } , A \_ { t } , R \_ { t + 1 } , \\ldots R \_ { T } , S \_ { T } $

```PlainText
定义价值函数如下：
```

 $ V \_ { \\pi } ( s ) = \\mathbb { E } \_ { \\pi } \\left( G \_ { t } \\mid S \_ { t } = s \\right) = \\mathbb { E } \_ { \\pi } \\left( R \_ { t + 1 } + \\gamma R \_ { t + 2 } + \\gamma ^ { 2 } R \_ { t + 3 } + \\ldots \\mid S \_ { t } = s \\right) $

那么所有历史数据可以形成若干条轨迹，只需要求出所有的完整序列中该状态出现时候的收益再取平均值即可近似求解，根据大数定律，数据量越大，越接近真实值。

其中gama表示的是衰减因子，用来减小未来订单对当前状态价值计算的影响，R表示每一单的收益，G表示总收益。

## 时间差分（TD）求解

在介绍TD learning之前，我们先引入如下简单的蒙特卡罗算法，我们称为**constant-α MC**，它的状态值函数更新公式如下：

 $ V \\left( s \_ { t } \\right) \\leftarrow V \\left( s \_ { t } \\right) + \\alpha \\left\[ R \_ { t } - V \\left( s \_ { t } \\right) \\right\] $

其中Rt是每个episode结束后获得的实际累积回报, alpha是学习率，这个式子的直观的理解就是**用实际累积回报Rt作为状态值函数V(st)的估计值**。具体做法是对每个episode，考察实验中st的实际累积回报Rt和当前估计V(st)的偏差值，并用该偏差值乘以学习率来更新得到V(st)的新估值。

现在我们将公式修改如下，把Rt换成rt+1 + gamma \* V(st+1), 就得到了TD(0)的状态值函数更新公式：

 $ V \\left( s \_ { t } \\right) \\leftarrow V \\left( s \_ { t } \\right) + \\alpha \\left\[ r \_ { t + 1 } + \\gamma V \\left( s \_ { t + 1 } \\right) - V \\left( s \_ { t } \\right) \\right\] $

# 算法细节

### semi-MDP（个人理解，有可能有错）

连续时间的MDP：从一个状态转移到另一个状态的时间是符合指数分布的，并且当前状态只与前一状态相关，与历史状态无关。

离散时间的MDP：从一个状态转移到另一个状态的时间是符合几何分布的，并且当前状态只与前一状态相关，与历史状态无关。

而由于订单的随机性，导致司机从一个状态（接单）到另一状态（完单）的时间是随机的。并且在状态转移的过程中（送驾）所经历的状态，是依赖于历史状态的，不仅仅只依赖于前一时刻的状态（路径规划）。

因此，可以把MDP扩展到semi-MDP，semi-MDP可以解决部分状态不具有马尔可夫性，并且状态转移时间是随机分布的。

### 状态s定义

当前格子id和时间t，时间按照每5min进行划分，例如8:00:00-8:04:59内都视为一个时间状态下。

例如北京，3800格子，总状态3800\*12\*24。

### 动作a定义

如果考虑Q价值函数来计算的话，那么需要定义动作空间；而如果用V价值函数计算的话，不需要定义动作空间；

选单：去每个格子看成是一种动作，比如一共1000个格子，就有1000钟动作；

不选单：只有一种动作，不选单；

整个动作空间 = 选单动作集合 + 不选单

**奖励值计算**

 $ R \_ { \\gamma } = \\sum \_ { t = 0 } ^ { T - 1 } \\gamma ^ { t } \\frac { R } { T } $

```PlainText
如果当前有一订单从s(A,0)至s(B,3)，价值30元，预估完单时间（包括接驾，等待，送驾时间）15min，那么该订单的iph是10元／时间片，假设gamma=0.9，则奖励值是
```

 $ r=10+10\*0.9+10\\times0.9^2=27.1 $

### 状态转移

状态转移时间在求解的时候采用预估时间。

### 短期收益

在求解价值的时候，对于每个时空状态下的价值，以历史上未来2h的收益求解。如当前时间是8:00:00，那么所用的历史数据在线时间要囊括8:00:00\~10:00:00。

司机可能不会全天在线，全天价值也会衰减。

乘客侧依旧按照距离作为边权。

司机侧边权按照公式

 $ A(i, j) = r + \\gamma ^ { t } V(s') $

其中i,j分别表示司机和乘客id，r表示当前所连订单的价格，gamma暂定0.9，t表示预估接驾+等待+送驾时长，s‘表示订单终点格子和预计完单时间，s'k表示s’相邻一圈格子和时间的状态，取平均来衡量订单终点格子和时间的价值。

司机和空节点的边权定义为：

 $ A(i, i) = V(s) $

其中，s表示当前格子的状态，用该状态表示司机轮空情况下未来收益的期望。

因为空节点不会存在冲突，所以没有乘客侧边权。

### 空节点衰减

随着司机等单时间增长，空节点的价值逐渐降低，防止司机一直空跑。

### trick

为了防止周边格子价值高，当前格子价值低，故采用平均价值做平滑。

空节点，衰减等待价值，防止司机无单时间太长。

# 反思

上线后效果不明显，反思的点以及更新计划：

1，目前是离线更新，每周或每天更新一次，这样无法反应实时热度状况，比如突然下大雨会明显改变某个区域的热度；后面采用的是增量更新方法，这样可以每个时间片更新一次；

2，样本稀疏（冷区 热区但没订单），冷区指的是几乎没有订单到达过，但它可能离热区很近，司机可以到达冷区后再到旁边的热区接下一单；实际情况是司机愿意接这样的单，但因为热度低，系统不倾向于推荐这样的订单；可以采用平滑处理的方法（建议取MAX（邻域的MDP值））；热区的情况则是这个地区有很多乘客，但因为交通不便或其它原因导致很少有订单来到，MDP值低但实际热度高，这也是需要被挖掘的；

3，目前Hold和MDP分离的，可以用基于空节点的方式把两者合并；
