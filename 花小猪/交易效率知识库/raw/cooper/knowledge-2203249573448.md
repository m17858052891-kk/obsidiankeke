# 项目背景

PK是聚合平台里分单系统的一部分。PK算法旨在在一个时间窗口内从所有举手的司机中选最优司机给某个订单，作为该订单的最终胜者。动态PK窗口策略是一种通过动态调节PK时间间隔以提升资源利用率以及收益的策略。PK时间不能过短，因为不同司机的举手时间有先后顺序，如果时间太短可能让订单错过更好的司机，另外PK时间不能过长，因为算法在PK时间截止才决定分配哪辆司机，订单在等待过程中可能会取消，影响完单；另外时间过长也会影响运力资源。因为如果只考虑当前平台PK过程，司机在PK时会锁定在当前订单中，无法匹配到其他的单子。本文主要考虑强化学习来设计PK算法，在选取最好司机给订单的同时尽可能减少PK窗口的时间。

# 问题描述

一次PK过程中，每个订单会对应一至多个举手司机，每个司机只能匹配一个订单。司机会在不同的时间点先后举手，策略需要实时决定是否需要关闭PK 窗口以及从已经举手的司机里选择一个司机给当前订单。将问题建模成一个强化学习的问题：

# V0强化学习PK策略

## 问题建模

第一版策略考虑在模拟器上进行仿真，需要将所有强化学习的要素定义好，具体如下：

1. 状态$$S_t$$：定义为第t秒时订单的相关特征，供需相关特征。

2. 动作$$A_t$$：定义为第t秒时决定是否关闭窗口， 0表示关闭当前PK窗口，未到的司机无法继续举手了。

3. 奖励$$R_t$$:   定义为：$$\Delta(t) / t - \alpha \times t$$ , 其中 t 为当前经过的PK时间长度，$$\Delta(t)$$ 表示第t秒到达的司机与t秒前到达司机的最大履约率的差。也可以用完单量来替代。

4. 智能体：动态PK算法，基于当前时刻的状态和奖励在决定当前时刻的动作。

5. 环境：这里表示的是模拟器，提供当前时刻智能体决策所需的状态和奖励信息，为RL算法训练的交互接口。

## 实现细节

### 训练智能体：

我们选取基于Q-learning 的方法来训练我们的PK 策略。具体来说，该算法有一个函数来评估在当前状态下采取当前动作对当前订单的收益：$$Q(s,a)：{{\mathcal{S}}\times{\mathcal{A}}\to\mathbb{R}}$$在开始学习之前，将Q(s,a) 初始化为任意固定值（由程序员选择）。然后，在每个时间t，智能体选择一个动作$$A_t$$，观察奖励$$R_{t+1}$$并进入新状态$$S_{t+1}$$（取决于先前状态和所选动作），然后更新Q。该算法的更新是利用贝尔曼方程作为简单的值迭代更新，使用当前值和新信息的加权平均值：

![](https://s3-ep-inter.didistatic.com/didoc-upload-image-prod/173018335965767bbc571e12ef076ce2bcffc349e3e2c/Pastedimage20241028201142.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T110318Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=07037576b03620c9210afcfbd9ce0501b6d7f4382a77bbe07391cbc54946eac5)

$$\alpha$$是学习率预先定义为0.99。策略的动作选择通过比较每一个动作的值函数，也就是$$Q(s,a_i), ~ a_i = 0,1$$。直观来说，**这个公式会让策略学会为不同状态选择最优停止时间**，它会用一个叫「Q表」的表格来记录每个「状态-动作对」的价值。 价值越高，说明在该状态下做这个动作能更快获得奖励。 在学习过程中，策略不断地更新这个Q表，最终让自己学会最佳的决策方式。

## 环境实现

环境主要用于提供智能体交互和决策所需的状态和奖励信息。除了定义动作、状态。还需要实现状态转移模型(dynamic model)。假设当前订单司机的到达时间服从时间变量上的高斯分布，并且司机的履约率随机生成\[50, 100\]的数，不同司机的到达时间和履约率互相独立。另外还将pk策略的决策时间离散化，例如，每隔0.5秒允许策略采取一次动作进行决策。因此每隔0.5秒，司机会以一定的概率到达，模拟器会更新下一步状态和奖励的信息。注意智能体只能观察到当前时间前已经举手的司机的信息。

**优化点1: 该环境的代码实现严格按照强化学习环境OpenAI Gym 的 API 标准，可以容易移植常用的强化学习算法。**

## 实验结果：

我们比较强化学习的动态PK窗口算法在每种固定时间下的完单量。我们比较我们的算法与固定时间窗口算法的性能，假设最大可能的PK 窗口的长度8，固定时间窗口算法分别在1，2，... 7秒内关闭PK窗口。我们在随机选取1000个订单中测试。与**固定时间算法相比，我们的方法获得接近最佳的完单量，并且平均窗口长度接近理论最优**。

# V1强化学习策略：

为了上一版的模拟器更符合实际情况，我们需要从离线数据集中学习两个关键参数，一个是假设了当前订单下司机的到达时间概率分布，另一个是需要利用离线数据集估计司机的履约分。现在已经有了履约分预测模型。我们还需要去预测司机的到达时间概率分布。

司机到达时间分布通过当前订单特征和供需特征来影响，我们利用离线数据训练了到达时间分布模型。离线数据分布为：

使用回归模型进行训练，模型收敛后MSE约为0.3。到达时间模型可以用来替代V0版本的柏松分布。

总结该版本的改进如下：

**优化点1: 使用离线数据来对模拟器中的特征进行模拟，替代了特征在分布上的强假设，模拟器更加接近真实效果**

**优化点2: 环境中的状态转移模型将供需特征和司机特征进行解耦合，这些信息包含在了额外的模型中。动机：状态转移模型需要模拟每一个时刻所有司机可能的情况，计算动力学方程的时间复杂度为$$\mathcal{O}(d^N \cdot T)$$, 其中N为司机种数，T 为时间不长，d 为特征维度。这种情况下特征的维度应该尽可能小。**

**优化点3: 我们将强化学习替换成基于稀疏奖励的Q-learning算法，奖励模型可以通过完单来提供。（完单是对整条PK轨迹进行打分，履约分是对单个状态进行打分）。**
