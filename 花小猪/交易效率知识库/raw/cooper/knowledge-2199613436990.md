- 模拟系统启动并测试build

- ## 当user需要拉取环境并启动与其他user**互不干扰**的模拟器 && 当你想要**并行**多个模拟器自己做实验时，你可以(稳定后会同步在readme上)：

- **模拟环境启动**

- server、client通过port number对应

- 

- **step #1 server build**

- git拉取repo并build server：

	- git clone [https://git.xiaojukeji.com/Zeroizer/share_simulation_env.git](https://git.xiaojukeji.com/Zeroizer/share_simulation_env.git)

	- cd share_simulation_env

	- git checkout test1.0

	- cd server && mkdir bin (非常重要)

	- sh build.sh

- 

- **step #2 server start**

- build完server之后启动server端，需要手动配置port number，e.g. 8888:

	- cd scripts

	- 在server_start.sh里修改port号并保存

	- sh server_start.sh

- 

- **step #3 client start**

- 手动配置client端与已经启动的server对应的port number：

- 1\. 在client_start.sh里修改port号并保存

- 2\. sh client_start.sh

- 3\. make sure step #3 的conda/pip环境下有thrift包

- 

-  同时在readme中了解server / client的相关用法

- repo：<https://git.xiaojukeji.com/Zeroizer/share_simulation_env/tree/test1.0>  
client_test.py 提供了详尽的示范功能  
  
**实际上，step2、3可以自定义为你想要启动的shell文件**，只要对应好port number 即可，建议在shell脚本中添加awk语句在模拟完成后结束端口对应程序  

- 现有policy现在提供了km、greedy gs以及gs、gs连环派的policy使用
