# **一、背景**

本次策略方案作为补刀需求，商家召回策略V1.0当前已完成完整实验，逐步放量中，但主要缺乏对播单 -> PK -> 完单中的PK关于竞争胜率的漏斗，导致实际value价值判断中并未考虑所选择OD的竞争胜率，缺乏对完单期望的整体估计。

# 二、收益预估

## **核心目标**

> **在三端整体完单不负的条件下，提升端内完单+0.1%**

## 收益预估：

过滤端外低胜率画像OD（约占总举手2%），使这些司机资源有机会参与更优订单举手，通过司机资源腾挪的方式提升端内完单量。

# 三、策略细节

【数据源：召回V1.0时间片实验生效时期20260914-20260919的实验组，实验城市：33, 22, 58, 14, 157, 125, 38, 6, 19, 50, 42, 153】

## 3.1 问题发现

（1）竞争胜率与距离关系

在召回V1.0中发现竞争胜率实际并未呈现“距离越长、胜率越低”的单调性关系，下面分端计算胜率分桶与平均接驾距离的关系也可以验证该问题，所以才导致在召回V1.0线上实验中无法调节竞争胜率模型和距离的单调性关系。

（2）长距离高竞争胜率特征

对比低竞争胜率VS高竞争胜率的候选OD特征，可以发现这些长接驾距离却有着高竞争胜率的候选OD主要是因为等待时间长、供需较差，所以在一个竞争候选OD本就较少的场景下，所剩的长接驾距离的OD也会胜出。

## 3.2 改造必要性&充分性

- **改造必要性：**

	- 现有召回策略并没有在总体上优先过滤低胜率分数，主要过滤的是长接驾距离候选，而低竞争胜率的候选OD进入匹配和后续PK环节仍然不会胜出却会占据司机资源；【OD通过率：进入召回矩阵的候选OD/模型日志中的候选OD】

- **改造充分性：**当前竞争胜率模型的高分画像和低分画像大致有如下特点，

	- 高分画像：订单长等待但供需紧张；

	- 低分画像：等待时间短、周围空闲司机多供给充足，但长接驾距离。

## 3.3 策略方案

根据前面分析可以知道，召回V1.0策略在过滤长距离的OD上表现优秀，但缺乏对低胜率的候选OD过滤，本次改造的目的是将竞争胜率低的候选OD过滤，使这些司机资源有机会参与其他订单。

# 四、工程说明

继续召回V1.0中调用winrate_net_baseline_onnx模型，获取gs_value作为竞争胜率，过滤“**滴滴+PBD端gs_value <= 0.1且接驾距离>=1000m**”的候选OD。
