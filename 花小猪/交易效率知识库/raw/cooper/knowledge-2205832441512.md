# 一、背景

差供需保端策略已上线一年，作为一个端流量分发的抓手，根据丢单力度的不同，预估会提升端内0.2%至0.7%的完单。

在某些场景下，端外丢弃的订单不能够被API承接，导致置换比差；另一方面，释放出的可控运力腾挪到端内时会争夺API的订单，导致运力浪费。

基于以上两点，提出本需求进行优化改进。

# 二、需求收益

提升差供需保端策略效率，衡量指标为大聚合完单折损/端内完单增量的置换比

# 三、需求细则

1. 需要建设端外实时供需特征：格子及周围一圈格子5分钟联盟端呼叫数、格子及周围一圈格子5分钟联盟端API呼叫数、格子及周围一圈格子5分钟联盟端API应答数、格子及周围一圈格子5分钟小猪端API应答数

2. 联盟端订单特征：是否勾选API

3. 城市维度实时特征：全城近5分钟呼叫数、全城近5分钟应答数

4. 逻辑优化：

	1. 原逻辑：根据端内格子及周围一圈格子5分钟呼叫数>x、应答率<y，丢弃里程<z的呼叫

	2. 改造：

		1. 根据全城近5分钟应答率<yy，丢弃里程<zz的呼叫

		2. 根据端内格子及周围一圈格子5分钟呼叫数【计作A】、应答率【计作P】、API应答占总应答【计作F】、API是否进勾选【计作C】、格子及周围一圈格子5分钟联盟API应答率【计作D】，格子及周围一圈格子5分钟联盟API应答数【计作B】，四个特征的组合判断，丢弃里程<z的呼叫（会有多种组合）

		3. 公式：$$\frac{B(1-CD)}{min(A-AP,B)(1-PF^2)}$$和一个阈值判断是否丢弃，根据$$\frac{A-AP}{B}$$的比例进行丢弃里程<z的呼叫

5. 数据：以上新建特征，上线后需空跑一周收集数据

6. 实验：支持格子id分流实验
