Q：将取消从应答前向应答后腾挪的收益链路是否可行？A：v1_1实验组2已验证可行，v1_2实验组已实现。

# 四、中间过程结果

### 4.0 结论

- **符合预期的：**

	- 加强 HOLD 稳定降低召回及应答距离

	- 加强 HOLD 提高召回后质量，但牺牲召回覆盖和总体完单

- **不符合预期的：**

	- **加强 HOLD 没有表现为“更晚召回”，而是让召回更加集中在早期。**

	- **HOLD 更集中地过滤了远距离候选，但也误伤近距离候选。--需要验证近距离过滤是否值得**

### 4.1 OD×轮次：每轮动作与召回画像

- **调用召回率（OD✖️轮次维度）**：反映召回强度；预期加强 HOLD 后下降，放宽 TP 后上升或持平。

- **TP 召回占比**：反映 TP/GS 路径结构；预期放宽 TP 后上升。

- **平均召回距离**：反映放行候选的距离；预期加强 HOLD、过滤远距离候选后下降。

- **平均召回等待时长**：反映召回发生的早晚；预期 TP 提前放行时下降，HOLD 延迟放行时上升，整体方向取决于两者作用。

- **入样 OD×轮次数**：反映调用规模；相同流量下，持续 HOLD 可能增加后续调用，不预设越高或越低越好。

```SQL
SELECT
    exp_group,
    count(*) AS od_round_cnt,

    100.0 * sum(CASE WHEN action IN ('TP', 'GS') THEN 1 ELSE 0 END)
        / nullif(count(*), 0) AS recall_rate,

    100.0 * sum(CASE WHEN action = 'TP' THEN 1 ELSE 0 END)
        / nullif(
            sum(CASE WHEN action IN ('TP', 'GS') THEN 1 ELSE 0 END),
            0
        ) AS tp_share_in_recalled,

    avg(CASE WHEN action IN ('TP', 'GS') THEN lumian_dis END)
        AS avg_recalled_distance,

    avg(CASE WHEN action IN ('TP', 'GS') THEN wait_time END)
        AS avg_recalled_wait_time

FROM source_data
GROUP BY exp_group;
```

```SQL
-- Distinct OD 距离/时间取窗口内末次召回记录（TP/GS）；后续 HOLD 不覆盖该取值。
-- 末次按 wait_time DESC、score_time DESC；距离和时间取同一条记录，距离缺失不回退。
-- Spark SQL / Hive 窗口与 CTE 语法；只查询，不建表、不写表。
-- 使用：修改 params 的日期/时刻和 raw 的源表；五个组名在最终透视中修改。
-- 所有结果是窗口内观察，不宣称完整生命周期；百分比输出 0–100。
-- dt 为日期键，跨日同订单会分开；wait_time 作为轮次代理需业务确认。
-- 漏斗标签为 OD 日级曾发生标记，不能用于轮次播单或事件时序推断。
WITH params AS (
    SELECT '2026-08-22' AS start_dt, '2026-08-23' AS end_dt,
           '2026-08-22 00:00:00' AS start_time,
           '2026-08-24 00:00:00' AS end_time
),
raw AS (
    SELECT cast(t.dt AS string) AS dt, cast(t.order_id AS string) AS order_id,
           cast(t.driver_id AS string) AS driver_id, t.exp_group,
           cast(t.wait_time AS double) AS wait_time,
           cast(t.score_time AS string) AS score_time,
           upper(t.action) AS action,
           CASE WHEN t.lumian_dis >= 0 THEN cast(t.lumian_dis AS double) END AS distance_m,
           cast(t.is_broadcast AS int) AS b,
           cast(t.is_handup AS int) AS h, cast(t.is_winner AS int) AS w,
           cast(t.is_answer AS int) AS a, cast(t.is_finish AS int) AS f
    FROM kflower_strategy_dev.all_od_base_0822_0823_funnel t CROSS JOIN params p
    WHERE cast(t.dt AS string) BETWEEN p.start_dt AND p.end_dt
      AND cast(t.score_time AS string) >= p.start_time
      AND cast(t.score_time AS string) < p.end_time
      -- 可在此追加城市等条件；四份 SQL 必须使用相同条件。
),
-- 跨组或分组缺失的订单整单排除，不能按 max(exp_group) 随意归组。
valid_orders AS (
    SELECT dt, order_id FROM raw
    WHERE dt IS NOT NULL AND order_id IS NOT NULL
    GROUP BY dt, order_id
    HAVING count(DISTINCT exp_group) = 1 AND count(exp_group) = count(*)
),
src AS (
    SELECT r.* FROM raw r JOIN valid_orders v
      ON r.dt=v.dt AND r.order_id=v.order_id
    WHERE r.driver_id IS NOT NULL AND r.wait_time >= 0
      AND r.score_time IS NOT NULL
),
-- 同时刻重复召回先聚合；不同动作的时间并列记为冲突，不任意优先 TP。
recall_events AS (
    SELECT dt,order_id,driver_id,exp_group,wait_time,score_time,
           avg(distance_m) AS distance_m,
           CASE WHEN min(action)=max(action) THEN min(action) END AS first_action
    FROM src WHERE action IN ('TP','GS')
    GROUP BY dt,order_id,driver_id,exp_group,wait_time,score_time
),
ranked_recall AS (
    SELECT e.*,
      row_number() OVER (PARTITION BY dt,order_id,driver_id,exp_group,wait_time ORDER BY score_time) AS rn_round,
      row_number() OVER (PARTITION BY dt,order_id,driver_id,exp_group ORDER BY wait_time DESC,score_time DESC) AS rn_od
    FROM recall_events e
),
round_base AS (
    SELECT dt,order_id,driver_id,exp_group,wait_time,
      max(CASE WHEN action IN ('TP','GS') THEN 1 ELSE 0 END) AS recalled
    FROM src GROUP BY dt,order_id,driver_id,exp_group,wait_time
),
rt AS (
    SELECT x.*,r.distance_m,r.first_action
    FROM round_base x LEFT JOIN ranked_recall r
      ON x.dt=r.dt AND x.order_id=r.order_id AND x.driver_id=r.driver_id
     AND x.exp_group=r.exp_group AND x.wait_time=r.wait_time AND r.rn_round=1
),
od_flags AS (
    SELECT dt,order_id,driver_id,exp_group,
      max(CASE WHEN action IN ('TP','GS') THEN 1 ELSE 0 END) AS recalled,
      max(b) AS b,max(h) AS h,max(w) AS w,max(a) AS a,max(f) AS f
    FROM src GROUP BY dt,order_id,driver_id,exp_group
),
od AS (
    SELECT x.*,r.distance_m,r.wait_time AS last_recall_wait,r.score_time AS last_recall_time
    FROM od_flags x LEFT JOIN ranked_recall r
      ON x.dt=r.dt AND x.order_id=r.order_id AND x.driver_id=r.driver_id
     AND x.exp_group=r.exp_group AND r.rn_od=1
),
ot AS (
    SELECT dt,order_id,exp_group,wait_time,max(recalled) AS recalled,
      sum(recalled) AS candidate_cnt,avg(CASE WHEN recalled=1 THEN distance_m END) AS distance_m
    FROM rt GROUP BY dt,order_id,exp_group,wait_time
),
order_first_rank AS (
    SELECT dt,order_id,exp_group,last_recall_wait,
      row_number() OVER (PARTITION BY dt,order_id,exp_group ORDER BY last_recall_time,last_recall_wait,driver_id) AS rn
    FROM od WHERE recalled=1
),
o_agg AS (
    SELECT dt,order_id,exp_group,max(recalled) AS recalled,
      max(b) AS b,max(h) AS h,max(w) AS w,max(a) AS a,max(f) AS f,
      avg(CASE WHEN recalled=1 THEN distance_m END) AS distance_m
    FROM od GROUP BY dt,order_id,exp_group
),
o AS (
    SELECT x.*,z.last_recall_wait FROM o_agg x LEFT JOIN order_first_rank z
      ON x.dt=z.dt AND x.order_id=z.order_id AND x.exp_group=z.exp_group AND z.rn=1
),
group_metrics AS (
    SELECT exp_group,
      count(*) AS m0,
      100.0 * (sum(recalled)) / nullif((count(*)),0) AS m1,
      100.0 * (sum(CASE WHEN recalled=1 AND b=1 THEN 1 ELSE 0 END)) / nullif((sum(recalled)),0) AS m2,
      avg(distance_m) AS m3,
      avg(last_recall_wait) AS m4
    FROM od GROUP BY exp_group
),
metric_rows AS (
    SELECT 1 AS sort_no, '入样 OD 数' AS metric, '个' AS unit, '窗口内 dt+order+driver 去重' AS note, exp_group, cast(m0 AS double) AS value FROM group_metrics
    UNION ALL
    SELECT 2 AS sort_no, '曾召回率' AS metric, '%' AS unit, '窗口内至少一次 TP/GS' AS note, exp_group, cast(m1 AS double) AS value FROM group_metrics
    UNION ALL
    SELECT 3 AS sort_no, '召回且曾播单率' AS metric, '%' AS unit, 'OD 日级标签；共现比例，不保证播单在本窗口或召回之后' AS note, exp_group, cast(m2 AS double) AS value FROM group_metrics
    UNION ALL
    SELECT 4 AS sort_no, '末次召回平均距离' AS metric, 'm' AS unit, '每个曾召回 OD 等权，窗口内末次TP/GS，按wait_time降序、score_time降序选取' AS note, exp_group, cast(m3 AS double) AS value FROM group_metrics
    UNION ALL
    SELECT 5 AS sort_no, '末次召回平均等待时长' AS metric, 's' AS unit, '每个曾召回 OD 等权，窗口内末次TP/GS，按wait_time降序、score_time降序选取' AS note, exp_group, cast(m4 AS double) AS value FROM group_metrics
)
SELECT 'distinct OD' AS `粒度`, metric AS `指标`, unit AS `单位`,
       round(max(CASE WHEN exp_group='control_group' THEN value END),2) AS `对照组`,
       round(max(CASE WHEN exp_group='treatment_group' THEN value END),2) AS `G1`,
       round(max(CASE WHEN exp_group='treatment_group_2' THEN value END),2) AS `G2`,
       round(max(CASE WHEN exp_group='treatment_group_3' THEN value END),2) AS `G3`,
       round(max(CASE WHEN exp_group='treatment_group_4' THEN value END),2) AS `G4`,
       note AS `口径备注`
FROM metric_rows
GROUP BY sort_no,metric,unit,note
ORDER BY sort_no;
```

### 4.5 距离分布（Distinct OD）

- **近距离 HOLD OD 比例**：反映近距离候选被 HOLD 的程度；预期减少不必要的过滤。

- **远距离 HOLD OD 比例**：反映远距离候选的过滤程度；预期加强 HOLD 后上升。

- **HOLD 比例随距离的变化**：反映过滤是否集中于远距离；预期整体随距离增加而提高。

**口径描述。** 窗口内按dt＋order_id＋driver_id去重，每个OD只计一次；以首次入样记录（score_time升序、wait_time升序）的lumian_dis分桶。每桶 HOLD OD 比例＝窗口内从未出现TP/GS的OD数／该桶全部入样OD数；即 action 不是 TP/GS 的 OD 记为 HOLD。多次HOLD后召回计入已召回。暂以首次距离代表OD距离，移动很小的假设后续验证。

### 4.6 等待时长分布（召回Distinct O）

- **目前的加强 HOLD 没有表现为“更晚召回”，而是让召回更加集中在早期。**

- **曾召回订单率**：反映窗口内获得过至少一个召回候选的订单覆盖；预期加强 HOLD 后可能下降，需结合业务结果判断是否值得。

- **从未召回订单率**：反映策略完全未提供召回机会的订单风险；预期不能明显上升。

- **短等待末次召回订单占比**：反映曾召回订单的召回动作是否较早结束；占比提高表示召回更集中在早期。

- **长等待末次召回订单占比**：反映订单等待较久后是否仍发生召回；占比提高可能表示后期放宽，也可能表示订单更久未结束。

- **累计订单占比**：反映多少曾召回订单在指定等待时间前完成末次召回；预期曲线前移，但必须同时检查曾召回订单率。

```SQL
-- 召回后置过滤下钻
--
-- 统计对象：control_group 中非连环派、决策为 hold、接驾距离 < 1km 的候选 OD。
-- 匹配口径：safe_log 发生在 score_time 后 0~2 秒（含边界）。
-- 判定口径：同一决策轮次的匹配窗口内，只要出现任一非 0 filter_type，
--           该轮即判为“已过滤”；仅出现 0 时判为“未过滤”。
-- 注意：无 safe_log 的轮次单独统计，不归入“未过滤”。

with total_raw as (
    select
        substr(score_time, 1, 10) as dt,
        cast(order_id as string) as order_id,
        cast(driver_id as string) as driver_id,
        wait_time,
        score_time,
        unix_timestamp(score_time, 'yyyy-MM-dd HH:mm:ss') as score_ts
    from kflower_strategy_dev.all_od_base_0822_0823_3s
    where exp_group = 'control_group'
      and is_serial_order = 0
      and lower(action) = 'hold'
      and cast(lumian_dis as double) >= 0
      and cast(lumian_dis as double) < 1000
      and score_time is not null
      and order_id is not null
      and driver_id is not null
),

-- 源表可能因日志重试产生完全重复行，先收敛到“一轮一个候选 OD”。
total as (
    select distinct
        dt,
        order_id,
        driver_id,
        wait_time,
        score_time,
        score_ts
    from total_raw
    where score_ts is not null
),

safe_log as (
    select
        concat_ws('-', year, month, day) as dt,
        cast(param['base_oid'] as string) as base_oid,
        cast(param['did'] as string) as did,
        param['timestamp'] as log_time,
        unix_timestamp(param['timestamp'], 'yyyy-MM-dd HH:mm:ss') as log_ts,
        cast(trim(param['filter_type']) as int) as filter_type
    from kflower_marketplace.ods_log_kflower_safe_log_hh_h
    -- 按天过滤小时分区，避免用 yyyy-MM-dd-HH 与 yyyy-MM-dd 比较而漏掉结束日。
    where concat_ws('-', year, month, day) between '2026-08-22' and '2026-08-23'
      and param['base_oid'] is not null
      and param['did'] is not null
      and param['timestamp'] is not null
      and unix_timestamp(param['timestamp'], 'yyyy-MM-dd HH:mm:ss') is not null
),

-- 先按决策轮次聚合，防止多条 safe_log 放大样本。
round_filter_result as (
    select
        t.dt,
        t.order_id,
        t.driver_id,
        t.wait_time,
        t.score_time,
        count(s.base_oid) as matched_log_cnt,
        max(case
            when s.filter_type is not null and s.filter_type <> 0 then 1
            else 0
        end) as has_filtered_log,
        max(case when s.filter_type = 0 then 1 else 0 end) as has_no_filter_log
    from total t
    left join safe_log s
      on t.dt = s.dt
     and t.order_id = s.base_oid
     and t.driver_id = s.did
     and s.log_ts between t.score_ts and t.score_ts + 2
    group by
        t.dt,
        t.order_id,
        t.driver_id,
        t.wait_time,
        t.score_time
),

-- 原查询按 order_id + driver_id 统计，因此跨轮次继续收敛到候选 OD。
-- 若任一轮被过滤，则该 OD 记为已过滤；仅在有日志且所有轮均未过滤时记为未过滤。
od_filter_result as (
    select
        order_id,
        driver_id,
        sum(matched_log_cnt) as matched_log_cnt,
        max(has_filtered_log) as has_filtered_log,
        max(has_no_filter_log) as has_no_filter_log
    from round_filter_result
    group by order_id, driver_id
)

select
    count(*) as tt_cnt,
    sum(case
        when matched_log_cnt > 0 and has_filtered_log = 0 and has_no_filter_log = 1 then 1
        else 0
    end) as no_filter_cnt,
    sum(case when has_filtered_log = 1 then 1 else 0 end) as filtered_cnt,
    sum(case when matched_log_cnt = 0 then 1 else 0 end) as no_log_cnt,
    sum(case
        when matched_log_cnt > 0 and has_filtered_log = 0 and has_no_filter_log = 0 then 1
        else 0
    end) as invalid_filter_type_cnt,
    1.0 * sum(case
        when matched_log_cnt > 0 and has_filtered_log = 0 and has_no_filter_log = 1 then 1
        else 0
    end) / nullif(count(*), 0) as no_filter_ratio,
    1.0 * sum(case when has_filtered_log = 1 then 1 else 0 end)
        / nullif(count(*), 0) as filtered_ratio,
    1.0 * sum(case when matched_log_cnt > 0 then 1 else 0 end)
        / nullif(count(*), 0) as safe_log_coverage_ratio
from od_filter_result;
```

**新模型离线效果**

模型结构和线上推理接口保持不变，仅在原标签损失之外增加距离惩罚：

$$L_{\text{total}} = L_{\text{label}} + \lambda L_{\text{distance}}$$

距离惩罚损失的计算公式为：

$$\boxed{ L_{\text{distance}} = \frac{1}{N} \sum_{i=1}^{N} w(d_i)\cdot BCE(t(d_i),p_i) }$$

其中，\\(N\\) 为有效样本数，\\(d_i\\) 为接驾距离，\\(p_i\\) 为模型预测取消率。

距离方向目标为：

$$t(d)= \begin{cases} 0,& d<d_0\\ 1,& d>d_0 \end{cases}$$

默认基准距离：

$$d_0=2km$$

因此：

- 距离小于2km时，目标设为0，推动预测取消率下降；

- 距离大于2km时，目标设为1，推动预测取消率上升；

- 距离等于2km时，距离权重为0，不产生惩罚。

距离权重为：

$$\boxed{ w(d) = \min\left( s\cdot\frac{|d-d_0|}{u}, w_{\max} \right) }$$

默认参数：

$$s=1,\quad u=1km,\quad w_{\max}=3$$

距离越偏离2km，业务倾斜力度越大；达到上限后不再增加。

将 BCE 展开后：

$$BCE(t,p) = -t\log p-(1-t)\log(1-p)$$

所以距离损失等价于：

$$L_{\text{distance},i} = \begin{cases} -w(d_i)\log(1-p_i),& d_i<2km\\ 0,&d_i=2km\\ -w(d_i)\log(p_i),&d_i>2km \end{cases}$$

直观理解：

- 近距离预测值越高，惩罚越大，推动取消率下降；

- 远距离预测值越低，惩罚越大，推动取消率上升；

- 距离2km越远，惩罚力度越强。
