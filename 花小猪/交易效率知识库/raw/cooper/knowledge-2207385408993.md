# GS和TP离线模拟


# 一、背景

- 背景：TP相比GS优势是更快，缺点是会破坏全局司乘稳定匹配，因此后续希望将匹配模式也作为一个决策项纳入分单联合决策。

- 规划：v0版本希望进行离线模拟+按城市画像实验看TP空间，v1版本希望by单考虑胜率决策TP/GS。

- 动机：对于v0版本，首先想要离线模拟GS和TP的匹配结果差异，看最终匹配结果会有多大差异，从而分析GS切换成TP的收益空间（例如，如果GS和TP的每轮模拟结果都是几乎相同的，那么可以尝试直接使用TP）。

# 二、城市画像

by城市 看DO连边特征

哪些特征适合全部走TP：

- TP匹配结果和GS几乎一致，则TP更快，纯增量

	- D选O空间几乎为0的城市：看连多个O的D在所有分单轮次中的占比

- 以及需要论证更快1.几秒带来的胜率增益、完单增益

哪些特征可能不适合全部走TP：

- 整体俩看TP结果和GS一致性不够高（存在相对较高的D选O空间），且存在特定时空与整体差异大--可能需要更精细的解法

	- 对于这样的城市，离线模拟单轮TP和GS的差异（预期是TP的sum全局履约率不如GS）

应该先分析下每个城市的OD连边（用于匹配的二部图现状）

现状GS 每轮有多少OD对；OD对根据O、D是否唯一连边可以分为四种

# 三、匹配模式模拟

- 原先计划的模拟方式：选召回矩阵表中单轮GS匹配的数据，离线模拟时根据timestamp进行订单贪心从而模拟TP的匹配结果

（只看单轮是因为这一轮的匹配结果会影响下一轮，无法离线模拟多轮）

- 实际上离线模拟存在的困难：

	- **每轮次的O、D稀疏**：即使是在最大的城市沈阳50%的轮次只有一个O，仅10%的轮次有5个O以上。

	- **无法判断O先后**：召回矩阵表中每轮的 timestamp是相同的，GS每轮次分单2s，统一轮次落表的timestamp相同。精确到秒无法有效区分统一轮次内的订单先后顺序。

- 后续todo：论证假设匹配结果一致情况下 **更快举手的收益**。

- **策略v0**：如果所有D都是唯一连边，则GS（司乘互选）和TP（订单贪心）的匹配结果完全一致。**因此简化地，可以先尝试对D唯一连边占比高于阈值（95%）的城市先尝试全部TP。**

	- **但需要看下峰期，全部TP会较大地拉低效率 或造成badcase吗？**
