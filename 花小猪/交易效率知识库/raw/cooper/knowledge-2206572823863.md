# 差供需保端策略优化v3

# 一、背景

差供需情况下丢端外流量，释放运力保端内供需，预估会提升端内0.2%至0.7%的完单。

**核心收益链路：**差供需小猪端外丢单->可控运力回流端内->端内CR提升->降丢单比减少大盘CR降幅

**目标：提升端内CR**，优化丢单比（丢单比=端外丢单：端内增量），降低端内获得一单在端外的丢单数

**二期实验丢单大盘丢单比为3.41，端内完单涨+0.73%，CR+0.5pp；目标丢单比3以下<!--评论:[{"u":"rongbohui","c":"这个还是要给一个更明确的值"},{"u":"jiangdingyi","c":"已修正"}] -->，保持端内完单及CR提升。**

**端内外流量概念：**

端内：小猪端；

端外：特惠联盟（滴滴主端app）、PBD（powered by didi，百度地图等使用滴滴引擎的流量）

```PlainText
with instantaneous_event_data as (
    select
        case
            when datediff(DATE_FORMAT(param["timestamp"], 'yyyy-MM-dd'), '2025-09-01') % 2 = 0 then 
                (case when HOUR(param["timestamp"]) % 2 = 0 then 'control' else 'treatment' end)
            else 
                (case when HOUR(param["timestamp"]) % 2 = 1 then 'control' else 'treatment' end)
        end as ab_group,

        param ['resident_city'] as city_id,
        DATE_FORMAT(param ["timestamp"], 'yyyy-MM-dd') as tdate,
        hour(param ["timestamp"]) as tid,
        count(distinct param ["driverid"]) as connect_driver_cnt,
        -- 端外连边
        count(distinct case when b.is_thlm = 1 or b.is_pbd = 1 then a.param ["driverid"] end) as connect_ex_driver_cnt
    from
        kflower_marketplace.ods_log_kflower_stgmatrix_hh a
        left join(
            select 
                order_id, 
                is_pbd,
                is_thlm
            from kflower_dw.dwd_kf_trd_unity_order_di
            where dt between '2025-08-29' and '2025-09-11'
        )b on a.param['orderid']=b.order_id
    where
        concat_ws('-', year, month, day) between '2025-08-29' and '2025-09-11' 
        and param ['area'] in (11,36,25,26,18,193,160,162,143,167,300,147,104,6,138,227,139,80,8,81,50)
    group by
        1,
        param ['resident_city'],
        DATE_FORMAT(param ["timestamp"], 'yyyy-MM-dd'),
        hour(param ["timestamp"])
)

SELECT
    SUM(CASE WHEN ab_group = 'treatment' THEN connect_driver_cnt ELSE 0 END) - 
    SUM(CASE WHEN ab_group = 'control' THEN connect_driver_cnt ELSE 0 END) AS total_driver_cnt_delta,

    SUM(CASE WHEN ab_group = 'treatment' THEN connect_ex_driver_cnt ELSE 0 END) - 
    SUM(CASE WHEN ab_group = 'control' THEN connect_ex_driver_cnt ELSE 0 END) AS total_driver_ex_cnt_delta
FROM 
    instantaneous_event_data;

WITH raw_data AS (
    SELECT 
        from_grid13 AS grid_id,
        (low_answer_fuse_ar / 0.8) AS current_ratio,
        -- low_answer_fuse_ar,低应答熔断--格子应答率
        -- low_answer_fuse_min_ar,低应答熔断--熔断条件格子应答率
        traceid
    FROM 
        kflower_marketplace.ods_log_kflower_dups_fps_stg_call_return_amount_public_log
    WHERE 
        concat_ws('-', year, month, day) = '2026-02-07'
),
transition_data AS (
    SELECT 
        grid_id,
        current_ratio,
        LAG(current_ratio) OVER (PARTITION BY grid_id ORDER BY traceid) AS prev_ratio
    FROM 
        raw_data
),
jump_flags AS (
    SELECT 
        CASE 
            WHEN (prev_ratio > 1 AND current_ratio < 1) OR (prev_ratio < 1 AND current_ratio > 1) THEN 1 
            ELSE 0 
        END AS is_jump
    FROM 
        transition_data
    WHERE 
        prev_ratio IS NOT NULL
)
-- 统计总占比
SELECT 
    SUM(is_jump) AS jump_count,
    COUNT(*) AS total_transitions,
    CONCAT(ROUND(SUM(is_jump) * 100.0 / COUNT(*), 2), '%') AS jump_percentage
FROM 
    jump_flags;
```

**痛点：**

**1.端内问题：**释放出的可控运力腾挪到端内无效释放(占释放运力56%，其中闲置运力占23.5%)或争夺API的订单(占端内增量28.3%）；

**解决思路：**根据运力缺口控制丢单率，做到丢单率实时调控，精准丢单，避免运力浪费。

**2.端外问题：**端外丢弃的订单不能够被API承接(占端外丢单95.6%)；

**解决思路：**端外运力不可控，只有尽可能控制端内可控运力，把控丢单率，端内运力承接端外流量。

**三期改进方法：**不再全部丢单而是根据丢单比约束按比例丢单，优先丢占用TSH高的长单。
