# 一、需求简述

- **目前召回策略的阈值有十几个by流量渠道by不同城市的阈值配置，不利于策略维护和优化迭代。存在问题：**

	- **不利于维护：**目前召回配置过多，工程上配置实验和维护都较为复杂。

	- **不利于召回重构后续迭代**：召回重构V1的目标之一是精简线上配置并对召回问题进行形式化建模，需要对大渠道（小猪端、PBD端、DD端）的参数进行收敛和看清策略效果，目前线上召回距离配置过于复杂不利于后续策略数据分析和优化迭代。

- 因此希望收敛召回距离配置，**对于自营鸿鹄、对于连环派和非连环派配置 分别收敛到滴滴端、PBD端 所有城市一套距离阈值**，用于取代现状十几种by流量渠道by不同城市的阈值配置。

- 需要对于收敛后的精简配置vs现状复杂配置 进行实验（需支持pid和时间片实验），收敛后的召回距离

# 二、目标与收益

- **目标：（可维护性目标）将现状的线上十几种参数配置收敛为6套。**

- **约束：约束自营鸿鹄端外召回量不下降。**

- **收益预估：减少召回距离配置数量，提升可维护性；统一召回距离配置，提升策略全局最优空间，便于后续策略优化迭代。**

# 三、需求内容

- 本需求需要工程将召回距离配置收敛为4套距离配置参数（by商家（自营鸿鹄）by大渠道（PBD端、DD端）），用于替代目前十几种部分城市部分渠道的配置。

- 由策略同学产出新的距离阈值参数。

当前召回距离配置现状：

非连环派：<https://yunchou.intra.hongyibo.com.cn/experimentManage?layerId=248>

连环派：<https://yunchou.intra.hongyibo.com.cn/experimentManage?layerId=260>

# 四、工程要求

- 去掉目前的召回配置，收敛为4套端外全国城市的整体配置，并支持两套配置做pid实验和时间片实验的能力。
