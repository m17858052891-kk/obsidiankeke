# OCR 离散 Hazard 与等待时间多通道建模方案


## 1. 背景问题

> OCR 模型当前以“订单 × 轮次”为样本，预测本轮未播单时，订单在当前轮次到下一轮之间（约 3 秒）是否流失。

由于同一个订单会在多个未播单轮次上产生多条样本，且这些样本中大部分订单级特征、乘客特征、起终点特征、供需特征基本相同，只有 `wait_time` 等少量时间相关特征发生变化，普通二分类模型容易优先学习订单之间的静态差异，而不是同一订单随等待时间增加产生的边际流失风险。

这个现象可以概括为：`**wait_time**` **被大量重复的静态特征淹没**。

## 2. 建模目标

第一阶段不直接上复杂的连续 treatment 因果模型，也暂不优先做三分类竞争风险，而是将 **OCR 明确建模为离散时间 hazard 问题**：

```PlainText
h_t = P(订单在未来 3 秒内流失 | 订单已经存活到 wait_time=t，本轮未播单，X_t)
```

其中：

- `X_t`：当前轮次可观测的订单、乘客、场景、供需等特征

- `wait_time=t`：订单当前累计等待时长

- `h_t`：当前轮次继续不播单时，未来约 3 秒内的条件流失概率

对应线上使用时，模型每一轮重新计算：

```PlainText
OCR_r = P(订单在第 r 轮之后约 3 秒内流失 | 当前仍存活，当前未播单，X_r, wait_time_r)
```

## 3. 核心模型形式

**为避免** `**wait_time**` **被普通特征池淹没，模型结构应显式拆成三个通道：**

```PlainText
logit(OCR) = time_base(wait_time)
    + static_risk(order_features)
        + interaction(order_features, wait_time)
```

三个部分的含义如下：

| 模块 <br> | 输入 <br> | 作用 <br> |
| --- | --- | --- |
| `time_base` <br> | `wait_time`、`wait_time_bucket`、`round_idx` 等时间特征 <br> | 学习全局等待时间风险曲线 <br> |
| `static_risk` <br> | 订单、乘客、起终点、价格、供需等非时间主特征 <br> | 学习订单本身及场景的基础流失风险 <br> |
| `interaction` <br> | 静态特征表征 + 时间特征表征 <br> | 学习不同订单在不同等待阶段的异质性风险 <br> |

最终输出：

```PlainText
p_churn = sigmoid(logit(OCR))
```

第一阶段建议先做二分类：

```PlainText
label = 1：当前轮次到下一轮之间订单流失
label = 0：当前轮次到下一轮之间订单仍存活
```

后续如果能稳定区分“乘客取消”和“被其他商家应答”，再扩展为竞争风险多分类模型。

## 4. 推荐特征设计

### 4.1 时间特征

建议不要只使用一个连续 `wait_time`，而是同时加入多种时间表达：

```PlainText
wait_time
log1p(wait_time)
wait_time_bucket
round_idx
```

`wait_time_bucket` 可先采用粗粒度分桶：

```PlainText
0-6s
6-12s
12-18s
18-30s
30-45s
45-60s
60s+
```

分桶的目的不是替代连续值，而是帮助模型更稳地学习非线性的等待时间风险曲线。

### 4.2 静态与场景特征

静态主特征包括但不限于：

- 城市、渠道、车型、时段、工作日

- 起终点经纬度、起终点距离、预估价格

- 乘客历史应答、取消、完单行为

- 起点附近冒泡、订单、应答、空车、响应时长等供需特征

这些特征进入 `static_risk` 通道，用于判断订单和场景的基础流失风险。

### 4.3 交互特征

可显式加入部分时间交互，或交给 `interaction` tower 学习：

```PlainText
wait_time_bucket × city_id
wait_time_bucket × channel_id
wait_time_bucket × input_hour
wait_time_bucket × supply_pressure
wait_time_bucket × passenger_cancel_rate
```

交互项用于表达：不同城市、不同供需紧张程度、不同乘客历史行为下，等待时间增加带来的流失风险变化可能不同。

## 5. 模型结构建议

第一阶段推荐使用简单、可解释、容易上线的多通道 MLP：

```PlainText
static_repr = StaticTower(static_features)
time_repr   = TimeTower(time_features)

static_logit = Linear(static_repr)
time_logit   = Linear(time_repr)

interaction_repr  = concat(static_repr, time_repr, static_repr * time_repr)
interaction_logit = InteractionTower(interaction_repr)

logit = static_logit + time_logit + interaction_logit
p_churn = sigmoid(logit)
```

其中：

- `TimeTower` 是解决特征淹没的关键，保证等待时间相关特征有独立建模通道

- `static_logit` 保留订单和场景本身的基础风险

- `interaction_logit` 学习“什么样的订单在什么等待阶段更容易流失”

- 三个 logit 相加，便于后续做消融和解释

## 6. 样本与 Loss 设计

### 6.1 基础样本

沿用当前“订单 × 轮次”的样本构造方式：

- 本轮未播单，且下一轮仍出现：`label = 0`

- 本轮未播单，且之后不再出现，并确认未被本商家播单：`label = 1`

- 本轮已经被本商家播单：不进入 OCR 样本

### 6.2 订单级权重

为避免长生命周期订单贡献过多重复负样本，建议按订单归一化 loss：

```PlainText
order_weight = 1 / order_sample_cnt
```

如果还需要处理正负样本不平衡，可在订单级权重基础上叠加类别权重：

```PlainText
final_weight = order_weight × class_weight
```

这样可以减少重复静态特征对训练目标的主导，让模型更关注同一订单内等待时间变化带来的风险差异。

### 6.3 可选的订单内排序约束

后续可加入同订单内 pairwise 辅助损失。对最终流失订单，最后一个流失轮次的风险应高于更早的存活轮次：

```PlainText
score(order, last_round) > score(order, earlier_round)
```

可使用 margin ranking loss：

```PlainText
loss_pair = max(0, margin - score_last + score_earlier)
```

该约束直接强化同一订单内 `wait_time` 增长与流失风险上升之间的关系。

## 7. 评估方式

除了整体 AUC / LogLoss，还必须增加时间维度评估，否则无法判断特征淹没是否缓解。

建议至少评估：

| 评估项 <br> | 目的 <br> |
| --- | --- |
| 整体 AUC / LogLoss <br> | 判断总体分类能力 <br> |
| `wait_time_bucket` 分桶 AUC <br> | 判断不同等待阶段的区分能力 <br> |
| `wait_time_bucket` 分桶校准 <br> | 判断预测风险曲线是否符合真实流失率 <br> |
| 按订单聚合后的评估 <br> | 避免被长订单重复样本影响 <br> |
| 消融实验：去掉 `TimeTower` <br> | 验证等待时间独立通道是否有效 <br> |
| 消融实验：去掉 `interaction` <br> | 验证时间与订单特征交互是否有效 <br> |

重点观察：

```PlainText
1. 加入 TimeTower 后，wait_time 分桶校准是否更好
2. 同一订单越靠后轮次，预测风险是否更合理
3. 整体 AUC 是否提升，或在 AUC 持平时校准明显改善
```

## 8. 后续扩展

第一阶段先实现二分类离散 hazard + 多通道等待时间建模。后续可逐步扩展：

1. **1 秒 bin hazard**

	- 将每个 3 秒轮次拆成 3 个 1 秒 bin

	- 每个 bin 预测条件流失风险 `h_j`

	- 汇总为 `OCR = 1 - ∏(1 - h_j)`

2. **竞争风险模型**

	- 在事件原因可靠时，将二分类扩展为：

```PlainText
[p_rob, p_cancel, p_survive]
```

	- 最终：

```PlainText
OCR = p_rob + p_cancel
```

3. **连续 treatment 校正**

	- 将 `wait_time` 视为连续 dose

	- 估计 `P(wait_time_bucket | X)`

	- 使用 IPW / stabilized weight 缓解等待时间分布的选择偏差

4. **序列模型**

	- 在能稳定获取订单完整历史轮次序列后，再考虑 GRU / Transformer / DeepHit 等复杂结构

## 9. 第一阶段推荐实验

建议按以下顺序推进：

```PlainText
Exp0：当前普通二分类模型，作为 baseline

Exp1：加入 wait_time_bucket、log1p(wait_time)、round_idx

Exp2：加入订单级 loss weight

Exp3：改为多通道结构：
      logit = time_base + static_risk + interaction

Exp4：增加同订单内 pairwise 辅助约束
```

第一阶段成功标准：

```PlainText
1. wait_time_bucket 分桶校准改善
2. 同订单后续轮次预测风险相对更高
3. 整体 AUC / LogLoss 不退化，最好有提升
4. TimeTower 消融后效果下降，说明等待时间通道确实生效
```

## 10. 当前结论

OCR 的核心建模语义应从普通二分类调整为离散时间 hazard：

```PlainText
预测订单已经等待到当前时刻后，继续不播单时未来短窗口内的条件流失风险。
```

为解决 `wait_time` 被静态特征淹没的问题，第一阶段采用：

```PlainText
二分类离散 hazard
+ 等待时间特征分桶
+ TimeTower 独立通道
+ StaticTower 基础风险
+ InteractionTower 时间交互
+ 订单级 loss 权重
```

该方案比直接上复杂连续 treatment 或 DeepHit 更贴近当前样本构造，也更容易快速验证和上线。
