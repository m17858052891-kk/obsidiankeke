## benchmark_v1 **base**环境分类：

- 城市：11城，包括 **北京、广州、深圳、厦门、南京、太原、长沙、长春、武汉、杭州、沈阳**, 依据gmv和成交量选择，v1运行稳定后会批量增加可模拟城市；

- 日期：workday / weekend (**5月底至7月初**)；

- 时间：早高峰(7:30 - 9:30) / 平峰(14:00 - 16:00) / 晚高峰(18:00 - 20:00)

- base环境共 66个

## benchmark_v1 **customized**环境分类：

- 时段：传参可设定2h以内任意时长用来模拟；

- 司乘配比：除initialized的配比外，user可以根据实际司乘records size给出超/平/缺配比模拟

## benchmark_v1 传参：

- client传入的参数为base环境：base环境命名为 d/o + city_name + work / weekend + mor / aft / eve

- 以及时段：两小时内的任意时长

## 环境特征说明：

- drivers：每个base环境的司机特征为司机编号(unique)、首次出现的时间、经纬度

- orders：每个base环境的订单特征为订单编号(unique)、发单时间、发单地经纬度、预估时长、预估gmv、目的地经纬度

## recap:

v1模拟系统方案

- 可以按照城市人口规模划分(意味着整体上的订单量和司机配备量能够比较明显的区分开)，在大/中/小三类城市(千万以上/500万以上/100万以上)中各选择6个城市；

- 并且在每个类别中覆盖到基本的**典型城市地域模态****：多核心**(上海)、**同心圆**(成都)、**扇形**(沈阳)，(北京是什么?)

- 每个城市配置周中、周末以及不同时间段内的真实订单生成起、终点经纬度、时间、里程等信息；

- 在每次分配的召回过程中，由于是按照历史数据给出，可以直接统计未播订单和闲置司机数量信息；

- 订单价格按照真实订单gmv_amt给出，这里1)需要和定价对一下计算逻辑或在用的模型 2)或者用全体历史数据做回归给出一个模型；

- 订单前取消模块已上；

- 司机随机游走不考虑下线，意味着随着一天的时间变化，司机数量会越来越多，大概率出现一直超配

- 司机出车方案按照dri_online_patch_di给出的司机最早online时刻和经纬度pair给出；如果考虑下线(更合理)，则按照is_online = 0的时刻让司机消失
