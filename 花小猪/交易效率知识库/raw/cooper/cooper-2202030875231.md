# 一、需求背景

在发单周围缺少乘客勾选运力时预分单作为降低等待应答时间保障完单的有效手段，但由于预分单举手运力相对较高，大多数情况下乘客拒绝接受从而通过预分单的完单占比较低。

对2024.02.02-2024.03.02期间内对小猪端整体发起预分单占比、乘客接受率、预分单完单率、预分单完单大盘占比及乘客取消率漏斗进行统计结果

|发起预分单占比|预分单乘客接受率|预分单应答后完单率|预分单完单大盘占比|
|:----|:----|:----|:----|
|20.11%|25.83%|67.16%|3.49%|

目前预分单整体乘客接受率在25%左右，考虑通过发放C端补贴，可提升乘客对预分单的接受度，从而有效降低在缺少勾选车型时乘客应答前取消率，提升大盘CR。


# 二、需求类型归纳

	预判有收益，要新增能力。

# 二、需求收益判断

预期收益：小猪端内大盘CR提升0.7pp；ROI为2.17；

#### CR提升

目前该期间内小猪端内预分单乘客接受率只有25%左右，若通过发放C端补贴提高乘客对预分单的接受度，预期乘客接受率可达到50%。同期内小猪端发起预分单的订单且乘客未接受应答前取消率为31%左右，应答后完单率约为76%。

假设乘客接受预分单可完全避免应答前取消的情况，此时可以大体估算乘客预分单接受率提升后对大盘整体的收益为

[20%(预分单占比)*(50%-25%)(乘客接受率diff)*67%(预分单应答后完单率)] -

[20%(预分单占比)*(50%-25%)(乘客接受率diff)*(1-31%)(应答前不取消)*76%(应答后完单率)] 

= 3.35% - 2.62% = 0.73%

因此对小猪端内大盘CR有大约0.7pp的提升。

#### 期望ROI

对发起预分单价格系数与乘客接受率建模得到指数模型为c=0.633exp{-4.405A}，其中A为乘客预期接受率，c为预分单超额价格系数(预分单举手运力价格/最高呼单价格-1)，具体建模过程可见[策略文档](https://cooper.didichuxing.com/knowledge/2199610335356/2201893866338)。

若接受若将乘客预期接受率由25%提到50%，需要发放的C补约为最高呼单价格的14%。

设呼单最高价格为P，此时投入为0.14P，预期增益回报为(50%-25%)*0.633exp{-4.405*0.25}*P，期望ROI为0.25 * 1.21P / 0.14P = 2.17。

后期可对拒绝预分单应答率进行预测，若应答率较高可不发放C补，提升ROI；

# 三、需求说明和功能点

## 需求说明：

通过对预分单乘客侧发放补贴提升接受率，最终提升大盘CR。本次需求涉及终端技术，服务端，交易引擎及策略部等团队参与。

## 功能点:

1. 新增预分单环节拉取补贴信息，优惠下发功能；

2. 支持乘客端预分单运力举手界面弹窗展示补贴信息；


# 四、需求通用属性

覆盖范围：

乘客API，小程序，Pope等

对照组：预分单不发放C补；

评估指标：端内CR， 人均完单，人均ROI；
