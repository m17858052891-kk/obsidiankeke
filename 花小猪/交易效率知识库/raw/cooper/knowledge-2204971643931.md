# 一、业务背景

第一批宏鹄出租车于6.16上线，由于宏鹄出租车系统与现有的冷启动自动化配置链路不兼容，因此开城后冷启动均采用手动配置

手动配置需要占用交易策略的人力（0.5天/周），而且有配置出错的风险。考虑进行链路改造，实现宏鹄出租车冷启动配置自动化

# 二、策略流程

- 判断召回或举手商家是否为新开城商家，若是，则触发冷启动策略，否则不触发冷启动策略

	- by天产出by城市旧开城商家列表，旧开城商家满足近180天（不含近14天）存在有效冒泡流量

	- （需工程开发）对宏鹄出租车商家兼容判断逻辑，衔接冷启动策略流程

- 若触发冷启动策略，则读取冷启动特征或司机自身特征，否则读取司机自身特征

	- by天产出by城市冷启动特征并写入司机特征表，保证冷启动特征组合对应的PK打分位于中游水平

	- （需策略开发）产出有别于宏鹄商家的宏鹄出租车冷启动特征，索引为-<u>产品线id</u> <u>city_id</u>（<u>产品线id</u>不限位数，<u>city_id</u>固定三位），例如-<u>600</u> <u>001</u>代表北京的宏鹄出租车

- 判断司机近14天完单数是否大于城市阈值，若是，则使用driver_id读取自身特征，否则替换driver_id读取冷启动特征

	- 保留手动配置的最高优先级，若手动配置生效，则替换为手动配置的其他driver_id，否则进行自动化替换

	- （需工程开发）触发自动化替换时，判断是否为宏鹄出租车，若是，则替换为-<u>产品线id</u> <u>city_id</u>，否则替换为-city_id

# 三、规则内容

- 策略范围：冷启动配置将在宏鹄出租车分单和平台PK阶段同时生效，策略逻辑在两阶段保持一致

- 特征逻辑：产出冷启动特征时，优先参照同城其他宏鹄出租车司机的表现，若数据量不足则参照宏鹄商家的表现

	- 统计同城其他宏鹄出租车司机近14天完单数，若大于阈值，则仅参照这些司机的特征，否则参照宏鹄商家的特征

# 四、规则透传

- 透传内容：宏鹄出租车商家新开城冷启动规则和宏鹄商家一致

- 透传节奏：宏鹄出租车商家开城之前

- 透传对象：宏鹄出租车商家

- 透传形式：线上沟通、宏鹄出租车沟通会

# 五、规则落地

- 协同方职责：交易策略和商家供需共建规则，交易策略配置规则，商家区域运营透传规则

- 潜在风险：在宏鹄出租车的开城城市，存在对其他商家运力的流量争抢现象

- 落地节奏：预计8.25上线规则，收集宏鹄出租车商家的反馈，决策落地节奏
