# 一、需求背景

小猪端流量调节相关深度模型如等待应答页预估应答时长模型等目前为luban离线训练，再导出到eve集群部署上线。因此当前部署流程需要定期luban上手动跑取最新数据更新模型，需要一定的人力投入。为了方便模型自动化更新，可直接基于eve进行模型训练及导出部署上线，eve提供了模型自动更新功能。然而当前eve直接导出部署深度学习只支持容器部署，因此需要工程团队将集群部署模型调用变更为容器部署调用。

# 二、需求类型归纳

预判有收益，要新增能力。

# 二、需求收益判断

收益来源：

   1. 策略侧可以基于eve实现定期自动更新模型，减少模型更新人力投入；

   2. 工程侧基于容器部署方式可以减少对dufe的访问，提高调用效率；

# 三、需求说明和功能点

## 需求说明：

等待应答页ETA预估深度模型集群部署方式下不支持eve的自动化定期更新，需手动luban取最新数据更新模型重新部署。为了基于eve实现模型定期自动化更新，现部分模型已通过eve完成了模型直接训练且已导出容器部署上线，需要工程侧将集群部署调用方式更迭为容器部署调用。

## 功能点:

工程侧将集群部署模型调用变更为支持容器部署模型调用，且保证线上传入特征一致无误。

切换模型： 等待应答页预估时长模型；特快盒子预估应答时长模型；

# 四、需求通用属性

覆盖范围: Athena模块。 

# 五、效果评估方案

深度模型定期自动更新；

线上访问服务效率提升；
