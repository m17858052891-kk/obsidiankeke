# 召回端内外距离配置梳理


# 背景

- 商家分单系统可以分为召回阶段和匹配阶段两个阶段；召回阶段对OD进行一系列的过滤，最终召回的结果进入召回矩阵表。

- 召回阶段线上目前有较多策略叠加，对于维护和策略优化都带来困难，因此召回重构希望用一套更清晰简洁的逻辑替代原有的诸多配置，便于后续维护和策略迭代优化。

# 召回阶段的策略汇总

- 召回策略的范围：工程上的召回阶段过滤条件非常多，在交易策略做的召回过滤（召回重构，以及它所替代的之前的司乘取消率过滤）之外还有50多条过滤条件。其中有些是功能性的过滤，有些是历史策略（例如 诱导取消过滤过滤、安全分单过滤 等等）。

# 召回距离配置梳理

## 结论

- 现状预计需要收敛的地方：

	- **针对单个城市单独做的配置【标灰】**

	- **针对部分城市✖️小渠道做的配置【标紫】**

- **最终预计收敛后形态：最大距离+模型过滤 这样的召回结构；最大阈值收敛为商家（自营、宏鹄）✖️大渠道（小猪端、PBD端、DD端） 全国城市一套距离阈值，不再将召回最大距离阈值开放给商家修改。**
