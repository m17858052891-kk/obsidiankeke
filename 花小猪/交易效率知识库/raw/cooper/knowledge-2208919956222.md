# 论文分享

## 多行为序列：

### onetrans

<https://arxiv.org/abs/2510.26104>

解决问题：传统模型通常先编码用户序列，再拼接用户、物品、上下文特征再做特征交叉，onetrans认为这样会割裂序列特征和非序列特征，所以把所有东西统一成token。

做法：把历史订单序列特征和当前订单特征统一变成token，交给一个Transformer做特征组合。

![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1784625449757/VU9gfl4eG0hLcx89WDds7/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T093104Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=4e6b7ddebac31d9f1935e488a206ffb44fd291f4b18e80e05d5740364f2ea29c)

左图传统方法，用户行为序列建模拼上非序列建模，后面非序列特征很难影响序列特征（压缩后语义更深）。

右图onetrans，将序列行为和非序列行为编码为token并输入。

![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1784626696940/9ukX8kwgFTM04DQFuQhrn/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T093104Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=30cd8045942a2b89fbd494df020060d0f9a4e8862f71a5deb407d89542bea079)

#### 系统架构

序列特征进入序列分词器得到序列token，不同序列特征间以\[SEP\]隔开；

非序列特征进入非序列分词器得到非序列token；

组合输入transformer（序列特征共享QKV，FFN：因为序列特征比较同质；非序列特征每个是单独的QKV，FFN：不同非序列特征差异较大）

非序列特征放后面是为了序列特征看不到非序列，非序列能看到序列特征。（用的causal atttention）

左图中金字塔模式是越往深层，裁掉一部分序列token，只保留尾部信息量较多的token和非序列token，将历史行为放进尾部少量token，减少显存和FLOPs

#### tokenizer方法：

1. 序列特征：

用MLP对同类序列特征压缩到token：

N个乘客序列输入同一个MLP_o得到token1-N

M个司机序列输入同一个MLP_d得到token1-M

2. 非序列特征：

- group-wise：人工分组，每组过MLP

- auto-split：所有特征拼接过MLP，结果再切分成多个token。（效果较好）

#### 消融实验：

对于输入：

使用人工分组（降低）

不管真实发生时间，按类型拼（降低）

比如买1，买2\[SEP\]点击1，点击2而不是点击1，买1，点击2，买2（可以不需要SEP分隔）

不管真实发生时间，按类型拼并且不加SEP（降低）

对于网络结构

共享QKV，FFN（降低）-不同语义的特征确实需要独立的网络，不能用一套参数处理。

使用full-attention，序列特征和非序列特征都能互相看（差不多）-casual attention工程更友好（能用kv cache），full没啥提升

不用金字塔结构（提升不明）-计算量提升到3倍（文中），效果没有明显提升。

#### 另外的启发点：

1. sequence-type indicator：

把多条行为序列融合成一条token序列后，模型需要知道这个token来自哪个序列，因此：第i个token=本身特征+事件属于哪类序列（点击，购买？）也可以再加时间序列

2. Pre-Norm+RMSNorm：

```PlainText
x = x + MixedAttention(RMSNorm(x))
x = x + MixedFFN(RMSNorm(x))
```

RMSNorm，相比layerNorm更轻量，数值上更稳。token上分布差异可能很大，在attention前需要norm。

### Hyformer：

<https://arxiv.org/abs/2601.12681>

核心：不要把长序列压成一个向量再和其他特征交叉，而是让非序列特征生成的querry一层一层与序列特征交互。

![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1784638716669/bs2Did5LPLDLiC52Lx4FA/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T093104Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=9ca48ae645796e79626acdd538e83f7118f4a21eb0ae91548e2bd16a1700803f)

传统模型做法是将长序列建模模块压缩成几个序列token，再和其他非序列特征做交叉进行预测。劣势：序列特征先被压缩，非序列特征参与太晚，交互不够深。

hyformer每层有query decoding和query boosting：

- decoding是让==query==去==序列特征转化的K/V==里获取信息；

- boosting是读完序列后的query再和==非序列token==做交互，得到更深层的==query==

#### ==生成query==：

1. 非序列特征 生成 tokens，Hyformer实践按语义分组生成token（更好解释）。

2. 序列特征（一个订单信息对应一个token）生成token

3. 所有非序列特征向量+序列特征（meanpooling后）经过N个FFN得到query向量（N个）

#### decoding：

输入包括==query==和==序列特征token（K/V，每层重新计算）==，做cross attention，此时query就带上了序列特征信息。

流程
原始行为序列 token:

S_0 = \[s1, s2, s3, ..., sn\]

第 1 层序列编码:

S_0 → 序列编码器 → H_1

H_1 → Linear_K / Linear_V → K_1, V_1

第 1 层 query 读取:

Q_1 attend K_1,V_1 → decoded_query_1

decoded_query_1 + 非序列特征 → boosting → Q_2

第 2 层序列编码:

H_1 → 序列编码器 → H_2

H_2 → Linear_K / Linear_V → K_2, V_2

第 2 层 query 读取:

Q_2 attend K_2,V_2 → decoded_query_2

...

#### boosting：

将带上序列特征信息的query再和非序列特征进行特征交叉。

1. 将query（N）和非序列特征（M）concat（T=N+M）得到$$Q\in R^{T*D}$$。

2. 进行RankMixer提出来的token-mixing，文中将这里的H=T，保证之后也是T个token

![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1784701598700/JtTT7Y81ZEUBahacJqPkG/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T093104Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=8836891461f537f7e8642ca499b8bfa64bcf9b1d0a922f36e9aec0bdec57f542)

将Q切为$$q_i$$，即$$Q=[q_1,q_2,...,q_T],q_i \in R^D$$。再把每个q切为T个通道子空间，即$$q_i=[q_i ^{(1)},q_i ^{(2)},...,q_i ^{(T)}],q_i^{(h)} \in R^{D/T}$$。再转置拼起来，对每一个子空间编号h，取所有token的第h块拼起来。$$\tilde q_h=Concat(q_1 ^{(h)},q_2 ^{(h)},...,q_T ^{(h)} \in R^{D}$$，现在变成$$\hat Q=[\tilde q_1,\tilde q_2,...,\tilde q_T] \in R^{T*D}$$。完成了token间的信息交换

3. 把$$\hat Q$$输入preToken-FFN（对每一行token，即$$\tilde q_{h}$$分别用一个FFN，两层linear）得到$$\tilde Q$$。

4. 最后残差更新Q，$$Q_{boost} = Q+\tilde Q$$。

整体结构

#### 1.历史行为时间戳：

##### 输入带有时间序列：

\[（历史订单1，发单时间1），（历史订单2，发单时间2），（当前订单，当前发单时间）\]

构造时间间隔，$$\Delta t'_i = t_{i+1} - t_n,$$其中$$\Delta t'_n = t_{current}-t_n$$。

##### 截断和归一化：

极端长间隔会带来噪声，设置阈值$$\tau _{max}$$为最大时间间隔（时间间隔分布95%分位数）。

$$\Delta t_m = min(\Delta t'_m ,\tau_{max})/\tau_{max}$$

#### 2.时间特征提取：

##### 使用LSTM层提取全局时间相关特征。

$$h_{rnn}=[h_1,h_2,...,h_n]=LSTM(\Delta t)\in R^{B*T*H}$$

B：batch_size

T：时间间隔序列长度

H：隐藏层维度

希望建模时间节奏的累积变化。

##### 再使用CNN提取局部时间特征。

用两层1维卷积提取局部，在时间序列维度，转成$$R^{B*H*T}$$

![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1784791347711/sQ0Y7_N2HSxPILLqophZ8/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T093104Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=09a26f2c237a2b2458e8256252fe8bba82f4bbc8de281c3867be9389e5a16bbc)

最后残差融合，保留全局时间演化和局部时间演化

$$h=h_{rnn}+h_{cnn}$$

#### 3.通道注意力机制：

用SE block做通道注意力，判断哪些时间模式更重要

![](https://s3-ep-inter.didistatic.com/didoc2-upload-file-prod/images/1784791471178/3PHwyZhNPwoNJWWDyC3hH/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T093104Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=f653f6a0c006ff9cb9731049a6d9046ea7cabe3efa5c1b22d0b6f5abc4b9a228)
