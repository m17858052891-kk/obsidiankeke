## 结构

- ==每一个Expert、Gate和Tower都是一个全连接网络MLP，层数自己决定==

- Expert网络和Gate网络的输入都是相同的

- Gate网络最后的输出会经过softmax归一化，然后作用在每一个Expert上，相当于一个权重。最后多个Expert的输出加权求和，输入到特定的任务塔中

- Gate网络的数量与Task数量一致，即每个Task拥有一个自己的Gate网络

### 1. Expert（专家网络）

- **特征提取的多样性**：多个并行的专家子网络（通常为相同结构的DNN），每个专家独立处理输入特征，学习**不同视角的特征表示**。

	- *示例*：在推荐系统中，专家A可能专注用户历史行为，专家B关注商品属性，专家C捕捉上下文信息。

- **参数共享基础**：所有任务共享专家层的参数，但**不强制任务使用相同特征组合**（区别于传统硬共享）。

#### **设计动机**

- 传统多任务模型使用单一共享层，当任务目标冲突时（如点击率与停留时长），共享层无法同时优化所有任务。

- 专家机制提供**特征表示的多样性**，为不同任务提供定制化特征基础。

### **2. Gate（门控网络）**

#### **作用**

- **动态权重分配**：为**每个任务独立设计**一个门控网络，根据输入 x*x* 动态计算各专家对该任务的**重要性权重**。

	- *示例*：预测"点击率"的任务可能更依赖行为专家，而预测"转化率"的任务更关注商品专家。

- **解决任务冲突**：通过差异化权重分配，使冲突任务（如点击率与退货率）自动选择不同专家组合，避免负迁移。

#### **设计动机**

- 传统MoE（Mixture-of-Experts）使用**单一全局门控**，所有任务共享相同专家权重，无法适应任务差异。

- MMoE的**多门控机制**（Multi-gate）是核心创新：**每个任务拥有专属门控** → 任务可自主选择专家 → 任务关系由数据驱动自动学习。

### **3. Tower（任务塔）**

#### **作用**

- **任务特异性建模**：每个任务有独立的子网络（Tower），接收门控加权后的专家输出，进行**最终预测**。

	- *示例*：点击率Tower输出概率值，转化率Tower输出另一概率值。

- **隔离任务干扰**：确保任务间仅通过专家层和门控交互，**不共享高层参数**，避免目标冲突。

#### **设计动机**

- 传统多任务模型在共享层后直接接任务输出层，当任务差异大时，高层特征互相干扰。

- Tower为每个任务提供**专属表示空间**，在融合专家特征后进一步精细化处理。

## MMoE：基于多门控混合专家网络的多任务学习建模 | Google | Multi-gate Mixture-of-Experts

### 背景

1. **问题痛点**：

	- 现有基于神经网络的多任务学习（MTL）模型（如Shared-Bottom结构）对**任务间相关性高度敏感**。当任务相关性较低时（如推荐系统中同时优化用户点击率与满意度），任务间优化冲突导致模型性能显著下降。

	- 现有改进方法（如L2约束、Cross-Stitch网络、张量分解）需为每个任务引入大量额外参数，在**大规模工业场景**（如十亿级参数推荐系统）中面临训练效率低、计算开销大、过拟合风险高等问题。

2. **核心挑战**：

	- 如何在**不显著增加参数量**的前提下，显式建模任务间关系，动态平衡共享知识与任务特异性？

- **场景**：十亿级用户内容推荐，同时优化：

### 《POSO: Personalized Cold Start Modules for Large-scale Recommender Systems》

#### 背景：

快手针对冷启动的工作。==如果有一类用户的数据在训练集中出现的很少，就很难学习出他们的分布，就是冷启动问题。==[冷启动](https://so.csdn.net/so/search?q=%E5%86%B7%E5%90%AF%E5%8A%A8&spm=1001.2101.3001.7020)==问题的特点是：1、新用户行为稀疏，训练数据少。2、新用户耐心差，对推荐结果敏感，模型试错机会少，因此数据更加稀疏。常用的解决方法：1、元学习（先让模型到这些分布的附近）；2、利用其他特征生成id== embedding==，从而缓解冷启用户历史数据稀少的问题。==**样本分布差异大、不均衡。**虽然缓解了数据稀疏的问题，但是依然存在样本分布极度不均衡的问题。显然，冷启用户的特征分布和全量用户的特征分布差别很大，但是冷启动用户样本一般占全量样本5%以下，因此模型主要受正常用户的影响。

直观的做法是加入一个指引特征（new_user），用该给模型指引这个样本是否是冷启动样本，从而让模型自动学习到样本之间的偏差，但是有没有效果呢？

#### 方法：

之前已经提过，直观朴素的解决方法是用单独的模型学习这类分布，强迫模型关注到这个特征，POSO的核心思想也类似，即对每个用户学习对应的模型，不受其他用户样本的影响，做到完全基于用户自己的个性化。基于此思路，进行简化和近似等价，在基础的单个模型中引入个性化模块，使模型对每个用户在模型结构层面进行个性化响应，实现模型结构的个性化。

当前模型利用

通过用户分群的方法，虽然实际落地可行，但依然需要学习N个模型，参数量随着用户群数量线性增长，因此利用gate对模型数量简化，仅使用当前模型即可。既然需要不同用户群模型，那就以当前模型为基础，通过加权得到某个用户群的模型，再进行加权得到某个用户的模型，两次加权可以通过一个gate网络合并。这种简化方式减少了模型数量，而且无需重新训练模型，直接在原有模型上改造。

### PPNet

PPNet (Parameter Personalized Net) 是由快手提出，将上述 LHUC 的思想迁移到了推荐领域。==与 LHUC 中为每个 speaker 定制幅度类似，PPNet 为每个用户学习了个性化的偏置项，并以全局共享为基础进行个性化的微调。个性化参数则使用门控网络来拟合。==橘色部分可以视为原有基线模型，主要用于训练CTR模型。

- 灰色和蓝色部分为新增模块：灰色部分是基于所有用户共享的，蓝色部分是门控网络 (slot-gate)，通过门控网络与灰色部分的网络来学习用户的个性化。

![](https://s3-ep-inter.didistatic.com/didoc-upload-image-prod/1764213486046617768e1-1a5c-41c6-afd9-44296056dfec/image.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T093027Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=5922e1fa2787d1cf7100990f88e64e756e4d87328555e8da9b64b267afa512ed)

需要注意一下蓝色部分的 [Gate NN](https://zhida.zhihu.com/search?content_id=225348464&content_type=Article&match_order=1&q=Gate+NN&zhida_source=entity) 部分，其中 uid，pid，aid 分别表示 user id，photo id，author id，进行梯度回传；但是左侧其他特征，虽然也会和这 3 个 id 特征的 embedding 拼接到一起作为所有 Gate NN 的输入，但并不接受 Gate NN 的反传梯度，**减少 Gate NN 对现有特征 embedding 收敛产生的影响**。

Gate NN 的数量同左侧神经网络层数一致 (上图中灰色网络共四层，因此一共有四个 Gate NN)，其输出同每一层神经网络的输入做 element-wise product 来做用户的个性化偏置。Gate NN 采用的是一个 2 层神经网络，其中第二层网络的激活函数是 2 \* sigmoid，这一部分与 LHUC 原文中设置是相同的。

经实验对比，通过 Gate NN 为神经网络层输入增加个性化偏置项，可以显著提升模型的目标预估能力，具体表现为离线评估指标 AUC 等指标的上涨，以及在线指标的提升。此外，PPNet 足够轻量化，其通过 Gate NN 来支持 DNN 网络参数的个性化能力，来提升目标的预估能力，可以很容易用到所有基于 DNN 模型的预估场景，如个性化推荐，广告，基于 DNN 的强化学习场景等。

#### EPNet (Embedding Personalized Network)

这一部分算是 paper 最大的看点了。我们知道对于不同 domain，就算是同一个用户，亦或是同一个视频，其在特征空间的语义 (Semantic) 是有较大差异的，仅 share embedding 的效果不尽如人意；如果搞两套 embedding 在计算与存储上的开销又会比较大。

本文通过 EPNet 结构，将 domain 相关的特征作为 Gate NU 的输入，来对特征的 embedding 进行动态调整。换一种方式可以理解为：**domain 作为输入的 Gate NU 将原始的 embedding 对于不同 domain 进行了映射，**进而高效解决了不同 domain 特征空间的语义不一致的问题。

==我们可以看到，最底层的 embedding 还是共享的，EPNet 对齐了特征在不同 domain 的分布。最终我们得到了==**基于场景的个性化 embedding** ==作为后续模块的输入。==

EPNet 主要对不同 domain 进行区分，对应的 Gate NN 的输入为 domain 相关的特征；而 PPNet 则关注另一个在推荐系统中重要的方面，即对用户的个性化。用户的偏好可以被进行细化，成为一个个 task (如点赞，转发等)，所以 **PPNet 可以看做是对预估任务中 task-specific 的个性化**。

**id 作为输入的 Gate NU 将原来 NN 的隐层，对于不同 user / task 进行了调整。**对于每一个用户，虽然 NN 的结构是共享的，但是由于 NN 的结果都经过 Gate NU 变换，模型最后的预估结果都是不尽相同的，做到了千人千面。

**EPNet 在 Sparse 层面做到了 domain 粒度的个性化；PPNet 在 Dense 层面做到了 user / task 粒度的个性化。**当然，还有很多别的方法对 sparse 或是 dense 做操作，这个留到以后再说。

总的来说，PEPNet / LHUC 模块与推荐场景的相性是非常好的，我们也可以根据场景自定义 Gate NU 的输入，把我们需要区分的部分 (bias 特征) 作为输入以达到个性化网络的效果。同时 LHUC 的成本非常低，能较好兼容 NN 网络中的 Dense Layer，也非常推荐大家尝试一下效果。
