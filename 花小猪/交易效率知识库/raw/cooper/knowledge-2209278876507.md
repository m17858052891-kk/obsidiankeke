# 一、背景

- **背景**：接驾远换车 V2.1 已建立“ETA 准入 + 应答后乘客取消率模型”的分档换车能力，并通过自动换车、手动换车和轮询机制降低乘客取消。V2.2作为[接驾远换车v2.2策略方案](https://cooper.didichuxing.com/knowledge/2199610335356/2206934749054/edit)中二阶段实验，核心仅针对连环派扩大换车触发面。前序实验结果已通过[【LR26-013】交易效率-乘客引导-接驾远换车策略-V2.1](https://cooper.didichuxing.com/knowledge/2199610335356/2207853025753)并放量。

- **动机**：V2.2 进一步扩大连环派换车出发面的的迭代动机如下：

	- **连环派仍有扩量空间。** V2.1 线上主策略下，连环派实际换车率约 22%，而前期分析显示约 55% 的连环派属于相对不顺路订单，连环派的换车触发面有进一步扩大的空间。

	- **连环派换车的空驶折损较低。** 连环派司机在上一单送驾阶段被换出时，AB 段不属于本单接驾空驶。前期评估中，连环派换车司机平均空驶约 3 秒，非连环派约 22 秒。

	- **新增绕路程度判断。** 相同 AB+BC 总 ETA 下，路线是否顺路会显著影响乘客实际等待体验，因此需要增加 A（司机位置）、B（上一单终点）、C（本单起点）的空间关系判断。

	- **需要识别实验组间运力挤占。** 扩大换车会共同消耗候选运力，PID 分组可能相互影响，因此在 PID 实验之外补充时间片实验，评估整体运力环境下的真实收益。

# 二、目标与约束

- **目标：** 应答后乘客取消率（下降-0.1pp），完单（提升0.1%）。

> 扩大连环派换车覆盖，降低乘客总等待时长 ETP，提升 CR 和完单，并观察是否能进一步降低应答后乘客取消。

- **约束：** 乘客ETP+司机接驾时长不显著上涨。

## 3.1 策略流程

- **策略流程**：V2.2 继承 V2.1 的整体换车链路，**仅将连环派的换车触发面由22%提升至约60%**，非连环派策略不变。分两个pid实验组，设置两类对连环派增量换车方案如下：

| 方案 <br> | 连环派增量策略 <br> |
| --- | --- |
| 规则策略（PID 组 2） <br> | AB+BC 总 ETA &gt;300 秒时自动换车；总 ETA &gt;250 秒且判断为不顺路时手动换车；其余不换车。 <br> |
| 模型策略（PID 组 3 / 时间片实验组） <br> | AB+BC 总 ETA ≤180 秒时不换车；大于 180 秒后进入取消率模型，预估取消率达到自动换阈值时自动换车，其余命中阈值的订单手动换车。 <br> |

## 3.2 策略细节

- **规则策略组新增顺路度规则：**AB+BC 总 ETA >300 秒时自动换车；总 ETA >250 秒且判断为不顺路时手动换车；其余不换车。顺路度定义如下：

顺路度定义
高顺路度订单刻画：司机当前位置记为A、上一单终点为B、本单起点为C；定义司机不会越来越远为∠A < 90度 &&∠C < 90度

1、**司机不会越来越远时，司机不会绕路的订单为高顺路订单**：绕路比=(AB+BC)/AC < y 为高顺路订单，一期实验y=1.2

2、**司机会越来越远时，上一单终点在司机当前位置附近 或 上一单终点在本单起点附近的订单为高顺路订单**：AB≤a 或 BC≤b 为高顺路订单，一期实验a=1000，b=250 ，单位米

# 四、实验评估

## 4.1 核心结论

V2.2 通过 PID 实验和时间片实验，分别验证策略触发链路与整体交易效率：

**【核心结论】进一步扩大连环派换车触发面能进一步降低乘客等待时长（ETP显著-0.78%）并带来大盘完单收益（完单显著+0.31%，CR显著+0.29pp），完单收益主要来源于更高的换车触发加速了运力流转（司机在线时长不变的前提下，司机空闲时长不显著-0.2%，忙碌时长不显著+0.07%）。**

> 以下数据来源：4.3时间片实验数据。

**【完单收益】完单显著+0.31%，CR显著+0.29pp；完单收益的来源主要是加快了运力流转。**

【**乘客体验】进一步扩大连环派换车未带来乘客取消率进一步下降：**应答后乘客取消率-不含改不显著+0.03pp，归一乘客取消率不显著+0.01pp；**表明 V2.2 新增覆盖的乘客本身大多不会取消**。

**【交易效率】**归一完单订单的**乘客ETP显著****-0.78%**，归一应答订单的**司机接驾时长显著****+0.82%**，**ETP+司机接驾时长不显著-0.09%。**

### 4.2.3 下钻分析

**（1） 触发面和找车成功率**

- 连环派的**实际换车率从22%提升到53%**，符合本期迭代「扩大连环派换车」的策略预期。

- 连环派换车触发的提升带来一定的找车成功率降低：**找车成功率从40%降低到33%**，原因是换车触发面扩大，造成运力挤占，找车成功率下降。

- 最终连环派**实际换车成功率从9%提升到18%**，是策略扩大触发和触发提升导致的找车成功率下降综合作用的结果。

**（3）交易效率**

对于所有应答订单，根据其经过可能的换车/改派流转后的最终状态是否完单 区分为 **归一完单订单** 和 **归一未完单订单**，分别拆分其司机接驾时长和乘客等待时长ETP（包括等应答时长和等接驾时长）。

- 最终归一完单订单的单均乘客ETP均下降，且扩大连环派触发的组2组3（约-1%）降幅比组1（-0.64%）更大，**符合换车缩短乘客等接驾时长的策略预期**。

- 最终归一完单订单的司机接驾时长均上涨，且扩大连环派触发的组2组3（约+0.5%）涨幅比组1（+0.2%）更大，原因是目前的策略对于**连环派换车时仅从乘客视角比较新旧车的总eta**（连环派ab+bc的总eta），**而并未从司机视角比较连环派bc段（bc段是实际计入司机接驾时长的部分，ab段由于司机仍在上一单送驾中，因此不会计入司机接驾时长）和新车的司机接驾时长**，**因此会出现乘客视角等接驾时间缩短、但司机视角接驾时长反而上涨的结果。**

- 最终归一未完单订单的单均乘客ETP和司机接驾时长均下降，原因是换车策略将部分长时等待最终取消的订单 腾挪到 完单，因此拉低了这部分的时长。

```SQL
-- ============================================================================
-- 司机有效在线时长时间片评估
-- 口径来自《大盘指标时间片评估.sql》中的 tsh_data。
-- valid_tsh 单位：小时。

with tsh_data as
(
    select
        -1 as city_id,
        dt as tdate,
        hour(online_time) as minf,
        case
            when datediff(dt, '2026-07-08') % 2 = 0 and hour(online_time) % 2 = 0 then 'control_group'
            when datediff(dt, '2026-07-08') % 2 = 0 and hour(online_time) % 2 = 1 then 'treatment_group'
            when datediff(dt, '2026-07-08') % 2 = 1 and hour(online_time) % 2 = 0 then 'treatment_group'
            when datediff(dt, '2026-07-08') % 2 = 1 and hour(online_time) % 2 = 1 then 'control_group'
        end as exp_group,
        sum(
            case
                when (is_hxz_online = 1 or is_hh_online = 1)
                 and is_dd_busy <> 1
                 and is_other_busy <> 1
                then 1
                else 0
            end
        ) / 60 as valid_tsh_online
        ,sum(
            case
                when 
                    (is_hxz_online = 1 or is_hh_online = 1)
                 and (is_hxz_busy=1 or is_hh_busy=1)
                 and is_dd_busy <> 1
                 and is_other_busy <> 1
                then 1
                else 0
            end
        ) / 60 as valid_tsh_busy
    from
        kflower_dw.dwm_kf_dri_valid_tsh_di
    where
        dt between '2026-07-09' and '2026-07-22'
        and city_id in (33,44,55,56,67,13,37,59,38,49,39,7,60,50,40,62,41,20,42,53,64,54,65)
    group by
        dt,
        hour(online_time),
        case
            when datediff(dt, '2026-07-08') % 2 = 0 and hour(online_time) % 2 = 0 then 'control_group'
            when datediff(dt, '2026-07-08') % 2 = 0 and hour(online_time) % 2 = 1 then 'treatment_group'
            when datediff(dt, '2026-07-08') % 2 = 1 and hour(online_time) % 2 = 0 then 'treatment_group'
            when datediff(dt, '2026-07-08') % 2 = 1 and hour(online_time) % 2 = 1 then 'control_group'
        end
)

select
    city_id,
    tdate,
    minf,
    exp_group,
    valid_tsh_online,
    valid_tsh_busy
from tsh_data
order by tdate, minf, exp_group
```

```SQL
    select
        order_answer_dt as dt,

        0 as pickup_dur,

    from(
        select
            order_id,
            to_date(answer_time) as order_answer_dt,

        select
            order_id,
            to_date(answer_time) as order_answer_dt,
            hour(answer_time) as order_answer_tid,   
            sum(case
                    when order_status in ('完单') then unix_timestamp(begin_charge_time) - unix_timestamp(answer_time)
                    when order_status not in ('完单') then unix_timestamp(cancel_time) - unix_timestamp(answer_time)
                end) as pickup_dur,
            sum(case when order_status in ('完单') then unix_timestamp(end_charge_time) - unix_timestamp(begin_charge_time) end) as charge_dur

            order_rank_max

            platform_mode_name in ('花小猪自营','宏鹄')
            and is_td_answer = 1
            and is_answer_serial_assign = 0

            to_date(answer_time),
            hour(answer_time)

        sum(charge_dur) as charge_dur
    from (
        select
            order_id,
            to_date(answer_time) as order_answer_dt,
            hour(answer_time) as order_answer_tid,   
            sum(case
                    when order_status in ('完单') then unix_timestamp(begin_charge_time) - unix_timestamp(answer_time) - driver_to_last_dest_eta
                    when order_status not in ('完单') and (unix_timestamp(cancel_time) - unix_timestamp(answer_time)) > driver_to_last_dest_eta then (unix_timestamp(cancel_time) - unix_timestamp(answer_time) - driver_to_last_dest_eta)
                    when order_status not in ('完单') and (unix_timestamp(cancel_time) - unix_timestamp(answer_time)) <= driver_to_last_dest_eta then 0
                end) as pickup_dur,
            sum(case when order_status in ('完单') then unix_timestamp(end_charge_time) - unix_timestamp(begin_charge_time) end) as charge_dur
        from
            order_rank_max
        where
            platform_mode_name not in ('花小猪自营','宏鹄')
            and is_answer_serial_assign = 1
        group by
            order_id,
            to_date(answer_time),
            hour(answer_time)
    )t
    group by order_answer_dt, order_answer_tid
    union all 
    select
        order_answer_dt as dt,
        order_answer_tid as tid,
        '非可控运力' as type,
        '非连环派' as is_serial,
        sum(pickup_dur) as pickup_dur,
        sum(charge_dur) as charge_dur
    from (
        select
            order_id,
            to_date(answer_time) as order_answer_dt,
            hour(answer_time) as order_answer_tid,   
            sum(case
                    when order_status in ('完单') then unix_timestamp(begin_charge_time) - unix_timestamp(answer_time)
                    when order_status not in ('完单') then unix_timestamp(cancel_time) - unix_timestamp(answer_time)
                end) as pickup_dur,
            sum(case when order_status in ('完单') then unix_timestamp(end_charge_time) - unix_timestamp(begin_charge_time) end) as charge_dur
        from
            order_rank_max
        where
            platform_mode_name not in ('花小猪自营','宏鹄')
            and is_td_answer = 1
            and is_answer_serial_assign = 0
        group by
            order_id,
            to_date(answer_time),
            hour(answer_time)
    )t
    group by order_answer_dt, order_answer_tid
),
all_order_dur as 
(
    select 
        dt,
        
        tid,
        case
	        when datediff(dt, '2026-07-08') % 2 = 0 and tid % 2 = 0 then 'control_group'
	        when datediff(dt, '2026-07-08') % 2 = 0 and tid % 2 = 1 then 'treatment_group'
	        when datediff(dt, '2026-07-08') % 2 = 1 and tid % 2 = 0 then 'treatment_group'
	        when datediff(dt, '2026-07-08') % 2 = 1 and tid % 2 = 1 then 'control_group'
      	end as exp_group,
        type,
        is_serial,
        sum(pickup_dur)/3600 as pickup_dur,
        sum(charge_dur)/3600 as charge_dur
    from 
    (
        select 
            *
        from 
            zyhh_serial_pickup_dur_tid
        union all 
        select 
            *
        from 
            order_dur
    ) a 
    group by 
        dt,
        
        tid,
        case
	        when datediff(dt, '2026-07-08') % 2 = 0 and tid % 2 = 0 then 'control_group'
	        when datediff(dt, '2026-07-08') % 2 = 0 and tid % 2 = 1 then 'treatment_group'
	        when datediff(dt, '2026-07-08') % 2 = 1 and tid % 2 = 0 then 'treatment_group'
	        when datediff(dt, '2026-07-08') % 2 = 1 and tid % 2 = 1 then 'control_group'
      	end,
        type,
        is_serial
)

select
    dt as tdate,
    tid as minf,
    exp_group,
    sum(pickup_dur) as `接驾时间`,
    sum(charge_dur) as `送驾时间`
from all_order_dur
group by
    dt,
    tid,
    exp_group
order by dt,tid,exp_group
```

**【收益链路】**

- 扩大连环派换车把订单换给乘客视角下更快到达的司机，直接降低等接驾时长和总等待时长 ETP。

- **换车加快运力流转。** 

	- **从交易漏斗来看，在去重呼叫未增加（不显著-0.25%）的情况下，不含改应答量显著 +0.34%、应答率显著 +0.34pp，进而带来 CR 和完单提升。**

	- **从运力视角来看，在司机在线时长未增加（不显著-0.01%）的情况下，司机忙碌时长（包含接送驾）不显著+0.07%，司机空闲时长不显著-0.2%，表明运力流转加速的来源是将司机的空闲无单时长转换到了接送驾的忙碌时长，从而带来大盘应答和完单的提升。**

- 新增触发未进一步降低乘客取消率，说明增量覆盖的乘客本身大多不会取消；本次收益主要来自运力周转效率，而非取消挽回。
