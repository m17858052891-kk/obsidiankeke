# 接驾远换车v2.2策略方案

# 一、背景

*需求背景：[接驾远换车V2.2](https://cooper.didichuxing.com/knowledge/2199610335356/2206903780552)拿到显著受益（应答后乘客取消显著-0.89pp，CR显著+0.28pp），本次V2.3迭代希望扩大连环派收益，同时解决一些bug和badcase。*

- **做什么：核心是提升连环派订单换车触发面。**

	- **连环派策略调整**：扩大连环派换车触发面，**降低连环派换车触发eta阈值**；新增连环派顺路度判断，**对于低顺路度的连环派提高换车触发面**。

	- **bug修复<!--评论:[{"u":"tommywujian","c":"只是分单找车的时候有bug，找到车后判断的逻辑没问题"}] -->**：目前线上换车存在bug需修复。

		- bug描述：在触发换车阶段，线上对于完成了上一单的连环派，标签仍记为连环派，导致ab+bc距离错算触发换车。

		- bug影响：目前的bug仅存在于触发换车阶段（会导致数据表现上触发面变高、找车成功率变低），找到车后 新车须比老车更近90s的逻辑不受该bug影响。

	- **badcase优化**：**约束直线距离**（为了避免一些司机在一些调头场景未按照导航行驶而造成的司乘碰面后遇到换车，约束换车的直线距离<50m后只能命中手动换车）。

- 为什么：

	- **为什么要提升连环派触发面：发现连环派换车仍有继续提升触发面空间，能够扩大c取消降低收益。**

		- 动机：若在连环派送驾阶段换车则不造成司机空驶<!--评论:[{"u":"tommywujian","c":"数据是什么样"},{"u":"qinjiatong","c":"根据二期实验结果，连环派换车的司机平均空驶时间3s，非连环派换车的司机平均空驶时间22秒。"}] -->，**连环车换车造成的司机空驶折损更少。**

			- 根据[V2.2实验评估结果](https://cooper.didichuxing.com/docs2/document/2206157884766)，连环派换车的司机平均空驶时间3s，非连环派换车的司机平均空驶时间22秒，连环车换车造成的司机空驶折损更少。

		- 可行性：**目前连环派触发面仍有扩大空间。**

			- 当前连环派订单中32%订单触发了换车（连环派中55%为较为不顺路订单、预期应该触发换车），连环派当前触发换车的eta阈值为470，阈值较为宽松。

- 收益测算：连环派换车触发面预计从30%提升到60%。预计带来每天3000单完单收益，c取消-0.1pp，大盘完单+0.07%。

> ds评估报告：文件名称：连环派换车优化  链接：<https://cooper.didichuxing.com/docs2/document/2206551934682>  密码：827208

- 产品形态优化：修改了自动换的乘客感知文案，**在自动换车时给出换车原因解释**。

> 动机是给乘客更好的感知体验：当前的的轮询进自动换的乘客体验为应答时不显示换车，过3-4分钟后，出现换车中提示，用户整体体验中是比较迷惑的不知道为什么突然会被换车。

# 二、策略方案

*V2.3仍然分规则组和模型组两个实验组：规则组在触发链路中新增连环派顺路度判断；模型组在取消率模型中新增连环派相关特征。*

### 2.1、整体流程（规则组）

在触发链路中新增顺路度规则：

> 使用到的距离为请求地图得到的路面距离。

- 顺路度定义（和连环派展示优化采取一套定义）

高顺路度订单刻画：司机当前位置记为A、上一单终点为B、本单起点为C；定义司机不会越来越远为∠A < 90度 &&∠C < 90度

1、**司机不会越来越远时，司机不会绕路的订单为高顺路订单**：绕路比=(AB+BC)/AC < y 为高顺路订单，一期实验y=1.2

2、**司机会越来越远时，上一单终点在司机当前位置附近 或 上一单终点在本单起点附近的订单为高顺路订单**：AB≤a 或 BC≤b 为高顺路订单，一期实验a=1000，b=250 ，单位米

- 触发流程（规则组）：

	- 对于距离远的连环派（eta>300s），全部自动换车。

	- 对于距离相对较远（250s<eta<300s）且不顺路的连环派，全部手动换车。
