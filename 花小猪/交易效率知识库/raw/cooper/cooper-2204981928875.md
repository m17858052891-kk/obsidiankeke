# 一、需求背景

1. 商家分单引擎的匹配阶段基于GS算法进行最稳定的双边匹配，由于小猪初期阶段运力侧相对占据主导地位，在GS中先进行司机对乘客的选择再由乘客反选；然而目前市场供需状况在多种因素影响(如平高峰期等)日趋复杂多变，因此当下静态的选择顺序并不一定为最优的匹配机制；

2. 希望基于供需状况等因素动态决策司乘双边的选择顺序，增强算法的灵活性，保障分单稳定性的前提下提升分单效率和双边体验性，最终提升商家完单份额，降低商家应答后取消率；

# 二、需求类型归纳

预判有收益，已具备初步功能，持续优化；

# 二、需求收益判断

自营商家大聚合完单+1%，应答后乘客取消-0.5pp；

宏鹄商家大聚合完单+0.5%，应答后乘客取消-0.3pp；

# 三、需求说明和功能点

## 需求说明：

	本次需求涉及交易引擎与交易引擎测试团队，为策略类需求；

## 功能点:

1. 分单Dispatch匹配模块GS算法可基于供需等特定特征进行OD选择顺序的调整；

2. 支持时间片分流等相关线上实验与现有机制对比；

# 四、需求通用属性

覆盖范围：

交易分单环节Dispatch 模块；

# 五、效果评估方案

全国部分城市时间片分流实验；
