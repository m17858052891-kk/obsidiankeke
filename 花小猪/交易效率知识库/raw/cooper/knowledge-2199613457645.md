# 背景描述

在GS匹配中，我们将价值拆分成司机视角和乘客视角，司机视角采用订单iph，乘客视角采用接驾距离。

而**如此计算司机侧价值，仅仅考虑了当前一轮的匹配，没有考虑长远利益。**例如，在某一次匹配中，司机A有两个可选订单a和b，而a订单iph > b订单iph，因此GS匹配会优先考虑订单a。但是有可能订单b的终点是更热的地区，接到大单的概率更大，例如火车站、飞机场等等，而a订单的终点也许是偏远地区。这种情况下显然b订单带来的未来价值要大于a订单，因此，基于此提出MDP价值计算，来改进原有价值计算方式。改进目标就是，提升司机IPH，进而提升平台GMV和毛利率。

# 需求描述

我这边会产出一个“**价值表**”，格式为：**时间索引，格子编号，价值**

**时间索引：**zero-index，从00：00开始，每5分钟一个时间片，每个时间片一个索引编号，每天一共24\*12个时间片；

**格子编号**：系统划分的，同一块六边形区域属于同一个格子；

**价值表的使用方法：**

**在司机端，**

**起点价值 = 修正后的订单价格 + 修正后的终点时空MDP价值**

**= Sum(pow(衰减系数gamma_1, 时间片索引) \* 对应时间片订单价格) + pow( 衰减系数gamma_2, 上取整（订单时长/时间片长度）) \* 终点时空的价值**
