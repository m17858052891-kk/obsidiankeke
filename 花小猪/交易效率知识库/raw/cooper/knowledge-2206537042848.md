# 接驾远换车-讨论WIP


# 一、背景

应答后换车v3的目标是突破v2阈值启发式的策略，通过定义「应答后换车」更底层的问题来寻求这个问题更通用简洁的解法。

# 二、前置分析

### 问题定义

- **决策：是否换车**

	- **将换车决策定义为「效率上有收益、且约束司机体验不能太差」**

	- **「效率上有收益」：突破启发式的换车阈值**

	- **「约束司机体验不能太差」：通过阈值来控制前置司机空驶时长不能太长**

		- [ ] 需要前置看：之前实验的父单司机空驶时长平均是多少，**==空驶时长过长被换的父单司机差体验case占比多少？==**


		- [ ] 之前实验的置换比（多少司机空驶 换了多少完单增量）

	- 后续还可以做一些产品上的优化，以及是否可以和其他抓手联合考虑（诱导换车，有可能都是因为接驾远；订单hold，从更前的环节解决）

- **目标：最大化完单**

- **约束：司机空驶时长**

	- 一方面是效率方面的约束，完单增量要高于司机折损（或者乘以一个系数），证明在效率上值得做

	- 另一方面是体验上的约束，约束负担司机空驶时间不能过长

#### **1、Q：站在单个乘客/订单视角去决策换车是合理的吗？是符合全局效率的吗？**

       **A：是的，在目前的整体供需（O主导的市场）下，站在乘客视角去决策换车是符合全局效率的。**

- **现在的换车逻辑本质上是站乘客/订单视角**：只要这个乘客/订单体验不够好（接驾远或者取消率高），平台就会给它**再在GS分单系统中发一单**，让它重新寻找是否有更近的司机。

- **目前这种订单个体维度的决策，是符合全局效率的吗？**

	- 逻辑上不是：因为换车就是在GS分单系统中把这个单再发一次（然后再判断是否满足更近90s的条件），现在的GS分单保证的是「司乘最优」「稳定匹配」，本来就不是全局最优。

- 但是实验结果完单整体是正向的，说明**目前从乘客/订单视角出发的换车策略对于平台而言整体效率也是略微提高的**。

- **这或许是因为目前的匹配现状就是一个O主导的市场，因此仅站O视角的匹配结果和全局视角的匹配结果几乎一致**。**对单个O有利的重新匹配（换车），大概率对全局也是有利的，因为目前是一个由O占绝对主导的双边市场**。这个结论和目前分单中「只由O选D就接近GS分单最优结果」的结论是一致的，本质都是由于目前这是一个不均衡的、O主导的匹配市场。[DO连边现状梳理](https://cooper.didichuxing.com/knowledge/2199610335356/2206854359553)

- [ ] 这个结论能不能通过离线模拟来看？

	- 当供需改变，这个结论有没有变？没有，O选D空间在差供需时仍不超过10%。因此我们可以认为，**当前始终是O单方面主导匹配结果**。

#### **2、Q：换车想解决的问题可以在分单环节中解决吗？换车和订单hold的关系是什么？**

       **A1：不可以，应答后换车是为了应对短时供需变化的必要策略，无法在分单环节解决。**

       **A2：应答后换车和订单hold本质都是在解短时供需变化的问题，但应答后换车可等待的时间更长，因此有其必要性。**

（「订单hold本质是在解短时供需变化」这个有待商榷，好像不止是在解这个问题。）

- **「过了一段时间后出现的更近的车」为什么没有成为一开始就应答的车呢？**

	- 这其实是在比较子单司机和父单司机，为什么父单司机一开始是优于子单司机的，一段时间后反而不如子单司机了。

		- 情况A：子单司机未参与初次匹配，是**「突然冒出来」**的：**比如司机刚出车，原来接驾中被乘客取消释放**。

		- 情况B：初次匹配时子单司机确实是更远的，但一段时间后更近了：比如父单司机堵车了。

		- 情况C：分单阶段的打分逻辑和换车阶段的逻辑存在gap：分单时比较的是O对D1和D2的打分，但换车时只要O连到D2且D2比D1更近90s就符合换车要求，这两种比较方式存在gap。

		- 其他：考虑PK；D被别的O抢走了 但后续由于pk失败或者c取消又被释放 重新回到匹配池。

	- **数据分析表明，只有6%的子单司机出现在父单的分单矩阵表里，这表明情况A、B占大多数，也就是在当前召回半径下，绝大多数的后续换车情况无法在分单阶段预知和解决。**

A：有多少换车成功子单（子单被应答）的子单司机出现在父单的分单矩阵表里 ？

Q：只有6%的子单司机出现在父单的分单矩阵表里。**说明在当前召回策略下，绝大多数更好的司机都是后来突然出现的，不是在初次分单中由于匹配机制原因错过的。因此应答后换车机制是必要的，无法通过分单阶段的优化来解决短时供需变化的问题。**

- **应答后换车和分单阶段的「订单hold」解决的是同一个问题吗？**

	- 订单hold是 觉得等一等能等到更近的车 所以hold一定秒数再分单。

		- 也不完全是。订单hold还可以起到提高司乘密度的作用，即使没有短时冒出O/D，订单hold也一定能保证找到更近司机。相当于两轮叠一起。

	- 换车是 过了一段时间周围出现了更近的车 所以重新匹配了。

	- **本质上应答后换车和分单阶段订单hold都是在解「等等能更近」的问题****。但先应答、后换车能带来的找车时间更长，因此即使存在订单hold，应答后换车也是有必要的。**

#### **3、Q：如何从体验和效率两方面考虑司机空驶？**

       **A1：从体验的角度，需要约束司机空驶。**

       **A2：从效率的角度，父单司机空驶不影响匹配决策。我们比较的仅仅是 原匹配 和 新匹配，哪种更优，司机空驶是沉没成本不影响匹配结论（可以当作是父单司机自己在游走）。**

- 如果换车是必要的，那么可以做哪些事情来更好地保护司机体验、减小伤害？

	- 首先可以将换车比例尽量往连环派倾斜，因为连环派对司机的伤害是最小的，司机没有空驶接驾。

	- 对于非连环派换车：

		- **约束司机空驶时间/距离**：不超过x秒/x米/不超过原接驾路程的x%

			- 注意：特别远接驾的单子其实也是司机不想要的，可能会诱导乘客取消，**那么对于特别长接驾的单子 换车对于司机是不是也是好事**？

		- **约束不要让司机多次连续遭遇换车**：司机有很多进线是投诉连续被“切单”

		- 从产品形态上加强和司机的透传

			- 解释对司机有益的部分，因为司机也不喜欢接驾远的单，只要剩余接驾路程对于司机仍是远的，那么换车就对于司/乘/平台三方都有利。最好是能快速给司机找到更近的单（太理想了做不到？）

- 换车本质上就是「重新匹配」吗？

	- **不完全是：换车本质上就是该订单再次进入GS分单系统，但父单司机仍被占用、不参与本轮分单。**

	- 就平台全局视角而言，需要应答后换车是因为 **「整体的O、D分布变化了，存在更优的匹配结果」**

		- 虽然目前的换车决策并不是从平台全局效率考虑的，目前是从单个订单的体验视角考虑的，逻辑是：如果这个订单体验不够好（接驾远或取消率高）且周围有更好选项，就改善这单的体验

	- 「父单司机无法参与新一轮匹配」是否影响我们对于「单个订单更优大概率等于全局更优」的判断？

		- 会影响效率，但不影响结论

	- 父单的司机空驶时长 是「折损」吗？除了作为约束，还会作为折损影响换车的决策吗？

		- 不会。如果把换车问题定义为「为了应对OD分布随时间变化进行的重新匹配」，那么关注的就仅仅是当前的匹配情况，父单空驶仅作为体验约束。

	- 如果是这样的结论，换车策略应该是怎样的？

		- 只要能更近（更近90s）且符合约束（父单司机空驶小于60s）就都应该寻求换车？**是的。如果这是一个简化的、只追求效率的系统，那么在分单池子中保留已匹配的OD、并允许随时更换更优的匹配就是有利于系统效率的。**

		- **从全局效率视角，哪一方在匹配市场中占主导，哪一方就应该具有随时换更优匹配对象的权利，这样的匹配结果也将是全局更优的。**（是这样吗？；这和上一条结论其实是一致的。）

#### 5、Q：在不同的供需条件下，换车的策略会不一样吗？

**A：根据数据分析，当前供需波动没有影响「绝大多数匹配由O单方面决定」的整体事实。因此在换车策略推导中暂不考虑供需变化。**

有可能，我们的目标是想寻找一个能穿越不同供需的策略。

根据[OD连边分析](https://cooper.didichuxing.com/knowledge/2199610335356/2206854359553)，**D反选O的空间即使在峰期也不到10%**。因此，**我们可以把目前的匹配市场简化为一个O单方面选D的市场来考虑换车问题。**所以可以认为供需变化不会大到影响OD匹配现状，因而在整体匹配现状下推导出的换车策略足以穿越供需。

#### 6、Q：思想实验：假设在一个仅追求效率的简化系统中，换车的理想态解法？

所以现在的换车，是在乘客/订单侧占匹配市场绝对主导的情况下，平台伤害司机侧而优化乘客侧的一种重新匹配策略。由于这是一个乘客主导的市场，因而这种策略也是符合系统的利益的。

- 如果所有的司机都是要么接驾，要么送驾（载人车可被连环派召回），要么随机游走，不存在司机突然出车和收车，不存在乘客应答后取消：是不是就不存在换车，理论上分单匹配阶段就是最优结果，后续不可能换到更优？

	- 理论上是。目前换车触发面8%\*40%成功率=3%的实际换车，所以说是有至少3%的订单在其周围遇到了司机出收车（这部分应该占比极少）、司机被应答后c取释放？

	- 现在应答后c取消率有多少：10% 。10%的订单释放出的司机，至少30%成为了别的O的更近司机。这个比例好像是合理的。

	- [ ] 有办法从数据上验证吗？

- 理想情况下，可以所有O都在匹配后仍留在匹配系统中吗？目的是看周围会不会有更近的车冒出来，有就换。

	- 这样会提升O的密度（假设还是像现在这样：O重新进入匹配池，父单D仍被占用 不会重新进入匹配池）

	- 似乎也是合理的，因为一旦O找到新D，原D会被立刻释放，这和同时释放O、D对结果的区别不大。

#### 7、Q：完成简化的效率系统的解法推导后，在实际情况中，如何加上体验约束？

- 前提假设：分单阶段已经合理考虑了连环派（送驾中车辆召回），换车理论上仅解决有车「冒出来」或者原司机堵车

- 约束：

	- 司机体验方面：

		- 父单司机空驶时长<= x s ;连环派可以把ab段空驶都计0，从完成上一单送驾后开始计空驶

		- 不要连续遭遇换车

	- 乘客体验方面：

		- 不要频繁换车

		- 有确定性（不要突然换车，提前沟通透传）

- 策略：

while 本单司机接驾已行驶时间<= x s:

O都继续留在匹配池中

if 发现更近的D then 换新的D 释放原D重新回匹配池

Q：对于取消率本身就不高的单，换车有意义吗？

A：对于系统来说是效率更高的，因为换车是因为全局中冒出了原来不在匹配池里的D，导致出现了更优的匹配

Q：目前的推理都是基于D反选O的空间不到10%、绝大多数匹配结果由O主导这个认知，如果更多O留在匹配池，O密度上升，单个O最优还等于系统最优吗？

A：只要D反选O的空间还是很小，那么把已匹配的O仍留在匹配池中等待更近的D 就是符合系统利益的。
