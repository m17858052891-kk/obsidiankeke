### 方案

离线取近二周分城市、分小时，HXZ和其他三方应答时长的90分位点作为HOLD滴滴发单的时长。

二期可取线上by格子的实时特征（如应答率、应答时长等供需特征）和离线特征做计算，产出准实时的HOLD时长。

## 指标

### 评估cd_time的两个核心方面？

1. 有多少订单可以HOLD时长短些——滴滴的呼单中乘客应答前取消了，但是还在cd_time中，订单还没有开始找滴滴司机。这个数现在可以看。

2. 有多少订单可以HOLD时长长些——

	1. 再等几秒，就能等到别的品牌参与举手，这部分无法准确地评估。但却是需要关注的，因为滴滴来了立刻发起PK，所以如果滴滴来时没人举手则滴滴会直接胜出，但滴滴司机密度很大，如果是平峰的话基本上开始找滴滴司机时就会有举手，我们不知道是否再等一两轮分单/PK，会找到别的司机）；

	2. 滴滴来时已有别的品牌举手，但滴滴胜出了，抢占了其他商家订单。这个数现在可以看。

（cd_time的最优状态，是滴滴呼单中的乘客应答前取消都是已经开始找滴滴司机但是没找到，且滴滴的应答订单都是周围一段时间内找不到任何其他品牌的司机的。）

```PlainText
with t as (
    select
        cast(param ['order_id'] as bigint) order_id,
        param ['hold_info'] hold_info
    from
        kflower_marketplace.ods_log_kflower_order_hold
    where
        concat_ws('-', year, month, day) = '2022-05-18'
)
select
    count(distinct order_id) `呼单数`,
    count(
        distinct case
            when cancel_type = 1 then order_id
            else null
        end
    ) `应答前乘客取消数`,
    count(
        distinct case
            when cancel_type = 1
            and nvl(hold_time, 0) < cancel_dur then order_id
            else null
        end
    ) `应答前乘客取消未呼叫滴滴数`,
    count(
        distinct case
            when cancel_type = 1
            and hold_time is null then order_id
            else null
        end
    ) `check日志`
from
    (
        select
            AA.order_id,
            cancel_dur,
            cancel_type,
            hold_time
        from
            (
                select
                    order_id,
                    cancel_dur,
                    cancel_type
                from
                    kflower_dw.dwd_kf_trd_order_anycar_di
                where
                    dt = '2022-05-18'
                    and product_id = 384
            ) AA
            left join(
                select
                    order_id,
                    cast(
                        get_json_object(B.json, '$.product_category') as bigint
                    ) as product_category,
                    cast(get_json_object(B.json, '$.hold_time') as double) as hold_time
                from
                    (
                        select
                            order_id,
                            split(
                                regexp_replace(
                                    regexp_replace(
                                        hold_info,
                                        '\\}\\,\\{',
                                        '\\}\\;\\{'
                                    ),
                                    '\\[|\\]',
                                    ''
                                ),
                                '\\;'
                            ) as json
                        from
                            t
                    ) A lateral view explode(A.json) B as json
            ) BB on AA.order_id = shiftleft(
                shiftright(BB.order_id, 46) & 262143,
                32
            ) +(BB.order_id & 4294967295)
        where
            BB.product_category = 328
        group by
            AA.order_id,
            cancel_dur,
            cancel_type,
            hold_time
    ) AAA;
```
