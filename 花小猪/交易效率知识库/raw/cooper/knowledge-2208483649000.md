# 一、背景

*核心讲1.3现状局限性 & 1.4改造动机和总目标*

## 1.1 分单系统在小猪交易链路中的位置

分单系统的核心目标是**==最大化商家完单==**（聚合 PK 模式下需要兼顾举手速度、PK 胜率与履约率）。一次完整决策从订单产生到司机触达，链路如下：

```PlainText
订单产生
  │
  ▼
运力候选池（按订单/司机半径召回连边）
  │
  ▼
【召回阶段】
  ├─ 过滤（Hold）：丢掉不应播的 OD 对
  ├─ TP（极速指派 ~300ms，全指派）
  └─ GS（轮次匹配 2s/轮，全局优化）
  │
  ▼
【匹配阶段】
  └─ GS 池内 M×N 全局优化，决策每个 OD 对的交易模式
  │
  ▼
【派单模式】
  ├─ 全指派 / 半指派 / 抢单 / 连环派
  │
  ▼
司机端听单 → PK → 应答 → 履约 → 完单
```

**召回 vs 匹配 vs 派单模式 的分工**（详见 [召回与匹配阶段对比](召回与匹配阶段对比) 与 [派单模式](派单模式)）：

| 模块 <br> | 决策维度 <br> | 决策对象 <br> | 目标 <br> |
| --- | --- | --- | --- |
| 召回 <br> | 纵向时间维度（订单生命周期） <br> | 单 OD 对：何时播单（TP / GS / Hold） <br> | ==最大化====**单订单**====生命周期期望完单== <br> |
| 匹配 <br> | 横向空间维度（单轮 M×N 全局） <br> | 一轮内多 OD 对的全局指派 <br> | ==最大化====**多订单**====单轮期望完单之和== <br> |
| 派单模式 <br> | 模式选择 <br> | 每个播单 OD 对走哪种模式 <br> | ==调节司机举手率与履约率== <br> |

## 1.2 线上现状

略，详细可参考：

> 历史策略：[商家分单历史策略梳理](https://cooper.didichuxing.com/knowledge/2199610335356/2206793429944)

> 线上参数：[商家召回策略V2.1策略方案](https://cooper.didichuxing.com/knowledge/2199610335356/2207164149659)

- 召回

	- **订单侧**：固定最大初始召回半径，不再动态缩扩播

	- **司机侧**：初始缩小听单半径，逐渐扩至最大

	- **召回机制**：三模型联合过滤 — BCAA + CCAA + OCR（T 维度公式）；召回规则 `max{BCAA, CCAA} < OCR`

-  匹配

	- **GS 分单**：2s/轮，GS 稳定匹配算法，多轮全局优化

	- **TopSpeed 分单**（2025-03 自营放量）：\~300ms 一轮，仅对送驾里程 > 4.5km 订单生效，播单半径 2.5km，全指派

	- **匹配打分**：O 选 D / D 选 O 偏好分；94% 的匹配由 O 对 D 打分决定（唯一连边 D 仅 6%）

- 派单模式

	- 由**订单价值模型**（预估司机拒单/取消率）在召回阶段决定全指派 / 半指派 / 抢单

## 1.3 现状局限性

### 1.3.1 召回侧

（四大瓶颈，引用 [商家召回重构1.0策略方案](商家召回重构1.0策略方案) §1.2）

- **过滤条件未体现完单==最大化目标==**：`max{BCAA,CCAA} < OCR` 是单轮贪心，未考虑多轮最优，**没有显式建模竞争胜率 σ**——大量 PK 必输的无效播单仍占用司机听单容量

- **==TP / GS 决策缺统一价值框架==**：TP 入口为启发式（4.5km / 2.5km），全局机会成本未显式建模

- **多模型 + 多参数==维护==复杂**：BCAA / CCAA / OCR 三模型独立 + 多个 by 城市偏置项，运维成本高

- **==OCR 模型==****存在瓶颈**：ODTP 维度 XGB 在竞争阶段过滤过多运力（60% 订单 10s 内完成播单导致首末轮特征几乎无差异），线上效果不如 T 公式但 T 公式本质是启发式

### 1.3.2 匹配侧

（引用 [商家匹配重构1.0策略方案](商家匹配重构1.0策略方案) §1.2）

- **==匹配 / 交易模式==****分别决策**：两者目标都是最大化完单，但在不同阶段独立优化，存在联合空间

	- **==交易模式决策与匹配解耦==**：交易模式影响举手率，但在召回阶段就已固化，匹配阶段无法联合优化

- **GS 打分不含竞争胜率 σ**：==司乘稳定 ≠ 完单最大化；==**GS 追求稳定匹配而非完单最大化**：稳定匹配的目标函数与"商家完单"目标存在 gap

- 如何符合业务约束，缺乏显式的==可调节能力==

### 1.3.3 派单模式侧

- 派单模式分流在**召回阶段静态固化**，匹配阶段无法基于候选集再优化

- 不同模式的 q（半指派接受率）与 σ（PK 胜率）耦合明显，但当前体系无 q 模型

### 1.3.4 ==跨模块：价值口径不一致==

召回用"取消率 < 流失率"贪心目标 + 匹配用"司乘稳定"目标 + 派单模式用"司机拒取率"目标——三段决策**价值函数不同源**，导致整体次优。

## 1.4 改造动机与总目标

**改造动机**：==用同一套"最大化期望完单"价值函数贯通**召回 → 匹配 → 派单模式**三段决策==；==把派单模式从召回阶段下放到匹配阶段联合决策==；用模型 + ==少量超参==替代 V2.0 的"多模型 + 多偏置项"。

**总目标**（与 [商家召回重构1.0策略BRD-V2](商家召回重构1.0策略BRD-V2) §2.1 对齐）：

> ==在**完单不负**的约束下，降低**乘客 ETP + 司机接驾时长合计 1%**。==

**量化贡献预期**：召回 V1.0 承担 \~80%、匹配 V1.0 承担 \~20%（拆解见 [商家召回重构1.0策略BRD-V2](商家召回重构1.0策略BRD-V2) §2.5；匹配侧贡献区间 `【待策略补充】`）。

### 2.2 为什么必须改召回

1. **价值口径正本清源**：召回是匹配 / 派单模式的输入源，价值口径不统一会让下游优化"无米下锅"——V1.0 把过滤 / TP / GS / Hold 全部对齐到"最大化期望完单"，是后续匹配联合决策的前置

- **参数 32 → 18 的可解释性收益**：V2.0 32 个参数中 16 个是必要的最大召回半径 ETA/EDA，**仅 2 个超参 β + λ' 是 V1.0 引入**，去掉多套 by 城市偏置项；新城市上线无需调参（详见 [商家召回重构1.0策略方案](商家召回重构1.0策略方案) §3.2 参数对比表）

- **β / λ' / r 解决调参痛点**：单一 β 旋钮调节"完单 vs 接驾/ETP"权衡，不再需要分城市分框堆参数；λ' 显式建模 TP 的全局机会成本

- **前置条件就绪可 4 周压缩**：σ / CAA / OCR 训练数据可复用现有举手 + PK 结果、应答后取消、未播单订单样本；E(finish) 分桶查找表与 p_next 实时统计有现成基础设施（SDS 格子 / GeoHash）；详见 [4周排期总表](4周排期总表) §1.2 4 周压缩思路

### 2.3 为什么必须改匹配（紧跟召回）

1. **下游价值对齐**：召回升级到 `σ·(1-CAA)` 价值口径后，匹配若仍用"O 选 D / D 选 O 偏好分"会出现召回淘汰的订单匹配又救回来的逻辑断层；匹配 V1.0 复用召回 σ\_GS、CAA 实现价值统一

- **派单模式联合决策的天然容器**：候选集已知 + 约束可线性化 + 求解可在 2s 内完成——匹配阶段是唯一同时具备这三个条件的阶段

- **边际成本低**：匹配 V1.0 复用召回 σ / CAA 两大模型，**只需新增 q（半指派接受率）模型**；ILP 求解链路工程改造可控

### 2.4 为什么召回-匹配必须耦合改

1. **价值口径错配反例**：召回侧改、匹配侧不跟 → 召回按 `σ·(1-CAA) > β·(1-OCR)·E(finish)` 淘汰的 OD 对，匹配按"O 选 D / D 选 O 偏好分"仍可能优先指派，价值框架被旁路

- **派单模式必须有承接**：召回侧 V1.0 明确"交易模式推迟到匹配阶段"（[商家召回重构1.0策略方案](商家召回重构1.0策略方案) §5.2 模块五），如果匹配侧没承接，全/半/抢决策会无家可归

- **AB 评估口径**：联合上线才能用同一组指标（ETP / 接驾 / 完单 / CAA）做端到端 AB；分两次迭代会导致两轮 AB 的归因互相污染

### 3.1 召回策略方案（详写）

#### 3.1.1 优化目标与收益拆解

**核心目标**：在**完单不负**约束下，降低**乘客 ETP + 司机接驾时长合计 1%**。

**==收益拆解==**==（引用 [商家召回重构1.0策略BRD-V2](商家召回重构1.0策略BRD-V2) §2.3）：==

| 链路 <br> | 接驾时长 <br> | ETP <br> | 完单 <br> | 测算依据 <br> |
| --- | --- | --- | --- | --- |
| **链路 1：σ 模型引入（核心增量）** <br> | ↓0.5% <br> | ↓0.3% <br> | 中性持平 <br> | V2.0 实验中"缺 C 城市 PK 胜率"是主瓶颈；σ 把 PK 必输无效播单识别并过滤，司机听单池释放给真正能赢的订单 <br> |
| **链路 2：TP/GS 价值决策统一** <br> | ↓0.3% <br> | ↓0.5% <br> | 持平 / 微正 <br> | GS→TP 扩展（举手 \~2s → \~300ms，ETP 直接受益）+ TP→GS 回流（贪心损失大的订单走全局优化，接驾受益）；对标 TopSpeed 上线幅度 <br> |
| **链路 3：CAA 合并 + 深度模型升级** <br> | ↓0.2% <br> | — <br> | 中性 <br> | 更准识别长接驾高取消 OD 对 <br> |
| **链路 4：OCR → ODTP 深度模型** <br> | — <br> | — <br> | 中性兜底 <br> | 突破 ODTP-XGB 在竞争阶段过滤过多运力的瓶颈 <br> |
| **合计（同向叠加）** <br> | **↓约 1.0%** <br> | **↓约 0.8%** <br> | **±0.1% 内** <br> | 综合 **ETP + 接驾↓\~1%** <br> |

**AB 评估锚点**：合计↓ ≥ 0.5% 通过下限 / ≥ 1.0% 目标值 / 完单 ±0.1% 约束门槛。

#### 3.1.2 问题定义与符号

**召回阶段**解决**纵向时间维度的短时最优**——求解订单生命周期内何时播单。决策对象：每个 OD 对 (i, j) 走 TP / GS / Hold 三选一。

| 符号 <br> | 含义 <br> |
| --- | --- |
| T <br> | 当前轮次 <br> |
| i / j <br> | 订单 / 司机索引 <br> |
| \\mathcal{D}\_i <br> | 订单 i 候选司机集合 <br> |
| k \\in \\{0,1,2\\} <br> | 播单模式：0= 不播，1= TP，2= GS <br> |
| \\sigma\_{ijk} <br> | 竞争胜率（举手后 PK 获胜概率） <br> |
| CAA\_{ij} <br> | 应答后取消率 <br> |
| OCR_i <br> | 不播单时一个轮次间隔内订单流失率 <br> |
| E(\\text{finish})\_i^{T+1} <br> | 进入下一轮后的期望完单 <br> |
| p\_{next}(j) <br> | 司机 j 周围 1-2km 未分配订单密度 <br> |
| \\beta <br> | Hold 激进度系数（默认 1） <br> |
| \\lambda' <br> | TP 惩罚项系数（吸收 \\Delta CAA 均值效应） <br> |

#### 3.1.3 三路价值公式（核心）

把过滤 / TP / GS 三类决策统一到同一价值框架。对每个候选 OD 对 (i,j) 计算三路价值并取最大值：

\\text{value\\\_TP} = \\sigma\_{ij1} \\cdot (1 - CAA\_{ij}) - \\lambda' \\cdot p\_{next}(j)

\\text{value\\\_GS} = \\sigma\_{ij2} \\cdot (1 - CAA\_{ij})

\\text{value\\\_hold} = \\beta \\cdot (1 - OCR_i) \\cdot E(\\text{finish})\_{\\text{baseline}}(\\text{city}, \\text{time\\\_slot}, \\text{supply\\\_demand}, \\text{wait\\\_rounds})

```PlainText
if value_TP > value_GS and value_TP > value_hold:
    → TP（极速指派 ~300ms，全指派）
elif value_GS > value_hold:
    → GS（轮次池，2s/轮全局优化）
else:
    → Hold（不播，等下一轮）
```

**物理含义**：

- 播单完单概率 = \\sigma \\cdot p \\cdot (1 - CAA)；V1.0 召回阶段 p=1（TP 全指派、GS 乐观估计），消去 p

- 不播单完单概率 = (1 - OCR) \\cdot E(\\text{finish})^{T+1}

- 三种决策（过滤 / GS / TP）是同一价值评估体系的不同输出

**TP vs GS 价值差来源**：

- \\sigma\_{ij1} 通常 > \\sigma\_{ij2}（TP 速度优势 → 更早进入 PK 窗口 → 竞争对手更少）

- \-\\lambda' \\cdot p\_{next}：TP 全局机会成本（贪心匹配破坏全局最优）；司机周围订单密度低时 TP 惩罚小、倾向 TP

**与 V2.0 过滤的等价性**：V2.0 旧过滤 `max{BCAA,CCAA} < OCR` 是新价值框架的退化形态（当 σ=1、β=1、E(finish)=1、CAA=max{BCAA,CCAA} 时两式等价）—— 这是 PID 实验 G1→G4 归因路径完全干净的数学基础。

#### 3.2.2 数学框架（已共识）

**==优化目标==**==：最大化本轮所有 OD 对的期望完单之和==

\\max \\sum\_{i,j,l} z\_{ijl} \\cdot \\sigma\_{ij} \\cdot q\_{ijl} \\cdot (1 - CAA\_{ij})

| 符号 <br> | 含义 <br> |
| --- | --- |
| i / j <br> | 订单 / 司机索引（本轮共 M 个订单、N 个司机） <br> |
| l \\in \\{1, 2\\} <br> | 交易模式：1= 全指派 / 2= 半指派 <br> |
| z\_{ijl} \\in \\{0,1\\} <br> | 匹配决策变量 <br> |
| \\sigma\_{ij} <br> | 复用召回 σ\_GS 模型预测值 <br> |
| q\_{ijl} <br> | 半指派有效响应率（q\_{ij1}=1 全指派必接受；q\_{ij2} 由 q 模型预测） <br> |
| CAA\_{ij} / BCAA\_{ij} / CCAA\_{ij} <br> | 多任务 CAA 模型三输出，OD 维度，不依赖 l <br> |
| \\eta\_{ij} <br> | 接驾 ETA <br> |
| \\eta_0 / BCAA_0 / CCAA_0 <br> | 单轮全局约束阈值（由全天目标映射） <br> |

**约束**：

- **C1 订单播单约束**（每订单最多一个司机、一种模式）

\\sum\_{j,l} z\_{ijl} \\leq 1, \\quad \\forall i

- **C2 司机播单约束**（每司机最多一个订单）

\\sum\_{i,l} z\_{ijl} \\leq 1, \\quad \\forall j

- **C3 平均 ETA 约束**（按预期应答量 σ·q 加权，分母移项后线性化）

\\sum\_{i,j,l} (\\eta\_{ij} - \\eta_0) \\cdot \\sigma\_{ij} \\cdot q\_{ijl} \\cdot z\_{ijl} \\leq 0

- **C4 平均 BCAA 约束**

\\sum\_{i,j,l} (BCAA\_{ij} - BCAA_0) \\cdot \\sigma\_{ij} \\cdot q\_{ijl} \\cdot z\_{ijl} \\leq 0

- **C5 平均 CCAA 约束**

\\sum\_{i,j,l} (CCAA\_{ij} - CCAA_0) \\cdot \\sigma\_{ij} \\cdot q\_{ijl} \\cdot z\_{ijl} \\leq 0

```PlainText

输出 z*_{ijl} ∈ {0, 1}
```
