# 一、背景

- 动机：在GS算法中，D先选还是O先选理论上可能影响最后的匹配结果（参考[商家分单GS算法优化V1策略方案](https://cooper.didichuxing.com/docs2/document/2205087355122)中给出的case）。

- 现状：目前线上GS匹配算法是D先选。

- 本次策略：新增了GS_O（O先选的GS功能），将O先选的GS匹配结果落表（仅模拟和落表，未在线上实际生效）。

- 测算目的：根据工程落表的GS_O和GS_D两种模式下的匹配结果，测算优化GS匹配模式的收益空间。

# 二、结论

**结论：by轮次by层级来看，0.21%的召回在GS_O和GS_D下会产生不同的匹配结果。**

```SQL

with

base as (

select

param['area'] as city,
param['output'] as output,
param['traceId'] as traceId,
param['input'] as input,
param['input_num'] as input_num,
param['level'] as level,
param['driver_group'] as driver_group,
param['broad_source'] as broad_source,
param['uuid'] as uuid,
param['strategy_name'] as strategy_name,
param['output_num'] as output_num,
param['timestamp'] as time_stamp


from kflower_marketplace.ods_log_kflower_stg_strategy_result_h
where concat_ws('-', year, month, day) = '2026-03-18'
and param['area'] in(24)
-- limit 100

)

,base_two_output as (
select 

city,
traceId,
input,
input_num,
level,
driver_group,
broad_source,
uuid,
time_stamp,
-- strategy_name, 


max(case when strategy_name in ('OrderFGS') then output end) as OrderFGS_output,
max(case when strategy_name in ('OrderFGS') then output_num end) as OrderFGS_output_num,

max(case when strategy_name in ('DriverFGS') then output end) as DriverFGS_output,
max(case when strategy_name in ('DriverFGS') then output_num end) as DriverFGS_output_num

from base 
group by 1,2,3,4,5,6,7,8,9
)

-- select * from base_two_output limit 100



select 
a.*,
same_cnt/tt_cnt as same_ratio

from(
    select 

    count(*) as tt_cnt,
    sum(if(OrderFGS_output=DriverFGS_output,1,0)) as same_cnt

    from base_two_output 

)a
```

> 数据：2026-03-18 长沙市（24）一天数据
