# 业务背景

==用户未主动勾选某车型&&车型满足一定条件时，则在发单or等待应答时也呼叫该车型；若该车型有运力举手则询问用户是否接受；若用户接受则进入接驾流程。==

**收益来源**：

用户发单勾选品牌无运力时，预分单运力带来完单增量

**可能折损**：

用户不接受预分单车型

**策略可提升的点**：

1. 可预分单车型

2. 预分单触发率&触发准确率

3. 用户接受度

> 注：二期实验配了四组阈值，两组正向，两组不显著负向

  <https://cooper-vpn.xiaojukeji.com/docs/document/2200156645547>

**触发策略**：

发单数和应答率为中心+格子一圈，5分钟的数值

 

发单数>(差应答，dufe)阈值 &&

应答率 < 预分单应答率阈值\_A 时，等待应答时长＞T1秒开始预分单

 

发单数>(差应答，dufe)阈值 &&

应答率 < 预分单应答率阈值\_B 时，等待应答时长＞T2秒开始预分单

 

否则，等待应答时长＞T3秒开始预分单

 

新增"预分单应答率阈值\_A"、"预分单应答率阈值\_A"、"T1"、"T2"、"T3"为本次新增灰度配置中参数

只计算第一次轮询时的时间缓存下来即可
