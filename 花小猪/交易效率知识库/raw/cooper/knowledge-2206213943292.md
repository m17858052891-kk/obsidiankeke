# 一、背景

- 策略：接驾远换车v2策略方案（[接驾远换车优化策略方案](https://cooper.didichuxing.com/knowledge/2199610335356/2204880840509)），相比v1简单人工规则，v2策略的核心改动是新增了取消率模型并将自动换和手动换相结合，并扩大了触发面。

- 实验版本：v2.1实验发现线上bug较多（**连环派eta计算bug，换车中父单司机取消无法改派问题**），以及eta切caller后重新测算了新口径下的阈值。**上述两个bug修复完和eta caller切换完后，重新开启二期实验**。

### 5.2、接驾时间

**结论：**

- **反映「大盘乘客真实等待时长」的指标是<u>【归一订单维度】大盘单均等待时间</u>，组a和b分别比对照组降低0.8秒和1.6秒**

	- **换车会缩短完单订单的等待时长，同时也会降低乘客取消率、因此拉长大盘单均等待时长，大盘单均等待时间变化是这两个因素共同作用的结果**

	- 单独拆分**<u>完单订单的单均等待时长</u>，反映 <u>大盘完单乘客能够平均少等多少秒</u>，组a和b分别比对照组降低4.7秒和4.8秒**

- **反映「换车理论上缩短了大盘多少预估接驾时间」的指标是<u>【订单维度】由换车成功单换算到大盘的单均eta缩短时间</u>，组a和b分别缩短了6.8秒和6.9秒**

	- 这是一个理论预估值，只能反映「预估接驾时长平均到大盘会下降多少」，但eta的下降会影响乘客取消行为，因此和乘客实际等待时间并不等价

# 六、后续优化

### 6.1 线上bug修复

本次实验线上仍存在2个问题：

#### （1）改派锁

- 问题描述：仍有部分司机取消没有被改派，原因是线上存在改派锁（无法在15秒内进行两次改派，第二次改派会被拦截）

- 影响：详见本文档4.4 。修复后预估：归一应答后最终完单率：+0.25pp -> +0.36pp，人均完单量：+0.16% -> +0.28%

- 需求：后续会将改派锁时间修改为可配置的x秒。目前已完成修复，时间由15秒改为3秒。

- 进展：1.16已修复完成。预计2026春节后重新分流进行实验并评估收益。

#### （2）连环派eta bug

- 问题描述：api侧bug，没有去除连环派标签，导致eta和eda计算逻辑错误

- 影响：连环派eta计算错误，导致轮询换车次数变多，连环派找车成功率变低。

- 需求：修复bug，在司机送完上一单后去除连环派标签

- 进展：1.27已过prd，待排期。

### 6.3 策略迭代-约束司机空驶的优化问题
