# 一、背景

当今的大语言模型尽管在实际应用中取得不俗的表现，但很难保证其输出的可靠性，由于预训练模型在大规模语料通过**最大似然概率的方式学习**，网络的海量数据总是倾向让模型给出回复。大模型获取的知识一般在预训练阶段就已经确定并以参数化的形式储存，如果在指令微调中使用模型没见过的知识样例，那必然会导致模型对于未知的问题也给出确定答复，即编造一个答案，这就是模型**过度自信导致的幻觉问题**。如果盲目轻信采用模型生成的答案，很可能会误导用户。

# 二、前置知识

在机器学习中，**置信度**与**不确定性**并非相互独立的概念：在理想情况下，更高的预测置信度应对应更低的不确定性。在监督学习设定下，给定输入 $$x$$、真实标签 $$y$$ 以及模型预测 $$\hat{y}$$​，模型的预测置信度通常表示为：

$$conf(x,\hat{y})$$

对模型置信度的量化研究催生了两个关键概念：**相对置信度得分**和**绝对置信度得分**，它们提供了评估和解释置信度水平的不同方法。

**相对置信度**

相对置信度强调模型**对样本进行排序的能力**，即模型是否能够为“更可能预测正确”的样本分配更高的置信度分数。理想情况下，对于任意两个样本 $$(x_i, y_i)$$与 $$(x_j, y_j)$$，其预测结果 $$\hat{y_i},\hat{y_j}$$应满足:

$$\mathrm{conf}(x_i, \hat{y}_i) \le \mathrm{conf}(x_j, \hat{y}_j) \Longleftrightarrow P(\hat{y}_i = y_i \mid x_i) \le P(\hat{y}_j = y_j \mid x_j)$$

**绝对置信度**

与相对置信度不同，**绝对置信度要求模型输出的置信度分数具有明确的概率含义**。具体而言，当模型给出置信度时，在统计意义上应满足:

$$P(\hat{y} = y \mid \mathrm{conf}(x, \hat{y}) = q) = q$$

当模型的预测置信度与真实准确率一致时，模型被称为是**良好校准的**。例如，如果模型对一类事件预测 0.7 的置信度，那么在相似条件下，该事件应约有 70% 的概率发生。

# 三、 生成模型置信度估计

==传统分类任务的不确定性或置信度度量比较简单，但是大模型的输出通常为序列，而所对应的下游任务更是种类繁多，这就给大模型不确定性度量带来一定困难，大模型生成任务的不确定性估计通常有以下两点困难：==

==1、传统分类任务的输出空间是有限的，一般为类别==$$N$$==，而生成任务输出空间为==$$N^L$$ ==，其中==$$L$$ ==为序列长度，而又因为输出序列**长度是可变的**，因此生成任务的输出空间可以认为是无穷大。因此很多分类任务的不确定性估计和校准方法并不适用于生成任务。==

==2、分类任务的 SoftMax 输出概率往往可以直接反应对一个预测的置信度，但是生成任务的句子序列中每一个词元 token 的概率并不能反应置信度，因为**生成任务我们更关注句子的含义**，也就是语义。生成任务更关注如何捕捉准确的语义信息来进行不确定性建模。==

因此，生成式模型的不确定性估计问题，通常围绕如何刻画模型对**生成文本整体可靠性**的认知展开。从模型可访问信息的角度出发，现有方法通常根据**是否能够获取每个 token 位置的预测概率**，将不确定性估计方法划分为**白盒方法**与**黑盒方法**。==下面列出了几类大模型常见的不确定性估计方法。==

## 3.1 基于 llikelihood 的置信度估计

基于似然的置信度是通过计算在给定输入$$x$$ 下生成序$$y = {y_1, y_2, \ldots, y_N}$$ 的联合概率来进行估计的。由于生成序列越长，其联合概率会随长度呈指数级下降，因此通常对条件概率的乘积进行长度归一化，以消除序列长度带来的影响。具体而言，置信度可表示为：

$$\mathrm{Conf}(x, y) = \left(\prod_{i=1}^{N} p(y_i \mid y_{<i}, x)\right)^{\frac{1}{N}}$$

其中$$p(y_i \mid y_{<i}, x)$$ 表示在给定输入$$x$$ 及先前已生成序$$y_{<i}$$ 的条件下生成第$$i$$ 个 token 的概率。

由于生成序列中某些高频词（如 "the"）本身具有较高的预测概率，而实际不确定性往往由低频或信息量较大的 token 所主导，因此也有研究直接采用生成序列中最小的 token 概率作为预测置信度，其形式为：

$$\mathrm{Conf}(x, y) = \min { p(y_1 \mid x), \ldots ,p(y_N \mid y_{<N}, x) }$$

此外，也可以通过对所有 token 的条件概率取算术平均值来估计生成结果的置信度，即：

$$\mathrm{Conf}(x, y)= \frac{1}{N} \sum_{i=1}^{N} p(y_i \mid y_{<i}, x)$$

这类方法在一定程度上能够通过捕捉输出词元的预测概率来反映模型的不确定性信息，但这些概率值更多反映的是模型在最大似然训练目标下对语言分布的拟合结果，而非对生成文本真实语义正确性的可靠刻画。此外，上述方法均依赖于访问 token 级别的预测概率，这在许多闭源或黑盒大语言模型中难以实现，从而限制了其在实际应用中的适用性。

**DeepConf**

上述三种方法均基于“**已采样 token 的概率**”$$p(y_i \mid y_{<i}, x)$$，而 DeepConf 的核心创新在于不再关心“**选中了哪个 token**”，而是关心“**模型在该位置整体有多确定**”。

在生成中/生成后，用模型内部的 **token 分布计算局部置信度**，据此过滤掉不靠谱的轨迹，或者在轨迹变不靠谱时立刻提前停。分为两种场景：

- **离线（offline）**：先生成完一批轨迹，再用置信度加权投票/过滤后投票。

- **在线（online）**：边生成边看“**分组置信度**”是否小于阈值，若小于则立即截断该轨迹，可以节省大量 Token。

![](https://s3-ep-inter.didistatic.com/didoc-upload-image-prod/176580104712052218113-4844-4d82-b6e5-87b54a9594e9/%E6%88%AA%E5%B1%8F2025-12-1520.17.23.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T093036Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=2807a3887713c6aefd375fdff82c82c1a6a9bb3f08f683ce2183dd79bca99932)

DeepConf从top-k 分布视角定义**token置信度**为：

$$C_i = -\frac{1}{k} \sum_{j=1}^{k} \log P_i(j)$$

基于token置信度，进一步定义了5类推理轨迹的置信度

|  <br> | 定义 <br> |
| --- | --- |
| 平均轨迹置信度 <br> | $$C_{\mathrm{avg}} = \frac{1}{N} \sum_{i=1}^{N} C_i$$ <br> |
| 分组置信度 <br> | $$C_{G_i} = \frac{1}{|G_i|} \sum_{t \in G_i} C_t$$ <br> |
| 底部10%分组置信度 <br> | $$C_{\text{bottom-10}}(t) = \frac{1}{|G_b|} \sum_{G_j \in G_b} C_{G_j}$$ <br> |
| 最低分组置信度 <br> | $$C_{\text{least}}(t) = \min_{G_j \in G} C_{G_j}$$ <br> |
| 尾部置信度 <br> | $$C_{\text{tail}}(t) = \frac{1}{|T_{\text{tail}}|} \sum_{t \in T_{\text{tail}}} C_t$$ <br> |

**离线方法**：

采用置信度加权多数投票，对每个候选答案 a，其投票权重定义为所有生成该答案轨迹的置信度加权和，选择加权得分最高的做为最终答案。

$$V(a) = \sum_{t \in T} C_t \cdot \mathbb{I}(\mathrm{answer}(t) = a)$$

此外，为进一步减少低质量推理轨迹的干扰，可在投票前引入**置信度过滤**。该步骤按照轨迹级置信度对所有轨迹进行排序，仅保留置信度排名前 η 的轨迹参与投票，其中 η 取 10% 或 90%。前者强调高置信度集中决策，后者在保持多样性的同时削弱低置信度轨迹的影响。

![](https://s3-ep-inter.didistatic.com/didoc-upload-image-prod/1765803147238742302c5-6d37-4cd8-b898-39cfac511ee0/%E6%88%AA%E5%B1%8F2025-12-1520.52.24.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T093036Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=b1c217d4588718e7610c7bc5493087296f33fd13a01bbd96be3c7b1b23c455e7)

**在线方法**

核心目标为在生成过程中实时评估推理轨迹的置信度，并尽早终止低质量轨迹，从而节省计算资源并提升整体输出质量。全流程如下：

- **离线预热**：对同一个 prompt，先生成 $$N_{init}$$ 条完整推理轨迹。对每条轨迹计算其整体置信度 $$C_t$$，根据这些置信度的分布，计算停止阈值$$s=Percentile_{100-\eta}(C_0, C_1, C_{init-1})$$

- **在线生成**：在轨迹数量未超过预算 B 的前提下，开始生成新的推理轨迹。

- **轨迹早停**：对于每一条新轨迹，模型按 token 逐步生成内容；每生成一个 token，就计算其所属 token 组的组置信度$$C_{G_i}$$，如果$$C_{G_i} < s$$立即停止当前轨迹的生成，否则继续生成下一个 token，从而实现对低质量推理轨迹的在线早停，避免无效计算。

- **轨迹汇总**：当一条轨迹结束后，将其加入轨迹集合 T，计算该轨迹的整体置信度 $$C_t$$，并更新对应答案的投票权重 V(a)，根据当前所有轨迹的投票情况，重新计算多数答案 $$\hat{a}$$及其投票占比$$\beta = \frac{V(\hat{a})}{\sum_a(V_a)}$$, 若 $$\beta$$大于一致性阈值 $$\tau$$，认为模型已达成一致，停止所有生成并输出最终答案；否则继续生成新的轨迹，直到满足一致性条件或达到预算上限 B。

![](https://s3-ep-inter.didistatic.com/didoc-upload-image-prod/17658031649287d8a8e50-fb16-4ae2-beb3-c95fca045701/%E6%88%AA%E5%B1%8F2025-12-1520.52.42.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=AKDD00000000000EBLCTZNRBJHX6ZS%2F20261104%2Fgzep%2Fs3%2Faws4_request&X-Amz-Date=20261104T093036Z&X-Amz-Expires=86400&X-Amz-SignedHeaders=host&X-Amz-Signature=47389c5c6a64499f4116a54e076c2aee0c630bbd343b9cff1098d3a3fd8de685)

## 3.2 基于 Prompt 的置信度估计

一个例子："Chocolate milk comes from brown cows."

- 基于token likelihood视角来看非常合理：“Chocolate milk”，“milk comes from brown cows”，基于token likelihood的置信度得分很高

- 但从语义事实层面来看这是一条错误的断言，“Chocolate”和“cows”无关。

- token likelihood 衡量的是**语言连续性，**而不是**语义正确性，**仅依赖 token-level 概率，难以判断模型输出在语义层面是否可靠。

基于这一局限，一类方法转而采用**基于 prompt 的置信度估计。**==基于 Prompt 的方法有两种，分别是基于== $$P(\mathrm{True})$$和**语言置信度**。

$$P(\mathrm{True})$$ 置信度分数是通过简单地询问模型本身其对于问题$$x$$ 回复$$y$$ 是否为真来实现的，即在首次生成答案后，再次询问模型 “你认为你对问题$$x$$ 的回复$$y$$ 是正确（True）的吗”，然后获取模型分配的真实概率$$P(\mathrm{True})$$，这可以隐含获得模型自我反映的置信度。

$$\mathrm{Conf}(x, y) = p(\mathrm{True}) = p(y\ \text{is True?} \mid x)$$ 

由于大模型具备良好的指令遵循能力，现在有很多研究直接让模型口语化地输出对预测的不确定性估计，即直接提问模型对于问题$$x$$ 的回复$$y$$ 的置信度是多少，要求模型返回一个$$[0, 1]$$ 之间的小数。

基于 Prompt 的方法除了引入额外的推理计算代价，对不同的 prompt 也具有较强的敏感性。此外，这类 prompt 的作用方式与 CoT 类似，更多是激发模型表达其已有的置信判断，而非真正提升模型输出的客观可靠性。

**CAN LLMS EXPRESS THEIR UNCERTAINTY?** 

这篇文章设计并比较了多种“人类启发式”的 prompting 方法，试图缓解 LLM 在语言化置信度时固有的过度自信问题。具体方法包括五类：

**Vanilla**：最基础的方式模型直接回答问题，并给出一个整体置信度。这是基线方法，也是过度自信最严重的设置。

**CoT**：在回答和给置信度之前，要求模型先逐步推理。作者的动机是：更充分的理解和推理可能让模型更清楚自己哪里不确定，从而改善置信度表达。

**Self-Probing**：基于“人更容易发现他人错误而非自身错误”的假设。流程是：先生成答案，然后在另一个独立对话中，把“问题 + 已生成答案”交给模型，再问“上述答案正确的可能性有多大”。目的是**通过角色切换来降低自信偏置**。

**Multi-Step**：作者观察到模型在整体回答层面非常自信，因此尝试把推理过程拆解成多个步骤。模型需要对每个推理步骤分别给出置信度$$C_i$$​，最终的整体置信度通过所有步骤置信度的乘积得到。直觉是：某一步的不确定性会被显式暴露，从而抑制整体置信度。

**Top-K**：通过要求模型生成K个可能答案，并为每个答案给出其正确概率，来显式引入“多解意识”，能避免模型把全部置信度压在单一答案上。

## 3.3 基于多次采样的不确定性估计

对于无法直接获得输出概率的商业黑盒模型，除了以上语言表达置信度的方法，我们也可以通过针对一个问题  通过调整**温度系数**以及**解码方法**进行多次采样，如果采样三次其中有两次输出答案相同，我们可以认为置信度为 0.66。

==同样地，多次采样方法可能会引入更多的推理计算代价，并且也无法提高模型本身可靠性。==

**CAN LLMS EXPRESS THEIR UNCERTAINTY?** **采样策略**

**Self-random**：对同一个 prompt 多次输入，利用模型本身的随机性进行采样。通过调节 temperature 控制 token 分布的平滑程度，从而改变生成答案的多样性。回答差异越大，说明模型越不确定。

**Prompting**：通过对同一个问题进行不同方式的改写，生成多个回答。如果模型对语义真正理解充分，回答应当对问题表述的变化具有鲁棒性；反之，回答易变说明不确定性较高。

**Misleading**：在问题中加入误导性线索（例如“我觉得答案可能是……”）。灵感来自人类行为：

- 对于确信的内容往往会坚持原判断

- 对于不确定的内容更容易被外部暗示影响

## 3.4 基于训练的置信度估计

==基于训练的方法就是引入一个数据集，利用监督微调的方式训练一个额外的判别器或让模型本身学习置信度分数表达，这种方法可以提高模型实际置信度的表达，如何构造可靠的训练集就称为研究重点。==
