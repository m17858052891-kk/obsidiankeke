# 召回离线模拟设计

# 召回离线模拟设计

## 1. 背景

召回 V1 计划用统一价值公式替代线上 baseline 的启发式过滤和 TP 入口规则。为方便离线模拟讨论，后续统一使用以下版本命名：

- `V0`：线上 baseline 召回策略。

- `V1`：本次开发的新召回策略。

新版决策会把候选 OD 对在 TP、GS、Hold 之间重新分配，并引入 `sigma`、`CAA`、`OCR`、`E(finish)`、`p_next`、`lambda`、`beta` 等因子。

由于分单系统存在运力竞争、司机听单容量、全局匹配、时间片资源迁移等复杂因素，离线模拟很难完全复刻线上 AB。因此，`code/mock` 第一版不以“精确预测线上收益”为目标，而是以“上线前风险收敛和参数初选”为目标。

## 2. 离线模拟目标

离线模拟的核心目标是：

> 在上线前，用历史日志尽可能回答新版召回决策会把哪些 OD 对从 TP/GS/Hold 之间重新分配，以及这种重分配是否大概率满足“完单不负、接驾/ETP 改善”的业务目标。

更长期的理想态是：

> 输入一组 V1 新模型分和策略参数，离线系统自动复现 V0、回放 V1，生成 V0 -> V1 九宫格迁移矩阵，并围绕迁移格子与版本结果输出可扩展样本画像，用于解释策略腾挪、定位风险分层、辅助参数选择和线上 AB 归因。

具体拆成三类问题：

1. 决策正确性验证

	- 新公式是否按预期工作。

	- TP、GS、Hold 的分布是否合理。

	- 分城市、分时段、分供需档是否存在异常。

2. 收益方向预估

	- 相比 V0，新策略是否减少低胜率、长接驾、低价值播单。

	- 新策略是否把司机资源释放给更可能赢、更近、更稳定的订单。

	- 收益评估重点是方向和归因，不追求离线收益数的绝对精确。

3. 参数与上线风险收敛

	- 离线扫描 `lambda` 和 `beta`，找到若干 Pareto 候选点。

	- 判断调参后九宫格迁移会如何变化，过程指标会如何变化。

	- 明确哪些城市、时段、供需档风险较高。

	- 为 AB 实验提供初始参数、分层监控重点和降级判断依据。

## 3. 第一版定位

第一版建议优先做“策略分析/参数扫描工具”，而不是一开始就做重工程化的端到端回放框架。

原因：

- baseline 复现和新策略静态回放最快能服务 `lambda`、`beta` 调参。

- 召回项目当前最需要的是上线前判断“策略画像是否健康”。

- 端到端模拟最终完单会受到大量反事实偏差影响，早期投入产出比不如候选池和切换人群分析。

第一版应先跑通：

- V0 决策复现。

- V1 三路价值公式静态回放。

- V0 vs V1 的决策切换人群分析。

- 迁移画像和结果画像。

- 分层报表。

- `lambda`、`beta` 参数扫描。

## 4. 分层拆解

### 4.1 第 0 层：V0 复现

先不跑新策略，只复现线上 baseline，即 V0 的召回决策。

目标问题：

- 历史日志里能否还原线上当时的候选 OD 对。

- 能否还原 V0 的过滤规则：`max(BCAA, CCAA) < OCR`。

- TP、GS、Hold 比例是否与线上监控一致。

- 分城市、分时段、分供需档是否对得上。

这一层是后续所有模拟的可信度基础。V0 复现不了，后面的收益推断都不可靠。

产出：

- V0 决策明细表。

- V0 决策分布报表。

- 与线上监控的差异检查。

### 4.2 第 1 层：新策略静态决策回放

在同一批历史 OD 候选上，用 V1 决策公式替换 V0 规则。

简化后的价值公式：

```PlainText
value_TP   = sigma_TP * (1 - CAA) - lambda * p_next
value_GS   = sigma_GS * (1 - CAA)
value_hold = beta * (1 - OCR) * E(finish)
```

对每个候选 OD 对，计算三路价值，选择最大值对应的动作：

- `TP`

- `GS`

- `Hold`

目标问题：

- V0 播单、V1 Hold 的 OD 是哪些。

- V0 Hold、V1 播单的 OD 是哪些。

- TP/GS 入口变化有多大。

- 新策略是否主要过滤低 `sigma`、高接驾、高 `p_next` 的 OD。

- 新增播单是否集中在高 `sigma`、低 `CAA`、高 `OCR` 的订单。

产出：

- V1 决策明细表。

- V0 vs V1 决策迁移矩阵。

- 分层决策分布报表。

#### V0 到 V1 的九宫格迁移矩阵

召回决策本质上是把每个候选 OD 对分到三种结果之一：

- `TP`：TP 召回。

- `GS`：GS 召回。

- `Hold`：暂不播单，等待后续轮次。

因此可以用一个 3x3 九宫格描述样本从 V0 到 V1 的腾挪关系：

| V0 \\ V1 <br> | TP <br> | GS <br> | Hold <br> |
| --- | --- | --- | --- |
| TP <br> | TP -&gt; TP <br> | TP -&gt; GS <br> | TP -&gt; Hold <br> |
| GS <br> | GS -&gt; TP <br> | GS -&gt; GS <br> | GS -&gt; Hold <br> |
| Hold <br> | Hold -&gt; TP <br> | Hold -&gt; GS <br> | Hold -&gt; Hold <br> |

九宫格的核心用途不是只看总量，而是逐格解释“为什么发生迁移”以及“迁移是否健康”。

建议解读口径：

| 格子 <br> | 含义 <br> | 重点关注 <br> |
| --- | --- | --- |
| TP -&gt; TP <br> | 两版都认为应 TP 召回 <br> | 稳定 TP 主体，检查价值分是否健康 <br> |
| GS -&gt; GS <br> | 两版都认为应 GS 召回 <br> | 稳定 GS 主体，作为常规播单基准 <br> |
| Hold -&gt; Hold <br> | 两版都不播 <br> | 稳定 Hold 主体，检查是否确实低价值 <br> |
| TP -&gt; GS <br> | V1 将强触达降级为普通召回 <br> | 是否降低取消/接驾成本，是否损失 ETP <br> |
| GS -&gt; TP <br> | V1 将普通召回升级为 TP <br> | 是否命中高流失、高胜率订单，是否增加取消 <br> |
| TP -&gt; Hold <br> | V1 收紧原 TP <br> | 高风险格，重点看历史完单、ETA/接驾、`sigma` 和 `p_next` <br> |
| GS -&gt; Hold <br> | V1 收紧原 GS <br> | 重点看是否过滤低胜率、长接驾、低 OCR 订单 <br> |
| Hold -&gt; TP <br> | V1 新增 TP <br> | 高风险高机会格，重点看高 OCR、高 `sigma` 是否成立 <br> |
| Hold -&gt; GS <br> | V1 新增 GS <br> | 检查新增播单是否具备完单增量，不应只是扩张噪声 <br> |

在报表上，每个格子至少输出：

- 样本量与占比。

- 平均 `sigma_TP`、`sigma_GS`、`CAA`、`OCR`、`E(finish)`、`p_next`。

- 平均接驾距离/接驾时长、ETP 或 ETP 偏差。

- 历史应答率、取消率、完单率。

- 分城市、分时段、分供需档拆解。

#### 两类核心画像

后续所有召回策略对比都应包含两类画像：迁移画像和结果画像。

**迁移画像**围绕九宫格展开：

```PlainText
V0_action, V1_action -> 样本画像
```

它回答的是：哪些样本从 `GS -> Hold`、`Hold -> TP`、`TP -> GS` 等格子发生了腾挪，这些被腾挪的样本长什么样，迁移是否符合策略预期。

**结果画像**围绕单版本结果展开：

```PlainText
version, action -> 样本画像
```

它回答的是：V0 的 TP/GS/Hold 整体画像是什么，V1 的 TP/GS/Hold 整体画像是什么。比如 V1 的 TP 是否更短接驾、更高 `OCR`、更高 `sigma`；V1 的 Hold 是否更低胜率、更远、更高 `p_next`。

两类画像的关系：

| 画像类型 <br> | 维度 <br> | 回答的问题 <br> |
| --- | --- | --- |
| 迁移画像 <br> | `V0_action, V1_action` <br> | V1 相比 V0 动了谁，为什么动，迁移是否健康 <br> |
| 结果画像 <br> | `version, action` <br> | 每个版本最终 TP/GS/Hold 的样本结构是什么 <br> |

建议把画像指标分成三层，避免第一版无限堆字段：

| 层级 <br> | 定位 <br> | 示例指标 <br> |
| --- | --- | --- |
| 核心画像 <br> | 每次回放必出，用于判断策略健康 <br> | 样本量、城市、时段、供需档、接驾距离/时长、`sigma_TP`、`sigma_GS`、`CAA`、`OCR`、`E(finish)`、`p_next`、历史应答率、取消率、完单率 <br> |
| 诊断画像 <br> | 发现异常后展开，用于解释问题 <br> | 每单候选司机数、每司机候选订单数、司机听单压力、订单等待轮次、PK 输赢、后续轮次完单 <br> |
| 专题画像 <br> | 围绕具体业务问题补充 <br> | 司乘履约率、连环派比例、商家/品类/car_level、司机被其他订单占用 <br> |

第一版可以先固化核心画像，诊断画像和专题画像作为可扩展指标逐步接入。

### 4.3 第 2 层：结果标签评估

给历史样本接上真实结果标签，用于分析策略切换人群的风险画像。

建议标签：

- 是否完单。

- 是否应答。

- 是否取消。

- 接驾时长。

- ETP 或 ETP 偏差。

- 是否 PK 赢。

- 司机是否被其他订单占用。

- 后续轮次是否完单。

重点分析人群：

| 人群 <br> | 含义 <br> | 关注点 <br> |
| --- | --- | --- |
| keep play <br> | V0 播，V1 也播 <br> | 稳定主体是否保持健康 <br> |
| drop <br> | V0 播，V1 Hold <br> | 是否真是低胜率、低完单、长接驾 <br> |
| add <br> | V0 Hold，V1 播 <br> | 是否带来完单增量机会或风险 <br> |
| TP shift <br> | GS 变 TP 或 TP 变 GS <br> | 是否改善 ETP，是否增加取消 <br> |

注意：这里不能直接把历史结果当作严格反事实结论。例如，一个 OD 在历史上被播并完单，不代表新策略 Hold 后一定损失该完单，因为订单后续可能被其他司机或其他轮次完成。该层更适合做风险画像，而不是直接算真实收益。

产出：

- 决策切换人群画像。

- drop/add 人群结果标签对比。

- 高风险分层清单。

### 4.4 第 3 层：资源约束近似模拟

在静态回放基础上，加入轻量资源约束，观察候选池质量变化。

可先做近似版本：

- 按轮次或时间窗口聚合候选 OD。

- 对每个司机限制最多进入 N 个听单候选。

- 对每个订单限制召回候选数量。

- 根据新策略 value 排序，重算候选集合。

- 比较候选集合质量。

重点指标：

- 平均候选距离。

- 平均 `sigma`。

- 平均 `CAA`。

- 平均 `OCR`。

- 平均 `p_next`。

- 司机资源占用分布。

- 每单候选司机数。

- 每司机候选订单数。

这一层不追求完全复刻匹配结果，重点是判断召回候选池是否变得更健康。

产出：

- V0 vs V1 候选池质量对比。

- 资源约束后的决策分布。

- 司机/订单维度的候选压力分析。

### 4.5 第 4 层：参数扫描与上线推荐

对 `lambda` 和 `beta` 做单参数回放和网格扫描，形成上线候选参数。

参数含义：

- `lambda`：TP 全局机会成本系数，越大越抑制 TP。

- `beta`：Hold 激进度系数，越大越收紧召回，越小越放宽召回。

系统应支持两种模式：

| 模式 <br> | 输入 <br> | 输出 <br> |
| --- | --- | --- |
| 单参数回放 <br> | 一组 V1 模型分和一组 `lambda`、`beta` <br> | 九宫格迁移矩阵、迁移画像、结果画像 <br> |
| 参数扫描 <br> | 一组 V1 模型分和多组 `lambda`、`beta` <br> | 不同参数下的九宫格变化、过程指标变化、Pareto 候选点 <br> |

每组参数输出：

- TP、GS、Hold 比例。

- 相对 V0 的 drop/add 人群规模。

- 九宫格每个格子的样本量和占比。

- V1 结果画像相对 V0 的变化。

- drop 人群历史完单率、取消率、接驾时长。

- add 人群画像。

- 过程指标变化，例如接驾距离、履约率、连环派比例、候选司机数、司机听单压力等。

- 分城市、分时段、分供需档风险。

- 预估收益方向。

参数扫描重点不是只找一个最优点，而是回答：

- `beta` 调大后，`TP -> Hold`、`GS -> Hold` 是否增加。

- `beta` 调小后，`Hold -> TP`、`Hold -> GS` 是否增加。

- `lambda` 调大后，`TP -> GS`、`TP -> Hold` 是否增加。

- V1 的 TP 结果画像是否更短接驾、更高流失风险、更高胜率。

- V1 的 Hold 结果画像是否更低胜率、更远、更高机会成本。

- 迁移样本的过程指标是否朝预期方向变化。

最终不只输出一个“最佳参数”，而是输出候选参数集：

| 档位 <br> | 特征 <br> | 用途 <br> |
| --- | --- | --- |
| 保守档 <br> | 完单风险最低，接驾收益较小 <br> | 初始灰度或风险城市 <br> |
| 均衡档 <br> | 完单风险可控，接驾/ETP 收益预期较好 <br> | 推荐 AB 初始参数 <br> |
| 激进档 <br> | 接驾收益空间更大，完单风险偏高 <br> | 离线观察或小流量试探 <br> |

产出：

- 参数扫描报表。

- Pareto 候选点。

- 推荐 AB 初始参数。

- 分层风险说明。

## 5. 第一版交付物建议

### 5.1 第一版代码边界

第一版代码先定位为“画像报告生成器”，核心能力是：

> 给定一张 Hive SQL 查询结果宽表，包含全量 OD 候选样本、两版召回结果和一批待挖掘特征，自动生成 Markdown 画像报告。

第一版先假设输入表已经直接给出两版召回结果：

- `base_action`：基准版本召回结果，通常是 V0。

- `target_action`：目标版本召回结果，可以是 V1，也可以是 V1.1、V1.2 等调参版本。

其中 action 的取值统一为：

- `TP`

- `GS`

- `Hold`

第一版不在代码里计算 V1 的三路价值，也不负责根据 `lambda`、`beta` 重算 action。也就是说，第一版暂不实现：

```PlainText
value_TP   = sigma_TP * (1 - CAA) - lambda * p_next
value_GS   = sigma_GS * (1 - CAA)
value_hold = beta * (1 - OCR) * E(finish)
```

而是先把“给定两版 action 后如何自动做九宫格迁移、迁移画像、结果画像、差异挖掘和 Markdown 报告”这件事做稳定。

这样设计的好处是：

- 第一版数据依赖更清晰，只要 Hive 查询结果里有两版 action 就能跑。

- 后续支持 V1.1、V1.2、V1.3 时，只需要把 `target_action` 换成对应版本列。

- 画像能力可以复用到不同模型版本、不同参数版本、不同城市策略版本的对比。

- 后续再扩展“回放模式”，用模型分和参数在代码里重算 action。

### 5.2 输入数据形态

输入数据逻辑上来自 Hive SQL 查询结果。建议由 SQL 先产出一张 OD 候选级宽表，每行是一条候选 OD 样本。

最小字段结构：

```PlainText
candidate_id
order_id
driver_id
base_action
target_action
feature columns...
```

其中：

- `candidate_id`：候选 OD 唯一标识，如没有现成字段，可由订单、司机、轮次、时间等字段组合生成。

- `order_id`：订单标识。

- `driver_id`：司机标识。

- `base_action`：基准版本召回结果。

- `target_action`：目标版本召回结果。

- `feature columns`：待挖掘画像特征，可以包含数值型、类别型、布尔型。

如果后续同时比较多个目标版本，可以在宽表中保留多列 action：

```PlainText
v0_action
v1_action
v1_1_action
v1_2_action
v1_3_action
```

报告生成时通过配置选择：

```PlainText
base_action_col = v0_action
target_action_col = v1_2_action
base_version = V0
target_version = V1.2
```

### 5.3 特征配置化

画像特征不应写死在代码里，而应通过配置声明。这样后续新增接驾距离、司乘履约率、连环派比例、商家维度等指标时，只需要改配置，不需要改主逻辑。

示例配置：

```YAML
id_cols:
    - candidate_id
    - order_id
    - driver_id

action_cols:
  base: v0_action
  target: v1_action

versions:
  base: V0
  target: V1

numeric_features:
    - pickup_distance
    - pickup_duration
    - eta
    - sigma_tp
    - sigma_gs
    - caa
    - ocr
    - p_next

categorical_features:
    - city_id
    - time_bucket
    - supply_demand_level
    - car_level

boolean_features:
    - is_chain_dispatch
    - is_pk_win
    - is_finish
```

不同类型特征的默认聚合口径：

| 特征类型 <br> | 默认画像指标 <br> |
| --- | --- |
| 数值型 <br> | count、mean、std、p25、p50、p75、p90、missing_rate <br> |
| 类别型 <br> | top value、top share、各类别 count/share、missing_rate <br> |
| 布尔型 <br> | true_count、true_rate、false_count、missing_rate <br> |

### 5.4 SQL 与 Python 分工

第一版采用 SQL + Python 结合的方式，但职责分清。

Hive SQL 负责：

- 从线上/离线宽表中取全量 OD 候选集。

- join 必要特征表、召回结果表、履约/结果标签表。

- 做分区过滤、样本过滤、必要的数据清洗。

- 产出画像输入宽表。

- 在数据量很大时，承担部分粗聚合或抽样。

Python 负责：

- 读取 Hive SQL 查询结果。

- 生成 V0 -> V1 九宫格迁移矩阵。

- 计算迁移画像。

- 计算结果画像。

- 自动发现差异最大的特征。

- 生成 Markdown 报告。

- 后续支持多版本 action 对比和参数扫描。

不建议第一版把所有画像逻辑写在 SQL 里。原因是：

- 九宫格、分位数、lift、Top 差异特征、Markdown 报告，用 Python 表达更清楚。

- 特征配置化、多版本循环、报告模板化在 Python 中更容易维护。

- SQL 更适合产出输入宽表，而不是承载复杂画像报告逻辑。

如果后续数据量过大，可以把部分聚合下推到 Hive：

```PlainText
Hive SQL 做九宫格基础聚合 / 分层聚合
Python 汇总聚合结果并生成报告
```

因此整体原则是：

> 数据准备和大规模聚合用 Hive SQL 管；画像口径、差异挖掘和报告生成用 Python 管。

### 5.5 自动差异挖掘

除了固定画像聚合，第一版还应支持自动发现差异最大的特征。

对数值型特征：

- 比较目标格子 vs 全量样本的均值差、分位数差。

- 比较目标格子 vs 稳定格子的均值差、分位数差。

- 输出绝对差、相对差、标准化差异。

对类别型特征：

- 比较目标格子中各类别占比 vs 全量占比。

- 输出占比差和 lift。

- 找出在某个迁移格子中过度集中的城市、时段、供需档、car_level 等。

对布尔型特征：

- 比较目标格子 true_rate vs 全量 true_rate。

- 输出 rate 差值和 lift。

- 适合挖掘连环派比例、是否完单、是否 PK 赢、是否履约等指标。

示例输出：

```PlainText
GS -> Hold 的显著画像：
- pickup_distance 均值高于全量 18.4%
- sigma_gs 均值低于 GS -> GS 12.1%
- city_id=xxx 占比 lift 2.3x
- is_chain_dispatch true_rate 高于全量 6.2pp
```

### 5.6 Markdown 报告结构

第一版报告输出为 Markdown。建议结构如下：

1. 样本概览

	- 样本总量。

	- 订单数、司机数。

	- base/target 版本名。

	- action 合法性检查。

2. V0/V1 结果分布对比

	- V0 下 TP/GS/Hold 数量和占比。

	- V1 下 TP/GS/Hold 数量和占比。

	- V1 相比 V0 的变化。

3. V0 -> V1 九宫格迁移矩阵

	- 9 个格子的样本数。

	- 9 个格子的样本占比。

	- 重点迁移格子标记。

4. 迁移画像

	- 每个迁移格子的核心画像。

	- 高风险格子重点展开，如 `TP -> Hold`、`GS -> Hold`。

	- 高机会格子重点展开，如 `Hold -> TP`、`Hold -> GS`。

5. 结果画像

	- V0 的 TP/GS/Hold 画像。

	- V1 的 TP/GS/Hold 画像。

	- V1 相比 V0 的结果结构变化。

6. 自动差异挖掘 TopN

	- 每个重点迁移格子的 Top 差异数值特征。

	- 每个重点迁移格子的 Top 差异类别特征。

	- 每个重点迁移格子的 Top 差异布尔特征。

7. 分层拆解

	- 城市。

	- 时段。

	- 供需档。

	- car_level 或其他配置维度。

8. 风险与结论摘要

	- 哪些迁移健康。

	- 哪些迁移风险高。

	- 哪些特征最能解释策略变化。

	- 后续需要补充验证的问题。

### 5.7 后续回放模式

第一版先做画像模式：

```PlainText
输入：base_action + target_action + 画像特征
输出：九宫格迁移矩阵 + 迁移画像 + 结果画像 + Markdown 报告
```

第二阶段再扩展回放模式：

```PlainText
输入：base_action + V1 模型分 + lambda/beta 参数 + 画像特征
过程：根据 value_TP/value_GS/value_hold 重算 target_action
输出：不同参数版本下的九宫格迁移、画像变化、过程指标变化
```

这样可以支持：

- V1 vs V1.1

- V1.1 vs V1.2

- 不同 `lambda` / `beta` 参数版本对比

- 不同模型版本对比

- 不同城市策略版本对比
