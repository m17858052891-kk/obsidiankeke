# 一、需求背景（*）

目前商家冷启动，通过人工配置的方式进行。

1、运营邮件和dc群通知策略同学

2、策略同学下载开城list，运行脚本，生成冷启动参数

3、手动导入线上配置平台

4、冷启动到期，手动下掉配置

过程环节多，容易出错；单点支持，遇到同学请假或者疏忽，容易漏赔。

# 二、需求类型归纳（*）

* 已有能力，使用有问题/有风险，要解决问题

# 三、需求收益判断（*）

1. 减少出错，24年H1出现过两次配置问题（漏配置、单点支持导致延迟配置）

2. 减少人力消耗

# 四、需求说明和功能点（*）

## 需求说明：

1. 算法同学每周产出所有城市维度冷启动参数

2. 交易系统自动读取新开城商家标识，获取该城市冷启动参数

3. 自动对新开城商家执行冷启动策略14天

4. 可根据运营同学要求，手动操作，中途停止冷启动策略

# 五、需求通用属性（*）

1. 覆盖范围:

   1. HH商家开城配置，涉及所有开城的流量端。

2. 前置依赖：

   1. 无

 

# 六、效果评估方案

* 预期收益：

   * 提高人效

   * 减少人工出错的case
