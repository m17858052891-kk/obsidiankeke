### 背景

- 优化目标：对自营运力最大化**司机应收**、提升自营长单举手率、完单占(大盘)比以及自营的长单绝对PK胜率

- 约束条件：自营GMV

- 策略场景：小猪分单矩阵内决策司机对订单的偏好顺序  

##### 一期策略背景

1\. 小猪司机在自营的日均做单数较低的情况下，自营优先派高IPH订单不如优先争抢长单以达到对自营司机的锁定和长期留存，保持B侧运力占用；

当前自营司机日均做单数3.4单(最近一个月)，假设完单数不变，则尽可能给司机长单在当前竞争态下比司机的IPH

2\. 在聚合平台模式下自营优先把运力分配给长单争抢有利于自营cp的交易效率 -- GMV提升，因为相比短单，长单司机分成更高，毛利更高，适当放弃短单对自营有长期利好.

在58个阳关强势的城市，自营的长单举手率在5公里以上和阳光存在较大的gap，也就是说即使在长里程类型订单里自营的PK胜率不差于阳光，但是参与少，e.g. 自营参与30次胜出20次，胜率67%，而阳光参与100次，胜出50次，胜率50%.

当长单举手次数提升时，自营PK胜率会下跌，因为样本积累够多才能说明真实PK能力；但是通过积累更多的长单参与，长期会提升自营的PK胜率，做到**举手率和PK胜率同时比大三方高**的终态.

策略上的抓手则是调整当前的分单排序，

一方面，目前自营的GS分单看重IPH效率，所以司机视角对订单极大程度上考虑“里程应收”，而不是以订单gmv应收为主；

另一方面，在三方优势较大的城市，三方天然看重大金额长单，因此在司机对大单履约能力较好的基础上，三方积累越来越多的长单类型数据，在PK模型打分里也越来越占优势，造成马太效应，

后果是自营天然被挤到了短单生态层，只能和小cp挤占短单份额，而长单的生态层被个别大三方抢占，且自营司机难以积累大单的PK完单数据(参与率)，造成自营收到的模型打分越来越差，相当于在平台生态上，自营完全失去和三方竞争大单的机会.

为了适应PK模型打分的约束or偏好，小猪侧的GS分单需要强化对长单高应收订单的偏好权重.

##### 实验预期

通过以司机应收为司机对乘客的打分顺序调整司机对长单的举手率，进一步提升自营长单的PK参与率、PK胜率和完单占比.

在司机应收为优化目标的基础上，提升自营GMV效率指标

预期在实验城市自营的绝对PK胜率相对提升2%，自营的长单占大盘完单占比相对提升2%；自营GMV相对提升1%.

### 策略设计

#### 策略逻辑

自营现有实时单品类为一口价和特快，运力分配出现的场景可分为以下两类：

- 同流量端发单，不同乘客(品类)订单的GPH相等，且两个品类都能匹配上同一司机(共享分单矩阵)，e.g. A订单一口价，B订单特快，共享司机D

- 不同流量端发单，同一乘客勾选的自营订单GPH相等，对于分单矩阵中的共享司机决策把运力给到哪个订单

第一类场景(更简单的两个订单都是单勾)主要考虑在运力有限的情况下，通过分配运力给不同品类订单来提升期望GPH，第二类场景在前一类场景的基础上，还要考虑订单来源不同，在自营推选运力后，提升PK阶段的期望GPH.

因此对于运力分配策略的场景，共同点都是订单共享司机，需要放在同一分单矩阵中进行，而不是分层实现各品类播单.

#### 方案

考虑到目前的分单流程分为(自营)分单匹配和公平PK决策，运力分配将司机收入效率：期望GPH在gs分单矩阵内部完成，不额外的在匹配和PK两个模块以外进行.

现有的gs匹配中，司机对乘客打分为GPH = GMV / (T\_接 + T\_送)，考虑到最大化GPH的目标不变，将GPH转化为得到它的期望值：

GPH = GMV \* (1 - P\_应答后取消) \* P\_渠道pk胜率/ (T\_接 + T\_送)

即从司乘匹配的应答情况、订单渠道等方面考虑运力分配给哪个订单能够最大化GPH，且最小化取消率和PK失败的风险.

同时，在订单价值侧与司机价值拉齐([V1版价值线上开发](https://cooper.didichuxing.com/cooper_gateway/metis/v1/knowledge/2199610335356/wikiFile/860100196.html?taskId=2199613477654))；

渠道PK胜率可以不作为v1方案的一个乘子，

- 一是考虑PK模型仍在迭代中，对期望价值的打分会造成偏差；

- 二是打分可以对渠道、订单类型调权改变排序，这部分有待优化.

        end

    -- 小猪和(滴滴或三方)pk时，三方赢数量
    count(

            and (
                third_flag = 1
                or didi_flag = 1
            ) then 1
            else null
        end
    ) as didi_win_num,

    count(

            when win_cp = 2 --小猪获胜
            and hxz_flag = 1
            and (
                third_flag = 1
                or didi_flag = 1
            ) then 1
            else null
        end
    ) as hxz_win_num -- 三方和小猪或自营pk时，小猪赢数量

        a.round_token        
),
-- 总数  订单、轮次维度有效举手信息
didi_info as (
    select
        *,
        1 as didi_flag
    from
        effect_all_info_by_cp
    where
        cpid = 1
),
-- 总数  有效的滴滴举手
third_info as (
    select
        *,
        1 as third_flag
    from
        effect_all_info_by_cp
    where
        cpid = 3
),
-- 总数  有效的三方举手
hxz_info as (
    select
        *,
        1 as hxz_flag
    from
        effect_all_info_by_cp
    where
        cpid = 2
),
-- 总数  有效的花小猪举手
pked_info_dis as (
    select
        e.orderid as orderid,
        e.round_token as round_token,
        e.win_dis as win_dis,
        e.dis as tend_dis,
        e.win_cp as win_cp,
        third_flag,
        hxz_flag,
        didi_flag
    from
        effect_all_info e
        left join didi_info d on e.orderid = d.orderid
        and e.round_token = d.round_token
        left join third_info t on e.orderid = t.orderid
        and e.round_token = t.round_token
        left join hxz_info h on e.orderid = h.orderid
        and e.round_token = h.round_token -- where
        -- e.win_cp_num = 1
) -- 总数111697  各轮次三方举手情况
select
    count(
        case
            when hxz_flag = 1 --小猪举手 -- 比之前三方视角的版本少很多是因为小猪参与举手的多勾量不大
            and (
                didi_flag = 1
                or third_flag = 1
            ) then 1
            else null
        end
    ) as both_participated,
    --小猪和（滴滴或三方）任一方参加举手数量
    count(
        case
            when win_cp = 3 --三方获胜
            and hxz_flag = 1
            and (
                third_flag = 1 -- third
                or didi_flag = 1
            ) then 1
            else null
        end
    ) as third_win_num,
    -- 小猪和(滴滴或三方)pk时，三方赢数量
    count(
        case
            when win_cp = 1 --滴滴获胜
            and hxz_flag = 1
            and (
                third_flag = 1
                or didi_flag = 1
            ) then 1
            else null
        end
    ) as didi_win_num,
    -- 三方和小猪或自营pk时，滴滴赢数量
    count(
        case
            when win_cp = 2 --小猪获胜
            and hxz_flag = 1
            and (
                third_flag = 1
                or didi_flag = 1
            ) then 1
            else null
        end
    ) as hxz_win_num -- 三方和小猪或自营pk时，小猪赢数量
from
    pked_info_dis;
