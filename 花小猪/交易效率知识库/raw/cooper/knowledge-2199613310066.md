# 一、背景

根据[聚合日报报表](http://bigdata.xiaojukeji.com/datae/#/homepage/report-info?type=reportView&reportId=152552&source=market&isContainMenu=0)的4.14的数据，应答后乘客取消率为15.93%，应答后司机取消率为1.47%，改派率为5.24%。其中改派率虽然不会直接造成完单的折损，但是会增加应答后乘客取消率，进而降低完单率。因此，降低乘客等待过程中的取消，应该从乘客、司机两方面进行考虑，会有更大的收益。

# 二、方向节奏

降取消的最终目的是为了促完单，有些订单是乘客或司机单方面偏向取消，有些订单是乘客和司机双方都偏向取消的，因此可以判断订单的取消情况，再进一步分配该订单在司机乘客侧的补贴比例。

不过线上已经存在了b侧的接驾补贴，但是c侧还没有，因此在此之前，可以先验证c侧接驾补贴的效果。

考虑到目前补贴率有限，对c侧取消率高的订单进行补贴，会获得更大的收益，可先对这部分订单进行实验，再进一步扩大覆盖面。

因此整体节奏如下：

- 选取取消率较高，覆盖面较小的一部分订单，发放补贴进行实验

- 扩大补贴订单覆盖面，订单的补贴额和取消率呈正相关，提高大盘完单GMV

- 结合b侧补贴，从平台视角发放补贴，避免因单侧问题取消的订单，在b侧和c侧重复发放补贴。实现在维持GMV增量的前提下，降低平台补贴

目前先对第一步的节奏进行展开探讨

# 三、c侧接驾愿等

## 目标

降低应答后乘客取消率，提高完单率，提高GMV

约束：补贴率0.1%，roi>2

## 补贴规则

在补贴率的约束下，对 取消率更高、接驾距离更远、当单GMV更大的订单 补贴更多，会获得更高的roi

综合考虑下，限定 接驾距离>=2.5km 和 取消率>0.65 的订单才可以发放补贴，补贴金额 = min( max（**gmv\*driver_start_dis/50000**，0.5），5）

### 1. 覆盖面限制

通过 接驾距离 和 取消率 筛选出发放接驾补贴的订单

- 接驾距离、订单距离、预估价格等影响因素都与订单的【应答后乘客取消率】呈现较强的相关关系，这些因素都被包括在了模型拟合的过程中，可以认为 模型预测取消率 可以较大程度考虑这些因素。

- 订单的预估取消率高的订单才是优先发放补贴的订单，因此 模型预测取消率 是实现目标需要考虑的因素

- 接驾距离 虽然被 模型预测取消率 考虑在内了，但是初期的产品定位是 **接驾距离远** 才发放补贴，这有利于培养心智，因此 接驾距离 也是需要考虑的因素

结合以下的相关数据，限制 接驾距离>=2.5km（可配） 和 取消率>0.65（可配） 的订单发放补贴，这部分订单占应答订单的2%，应答后乘客取消率为30%

### 2. 补贴金额：

补贴金额应该与 本单GMV 和 接驾距离 呈现正相关关系

对通过筛选的订单，补贴金额 = **gmv\*driver_start_dis/ λ** ，其中gmv单位：元，driver_start_dis单位：米，每单补贴金额上限为5元，下限为0.5元

根据3.21-3.27全国一周数据，调整λ的取值获得以下两种补贴方式

- 补贴率约为0.05%，λ = 50000，部分订单的gmv和补贴金融展示如下

#### **优化点**

- ①的漏斗中，覆盖面仅为2%，目的是为了在小覆盖面下实验可以获得更高的收益。如后续增大覆盖面，大盘的完单增量也会增加

- ②的漏斗中，更新为应答后乘客取消模型，订单预测的准确率会有所增加

- ③的漏斗中，取消率的下降幅度依赖补贴金额和产品形态，现阶段为人为强假设，上线后可能会带来更高的收益。

展开源码

```PlainText
select
    gp,
    count(*),
    count(if(cancel_type = 2, order_id, null)) / count(if(source_type<>2,order_id,null))
from(
        select
            order_id,
            driver_id,
            is_td_cancel,
            cancel_type,
            case when int(est_price_amt / 5) + 1>20 then 20 else int(est_price_amt / 5) + 1 end as gp,
            is_td_finish,
            start_dest_dis,
            source_type,
            driver_start_dis
        from
            kflower_dw.dwd_kf_trd_order_base_di
        where
            dt between '2022-03-21'
            and '2022-03-27'
            and is_td_answer=1
            and call_time is not null
            and call_time <> '0000-00-00 00:00:00'
            and (
                is_short_book_flag = 0
                or is_short_book_flag is null
            )
            and order_type <> 1
            and driver_start_dis>=2500
    )t
    group by gp
    order by gp
```
