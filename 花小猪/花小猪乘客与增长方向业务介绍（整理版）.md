# 花小猪乘客与增长方向业务介绍（整理版）

> [!abstract] 一句话定位
> 乘客与增长方向覆盖乘客从端外触达、登端、冒泡、发单、完单到长期留存的全过程；核心是在乘客体验、商家生态和平台控制权等约束下，提高平台或商家的资源效率，最终推动平台长期规模增长。

## 1. 先回答几个直观问题

### 1.1 价格是怎么确定的？

乘客看到的最终价格和展示形态，并非只由基础定价决定，还会受到以下因素共同影响：

- 商家或品类的基础价格；
- 前置优惠券；
- 平台呼返等实时补贴；
- 幸运盒子、特价盒子等产品形态；
- 展示价格取整规则；
- 同价车型合并、车型折叠、盒子扩展等表单规则；
- 平台联合决策对折扣组合和默勾车型范围的选择。

平台呼返采用“折上折”方式。例如：GMV 为 100 元，前置券 9 折，平台呼返 8 折，则最终实付为 `100 × 0.9 × 0.8 = 72` 元，平台呼返补贴为 `100 × 0.9 × (1 - 0.8) = 18` 元。

### 1.2 为什么有时能领到券，有时没有？

券和优惠并非随机发放。不同策略会根据人群、场景、实时行为、预算和业务目标决定是否发放以及发放力度。例如：

- 新客天降红包：面向未完单注册用户，促进首单；
- 流失召回红包：面向长期未完单但再次登端的用户；
- 竞争用户红包：面向存在双冒、双呼等跨平台行为的用户；
- 主题营销：通过弹窗、Banner、营销会场等引导领券；
- 套餐：通过多张券锁定未来需求、促进提频和留存。

因此，是否有券通常与用户所处生命周期、历史行为、实时场景、对补贴的敏感程度、预算约束及运营活动有关。原材料不支持反推出一套可由用户稳定“刷券”的确定规则。

### 1.3 没有券时为什么偶尔也会优惠？

优惠不只来自用户主动领取的券。冒泡和呼叫阶段还可能触发幸运盒子精细化定价、特价盒子呼返、自营呼返、宏鹄呼返等实时 C 补。它们可能直接反映在最终实付价中，因此用户没有显式领券，也可能看到优惠。

### 1.4 营销电话和短信是随机发送的吗？

通常不是。增长策略会利用用户画像、场景标签和需求预测识别目标人群与潜在需求，再结合频控、渠道成本、用户授权状态和预算进行触达。例如，可依据规律性出行行为预测 T+1 需求，并在需求发生前的合适窗口触达。

### 1.5 为什么表单按价格升序排列？

常规规则是按车型真实实付价从低到高排列，以强化低价感知并提高信息传递效率。但置顶推荐、顺风车导流、乘客拉黑车型，以及幸运盒子或特价盒子置顶等情况会例外。

## 2. 业务背景

### 2.1 聚合平台的相关用户价值

- 乘客：更便宜、等等就能走、不生气；
- 司机：全职赚更多、接单更自由；
- 商家：更强赋能、更好的营商环境。

### 2.2 乘客打车全流程

```mermaid
flowchart LR
    A["端外触达"] --> B["登端"]
    B --> C["浏览权益"]
    C --> D["冒泡"]
    D --> E["呼叫"]
    E --> F["加勾 / 反勾"]
    F --> G["等待应答"]
    G --> H["等待接驾"]
    H --> I["行程中"]
    I --> J["行程结束"]
```

#### 端外触达

| 渠道 | 主要限制或特点 |
|---|---|
| 外呼 | 主动发送，有频控，成本较高 |
| 短信 | 主动发送，有频控，成本中等 |
| App Push | 需用户打开权限；营销型消息有频控 |
| 灵动岛 / 实时活动 | 需用户打开权限后展示 |
| 小程序订阅消息 | 需用户订阅模板 |
| 小程序客服消息 | 用户发送消息后 48 小时内可发送 5 条 |
| 公众号模板消息 | 需用户关注公众号 |
| 公众号客服消息 | 用户发消息后 48 小时内可发送 5 条 |
| 公众号群发消息 | 需用户关注公众号，且有频控 |
| 企微 / 社群 | 主动触达，有相应频控或运营规则 |

相关策略包括需求预测，以及 ACTI（触达、补贴与交易）多抓手联合决策。除此之外，用户还可能通过端外广告、裂变、地推等方式获知品牌。

#### 登端与权益

首页资源位包括开屏、弹窗、右下角 icon、情感沟通位、金刚位、Super Banner、核心运营区域、任务/会员/套餐、兜底 Banner 等。资源位与策略抓手不是固定绑定关系，会随运营节奏和策略表现调整。

除了首页，冒泡页有呼叫牵引位，行程中送驾页可能有砍车费资源位，行程结束页也有相应资源位。

#### 冒泡与呼叫

该阶段主要承载：

- 表单策略：车型展示、排序、默勾、折叠等；
- 商家策略：自营或宏鹄等商家侧策略；
- 增长策略：套餐等乘客补贴抓手。

部分场景的快车 Tab 会展示顺风车品类，但默认不推荐勾选。乘客对顺风车的加勾或反勾行为不计入常规默勾接受度、加勾率或反勾率。

## 3. 乘客生命周期

| 一级分层 | 二级分层 | 三级分层 | 定义 |
|---|---|---|---|
| 新客 | 纯新注册 | — | `dt` 日注册 |
| 新客 | 存量注册、未首单 | — | `dt-1` 日及以前注册，且截至 `dt-1` 未首单 |
| 老客 | 存量注册、已首单 | 新客成长期 | 首单在近 14 天，即 `[dt-13, dt-1]` |
| 老客 | 存量注册、已首单 | 低活跃 | 首单在近 14 天外，近 28 天完单 1～4 单 |
| 老客 | 存量注册、已首单 | 中活跃 | 首单在近 14 天外，近 28 天完单大于 4 且不超过 12 单 |
| 老客 | 存量注册、已首单 | 高活跃 | 首单在近 14 天外，近 28 天完单超过 12 单 |
| 老客 | 沉默用户 | 沉默未召回 | 首单在近 14 天外，近 28～90 天内有完单，`dt` 日未完单 |
| 老客 | 沉默用户 | 沉默已召回 | 同上，但 `dt` 日完单；`dt` 为召回完单日 |
| 老客 | 流失用户 | 流失未召回 | 首单在近 14 天外，超过 90 天未完单，`dt` 日未完单 |
| 老客 | 流失用户 | 流失已召回 | 同上，但 `dt` 日完单；`dt` 为召回完单日 |

> [!note] 口径说明
> 原文的区间表达有少量方向性歧义。本表依据自然语言含义重述：沉默为最近一次完单距今约 28～90 天，流失为超过 90 天未完单。正式取数前仍应以生产标签 SQL 或最新口径文档为准。

## 4. 三个子方向总览

| 子方向 | 主要业务方 | 主要目标 | 关键约束 | 作用范围 | 代表策略 |
|---|---|---|---|---|---|
| 表单策略 | 平台供需 | 平台规模增长、平台长期完单 | C 补资源、乘客体验、商家生态、平台控制权 | 冒泡页 | 价格取整、同价车型合并、平台联合决策 |
| 增长策略 | 平台流量、平台供需 | 乘客侧增长、平台呼叫、新流人群完单 | C 补资源、平台规模 | 端外、首页 | 基于需求预测的外呼、天降红包 |
| 商家策略 | 自营供需、商家供需 | 商家侧增长、自营或宏鹄商家完单 | C 补资源、商家生态、平台规模 | 冒泡页 | 自营呼返、宏鹄品牌优惠 |

推荐理解顺序：**增长策略 → 商家策略 → 表单策略**。

## 5. 表单策略

### 5.1 核心问题

表单策略优化冒泡页这一关键流量分发场景。它不是单纯追求短期转化，而是在多方权衡下实现长期规模增长：

- 乘客低价诉求与交易体验之间的权衡；
- 乘客短期需求增长与长期留存之间的权衡；
- 乘客利益与司机利益之间的权衡；
- 商家效率与商家生态之间的权衡。

主要约束为：

- 乘客体验：默勾接受度、计费规则认可度；
- 商家生态：公平性、流量稳定性、规则透明度；
- 平台控制权：平台品类份额和流量分配能力。

### 5.2 表单规则

表单规则分为两类：

- **表单编排**：车型和品类以什么顺序、怎样的价格粒度展示；
- **表单收放**：哪些车型应该展示、折叠或纳入盒子。

| 规则 | 当前逻辑摘要 | 目标 / 约束 |
|---|---|---|
| 车型排序与默勾 | 默认按真实实付价升序；置顶推荐、顺风车导流、乘客拉黑车型除外 | 最大化完单；约束默勾接受度及商家公平 |
| 置顶推荐 | 幸运盒子或特价盒子为最低价时置顶；同价时幸运盒子优先 | 提升平台对表单流量分配的控制；约束大盘完单不负 |
| 展示价格取整 | 一口价品类向上取整到角；实时计价品类向下取整到元；已支持多种场景能力 | 降低展示价格方差，提高对较高价格的接受度和呼叫车型数；约束计费规则认可度 |
| 同价车型合并 | 相同计价模式且展示价格相同的车型合并为一行；盒子不与其他车型合并 | 提升有效信息传递效率；约束计费规则认可度 |
| 无车折叠 | 可控运力：30 分钟内中心及一圈格子在线司机数不大于 0；非可控运力：呼叫大于 2 且举手数为 0 | 提高首屏价格集中度和 CR，避免低价僵尸品牌占用曝光；约束商家公平与透明度 |
| 价格折叠 | 强势城市按应付价或实付价与特价盒子的关系折叠；其他城市未开启 | 防止盒外通过定价或 C 补形成价格倒挂；约束商家经营意愿、ECR、CR |
| 盒子扩展 | 被折叠品牌若实付价低于特价盒子且不在盒内，则扩入盒子；触发后改名“超值车”并替换 icon | 将更低价的折叠车型纳入盒子并承接默勾，以提升 CR |

盒子扩展有 CP 数量兜底：表单 CP 数不少于 5；若折叠后不足 5 个，则候选 CP 按价格升序依次折叠，以保留足够展示供给。

### 5.3 表单抓手

#### 平台联合决策

全称为“平台定价、补贴与流量分发联合决策”。它通过算法选择表单默勾价格区间，以提升平台完单规模：

- 最低价端：幸运盒子（动态展现）或特价盒子；
- 最高价端：价格锚点；
- 策略动作：幸运盒子展示与精细化定价、特价盒子呼返、价格锚点。

线上大致流程：

1. 按候选折扣组合生成价格列表；
2. 折扣组合剪枝，过滤不满足幸运盒子定价要求的组合，包括 B-CPM、B 总价、幸运盒子必须最低价、需低于滴滴快车某折扣、幸运盒子累计应答率等约束；
3. 按城市累计应答率阈值对默勾组合剪枝；
4. 对“折扣组合 × 默勾组合”计算得分；
5. 选择得分最高的折扣和默勾组合。

决策依赖三个核心模型：

| 模型 | 作用 |
|---|---|
| ECR | 预估不同折扣组合下的冒泡发单率 |
| DSAR | 预估不同默勾车型组合下的默勾接受度 |
| acc_CR | 预估不同默勾发单组合最终完单的概率 |

现状：V3 曾全量上线，V4 迭代方向包括端到端 BCR 预测、多目标权重优化，以及补贴率与幸运盒子水位的双约束联动，以兼顾短期完单、长期目标和业务响应速度。

#### 供需熔断

供需熔断以冒泡为粒度，分别按城市和格子统计发单量与应答率。当任一维度同时满足“发单量高于阈值、应答率低于阈值”时触发，触发后将盒子呼返、自营呼返、宏鹄呼返等实时 C 补统一调整为 100 折。

目标是在差供需场景减少无效补贴与无效呼叫。原材料记录该策略因对冒泡及用户留存影响较大而下线。

#### 实时预算控制

将一天切成半小时片段，持续收集：

- 已发生时间片的实际 COST 和 GMV；
- 历史基期离线仿真的各时间片 COST 和 GMV。

每个时间片根据最新偏差调整下一时间片补贴率，使全天实际花费逼近规划补贴率。实现过 PID、RASR、MPC 等算法，其中 RASR-OPT 和 MPC 表现较好。原材料记录该能力当前已下线，待 V4 上线后继续迭代。

#### 无车赔

通过“等待承诺 + 超时赔付”管理乘客的确定性预期。按预估应答时长分档，遵循“等待越久、赔付越高”的规则。主要面向新流人群和竞争人群的日常运营使用。

## 6. 增长策略

### 6.1 核心问题

增长策略聚焦平台约束下的 C 端增长。出行需求在 ODT（起点、终点、时间）上高度异质，乘客对天降红包、营销会场、套餐等抓手的敏感程度也不同，因此精细化补贴存在巨大的优化空间，同时也带来较高复杂度。

增长策略主要追求两类提效：

- 钱效：精准识别人群、场景和需求；提高单抓手钱效；在总预算内优化多抓手预算分配；
- 人效：沉淀可复用的算法和工程能力。

### 6.2 算法中台

算法中台包括用户画像、场景标签和需求预测。业务上解决“识别谁、何种场景、何种需求”；工程上主要承载不依赖用户实时行为、可按天调度产出的算法资产。

#### 用户画像

| 类型 | 项目 | 识别目标 | 主要方案 |
|---|---|---|---|
| 规则类 | 竞争用户 | 同时在花小猪与竞品平台活跃，可能存在比价或提速诉求 | 基于一定周期内行业冒泡、双冒冒泡、端内冒泡数设阈值 |
| 规则类 | 时间敏感型 | 容易因等待过久而取消的用户，分应答前和应答后 | 综合呼叫数、高峰呼叫占比、长单占比、竞争行为设阈值 |
| 模型类 | 学生人群 | 识别未认证但认证大概率通过的潜在学生 | XGB + 动态阈值 + 增量更新 |
| 模型类 | 价格敏感型（天降红包） | 识别对天降红包补贴敏感的用户 | RCT 数据 + 历史行为 + EMH/ECR，计算各折扣 ROI |
| 模型类 | 价格敏感型（特价盒子呼返） | 识别对盒子呼返敏感的用户 | RCT 数据 + 历史行为 + DR-CFR/ECR，计算各折扣 ROI |
| 模型类 | 营销敏感型 | 判断营销曝光是否带来额外花费和呼叫 | DR-CFR Uplift + ZILN Cost，对近 90 天登端用户建模 |
| 模型类 | 裂变敏感型 | 识别用户对助力类裂变抓手的偏好或厌恶 | 待开发 |

#### 场景标签

- 冒泡场景标签：以每次冒泡为粒度，依据起终点 POI 类型，通过场景矩阵映射通勤、商务、休闲娱乐、大型枢纽等一级和二级场景；
- 呼叫场景标签：以每次呼叫订单为粒度，逻辑与冒泡场景标签 V5 一致。

#### 需求预测

| 项目 | 价值 | 方案 / 状态 |
|---|---|---|
| 基于长周期行为的 T+1 需求预测 | 对规律性出行需求提前触达，引导进端释放需求 | 规则版基于跨端若干天的冒泡序列；Decoder-only Transformer 版开发中 |
| 日维度复购预测 | 预测返程或复购需求及时间，在需求前触达 | 第一阶段预测是否返程，第二阶段预测 24 小时时间段；均使用 XGB，开发中 |

### 6.3 依赖实时行为的专项算法

| 抓手 | 人群 | 目标与约束 | 描述 | 模型与求解 |
|---|---|---|---|---|
| 天降红包 | 新客 | 约束 CAC；目标访问完单率 | 未完单注册用户登端时下发当日首单立减券 | DR-CFR + 贪心；每周自动更新 |
| 天降红包 | 流失 | 约束 CAC；目标访问完单率 | 长期未完单用户再次登端时下发归来立减券 | DR-CFR + 分城市框分桶；上线后未再更新 |
| 天降红包 | 竞争 | 约束 C 补率；目标呼叫 | 面向双冒、双呼等跨平台行为用户增强价格吸引力 | DRCFR-UB 分段函数 + 贪心；上线后未再更新 |
| 主题营销 | 全量 | 约束 C 补率；目标呼叫 | 通过弹窗、Banner、会场和一键领券产生增量呼叫 | XTNet + 全国分桶；上线后未再更新 |
| 套餐 | 全量 | 约束 C 补率；目标呼叫 | 用户购买多张打车券，锁定未来行程并促进提频留存 | DR-CFR + 贪心；上线后未再更新 |
| ACTI 多抓手联合决策 | 竞争 | 约束 C 补率；目标完单 | 联合短信、端外绑券、无车赔、升舱等抓手，处理交叉弹性与预算协同 | 基于 ESMM 的双 DRCFR + 分桶；按周更新 |

## 7. 商家策略

商家策略聚焦平台约束下的商家增长，需要平衡商家效率与商家生态。算法框架延续“Uplift Model + 决策优化”的经典两阶段结构。

宏鹄呼返的演进体现了效率与生态之间的取舍：

- 早期：按品牌实施差异化 C 补，利用差异化创造效率空间；
- 后期：品牌维度采用统一 C 补，强化生态公平与稳定。

原材料说明：由于战略调整，自 2026 年起本方向不再迭代商家策略。

## 8. 如何理解不同补贴抓手之间的关系

之所以存在多种 C 补抓手，是因为它们的目标、受众和生效环节不同：

| 环节 | 典型抓手 | 主要作用 |
|---|---|---|
| 端外 | 外呼、短信、Push、端外绑券 | 唤起或召回，释放潜在需求 |
| 登端 / 首页 | 天降红包、主题营销、套餐 | 促进领券、首单、复购或提频 |
| 冒泡 / 呼叫 | 幸运盒子、特价盒子呼返、自营或宏鹄呼返、平台联合决策 | 优化价格、默勾和发单转化 |
| 等应答 / 接驾 | 无车赔、升舱等 | 管理确定性预期，提高应答与履约 |
| 长期 | 生命周期运营、需求预测 | 提高留存和 LTV |

效率保障主要来自：

- 单抓手的钱效约束；
- 总预算内的预算分配；
- 多抓手联合决策，建模抓手间交叉弹性；
- 供需、体验、生态和平台控制权等守护指标。

原文口诀：**平台券互相 PK，盒子呼返折上折。**

## 11. 值得继续思考的问题

1. 为什么多个抓手分别做到局部最优，整体仍可能不是全局最优？
   - 因为抓手争夺同一批用户和预算，存在重复触达、替代效应、协同效应及跨环节影响。单抓手实验无法完整识别这些交叉弹性。
2. 为什么“预测谁会下单”不能直接等价于“决定给谁补贴”？
   - 下单概率是自然转化倾向，而补贴决策需要估计补贴带来的增量效果。高自然转化用户即使不补贴也会下单，补贴可能只是浪费预算；应优先识别具有正向增量且钱效合适的人群。
3. 平台联合决策如何纳入长期价值？
   - 可将单次完单目标扩展为短期交易收益与留存、复购、LTV 的多目标函数，并纳入体验损伤、预算和供需等约束；同时通过长期实验或序列决策方法验证，避免短期补贴透支未来需求。
4. 历史上部分特价盒子策略效果不佳，可能说明什么？
   - 需要优先检查策略是否真正改变了用户可感知的价格或确定性、是否覆盖了正确人群与供需场景，以及盒内外价格倒挂、运力不足、默勾接受度变化是否抵消了收益。仅凭本材料无法确定唯一原因。
