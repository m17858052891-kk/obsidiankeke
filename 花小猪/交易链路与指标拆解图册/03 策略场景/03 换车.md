# 换车

![换车决策、交接与乘客及运力结果](../图片/03%20换车.png)

从原司机正式应答开始看一笔需求。换车找车期间，父单司机继续接驾。新司机应答并完成交接后取消父单，子单继续履约。如果找车窗口结束仍未换成，原司机继续接驾。若原司机在途中取消，先核在途换车子单的停单状态，再分允许改派和不可改派。换车成功的父单取消要用取消原因和父子关系识别，需求终态继续追到最后一张有效订单。

| 要回答的问题 | 查哪个中间事件 | 计数方式 |
|---|---|---|
| 哪些单值得发起换车？ | 轮询时的原司机状态、接驾 ETA、连环派与绕路、乘客取消风险、规则版本和不换／手动／自动决策 | 按同一批原始需求算触发覆盖，同时保留决策轮次。按连环派与非连环派拆，分别核三种动作的占比。 |
| 推荐了但没有发出去，还是发出后没找到车？ | 手动提示与乘客点换、实发子单、首个有效举手、父子实时 ETA 与改善门槛 | 手动点换率用实际收到手动换车提示的需求作分母。找车转化用已实发子单作分母，同一轮同一子单去重。 |
| 找到车后为什么没切过去？ | 子单应答与交接、父单取消原因和时刻、原司机到达或取消、改派子单应答 | 交接转化按已找到候选的同批次尝试计算。已换车、未换车及改派过的需求都追终态，完单按原始需求去重。 |
| 净结果如何？ | 原司机已投入、新司机接驾、连环派中上一单结束时间、最终完单与取消、候选司机在周边的承接 | 分别报告乘客 ETP、归一取消、最终完单和司机接驾投入，明列样本与起止点。相邻订单的运力影响需要市场侧实验或其他可比设计。 |

LR26-031 的 V2.2 时间片结果中，归一完单单均 ETP **−0.78%**，归一应答单均司机接驾时长 **+0.82%**，大盘完单 **+0.31%**。换车可以缩短乘客看到的总 ETA，同时增加本单实际占用的接驾时间。对连环派，先把原司机上一单送驾至终点（AB）与由上一单终点去接本单乘客（BC）分开，再比新司机的接驾时长及原司机已经投入的时间。LR 用 PID 与时间片交叉评估，原因是两组订单可能争用同一批司机。被换成订单的体验改善用于定位机制，策略收益按实验分组的全量样本判断。

**数据怎么拼。** 历史轮询 SQL 用 `kflower_marketplace.ods_log_kflower_athena_guide_answer_after_rec_h` 的 `oid`、`change_car_type`、`is_serial` 定位决策，并以 `first_access` 取首次记录。排查反复轮询时另保留各轮，发单、举手、应答到终态按子单明细衔接。历史样例通过 `parent_order_id` 关联父单的 `answer_time`。建议另外核实展示与点换、父子比较及交接的事件标识，再对真实事件时间。当前版本的门槛、找车窗口、到达退场与改派锁需按分析日期核对。

若目标是挽回完单，可在决策前定义同类风险样本，比较限制条件相同的换车策略与基线，联看归一完单和等待。优先区分高取消风险和能被换车挽回的需求，后者需要对照结果。
