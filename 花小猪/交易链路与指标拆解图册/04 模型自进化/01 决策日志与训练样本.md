# 决策日志与训练样本

预分单模型要学习乘客对**实际看见的车型和价格**的反应。升舱决策还需要估计，乘客在**没有升舱补贴**时会不会自付差价接受，以及候选运力能否最终履约。要分别追到乘客决定、司机承接、最终完单和实际补贴四类结果。

## 怎样接起一次决策

建议以**原需求 × 决策轮次 × 候选车型 × 动作**保留候选明细，再以原需求归一应答、取消和履约结果。记录决策时点、候选所属商家和车型，关联原单、子单及司机承接段。现有平台表先用 `source_id + order_id` 核对来源和订单，候选表再检查 `product_id`、事件时间或可用的决策标识。重复轮询和跨来源关联要做一对多校验。仅用订单号连候选容易把另一轮或另一车型的反馈接进来。

| 环节 | 已有资料能定位什么 | 为后续迭代建议补齐什么 |
|---|---|---|
| 决策前 | 历史接受度推理日志 `kflower_ods.ods_log_kflower_ether_hxz_pre_dispatch_accept_model_h` 可按模型版本和日期查输入。升舱工程文档还列出了等待、门槛、价差、边际收益等日志需求。 | 保存当时的等待、供需、原勾选、候选报价及特征版本。完整可行候选、过滤原因、分配动作与随机探索概率需核是否已落表。 |
| 实际执行 | `dwd_kf_trd_pre_dispatch_order_di` 能查预分单发单，`dwd_kf_trd_pre_dispatch_strivetender_di` 可查举手。 | 区分“选中、发单、找到运力、推送、实际展现”。保留原车型先应答、授权或预算拦截及其他退出原因。实际展现与决策轮次的关联待核。 |
| 乘客反馈 | `dwd_kf_trd_pre_dispatch_decision_di.is_refused` 可区分 0 接受、1 拒绝和 3 默认拒绝。 | 保留实际展示的车型、价格、补贴和操作时间。遇到默认拒绝要核对应版本、是否真实展示、是否由其他事件截断。 |
| 完整结果 | 平台订单及标签表有应答、取消、完单，`dwm_kf_trd_order_index_di.is_upcabin_ans` 标识升舱应答。 | 追同一原需求的最终完单、最终商家和实际补贴结算。升舱应答、升舱完单、实际补贴各核自己的字段和终点。 |

历史表单分析对 `extend_feature.pre_dispatch` 与 `is_pre_dispatch` 是否同口径仍有疑问。复盘前先验总量、空关联、多关联及来源分布，再逐笔核对一单多轮、提前退出和父子单案例。表名和字段以所引历史材料为准。[历史链路与待核字段](https://git.xiaojukeji.com/bwh_stg/trading-efficiency-wiki/blob/9847514d22aee1525646d16e07d8429ab57a267a/wiki/%E6%8C%87%E6%A0%87/%E9%A2%84%E5%88%86%E5%8D%95%E6%95%B0%E6%8D%AE%E8%A1%80%E7%BC%98%E4%B8%8E%E5%8F%A3%E5%BE%84.md) · [[预分单接受度模型在离线一致性检验|接受度日志与版本对齐]] · [[升舱工程文档|升舱工程日志设计]]

## 标签在什么条件下成立

| 事件 | 接受度如何使用 | 其他结果如何记录 |
|---|---|---|
| 已展现自付预分单且主动接受／拒绝 | 作为对应车型和报价的真实反馈 | 继续追是否正式应答及完单。 |
| 已展现，超时默认拒绝 | 保留状态。是否进入二分类负样本由学习目标和可观察窗口决定，并单列敏感性结果。 | 区分看见后无操作、竞态退出和日志缺失。 |
| 未发、未找到车、未展现或未到观察窗终点 | 接受度保持未知 | 可分别用于执行、供给或标签成熟度分析。 |
| 实际给了升舱补贴 | 观察已执行动作下的响应和履约 | 同一候选的自付接受和不升舱结果仍待比较；实际补贴与成本按结算核。 |

历史模型曾对没有发单、没有结果的候选按人工规则补标签，原记录指出这种构造会让模型学习规则。改用有真实反馈的样本能解决一部分标签问题，但数据仍由旧策略选择。对很少展现的车型、价格或时点，要量化覆盖和样本量。需要估计新动作时，在业务允许的候选范围内设计随机探索并记录概率，或用合适的线上对照；缺少覆盖的动作先记为证据不足。[[预分单接受度模型|历史人工补标与真实标签重训]] · [[新流升舱：接受度模型、取消分析与实验结果|新流样本的标签与人群分布]]

例如接受率变动，先对比同一口径下“已推送 → 已展现 → 可判定反馈”的样本数，再分等待时段、价差、车型、人群和策略版本看实际接受。比较同类已展现样本的实际反馈，再判断触达构成和乘客反应各自的变化。若发现“接受后仍没有应答”，回查同轮的选优和原车型是否先应答。
