# 商家 PK 胜率与完单份额

先看商家进入什么样的 PK，再看同类竞争里是否胜出，最后看赢家是否履约。

![商家 PK 胜率与完单份额拆解图](../图片/商家%20PK%20胜率与完单份额.png)

| 问题 | 历史资料中的分母 | 复盘中补哪一列 |
|---|---|---|
| 自营举手后的总体竞争胜率 | 自营胜出订单数 / 自营全部举手订单数 | 含无效举手的比例、有效独举和有效同举构成。轮内判定，再按样例订单口径聚合。 |
| 自营在同轮实质竞争时的绝对胜率 | 自营与三方均有效的订单中，自营胜出订单 / 双方均有效订单 | 同轮竞争对手、候选距离与确认状态。 |
| 部门 only / both 举手率 | 一位司机 / 多于一位司机举手的 PK 数，分别除以参与 PK 数 | 品牌资料的 only / both 按商家；同品牌多司机会被两种定义分到不同组。 |
| 商家完单份额 | 该商家最终完单数 / 平台归一完单数 | 并列商家绝对完单量、平台总完单量，另列首应答品牌与最终品牌。 |

**先核品牌报表取了哪些单。** 引用的自营竞争专题将“多勾”定义为同单勾选自营和三方，只取这批订单。多勾表示这笔呼叫给了两方机会，only / both 描述这一轮的实际有效举手，两者可以同时出现。样例含改派订单；同商家对同单多次举手，报表订单数去重。轮内仍要保留每条举手、轮号和胜者。样例 SQL 在同轮匹配到胜者后才判有效，诊断无胜轮还要补独立轮次记录。

先用同轮、同商家把上报与有效性连起来，再用胜者 OD 回连司机应答，最后用原始号看终态。只有双方都有效的子集才能直接回答“在同场竞争时选了谁”。若总体胜率变化而组内胜率稳定，查看竞争人群构成；若组内也有变化，再追候选质量、决策规则与确认过滤。最终赢家变了，也要核是不是同一批需求只换了承接方。

只有在样本互斥、同一计数单位、分母完整时，总率才能写成各组占比与组内率的加权和。多轮标签重叠时，先分轮或制定互斥的订单归属规则。
