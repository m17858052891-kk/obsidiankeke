# 乘客总等待时长 ETP

先看终点取司机到达还是开始计费，再把同一批乘客的等待切开。

![乘客总等待时长 ETP拆解图](../图片/乘客总等待时长%20ETP.png)

## 先固定时钟与样本

| 文档口径 | 怎么算 | 哪些需求进来 |
|---|---|---|
| 部门单均 ETP，到达版 | 平均（司机到达上车点 t3 − 首次呼叫 t0） | 有到达事件的需求，包括部分到达后取消。多次到达先核看板具体选点。 |
| 项目归一乘客 ETP，计费版 | 平均（开始计费 t4 − 首次呼叫 t0） | 最终完成的归一需求 F。部门称这一口径为“单均呼叫-计费时长”。 |

**计费版如何逐段对账。** 在每一笔完单需求上，用首次正式应答记 t1，最终履约那张单及司机的应答记 t2，随后取该司机到达 t3 和计费 t4。逐单有 `t4−t0 = (t1−t0) + (t2−t1) + (t3−t2) + (t4−t3)`。可先只拆应答前后，再展开后面三段。没有更换承接段时 t1=t2。跨多个子单时，t2−t1 包括从首次应答直到最终承接的所有经过时间，不能全称为某次换车耗时。

| 哪段有变化 | 中间证据 | 下一判断 |
|---|---|---|
| t1−t0 | 首次实播／选单点抢、首次有效举手、首胜、确认与正式应答 | 是到达平台前等待，还是入窗后等决策和承接？多商家查真实关键时间线，避免叠加并行耗时。 |
| t2−t1 | 原司机应答、发子单、新司机应答、交接和父单取消 | 换车／改派需求占比变了，还是同一类交接平均耗时变了？ |
| t3−t2 | 最终司机应答位置、预估路面接驾距离、到达时刻 | 分连环／非连环和城市时段，区分司机构成与同类司机实际接驾时间。 |
| t4−t3 | 到达事件、开始计费事件及缺失率 | 这段落在到达以后；没有乘客上车日志时，只能定位到两次打点之间。 |

**样本核对。** 同时报告到达数、完单数、取消数、各段打点有效数。缺 t3 时总等待仍可算，四段细分只能在打点完整子集对账，并列两批样本量。图中的四段是完单需求的诊断拆法。到达版若需分段，只在同一批到达需求上用认可的到达事件及其对应承接司机，拆到 t3。另看历史 SQL 的每段分子是否也过滤到同一批完单：全体已应答样本的应答耗时之和除以完单数，也无法还原这批完单乘客的等待。到达后最终没完单的需求没有“最终履约司机”，应回到到达版定义。
