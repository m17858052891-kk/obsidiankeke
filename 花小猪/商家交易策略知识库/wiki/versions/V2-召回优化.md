# V2：召回优化阶段

## 版本概述

V2 标志着策略架构的**范式转变**：从V1的「精确计算初始半径+渐进扩播」转向「大初始召回半径 + 应答后取消率模型过滤」。核心武器从"半径计算"变成了"模型过滤"。

## 核心架构

```
发单 → 大初始半径召回 → 取消率模型过滤(caa < ocr + bias) → 动态阈值(基于流失率) → 应答
```

**过滤公式**：`取消率预测值 < 订单流失率 + 偏置项`
- 偏置项(bias)越小 → 过滤越严格
- 偏置项(bias)越大 → 过滤越宽松

**动态播单实现**：每轮召回都调模型重新过滤，随时间推移过滤范围自然扩大。

## V2.0：基础架构

### 模型体系（5个模型）
- 非连环派乘客取消模型 (cp_pas_caa_model)
- 连环派乘客取消模型 (serial_pas_cancel_model)
- 非连环派司机取消模型 (cp_dri_caa_model)
- 连环派司机取消模型 (zy_serial_driver_cancel)
- 应答前流失率模型 (cp_loss_model)

### 分单模式
- **GS (Global Search)**：全局搜索，召回半径较大
- **TP (TopSpeed)**：极速模式，召回半径较小

### 特殊场景
V2.0 需管理多个 exempt 分组（腾讯端/百度端/美团端/上海特殊商家/宏鹄滴滴端），配置极为复杂。

## V2.1：配置收拢 + 参数迭代

### 核心改进
1. **模型整合**：5个 → 3个（连环派/非连环派合并）
2. **新增ETA约束**：召回和过滤不仅看距离(EDA)，还看时间(ETA)
3. **连环派过滤放松**：近距离连边不走模型（ETA<2min且EDA<1.2km）
4. **非连环派过滤收紧**：偏置项从0.5-0.6降至0.2左右

### 策略效果

**本质是播单份额从非连环派向连环派腾挪**：
- 连环派份额：17% → **42%**
- 非连环派质量大幅提升：C取消 -2.7pp
- 连环派质量下降：C取消 +2.0pp
- 净效果正向：端内完单 +4.14%，CR +0.5pp

### 实验结果（V2参数，2026.03.25—03.29）

| 指标 | 变化 |
|------|------|
| 端内人均完单 | **+4.14%** |
| 端内CR | **+0.50pp** |
| 端内AR | +0.99pp |
| C取消 | +0.08pp（几乎不变） |
| B取消 | **+1.21pp** |
| 平台完单 | +0.57% |
| 平台CR | +0.42pp |

## 从 V1.2 到 V2 的关键转变

| 维度 | V1.2 | V2 |
|------|------|-----|
| 理念 | 计算最优半径，瞬时扩播 | 大半径召回，模型过滤 |
| 应答率保障 | 依赖扩播时机和速率 | 大半径直接保证候选充足 |
| 质量控制 | 近距离 ≈ 低取消 | 模型预测取消率 + 动态阈值 |
| 连环派 | 和非连环派统一策略 | 分开配置，差异化过滤 |
| 核心参数 | 供需比→半径 | 偏置项→过滤严格程度 |

## 关键依赖

1. **取消率模型准确性**：模型不准则过滤无效
2. **流失率模型**：影响动态阈值决策
3. **ETA预估准确性**：新增的时间维度约束
4. **计算性能**：每轮召回都要调模型打分

## 遗留问题

1. B取消 +1.21pp 需要解决（连环派过滤过松）
2. 连环派和非连环派的实验组不同质可比
3. 全量召回数据稀疏，缺乏全量呼单数据
4. 后续计划：收紧连环派过滤 → 调阈值放量 → 下一版本策略迭代
