离线产出的历史7天的数，groupby小时，groupby格子，获得“十分钟的格子空车司机数”，“十分钟的格子发单数”，“十分钟的格子实时未播单数”

但只用十分钟的格子空车司机数和十分钟的格子发单数，即coordstream_driver_empty_cnt_json和biz_order_create_minute_cnt_json中对应十分钟时间片的数值

同时记格子5min空车司机数和格子5min发单数为realtime_empty_driver_cnt和realtime_order_create_cnt

计算**需供比ratio**逻辑（之前为供需比，调换一下）

如果coordstream_driver_empty_cnt_json 或 biz_order_create_minute_cnt_json对应时间片的值**为空或为零**，则空车召回BaseRadius = 3000m，连环派走线上serial_dispatch_conf灰度的配置

否则，

      如果realtime_empty_driver_cnt**为空或为零**，则ratio = biz_order_create_minute_cnt_json对应时间片的值/ coordstream_driver_empty_cnt_json对应时间片的值

      否则，ratio = 0.5 \*  realtime_order_create_cnt / realtime_empty_driver_cnt + 0.5 \* biz_order_create_minute_cnt_json / coordstream_driver_empty_cnt_json

二、

**方案一**

计算出来的对空车的召回半径**BaseRadius**的生效范围：

若BaseRadius<3000：

则召回空车的订单侧距离，和连环派召回的两段和距离==timeFilterDistanceLimitAC，均为==**BaseRadius**

若BaseRadius>=3000：

  则召回空车的订单侧距离BaseRadius=3000，连环派召回的两段和距离==timeFilterDistanceLimitAC读取连环派正常生效的值==

举个例子，动播计算出来BaseRadius是2800m，则本订单召回空车时，初始距离为2.8km，且订单侧随时间逐渐增大；本订单召回连环派订单时，两段和不再增大，始终为2800m

**方案二**

增加一个R2，类比R1，为不同供需比下，空车和载人车的播单半径（对空车为BaseRadius，对载人车**暂**为两段和==timeFilterDistanceLimitAC）==
