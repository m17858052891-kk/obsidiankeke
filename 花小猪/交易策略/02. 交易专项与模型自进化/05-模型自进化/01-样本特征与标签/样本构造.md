# 样本构造

[Cooper 原文](https://cooper.didichuxing.com/knowledge/2199610335356/2208656608920)

先看样本构造的整体步骤，再定位价格列表与动作空间。更完整的 V4 链路说明仍单独保留，可按对应表名交叉查阅。

**阅读定位**　[[#整体步骤|整体步骤]] · [[#1. 获取冒泡基础数据|1. 获取冒泡基础数据]] · [[#2. 构造价格列表（plft_v4_bubble_full_price_list）|2. 构造价格列表（plft_v4_bubble_full_price_list）]] · [[#附录：口径验证|附录：口径验证]]

## 整体步骤

1. 获取冒泡基础数据：原始价格列表、最终决策结果、是否RCT、呼叫/默勾/完单 label、完单GMV

2. 构造特价盒子 × 幸运盒子 × 平台呼返100折下的合并价格列表，模拟表单展示策略

3. 从合并后的价格列表，获取每个默勾下商家的真实发单品类特征，并计算率指标

4. 获取P维度、城市维度特征

## 1. 获取冒泡基础数据

### 1.1 日志解析表（plft_log_parse_ori_category_list）

**用途**：从 public 日志的 `category_list` 字段中解析车型维度价格信息，供车型表 join 使用。

**目标表**：`kflower_strategy.plft_log_parse_ori_category_list`

**字段映射**：

| 原始字段 | 映射字段 | 说明 |
| --- | --- | --- |
| e_id | estimate_id | 车型id |
| pro_id | product_id | 商家id |
| lt | level_type | 品类 |
| p_t | price_type | 0=司乘一口价；1=乘客一口价/司机实时；2=司乘实时 |
| basic_total_fee | basic_total_fee | 可优惠金额，单位分 |
| pre_dis_amt | pre_dis_amt | 前置最大优惠额，单位分 |
| un_dis_fee | un_dis_fee | 不可抵扣费项，单位分 |

**解析口径**：对含 `box_list` 的记录，`e_id`、`pro_id` 取 `box_list` 中的值，其余字段取外层字段。

**关键取数说明**：

- 一个 `trace_id` 在原始日志表中可能落多条记录（占比约 0.3%），且各行 `category_list` 内容可能不同。需先对每行原始记录独立解析 `category_list`，再按 `trace_id + estimate_id` 做 group by，**不能**在解析前用 `max(category_list)` 去重（会导致部分 estimate 数据丢失）。

- `basic_total_fee` 为空的行直接过滤，对应两类情况：在日志中无记录的 trace；或在冒泡表中被折叠（`is_fold_cp=1`）的滴滴出行车型，解析表中 `basic_total_fee` 本身为空。

### 1.2 车型维度特征（plft_v4_bubble_vehicle_info）

**用途**：计算不同折扣下的价格列表，支持表单模拟；提供表单序列特征-价格。

**产出表**：`kflower_strategy.plft_v4_bubble_vehicle_info`，SQL 见 `vehicle_feature.sql`

**取数说明**：

- 底表：`kflower_dw.dwd_kf_trd_bubble_base_all_di`，基于去重冒泡 `trace_id` 过滤

**去重冒泡口径**（对同一用户同一行程的重复冒泡，按 `distinct_bubble_id` 分组，取最新冒泡的 `trace_id`）：

> [!example]- sql 实现细节（25 行）

> with deduplicate_bubble as (
>     select distinct trace_id
>     from (
>         select
>             a.trace_id,
>             a.estimate_id,
>             row_number() over (partition by b.distinct_bubble_id order by a.bubble_time desc) as time_rank
>         from (
>             select trace_id, estimate_id, bubble_time
>             from kflower_dw.dwd_kf_trd_bubble_base_di

>                 and is_from_waiting_response <> 1   -- 去掉等待应答页冒泡

>             select estimate_id, distinct_bubble_id
>             from kflower_dw.dim_kf_trd_unity_bubble_anycar_label_di
>             where dt = '${BIZ_DATE_LINE}'
>                 and source_id = 'kf'
>         ) b on a.estimate_id = b.estimate_id
>     ) t
>     where time_rank = 1
> )
> ```

### 2.4 模拟盒子扩展

被折叠的车型，若满足以下条件则扩展进特价盒子：

- 实付 < 特价盒子最低展示价

- 非特价盒子/幸运盒子本身（level_type not in 105,202,201,107）

**小猪自营（product_id=80）特殊处理**：

- 若小猪特价（level_type=104）已在盒子里：小猪特价不可扩展，小猪一口价/打车/特快可以扩展

### 2.5 模拟置顶

- 当「幸运盒子」或「特价盒子」的真实实付价为可见品类最低实付时，将其置顶

- 幸运盒子和特价盒子实付相同时，优先置顶幸运盒子

### 2.6 同价车型合并

将展示价格相同的非盒子车型合并（is_merged=1）：

- 盒子（level_type in 105, 200, 202, 201, 107）不参与合并

- 折叠且未扩展进盒子的车型不参与合并

- 展示价格相同但计价方式不同（一口价 vs 实时计价）不合并

### 2.7 车型排序规则

- 折叠且未扩展进盒子（is_folded=1 AND is_box_extended=0）：不展示，car_rank=null

- 置顶（is_top=1）：car_rank=1

- 扩展进特价盒子的车型：与特价盒子排序一致

## 附录：口径验证

### 验证1：basic_total_fee_amt 为空原因排查

**问题**：车型表中，部分去重冒泡对应的 `basic_total_fee_amt` 为空值。

#### 原因1：max(category_list) 导致部分 estimate 数据丢失

**背景**：原始日志表中同一 `trace_id` 可能存在多行记录，且 `category_list` 内容不同。原 SQL 使用 `max(category_list)` 去重，只保留字典序最大的一行，可能造成部分 estimate 数据缺失。

下方 SQL 对同一 trace 的两行原始数据分别解析并横向对比，判断 `max` 是否引入数据偏差：

> [!example]- sql 实现细节（68 行）
> ```sql
> with raw_rows as (
>     select
>         param['traceid']        as trace_id,
>         param['category_list']  as category_list,
>         row_number() over (
>             partition by param['traceid']
>             order by param['category_list'] desc
>         )                       as rn   -- rn=1 即 max 选中行
>     from
>         kflower_marketplace.ods_log_kflower_platform_call_return_public_log_h
>     where
>         year  = '2026'
>         and month = '06'
>         and day   = '27'
>         and hour  = '18'
>         and param['traceid'] = '9fa5864a6a3f9f82b79b884f3a2afbd4'
> ),
> parsed as (
>     select
>         trace_id,
>         case when rn = 1 then 'max选中行' else 'max丢弃行' end  as source,
>         if(box.e_id is not null, box.e_id,    item.e_id)        as estimate_id,
>         if(box.e_id is not null, box.pro_id,  item.pro_id)      as product_id,
>         coalesce(item.lt,  0)                                    as level_type,
>         coalesce(item.p_t, 0)                                    as price_type,
>         item.basic_total_fee                                     as basic_total_fee,
>         coalesce(item.pre_dis_amt, 0)                            as pre_dis_amt,
>         coalesce(item.un_dis_fee,  0)                            as un_dis_fee
>     from raw_rows
>     lateral view explode(
>         from_json(
>             category_list,
>             concat(
>                 'array<struct<',
>                     'e_id:string,',
>                     'pro_id:bigint,',
>                     'lt:int,',
>                     'p_t:int,',
>                     'basic_total_fee:bigint,',
>                     'pre_dis_amt:bigint,',
>                     'un_dis_fee:bigint,',
>                     'box_list:array<struct<e_id:string,pro_id:bigint>>',
>                 '>>'
>             )
>         )
>     ) tmp as item
>     lateral view outer explode(item.box_list) box_tmp as box
>     where item.e_id is not null
> ),
> r1 as (select * from parsed where source = 'max选中行'),
> r2 as (select * from parsed where source = 'max丢弃行')
> select
>     coalesce(r1.trace_id,    r2.trace_id)    as trace_id,
>     coalesce(r1.estimate_id, r2.estimate_id) as estimate_id,
>     r1.basic_total_fee                       as kept_basic_total_fee,
>     r2.basic_total_fee                       as drop_basic_total_fee,
>     (r1.basic_total_fee = r2.basic_total_fee) as basic_fee_same,
>     case
>         when r1.estimate_id is null then '仅在丢弃行中，max导致漏数'
>         when r2.estimate_id is null then '仅在选中行中，丢弃行无此estimate'
>         else '两行均有，对比字段值'
>     end                                      as diff_status
> from r1
> full join r2
>     on  r1.trace_id    = r2.trace_id
>     and r1.estimate_id = r2.estimate_id
> order by diff_status, estimate_id
> ;
> ```


**结论**：一个 trace 可能落多条日志记录，需先解析再按 `trace_id + estimate_id` 聚合，不能先用 `max` 去重。

#### 原因2：解析或 join 环节存在数据丢失

修复原因1后，验证仍为空的 trace 是否在原始日志表中本身不存在：

```sql
with null_fee as (
    select distinct trace_id
    from kflower_strategy.plft_v4_bubble_vehicle_info
    where dt = '2026-06-27' and basic_total_fee_amt is null
),
raw_log as (
    select distinct param['traceid'] as trace_id
    from kflower_marketplace.ods_log_kflower_platform_call_return_public_log_h
    where year = '2026' and month = '06' and day = '27'
)
select
    count(1)                                 as null_fee_total,
    count(r.trace_id)                        as in_raw_log,
    count(1) - count(r.trace_id)             as not_in_raw_log,
    round(count(r.trace_id) / count(1), 4)   as coverage_rate
from null_fee n
left join raw_log r on n.trace_id = r.trace_id
;
```

**结论**：约一半的空值 trace 在日志中有记录，说明解析/join 环节存在数据丢失。进一步取样对比发现：约一半冒泡仅在冒泡表存在，解析表不存在；其余为冒泡表中被折叠的滴滴出行车型（`is_fold_cp=1`），`basic_total_fee` 在解析表中本身为空。**处理方式：直接丢弃** `**basic_total_fee**` **为空的行。**

取一条仍为空的 trace，对比解析表与冒泡表差异，定位丢失环节：

> [!example]- sql 实现细节（36 行）

> ),

### 验证2：车型表与冒泡表价格字段一致性校验

对比车型表 `basic_total_fee_amt`（来自日志解析表）与冒泡表 `basic_total_fee_amt` 的一致性：

> [!example]- sql 实现细节（22 行）
> ```sql
> with vehicle as (
>     select trace_id, estimate_id, basic_total_fee_amt as veh_basic_total_fee_amt
>     from kflower_strategy.plft_v4_bubble_vehicle_info
>     where dt = '2026-06-27' and basic_total_fee_amt is not null
> ),
> bubble as (
>     select trace_id, estimate_id, level_type, basic_total_fee_amt as bub_basic_total_fee_amt
>     from kflower_dw.dwd_kf_trd_bubble_base_all_di
>     where dt = '2026-06-27'
> )
> select
>     b.level_type,
>     count(1)                                                                    as total,
>     count(if(v.veh_basic_total_fee_amt = b.bub_basic_total_fee_amt, 1, null))  as basic_fee_match,
>     count(if(v.veh_basic_total_fee_amt <> b.bub_basic_total_fee_amt, 1, null)) as basic_fee_diff,
>     round(avg(v.veh_basic_total_fee_amt - b.bub_basic_total_fee_amt), 2)       as avg_diff,
>     max(abs(v.veh_basic_total_fee_amt - b.bub_basic_total_fee_amt))            as max_abs_diff
> from vehicle v
> inner join bubble b on v.trace_id = b.trace_id and v.estimate_id = b.estimate_id
> group by b.level_type
> order by basic_fee_diff desc
> ;
> ```


**结论**：除 `level_type=107` 外，约 0.1% 的冒泡存在 `basic_total_fee` 不一致的情况，以日志解析表值为准。
