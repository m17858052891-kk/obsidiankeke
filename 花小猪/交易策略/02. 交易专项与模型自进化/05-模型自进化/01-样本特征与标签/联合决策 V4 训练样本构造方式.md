### 1.1 日志解析表构造

- **表名**：`kflower_strategy.plft_log_parse_ori_category_list`

- **表粒度**：`trace_id × estimate_id`

- **FROM 表**：`kflower_marketplace.ods_log_kflower_platform_call_return_public_log_h`

- **写入分区**：`dt=T`

- **实现 SQL**：[plft_log_parse_ori_category_list（63709992）](https://studio.data.didichuxing.com/batch?projectId=1143&taskId=63709992)

- **用途**：将 public 日志中的 `category_list` JSON 数组展开为车型明细，供下游 `plft_v4_bubble_vehicle_info` 补充计价模式、基础价格和前置优惠。

#### 1.1.1 表字段

| 产出字段 | 类型 | 字段注释与构造 |
| --- | --- | --- |
| `trace_id` | `string` | 冒泡 trace ID，取自 `param\['traceid'\]` |
| `estimate_id` | `string` | 车型 ID；有 `box_list` 子车型时取 `box.e_id`，否则取外层 `item.e_id` |
| `product_id` | `bigint` | 运力商家 ID；有 `box_list` 子车型时取 `box.pro_id`，否则取外层 `item.pro_id` |
| `level_type` | `int` | 交易品类，取外层 `item.lt`，缺失时补 0 |
| `price_type` | `int` | 计价模式，取外层 `item.p_t`，缺失时补 0 |
| `basic_total_fee` | `bigint` | 可优惠金额，单位分；取外层 `item.basic_total_fee`，不补默认值 |
| `pre_dis_amt` | `bigint` | 前置最大优惠额，单位分；取外层 `item.pre_dis_amt`，缺失时补 0 |
| `un_dis_fee` | `bigint` | 不可优惠金额，单位分；取外层 `item.un_dis_fee`，缺失时补 0 |
| `dt` | `string` | 日志解析结果的分区日期，格式 `yyyy-MM-dd` |

#### 1.1.2 构造方式

```sql
-- 1. 读取当天 public 日志中的 trace 和车型列表
with base as (
    select
        param['traceid']       as trace_id,
        param['category_list'] as category_list
    from kflower_marketplace.ods_log_kflower_platform_call_return_public_log_h
    where year  = split('${BIZ_DATE_LINE}', '-')[0]
      and month = split('${BIZ_DATE_LINE}', '-')[1]
      and day   = split('${BIZ_DATE_LINE}', '-')[2]
)
```

> [!example]- sql 实现细节（25 行）
> ```sql
> -- 2. 将 category_list 解析为车型数组并逐项展开
> category_exploded as (
>     select
>         trace_id,
>         item
>     from base
>     lateral view explode(
>         from_json(
>             category_list,
>             concat(
>                 'array<struct<',
>                     'e_id:string,',
>                     'pro_id:bigint,',
>                     'lt:int,',
>                     'p_t:int,',
>                     'basic_total_fee:bigint,',
>                     'pre_dis_amt:bigint,',
>                     'un_dis_fee:bigint,',
>                     'box_list:array<struct<e_id:string,pro_id:bigint>>',
>                 '>>'
>             )
>         )
>     ) tmp as item
>     where item.e_id is not null
> )
> ```


```sql
-- 3. 盒子车型使用 box 内的 e_id/pro_id，其他字段继承外层车型
select
    trace_id,
    if(box.e_id is not null, box.e_id,   item.e_id)  as estimate_id,
    if(box.e_id is not null, box.pro_id, item.pro_id) as product_id,
    coalesce(item.lt, 0)          as level_type,
    coalesce(item.p_t, 0)         as price_type,
    item.basic_total_fee          as basic_total_fee,
    coalesce(item.pre_dis_amt, 0) as pre_dis_amt,
    coalesce(item.un_dis_fee, 0)  as un_dis_fee
from category_exploded
lateral view outer explode(item.box_list) box_tmp as box
```

```sql
-- 4. 收敛到 trace_id × estimate_id 粒度
insert overwrite table plft_log_parse_ori_category_list
partition (dt = '${BIZ_DATE_LINE}')
select
    trace_id,
    estimate_id,
    max(product_id)      as product_id,
    max(level_type)      as level_type,
    max(price_type)      as price_type,
    max(basic_total_fee) as basic_total_fee,
    max(pre_dis_amt)     as pre_dis_amt,
    max(un_dis_fee)      as un_dis_fee
from parsed_category
group by trace_id, estimate_id
```

上述最后一段使用 `parsed_category` 表示原 SQL 中展开盒子车型后的内层子查询，聚合字段和写入逻辑与原 SQL 一致。

#### 1.2.2 构造方式

##### 1. 选择去重冒泡

先从 `kflower_dw.dwd_kf_trd_bubble_base_di` 的 `dt=T` 分区读取候选车型行，并应用以下过滤：

- `product_1level<>4`：去掉 PBD 端；

- `is_anycar_form=1`：只保留新表单；

- `order_type=0`：只保留实时单；

- `is_from_waiting_response<>1`：去掉等待应答页冒泡。

候选行通过 `estimate_id` 关联 `kflower_dw.dim_kf_trd_unity_bubble_anycar_label_di` 的 `dt=T`、`source_id='kf'` 分区，取得 `distinct_bubble_id`。随后按 `distinct_bubble_id` 分组、`bubble_time desc` 排序，保留 `time_rank=1` 所在的 `trace_id`，形成去重冒泡集合 `deduplicate_bubble`。

这里选出的是要保留的最新冒泡 `trace_id`，不是只保留该排序行对应的单个车型。下一步会重新读取该 `trace_id` 下的全部车型。对应 SQL 和关键注释如下：

> [!example]- sql 实现细节（42 行）
> ```sql
> -- 1. 按 distinct_bubble_id 选择最新一次实际冒泡
> with deduplicate_bubble as (
>     select distinct
>         trace_id
>     from (
>         select
>             a.trace_id,
>             a.estimate_id,
>             -- 同一去重冒泡组内按冒泡时间倒序，time_rank=1 为最新冒泡
>             row_number() over (
>                 partition by b.distinct_bubble_id
>                 order by a.bubble_time desc
>             ) as time_rank
>         from (
>             -- 候选冒泡范围：T 日、新表单、实时单、非 PBD、非等待应答页
>             select
>                 trace_id,
>                 estimate_id,
>                 bubble_time
>             from kflower_dw.dwd_kf_trd_bubble_base_di
>             where dt = '${BIZ_DATE_LINE}'
>               and product_1level <> 4           -- 去掉 PBD 端
>               and is_anycar_form = 1            -- 只保留新表单
>               and order_type = 0                -- 只保留实时单
>               and is_from_waiting_response <> 1 -- 去掉等待应答页冒泡
>         ) a
>         left join (
>             -- 通过 estimate_id 取得同一行程的 distinct_bubble_id
>             select
>                 estimate_id,
>                 distinct_bubble_id
>             from kflower_dw.dim_kf_trd_unity_bubble_anycar_label_di
>             where dt = '${BIZ_DATE_LINE}'
>               and source_id = 'kf'
>         ) b
>           on a.estimate_id = b.estimate_id
>     ) t
>     where time_rank = 1
> )
> -- 此处只确定需要保留的最新 trace_id。
> -- 下一步会按 trace_id 重新读取 dwd_kf_trd_bubble_base_all_di，
> -- 恢复该冒泡下的全部 estimate_id，而不是只保留排序命中的单个车型。
> ```


##### 2. 恢复车型并拼接日志价格

使用 `deduplicate_bubble.trace_id` 内连接 `kflower_dw.dwd_kf_trd_bubble_base_all_di`，该底表同样读取 `dt=T` 并应用上述四个过滤条件，从而恢复每个保留冒泡下的全部 `estimate_id`。

车型行再按 `trace_id + estimate_id` 左连接 `kflower_strategy.plft_log_parse_ori_category_list` 的 `dt=T` 分区，补充：

- `price_type`；

- `basic_total_fee`，输出为 `basic_total_fee_amt`；

- `pre_dis_amt`。

最终使用 `where c.basic_total_fee is not null` 过滤，因此没有命中日志解析价格或解析后基础价为空的车型不会进入产出表。

##### 3. 加工字段和统一单位

车型、商家和上下文字段主要来自 `dwd_kf_trd_bubble_base_all_di`，价格相关字段结合日志解析表加工：

##### 2. 聚合呼叫、完单和 GMV Label

`agg_call_label` 从 `kflower_dw.dwm_kf_trd_hxz_order_anycar_view_di` 读取 `dt between T and T+1` 的订单，并要求：

- `call_time` 非空且不等于 `0000-00-00 00:00:00`；

- `order_id>0`；

- `product_1level in (1,2,999)`。

订单按 `bubble_trace_id` 聚合到 `trace_id`：

- `is_td_call`、`is_td_finish` 分别取 `max`；

- `gmv_amt` 取 `max(gmv_amt) × 100`，从元转为分

- 完单品类按订单 `level_type` 判断：`107` 为幸运盒子，`105/202/201` 为特价盒子，其余为其他品类。

##### 3. 构造默勾、加勾和反勾

`mogou` 从 `kflower_dw.dwm_kf_trd_bubble_silent_check_all_di` 的 `dt=T` 分区读取数据，并过滤等待应答页、PBD 端和已折叠车型。SQL 先按 `trace_id + box_name` 汇总 `selected_status` 和 `is_call`，再按 `trace_id` 统计：

- 默勾且呼叫的盒子数 `mg_call`；

- 非默勾但呼叫的盒子数 `jg_call`；

- 默勾但未呼叫的盒子数 `fg_call`；

- 是否存在任意呼叫 `is_calls`。

最终口径为：

```text
is_mogou_accept = 1，当 mg_call>0 且 jg_call=0 且 fg_call=0
is_jiagou       = 1，当 jg_call>0
is_fangou       = 1，当 fg_call>0 且 is_calls>0
```

##### 4. 拼接时间和策略日志字段

时间字段由 `bubble_base.bubble_time` 生成：

- `hour_of_day` 为 `0~23`；

- `day_of_week` 转成周一为 1、周日为 7；

- `is_workday` 从 `whole_dw.dim_date` 的当日记录读取，未命中时补 0。

`bubble_log` 从 `ods_log_kflower_platform_call_return_public_log_h` 读取 `T` 日全部小时，按 `param['traceid']` 聚合。当前代码对下列字段分别取 `max`：

- `is_rct`：`flow_control.ExpGroupName='union_stg_v3_max_order_v1_only_box_rct'` 时为 1；

- `lucky_box_discount` → `luckybox_discount`；

- `box_discount` → `uabox_discount`；

- `platform_discount`；

- `anchor_select_cnt`；

- `price_anchor_point`。

最终以 `bubble_base` 为主表执行左连接。呼叫、默勾、加勾、反勾、完单、分品类完单和 GMV 未命中时使用 `nvl(...,0)`；策略日志字段未使用 `nvl`，未命中日志时仍可为 `null`。

### 2.4 构造方式：金额定义

本节金额字段的单位均为分，公式直接使用 SQL 字段名。

#### 幸运盒子

适用范围为 `level_type=107`。

| 字段 | 计算公式 | 字段说明 |
| --- | --- | --- |
| `non_deductible_fee_amt` | `spring_festival_fee_amt + dups_cross_city_fee` | 不可抵扣费用，由节假日服务费和跨城费组成 |
| `pas_total_fee_amt` | `basic_total_fee_amt - trip_cloud_discount_fee_amt + spring_festival_fee_amt + dups_cross_city_fee` | 幸运盒子应付价格，也是假 GMV；`trip_cloud_discount_fee_amt` 按 SQL 注释应恒为 0，因此等价于 `basic_total_fee_amt + spring_festival_fee_amt + dups_cross_city_fee` |
| `uabox_basic_total_fee_amt` | `max(basic_total_fee_amt)`，限定同一 `trace_id` 且 `level_type=105` | 幸运盒子计算实付时使用的特价盒子基础价 |
| `uabox_pre_dis_amt` | `max(pre_dis_amt)`，限定同一 `trace_id` 且 `level_type=105` | 幸运盒子计算实付时使用的特价盒子前置最大优惠额 |
| `uabox_coupon_cost` | `0` | 幸运盒子不计算特价盒子呼返 cost |
| `payable_fee_amt` | `ceil((coalesce(uabox_basic_total_fee_amt, 0) - coalesce(uabox_pre_dis_amt, 0)) × luckybox_discount / 100.0) + spring_festival_fee_amt + dups_cross_city_fee` | 幸运盒子实付价格；先对特价盒子基础价扣除前置优惠并应用幸运盒子折扣，再加不可抵扣费用 |

当前确认口径是对 `basic_total_fee_amt` 和 `pre_dis_amt` 分别取 `max`，不要求两个最大值来自同一条 `level_type=105` 记录，也不是先计算单行 `basic_total_fee_amt-pre_dis_amt` 后再聚合。`price_raw` 上方仍有一处历史注释写成 `min`，那不是可执行逻辑；本文和独立对账均以 `uabox_base_for_lucky` 的 `max/max` 实现为准。

#### 特价盒子

适用范围为 `level_type in (105, 201, 202)`。

| 字段 | 计算公式 | 字段说明 |
| --- | --- | --- |
| `non_deductible_fee_amt` | `spring_festival_fee_amt + dups_cross_city_fee` | 不可抵扣费用，由节假日服务费和跨城费组成 |
| `pas_total_fee_amt` | `basic_total_fee_amt - trip_cloud_discount_fee_amt + spring_festival_fee_amt + dups_cross_city_fee` | 特价盒子应付价格，扣除 API 三方优惠后加不可抵扣费用 |
| `uabox_coupon_cost` | `least(floor((basic_total_fee_amt - pre_dis_amt) × (100 - uabox_discount) / 100.0), 2000)` | 特价盒子呼返 cost，向下取整且最高为 2000 分 |
| `payable_fee_amt` | `basic_total_fee_amt - pre_dis_amt - uabox_coupon_cost + spring_festival_fee_amt + dups_cross_city_fee` | 特价盒子实付价格，基础价扣除前置优惠和呼返 cost 后加不可抵扣费用 |

`uabox_coupon_cost` 上限为 2000 分，因此实付不能直接改写成不含 `uabox_coupon_cost` 上限逻辑的折扣率公式。

#### 普通品类

普通品类按平台呼返 100 折处理；当前 SQL 中特快品类也使用同一组公式。

| 字段 | 计算公式 | 字段说明 |
| --- | --- | --- |
| `non_deductible_fee_amt` | `spring_festival_fee_amt + dups_cross_city_fee` | 不可抵扣费用，由节假日服务费和跨城费组成 |
| `pas_total_fee_amt` | `basic_total_fee_amt - trip_cloud_discount_fee_amt + spring_festival_fee_amt + dups_cross_city_fee` | 普通品类应付价格，扣除 API 三方优惠后加不可抵扣费用 |
| `uabox_coupon_cost` | `0` | 普通和特快品类不计算特价盒子呼返 cost |
| `payable_fee_amt` | `basic_total_fee_amt - pre_dis_amt + spring_festival_fee_amt + dups_cross_city_fee` | 普通和特快品类实付价格，基础价扣除前置优惠后加不可抵扣费用 |

### 2.5 构造方式：展示价取整

当前代码对所有品类统一按 `price_type` 处理展示价：

```text
price_type in (0, 1):
show_fee_amt = ceil(payable_fee_amt / 10) × 10

price_type = 2:
show_fee_amt = floor(payable_fee_amt / 100) × 100

其他:
show_fee_amt = payable_fee_amt
```

即：

- 一口价向上取整到角；

- 实时计价向下取整到元。

### 2.6 构造方式：特价盒子参考价

对每个 `trace_id × luckybox_discount × uabox_discount`，只使用 `level_type in (105,202,201)` 计算：

```text
uabox_min_payable = min(payable_fee_amt)
uabox_min_pas     = min(pas_total_fee_amt)
uabox_min_show    = min(show_fee_amt)
```

三项参考价分别用于价格折叠和盒子扩展判断。

### 2.7 构造方式：混合折叠

本节在每个模拟价格行上生成 `hybrid_fold`，将线上已有的非价格折叠与当前折扣组合下重新计算的价格折叠合并。

- 构造粒度：`trace_id × estimate_id × luckybox_discount × uabox_discount`。

- 输出：`hybrid_fold`，最终以 `is_folded` 字段输出。

- 核心公式：`hybrid_fold = 线上非价格折叠 OR 模拟价格折叠`。

主要输入字段：

| 字段 | 本节用途 |
| --- | --- |
| `sub_select_status` | 识别线上折叠原因 |
| `is_fold_cp` | 判断线上车型是否已被折叠 |
| `payable_fee_amt` | 作为当前车型的真实实付价 |
| `pas_total_fee_amt` | 作为当前车型的应付价 |
| `uabox_min_payable` | 作为实付折叠的特价盒子参考价 |
| `uabox_min_pas` | 作为应付折叠的特价盒子参考价 |
| `level_type` | 识别幸运盒子和特价盒子族，应用价格折叠豁免 |
| `city_id` | 选择策略 A、策略 B 或不启用价格折叠 |
| `platform_id` | 在策略 B 中识别可控运力 |

#### 2.7.1 判断顺序

当前 SQL 按以下顺序确定 `hybrid_fold`，命中前一条后不再继续判断：

| 顺序 | 判断条件 | `hybrid_fold` | 说明 |
| ---: | --- | ---: | --- |
| 1 | 继承的线上非价格折叠为 1 | `1` | 线上非价格折叠优先级最高 |
| 2 | `level_type in (107,105,202,201)` | `0` | 幸运盒子和特价盒子族自身不参与价格折叠 |
| 3 | 策略 A 城市 | 按实付折叠或应付折叠 A 判断 | 满足任一价格条件即折叠当前车型行 |
| 4 | 策略 B 城市 | 按应付折叠 B 判断 | 仅检查可控运力车型行 |
| 5 | 其他城市 | `0` | 不模拟价格折叠 |

第 2 步只豁免盒子的**价格折叠**。如果盒子车型已在第 1 步命中线上非价格折叠，`hybrid_fold` 仍为 `1`。

#### 2.7.2 继承线上非价格折叠

线上折叠结果先按 `trace_id × estimate_id` 聚合，再广播到该车型的全部折扣组合。只有线上记录满足 `is_fold_cp=1`，

且 `sub_select_status` 属于显式继承范围时，才记为非价格折叠。

| `sub_select_status` | 折叠含义 | 当前 `v2` 处理方式 |
| ---: | --- | --- |
| `0` | 不折叠 | 不继承为折叠 |
| `1` | 僵尸商家折叠 | 继承 |
| `2` | 执规率折叠 | 继承 |
| `3` | 客服考核折叠 | 继承 |
| `4` | 无车折叠 | 继承 |
| `5` | 品类折叠 | 继承 |
| `6` | 供需折叠 | 继承 |
| `7` | 实付价格折叠 | 不继承，根据 `payable_fee_amt` 重新模拟 |
| `8` | 运营配置折叠 / 人工配置折叠 | 继承 |
| `9` | 盒子内所有车型被折叠 | 继承；该状态理论上应在盒外品类确定后最后判断 |
| `10` | 白名单折叠 | 继承 |
| `11` | 应付价格折叠 | 不继承，根据 `pas_total_fee_amt` 重新模拟 |

`sub_select_status=7` 和 `11` 不直接继承，是为了避免把线上实际折扣下的价格折叠结果广播到全部 28 组模拟折扣中。

#### 2.7.3 模拟价格折叠

依据[《表单策略白皮书》](表单策略白皮书.md)，价格折叠分为实付折叠和应付折叠。两类判断均使用严格小于号 `<`；

与特价盒子参考价相等时，不属于价格倒挂，不触发价格折叠。

价格折叠直接复用 2.6 节构造的特价盒子参考价。在未命中线上非价格折叠、进入模拟价格折叠判断后，

三类价格折叠的完整判断条件如下：

| 折叠规则 | 当前 SQL 判断条件 | 价格含义 | 命中后处理 |
| --- | --- | --- | --- |
| 实付折叠 | `city_id` 属于策略 A 城市<br>`AND level_type not in (107,105,202,201)`<br>`AND payable_fee_amt &lt; uabox_min_payable` | 当前车型真实实付价低于特价盒子族最低真实实付价 | 折叠当前车型行 |
| 应付折叠 A | `city_id` 属于策略 A 城市<br>`AND level_type not in (107,105,202,201)`<br>`AND pas_total_fee_amt &lt; uabox_min_pas` | 当前车型应付价低于特价盒子族最低应付价 | 折叠当前车型行 |
| 应付折叠 B | `city_id` 属于策略 B 城市<br>`AND level_type not in (107,105,202,201)`<br>`AND platform_id in (1,5)`<br>`AND pas_total_fee_amt &lt; uabox_min_pas` | 当前可控运力车型的应付价低于特价盒子族最低应付价 | 折叠当前车型行 |

实付折叠使用**真实实付价** `payable_fee_amt`，不使用展示价 `show_fee_amt`。如果使用展示价，可能误折叠真实实付价实际高于特价盒子的商家。

白皮书定义的应付价等于参与优惠计算的金额（不包含节假日服务费和跨城费），加节假日服务费和跨城费，再减商家优惠；

API 商家优惠按负值口径处理。在当前样本 SQL 中，该价格对应 `pas_total_fee_amt`。

白皮书中，应付折叠 A 命中后的折叠对象是“所有品类”，应付折叠 B 命中后的折叠对象是“可控运力”。当前 SQL 是在车型行粒度判断，

没有在 `trace_id` 内将应付折叠结果广播到上述整体对象。

### 2.8 构造方式：模拟扩展进特价盒子

候选车型必须同时满足：

1. `hybrid_fold=1`；

2. 不是 `105/202/201/107` 盒子品类；

3. 当前折扣组合存在 `uabox_min_show`，且 `payable_fee_amt<=uabox_min_show`。

商家去重规则：

- 一般商家：若该 `product_id` 已在特价盒子中，则不再扩展；

- `product_id=80` 的小猪自营单独处理：

	- 小猪特价已在盒子中时，`level_type=104` 不再扩展；

	- 其他小猪品类仍可扩展。

当前 `v2` 代码以 `hybrid_fold=1` 作为扩展入口，因此价格折叠和线上非价格折叠车型都可能进入扩展判断。

### 2.9 构造方式：展示单元

当前代码先把车型行转换为展示单元。

盒子品类 `105/200/202/201/107` 各自按 `level_type` 单独成组，不参与同价合并：

```text
display_group_id = BOX#level_type
```

扩展车型使用单独的回挂规则：

```text
is_box_extended=1
→ display_group_id='BOX#105'
```

扩展车型不参与 `display_group` 和 `display_ranked` 的聚合，因此不会改变 105 特价盒子展示单元的展示价、最低实付、置顶或排名；最终落表时再通过 `BOX#105` 复用其 `car_rank`。

其他品类按以下字段合并：

```text
show_fee_amt
× 计价模式组（一口价 0/1；实时计价其他）
```

仅 `hybrid_fold=0` 的原始可见行构造展示单元。折叠后扩展进盒子的子车型不形成自己的展示单元和独立 `car_rank`，但 `is_box_extended=1` 时允许回挂 `BOX#105` 的已有排名。

当前回挂目标固定为 `BOX#105`，而特价盒子参考价允许由 `105/201/202` 任一品类形成。因此，只有 201/202 或 105 不可见的边界下，扩展行可能找不到 `BOX#105` 并得到空 `car_rank`。这是当前代码边界，不应在文档中把“所有扩展车型一定已有 rank”写成已验证事实。

### 2.10 构造方式：置顶

对每个 `trace_id × luckybox_discount × uabox_discount`，当前代码只计算一个置顶比较基准：

```text
min_visible_payable
= min(所有 hybrid_fold=0 原始可见行的 payable_fee_amt)
```

扩展行不进入该最低实付集合。历史实现曾拆成表达式相同的 `min_r1/min_r2`，当前 `v2` 已合并为 `min_visible_payable`。

置顶规则：

1. 可见幸运盒子组的最低实付等于 `min_visible_payable` 时，幸运盒子置顶；

2. 否则，可见特价盒子族组的最低实付等于 `min_visible_payable` 时置顶；

3. 当幸运盒子已占据同一最低实付价位时，特价盒子族不再置顶；

4. 最终只有 `107/105/202/201` 四类盒子可能输出 `is_top=1`。

### 2.11 构造方式：同价合并和排序

非盒子、混合未折叠车型按以下键统计可见车型数：

```text
trace_id
× luckybox_discount
× uabox_discount
× show_fee_amt
× 计价模式组
```

组内车型数大于 1 时，输出 `is_merged=1`。盒子品类不参与合并。

当置顶状态、展示价格和展示单元最低实付均相同时，才按以下品类优先级继续排序：

```text
幸运盒子 107
> 小猪特价 104
> 特价盒子 105
> 超值达 201
> 小猪一口价/打车 102/103
> 出行优选盒子 202
> 实时计价品类 0
> 小猪特快 101
> 特快盒子 200
> 其他
```

`car_rank` 在展示单元层使用 `dense_rank`，排序键依次为：

1. 是否置顶；

2. 展示单元价格；

3. 展示单元最低实付；

4. 品类优先级。

同一非盒子合并组的车型共享一个 `car_rank`。最终排名回挂分两类：

- `hybrid_fold=0`：按自身 `display_group_id` 取得 `car_rank`；

- `is_box_extended=1`：按固定的 `BOX#105` 尝试复用 105 特价盒子 `car_rank`；

- `hybrid_fold=1 AND is_box_extended=0`：不参与展示，`car_rank=null`。

### 2.12 写入价格列表

价格列表最终输出：

- 主键：`trace_id`、`luckybox_discount`、`uabox_discount`、`estimate_id`；

- 车型：`product_id`、`level_type`、`price_type`；

- 金额：`pas_total_fee_amt`、`payable_fee_amt`、`show_fee_amt`、`non_deductible_fee_amt`、`uabox_coupon_cost`；

- 表单状态：`is_folded`、`is_box_extended`、`is_top`、`is_merged`、`car_rank`。

### 3.3 构造方式：选择 detail 日志空间

#### 3.3.2 detail 折扣组合

#### 3.3.3 RCT 日志来源选择

分别统计首次日志和样本日志中的保留折扣组合数，当前 SQL 的优先级为：

1. `sample_trace_id` 的保留组合数大于 1：选择样本日志；

2. 否则，`first_trace_id` 的保留组合数大于 1：选择首次日志；

3. 两侧均缺失或均只有 0/1 个保留组合：该 RCT 样本不进入后续动作空间。

两侧统计使用 `LEFT JOIN`，任一侧缺失不会阻断另一侧判断。

OBS 不做样本/首次 trace 映射，直接使用样本自己的 `trace_id` 读取 detail。

#### 3.3.4 保留组合和幸运盒子优先

常规组合必须存在至少一条保留记录。唯一例外仅适用于 OBS：

```text
当前 trace 只有一个折扣组合
AND uabox_discount = 100
AND luckybox_discount = 100
AND 该组合没有保留记录
```

此时仍保留 `100/100` 作为兜底。

随后应用幸运盒子优先规则：

- 若当前 trace 存在任一 `luckybox_discount<>100` 的组合，删除全部 `luckybox_discount=100` 的组合；

- 若不存在可见幸运盒子组合，保留当前全部组合。

### 3.4 构造方式：可行默勾决策空间与序列特征折扣

本节将 detail 中保留的折扣组合与价格列表求交，完成两项构造：一是确定 28 组折扣各自是否可行，以及每组折扣下能够默勾到的最大展示位置；二是从全部可行折扣组合中选择一组，作为后续价格、实时供给和历史供给序列特征共同使用的折扣。两类结果的关系如下：

| 构造结果 | 构造内容 | 输出字段 | 下游用途 |
| --- | --- | --- | --- |
| 完整的可行默勾决策空间 | 逐一判断 28 组折扣是否能够生成可见价格列表，并记录该折扣下的最大可见位置 `k_max` | `decision_k_max\_\*` | 表示各折扣组合是否可选，以及选择该折扣时允许使用的最大默勾位置 |
| 序列特征使用的折扣 | 从完整可行决策空间中选择唯一一组折扣，并保留该组合的 `k_max` | `sequence_luckybox_discount`、`sequence_uabox_discount`、`sequence_k_max` | 确定价格、实时供给和历史供给序列按哪组折扣及位置范围构造 |

#### 3.4.1 构造每组折扣的可行默勾决策空间

价格列表先在 `trace_id × luckybox_discount × uabox_discount` 粒度，按以下条件统计每组折扣的最大可见位置：

```text
dt = T
AND (is_folded = 0 OR is_box_extended = 1)
AND car_rank <= 20

k_max = max(car_rank)
```

`k_max` 表示当前折扣组合下可以默勾到的最大展示位置。`is_box_extended=1` 的扩展车型不会增加独立位置：若成功回挂 `BOX#105`，它复用已有盒子位置；若没有匹配到可见的 `BOX#105`，其 `car_rank` 为 `null`，不会进入 `k_max` 聚合。

随后，将已经执行兜底和幸运盒子优先规则的 detail 折扣组合，与价格列表统计结果按以下键做 `INNER JOIN`：

```text
trace_id
× luckybox_discount
× uabox_discount
```

只有同时存在于 detail 保留空间和价格列表中的折扣组合，才进入可行默勾决策空间。28 组折扣分别对应一个固定的 `decision_k_max_*` 字段：能够生成可见价格列表的组合写入其 `k_max`，不能生成可见价格列表的组合写入 `-1`。因此，全部 `decision_k_max_*` 字段共同表达完整的可行默勾决策空间，而不是仅记录最终选中的一组折扣。

同一价格列表聚合还为每组可行折扣保留特价盒子 cost：仅从 `is_folded=0` 且 `level_type in (105,201,202)` 的展示行读取 `uabox_coupon_cost`，同组多行通过 `max` 收敛。扩展车型可以参与 `k_max` 的位置覆盖，但不会单独提供该 cost。

#### 3.4.2 选择序列特征使用的唯一折扣

序列特征不会分别展开 28 组折扣，而是从上述完整可行决策空间中选择唯一一组。可行组合先按以下顺序排序，再取第一组作为价格、实时供给和历史供给序列共同使用的折扣：

```text
luckybox_discount DESC
uabox_discount DESC
```

| 字段 | 写入值 |
| --- | --- |
| `sequence_luckybox_discount` | 该组合的幸运盒子折扣 |
| `sequence_uabox_discount` | 该组合的特价盒子折扣 |
| `sequence_k_max` | 该组合的最大可见位置 |

因此，`sequence_*` 不是另一套独立的折扣决策空间，而是从 `decision_k_max_*` 所表达的完整可行空间中选出的一组折扣及其最大可见位置。幸运盒子优先已经在 detail 阶段完成：一旦存在 `luckybox_discount<>100` 的组合，`luckybox_discount=100` 的组合已经被删除。

### 3.5 构造方式：还原真实 Treatment

每条样本的真实 Treatment 由实际幸运盒子折扣、实际特价盒子折扣和实际默勾位置数组成：

```text
actual_luckybox_discount
actual_uabox_discount
actual_anchor_select_cnt
```

两个实际折扣直接取自 `plft_v4_bubble_sample`。实际默勾位置数不直接使用日志中的 `anchor_select_cnt`，而是先取得真实价格锚点，再在这组实际折扣对应的价格列表上反算。只使用 `is_folded=0` 的真实展示行，同一 `car_rank` 合并为一个展示位置；盒内扩展车型跟随特价盒子，不单独参与价格判断。

RCT 和 OBS 的锚点含义不同，因此反算条件也不同：

| 样本类型 | 价格锚点来源 | 展示位置命中条件 | 后处理 |
| --- | --- | --- | --- |
| RCT | `plft_v4_bubble_sample.price_anchor_point` | `show_fee_amt &lt;= floor(actual_price_anchor_point / 100.0) × 100`，或 `payable_fee_amt &lt;= actual_price_anchor_point` | 不修正 |
| OBS | 有效冒泡记录按 `trace_id` 取 `max(price_anchor_point)` | `show_fee_amt &lt;= actual_price_anchor_point` | 特定幸运盒子单勾场景由 2 修正为 1 |

同一展示位置只要有一条真实展示行满足对应条件，就认为该位置被锚点命中。初始默勾位置数取所有命中位置中最大的 `car_rank`，没有命中则为 0：

```text
anchor_initial_select_cnt
= max(anchor_selected=1 的 car_rank，未命中按 0)
```

OBS 还需复现 Athena 的幸运盒子单勾规则：如果锚点初始恰好命中前两个展示位置，且第 1 位是幸运盒子、第 2 位是特价盒子、没有命中其他车型，则将 `actual_anchor_select_cnt` 从 2 修正为 1；其他 OBS 和全部 RCT 均直接使用 `anchor_initial_select_cnt`。

完成反算后，仅保留实际折扣组合属于可行决策空间、`actual_anchor_select_cnt` 位于 `0` 到该组合 `k_max` 之间，并且能够选出序列特征折扣的样本。`log_anchor_select_cnt` 只用于独立对照，不作为训练 Treatment。OBS 锚点反算仍属于当前 SQL 的构造近似，相关边界差异继续在验证文档中跟踪。

### 3.6 构造方式：真实特价盒子 cost

动作空间在真实折扣组合和真实默勾位置通过可行性约束后，从该真实组合携带的 `uabox_coupon_cost` 构造：

```text
actual_uabox_cost
= if(is_uabox_finish=1, coalesce(uabox_coupon_cost, 0), 0)
```

其中 `uabox_coupon_cost` 沿用价格列表中的计算结果和 2000 分上限。该字段只在真实特价盒子完单时保留 cost；未完单，或真实组合未取得未折叠特价盒子展示行 cost 时，均写 0。最终训练样本直接透传该字段，不在最终宽表再次计算。

### 6.2 构造方式：位置骨架和输入

序列特征 SQL 使用动作空间层选定的：

价格列表只读取：

```text

AND (is_folded = 0 OR is_box_extended = 1)
AND car_rank between 1 and 20
```

因此成功回挂 `BOX#105` 的扩展车型会从特价盒子所在位置开始参与价格位置聚合和商家累计，但不会形成额外位置；未取得 `car_rank` 的扩展车型不会进入序列。

有效位置判断：

```text
pos <= sequence_k_max  → 有效位置
pos > sequence_k_max   → padding
```

每个位置固定 42 个字段：

### 6.3 构造方式：每个位置的 8 个价格表单特征

同一 `trace_id × car_rank` 下可能有多个车型明细，按以下方式聚合：

| 输出字段 | 计算方式 |
| --- | --- |
| `avg_after_pre_coupon_fee_amt` | `avg(basic_total_fee_amt-pre_dis_amt-trip_cloud_discount_fee_amt+spring_festival_fee_amt+dups_cross_city_fee)` |
| `avg_pas_total_fee_amt` | `avg(pas_total_fee_amt)` |
| `avg_show_fee_amt` | `avg(show_fee_amt)`，但排除 `is_box_extended=1` 的扩展子车型 |
| `avg_pre_dis_amt` | `avg(pre_dis_amt)` |
| `merchant_cnt` | `count(distinct product_id)` |
| `category_type` | 每条车型先按下表映射，再对同一位置取最小枚举 |
| `is_box` | 每条车型先映射盒子标记，再对同一位置取最小值 |
| `price_type` | 每条车型映射为一口价 0、实时计价 1、未知 `-9999`，再对同一位置取最小值 |

除 `avg_show_fee_amt` 外，当前位置聚合会纳入成功回挂到该 `car_rank` 的扩展车型。因此：

- `avg_after_pre_coupon_fee_amt`、`avg_pas_total_fee_amt`、`avg_pre_dis_amt` 和 `merchant_cnt` 会包含扩展子车型；

- `avg_show_fee_amt` 只由原始展示行计算，避免使用扩展车型自己的展示价改变盒子位置价格；

- `category_type`、`is_box`、`price_type` 按同一位置全部明细取 `min`。当特价盒子位置同时包含非盒子扩展车型时，输出值取决于两类明细的最小映射值，不能只按盒子原始行理解。

`category_type` 映射：

| `level_type` | `category_type` |
| --- | ---: |
| `200` | 0 |
| `101` | 1 |
| `0` | 2 |
| `102` | 3 |
| `103` | 4 |
| `104` | 5 |
| `105/201/202` | 6 |
| `107` | 7 |
| 其他 | 8 |

`is_box=1` 的品类为：

```text
level_type in (200, 105, 201, 202, 107)
```

这里是单条车型的映射规则；位置最终值仍按上文所述对同一 `car_rank` 的全部明细取 `min`。

`price_type` 映射：

```text
原 price_type in (0,1) → 0（一口价）
原 price_type = 2      → 1（实时计价）
其他                    → -9999
```

### 6.4 构造方式：按交易优先级生成每个位置的去重商家集合

本节先汇总位置 `pos` 内所有 `car_rank<=pos` 的车型，再在 `trace_id × pos × product_id` 粒度按照交易优先级排序，每个商家只保留优先级最高的真实发单品类，由此得到每个位置的去重商家集合。后续实时供给和历史供给序列均基于这套商家集合聚合。

#### 通用绝对优先级

宏鹄、API 和花小猪接入非自营商家使用同一套绝对优先级，即 `platform_id in (1,4,5)` 且 `product_id<>80`：

```text
特快盒子 200
> 实时计价品类 0
> 出行优选盒子 202
> 超值达 201
> 特价盒子 105
> 幸运盒子 107
> 其他
```

#### 小猪自营：`product_id=80`

`platform_id=5` 只表示花小猪接入平台，不能直接等同于小猪自营。只有 `product_id=80` 使用相对优先级、应付价和绝对优先级三层排序。

先按相对优先级分组：

```text
第 1 组：200、101
第 2 组：202、102、103
第 3 组：201
第 4 组：105、104
第 5 组：107
```

同一商家先选择相对优先级更高的分组；同组内选择 `pas_total_fee_amt` 更高的品类，空值排在有效价格之后；同组且同价时再按以下绝对优先级选择：

```text
200
> 101
> 202
> 102/103
> 201
> 105
> 104
> 107
> 其他
```

最终每个 `trace_id × pos × product_id` 只保留一条记录。实时和历史累计特征共用这一商家集合。

扩展车型与 105 盒子共享 `car_rank` 后，会从该盒子位置开始进入 `car_rank<=pos` 的累计商家集合；同一 `product_id` 若同时出现在多个品类，仍按本节优先级只选一个真实发单品类。排序不使用 `car_rank` 或 `level_type` 作为额外兜底，未映射品类和最高优先级并列由独立检查 SQL 跟踪。

### 7.2 构造方式：主集合和准入过滤

最终 SQL 以动作空间表为唯一主集合，并在进入十张特征源关联前完成样本准入过滤。

首先剔除乘客标识无效的样本：

```text
passenger_id is null
或 passenger_id = 0
```

然后剔除三类 Label 冲突：

1. 完单但未呼叫；

2. 完单但 GMV 为空或不大于 0；

3. 默勾接受但未呼叫。

上述过滤只作用于最终训练样本，不删除车型表、冒泡样本、价格列表、动作空间表和序列特征表中的原始记录。因此，中间表到最终表的集合差异需要按这四类准入条件解释，不能直接要求最终表与未过滤的动作空间表完全相等。

序列特征在最终准入过滤之前已经按动作空间全集生成。最终 SQL 以过滤后的 `action_space_source` 为唯一主集合，`LEFT JOIN` 序列和其他特征；因此被最终准入剔除的 trace 可以继续保留在动作空间和序列中间表中，但不会落入最终训练样本。

十张特征源是否命中不属于准入条件。车型、乘客历史、城市历史、冒泡 SDS 或序列特征未命中时，样本不会因此被删除，而是按最终缺失值规则填充。

### 7.4 构造方式：缺失值

特征源未命中或字段为空时，最终 SQL 按目标字段类型统一填充 `-9999`。Label、Treatment、主键和从动作空间直接透传的 `actual_uabox_cost` 不依赖该填充规则。业务上真实的数值 0 不会被改写为 `-9999`。

序列与非序列字段需要分开理解：

- 序列中 `pos>sequence_k_max` 的 padding 固定为 `-9999`；

- 序列有效位置若价格、SDS 原始量缺失，或派生指标分母为 0，也会写为 `-9999`；

- 非序列特征源未命中或源字段为空时，在最终 `LEFT JOIN` 后写为 `-9999`；

- `uabox_after_pre_coupon_fee_amt` 未命中特价盒子族车型，或聚合结果为空时写 `-9999`；`actual_uabox_cost=0` 则表示未发生特价盒子完单或未取得 cost，不改写为缺失值；

- P 维度乘客历史未命中不会触发样本剔除，对应字段按缺失值规则写为 `-9999`；源表中的有效数值 0 按业务值原样透传。

| 类别 | 问题或不一致点 | 解决方案 |
| --- | --- | --- |
| 车型原始信息 | 冒泡底表 `level_type=0` 的 `price_type=0` ，全部为兜底值 | 使用dups侧日志的price_type替代，并与DE沟通，修复冒泡表price_type字段。 |

| 价格计算 | 实付金额差1分，原因是离线对优惠金额使用了四舍五入，在线为向下取整 | 优惠金额向下取整、实付向上取整 |
| 特价盒子优惠金额不一致，原因是在线存在优惠金额上限 | 基于apollo配置生成分城市优惠金额上限 |
| 实付低于1元时，展示价格不一致，原因是实付低于1元时，不再沿用向下取整的逻辑 | 与API侧保持一致的兜底逻辑 <br>- 四舍五入到角：如果实付价格（非0）四舍五入到角的结果为0，则强制转成0.1元 <br><br>- 四舍五入到元：如果实付价格（非0）四舍五入到元的结果为0，则强制转成1元 <br><br>- 向下取整到元：如果实付价格（非0）向下取整到元的结果为0，则强制转成1元 <br> |

| 扩展 | 扩展车型的进扩展条件为「实付低于特价盒子实付」，未明确是&lt;还是&lt;= | 通过一致性判断，是&lt;= |

| 置顶 | 离线构造置顶含义为「表单排序第一」，冒泡表置顶字段的含义为「原本排序不是第一、但置顶为第一」 | 不再比较置顶字段，只比较排序字段 |
| 错误以「折叠进扩展」的特价盒子最低实付价判断置顶逻辑 | 仅以特价盒子本身的最低实付价判断置顶逻辑 |
