## 1. 一页结论

| 问题 | `2026-07-20` 分区规模 | 根因 | 处理结论 |
| --- | ---: | --- | --- |
| `actual_anchor_select_cnt=0` | OBS `401` 条，RCT `423` 条，合计 `824 / 1,189,578 = 0.069268%` | SQL 在无展示位命中锚点时回填 `0`；实际由离线价格重建与线上折叠不一致、RCT 锚点来源不一致和极少量原始选中行缺失导致 | 按异常数据处理；训练和策略评估前直接剔除，不将 `0` 解释为第一个有效默勾动作 |
| `uabox_after_pre_coupon_fee_amt=-9999` | OBS `21,694` 条，RCT `5,270` 条，合计 `26,964 / 1,189,578 = 2.266686%`；RCT 占比 `2.265001%` | 字段只从 `level_type in (105,201,202)` 构造；本分区的缺失样本全部没有这三类特价盒子目标车型，因此是 join 未命中后的哨兵值，不是价格本身为 `-9999` | 不剔除； <br>- 标记为“无特价盒子”，有效特价盒子/幸运盒子折扣均归一为 `100` <br><br>- 只保留 `(lucky=100,uabox=100,mogou=k)` 动作； <br><br>- 在 uplift 指标中只评估 BR-DC <br> |

本文所有数量和比例都按 `count(distinct trace_id)` 统计。当前最终样本分区共有 `1,189,587` 行、`1,189,578` 个去重 trace，存在 `9` 行额外重复；为避免重复行放大异常率，本文统一使用去重 trace 口径。

## 2. `actual_anchor_select_cnt=0`

### 2.1 数据分布

| 样本类型 | 去重 trace 数 | `actual_anchor_select_cnt=0` | 占比 |
| --- | ---: | ---: | ---: |
| OBS | 956,907 | 401 | 0.041906% |
| RCT | 232,671 | 423 | 0.181802% |
| 合计 | 1,189,578 | 824 | 0.069268% |

RCT 的零值率约为 OBS 的 `4.34` 倍，但两类样本的根因结构不同。

### 2.2 SQL 为什么会产生 `0`

[动作空间 SQL](../../../02.%20%E4%BA%A4%E6%98%93%E4%B8%93%E9%A1%B9%E4%B8%8E%E6%A8%A1%E5%9E%8B%E8%87%AA%E8%BF%9B%E5%8C%96/03.%20%E4%BB%B7%E6%A0%BC%E9%94%9A%E7%82%B9/07.%20%E5%B9%B3%E5%8F%B0%E8%81%94%E5%90%88%E5%86%B3%E7%AD%96/%E5%B9%B3%E5%8F%B0%E8%A1%A5%E8%B4%B4%E4%B8%8E%E6%B5%81%E9%87%8F%E5%88%86%E5%8F%91%E8%81%94%E5%90%88%E5%86%B3%E7%AD%96V4/BCR%E6%A8%A1%E5%9E%8B/%E6%A0%B7%E6%9C%AC-%E4%BB%B7%E6%A0%BC%E5%88%97%E8%A1%A8%E6%9E%84%E9%80%A0/sql/plft_v4_training_sample_action_space.sql) 使用如下逻辑反算锚点选中的最大展示位：

```sql
max(
    case
        when anchor_selected = 1 then car_rank
        else 0
    end
) as anchor_initial_select_cnt
```

因此 `0` 不是一个来自业务日志的正常默勾数，而是“当前离线价格列表中没有任何展示位命中样本锚点”时的聚合回退值。下游又使用 `actual_anchor_select_cnt between 0 and k_max` 作为准入条件，所以 `0` 会通过动作空间的现有过滤。

### 2.3 根因拆分

824 条零值样本可拆为三类：

| 根因 | OBS | RCT | 合计 | 证据结论 |
| --- | ---: | ---: | ---: | --- |
| 离线价格重建/折叠与线上选中结果不一致 | 400 | 15 | 415 | 线上选中车型在原始行中存在，但在当前离线重建价格列表中被价格折叠；这 `415` 条均不是继承线上非价格折叠导致 |
| RCT 样本锚点与 Bubble/价格列表锚点来源不一致 | 0 | 408 | 408 | 选中位置在离线价格列表中仍可见；样本锚点无法解释实际选中，Bubble 锚点可解释全部 `423` 条 RCT 零值样本的原始选中 |
| 原始选中行缺失，尚未完全闭环 | 1 | 0 | 1 | OBS 样本的日志锚点为正，但无法在原始车型行中定位对应选中车型 |

RCT 锚点下钻中，Bubble 锚点与样本锚点相等的 trace 为 `0`：`408` 条 Bubble 锚点高于样本锚点，`15` 条 Bubble 锚点低于样本锚点。样本锚点只能命中 `15` 条原始选中，Bubble 锚点能命中全部 `423` 条原始选中。

### 2.4 数据处理决策

1. 训练和策略评估前剔除 `actual_anchor_select_cnt <= 0` 的样本。

2. 保留剔除数量及 OBS/RCT 分布监控，避免上游口径变化后异常率扩大。

3. 不将 SQL 中的数量 `0` 直接当作模型动作下标 `0`。SQL 字段表示默勾位置数，若模型使用 `0..L-1` 的下标编码，必须在适配层明确完成“位置数 → 动作下标”的转换。

4. 根因修复需分别统一离线/线上价格折叠逻辑与 RCT 锚点来源；在修复和目标分区重刷验证完成前，不将零值样本恢复到训练集。

## 3. `uabox_after_pre_coupon_fee_amt=-9999`

### 3.1 数据分布

| 样本类型 | 去重 trace 数 | 价格为 `-9999` | 占比 |
| --- | ---: | ---: | ---: |
| OBS | 956,907 | 21,694 | 2.267096% |
| RCT | 232,671 | 5,270 | 2.265001% |
| 合计 | 1,189,578 | 26,964 | 2.266686% |

OBS 和 RCT 的缺失率接近，说明该现象不是 RCT 独有的随机实验日志问题。

### 3.2 SQL 为什么会产生 `-9999`

[最终样本 SQL](../../../02.%20%E4%BA%A4%E6%98%93%E4%B8%93%E9%A1%B9%E4%B8%8E%E6%A8%A1%E5%9E%8B%E8%87%AA%E8%BF%9B%E5%8C%96/03.%20%E4%BB%B7%E6%A0%BC%E9%94%9A%E7%82%B9/07.%20%E5%B9%B3%E5%8F%B0%E8%81%94%E5%90%88%E5%86%B3%E7%AD%96/%E5%B9%B3%E5%8F%B0%E8%A1%A5%E8%B4%B4%E4%B8%8E%E6%B5%81%E9%87%8F%E5%88%86%E5%8F%91%E8%81%94%E5%90%88%E5%86%B3%E7%AD%96V4/BCR%E6%A8%A1%E5%9E%8B/%E6%A0%B7%E6%9C%AC-%E4%BB%B7%E6%A0%BC%E5%88%97%E8%A1%A8%E6%9E%84%E9%80%A0/sql/plft_v4_training_sample.sql) 先在车型表中限制 `level_type in (105,201,202)`，按 trace 计算：

```sql
max(basic_total_fee_amt) - max(pre_dis_amt)
```

然后将该结果左关联到最终样本，并使用：

```sql
coalesce(up.uabox_after_pre_coupon_fee_amt, -9999)
```

因此 `-9999` 表示子查询没有产生可关联的特价盒子价格。对 `2026-07-20` 分区全量下钻后，`26,964` 条缺失 trace 均没有 `level_type in (105,201,202)` 的目标车型，因此本分区的实际根因是无特价盒子导致的 join miss，而不是目标车型价格字段存储了 `-9999`。

`level_type=104` 是小猪特价，不属于当前这个特价盒子价格字段的目标范围。

### 3.3 RCT 缺失样本下钻

| 特征 | trace 数 | 占 5,270 条 RCT 缺失样本比例 |
| --- | ---: | ---: |
| 原始下发 `actual_uabox_discount &lt; 100` | 4,462 | 84.67% |
| 原始下发 `actual_uabox_discount = 100` | 808 | 15.33% |
| 只存在 `level_type=104`，不存在 105/201/202 | 2,530 | 48.01% |
| 104 和 105/201/202 都不存在 | 2,740 | 51.99% |
| 存在 105/201/202 | 0 | 0% |
| `is_uabox_finish=1` | 0 | 0% |
| `actual_uabox_cost&gt;0` | 0 | 0% |

RCT 中的 `4,462` 条非 100 折是随机系统记录的原始下发动作，但由于表单实际没有特价盒子，该折扣没有业务承接对象。它们应保留为原始实验分配字段供审计，但不能当作实际生效的特价盒子折扣。

### 3.4 OBS 缺失样本下钻

| 特征 | trace 数 |
| --- | ---: |
| `actual_uabox_discount = 100` | 21,670 |
| `actual_uabox_discount &lt; 100` | 24 |
| `is_uabox_finish=1` | 2 |
| `actual_uabox_cost&gt;0` | 0 |

OBS 中有 `2` 条“无目标特价盒子车型，但标记特价盒子完单”的强不一致样本，不应与正常的无盒子样本合并解释。在完单品类和价格列表折叠语义闭环前，建议对这 `2` 条单独剔除或建立异常监控。

### 3.5 业务和评估口径

[平台品类白皮书](../../../02.%20%E4%BA%A4%E6%98%93%E4%B8%93%E9%A1%B9%E4%B8%8E%E6%A8%A1%E5%9E%8B%E8%87%AA%E8%BF%9B%E5%8C%96/03.%20%E4%BB%B7%E6%A0%BC%E9%94%9A%E7%82%B9/raw/sources/v4/00_%E9%A1%B9%E7%9B%AE%E6%80%BB%E8%A7%88/2026-08-03_%E5%B9%B3%E5%8F%B0%E5%93%81%E7%B1%BB%E7%99%BD%E7%9A%AE%E4%B9%A6_v01.md) 明确记录：表单无特价盒子时，幸运盒子不展现。因此这类样本的有效盒子动作应收缩为：

```text
effective_uabox_discount = 100
effective_luckybox_discount = 100
effective_action = (lucky=100, uabox=100, mogou=k)
cost = 0
```

这里的 `effective_*` 是评估和求解口径，不覆盖原始日志中的随机分配折扣。

在策略 uplift 指标中：

| 指标 | 是否参与 | 原因 |
| --- | --- | --- |
| MTAUCC | 否 | 没有特价盒子和有效非 100 折 treatment，也没有可定义的特价盒子补贴成本轴 |
| MTAUPC | 否 | 幸运盒子不展现，不存在可评估的幸运盒子折扣变化 |
| BR-DC | 是 | [BR-DC 的设计目的](../../../02.%20%E4%BA%A4%E6%98%93%E4%B8%93%E9%A1%B9%E4%B8%8E%E6%A8%A1%E5%9E%8B%E8%87%AA%E8%BF%9B%E5%8C%96/03.%20%E4%BB%B7%E6%A0%BC%E9%94%9A%E7%82%B9/raw/sources/v4/05_%E5%AE%9E%E9%AA%8C%E4%B8%8E%E8%AF%84%E4%BC%B0/%E5%B9%B3%E5%8F%B0%E8%81%94%E5%90%88%E5%86%B3%E7%AD%96V4%E8%AF%84%E4%BC%B0%E6%8C%87%E6%A0%87.md) 就是评估 cost=0 场景下模型最优决策相对随机决策的完单率增益；本场景实际上只比较不同默勾数 |

如果某条样本只有一个可行默勾动作，则模型最优动作与随机动作没有可比较空间，该样本不参与 BR-DC，但仍可参与 BCR/ECR/DSAR 等普通任务指标。

### 3.6 当前实现风险与待落地项

1. [当前动作空间 SQL](../../../02.%20%E4%BA%A4%E6%98%93%E4%B8%93%E9%A1%B9%E4%B8%8E%E6%A8%A1%E5%9E%8B%E8%87%AA%E8%BF%9B%E5%8C%96/03.%20%E4%BB%B7%E6%A0%BC%E9%94%9A%E7%82%B9/07.%20%E5%B9%B3%E5%8F%B0%E8%81%94%E5%90%88%E5%86%B3%E7%AD%96/%E5%B9%B3%E5%8F%B0%E8%A1%A5%E8%B4%B4%E4%B8%8E%E6%B5%81%E9%87%8F%E5%88%86%E5%8F%91%E8%81%94%E5%90%88%E5%86%B3%E7%AD%96V4/BCR%E6%A8%A1%E5%9E%8B/%E6%A0%B7%E6%9C%AC-%E4%BB%B7%E6%A0%BC%E5%88%97%E8%A1%A8%E6%9E%84%E9%80%A0/sql/plft_v4_training_sample_action_space.sql) 只将日志折扣组合与离线价格组合取交集，没有在 `has_uabox=0` 时将非 `(100,100)` 的折扣组合统一 mask 为不可行。

2. [当前 uplift 评估代码](../../../02.%20%E4%BA%A4%E6%98%93%E4%B8%93%E9%A1%B9%E4%B8%8E%E6%A8%A1%E5%9E%8B%E8%87%AA%E8%BF%9B%E5%8C%96/03.%20%E4%BB%B7%E6%A0%BC%E9%94%9A%E7%82%B9/07.%20%E5%B9%B3%E5%8F%B0%E8%81%94%E5%90%88%E5%86%B3%E7%AD%96/%E5%B9%B3%E5%8F%B0%E8%A1%A5%E8%B4%B4%E4%B8%8E%E6%B5%81%E9%87%8F%E5%88%86%E5%8F%91%E8%81%94%E5%90%88%E5%86%B3%E7%AD%96V4/code/union_v4_bcr/evaluation/evaluation_uplift.py) 使用 `BCR × p_u_prime × (1-uabox_discount/100)` 计算候选动作 cost。若 `p_u_prime=-9999` 且仍保留非 100 折动作，会产生负 cost，污染 MTAUCC 的成本排序。

3. 当前 `evaluate_br_dc` 直接用原始 `actual_uabox_discount == 100` 过滤零成本样本。若不构造有效动作字段，RCT 中 `4,462` 条“原始下发非 100 折、但实际无特价盒子”的样本会被 BR-DC 直接漏掉。

4. 评估适配层应保留 `raw_actual_uabox_discount` / `raw_actual_luckybox_discount`，另行产出 `effective_uabox_discount` / `effective_luckybox_discount`。

5. `has_uabox=0` 时只保留 `decision_k_max_uabox_100_lucky_100`，其余 27 个折扣组合均设为不可行。

6. 将原始随机折扣合并为有效 `(100,100,mogou)` 动作后，需校验各默勾动作的实际分配概率；如果不等概率，BR-DC 应使用合并后的 propensity 加权，不能默认均匀随机。

`-9999` 本身不应长期充当动作可行性字段。后续应优先增加明确的 `has_uabox`/盒子可行性信号；对未来分区，应先用该信号判断是否存在特价盒子，而不是只凭价格哨兵值反推。

## 4. 数据准入与评估规则

建议按以下顺序处理：

```text
1. 先剔除 actual_anchor_select_cnt <= 0
2. 识别 has_uabox
3. has_uabox = 0：
    - effective_uabox_discount = 100
    - effective_luckybox_discount = 100
    - 只保留 (100,100,mogou) 动作
    - cost = 0
    - uplift 只参与 BR-DC
4. has_uabox = 1：
    - 使用正常特价盒子价格和折扣动作
    - 按可行空间参与 MTAUCC / MTAUPC / BR-DC
5. 无论是否有盒子，原始实验分配字段均保留供追溯
```

需特别注意：“`actual_uabox_discount=100` 只评估 BR-DC”不是一条可对全部样本通用的规则。若表单实际存在特价盒子，100 折样本还可能作为 MTAUCC 的控制样本。本文的“只评估 BR-DC”结论同时依赖两个条件：

1. `has_uabox=0`；

2. 无特价盒子时幸运盒子不展现。

## 6. 实施状态

本文只记录排查结论和已确认的处理口径，本次未修改生产 SQL、训练预处理或 uplift 评估代码。下列项仍属于待实施/待复验：

- 训练入口剔除 `actual_anchor_select_cnt<=0`；

- 无特价盒子的显式标记和动作空间收缩；

- 原始折扣与有效折扣字段分离；

- BR-DC 使用有效动作和合并后分配概率；

- 目标分区重刷后复核样本数、动作 mask、cost 非负性和三类 uplift 指标的入样边界。
