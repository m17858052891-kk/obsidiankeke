## 4 获取price_list

目的：获取决策空间的候选折扣，及每个折扣组合的价格列表

对决策空间折扣组合全集的每个折扣组合：

1. 获取平台呼返、特价盒子呼返的最深折扣、最浅折扣、CAP值（最大优惠额），key为city_id

	1. 来源[apollo](https://ab.intra.hongyibo.com.cn/conf/37/3956/4736/256776)参数「platform_activity_conf」

```PlainText
"0": { -- 代表全国
    "platform": {
      "max_subsidy_amount": 2000, -- 最大优惠额 CAP值，2000代表20元
      "min_subsidy_amount": 0, -- 最小优惠额
      "max_discount": 100, -- 最浅折扣
      "min_discount": 50, -- 最深折扣
      "limit_low_price": false,
      "low_price": 0,
      "subsidy_type": 100
    },
    "uabox": {
      "max_subsidy_amount": 2000,
      "min_subsidy_amount": 0,
      "max_discount": 100,
      "min_discount": 50,
      "limit_low_price": false,
      "low_price": 0,
      "subsidy_type": 100
    }
```

2. 获取品类列表category_list，每个品类的basic_total_fee、前置最大优惠金额、不可抵扣费项（e.g. 节假日费用），前置优惠后金额=basic_total_fee - 前置最大优惠金额

3. 计算呼返优惠金额

	1. 对出行快选、特价盒子、超值达盒子，呼返优惠金额=min(CAP值，前置优惠后金额 X 特价盒子折扣）

	2. 对幸运盒子，呼返优惠金额=前置优惠后金额 X 幸运盒子折扣

	3. 对其他，呼返优惠金额 = 前置优惠后金额 X 平台呼返折扣；**特殊处理，若是API商家，呼返优惠金额=0**

4. 计算每个品类

	1. 实付estimate_fee = basic_total_fee - 前置最大优惠金额 - 呼返优惠金额 + 不可抵扣费项

	2. 应付need_fee = basic_total_fee + 不可抵扣费项

	3. 实付展示价格 show_fee = 对estimate_fee取整，一口价向上取整到角，实时计价向下取整到元

		- price_type：0-司乘一口价；1乘客一口价、司机实时计价；2司乘实时计价

	4. 应付展示价格 = 对need_fee取整

5. 特殊处理幸运盒子价格：只在特价盒子/超值达存在时计算

	1. basic_total_fee、最大前置优惠、不可抵扣费项、前置优惠后金额 取 「特价盒子 / 超值达盒子」 的对应值

	2. 呼返优惠金额 = 幸运盒子折扣 \* 前置优惠后金额，不会被CAP

	3. 应付estimate_fee = basic_total_fee - 前置最大优惠金额 - 呼返优惠金额 + 不可抵扣费项

	4. 实付need_fee = basic_total_fee + 不可抵扣费项

	5. 平台花费 = 0

	6. 实付展示价格

	7. 应付展示价格

6. 折叠：此时添加是否折叠的flag

	1. 幸运盒子折叠：以下条件为或，会添加折叠标识，不会更改折扣空间

		1. 幸运盒子折扣为100

		2. 滴滴快车不存在

		3. 特价盒子不存在

		4. 幸运盒子上游API没有传

	2. 应付折叠、实付折叠（模拟）：

		1. 城市组A：应付折叠开启，且折叠API品类；实付折叠开启

		2. 城市组B：应付折叠开启，但不折叠API品类；实付折叠不开启

		3. 应付折叠：所有应付价格低于特价盒子应付价的品类，都进行折叠；对于API商家而言，是API商家优惠前的价格

		4. 实付折叠：所有实付价低于特价盒子的品牌，都进行实付折叠，包括API，幸运盒子除外

## 5 分场景决策

### 5.1 预估场景

以下折扣组为「平台呼返、特价盒子、幸运盒子、」

#### 前置策略

1. 频控策略：

	1. 获取优惠次数：以city_id、pid为key获取用户当天在该城市的优惠次数

	2. 获取阈值：以city_id为key，从[apollo](https://ab.intra.hongyibo.com.cn/conf/37/3956/4736/256776)参数「pas_freq_conf」获取阈值

	3. 计算：若优惠次数 > （确认是>还是>=）阈值，则命中频控策略，特价盒子和平台呼返决策空间为「100_100」，由于幸运盒子不是补贴，这里不控制幸运盒子

2. 乘客OD缓存策略

	1. 缓存时间是30秒

	2. 缓存的是实际生效的折扣，例如如果前面命中熔断，联合决策的折扣组和为100_97_82，生效的折扣组和为100_100_100，这里拿到的依旧是100_100_100

	3. 以pid、route_id为Key，拿到缓存内容，为实际生效的折扣组

3. 风控策略

	1. 命中时，实际生效的折扣组为100_100_100

4. 熔断策略：

	1. 包含格子熔断、全城熔断，熔断会和动调联动

	2. 命中时，实际生效的折扣组为100_100_100

5. 实验定折策略：

	1. 补贴率定折（优先级最高）：运筹参数「==fixed_subsidy_rate_discount」，若是，则命中，固定平台呼返、特价盒子折扣折扣，只决策幸运盒子折扣==

		1. 区县定折是补贴率定折的一部分

	2. 实验定折：平台呼返折扣对应运筹「platform_fixed_discount」，盒子呼返定折对应运筹「box_fixed_discount」，不受补贴率定折限制

	3. 定折为几折是怎么确定的？

		1. box_subsidy_rate_bg确定盒子呼返补贴率，platform_subsidy_rate确定平台呼返补贴率

		2. 对补贴率进行四舍五入，1.1pp对应1，对应99折

		3. 决策默勾时，ecr取最近的，99取100，95取94；dsar和acc_cr，会计算对应真实的price_list，用真实的price_list过模型

		4. 在discount_group中会保留最近的，用于取ecr的结果

6. 幸运盒子预估策略：判断幸运盒子是否展现，下列条件为或

	1. 滴滴快车不存在

	2. 特价盒子/超值达不存在

	3. 命中围栏、命中动调，trace维度判断

	4. 不满足展现时段

	5. 不满足快车y折约束、b-cpm约束、b总价约束，对应底表：kflower_strategy.pltf_union_stg_lucky_box_config_hive

7. 最终得到合法的折扣组合：

	1. 若幸运盒子不展现，则删除所有幸运盒子非100折的折扣组合

	2. 若幸运盒子展现，遍历以上所有策略合法折扣的交集

#### 联合决策策略

有两组折扣：幸运盒子100、幸运盒子非100

1. 获取$$\lambda$$

	1. 底表：kflower_strategy.platform_greedy_solver_lambda_dict

	2. key：stg_group、city_id、执行补贴率actual_subsidy_rate

	3. 对应运筹配置「==lambda_group」==

2. 过模型

	1. ecr模型：

		1. 特征（待梳理）

		2. 折扣100-73

	2. dsar模型

		1. 排序、同价车型合并（附文档）

		2. 折扣：所有幸运盒子合法折扣；如何定义合法？幸运盒子预估策略中满足幸运盒子b-cpm约束，则合法，前面若满足，则只有100折是合法的

	3. acc_cr模型：

		1. [特征](https://cooper.didichuxing.com/knowledge/2199610335356/2205679248871)，构造时包含被折叠车型

		2. 折叠后获取发单优先级

		3. 每个price_list，by商家过模型

		4. 计算acc_cr、pcr，不包含折叠车型，幸运盒子输出=特价盒子头100折输出X幸运盒子折扣X惩罚系数，惩罚系数底表==kflower_strategy.price_anchor_ar_penalty_factor_dict_for_box==

3. 决策：计算每个price_list，同价车型合并后默勾到k的结果（这里的折扣都有哪些？）

	1. 取候选折扣组，见7，

	2. 取最低折扣对应$$ecr_{j}$$，折扣X默勾的$$dsar_{jk}$$、$$acc\_cr_{ik}$$

	3. 计算score

		1. 问题：这里是否要区分幸运盒子展现和幸运盒子不展现计算？还是幸运盒子100折单独处理？

		2. 优先用有幸运盒子的最高score，如果没有幸运盒子折扣则取幸运盒子100对应的最高score

		3. $$gmv_{ik}=\sum\limits_{l=1}^k pcr_{jl}*need\_fee$$

		4. $$cost_{ik}=\sum\limits_{l=1}^kpcr_{jl}*呼返优惠金额$$

		5. $$score_{ik}=ecr_{j}*dsar_{jk}*acc\_cr_{jk}*(1+\lambda*\beta *gmv_{jk}-\lambda cost_{jk})$$

	4. acc_cr阈值过滤：对应运筹配置「==anchor_model_type_threshold」==

		1. 默勾acc_cr阈值过滤：过滤$$acc\_cr_{jk}<\gamma$$所有决策空间，对应底表price_anchor_new_price_accept_rate_threshold，key为city_id、group_id

		2. 幸运盒子acc_cr阈值过滤：过滤幸运盒子$$acc\_cr_{j0}<\theta$$的决策空间，对应底表==kflower_strategy.pltf_union_stg_lucky_box_show_by_acc_cr_threshold==

	5. 决策

		1. score最高的选项

		2. 如果默勾acc_cr阈值过滤完，则全勾兜底，取全勾状态下score最大的折扣组

			1. 问题：是指每个price_list都默勾兜底的最高，还是过滤完的最高

				1. 单独price_list处理

		3. 候选折扣组合有幸运盒子（问题：是指幸运盒子非100么？），在有幸运盒子的score中取最大

		4. 如果折扣组合没有幸运盒子，在没有幸运盒子的score中取最大

		5. 如果命中熔断，则另开始计算100_100_100下的默勾，取最大

### 5.2 修改目的地场景
