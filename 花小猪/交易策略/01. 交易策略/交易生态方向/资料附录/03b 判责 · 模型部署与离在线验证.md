### Deepconf探索

### 一、背景

==DeepConf 通过生成多个推理链，并利用模型在生成文本时==内部的**置信度信号**==来评估每条思维链的质量进行加权投票最终答案，提升模型在复杂任务上的准确率。==

DeepConf 通过聚合 token 级别的置信度，可以有效地区分正确与错误的推理路径：

![](6dbf841ce9a043e1-截屏2026-01-30_16.10.41.png)

当前一申大模型直接判责的准召难以达到较高的水准，通过“**命中高准组合才置信**”的tricky方式来提升准召，并节省人判资源的开销。当前申诉环节分特征场景提精确一期上线后离线测算的高准覆盖约22.06%（基于初判抽单样本），大盘实际测算覆盖率为10.34%（基于申诉全量样本测算，不达预期，已排查出问题<!--评论:[{"u":"rongbohui","c":"给一个链接？"},{"u":"zanewang","c":"https://cooper.didichuxing.com/docs2/document/2206720106799"},{"u":"rongbohui","c":"没看懂，是统计口径有问题，还是线上逻辑有问题？"},{"u":"zanewang","c":"线上逻辑问题"}] -->，修复后可提升至17%+）。为了进一步节省人判资源开销，期望在不折损有责判责精度的情况下，能够提升高准的覆盖率。

通过 Deepconf 的启发，对于所有判有责的订单，我们通过评估大模型判责输出推理链的置信度，并比较判责正确样本（TP）和判责错误样本（FP）的分布，看两个分布能否被有效的区分。以及，通过设定一个置信度得分阈值，在这个阈值下能够达到较高的精确与高准覆盖率。

进一步地，对所有在申诉环节判无责的订单，也可以结合大模型输出的置信度，对于某一高置信度阈值下，可以有效区分无责TP样本和无责FP样本（即高无责精确率，相对机判有责，可以适当降低标准）的子集直接置信，可进一步释放人力资源。

**核心结论**：Deepconf的价值在于可以在牺牲整体有责精确折损1pp下，多释放1倍的人力资源。<!--评论:[{"u":"rongbohui","c":"机器成本增加多少？"},{"u":"zanewang","c":"等显卡就位后，进行部署与压测分析"}] -->

- 乘取场景Deepconf效果并不好，在更低的覆盖率，即筛选的更小样本空间下，有责精确率反而更低；

#### 3.3 Deepconf感知

选取Deepconf策略司机取消单中相对于4.53版高准策略选取出的机判有责高准样本的差集，共计843条样本。

其中767条，占比 90.98% 命中 「取消时刻的司机位置与订单起点的直线距离大于200米」特征。这767条样本中，其中658条（占总样本78.06%）订单信息描述可以精准匹配：

```PlainText
这个订单有以下行为\n
- 本单司机在过往7天的订单中，司乘沟通、司机报备、申诉中、车载证据显示订单起终点为查车点小于10次\n
- 取消时刻的司机位置与订单起点的直线距离大于200米\n
- 司机未到达上车点\n
- 近30天命中130（车祸车坏）次数小于6次\n
- 近30天命中49（超载）次数小于6次\n
- 司机在通话中没有虚假描述\n
- 订单取消之后2小时内司机有完单\n
- 乘客非投诉\n
```

其中62条样本（占比7.35%）订单信息描述可以精准匹配：

```PlainText
这个订单有以下行为\n
```

### 1、司机取消

```PlainText
select  
    a.order_id
    ,dri_duty
    ,dri_duty_evil
    ,root_cause_name
    ,judge_feature_name
    ,area
    ,product_id
    ,accept_type
    ,0 as accept_type_l2
    ,3 as signpost_tag_l1
    ,0 as signpost_tag_l2
    ,dt
from    (
    select  
        order_id 
        ,get_json_object(response, '$.data.dri_duty') as dri_duty
        ,get_json_object(response, '$.data.dri_duty_evil') as dri_duty_evil
        ,get_json_object(
            get_json_object(response, '$.data.extra'), 
            '$.root_cause_name'
        ) as root_cause_name
        ,get_json_object(
            get_json_object(response, '$.data.extra'),
            '$.judge_feature_name'
        ) as judge_feature_name
        ,order_city as area
        ,product_id
        ,accept_type
        ,coalesce(get_json_object(ext_json, '$.cancel_role'), ext3) cancel_role
        ,case   
            when get_json_object(request, '$.extra.is_complaint') = 1 
            and get_json_object(request, '$.extra.is_cancel_complaint_sop') = 1 then 1
            else 0
        end is_p2d_complain --是否乘客投诉司机
        ,get_json_object(ext_json, '$.hit_supreme_rule') hit_supreme_rule
        ,case  
            when coalesce(get_json_object(request, '$.qid'), get_json_object(request, '$.extra.qid'), -999) > 0 then 1
            else 0
        end is_feedback_flag
        ,ihap_product_id
        ,order_city
        ,order_type
        ,get_json_object(ext_json, '$.order_info.airport_type') airport_type    -- 机场单类型
        ,get_json_object(ext_json, '$.order_info.railway_type') railway_type    -- 火车站单类型
        ,concat_ws('-', year, month, day) dt
        ,row_number() over (partition by order_id order by `timestamp` desc) rn
    from    dd_ods.ods_log_esp_c_public_increment
    where   1 = 1
        and  concat_ws('-', year, month, day) = date_sub('${BIZ_DATE_LINE}', 1)
        and   sys in ('dalis','hxz_dalis','hxz_nmg_dalis') 
        and get_json_object(request, '$.judge_scene') = 3
        and ihap_product_id in (60010000, 120030000, 170010000, 170020000)
        and get_json_object(get_json_object(response, '$.data.extra'), '$.llm') = '1'
    )a 
    inner join (
        select 
            order_id
        from 
            kflower_dw.dwd_kf_trd_unity_order_di
        where 
            dt between date_sub('${BIZ_DATE_LINE}', 2) and date_sub('${BIZ_DATE_LINE}', 1)
            and (is_hxz = 1 or is_thlm = 1)
            and start_city_id in (29, 157)
    )b on a.order_id = b.order_id
where   rn = 1
  and   cancel_role = 2 -- 司机取消
  and   dri_duty is not null
order by rand()
limit   200 -- 单量改这里
;
```

```PlainText
            ) b on a.order_id = b.order_id
            where rn = 1
```

```PlainText
import re
def extract_details(text):
    # 提取“订单司机取消/订单乘客取消”
    cancel_type = re.search(r'订单(司机|乘客)取消', text)
    cancel_type = cancel_type.group(0) if cancel_type else None
    
   # 提取“取消时间距离接单时间：”
    time_match = re.search(r'取消时间距离接单时间：(\d+)分(\d+)秒', text)
    if time_match:
        minutes = int(time_match.group(1))  
        seconds = int(time_match.group(2)) 
        cancel_time = minutes * 60 + seconds 
    else:
        time_match = re.search(r'取消时间距离接单时间：(\d+)秒', text)
        if time_match:
            cancel_time = int(time_match.group(1)) 
        else:
            cancel_time = None
    
    # 提取“是否连环派单”
    dispatch_type = re.search(r'(是连环派单|非连环派单|不是连环派单)', text)
    if dispatch_type:
        dispatch_value = dispatch_type.group(0)  # 获取匹配的字符串
        if dispatch_value == '是连环派单':
            dispatch_value = '连环派单'
        elif dispatch_value in ['非连环派单', '不是连环派单']:
            dispatch_value = '非连环派单'
    else:
        dispatch_value = None
    
    # 起点和终点
    start_point = re.search(r'订单起点：([^\\n]+)', text)
    end_point = re.search(r'订单终点：([^\\n]+)', text)
    start_point = start_point.group(1) if start_point else None
    end_point = end_point.group(1) if end_point else None
    
    #预估接驾距离
    estimated_distance = None
    distance_match = re.search(r'-\s*预估接驾距离[（(]米[）)]?[：:]\s*(\d+)(米)?', text) 
    if distance_match:
        estimated_distance = int(distance_match.group(1)) 


    # 是否场站单
    station_type = re.search(r'(是场站单|非场站单)', text)
    if station_type:
        station_type = station_type.group(0) 
    else:
        station_type = None


    # 提取“这个订单有以下行为”后的内容
    behaviors_match = re.search(r'这个订单有以下行为([\s\S]+)', text)
    if behaviors_match:
        behaviors_text = behaviors_match.group(1)
        behaviors = re.findall(r'-\s*(.*?)\\n', behaviors_text)
    else:
        behaviors = []
    
    return {
        'cancel_type': cancel_type,
        'cancel_time': cancel_time,
        'dispatch_type': dispatch_value,
        'start_point': start_point,
        'end_point': end_point,
        'estimated_distance': estimated_distance,
        'station_type': station_type,
        'behaviors': sorted(behaviors) 
    }
    
df['prompt_details'] = df['prompt'].apply(extract_details)
df['instruction_details'] = df['instruction'].apply(extract_details)
```

## 根因特征规范化

原目录：16.体验治理 › 90.大模型治理判责 › 05.大模型落地 · [根因特征规范化（Cooper 原页）](https://cooper.didichuxing.com/knowledge/2199610335356/2205847964711) ^eco-2205847964711


#### 一、背景

大模型输出<res_feature>根因特征</res_feature>存在不规范的问题（即不在限定的list中），线上不规范率达10%。会导致两个问题：

- 司机处置通知书取不到判责依赖的根因特征，只能取兜底文案

- 大模型判的订单正常会流入人机协同技能组，取不到根因特征将流入常规技能组

 

现离线通过修改system prompt实现根因特征规范化，离线测算将不规范率从11.59%降低至0.79%，并且评估改动后的prompt对判责准召影响不大。

 

#### 二、方法

通过对原模型容易输出的不规范的根因特征，添加到输出格式的正确示例中，强化对规范化根因的输出。

 

不规范的根因特征如下：

![](5f8c0c75cfa64f69-截屏2025-11-13_16.37.45.png)

 

原system prompt的输出格式要求：

```PlainText
## 输出格式严格保证!!!：<result>触发的根因</result>。<res_feature>判断根因所基于的具体特征</res_feature>。<responsibility>司机恶意有责，司机错误有责或司机无责</responsibility>。<reason>简单描述理由</reason>
比如：
<result>平台原因</result>。<res_feature>平台派单问题</res_feature>。<responsibility>司机无责</responsibility>。<reason>订单中起终点信息表明是场站单，场站单司机无私下加价即为无责。</reason>
<result>司乘扰乱平台秩序</result>。<res_feature>乘客主动要求线下交易，司机同意</res_feature>。<responsibility>司机恶意有责</responsibility>。<reason>订单中文本信息表明存在线下交易。</reason>
请根据上述步骤和输出格式对接下来提供的订单描述进行分析。
```

 

修改后system prompt的输出格式要求：

```PlainText
## 输出格式严格保证!!!：<result>触发的根因</result>。<res_feature>判断根因所基于的唯一特征!!!</res_feature>。<responsibility>司机恶意有责，司机错误有责或司机无责</responsibility>。<reason>简单描述理由</reason>
正确示例：
<result>乘客不满足平台乘车要求</result>。<res_feature>乘客在无责时间外不用车导致订单取消</res_feature>。<responsibility>司机无责</responsibility>。<reason>乘客表示不用车，且取消时间距离接单时间为10分钟，超过平台通常无责时间范围。</reason>
<result>平台规定范围内合理取消</result>。<res_feature>乘客在无责时间内不用车导致订单取消</res_feature>。<responsibility>司机无责</responsibility>。<reason>乘客在无责时间内取消订单。</reason> 
<result>司机扰乱平台秩序</result>。<res_feature>司乘未碰面，诱导乘客取消</res_feature>。<responsibility>司机恶意有责</responsibility>。<reason>司乘未碰面，司机让乘客取消。</reason>
<result>司机服务能力不足</result>。<res_feature>无特殊情况，司机未到达上车点</res_feature>。<responsibility>司机错误有责</responsibility>。<reason>无特殊情况，司机未到达上车点，属于司机服务能力不足判错误有责。</reason>
```

```PlainText
### 1. 根因优先级（Root Cause First）
- **行为时序溯源**：
```

##### 3、代码

限制组合长度最长阈值：3

挖掘数据集：707-717

避免伪高准场景：约束高准组合下的tp数 / 全量样本下tp数 > 5%

通过dfs搜索挖掘高准场景：

```PlainText
def dfs(text_caps, current_combination, df, valid_combinations, sample_threshold=80, max_combination_length=3, start_idx=0):
    # 如果当前组合超过最大长度，则返回
    if len(current_combination) > max_combination_length:
        return

    # 如果当前组合中有特征，根据当前组合的条件进行筛选
    if len(current_combination) > 0:
        mask = pd.Series([True] * len(df)) 
        for feature, value in current_combination:
            feature_mask = df[feature] == value 
            mask &= feature_mask 

        matching_samples = df[mask]

        tp = ((matching_samples['predict_label'] == '有责') & (matching_samples['true_label'] == '有责')).sum()
        if tp >= sample_threshold:
            print(f"Number of matching samples: {len(matching_samples)}") 
            fp = ((matching_samples['predict_label'] == '有责') & (matching_samples['true_label'] == '无责')).sum()
        
            precision = 0
            if tp + fp > 0:
                precision = tp / (tp + fp)
                print(f"{tp} / {tp + fp} = Precision: {precision}") 

            # 精度满足要求保存组合
            if precision >= 0.98:
                print(f"Combination meets precision requirement: {current_combination}")
                valid_combinations.append((current_combination.copy(), precision))
                return  
    
    # 从当前特征索引开始搜索，避免回溯到之前的特征
    for i in range(start_idx, len(text_caps)):
        feature = text_caps[i]
        for value in [0, 1]:
            current_combination.append((feature, value))
            # 递归时，传入 i + 1 作为新的起始索引，确保不会回到之前的特征
            dfs(text_caps, current_combination, df, valid_combinations, sample_threshold, max_combination_length, start_idx=i + 1)
            current_combination.pop()
    
    return
```
