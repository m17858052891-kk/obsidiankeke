# 预分单策略整理

乘客勾选的品牌没有运力时，平台可以在发单或等待应答阶段，同时呼叫符合条件、但乘客未勾选的车型。有司机举手后，再询问乘客是否接受；接受后才进入接驾。新增候选有机会挽回原本无法完成的订单，乘客也可能拒绝。因此，评估预分单要连着看三件事：**何时触发、呼叫哪些车型、乘客是否接受**，最后回到大盘成交率（CR）。

## V1 到 V4 改了什么，实验看到什么

| 版本 | 策略改动 | 对照与结果 |
| --- | --- | --- |
| V1 · 固定等待 | 所有场景等应答超过 60 秒后，呼叫自营或宏鹄，单次呼叫两个品牌。 | 相比空白组，CR +0.21 个百分点。[产品方案](http://wiki.intra.xiaojukeji.com/pages/viewpage.action?pageId=653125998) · [V1 评估](https://wiki.intra.xiaojukeji.com/pages/viewpage.action?pageId=810257475) |
| V2 · 提早触发、扩大候选 | 两组都在 1／3 分钟场景等 60 秒，在 5／8／10 分钟、无车或非自营场景等 30 秒。组一只呼叫价格最低的两个车型，组二呼叫全部可预分单车型。 | 相比 V1，触发率提高，两组均未观察到正向收益。组二的乘客接受度显著下降；组一为何也没有收益，原文留作待查。[V2 实验](https://wiki.intra.xiaojukeji.com/pages/viewpage.action?pageId=835767915) |
| V3 · 按接受度筛车型 | 引入接受度模型，把触发策略和车型过滤策略组合实验。 | 几次实验的大盘 CR 均无显著正向。模型针对的是 V2 组二暴露的接受度问题，组一的结果仍缺解释。[V3 实验](https://wiki.intra.xiaojukeji.com/pages/viewpage.action?pageId=932785941) · [时间片轮转评估](https://cooper.didichuxing.com/knowledge/share/page/z7Ww4rx8ThmL) |
| V4 · 按实时供需决定等待时间 | 用格子实时供需选择触发时间，接受度模型筛选的车型数从两个改为可配置的 N 个。 | 一期无显著正向。二期调参后报告大盘 CR +0.14 个百分点；四组阈值中两组正向、两组不显著负向。原文未注明 +0.14 个百分点这一数值的显著性。[V4 评估](https://cooper-vpn.xiaojukeji.com/docs/document/2200156645547) |

**API 接入单独看。** 接入发生在 V3 至 V4 之间，只做了接入前后对比（原文记作 AA），记录的 CR 变化约为 0.15 个百分点。缺少同期 A/B 对照，无法据此估算 API 接入的独立收益。

## V4 怎样决定何时触发

发单数和应答率取**中心格及周围一圈格子最近 5 分钟**的数据。下表沿用原方案的条件顺序。

| 条件 | 最早何时开始预分单 |
| --- | --- |
| 发单数超过 DUFE 的差应答阈值，且应答率低于阈值 A | 等待应答超过 T1 秒 |
| 发单数超过同一阈值，且应答率低于阈值 B | 等待应答超过 T2 秒 |
| 其他情况 | 等待应答超过 T3 秒 |

第一次轮询时计算触发时间并缓存，后续轮询复用。原文的条件分别写 A、B，灰度参数清单却将 A 写了两次；A、B 的数值、大小关系及两条件重叠时的执行优先级均需查配置。以上是该版方案记录。

## 接受度模型有哪些已知结果

原文记录**离线 AUC 0.89、在线 AUC 0.56，线上接受度阈值 0.2**。模型分数中位数为 0.3589。原文没有给出两套 AUC 的样本、标签和时间窗，也未说明分位表对应哪批流量，因此不能用这张分位表反推线上实际过滤比例。排查两套 AUC 的差距，可对读同目录的 [[预分单接受度模型在离线一致性检验]] 和 [[预分单接受度模型线上特征检查]]。
