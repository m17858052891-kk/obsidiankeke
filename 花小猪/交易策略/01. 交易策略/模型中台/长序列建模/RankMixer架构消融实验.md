# RankMixer架构消融实验

本阶段围绕大规模结构化特征交互完成了 RankMixer Dense 基线、序列消融、类别字段表示、双路 DIN、Token Pooling、Sparse-MoE、DTSI Router、GeoHash、训练轮数和学习率调度等多组实验。工作从复现约 1 亿参数的 Dense RankMixer 开始，逐步检查输入 Token 的语义、历史序列的贡献、最终读出方式、模型容量扩展和训练收敛情况，并在发现标签口径问题后重新建立了有效标签实验系列。

这条路线解决几个问题：大量异质字段如何组织成可交互的 Token，不使用 Self-Attention 时如何完成跨字段信息交换，以及扩大 FFN、增加专家或延长训练能否稳定转化为 AUC 收益。

单笔订单包含当前订单上下文、司机画像、乘客画像、供需、天气、路线和历史行为等不同类型的信息。城市、渠道、派单类型等字段属于类别；距离、时长、计数和比率属于连续值；司机和乘客历史则是带有先后顺序的事件序列。RankMixer 没有把所有原始字段直接拼成一个向量，而是先将它们组织成 16 个 Token，再通过固定混合和位置独立 FFN 完成交叉。

基础输入包括：

- 8 个离散字段；

- 152 个当前订单连续字段；

- 司机最近最多 30 笔历史订单，每笔 8 个字段；

- 乘客最近最多 30 笔历史订单，每笔 8 个字段；

- 司机和乘客各自的历史有效性 mask；

- 当前订单标签和标签有效性标记。

离散字段通过各自的 Embedding 表转换成稠密表示。连续字段使用训练集预先计算的中心值和缩放值做固定归一化。

非序列字段按照字段名和业务含义分成七组：

| 语义组 <br> | Token 数量 <br> | 主要内容 <br> |
| --- | ---: | --- |
| 稀疏画像 <br> | 1 <br> | 城市、渠道、业务类型等离散信息 <br> |
| 司机统计 <br> | 3 <br> | 司机完单、取消、应答和历史统计 <br> |
| 乘客统计 <br> | 2 <br> | 乘客呼叫、取消、完单和偏好统计 <br> |
| 供需 <br> | 2 <br> | 起终点附近订单量、司机量和供需状态 <br> |
| 天气 <br> | 1 <br> | 天气及环境信息 <br> |
| 路线与订单 <br> | 2 <br> | 距离、时长、价格和路线属性 <br> |
| 其他连续字段 <br> | 1 <br> | 未命中上述规则的剩余数值特征 <br> |

每个语义组内部先完成字段拼接，再按维度切分为一个或多个 chunk。每个 chunk 使用独立 Linear 投影到 768 维，最终形成 12 个非序列 Token。字段分组属于人工规则，不是模型自动学习结果；字段命名、分组归属和组内切分会直接改变每个 Token 携带的信息。

## 司乘历史编码与 Tokenizer

司机和乘客历史分别构造成 30 个时间步。每个 8 维历史事件先进行 signed log 变换，再经过事件编码器：

```PlainText
单个历史事件 8 维
    → signed_log1p
    → Linear 8 → 128
    → LayerNorm
    → GELU
    → Linear 128 → 64
    → 加入可学习位置表示
```

padding 位置通过 mask 重新置零，不参与有效历史表示。基础版本将每侧 30 个 64 维事件展平为 1920 维，再拼接一个有效历史长度比例，形成 1921 维序列向量。司机侧和乘客侧分别切成两个 chunk，并各自产生 2 个 768 维 Token。

完整 Tokenizer 输出为：

```PlainText
12 个当前订单非序列 Token
+ 2 个司机历史 Token
+ 2 个乘客历史 Token
= 16 个 Token

每个 Token 维度为 768
模型输入形状为 B × 16 × 768
```

## Token Mixing 与 Dense RankMixer 基线

RankMixer 的跨特征交互不使用 Q、K、V，也不构造 Token 两两之间的注意力矩阵。每个 Block 先把 768 维拆成 16 个 48 维子空间：

```PlainText
B × 16 Token × 768
    → B × 16 Token × 16 Head × 48
    → 交换 Token 轴与 Head 轴
    → B × 16 Head × 16 Token × 48
    → 重新整理为 B × 16 × 768
```

交换后，每个输出 Token 都包含来自全部 16 个原始 Token 的一个 48 维片段。司机、乘客、供需、路线和天气等信息因此被重新分配到同一位置。这个操作只做 Split、Transpose 和 Concat，本身没有可学习参数。

固定重排之后，每个位置进入独立的 Per-Token FFN：

```PlainText
单个 Token 768 维
    → Linear 768 → 2048
    → GELU
    → Dropout
    → Linear 2048 → 768
```

16 个位置不共享 FFN 参数。每个 RankMixer Block 先完成 Token Mixing，再做残差和 LayerNorm；随后进入 Per-Token FFN，再做第二次残差和 LayerNorm。基础模型堆叠两个 Block。单层 16 套 FFN 的主要权重约为 5030 万，两层约为 1 亿，因此 RankMixer 的参数和计算主要集中在规则的大矩阵乘法，而不是 Token Mixing。

基础版本最后对 16 个 Token 做 Mean Pooling，得到一个 768 维样本表示，再经过任务塔：

```PlainText
16 × 768
    → Mean Pooling
768 维样本表示
    → 512
    → 256
    → 128
    → 1 个 logit
```

训练使用 Focal Loss，验证指标为完整验证集 ROC-AUC。模型通过 DDP 在 4 张 H200 上训练，使用 BF16、梯度同步、checkpoint 和 TensorBoard 记录。任务成功退出只代表训练流程完成，结构是否有效仍以同口径验证集 AUC、运行日志和配置证据判断。

旧标签口径的 Dense v1 首次完成 104,584,177 参数 RankMixer 的全量训练。模型训练 5832 step，Best AUC 和 Final AUC 均记录为 0.857007。该实验确认，不依赖 Self-Attention，仅使用固定 Token Mixing 和位置独立 FFN，也能够完成结构化特征的跨域交互和稳定训练。

## 输入表示、序列聚合与最终读出实验

序列特征消融 v2 将司机和乘客产生的 4 个序列 Token 置零，只保留 12 个非序列 Token。Wiki 中保存的历史 AUC 为 0.778594，但该实验没有取得与 v1 同等级的全量日志，且属于后来确认存在标签问题的旧系列。该数值只作为当时完成过序列消融的记录，没有用于建立当前序列贡献结论。

序列类别 Embedding v4 检查了历史事件内部的字段类型。早期事件编码器把轮次、派单类型等类别编号和时长、计数等连续值一起输入数值 MLP，相当于默认类别编号存在连续距离。v4 为两个类别字段分别建立 16 维 Embedding，再与其他连续字段拼接后进入事件编码器。

v4 只增加 4,928 个参数，模型总参数为 104,589,105，Best AUC 达到 0.858005，比 Dense v1 提高 9.98 bp。与 8 Expert Sparse-MoE 相比，这次改动增加的容量很小，收益反而更高。该实验说明，先修正字段表达方式比直接扩大主干容量更有效。

双路 DIN v6 将司机和乘客历史的 Flatten 改为目标相关聚合。模型先从当前订单非序列特征生成 Query，再分别计算 30 个司机事件和 30 个乘客事件与当前订单的相关性。每侧历史按 DIN 权重汇总，再投影成序列 Token。

```PlainText
当前订单表示 → Query

司机 30 个历史事件
    → Driver DIN
    → 目标相关司机历史摘要

乘客 30 个历史事件
    → Passenger DIN
    → 目标相关乘客历史摘要
```

v6 参数量降至 101,910,451，Best AUC 为 0.856661，比 v4 下降 13.44 bp。DIN 实现和训练流程均正常，但当前聚合方式没有形成收益。Flatten 保留全部历史位置，DIN 在进入 RankMixer 前先压缩历史；当前结果表明，这次压缩损失的信息超过了目标相关加权带来的收益。

最终读出方面，v7 将 Mean Pooling 改为 Gated Pooling。门控网络根据每个样本的最终 Token 表示计算非负权重，再进行归一化加权求和。参数增加到 104,786,226，Best AUC 为 0.857368，比 v4 下降 6.37 bp。运行本身成功，但可学习门控没有超过简单均值，旧系列主线因此保留 Mean Pooling。

另一项 Autoresearch 实验在 Dense v1 上实现 Learned Token Pooling。该实现使用可学习 Query 汇总最终 Token，与 v7 的逐 Token 门控不是同一个算子。实验记录 Best AUC 为 0.858063，比其父版本 0.857007 提高 10.56 bp。验证曲线存在先下降再恢复的波动，运行环境和父版本证据也与 v4 系列不完全一致，因此这项结果作为独立实验保留，没有和 v7 合并解释。

人工业务语义分组围绕非序列 Tokenizer 展开。原 Tokenizer 已按字段名前缀形成七类 Token，但组内仍可能混入业务语义不同的字段。该项工作重新核对字段并按司机、乘客、供需、天气、路线和订单上下文组织输入，使一个 Token 内的字段来源更一致。Wiki 中保存了分组规则、代码结构和实验设计，但没有保存一份通过同等级日志与指标证据门禁的正式结果，因此没有补写 AUC，也没有将该方案列为已验证收益。

## Sparse-MoE、DTSI Router 与专家塌缩

容量扩展首先测试了 DTSI Sparse-MoE。v3 将每个位置原有的 Dense FFN 替换为 8 个 Expert，并增加 Router。训练阶段保留 Dense 路径，使所有专家都能获得梯度；推理表示使用稀疏路径，只选择少量专家。目标是在不按专家数量同比增加推理计算的情况下扩大模型容量。

v3 参数量从 104,584,177 增加到 810,251,761，约为 Dense v1 的 7.75 倍。Best AUC 为 0.857309，只比 v1 提高 3.02 bp，低于实验设定的 5 bp 验收线。模型稳定完成训练，但参数规模没有转化成相称的排序收益。

v8 以输入表示更好的 v4 为父版本，再次接入 8 Expert DTSI，同时补齐 Layer、Token 和 Expert 三个层级的监控：

- 每层总体专家激活率；

- 每个 Token 的专家选择分布；

- 每个 Expert 的命中次数和流量；

- Sparse Gate 的权重和；

- Dense 与 Sparse 路径的输出比例；

- Router 与 Expert 的梯度情况。

v8 参数量为 810,256,689，Best AUC 为 0.856990，比 v4 下降 10.15 bp。总体激活比例约为 11.303%，接近 8 个专家中激活 1 个的 12.5%，但 Sparse Gate 权重只有百万分之一量级，部分 Expert 的流量也明显集中。专家在统计上被选中，并不代表专家输出对最终表示产生了足够影响。

v8 还存在训练和验证前向不一致。训练阶段混合 Dense 与 Sparse 输出，验证阶段只使用 Sparse 输出；模型训练时优化的表示和验证时实际使用的表示并不完全相同。

v9 修正了两部分实现：被选中的正 Gate 在激活集合内重新归一化，使权重和为 1；训练前向只使用 Sparse 输出，Dense 路径通过 straight-through 形式补充反向梯度，不改变前向数值。这样训练、验证和推理使用同一 Sparse 表示。

v9 完成 5832 step，Best AUC 为 0.856136，比 v8 再下降 8.54 bp，比 v4 低 18.69 bp。训练与验证路径对齐后仍没有形成收益，说明前向不一致是实现问题，但不是 Sparse-MoE 效果不足的唯一原因。

监控进一步发现，ReLU Router 大量输出全零 Gate。一旦所有专家 Gate 都为零，正常 Top-k 选择虽然还能返回索引，但专家权重仍为零，Sparse 分支无法提供有效表示。

v10 为全零 Gate 增加 Top-1 Softmax-STE 兜底。当 ReLU Gate 没有任何正值时，模型从原始 Router logits 中选择一个 Expert，并使用 Softmax 权重保证至少有一个有效专家；straight-through 保留 Router 的反向梯度。

v10 Best AUC 回升到 0.857102，比 v9 提高 9.66 bp，比 v8 提高 1.12 bp，但仍比 v4 低 9.03 bp。TensorBoard 显示兜底后零路由比例为 0，Gate 权重和为 1，训练前向与 Sparse 输出一致。与此同时，两层分别有约 99.7150% 和 99.9966% 的样本-Token 依赖 fallback，原始 ReLU Router 仍接近完全塌缩。兜底机制修复了“没有专家输出”的问题，但没有证明 Router 学会了有效的专家分工。

Dense Per-Token MoE Residual 实验测试了更保守的容量扩展方式。它不替换原有 Dense FFN，而是在 Dense 主路径旁增加多个小专家，由门控网络按样本生成残差补充。模型参数增加 24.17%，Best AUC 为 0.857388，比父版本 0.858063 下降 6.75 bp。

旧系列先后完成了 Dense FFN 替换为 Sparse-MoE、训练验证前向对齐、全零 Router 兜底和 Dense 主路径旁追加 MoE Residual。几种实现都能训练，但没有稳定超过输入表示更简单的 Dense v4。现有结果没有显示专家容量是当时的主要限制。

## 标签有效性修正与实验口径切换

实验复核过程中发现，旧数据把原始 `class` 为空的样本映射成负样本。这些行本质上没有有效标签，却参与了训练 loss、验证 loss 和 AUC。由于无效样本被当作大量伪负样本，旧系列 AUC 整体虚高，并且模型学习目标也发生了变化。

修正实现没有直接在 Dataset 中删除无效行。DDP 下如果不同 rank 因过滤得到不同批次数，可能在梯度同步时互相等待。新实现保留行作为传输 padding，同时生成标签有效性 mask：

```PlainText
class 有值
    → valid mask = True
    → 参与训练 loss、验证 loss 和 AUC

class 为空
    → valid mask = False
    → loss 权重为 0
    → 不进入任何标签指标
```

这项修正同时作用于训练和验证。无效标签对梯度和指标的贡献严格为零，各 rank 仍保持相同的迭代步数。旧 v1 至 v10 被移动到“未剔除 class=null”目录；修正后的实验单独建立版本树。两个系列不能混排，也不能通过给旧 AUC 减去固定差值换算成新口径，因为标签修正同时改变了梯度、样本比例、排序对和最佳 checkpoint。

修正标签后的 v1 保留 8 个离散字段、152 个连续字段、司机 30 × 8 历史和乘客 30 × 8 历史。模型参数为 104,589,105，完成 5832 step 后 Best AUC 为 0.751190。它成为有效标签口径下的有序列 Dense RankMixer 基线。

修正标签后的 v2 完全移除司机和乘客历史序列，只保留 12 个非序列 Token。模型参数降到 101,607,281，只比 v1 减少约 2.85%；Best AUC 降到 0.742834，比 v1 下降 83.56 bp。

v1 与 v2 使用相同六月数据、相同非序列字段、相同 RankMixer 主干和训练设置，主要变量是是否保留司乘历史。参数量变化远小于 AUC 变化，因此这组实验明确确认了历史行为信息的价值。静态统计字段不能完全替代司机和乘客的个体时序信息。

## GeoHash、训练轮数与学习率调度

v2_1 保持无序列模型结构不变，只把数据切换到三月切分。参数量仍为 101,607,281，Best AUC 为 0.726926。三月和六月同时存在样本分布、正样本率、城市和供需差异，因此 v2_1 被记录为三月独立基线，没有把它与六月 v2 的差值解释成模型退化。

GeoHash v3 在六月无序列 v2 上加入起点和终点的粗细粒度位置编码。经纬度先离散成不同精度的 GeoHash 类别，再通过 Embedding 进入 Tokenizer。模型参数增加 26,230,660，达到 127,837,941，参数量增长约 25.82%，训练耗时增加约 11.13%。

v3 Best AUC 为 0.741935，比无序列 v2 的 0.742834 下降 8.99 bp。训练正常完成，没有出现 OOM、NaN、Inf 或任务重启。当前 GeoHash 实现增加了容量和运行成本，但没有改善排序效果。

训练充分性实验 v5 回到修正标签后的有序列 v1，只将训练轮数从 1 个 epoch 增加到 2 个 epoch。输入、模型、参数量、损失函数和数据均保持不变。模型完成 11664 step，Best AUC 为 0.752566，比 v1 提高 13.76 bp。

第二轮结束时仍然刷新全局最佳值，文本日志没有显示验证 AUC 持续回落。这个结果说明，原来 1 个 epoch 的训练预算没有使有序列 RankMixer 完全收敛。v5 的收益来自训练更充分，不来自模型容量变化。

学习率实验 v7 在相同 2 个 epoch 内，将恒定学习率改为 Cosine 衰减。学习率在 11664 step 内从初始值平滑下降到较低值，模型结构、数据和训练轮数保持不变。历史 CSV 记录 Best AUC 为 0.754143，比 v5 提高 15.77 bp。

v7 的 TensorBoard 已归档 13 个 tag 和 58,933 个原始 scalar 点。周期验证曲线中的最高 AUC 为 0.753709，与历史 CSV 的 0.754143 不一致；全量文本日志、准确 Best step 和训练结束后的最终验证没有完整恢复。总结同时保留两个来源，不把缺少证据的细节补写成确定事实。

## 实验结论

1. RankMixer 已完成从 160 个当前订单字段和两路 30 × 8 历史序列，到 16 × 768 Token 表示的完整数据链路。

2. Token Mixing 通过固定维度重排实现跨 Token 信息交换，Per-Token FFN 承担主要非线性建模和参数容量，不依赖 Self-Attention。

3. 序列类别字段改用独立 Embedding，只增加少量参数便超过旧 Dense 基线和 8 Expert Sparse-MoE，说明字段语义表达比直接扩容更有效。

4. 修正标签后的序列消融使 AUC 下降 83.56 bp，明确确认了司机和乘客历史行为的价值。

5. 当前双路 DIN 聚合低于 Flatten，说明在进入 RankMixer 前压缩历史会损失部分有效的事件和位置信息。

6. Gated Pooling 没有超过 Mean Pooling；另一种 Learned Token Pooling 出现正向独立结果，两种实现和证据环境不同，不能合并成同一结论。

7. Sparse-MoE 将参数量扩大约 7.75 倍，没有稳定超过 Dense 主线。专家监控、前向对齐和零路由兜底完成了问题定位，但 Router 仍主要依赖 fallback，专家容量没有转化成 AUC 收益。

8. 人工业务语义分组完成了字段整理和代码实现，但现有 Wiki 没有保存通过同等级证据门禁的正式 AUC，因此没有被写成已验证收益。

9. GeoHash 增加约 2623 万参数并增加训练耗时，AUC 下降 8.99 bp，当前实现没有产生收益。

10. 将训练从 1 个 epoch 增加到 2 个 epoch 后，AUC 提高 13.76 bp，说明原有训练预算不足。

11. 在相同 2 个 epoch 内使用 Cosine 学习率留下了更高的历史记录，但 Best 指标来源与周期验证曲线存在差异，结论中保留了证据边界。

12. class IS NULL 修正改变了训练目标和评估样本，旧系列只能用于历史结构对比，不能与修正后的结果直接排名。

13. 已有实验形成的 RankMixer 主线保留项包括：有效标签 mask、司乘历史序列、序列类别 Embedding、Dense Per-Token FFN、Mean Pooling、至少 2 个 epoch 的充分训练，以及经过记录的学习率调度。Sparse-MoE、当前双路 DIN、Gated Pooling 和 GeoHash 没有进入已验证保留项。
