实验配置怎么读

ECP 是实验配置平台。V3 常见配置链分为三层：Feature（功能层）决定某项能力是否准入（通常看 allow）；StgGroup（策略组层）决定本次请求选择哪些策略（通常看 stg_level，数组元素是策略英文名）；Stg（策略层）按 stg_name 匹配被选中的策略，并下发该策略的开关、阈值或枚举参数。策略层有配置不代表它会执行，必须同时满足功能层准入、策略组选择、策略层开启及代码前置条件。

分组 是实验内返回同一组参数的配置单元；bucket/流量 是进入某条路由后再按乘客 ID 等实验键分桶的比例；城市、版本、PID、人群、自定义条件和时间 是进入实验前的路由条件。流程 表示参数影响冒泡 V3、等待应答更新或 PBD 等哪条处理链。报告必须同时列出这些维度，不能只写实验名或“全量”。

1. 车型排序（共执行三次）

策略规则

输入：按 tag 分类的车型和出租车计价信息。tag 是展示类别，例如 cheep（经济型）、carpool（早鸟拼车）、special（特价置顶盒子）、taxi（出租车），不是车型品类 ID。

普通车型排序价：直接取本次 V3 入参中的表单展示价；该字段不存在时回退到预估实付价，不使用乘客应付总价。

花小猪特快盒子排序价：V3 入参可以直接携带专用排序价。外部运力进特快盒子规则执行时会覆盖该值：价格区间先以盒子的表单展示价初始化，再用实际进入盒子的外部车型端上展示价更新最低值和最高值；模式 1 取区间最高值，模式 2 取区间最低值，其他允许模式取盒子自身端上展示价。等待应答更新场景固定取区间最低值。规则未生成新值时沿用入参；专用排序价未传或等于 -1.00 时，依次回退表单展示价、预估实付价。

顺风车同呼盒子排序价：同呼命中后代码临时创建一个顺风车同呼盒子，遍历顺风车返回结果中所有 IsShow=true 的车型，取其中最高预估实付价写入盒子的专用排序价；没有任何展示车型时不创建该盒子。该值不是顺风车内部用于拼座排序的“拼成价/未拼成价较低值”。

排序结果：按上述排序价升序；排序价相同时，再按预估实付价升序；两者都相同则没有额外业务优先级。

处理：先在每个 tag 内排序，再合并后对全量车型按同一价格口径排序。出租车满足“允许混排”且展示打表计价时，在价格排序完成后移动到列表底部，因此不再受价格高低影响。

执行点：隐藏/折叠前一次，盒子扩展后一次；命中顺风车同呼后，BothCallCpList 替代 AllCPList 返回前再执行一次出租车置底。

当前配置现状

代码规则 + 请求入参排序函数本身没有独立开关；普通车型价格和出租车计价方式来自本次请求。is_kflower_taxi_mixed_sort=1 表示允许出租车混排，出租车 PriceType=2 表示打表计价。

关联控制花小猪特快盒子专用排序价受 athena_other_cp_enter_flash_box_control_ecp 控制，当前生产查询情况见“盒子展示与盒子扩展”；顺风车同呼盒子是否生成受代码最低版本和 SfcBothCallConf.Allow 控制，当前情况见“顺风车同呼”。

3. 滴滴车型展示控制（含差应答）

策略规则

输入：乘客 pid、城市、App 版本、车型品类；差应答查询使用起点坐标、起点网格和当前 5 分钟时间片，获取起点周边一圈的实时供需。

展示结果：Apollo 返回展示结果枚举（实验配置：flag）：v0 冒泡页和等待应答页均隐藏；v1 两页按正常规则展示和默勾；v2 冒泡页展示但不默勾、等待应答页正常默勾；v3 冒泡页隐藏、等待应答页正常展示；v4 等待应答页展示，冒泡页仅在差应答或价格水位与名次条件命中时展示。

差应答计算：DUFE 发单数 key 为 grid_1circle_last_5min_anycar_start_order_cnt_kf，应答数 key 为 grid_1circle_last_5min_anycar_start_answer_order_cnt_kf。无结果或发单数为 0 时不命中；否则 应答率=应答数÷发单数，同时满足“发单数大于发单数门槛（实验配置：kf_low_answer_fuse_max_call_cnt）”和“应答率低于最低应答率（实验配置：min_answer_rate）；该值无效时回退兜底应答率门槛（实验配置：kf_low_answer_fuse_min_ar）”才算差应答。

价格水位：价格水位 = 滴滴车型的预估实付价 ÷ 实时单车型的端上展示价，名次是滴滴车型在当前全量排序中的位置（从 1 开始）。非差应答场景下，价格水位必须大于价格水位门槛（实验配置：price_water_level），名次必须大于名次门槛（实验配置：price_rank）才展示；任一未超过门槛、缺少配置或实时单端上展示价不大于 0 时隐藏。最终只改车型是否展示，不改任何价格和车型顺序。

4. 车型折叠

策略规则

公共限制：按当前车型顺序逐个处理；只折叠仍展示且允许勾选的车型，跳过公共黑名单（实验配置：black_list）和已经折叠的车型。每折叠一个都会重新计算剩余展示数：冒泡页达到最小展示数（实验配置：bubble_show_cp_min_num），等待页达到最小展示数（实验配置：wait_show_cp_min_num）后停止。

新旧折叠链路与 Diff 灰度

Apollo 开关 form_fold_upgrade_enable 返回的链路路由（实验配置：route）在折叠执行前选择实现链路：route=old 走原 CpShowHandler，route=new 走新接口复用的纯折叠计算；其他值按旧链路处理。旧链路下 Diff 灰度开关（实验配置：allow）为 true 时还会复制独立上下文执行新计算并记录 Diff，但最终响应仍采用旧链路结果；新链路下无论 allow 取值都只采用新链路结果。该配置切换折叠实现和观测方式，不新增一种业务折叠策略。

1）僵尸商家折叠

仅处理非花小猪自营、非滴滴车型。UFS 特征 kflower.finish_cnt_14d 按车型的商家产品 ID（product_id）返回近 14 天花小猪完单量；只有 UFS 返回了该商家的记录且完单量严格小于完单量门槛（实验配置：jiang_shi_threshold）时才折叠，整份数据或该商家记录缺失时均不折叠。

2）合规治理折叠

仅处理鸿鹄车型。UFS 特征 kflower.governance_examine 按城市返回治理开始时间、结束时间和业务车型 ID 名单；当前时间须在闭区间内且车型业务 ID 命中名单。代码再读取国家法定节假日表，今天或明天任一天是法定节假日都不折叠；UFS 数据、时间或名单任一不满足也不折叠。

3）客服考核折叠

5. 盒子展示与盒子扩展

策略规则

花小猪特快盒子展示

先用盒内车型的“商家产品 ID + 服务等级 + 拼单类型”生成运力集合；盒外车型被折叠时，用相同三元组从集合中删除对应运力。集合变空且整盒隐藏开关（实验配置：is_open_fold_box）为 true 时隐藏整盒；无论集合是否为空，只要冒泡展示标记（实验配置：show_flag）为 0 就直接隐藏。盒内车型列表为空、没有找到盒子本身时不改状态。

幸运盒子展示

外部运力进入花小猪特快盒子

6. 价格锚点取整与后置处理

策略规则

取整处理

后置补勾与消费

消费方式：锚点默勾同时比较“预估实付价 ≤ 原始锚点”和“端上展示价 ≤ 取整后锚点”，任一成立即可勾选。主选择完成后还会按锚点上取整映射（实验配置：price_anchor_ceil_map）补齐实付价/展示价断档，并按相邻展示价差上限（实验配置：price_anchor_diff_upper）决定是否继续向上补勾；运行时计算的价差记录在 price_anchor_diff；因此最终公共日志中的 price_anchor_point 可能已包含后置补勾调整。

日志核验口径

日志口径：uri=FormPriceCeil 中 price_anchor_before 是取整前锚点、price_anchor_after 是取整后锚点，二者单位均为分，price_round_type 是上述 0～3 枚举。公共日志 old_price_anchor_point 记录原始锚点，price_anchor_point 记录后置处理后的实际锚点，price_anchor_diff 是允许继续补勾的相邻展示价差，ceil_add_select_cp_num 是价差处理额外补勾车型数。

10. 无车赔

策略规则

公共前置：ECP 策略开关（实验配置：allow）必须开启、策略选择列表（实验配置：stg_level）必须选中当前策略，且默认勾选数必须大于 0；起终点坐标来自请求，任一为 0 均视为未开启定位；路面距离来自路线数据，值为 -1 或超过路面距离门槛（实验配置：dist_threshold）时退出；Pope 活动事件（实验配置：pope_event）必须命中无车赔活动并返回非空券说明。任一失败都不返回赔付。

价格口径：“已选最高端上展示价”和“包含花小猪特价的最低端上展示价”都跳过早鸟拼车；花小猪特快盒子优先取选中态展示价，其余情况优先取表单展示价，没有时回退到预估实付价。公式先按元计算，再乘 100 转为赔付金额的分单位，不使用乘客应付总价。

用户是否接受默勾：从按排序价排列的列表末尾向前找到最后一个已勾车型，再到 DUPS 价格锚点预测列表中匹配接受率：盒子按盒类型匹配，普通车型按车型品类匹配。接受率或 DUPS 接受率阈值任一缺失时按“接受”处理；接受率严格低于阈值才视为可能取消。

11. 应答率、品类预期与特快应答时间

策略规则

应答率：统一模型开关（实验配置：open）开启时，基础值来自 DUPS 价格锚点预测列表中的车型品类、业务车型 ID 和预测应答率。某个普通车型缺少预测值时，在 Apollo 单车型随机补值下限（实验配置：single_rate_min）与上限（实验配置：single_rate_max）之间随机补一个值；同一业务车型包含多个品类时，业务车型应答率取这些品类的最大值。盒子应答率按盒内各业务车型计算 1 − 未应答概率连乘。最终只统计已勾选车型：同一业务车型勾选多个品类时只计算一次业务车型应答率，其他车型使用品类应答率；总应答率再次按 1 − 未应答概率连乘 计算，限制在 Apollo 总应答率下限（实验配置：rate_min）与上限（实验配置：rate_max）后乘 100 向下取整。没有 DUPS 预测列表或没有可计算车型时结果为 0。

特快应答时间：原始秒数来自 Ether/Eve 花小猪特快盒子应答时间模型。模型准入开关（实验配置：special_flash_ans_time_access）和使用开关（实验配置：special_flash_ans_time_use）都开启且盒内有车型时，将秒数向上取整到 60 秒的整数倍；取整后必须大于 0 且严格小于 ECP 展示上限（实验配置：show_ans_time），才写入花小猪特快盒子，否则不展示。模型失败或未返回时秒数保持 0，因此不会展示。
