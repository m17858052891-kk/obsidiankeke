派单匹配优化:两阶段详细方案与算法实现

最小化期望应答距离(分式目标),约束司机取消率 / 乘客取消率 / 完单量。本文把阶段一、阶段二每一步具体怎么算讲透,并给出完整可跑代码(已本地验证四个场景)。配套代码见附件 match_two_stage.py。

本版修订:完单约束由「率」改为「量」—— \(\sum A_{ijk}F_{ijk}z_{ijk}\ge F_0\)(\(F_0\) 是期望完单数的绝对下限,不是比例)。这改变了边成本的 F 项、\(\mu_F\) 的次梯度和可行性判断,并顺带消除了旧版「只派 2 单压低比值」的退化(见 §7)。C、D 仍是率约束。

1. 模型与记号

变量 \(z_{ijk}\in\{0,1\}\):订单 \(i\) 选司机 \(j\)、模式 \(k\)。常数 \(A\)(应答概率/权重)、\(d\)(应答距离)、\(C\)(司机取消率)、\(D\)(乘客取消率)、\(F\)(完单率)。

$$\min\ \frac{\sum A_{ijk}d_{ijk}z_{ijk}}{\sum A_{ijk}z_{ijk}}\quad \text{s.t.}\ \underbrace{\frac{\sum ACz}{\sum Az}\le C_0,\ \frac{\sum ADz}{\sum Az}\le D_0}_{\text{率约束}},\ \underbrace{\sum A_{ijk}F_{ijk}z_{ijk}\ge F_0}_{\color{#f0b35b}{\text{量约束}}}$$

结构约束:每单 \(\sum_{jk}z_{ijk}\le1\);GS 额外要求每司机 \(\sum_{ik}z_{ijk}\le1\)(TopSpeed 不要求)。

量纲提示:\(C_0,D_0\in[0,1]\) 是率;\(F_0\) 是计数量级(如 50 单),等于「期望完单数的下限」。

2. 三步化简(全方案地基)

  1. 率约束线性化:C、D 两分式与目标同分母 \(N=\sum Az>0\);两边乘 \(N\),变线性,如 \(\sum A(C-C_0)z\le0\)。
  2. 量约束本就是线性的:\(\sum AFz\ge F_0\) 不含分母,直接是线性约束,无需跨乘。
  3. 分式目标 → Dinkelbach:引入参数 \(\lambda\),子问题 \(\min\sum A(d-\lambda)z\);外层迭代 \(\lambda\leftarrow\) 当前解比值,超线性收敛。
  4. 线性约束 → 拉格朗日:乘子 \(\mu=(\mu_C,\mu_D,\mu_F)\ge0\) 吊进目标。

边成本怎么推出来(关键:F 项变了)

把三条约束按「违反为正」的形式写进拉格朗日函数:\(\mu_C\sum A(C-C_0)z+\mu_D\sum A(D-D_0)z+\mu_F\big(F_0-\sum AFz\big)\)。其中 \(\mu_F F_0\) 对 \(z\) 是常数,不影响选边,只剩 \(-\mu_F\sum AFz\)。合并到目标,得统一边成本:

$$\boxed{\;c_{ijk}=A_{ijk}\big[(d_{ijk}-\lambda)+\mu_C(C_{ijk}-C_0)+\mu_D(D_{ijk}-D_0)\;{\color{#f0b35b}{-\ \mu_F\,F_{ijk}}}\big]\;}$$
约束边成本里的项\(\mu\) 的次梯度(正=违反)
C 率\(+\mu_C(C-C_0)\)\(g_C=\sum A(C-C_0)z\)
D 率\(+\mu_D(D-D_0)\)\(g_D=\sum A(D-D_0)z\)
F 量\(\color{#f0b35b}{-\mu_F\,F}\)(无阈值常数)\(\color{#f0b35b}{g_F=F_0-\sum AFz}\)

直觉:完单量不够(\(g_F>0\))→ 加大 \(\mu_F\)→ 边成本里 \(-\mu_F F\) 让高 \(F\) 的边更"便宜"→ 鼓励多选高完单边,并（在可不派模式下)把更多订单拉回派单。之后一切比较都用 \(c_{ijk}\)(越负越该选)。阶段一、阶段二共用同一个 \(c\),只是内层怎么用它选边不同。

3. 阶段一:具体怎么做

目的:在松弛掉司机约束的简化问题上,便宜地把 \((\lambda,\mu)\) 调到接近最优,产出初始解 \(z^{(1)}\) 和对偶下界 \(LB\)。TopSpeed 到此结束;GS 用它热启动。

三层循环(从里到外)

1最内层 — 逐单 argmin(\(O(E)\))。 给定当前 \((\lambda,\mu)\) 算每条边 \(c_{ijk}\);因为没有司机约束,订单之间互不影响,每个订单 \(i\) 独立取 \(c\) 最小的那条:

$$z^{(1)}_i=\arg\min_{(j,k)} c_{ijk},\qquad \text{(可不派模式)若 }\min_{(j,k)}c_{ijk}\ge0\text{ 则订单 }i\text{ 不派}$$

2中层 — 次梯度调 \(\mu\)。 解完一次得到 \(z\),算上表三个次梯度 \(g=(g_C,g_D,g_F)\),更新 \(\mu\leftarrow\max(0,\ \mu+\alpha_t\, g)\),步长 \(\alpha_t=\alpha_0/(1+t)\) 递减。哪条约束违反就加大对应惩罚。

3外层 — Dinkelbach 调 \(\lambda\)。 中层收敛得到可行解后,更新 \(\lambda\leftarrow\dfrac{\sum Adz}{\sum Az}\),再进下一轮;\(|\lambda_{new}-\lambda|<\varepsilon\) 收敛。

产出:乘子 \((\lambda_0,\mu_0)\)、解 \(z^{(1)}\)、下界 \(LB=\) 阶段一最优可行解比值。\(LB\) 合法:阶段一是原问题松弛(约束更少),其最优 \(\le\) 原问题最优。

4. 阶段二:具体怎么做

目的(仅 GS):恢复"司机只接一单",在原问题上收口到可行且近最优。唯一改动是把最内层从逐单 argmin 换成二部图匹配,中层/外层完全一样,且从阶段一的 \((\lambda_0,\mu_0)\) 热启动。

最内层 — 二部图最小成本指派(司机约束在此精确满足)

  1. 仍用同一个 \(c_{ijk}\)。对每个 (订单, 司机) 对在不同模式里取 \(c\) 最小的折成一条边,得成本矩阵 cost[订单, 司机]。
  2. linear_sum_assignment 求最小成本指派:每订单至多配一司机、每司机至多配一订单——司机唯一由匹配结构精确保证,不需惩罚。
  3. "可不派"= 给每单加一个成本 0 的虚拟弃单列;必派模式则不加。
口径一致(踩过的坑):阶段一/二派单口径必须一致(代码用 force_dispatch 统一)。否则阶段二靠少派压低比值,产生假负 gap、破坏下界关系。必派模式要求司机数≥订单数;司机可能不足时两阶段都用"允许不派"。注意:完单量下限天然逼着多派,与弃单列的少派倾向相互制衡。

5. 业务分叉 + 冲突判据

业务路径
TopSpeed只做阶段一,逐单 argmin,不触发匹配。
GS阶段一 → 看司机冲突 → A/B/C 三选一。

阶段一后统计:超额总量 \(\Omega=\sum_j\max(0,\text{load}_j-1)\),冲突司机数 \(n_{\text{conf}}\)。

A\(\Omega=0\):直接最优。 无冲突 ⇒ 原问题可行;又达下界 ⇒ gap=0,跳过阶段二。
B\(n_{\text{conf}}\le\tau\cdot\)司机数:局部收口。 只对冲突订单重跑匹配,非冲突订单锁定。
C冲突较多:完整阶段二。 从 \((\lambda_0,\mu_0)\) 热启动,匹配做内层,继续调 \(\mu,\lambda\),用 \(LB\) 报 gap。

8. 工程注意点

  • F0 的单位:现在是期望完单数(ΣA·F·z),不是比例,随当批订单规模设定(如目标完单率×订单数)。
  • 两种底线可共存:若业务同时要"完单量≥下限"和"完单率≥下限",加两条约束即可——量约束 \(-\mu_F F\)、率约束 \(+\mu_{F'}(F'_0-F)\),各自一个乘子,互不冲突。
  • 口径一致 = 下界有效:必派模式需司机数≥订单数;否则 force_dispatch=False。量下限会把"允许不派"下的派单量往上顶。
  • 可证明最优:Charnes–Cooper → MILP(OR-Tools CP-SAT / Gurobi),量约束天然是线性约束,直接加入;本套解做 warm start。
  • τ 选取:B/C 分界按"局部收口可接受 gap"离线标定,一般 1~2% 司机占比。
