实验配置怎么读

ECP 是实验配置平台。V3 常见配置链分为三层：Feature（功能层）决定某项能力是否准入（通常看 allow）；StgGroup（策略组层）决定本次请求选择哪些策略（通常看 stg_level，数组元素是策略英文名）；Stg（策略层）按 stg_name 匹配被选中的策略，并下发该策略的开关、阈值或枚举参数。策略层有配置不代表它会执行，必须同时满足功能层准入、策略组选择、策略层开启及代码前置条件。

分组 是实验内返回同一组参数的配置单元；bucket/流量 是进入某条路由后再按乘客 ID 等实验键分桶的比例；城市、版本、PID、人群、自定义条件和时间 是进入实验前的路由条件。流程 表示参数影响冒泡 V3、等待应答更新或 PBD 等哪条处理链。报告必须同时列出这些维度，不能只写实验名或“全量”。

1. 车型排序（共执行三次）

策略规则

输入：按 tag 分类的车型和出租车计价信息。tag 是展示类别，例如 cheep（经济型）、carpool（早鸟拼车）、special（特价置顶盒子）、taxi（出租车），不是车型品类 ID。

普通车型排序价：直接取本次 V3 入参中的表单展示价；该字段不存在时回退到预估实付价，不使用乘客应付总价。

花小猪特快盒子排序价：V3 入参可以直接携带专用排序价。外部运力进特快盒子规则执行时会覆盖该值：价格区间先以盒子的表单展示价初始化，再用实际进入盒子的外部车型端上展示价更新最低值和最高值；模式 1 取区间最高值，模式 2 取区间最低值，其他允许模式取盒子自身端上展示价。等待应答更新场景固定取区间最低值。规则未生成新值时沿用入参；专用排序价未传或等于 -1.00 时，依次回退表单展示价、预估实付价。

顺风车同呼盒子排序价：同呼命中后代码临时创建一个顺风车同呼盒子，遍历顺风车返回结果中所有 IsShow=true 的车型，取其中最高预估实付价写入盒子的专用排序价；没有任何展示车型时不创建该盒子。该值不是顺风车内部用于拼座排序的“拼成价/未拼成价较低值”。

排序结果：按上述排序价升序；排序价相同时，再按预估实付价升序；两者都相同则没有额外业务优先级。

处理：先在每个 tag 内排序，再合并后对全量车型按同一价格口径排序。出租车满足“允许混排”且展示打表计价时，在价格排序完成后移动到列表底部，因此不再受价格高低影响。

执行点：隐藏/折叠前一次，盒子扩展后一次；命中顺风车同呼后，BothCallCpList 替代 AllCPList 返回前再执行一次出租车置底。

2. 车型隐藏

策略规则

按业务车型 ID 隐藏（策略名：hide_by_bi_stg）

输入：普通车型和盒内车型的业务车型 ID，以及 Apollo 合规名单（实验配置：cp_list）与 ECP 业务车型 ID 名单（实验配置：business_ids）。

判断与结果：两份名单取并集。普通车型命中后，其车型品类进入隐藏结果；盒内仅处理非花小猪自营车型，命中后把盒内车型品类记入该盒子的不可展示名单。

按车型品类隐藏（策略名：hide_by_pc_stg）

输入：普通车型和盒内车型的车型品类 ID 与 ECP 车型品类名单（实验配置：product_categorys）。

判断与结果：品类命中即进入隐藏结果；它和业务车型 ID 规则是“任一命中即可”。盒内花小猪自营车型跳过。

盒子整体隐藏（策略名：hide_box_stg）

判断与结果：盒子隐藏开关（实验配置：allow）开启后，逐盒比较“盒内不可展示品类数”和“盒内车型总数”；两者相等时隐藏盒子，只隐藏部分车型时仍保留盒子。

4. 车型折叠

策略规则

公共限制：按当前车型顺序逐个处理；只折叠仍展示且允许勾选的车型，跳过公共黑名单（实验配置：black_list）和已经折叠的车型。每折叠一个都会重新计算剩余展示数：冒泡页达到最小展示数（实验配置：bubble_show_cp_min_num），等待页达到最小展示数（实验配置：wait_show_cp_min_num）后停止。

新旧折叠链路与 Diff 灰度

Apollo 开关 form_fold_upgrade_enable 返回的链路路由（实验配置：route）在折叠执行前选择实现链路：route=old 走原 CpShowHandler，route=new 走新接口复用的纯折叠计算；其他值按旧链路处理。旧链路下 Diff 灰度开关（实验配置：allow）为 true 时还会复制独立上下文执行新计算并记录 Diff，但最终响应仍采用旧链路结果；新链路下无论 allow 取值都只采用新链路结果。该配置切换折叠实现和观测方式，不新增一种业务折叠策略。

1）僵尸商家折叠（策略名：jiangshi_stg）

仅处理非花小猪自营、非滴滴车型。UFS 特征 kflower.finish_cnt_14d 按车型的商家产品 ID（product_id）返回近 14 天花小猪完单量；只有 UFS 返回了该商家的记录且完单量严格小于完单量门槛（实验配置：jiang_shi_threshold）时才折叠，整份数据或该商家记录缺失时均不折叠。

2）合规治理折叠（策略名：compliance_stg）

仅处理鸿鹄车型。UFS 特征 kflower.governance_examine 按城市返回治理开始时间、结束时间和业务车型 ID 名单；当前时间须在闭区间内且车型业务 ID 命中名单。代码再读取国家法定节假日表，今天或明天任一天是法定节假日都不折叠；UFS 数据、时间或名单任一不满足也不折叠。

3）客服考核折叠（策略名：kefu_stg）

读取 Apollo 的城市、车型品类和生效时间；三者同时命中才折叠。配置起止时间都为 0 时按全天生效。

4）无车折叠（策略名：no_car_stg）

只检查前置检查数量（实验配置：pre_cp_num）限定的当前展示顺序前 N 个仍展示车型；黑名单车型和盒子跳过。花小猪自营及鸿鹄车型按业务车型 ID 查询 SDS 在线司机数，SDS 聚合时间窗口（实验配置：no_car_sds_feature_minute）当前为 30 分钟，对应 key COORDSTREAM_DRIVER_CNT_30；司机数 ≤ 在线司机数门槛（实验配置：driver_num）时折叠。其他 API 车型读取呼叫数 KFLOWER_OUTSIDE_BOX_ORDER_CREATE_CNT_30，举手数为花小猪和百度两个举手 key 的求和；同时满足“呼叫数 > 呼叫数门槛（实验配置：call_num）、举手数 ≤ 举手数门槛（实验配置：hands_up_num）”才折叠。查询前代码会为每个 SDS key 写入失败兜底：在线司机 key 为 10、呼叫 key 为 0、每个举手 key 为 10；花小猪端两个举手 key 均失败时合计为 20，默认不会误折叠。

5）乘客应付总价折叠（策略名：basic_total_fee_stg）

使用乘客应付总价，不使用预估实付价或表单展示价。先找到锚定车型品类（实验配置：anchor_product_category）指定的车型，计算门槛 = 锚定车型的乘客应付总价 × 折叠倍率（实验配置：anchor_rate）；API 车型是否参与由 API 车型折叠开关（实验配置：is_fold_api）控制；找不到锚定车型或门槛为 0 时不处理。其他车型的乘客应付总价严格小于门槛时折叠；锚定车型、幸运盒子和出行快选盒子跳过。

6）预估实付价折叠（策略名：actual_fee_stg）

使用车型的预估实付价，不使用乘客应付总价或表单展示价。锚定车型品类（实验配置：anchor_product_category）确定锚点，门槛 = 锚定车型的预估实付价 × 折叠倍率（实验配置：anchor_rate）；API 车型是否参与由 API 车型折叠开关（实验配置：is_fold_api）控制；找不到锚定车型或门槛为 0 时不处理。其他可展示车型的预估实付价严格小于门槛时折叠；锚定车型、幸运盒子和出行快选盒子跳过。

7）运营配置折叠（策略名：operate_stg）

ECP 运营折叠开关（实验配置：allow）开启后，读取 Apollo 的城市、车型品类和时间段，三者同时命中才折叠；结果与客服考核一样写入对应折叠原因。

8）强制名单折叠（策略名：white_list_stg）

车型品类命中 ECP 强制车型品类名单（实验配置：product_categorys_white_list）时折叠；仍须通过公共可勾选、黑名单和最小展示数限制，因此“在强制名单”不代表一定折叠。

9）盒内联动折叠（策略名：box_stg）

前序普通车型因允许联动的折叠原因名单（实验配置：box_flags）中的原因被折叠后，以商家 ID 关联盒内车型；同一商家的非自营盒内车型同步进入折叠名单。盒内隐藏数加折叠数等于盒内总数时，整盒联动开关（实验配置：is_open_fold_box）开启才折叠盒子本身。

10）缓存结果回放（策略名：cache_stg）

读取上一次冒泡缓存的车型品类和折叠原因，先按排序价排序，再从排序价高的车型向低的车型回放；本次仍存在该车型且原因在允许回放原因名单（实验配置：cache_stgs）时才复用，仍受公共限制。

7. 实时单默勾及默勾后规则

策略规则

随机数量默勾（策略名：select_to_random）

随机策略被策略选择列表（实验配置：stg_level）选中且策略开关（实验配置：allow）开启后，先统计未折叠的展示车型数 N，在 1～N 中等概率随机一个数量，再按当前排序价顺序勾选前 N 个可勾选车型；隐藏、折叠和不可勾选车型跳过。

锚点价格默勾（策略名：select_to_anchor_price）

锚点策略被策略选择列表（实验配置：stg_level）选中且策略开关（实验配置：allow）开启后，候选只取经济型、置顶型和符合出租车价格默勾条件的出租车，再按排序价升序。每个候选分别比较两套价格：预估实付价 ≤ 原始锚点，或端上展示价 ≤ 取整后锚点；满足任一条件即勾选。端上展示价优先取表单展示价，没有时回退到预估实付价。

用户关闭推荐、DUPS 锚点小于 0，或主规则一个都没勾上时，按城市和订单距离从 UFS 读取平均发单车型数：≤3km 为短单、3～10km 为中长单、>10km 为长单；缺数据时勾选当前可展示车型数的 60%（四舍五入），至少 1 个。

最后补齐价格断档：未勾车型的预估实付价不高于已勾最高预估实付价，或端上展示价不高于已勾最高端上展示价时补勾；之后再按配置的端上展示价差上限继续向上补勾。

出租车继承上一单

仅在出租车不混排且 Apollo 出租车默勾方式（实验配置：flag）选择“继承上一单”时执行。上一单车型列表包含出租车品类 8030 后，勾选当前第一个可勾选出租车；上一单缺失或不含出租车则不处理。

幸运盒子单勾

DUPS 幸运盒子单勾开关（实验配置：LuckyBoxSingleSelectSwitch）为 enable，或其为 original/空值且 Apollo 回退标记（实验配置：flag）允许时，只有特价盒子和幸运盒子同时被勾选、且没有其他车型被勾选时，取消特价盒子，只保留幸运盒子。

公共前置：ECP 策略开关（实验配置：allow）必须开启、策略选择列表（实验配置：stg_level）必须选中当前策略，且默认勾选数必须大于 0；起终点坐标来自请求，任一为 0 均视为未开启定位；路面距离来自路线数据，值为 -1 或超过路面距离门槛（实验配置：dist_threshold）时退出；Pope 活动事件（实验配置：pope_event）必须命中无车赔活动并返回非空券说明。任一失败都不返回赔付。

价格口径：“已选最高端上展示价”和“包含花小猪特价的最低端上展示价”都跳过早鸟拼车；花小猪特快盒子优先取选中态展示价，其余情况优先取表单展示价，没有时回退到预估实付价。公式先按元计算，再乘 100 转为赔付金额的分单位，不使用乘客应付总价。

用户是否接受默勾：从按排序价排列的列表末尾向前找到最后一个已勾车型，再到 DUPS 价格锚点预测列表中匹配接受率：盒子按盒类型匹配，普通车型按车型品类匹配。接受率或 DUPS 接受率阈值任一缺失时按“接受”处理；接受率严格低于阈值才视为可能取消。

公共后置：金额和等待时间必须大于 0；城市须有预算，且本次赔付不能使当日累计补贴超过上限。要求追加的车型数大于剩余可选数时，追加数强制改为 0。

必赔计算（策略名：must_m）

不检查预测时间门槛。时间与折扣配置键（实验配置：time_and_discount_conf）确定折扣表；预测会取消时，金额 =（已选最高端上展示价 − 含特价最低端上展示价）×折扣1×100；预测会接受时，金额 = 含特价最低端上展示价×折扣2×100。金额再乘支付倍率，并按预测取消金额下限（实验配置：min1）与上限（实验配置：max1），或预测接受金额下限（实验配置：min2）与上限（实验配置：max2）限制；订单固定券补开关（实验配置：is_add_order_subsidy）开启时最后相加，不参与倍率放大。

固定金额（策略名：fix_m）

预测应答时间来自 Ether 主应答时间模型，必须大于 0 且小于预测时间触发门槛（实验配置：trigger_threshold）；再按该时间落入时间与折扣配置键（实验配置：time_and_discount_conf）对应的 Apollo 时间区间读取固定赔付金额、等待值和追加车型数。没有匹配区间时返回 0，随后会被公共后置过滤。接受率只决定“是否预测取消”，不改变金额。

供需金额（策略名：supply_m）

同样先用预测时间触发门槛（实验配置：trigger_threshold）校验 Ether 预测应答时间，并匹配时间与折扣配置键（实验配置：time_and_discount_conf）对应的 Apollo 时间区间；再使用与必赔相同的公式，按预测取消金额下限（实验配置：min1）与上限（实验配置：max1），或预测接受金额下限（实验配置：min2）与上限（实验配置：max2）限制金额；订单固定券补开关（实验配置：is_add_order_subsidy）控制是否叠加券补；没有匹配区间时不赔。

模型金额（策略名：model_m）

在供需金额规则之前增加模型准入：模型标签（实验配置：model_tag）非空时，UFS 必须明确返回命中；下游失败、无结果或未命中都不赔。

1. Hold 计算策略

策略规则

配置路由与模式优先级

接口隔离：OrderHoldRecommend 从请求初始化 city、PID、车型、价格、距离、sid、是否多选等上下文，不复用 V3 的策略执行序列。

配置源：本报告统计的非 PBD 分支通过 ECP namespace dups_exp_flow_manager 读取车型 Hold 主配置；默认与 KC 使用实时单配置，SFC/Valet 使用顺风车配置。PBD 分支读取同名 Apollo 灰度，但不纳入本报告的配置统计。

路由参数：每个车型携带 business_id、product_category、distance、level_type、discount、是否含滴滴/小猪、是否多选和 sid；差应答时额外携带 didi_hold_stg，PBD 还携带 is_model_judge_pbd_no_driver。

优先级：new_mode 可以是逗号分隔列表，代码严格按该列表顺序执行；某模式经 checkHoldTimeValid 得到正值后立即停止。因此 V1～V9 是模式编号，不代表固定执行顺序。

1）V1 固定配置

直接使用外层 hold_time，并读取外层 silence；标签来自 v1_conf。

2）V2 网格/UFS

先用外层 hold_time 兜底。PBD 按城市、小时、business_id 取 UFS hold；花小猪侧按城市、半小时时间片、车型和起点网格读取 cd_time、answer_rate、answer_asp、cancel_dur。应答率低于阈值（实验配置：threshold_answer），或预估价低于正的 answer_asp 时改用取消时长。

3）V3 流量分发模型

外层 hold_time 是兜底；模型返回大于 0 时按最小值（实验配置：mode_hold_time_min）与最大值（实验配置：mode_hold_time_max）截断。

4）V4 应答/取消时长

use_model=true 且模型有值时按 min/max 截断；否则按时间片、半小时、城市时间片优先级读取 DUFE 应答/取消时长，车型系数可覆盖配置系数（实验配置：coefficient）。最终公式为 min + coefficient × (max-min)。

5）V5 双呼

乘客在物业侧最近订单存在，且该订单创建时间距本次发单为 0～300 秒时，使用配置 hold（实验配置：hold_time）；否则返回 0。

6）V6 双呼后摇摆兜底

先按 V5 使用第一段 hold（实验配置：hold_time_1）；V5 未命中且乘客 28 天内有物业/小猪完单时，在下界（实验配置：low_hold_time）与上界（实验配置：high_hold_time）间随机。is_cp_random=0 时所有车型复用一次随机结果，非 0 时按车型重新随机；结构中的 hold_time_2 当前计算代码未消费。

7）V7 随机

直接在 [low_hold_time, high_hold_time] 闭区间随机，并按 is_cp_random 决定请求级复用还是车型级随机。

8）V8 Apollo Config + Buffer

按配置的 namespace、conf_name、conf_key 批量读取“城市 → hold 秒数”，城市缺失时使用 default；乘调整系数（实验配置：factor）后，不得超过 start_range_begin - buffer - create_time。负 factor 回退 1，负 buffer 回退 0。

9）V9 灰度 Hold + Buffer

直接使用外层 hold_time，再应用相同的最早出发时间 buffer（实验配置：buffer）；负 buffer 回退 0。

10）公共时效校验与静默叠加

时效：所有模式都将计算值减去“当前时间－发单时间”；容器时间早于发单时间或扣减后为负时返回 0。非 SFC 的结果最多 10800 秒，SFC 不应用该上限。

短路：某模式校验后大于 0，记录该模式、tag、group_tag 并停止；否则继续尝试 new_mode 的下一项。

静默：外层配置 silence 与盒子流量静默按位或。盒子静默需 Apollo athena_guide_box_flow_rate_ctr.allow=true，排除业务车型白名单，并同时满足车型 level_type 在影响列表、UFS 返回该 business_id 需要静默。
