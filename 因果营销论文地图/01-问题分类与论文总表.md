# 按业务问题找论文

每行给出一个业务症状、可以先改的模块，以及论文证据能支持到哪一步。**可做小实验**指已有可隔离验证的改动，**需补条件**指关键假设、数据或实现尚待确认，**研究线索**指缺少原文支撑的候选方向。进入单篇可看指标分母、强基线、收益链和实验设计。

33 个条目的时间范围与公司署名详见[完整书目](07-完整书目.csv)。VALOR 首稿在 4 月，Microsoft 的论文包含 2018 年研究。给多阶段策略做仿真、评估代理指标、诊断经营原因的条目，在表中按各自解决的问题列出。

## 发券与收入增量

转化率提高后，还要看净增收入、客单变化和补贴叠加。按缺失的目标或动作维度选择模型。

|遇到的问题|论文与企业|先改哪一层|采用条件|
|---|---|---|---|
|发券拉动本店，平台净增多少|[CanniUplift](CanniUplift.md) / 阿里淘天|增加平台总量标签，拆分核销路径|**可做小实验**。平台总量拟合好后，还要验证单张券的边际排序。|
|哪档券带来更多收入，而非仅促成转化|[FunnelCausalNet](FunnelCausalNet_漏斗与收入.md) / 高德/Alibaba Group|对每档估计转化概率和条件客单，合成收入再做均值校准|**可做小实验**。工业前沿的均值优势未达显著。区间筛查只做监控。|
|销售名额有限，怎样按收入选客户|[Google VALOR](Google_VALOR_收入uplift.md) / Google|给零收入和长尾收入分别建模，再按预期增量排序|**需补条件**。各策略选中的账户不同。要衡量整体收益，需在同一批有资格的账户上比较。|
|券有多个处理维度，组合样本太稀|[TaQFormer](<../论文精读/TaQFormer/TaQFormer：多维优惠券建模与OBS-RCT融合.md>) / 滴滴|保留各维度的处理表示，先用随机数据对比 TransTEE|**可做小实验**。观察预训练的额外收益约 0.178%，整体 1.26% 包含其他改动。|
|处理组和对照组共享哪些信息|[CHAUN + RA-IPS](CHAUN_RA-IPS.md) / Alibaba/中国人民大学|先试双头交互，再单独试稳健倾向权重|**需补条件**。RA-IPS 式 12 和 13 的目标不一致。倾向匹配数据仍有未观测混杂风险。|
|两种补贴叠加后是否仍值得投|[M-DLRI](M-DLRI_候选.md) / Alibaba/西安电子科技大学|用低秩联合响应表示杠杆交互，单独检验单调约束|**研究线索**。仅有摘要索引。组合分配机制、强基线与消融表缺失。|

## 触达、召回与组合动作

先明确动作是开关一个召回源、少给一次曝光、选择发送时机，还是提交整组素材。每一种动作需要不同的对照。

|遇到的问题|论文与企业|先改哪一层|采用条件|
|---|---|---|---|
|哪些请求值得开启商业召回|[Pinterest 商业召回因果门控](Pinterest_商业召回因果门控.md) / Pinterest|随机开关召回源，估计增量并选择触发阈值|**可做小实验**。表 1 用处理组作百分比分母。上线前还要核对算法阈值方向和实际召回量。|
|怎样减少给本来就会发现内容的用户曝光|[Spotify Incremental Recommendation](Spotify_双阈值增量推荐.md) / Spotify合作，首作者工作在Spotify期间完成|用响应概率下限和自然发现概率上限决定是否曝光|**可做小实验**。两种标签窗口不同。需要等曝光对照和预设的消费非劣门槛。|
|同一人一天何时触达、用哪种样式|[BUOPLR](BUOPLR.md) / Kuaishou|先估时间和样式组合的多结果增量，再做配额分配|**需补条件**。多个动作竞争同一时槽时，剪枝可能漏掉最优解。需与小规模精确解比较。|
|怎样选出一起投放的一组广告素材|[Ad-POM](AdPOM_组合素材.md) / Hakuhodo Technologies/庆应大学|先选组合结构，再在该结构内选具体素材|**需补条件**。主结果包含已知真实奖励结构的对照。半合成结果还需在线验证。|

## 预算分配、定价与执行

已有响应分数时，定位损失发生在边际价值估计、动作超出历史覆盖、全局预算求解，还是实际送达。

|遇到的问题|论文与企业|先改哪一层|采用条件|
|---|---|---|---|
|固定总预算，往哪个渠道挪钱|[ReAlloc](ReAlloc.md) / Alibaba/淘宝|估计局部预算变化的边际价值，只在有数据支持的范围行动|**需补条件**。利润和成本区间有冲突。优先比较两种策略在相同动作限制下的表现。|
|多条业务线竞争同一份资源|[LinkedIn 因果增量与全局约束](<../2026推荐系统论文地图/论文/P7_探索多目标与增量价值/DragonBandit_2608_10182.md>) / LinkedIn|用增量分数和全局约束分配，再按实际送达调整进度|**可做小实验**。8 周 LTV 提高 7.20% 是整套系统的结果。各组实际花费尚不完整。|
|跨周调价时，历史响应曲线还能用吗|[Causal Action Geometry](Causal_Action_Geometry.md) / 淘天/北京大学/香港中文大学（深圳）等|筛选跨时稳定的相对响应，再拟合当前基线|**需补条件**。先与固定对数响应比较。理论保证与生产神经网络之间仍有实现差距。|
|共享预算是否被支持不足的补贴档耗尽|[CASH](CASH_广告主补贴.md) / 快手/复旦/天津大学|按预测可靠范围筛选动作，再做路由和分配|**需补条件**。历史已执行档位的预测误差，无法检验未投档位的反事实响应。|
|阶梯奖励怎样在共享预算内定门槛|[Meituan Threshold Incentives](Meituan_阶梯激励预算.md) / 美团，部分作者兼署NTU/清华/同济|用历史请求估计响应，再用小规模试验校准奖励成本|**需补条件**。S=2048 未通过预设近无损检验，理论预算收紧也未写入算法 1。|
|司机补贴怎样随需求和剩余预算调整|[D³-Subsidy](<../论文精读/自动出价论文精读/D3-Subsidy：城市级司机补贴的序贯控制.md>) / Didi International Business Group|用扩散模型生成城市状态轨迹，逆动力学给出控制量，再映射到订单补贴|**需补条件**。v4 允许预算容差。硬预算场景须检查每条实际执行路径。|
|激励广告怎样兼顾回报与全局约束|[GOAL](GOAL_邻近决策.md) / Kuaishou/电子科技大学|在生成动作时纳入全局约束|**需补条件**。工业离线评估与分流细节有限，合成实验表的 ROI、RVR 重算存在差异。|

## 渠道归因与经营诊断

先定义需要解释的差额。渠道报表归因、广告可触达人群的增量、销售下滑的可干预原因，各自依赖不同的比较对象。

|遇到的问题|论文与企业|先改哪一层|采用条件|
|---|---|---|---|
|日常归因高估广告增量|[ETDC+HCA](ETDC_HCA.md) / TikTok/ByteDance|用随机实验校准渠道归因，再向下分摊|**可做小实验**。91.38% 衡量校准误差下降。分摊到素材的金额仍缺少独立实验。|
|没做随机实验时，谁能作为广告对照|[Tatari CEM+DML](Tatari_CEM_DML.md) / Tatari|先限定可触达人群和相同观察窗口，再匹配、估计效应|**需补条件**。33.8 倍比较的是两个估计值。匹配人群的平均效应不能直接指导追加预算。|
|品牌搜索广告是否抢走自然点击|[Microsoft 品牌广告历史再发表](Microsoft_广告回报_历史再发表.md) / Microsoft Research合作|利用选择边界估计效应，处理内生投放|**需补条件**。2026 年出版的历史研究。复用估计器前还缺尾部公式和推断细节。|
|渠道间搬移的转化如何计入总增量|[GrowthLoop 跨渠道归因错配](GrowthLoop_跨渠道归因错配.md) / GrowthLoop|用持续留出的对照组区分跨渠道迁移和总量增长|**需补条件**。三组数值模拟检验了错配机制，真实预算调整的经营收益待验证。|
|销售下滑时该先改哪个经营因素|[Amazon 销售损失因果诊断](Amazon_销售损失因果诊断.md) / Amazon|用残差化和反事实替换生成建议，再观察是否执行|**需补条件**。29.14% 来自采纳建议的子组。需在最初全部随机对象上比较。|

## 网络外溢与跨期决策

队友或其他用户会受影响时，先确定随机化单位。动作会改变未来状态时，先确定策略持续时间和结果成熟窗口。

|遇到的问题|论文与企业|先改哪一层|采用条件|
|---|---|---|---|
|分享传播到对照组，怎样估全量效果|[Flywheel](Flywheel.md) / Tencent/HKUST|按分享来源区分直接访问与下游传播，修正全量读数|**需补条件**。校正会改变效应读数。200 次 A/A 复用了同一周日志。|
|激励一个人会不会同时影响队友|[TEUM](TEUM_证据待补.md) / Tencent/NUS|训练时加入队友信息，尝试将团队模型蒸馏到个人模型|**研究线索**。摘要提到效应解耦与蒸馏。团队效应的识别条件和部署收益未知。|
|这周发券是否改善之后几周的价值|[Lyft NBA](Lyft_NBA.md) / Lyft|校正发券后的状态转移，在预算约束下求长期策略|**需补条件**。19% 和 8% 来自模型离线估值。策略价值需要独立的跨周期随机实验。|
|激励广告短期稀疏，如何分配下一次激励|[Offline-MBRL](Offline_MBRL.md) / ByteDance/南京大学/HKUST|建模下一步收益与状态，用保守的价值估计约束策略|**可做小实验**。离线 CES 不能验证整条策略，同成本结论还需要实际支出证据。|
|排序分数怎样反映用户后续几天的价值|[DCEO](DCEO_长期代理排序.md) / 阿里淘天|用长期目标的价值模型训练可接入排序的代理分数|**需补条件**。代理受到同一价值模型的自评。结果窗最长 4 天，41 天为实验运行时长。|
|怎样让召回覆盖有后续价值的新品|[GrowthGR](GrowthGR_长期商品增长.md) / 阿里淘天|用商品长期价值预测和多目标奖励训练新品召回|**需补条件**。历史点击未经随机化。需分别验证新品净成交和对老品的挤占。|
|长期结果未成熟时怎样比较推荐策略|[STEAL](STEAL_证据待补.md) / 阿里淘天/浙江大学|用短期随机实验和历史长期结果构造评估候选|**研究线索**。仅有题录与二手介绍。长期效应定义、识别公式与实际效果未知。|

## 实验设计与发布

按决策环节选方法。区域实验要选分组和反事实，稀疏实验要估计不确定性，长期发布要衡量短期指标对最终结果的预测价值。

|遇到的问题|论文与企业|先改哪一层|采用条件|
|---|---|---|---|
|没有用户级标识，怎样做地区增量实验|[Google Meridian GeoX](Google_Meridian_GeoX.md) / Google|选择区域分组，建反事实，再按设计做安慰剂检验|**可做小实验**。A/A 可以检验零效应下的表现。非零提升的精度还需注入实验或真实实验。|
|转化稀疏时，实验结果值不值得发布|[Teads HBM](Teads_分层贝叶斯.md) / Teads|分层估计各 campaign 的效果，再加业务最小收益门槛|**可做小实验**。估计器和发布规则需分开验证。按小时反复查看还要检验误报率。|
|短期实验指标能否支持长期发布|[长期效果业界共识](长期效果业界共识.md) / Pinterest/Netflix/Meta/Google/Uber/Airbnb/Lyft等|在历史实验之间检验代理指标、长期效应与决策损失|**可做小实验**。文中汇总多个平台的经验与历史研究，适合设计本地回测。|
|核心经营指标噪声大，该多信代理几分|[Netflix Blending](Netflix_Blending_代理与北极星.md) / Netflix|按精度组合代理与同期可测的核心指标，改变发布权重|**需补条件**。论文与代码产生不同权重，混合检验也未保证核心指标的 5% 误报率。|
