# 模型构建交接协议

## 用途

`research_map/paper_modules.jsonl` 是论文模块的唯一中间协议。一条 JSONL 记录对应一个论文模块，同时服务两种下游：

1. 群播只抽取论文解释、模块重点、方法过程、输入输出、应用和证据；
2. 模型构建工作读取接入位置、最小可接入单元、训练/在线行为、耦合、数据条件和代码入口。

不要再创建内容重复的 `module_handoffs.jsonl`。不要在这里保存实验状态、负责人、排期、完成百分比或业务效果。

## 项目接口契约

长期项目在 `research_map/system_contract.yaml` 保存当前系统接口。它至少包含：

- 业务边界与明确排除项；
- 系统模块的稳定编号和中文名称；
- 每个模块的输入、输出、决策粒度和更新时点；
- 已确认的当前 baseline；
- 仍待项目确认的接口事实。

系统契约只用于论文入选后的工程映射，不能反过来限制论文分类，也不能把当前 DT baseline 变成文献范式锚点。

## 每条模块记录

必填字段：

| 字段 | 说明 |
|---|---|
| `协议版本` | 当前为 `1.0` |
| `模块编号` | 稳定且唯一，格式建议为 `论文编号__英文短标识` |
| `论文编号`、`论文标题`、`模块名称` | 论文和模块身份 |
| `解决问题`、`一句话重点`、`处理` | 面向人的问题、关键设计和方法过程 |
| `输入`、`输出`、`应用位置`、`证据` | 论文原始模块接口和支持方式 |
| `目标系统模块` | 必须使用 `system_contract.yaml` 中的中文模块名称，可为多个 |
| `接入方式` | 使用下方受控词表 |
| `最小可接入单元` | 真正能够独立工作的最小组件或组件组 |
| `离线训练内容`、`在线更新内容` | 明确哪些量何时学习或更新；没有则写 `无` |
| `耦合依赖` | 必须共同修改或共同训练的组件列表 |
| `数据前置条件` | 接入前必须具备的日志、标签、行为概率或时序信息 |
| `不适用条件` | 论文方法失效或不能直接迁移的条件 |
| `项目接入判断` | 问题匹配、改造范围和数据准备度，不合并为虚假的总分 |
| `代码入口` | 已核验仓库、模块级路径和说明；未知值用 `null` |

### 接入方式词表

- `直接替换`：替换现有组件，主要接口语义不变；
- `前置增强`：为现有组件增加状态、标签、样本或预测；
- `后置校正`：对已有分数、动作或预算结果再约束或校正；
- `训练约束`：主要改变目标函数、奖励或训练过程；
- `评估组件`：只用于离线比较、诊断或可信度判断；
- `耦合模块组`：必须与列出的组件共同接入或训练；
- `整链路替代`：状态、动作或反馈闭环被整体改变。

### 项目接入判断词表

- `问题匹配`：`直接`、`邻接`、`较弱`；
- `改造范围`：`局部`、`多模块`、`整链路`；
- `数据准备`：`已有`、`可加工`、`缺失`、`待项目确认`。

这些判断不影响论文是否进入群播。它们只帮助研发选择接入顺序。

## 更新规则

1. 同一 `模块编号` 只保留一条当前记录；论文版本或项目接口变化时更新原记录，不追加重复项。
2. 模块是论文中的解释单元；`最小可接入单元` 才是工程实施单元，两者可以不同。
3. 不能独立迁移的模块必须标为 `耦合模块组` 或 `整链路替代`，不能为了模块化而假装可插拔。
4. 没有核验到代码路径时保留仓库链接并将路径写为 `null`；没有仓库时整个入口为 `null`。
5. 当前项目数据、维度、延迟或 baseline 未确认时写 `待项目确认`，不要从论文推断业务事实。

## 查询

在长期项目根目录运行：

```bash
python .codex/skills/research-tech-broadcast/scripts/query_modules.py \
  --project . \
  "离线评估可以采用什么方法"
```

也可以按目标位置或接入方式过滤：

```bash
python .codex/skills/research-tech-broadcast/scripts/query_modules.py \
  --project . \
  --target 用户状态构造 \
  --integration 直接替换 \
  "用户历史"
```

## 校验

更新系统契约或模块记录后运行：

```bash
python .codex/skills/research-tech-broadcast/scripts/validate_protocol.py \
  --project .
```

校验器检查 JSONL 语法、必填字段、模块编号唯一性、受控词表，以及 `目标系统模块` 是否真实存在于系统契约中。
