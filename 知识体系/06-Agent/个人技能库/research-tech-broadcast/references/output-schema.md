# 群播输出结构

面向用户的交付物是一份统一的 Markdown 日报“技术雷达”。日报按论文组织，一篇论文只解释一次。完整的二至五个模块写入结构化存档；群播默认只展示最能解释方法或最容易接入的二至三个模块。每个展示模块标明仿真系统、出价模型或两者。“出价”指平台向用户给出的价格、券、折扣或激励，不是商家广告 bid。

```markdown
# 技术雷达｜日期

## 本期概览
- 用 1–2 句话写筛选数量、入选数量和真正出现的主题
- 默认不再附入选论文表；入选达到 4 篇时可加仅含标题的导航清单

### 论文标题：一句中文概括

[论文链接]｜日期｜评分｜方向

#### 这篇论文在做什么
用 2–4 句话讲清问题、整体方法流程和最强证据；只有理解方法确实需要时才解释旧方法不足。

#### 重要模块 1：中文模块名
- **核心做法**：一句话写清关键机制；必要时用二至三个短步骤。
- **接口与落点**：适用方向；输入 → 输出；可替换或接入位置。
- **证据与边界**：最直接的证据和最重要的迁移限制；只有整体结果时明确说明。

#### 重要模块 2：中文模块名
同上。

```

## 归类与拆分规则

1. 按模块的目标系统接口标注方向。用户/请求生成、用户状态、行为响应、反馈补全、校准、反事实数据、闭环仿真或离线评估标为“仿真系统”；用户价格/优惠动作、目标、预算、安全约束、探索或策略训练标为“出价模型”。
2. 同一模块命中两类接口时标为“仿真系统、出价模型”，但模块正文只出现一次。
3. 同一论文的不同模块可以标注不同方向，但论文概述和完整模块组只出现一次。
4. 整期无论文时写“本期无达标论文”，只做内部归档，不调用群 webhook。
5. 默认按 2000 字上限把整份日报作为一条 webhook 消息发送；只有正文确实超限时才优先按论文二级标题切块，不添加“消息 1/2”之类的展示性编号。
6. 每篇通常控制在 350–650 个汉字，不重复论文总述中已经交代的背景、作用和限制。

## 模块比较写法

“与已调研论文的关系”不是固定字段。只有存在明确且有帮助的模块关系时，在“证据与边界”之后追加一句，并同时交代：

1. 新论文的哪个模块与旧论文的哪个模块相比；
2. 两者共同解决的具体问题；
3. 机制上的相似点；
4. 最关键的区别，以及该区别为什么重要。

不要只写“类似 DT”“属于生成式方法”或“和 AIGB 同类”。若只能得到这种宽泛结论，就省略比较。

## 核心做法的最低标准

“核心做法”与“接口与落点”合起来，至少要让读者回答四个问题中的三个：

1. 从什么数据、状态或已有组件开始？
2. 论文具体学习、计算、替换或约束了什么？
3. 这个结果怎样进入下一步预测或决策？
4. 为证明作用，实验中固定了什么、只改变了什么？

不要写“使用多个 embedding，再做聚合”这种不可复述的概括。可压缩为：“从历史交互分别学习 ALS/BPR 用户与物品向量，构造静态、均值和近期序列三种状态，并在同一数据切分和策略集合上交叉比较。”群播不列完整公式和超参数网格，但必须点出决定方法性质的操作、更新时点或受控变量。

## 内部最小记录

为周期去重、后续检索和实验交接，在 `papers.jsonl` 与 `paper_modules.jsonl` 保存论文链接、评分分项、摘要、完整模块字段、来源版本和主要播报部分。精简群播只是这些记录的投影，不得反向删除结构化字段，也不应在群播末尾附加机器字段。
