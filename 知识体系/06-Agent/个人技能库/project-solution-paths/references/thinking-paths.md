# 六种通用思考路径

这些路径用于改变看问题的方式。单个项目可以组合使用，但应由当前最影响决策的不确定性决定先后。

<a id="p1"></a>
## 1. 目标倒推：从想要的结果，找真正能改变它的动作

**核心问题：** 如果项目成功，谁的什么结果会改变？我们实际能控制哪一个动作？

**展开顺序：**

业务目的 → 可观测的成功标准 → 产生结果的作用链 → 可控制的决策/动作 → 决策所需信息 → 最小方案。

- 先区分最终结果、过程指标和代理指标。例如“回答质量”可能影响“问题解决”，但还经过使用、执行和完成等环节。
- 把每条作用关系当作需要证据的假设。检查中间指标是否足以影响最终结果，以及实际覆盖规模是否足够。
- 从可以改变的动作倒推模型、规则或信息需求；不要从已有模型出发寻找可以包装的业务价值。
- 有多个目标时，区分可协商的权衡与不可突破的限制。用户没有确认的取舍不能悄悄写进综合分。

**应产出：** 一条简短的结果作用链；一个明确的决策对象；最值得优先验证的连接。

**容易走偏：** 把相关关系当作作用机制；用容易优化的指标替代真正目的；目标写得精确却没有可执行动作。

<a id="p2"></a>
## 2. 瓶颈定位：先确定卡在哪里，再决定用什么技术

**核心问题：** 哪个环节限制了最终效果？有哪些不同原因能产生同样的现象？

**展开顺序：**

还原完整链路 → 量化主要损失/异常 → 列竞争假设 → 找能区分假设的观察或实验 → 修最有证据的原因 → 复验业务影响。

- 按需检查指标口径、数据与标签、信息时点、模型判断、可行动作、执行覆盖、延迟/成本、用户采用。顺序由已有证据决定；已确认的部分不必重复审计。
- 区分“能力不够”“信息没给到”“决策没用上”“动作没执行”“用户没触达”。相同的最终失败可能需要完全不同的解决方案。
- 对最可能的两三个原因写出支持证据、尚不能解释的现象、最小区分实验。优先选择可以改变路线排序的检查。
- 估计环节改善可能影响的范围。小覆盖环节里的巨大提升，可能仍不足以改变整体；漏斗估算只有在口径与依赖关系成立时才可相乘。

**应产出：** 瓶颈假设排序；一项能有效排除原因的检查；对应的针对性改动。

**容易走偏：** 没看执行链路就换模型；把症状当原因；一次改多处后将全部收益归功于某个模块。

## 3. 结构重构：怀疑问题的拆法，而不只是调参数

**核心问题：** 现在被放进同一个模块、同一个目标或同一套规则的事情，是否真的应该一起处理？

**展开顺序：**

找反复冲突/失效的边界 → 识别被混合的机制 → 提出新的划分或职责边界 → 明确信息与资源如何共享 → 与简单统一方案比较。

可选择的重构方向：

- **分人群或场景：** 不同群体的响应机制、信息质量或可行动作不同，统一规则是否掩盖了差异？
- **分时间尺度：** 短期波动与长期趋势是否需要不同更新速度或决策周期？当前动作会不会改变未来状态？
- **分职责：** 事实预测、偏好权衡、资源约束、执行调度、效果评价是否混在一起，导致无法校准或定位问题？
- **改流程顺序或表示：** 是先筛选后判断，还是先整体判断再补信息？错误是否来自过早丢弃候选、工具依赖被截断或不可逆的信息压缩？

先提出“为何存在不同机制”的依据，再引入分层、模块、时序或组合方案。同时检查合并、删减或简化现有步骤是否更有效，重构并不等于拆得更细。比较复杂度、样本稀疏、边界不稳定、维护成本与预期价值。即使拆分，也需说明跨模块目标、接口及合并规则；统一建模加条件信息可能已经足够。

**应产出：** 原框架的限制性假设；一个更合适的结构草图；证明重构有必要的比较实验。

**容易走偏：** 为了看起来精细而分层；把任何异质性都解释为需要多模型；模块各自最优却无法组合。

<a id="p4"></a>
## 4. 增量与资源分配：从“谁表现好”转向“在哪里行动更有价值”

**核心问题：** 如果不做这件事会怎样？多投入一点资源，额外改变多少结果，放弃了什么其他机会？

**展开顺序：**

定义可行动作及不干预基线 → 判断干预分配与数据覆盖 → 估计增量响应及不确定性 → 比较边际收益/机会成本 → 在可行约束内分配 → 用可比条件验证。

- 自然转化高的人未必最值得投入；重要的是行动能改变多少，而不是原本会发生多少。
- 先看是否有识别增量的条件：随机或其他可信的识别设计、干预前信息、动作覆盖、选择机制。没有数据时可先设计小范围探索，不能直接从历史相关性宣称因果提升。
- 不只比较“投或不投”，还检查强度、时机和组合。响应可能饱和、非单调或因人而异；不要为了便于求解强加未经验证的曲线形状。
- 明确预算、容量、体验底线等约束的范围与周期。模型预测约束、求解结果可行性、实际执行后的约束达标是不同检查。
- 比较方案时维持可比预算与约束；额外投入带来的增长与分配效率提升要分开。

**应产出：** 行动—增量—成本的关系；需要补齐的识别或探索数据；一个可执行的资源分配原则。

**容易走偏：** 用高概率代替高增量；用未经校准的分数当金额收益；忽略不干预与未来机会；让优化器替代未知的业务取舍。

## 5. 系统联动：从局部提升，走向整体净收益

**核心问题：** 这里变好，是创造了新价值，还是把资源、风险或损失转移给了别处？

**展开顺序：**

画参与方与共享资源 → 找竞争、互相影响和反馈回路 → 区分局部作用与系统净效应 → 选择能捕捉影响的验证方式 → 检查受益、受损与持续性。

- 标出同一资源由谁竞争，策略如何改变他人的可用选项；检查多个控制器是否会相互抵消或放大。
- 同时看总量与组成：分人群、渠道、城市或阶段判断新增、迁移与挤出。不同单位或口径的指标不能直接相减。
- 区分短期适应与长期反馈，例如等待改变供给、补贴改变习惯、排序改变供给结构。只在确有相关机制时扩展时间视角。
- 实验分组需匹配影响范围；个体随机化若存在严重跨组影响，应考虑按区域、集群或时间等设计，但这些设计仍需处理残留效应、趋势和可比性。
- 形成局部保护或协同规则时，检查是否仍符合整体目标与实际执行约束。

**应产出：** 主要外部影响图或文字关系；系统级验收指标与分方护栏；合适的验证范围。

**容易走偏：** 把某个渠道的增长当平台净增长；只报告总均值而掩盖受损群体；认为扩大实验单位就自动消除偏差。

## 6. 验证迭代：让每一步投入都减少关键不确定性

**核心问题：** 现在最影响决策的未知是什么？用最小代价做什么，能让下一步选择明显更清楚？

**展开顺序：**

列决定成败的假设 → 定义可观察的成功/失败 → 检查评估是否可信 → 设计最小区分实验 → 根据结果选择继续/停止/改道 → 独立复验与扩展。

- 区分验证需求、验证机制、验证实现、验证收益四类任务。新项目可能先做原型或人工服务，成熟策略才需要更严格的系统效果比较。
- 若评分器、标注口径或离线指标本身存疑，先核验其与目标的关系。评估器与被评对象同时更改时，固定输入或执行记录分别比较，不能把标准放宽算作能力提升。
- 针对关键假设做小闭环：给出不同结果会导向哪个决策。只记录“实验成功/失败”，却不改变下一步行动的实验信息价值很低。
- 对复杂改动分离数据、特征、结构、训练预算和决策规则的贡献；按真正需要回答的问题安排消融，不要求穷举组合。
- 选出方案后，用符合真实迁移方式的独立数据或新场景复验，例如未来时间、不同群体或不同环境。调参集不能兼任最终独立证明。
- 扩大覆盖时检查新增区域的效果、成本和可信度；具备离线证据、可做实验、可逐步扩大和已证明稳定有效，是不同结论。

**应产出：** 一个优先假设；最小实验及其决策分支；升级与退出条件。

**容易走偏：** 把实验清单当学习路径；只优化评测集；照搬其他项目的阈值；没有停止标准地无限迭代。
