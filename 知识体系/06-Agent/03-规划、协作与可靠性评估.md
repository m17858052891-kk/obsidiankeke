# 规划、协作与可靠性评估

先修：[[知识体系/06-Agent/01-Agent：状态、工具与控制循环|Agent状态与工具循环]]、[[知识体系/06-Agent/02-RAG、记忆与上下文管理|RAG与上下文管理]]、[[知识体系/05-强化学习/01-MDP与Bellman|MDP与Bellman]]。规划的价值在于选择有效行动与管理依赖；评估的价值在于判断这些行动是否真的完成目标。

## 1. 计划是关于行动与条件的假设

“先查资料，再分析，再总结”没有给出依赖和验收条件。更有用的计划是：先确定统计口径；若来源冲突则核对时间版本；拿到可比较数字后计算差值；最后逐条检查结论是否由证据支持。

可将子任务表示为有向无环依赖图：上游输出满足下游输入条件才能继续。独立检索可并行，依赖检索结果的计算应顺序执行。错误地并行有依赖的步骤，会让后续动作使用猜测的中间结果。

计划也应随观察更新。初始计划可能假设文件是 CSV，读取后发现是多表 Excel，就需要调整解析方式。死守初始步骤不是规划能力，发现假设失败并修正才是。

## 2. 搜索多个候选何时有意义

一次生成只探索一条路径。多候选、beam 或树搜索可以扩大考虑范围，但需要候选生成器、评价函数、分支预算与回溯规则。

如果每层分支数为 $b$、深度为 $d$，完全展开约需 $O(b^d)$ 个节点，因此评价器要能有效剪枝。若评价器更偏爱流畅错误，增加搜索只会更积极地找到评分漏洞。Tree of Thoughts 展示了在若干任务上组织候选与搜索的方式；不能据此断言树搜索对所有 Agent 任务都有效。[Tree of Thoughts](https://arxiv.org/abs/2305.10601)

程序验证、精确计算、环境反馈通常比同一模型的无依据自评分更有独立信息。模型自我批评可能有用，但若共享同一盲点，重复反思也可能只是重述错误。

## 3. 多 Agent 的收益取决于分工和误差相关性

当任务能拆成独立来源检查、不同专业视角或互补证据收集，多 Agent 可增加覆盖与并行度。但每个 Agent 都读同样上下文、使用相同假设时，其错误可能高度相关；多数投票不等于独立证据。

委派应明确输入、期望产物、边界和合并标准。输出“我已经处理好了”不如返回结论、依据和不确定项。还需指定共享状态与文件的所有权，否则并发修改可能互相覆盖。

协作成本包括通信 token、重复阅读、协调等待和冲突处理。若任务很小、依赖链很长或只能共享一个可变环境，单个 Agent 配确定流程可能更有效。这是系统设计判断，不是智能体数量的竞赛。

## 4. 长任务成功率为什么容易下降

一个简化例子：假设 20 个关键步骤相互独立且每步成功率为 0.98，全部成功概率是 $0.98^{20}\approx0.668$。现实错误往往相关，所以这不是实际成功率公式，而是提醒：高单步准确率不足以保证长链可靠。

恢复机制能改变这个结果。若每一步都有可观察验证、可安全重试与必要回滚，失败不必传播到最后。相反，一个未发现的早期错误可能污染所有后续状态。

因此应把任务拆到能验证的阶段，并保留足以恢复的中间成果；不是为了展示很多步骤，而是减少不可检测的误差传播。

## 5. Eval 的评价单位应该是任务结果

对于文件整理任务，最终文件、链接和内容是否符合要求比工具调用数量更重要；对于检索任务，结论与引用是否可靠比文字长度更重要；对于工具任务，目标状态是否达到比模型说“成功”更重要。

指标可以分层：任务成功率、约束违反率、部分完成程度、成本与延迟；过程诊断再看错误工具选择、参数错误、漏读结果、恢复失败和停止错误。不要把过程代理指标当终极目标，否则系统可能学会刷分。

同一个任务应在必要时重复运行，因为模型采样、工具环境与网络可能随机。报告均值时也要看长尾失败和分类型表现；总体成功率可能掩盖某类关键任务完全不会做。

## 6. 评审模型也需要校验

LLM-as-judge 可扩展评价，但可能有位置、长度、风格和自偏好等偏差。先定义可执行标准，再用人工标注或客观检查校准 judge；对边界例子看一致性与误判模式。

有条件时让答案匿名、交换候选顺序、提供证据并要求对具体条件评分。若只问“哪一个更好”，很容易让文风取代正确性。训练奖励与最终评审也应避免共享完全相同的可利用漏洞，见 [[知识体系/03-LLM/06-偏好优化：DPO、PPO与GRPO|偏好优化与LLM强化学习]]。

## 7. 工具反馈如何成为学习信号

执行日志可用于 SFT 模仿成功轨迹、偏好学习比较不同轨迹，或 RL 优化任务回报。但日志有选择偏差：只保存成功案例会失去失败恢复信息；把错误执行结果写成成功会训练出虚假完成。

奖励需区分正确完成、部分完成和违反约束。仅奖励“最终给出答案”可能诱导跳过证据收集；仅惩罚工具成本可能诱导不用必要工具。一个合理目标可能是任务效用减成本，但硬约束仍需单独定义。

因果问题也会出现：某条工具路径与成功相关，可能只是它被用于简单任务，不代表切换到这条路径就会提升所有任务。算法比较应控制任务分布和资源预算。

## 8. 自检与解析

**问：为什么多次自我反思仍可能无效？** 没有新证据或独立检验时，同一模型可能重复同一误解。应找能区分候选解释的观察或验证。

**问：多 Agent 投票通过就更可信吗？** 只有误差具有一定独立性、投票对象合适且有可靠合并规则时才可能提高可信度。共同来源错误不会被人数消除。

**问：一个 Agent 连续成功一次能证明它可靠吗？** 不能。需要覆盖代表性任务、边界条件和重复运行，明确成本与失败范围。
