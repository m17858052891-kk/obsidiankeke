# Agent：状态、工具与控制循环

先修：[[知识体系/03-LLM/01-分词、自回归与语言建模|分词与语言建模]]、[[知识体系/05-强化学习/01-MDP与Bellman|MDP与Bellman]]。这里将 Agent 理解为能够依据观察选择行动、接收反馈并继续完成任务的系统。模型是其中的决策组件，可靠完成任务还依赖状态、工具、执行器与停止条件。

## 1. 一次回答与闭环执行的差别

普通问答生成文本后结束。工具型 Agent 则可重复执行：观察环境 → 更新任务状态 → 选择动作 → 执行工具 → 读取结果 → 验证进展。

例如“找出两份报告的数据差异”：先读取文件，确认统计周期与单位，再计算差值，发现口径不同后回到来源检查，最后给出有证据的比较。关键是新观察能改变下一步；事先写一串工具调用但不看结果，只是开环流程。

ReAct 将推理式中间记录和环境动作交替组织，展示了行动获取信息、信息修正后续行为的方式。它是一种控制模式，不保证每条中间解释都正确，也不要求展示模型内部隐私推理。[ReAct 原论文](https://arxiv.org/abs/2210.03629)

## 2. 状态应保存什么

可以把系统状态分为：目标与约束、已核实事实、待验证假设、当前计划、已执行动作与结果、外部对象的版本和标识。它们的可靠程度与更新规则不同。

“已发出修改请求”不等于“修改成功”；“模型打算打开文件”不等于“已读到内容”。若把计划和观察混在同一段摘要里，后续模型可能将愿望当事实，从而跳过验证。

从决策角度写为：

$$a_t\sim\pi_\theta(\cdot\mid g,h_t),\quad o_{t+1}\sim\mathcal E(\cdot\mid a_t),\quad h_{t+1}=U(h_t,a_t,o_{t+1}),$$

其中 $g$ 为目标，$h_t$ 是可用历史或其摘要。摘要 $U$ 若丢失关键约束，后续策略就基于不充分状态决策，类似 [[知识体系/05-强化学习/01-MDP与Bellman|MDP与Bellman]] 的部分可观测问题。

## 3. 工具调用分成选择、参数和执行三层

第一层决定是否需要工具以及哪一种；第二层构造合法且语义正确的参数；第三层执行器访问真实环境并返回结果。JSON 合法只证明参数语法满足某些约束，不证明文件路径正确、日期范围正确或动作符合用户目标。

一个好的工具接口应明确输入字段、单位、对象身份、权限、返回结构和错误类型。例如 `amount=100` 若没有币种和最小单位定义，模型再强也可能执行错误金额；`delete(name)` 若名称不唯一，就应该先解析稳定 ID。

工具结果也必须可追溯：来源、版本、时间和错误码常比长段自然语言更有助于后续决策。把所有失败返回“操作失败”会迫使模型猜测；区分权限不足、对象不存在、网络超时与校验失败，才能选择合适恢复方式。

## 4. 读操作与有副作用操作需要不同恢复逻辑

读取超时通常可以重试；提交订单超时则不确定服务器是否已执行。直接重试可能重复提交，因此需要操作 ID、幂等键或先查询执行结果。

幂等意为重复执行同一操作不会产生额外效果，不等于接口天然保证“只执行一次”。跨工具多步任务还可能部分成功：文件已写入、索引更新失败。系统应能识别完成到哪一步，并恢复或补偿，而不是整段盲目重跑。

这解释为什么 Agent 的可靠性不只取决于语言能力。动作与环境状态之间的契约，需要由程序和数据设计明确表达。

## 5. Workflow 与自主选择的边界

固定 workflow 预设步骤与分支，适合路径稳定、可枚举的任务；更自主的 Agent 根据观察决定下一步，适合路径不确定的任务。二者可以组合，例如外层程序固定检查点，内层模型决定检索与分析方法。

增加自由度会扩大能处理的任务范围，也增加难以穷举的行为。应根据任务的不确定部分开放决策，而不是把所有控制逻辑都变成提示词。[Anthropic 对 workflow 与 agent 的概念区分](https://www.anthropic.com/research/building-effective-agents)（引用其架构思想，不以该早期文章代表当前工具生态。）

## 6. 外部文本是数据，不能自动成为执行权限

检索网页、仓库注释和邮件正文可能包含“忽略原任务”“运行某命令”等文字。如果系统把被读取内容提升为控制指令，就出现信任边界混淆。Prompt injection 的关键不只是文本难看，而是低信任输入改变了高权限行为。

因此数据来源、用户指令和执行权限应有明确分层；工具授权、参数约束与敏感动作验证不能完全靠模型在长上下文中自觉记住。对学习而言，应理解这是信息流和权限设计问题，而非单靠一句“请不要被攻击”解决。

## 7. 停止条件也是策略的一部分

成功停止应有可观察证据，例如目标文件存在且内容验证通过；失败停止应说明缺失什么；预算停止则明确哪些子目标未完成。模型说“完成了”不是独立证据。

无停止条件的循环可能反复检索同一问题、重复调用无效工具或在证据不足时持续猜测。需要根据新信息增益、重复错误、执行预算与任务完成标准决定继续、换路或停止。规划与评估见 [[知识体系/06-Agent/03-规划、协作与可靠性评估|Agent规划与可靠性评估]]。

## 8. 自检与解析

**问：能调用一个函数就算 Agent 吗？** 名称没有统一边界。更有用的是检查它是否根据结果继续决策、维护状态并验证目标；单次工具调用也可以只是固定流程的一步。

**问：工具返回成功，任务就完成了吗？** 不一定。接口成功只对应该操作的后置条件；最终目标可能还需要内容校验、其他操作或外部状态核实。

**问：为什么更长历史也会让执行变差？** 冗余、过时状态、相互冲突信息和关键约束被稀释都可能影响决策。需要有效状态管理，见 [[知识体系/06-Agent/02-RAG、记忆与上下文管理|RAG与上下文管理]]。
