# 检索：表示、负采样与 ANN

先修：[[知识体系/01-统计与优化/02-似然、交叉熵与KL|似然、交叉熵与KL]]。检索要从巨大候选集合找到值得进一步处理的少量对象。它不仅是训练一个相似度函数，还要让训练目标、索引和线上候选空间一致。

## 1. 双塔为何适合大候选池

查询/用户编码为 $u=f_\theta(x)$，文档/物品编码为 $v_i=g_\phi(i)$，分数 $s_i=u^\top v_i$。物品向量可预计算，在线只计算查询向量并做向量检索。DPR 是这种思路在开放域问答中的代表应用。[DPR](https://arxiv.org/abs/2004.04906)

代价是 query 与 item 的复杂交互被压缩到向量与打分函数中。若任意候选都需和用户全特征共同跑一个大网络，就难以提前索引；可先双塔召回，再用更复杂模型排序。

若向量都 L2 归一，内积等于余弦相似度；若不归一，向量范数也影响分数。训练用内积、服务改余弦可能改变排名，不能当成无影响的实现替换。

## 2. 对比损失在区分什么

对一个正例和若干负例，常见损失：

$$L=-\log\frac{\exp(s^+/\tau)}{\exp(s^+/\tau)+\sum_{j=1}^{K}\exp(s_j^-/\tau)}.$$

对任一分数的梯度为 $(p_j-y_j)/\tau$。低温使概率更集中、强调高分竞争项，同时改变梯度尺度；效果还受向量范数和优化器影响。温度不是单纯“越小越精确”。

负例定义决定学到的区别：随机物品教粗粒度区分，近邻难负例教细粒度边界，但其中可能有未标注的相关物品。把“没有点击”直接当“不喜欢”还混入曝光位置、未看到和任务意图等因素。

## 3. In-batch negatives 的效率与采样偏差

一个 batch 的正例可互相作为其他 query 的负例，矩阵乘法得到 $B\times B$ 分数，复用计算。但 item 出现概率往往接近日志流行度，热门 item 更频繁成为负例。

为什么采样分布重要？假设正例来自 $p(i\mid x)$，负例来自 $q(i)$，把一个候选判为正例的最优分类 odds 与 $p(i\mid x)/q(i)$ 成比例。未经校正的对比打分因此可能学到对负采样分布的相对密度，而非全候选概率。

若目标是近似全量 softmax，可在适合的采样设定下用 $s_i-\log q(i)$ 等校正 logits；抽样次数、是否放回、正例是否可能重复和具体损失会影响精确形式。不能把任何 in-batch loss 都套上一个 logQ 就宣称无偏。[推荐采样校正的研究](https://research.google/pubs/sampling-bias-corrected-neural-modeling-for-large-corpus-item-recommendations/)

重复 item、同用户多个有效正例和语义近似项会产生 false negatives。可以根据任务使用去重、多正例目标或显式屏蔽，但也需要防止把真正有区分力的负例全删掉。

## 4. ANN 的近似发生在搜索，而非必然在表示

精确扫描 $N$ 个 $d$ 维向量成本约为 $O(Nd)$。近似最近邻以索引和压缩换取较少搜索：图索引通过邻接导航，倒排聚类先筛候选区域，乘积量化压缩向量和距离计算。[Faiss 官方说明](https://github.com/facebookresearch/faiss)

要分别看模型召回质量和索引近似损失：在相同向量上，ANN 找到精确 top-k 的比例；在业务标签上，这些候选是否相关。索引调参只能减少搜索误差，不能修复无意义 embedding。

搜索范围更大通常增加召回和延迟，但具体曲线依数据与索引而异。更新频率、删除过滤、内存、并发和候选权限也都属于检索系统条件。

## 5. 冷启动与索引新鲜度

新物品没有行为 ID 统计，可利用内容、类别、作者等特征产生向量；但内容相似不保证协同行为相同。训练时需模拟缺少行为数据的条件，否则线上冷启动分布不同。

新向量即使算好，没进入索引仍无法被主检索找到。可设计增量索引或新物品独立通路，再合并去重。模型版本更新时，query 塔和 item 塔坐标空间必须兼容；只更新一侧可能破坏相似度。

## 6. 多路召回与后续排序

协同、内容、热门、关注和新物品通路捕捉不同信号。评估每一路不仅看独立 Recall，还看并集合并后的边际贡献、候选重叠与成本。独立指标高但与主路高度重复，可能贡献很小。

Recall@K 衡量候选覆盖，无法回答排序后的用户效用；排序模型也无法选择未进入候选池的物品。不同阶段应明确自己的可控制范围。

## 7. 自检与解析

**问：batch 越大，负例越多，是否一定更好？** 不一定。计算、假负例、流行度采样与难度分布都改变；需要比较同一数据和资源条件下的有效信号。

**问：训练 Recall 好，线上突然变差，先查什么？** query/item 版本、特征预处理、归一化和距离度量、索引更新、过滤与候选覆盖，再看模型本身。

**问：RAG 检索与推荐召回是完全不同的知识吗？** 双塔、对比目标、ANN 与重排结构可共享；监督定义、证据完整性和业务评价不同，见 [[知识体系/06-Agent/02-RAG、记忆与上下文管理|RAG与上下文管理]]。
