# 序列推荐与生成式推荐

先修：[[知识体系/02-神经网络与Transformer/02-Attention：数学、信息流与复杂度|Attention原理]]、[[知识体系/02-神经网络与Transformer/04-位置编码与RoPE|位置编码与RoPE]]、[[知识体系/07-检索与推荐/01-检索：表示、负采样与ANN|检索表示与负采样]]。推荐序列不只是把文本 token 换成 item ID；行为、曝光、时间、候选与标签生成机制决定信息应如何流动。

## 1. 历史中包含什么，决定模型能学什么

点击序列记录已选择行为，曝光序列还记录未点击机会；二者提供不同监督。只看点击历史，无法知道用户没点击某 item 是不喜欢还是没看见。支付、收藏、停留也有不同含义和延迟。

预测时点必须明确。若目标是曝光时预测转化，之后的点击、订单状态或更新后的用户画像不能进入特征。按事件时间排序还不够，应检查字段何时实际可获得。

不同用户行为间隔差异很大，序号不能替代真实时间。行为类型、相对时间与会话边界可以补充序列结构，但需评估其贡献和泄漏风险。

## 2. DIN：候选决定读取哪段兴趣

给定候选 $q$ 和历史表示 $h_i$，可计算候选相关权重 $a(q,h_i)$，得到兴趣汇总 $u(q)=\sum_i a(q,h_i)h_i$。用户表示因候选不同而变化，适合表达“对这个候选，与哪些历史相关”。[DIN](https://arxiv.org/abs/1706.06978)

代价是每个候选都可能需要交互计算，不像一个固定用户向量可以直接查询所有 item。注意原始 DIN 的局部激活权重设计与标准 Softmax attention 不完全相同，不能把所有加权聚合统一改写后仍宣称是论文原式。

权重高说明该模块在当前前向中强调了某历史，不等于该历史对用户真实行为有因果影响。

## 3. SASRec：历史内部先建立依赖

SASRec 以因果 self-attention 编码过去行为，再预测下一物品。历史位置能读哪些位置由 mask 定义，位置表示提供顺序信息。[SASRec](https://arxiv.org/abs/1808.09781)

与 DIN 的核心区别是信息流：DIN 让候选显式查询历史；SASRec 先在历史内部整合序列，再用于候选打分。可以组合思想，但需要明确候选何时进入计算图，以及是否影响可缓存性。

若用未来行为编码当前状态再预测下一项，会引入穿越。离线滑窗构造要确保每个目标的输入前缀与部署一致。

## 4. 多兴趣表示与统一交互

一个用户向量会把多个兴趣压在同一表示中，多兴趣方法输出多个向量并分别召回，试图覆盖不同意图。但兴趣数量、路由和候选匹配都有设计取舍；多向量也增加索引查询和去重成本。

将用户、上下文、历史和候选放进统一 token 序列，可以让不同类型信息通过 attention 交互。自由度更大也意味着 mask、token 身份和训练任务更重要；某种候选前置或 token 排列是否有效，应看模型定义与消融，不能用“统一”二字替代机制。

你现有的 [[PCVRHyFormer/README|PCVRHyFormer入口]] 与 [[序列建模/README|序列建模入口]] 可作为具体案例。阅读时把论文结构、项目实现差异、消融结果分别对应到“候选进入时机”“哪些 token 可见”“哪个输出承担哪个任务”。

## 5. 生成式推荐改变输出空间组织

常规检索可对 item 向量打分；生成式路线可将物品编码为短离散序列 $z_{1:m}$，分解：

$$P(i\mid h)=P(z_{1:m}(i)\mid h)=\prod_{j=1}^{m}P(z_j(i)\mid h,z_{<j}(i)),$$

若编码唯一且所有合法码序列与 item 对应，这给出 item 的一种概率参数化。若编码碰撞、多物品共享同码，还需消歧；若模型生成不存在的码组合，则需合法性约束和映射规则。

语义 ID 希望相关 item 共享部分码，借助层级结构泛化。它可以由内容或协同表示学习得到，语义相近程度取决于底层表示，不是叫 SID 就自动具备稳定语义。[生成式推荐中的语义 ID 路线](https://arxiv.org/abs/2305.05065)

## 6. 残差量化怎样逐层编码

给定向量 $v$，第一层选择最近码向量 $c_1$，残差 $r_1=v-c_1$；第二层量化 $r_1$ 得 $c_2$，继续得到 $v\approx c_1+\cdots+c_m$。每层码本索引组成离散序列。

这与普通一次 K-means 的区别是逐步逼近剩余误差。训练中还需考虑码本利用率、重建目标和下游推荐相关性；仅重建得好不证明生成排序更好。已有细化内容：[[tmall-hstu/01-RQ-VAE原理与损失函数|01-RQ-VAE原理与损失函数]]。

编码稳定性也影响维护：码本更新后旧 ID 可能改变，需要同步训练数据、索引、缓存与物品映射。新 item 如何分码、冷启动如何处理，是系统的一部分。

## 7. HSTU 不应被简化成“商品版普通 GPT”

HSTU 等工作针对推荐序列的事件结构、计算与扩展方式设计模块。其 attention/归一化等细节应按论文与实现理解，而非假定所有模块都等同标准 Transformer。[HSTU 论文](https://arxiv.org/abs/2402.17152)

生成式推荐也不必等于用自然语言聊天生成商品名称。可以在离散 item/SID 空间建模，评价仍需回到候选合法性、召回、排序、覆盖、成本与真实用户效果。你的 [[tmall-hstu/README|tmall-hstu入口]] 是项目入口，模型效果结论应以对应实验记录为准。

## 8. 自检与解析

**问：因果 attention mask 是否让推荐结果有因果解释？** 不是。mask 控制时间可见性，因果效应识别仍需处理分配与潜在结果假设。

**问：生成的 SID 每一位都概率最高，物品就一定全局最优吗？** 不保证。逐位贪心可能错过高联合概率序列，且概率最大不等于业务效用最大。

**问：SID 和 item ID 哪个必然更好？** 没有必然。SID 提供结构共享也可能损失细粒度区分；应看表示质量、碰撞、冷启动与下游目标。
