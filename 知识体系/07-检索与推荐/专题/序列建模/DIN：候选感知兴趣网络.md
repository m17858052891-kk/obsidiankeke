# DIN：候选感知兴趣网络

> DIN（Deep Interest Network）的核心不是先生成一个固定用户向量，而是针对**当前候选物品**，从用户历史中动态挑出相关兴趣。它适合多兴趣用户的 CTR/CVR 精排。

## 1. 它解决什么问题？

Mean/Sum Pooling 将历史压成同一个向量：

$$u=\frac1L\sum_{j=1}^Le_j.$$

用户既买母婴也看数码时，候选是奶粉还是耳机，$u$ 却相同。DIN 令用户表示依赖候选 $c$：$u(c)$；奶粉激活母婴历史，耳机激活数码历史。

## 2. Local Activation Unit 如何实现？

候选 embedding 为 $e_c$，第 $j$ 条历史为 $e_j$。DIN 通常拼接：

$$[e_j,e_c,e_j-e_c,e_j\odot e_c],$$

送入小 MLP 得到相关分数：$a_j=f_{att}(e_j,e_c)$，再加权聚合：

$$u(c)=\sum_{j=1}^La_je_j.$$

最终将 $u(c)$、候选、静态用户及上下文特征送入 MLP 输出 CTR。

## 3. 为什么权重不一定 Softmax？

原始 DIN 更强调每条历史的独立激活强度，权重不必在序列维归一化。这样“三次相似购买”可比“一次相似购买”提供更大总信号。Softmax、Sigmoid 或未归一化权重都能实现，但语义、尺度和训练稳定性不同。

## 4. 它是否建模顺序？

原始 DIN 本质是候选感知集合加权。若不注入时间、位置或序列层，交换两条历史通常不改变结果，不能把 DIN 说成强时序模型。DIEN、SASRec、HSTU 才更直接建模兴趣演化与顺序。

## 5. 复杂度和工程注意点

单用户、单候选需对 $L$ 条历史逐条算相关性，约 $O(Ld)$ 加 attention MLP；有 $C$ 个候选时约为 $O(CLd)$。候选多时要矩阵化、限制长度，或缓存候选无关的历史 embedding。

Padding 必须通过 Length/Mask 将分数置零或置极小。仅把 padding embedding 置零不够，因为 Attention MLP 的 bias 仍可能给 padding 非零分数。

## 6. DIN 与 SASRec

| | DIN | SASRec |
|---|---|---|
| 核心 | 候选与哪些历史相关 | 历史顺序如何演化 |
| Query | 当前候选 | 每个序列位置 |
| 表示 | 每个候选一份 $u(c)$ | 可先得候选无关序列状态 |
| 服务 | 多候选时较贵 | 状态更容易缓存 |

二者可组合：先由 SASRec 编码行为状态，再做轻量 target-aware interaction。

## 7. 高频问答与 30 秒回答

**能缓存吗？** 历史 embedding、候选无关投影能缓存；最终 $u(c)$ 依赖候选，不能缓存为一个通用用户向量。

**为什么有效？** 用户兴趣多峰，固定池化混入无关历史；候选感知 attention 能强化候选相关行为。

> DIN 用候选 item 当 Query，对每条历史通过 MLP 算相关强度并加权聚合，因此同一用户面对不同候选会得到不同兴趣表示。它擅长多兴趣精排，但原始结构不强建模顺序，且多候选时计算为 $O(CLd)$，需要 mask、截断和批量化优化。
