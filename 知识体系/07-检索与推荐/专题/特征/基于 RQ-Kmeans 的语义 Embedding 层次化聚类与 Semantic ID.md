
在现代推荐系统、搜索引擎和生成式检索（Generative Retrieval）中，如何表示海量的 Item（商品、文章、视频等）一直是个核心问题。将**语义 Embedding** 通过 **RQ-Kmeans (Residual Quantization K-means，残差量化 K-means)** 转化为 **Semantic ID (语义 ID)**，是近年来工业界和学术界解决该问题的一种极其优雅且有效的方法。

下面我们将循序渐进地拆解这个过程。

## 1. 为什么需要 Semantic ID？

传统推荐系统和检索系统通常使用 **独立的一维 ID (Random ID)** 来表示 Item（例如 `item_id = 10086`）。

- **痛点**：这些 ID 之间是正交的，毫无语义关联。模型必须强行记住每个 ID 的特征，导致严重的**冷启动问题**（新 Item 没有交互历史，模型学不出它的 Embedding）以及**稀疏性问题**。
    

为了解决这个问题，研究人员提出将连续的**语义 Embedding**（例如通过 BERT 或双塔模型提取的 256 维向量）转化为**离散的、具有层次结构的 ID 元组 (Tuple)**。

例如：一个 Item 的 Semantic ID 可以表示为 `<12, 45, 8>`。

- **优势**：共享前缀的 ID 在语义上是相似的（例如 `<12, 45, 8>` 和 `<12, 45, 22>` 代表两个非常相似的商品）。模型可以通过学习前缀来泛化到未见过的 Item，完美解决冷启动问题。
    

## 2. 为什么是 RQ-Kmeans，而不是普通聚类？

要将向量转化为层次化的 ID，最直观的想法是**树状的 K-means（Hierarchical K-means）**：先聚成 $K$ 类得到第一层 ID，然后在每个类内部再做 K-means 得到第二层 ID，依此类推。

- **普通树状聚类的致命缺点**：数据分布往往是不平衡的。有的簇可能包含 100 万个 Item，有的簇只有 10 个。这会导致树的分支极度不平衡，且字典库（Codebook）的维护成本呈指数级增长。
    

**RQ-Kmeans (残差量化 K-means)** 巧妙地解决了这个问题。它不再切分“数据样本的空间”，而是**量化前一步拟合产生的“残差（误差）”**。所有层级共享同一个或同等大小的全局 Codebook。

## 3. RQ-Kmeans 层次化聚类的核心步骤

假设我们要为 $N$ 个 Item 生成长度为 $D$（层级数）的 Semantic ID 序列，每层有 $K$ 个聚类中心（即每层的 ID 取值范围是 $1$ 到 $K$）。

给定一个 Item 的原始语义向量为 $x$。

### 第一层 (Level 1)：粗粒度聚类

1. 对所有 Item 的原始向量进行标准的 K-means 聚类，聚成 $K$ 类。
    
2. 得到第一层的聚类中心集合（Codebook 1）：$C_1 = \{c_{1,1}, c_{1,2}, ..., c_{1,K}\}$。
    
3. 找到离 $x$ 最近的聚类中心 $c_{1, i}$。
    
4. **得到第一层 ID**：该 Item 的第一位 Semantic ID 就是 $i$。
    

### 第二层 (Level 2)：量化第一层的“残差”

1. 计算第一层的**残差向量 (Residual)**：
    
    $$r_1 = x - c_{1, i}$$
    
    _(残差代表了第一层粗粒度聚类没有捕捉到的、丢失的那部分细节信息)_
    
2. 将**所有 Item 的残差向量** $r_1$ 聚集在一起，对这些残差向量再次进行 K-means 聚类，聚成 $K$ 类。
    
3. 得到第二层的聚类中心集合（Codebook 2）：$C_2 = \{c_{2,1}, c_{2,2}, ..., c_{2,K}\}$。
    
4. 找到离 $r_1$ 最近的聚类中心 $c_{2, j}$。
    
5. **得到第二层 ID**：该 Item 的第二位 Semantic ID 就是 $j$。
    

### 第 $d$ 层 (Level d)：依此类推

1. 计算上一层的残差：
    
    $$r_{d-1} = r_{d-2} - c_{d-1, p}$$
2. 对 $r_{d-1}$ 进行 K-means，找到最近的中心 $c_{d, q}$。
    
3. **得到第** $d$ **层 ID**：该位 ID 为 $q$。
    

### 最终结果

经过 $D$ 层之后，原始的连续向量 $x$ 就被转化为了一个离散的 ID 序列：$<i, j, ..., q>$。 同时，$x$ 可以被近似重建为各层聚类中心的向量和：

$$x \approx c_{1, i} + c_{2, j} + ... + c_{d, q}$$

## 4. 举个直观的例子

假设我们要描述一件“**男士深蓝色纯棉 V 领短袖 T 恤**”。

- **原始 Embedding**：一个 128 维的稠密向量。
    
- **Level 1 (大类)**：RQ-Kmeans 发现它最靠近“上衣”的聚类中心 (ID: 5)。
    
    - _残差_：减去“上衣”的平均特征后，剩下的特征主要描述“短袖、V领、深蓝色、男士、纯棉”。
        
- **Level 2 (中类)**：对残差聚类，发现最靠近“男士短袖”的中心 (ID: 12)。
    
    - _残差_：减去“男士短袖”特征，剩下的特征描述“V领、深蓝色、纯棉”。
        
- **Level 3 (细分类)**：再次对残差聚类，靠近“深蓝色 V 领”的中心 (ID: 89)。
    
- **最终 Semantic ID**：`<5, 12, 89>`。
    

如果有一件“**男士黑色纯棉 V 领短袖 T 恤**”，它的 ID 可能是 `<5, 12, 92>`。它们共享了前缀 `<5, 12>`，模型一看就知道它们非常相似。

## 5. 典型的应用场景

将 Embedding 转化为 Semantic ID 的技术在当前 AI 领域大放异彩，最著名的应用包括：

1. **生成式推荐与检索 (Generative Retrieval)**
    
    - _代表作_：Google 的 TIGER 模型、SE-KGE 等。
        
    - _用法_：传统的检索是计算向量内积打分（如 Faiss），而生成式检索则是直接让 Seq2Seq 模型（如 T5, Transformer）**逐个 Token 地生成目标 Item 的 Semantic ID**。模型根据用户的 query 或行为历史，直接“预测”出 `<5, 12, 89>`，从而完成推荐。
        
2. **大模型 (LLM) 接入推荐系统**
    
    - 大语言模型很难直接输出几十万个 Item 的独立 ID，但如果 Item 被表示为几百个词表大小的 Semantic ID 组合，LLM 就可以像生成自然语言文本一样，轻松地进行商品推荐。
        
3. **解决新 Item 的冷启动**
    
    - 当一个新的 Item 录入系统时，只需过一遍内容提取模型（如图片/文本的 Encoder）拿到向量，再经过现有的 RQ-Kmeans 字典进行残差量化，就能立即获得它的 Semantic ID（例如 `<5, 12, 44>`）。即使模型从未见过这个新 Item，凭借它与其他老 Item 共享的前缀，依然能被准确推荐。
