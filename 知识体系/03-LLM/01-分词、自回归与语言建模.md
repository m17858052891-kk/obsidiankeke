# 分词、自回归与语言建模

先修：[[知识体系/01-统计与优化/02-似然、交叉熵与KL|似然、交叉熵与KL]]、[[知识体系/02-神经网络与Transformer/02-Attention：数学、信息流与复杂度|Attention原理]]。语言模型首先是一个条件概率模型：给定已观察到的序列，为后续序列分配概率。聊天、补全、工具调用都是在此基础上约束输入输出含义。

## 1. 从联合概率到逐 token 预测

概率链式法则给出：

$$
p_\theta(x_{1:T})=\prod_{t=1}^{T}p_\theta(x_t\mid x_{<t}),\qquad
\mathcal L=-\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t}).
$$

链式分解本身不假设 Markov 性；有限上下文、网络结构和参数共享才限制模型可使用的信息。例子：模型给“猫”“睡”“了”三个条件概率分别为 $0.2,0.5,0.8$，该序列概率为 $0.08$，负对数似然是三项负对数之和。

同一批训练序列的所有真实前缀已知，因此 causal Transformer 可以一次前向计算所有位置的预测。生成时第 $t+1$ 个输入依赖第 $t$ 个采样结果，通常必须逐步进行。这里的“并行训练”来自数据已知，不是自回归依赖消失。

## 2. Tokenizer 改变模型面对的统计单位

字符、字节、词和子词是不同的离散化方案。词表越大，常见文本可能越短，但 embedding/输出层参数越多，稀有 token 的统计估计也可能更困难。字节覆盖全面，但序列长度和跨字节组合负担会增加。

BPE 从较小单元出发反复合并高频相邻对，合并表决定后续切分。它按频率组织压缩单元，不保证每个 token 都是语义完整的词。SentencePiece 是可从原始文本训练分词器的工具体系，可使用 BPE、Unigram 等算法；它不是与 BPE 互斥的单一算法。[BPE 原论文](https://arxiv.org/abs/1508.07909)、[SentencePiece 原论文](https://arxiv.org/abs/1808.06226)

比如“计算机”可能是一个 token，也可能拆成多个 token；拼写、空格、数字格式和语言都会改变长度。模型对某些算术或拼写任务困难，可能部分来自切分方式，但不能把全部推理错误归咎于 tokenizer。

词表、规范化规则、特殊 token 与模型权重必须配套。相同 token ID 在另一词表下可能表示完全不同的内容。随意替换 tokenizer 不像替换显示字体，而是改变模型输入输出的坐标系。

## 3. 困惑度能比较什么

对 $N$ 个被计分 token，平均负对数似然 $\bar\ell$ 对应：

$$\operatorname{PPL}=\exp(\bar\ell).$$

若模型对每个位置都均匀分配 $V$ 个 token，则 PPL 为 $V$。低 PPL 表示在当前数据、分词和计分范围下，对真实 token 的平均概率更高。

不同 tokenizer 改变了分母 $N$ 与事件定义，因此不能直接拿不同模型的 token PPL 排名。跨分词比较可考虑按原始字节或字符归一化的负对数似然，并明确文本规范化与边界处理。即便语言建模损失更低，复杂任务能力也不一定等比例提高：高频格式预测与少量关键推理步骤对平均损失的贡献不同。

## 4. Teacher forcing 与生成分布

训练时条件是数据中的真实前缀；推理时条件可能包含模型自己的错误。一次错误会改变后续输入分布，这通常被称为 exposure bias。它描述的是分布差异，不表示最大似然目标数学上错误，也不意味着所有生成错误都来自它。

假设训练对话总在事实正确的前提下继续，部署时模型先产生了错误日期。后续即使每一步都流畅，也可能围绕错误日期自洽展开。针对这种情况，增加纠错数据、检索证据、验证器或重新规划，是不同层面的措施；它们与简单提高采样温度不是同一回事。

## 5. Mask、打包和 loss 的语义

输入可见性 mask 决定某个位置能读取哪些内容；loss mask 决定哪些位置计入优化目标。SFT 中常让模型读取用户问题，却只对 assistant 回答计算损失，两种 mask 不应混淆。

将多个样本 packing 到同一长度能减少 padding 浪费，但需要明确样本间是否可互相读取、位置编号如何重置、结束 token 如何插入。如果数据本来是独立文档，允许后文依赖前一个随机文档会改变训练分布；是否采用跨文档可见性是训练设计选择，不能由拼接代码偶然决定。

设两个回答分别长 10 和 1000 token。按全体 token 求平均时，长回答贡献约为短回答的 100 倍；先按样本平均再对样本求平均则不同。这不仅是实现细节，还决定模型强调哪些任务和输出长度。

## 6. 语言模型为什么会出现“看似懂了”的行为

为了预测文本，模型可能需要压缩语法、实体关系、程序结构和问题求解规律。这样的表示能迁移到许多任务。但训练目标直接奖励的是观测文本的预测，而非每一句事实经过验证，或每段推理都忠实反映内部计算。

因此要分开判断：是否能生成正确答案、是否能跨表述稳定回答、是否能应用到新组合、是否有可靠证据、是否能识别自己的不确定性。只看一段流畅解释不足以证明这些能力都成立。知识检索和工具执行的作用见 [[知识体系/06-Agent/02-RAG、记忆与上下文管理|RAG与上下文管理]]、[[知识体系/06-Agent/01-Agent：状态、工具与控制循环|Agent状态与工具循环]]。

## 7. 自检与解析

**问：自回归模型训练时同时预测多个位置，会偷看未来答案吗？** 只有 causal mask 和标签移位正确时不会。位置 $t$ 的目标是下一 token，读取范围必须与该定义一致；并行计算不等于信息可见。

**问：模型 A 的 PPL=5，B 的 PPL=7，能说 A 更好吗？** 要先检查测试文本、tokenizer、上下文、loss mask、是否有数据污染。条件不一致时数值不可直接比较；条件一致时也只是该语言建模指标更好。

**问：一个错误概率很小的 token 为什么仍可能让整题失败？** 任务效用不是 token 损失的线性函数。关键否定词、变量名或工具参数的单点错误可能改变整个结果。
