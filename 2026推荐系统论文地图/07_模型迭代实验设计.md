# 一次推荐模型迭代的实验记录

把下表复制到实验笔记。先写出什么观察会削弱假设，再决定扩量指标。[八个已展开的案例](13_实验选型与八类对照.md) · [各篇最小对照](02_逐篇收益链路与证伪矩阵.md)

| 要填的内容 | 写到能执行的程度 |
|---|---|
| 现象和人群 | 哪种请求、哪一层出现损失？以哪个线上版本为基线？ |
| 改动和机制 | 哪个模块改动，会让哪个可观测量先变化？该变化怎样传到主指标？ |
| 最小实验 | 每个实验组只改哪些条件？固定哪些混杂因素？哪些中间变量要允许自然变化？ |
| 输入与成本 | 列训练时、缓存刷新时、请求时分别可用的数据。记录样本、算力、候选配额、索引和端到端 P99。 |
| 主指标与护栏 | 指定指标单位、分母、随机化单位、观测窗、最小有意义提升和回退阈值。分别记录峰值负载和关键人群代价。 |
| 如何判断 | 若中间量变化而主指标持平，检查下游是否消费增量。若主指标变化而中间量持平，检查其他改动和预算。 |
| 扩量或停止 | 约定样本量、统计区间和业务门槛。对长期价值等待标签成熟，将灰度回退与监控成本纳入决定。 |

## 一个具体例子

检验“新查询能找回旧渠道漏掉的商品”时，固定可召回目录、候选数量、总预算和下游排序器，让各组返回的商品身份随查询变化。按请求记录独有候选数、精排保留、实际曝光和成交。另用相同候选重打分，可以诊断排序贡献。若独有候选增加却在精排前全部淘汰，下一步要查这批候选的质量和截断位置。

## 实验无效时先查什么

1. **实现**　核对特征是否真的进入服务，梯度是否到达目标参数，缓存、索引与模型版本是否一致。选少量样本做训练与服务对照。
2. **数据**　按事件时间核查可见特征、重复样本、曝光偏置、标签成熟度与人群采样。检查只在历史日志中才可获得的信号。
3. **机制**　比较预注册的中间量、业务主指标和负对照。打乱机制对应关系后结果仍相同，就应检查容量、刷新或配额等替代解释。
4. **场景**　检查下游截断、库存和不同人群的收益方向。随机分配的全体用户用于主效应判断，执行成功的子样本用于定位原因。

对短期点击、长期复购和成本分别给出观察窗口。只有部分代理指标变好时，按原先约定的主指标和护栏作决策。
