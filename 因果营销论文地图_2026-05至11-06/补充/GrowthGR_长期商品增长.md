# GrowthGR：把新品增长分数接入生成式召回，点击因果识别仍需补证

论文：[Towards Sustainable Growth: A Multi-Value-Aware Retrieval Framework for E-Commerce Search](https://arxiv.org/abs/2605.17994) · [全文v1](https://arxiv.org/html/2605.17994v1) · [PDF](https://arxiv.org/pdf/2605.17994v1)。作者Yifan Wang、Yixuan Wang、Yidan Liang、Qiang Liu、Fei Xiao，首页均署名淘天。

**独立审计2026-11-07。采用结论：需先补关键条件。证据状态：全文及附录已核**（v1，12页；正文§1—5、附录A—C，Fig1—6、Table1—6）。首次公开2026-05-18；未见修订；会议/正式出版未核，首页2018/Woodstock是模板占位。线上称观察超过两个月，具体日期未披露。

**范围：邻近的新品长期增长/召回系统。** 它把“点击的长期uplift”作召回奖励，并报告系统级A/B，但没有证明该点击uplift估计器已识别因果效应。不能当成成熟发券CATE或预算分配器直接替换方案。

## 1. 旧流程、处理和结果到底是什么

旧召回偏好历史交互充分的热门商品，按即时成交SFT训练的生成召回也可能忽略新品。本文在召回链增加ItemLTV预测“本次点击对新品成熟后成交的增量”，再用多价值奖励训练生成召回器；上线作为专门新品通道，经过轻排并与其他通道混排。

【原文事实】§3.1定义处理$W_i=1$为发生一次用户点击，参照为没有该特定点击，协变量含商品属性与用户/query上下文。结果$Y_i$是初始30天新品期之后7天的平均日订单，estimand在log空间：

$$
\tau(X_i)=E[\log(Y_i(1)+1)-\log(Y_i(0)+1)\mid X_i].
$$

统计行来自用户—商品交互日志，但结果附着在商品生命周期；同一商品多次点击如何分割、同一成熟标签如何复用、同商品是否跨训练/测试、某次点击时其他历史点击如何固定，公开稿未充分说明。模型的log订单差不能直接当原始GMV增量；线上TI@30用第31—37天日GMV，与ItemLTV训练的订单目标也不同。

【分析推断】点击是用户选择的处理后行为，不是系统可以随机命令发生的曝光。商品潜质、用户兴趣、已有流量和其他点击既影响$W$也影响后续销量。仅用带$W$的事实MSE训练双塔没有给出无混杂、支持、无干扰的识别证明；后续排名反馈还是机制的一部分。需要明确“让谁看到什么从而诱发一次点击”的可执行干预，不能由发券RCT思路直接等同。

## 2. 模块与训练/部署接口

【原文事实】§3/Fig2提供以下流程：

`商品/用户/query历史 → ItemLTV双塔 → 高增长标签；商品多模态表征 → RQ-VAE三级语义ID；用户/query+历史SID → 0.5B decoder → NTP预训练 → MoPO多价值对齐 → 合法SID beam → 轻排/混排 → 展示`。

- **ItemLTV**：商品塔给基础增长$G_{base}$，用户/query+商品attention塔给$G_{uplift}$；事实预测$\hat y=G_{base}+W G_{uplift}$，用$\log(Y+1)$的MSE训练。训练需要成熟结果、真实点击及处理前特征；推断需当前可得特征，不应输入未来点击。基础塔仅有商品特征，是对无点击结果的额外结构限制，不是由因果定义自动推出。
- **语义ID与生成召回**：商品多模态基础模型编码后RQ-VAE形成三级ID；decoder用自然语言用户/query和历史SID生成商品。NTP从成交日志学token序列；trie mask防止无效ID，SID冲突再用dense模型区分。这里改善冷启动泛化和可执行召回，不提供因果识别。
- **MoPO多价值奖励**：将购买、点击、曝光、候选层级标签与“已点击且预测uplift超过全局均值”的长期标签加权。按label distribution定权，但具体业务权重/更新细节未完整公开。group-relative advantage、PPO式概率比clip和KL约束更新decoder。
- **CIW奖励重权**：式7为$\operatorname{Clip}(-\log\pi_{old}(o_i\mid x),1,M)$乘多价值奖励。它提高低生成概率SID权重。**这不是标准$1/e(W\mid X)$因果IPS**，也不是新旧策略概率比；式8—9的token概率比是另一处策略训练组件。名字里的“importance”不能证明已校正点击混杂。
- **部署工程**：附录A日更ItemLTV/MultiGR，商品塔每日从大池筛约200万候选。早触发异步生成写Redis，平均缓存命中99%，在线约1000候选轻排至20后与其他通道混排；0.5B实用模型与离线3B/7B扩容应分开。线上动态beam缩窄前层，可能改变候选分布；未给端到端P99/成本、miss回退及全部超参。

附录A.1.2又以“最近一天成交标签配前一个月历史”描述日更，未完全展开与主文“新品期后7天均值”标签的对应；复现前需标签SQL/时间轴澄清，不能自行补成同一个过程。

## 3. 每个主要模块怎样可能变成经营收益

【待验证假说】下表的机制归因及诊断方案需在本业务独立验证；其中替代解释、失败条件和可推翻结果不是作者已完成的额外实验。原文支持到哪一步分别标在证据列。

| 模块→误差/表示→排序/动作→执行→结果 | 场景和原文事实 | 替代解释、成立条件与可证伪诊断 |
|---|---|---|
| 【分析推断】ItemLTV新增用户情境增量塔→分开商品基础与交互响应→给可能受益新品高奖励→同新品曝光槽位重排→可能增加成熟期交易 | 新连衣裙一次合适用户点击可能带来后续分发；【原文事实】Table2 MSE1.348→1.329、Table4去ItemLTV长期Recall下降 | 额外用户特征足以解释事实预测改善；无点击反事实真值。需同容量两头/纯预测MLP、按商品留出、随机曝光验证；若高分仅选天然赢家或随机曝光收益不校准，因果机制失败 |
| 【分析推断】多模态SID+生成decoder→共享新品语义缓解ID稀疏→召回更多适配商品→trie/冲突轻排输出合法候选→可能增加新品有效曝光/成交 | 新商品无历史但与已有款式语义接近；【原文事实】§3.2.1—2、Table3 TIGER对照 | 改善可能是foundation信息或容量，不是uplift；同SID/同0.5B比较SFT与MoPO，查新品覆盖、相关性、碰撞误排与请求时延；曝光多但净转化不增则经营链未闭合 |
| 【分析推断】MoPO漏斗+长期奖励→梯度从仅即时成交转向多价值候选集→高增长新品进入top-k→同混排规则展示→可能兼顾当期与未来GMV | 单看成交让尚无交易新品永远进不了候选；【原文事实】Table4 w/o MoPO实际为即时转化GRPO，差异含奖励而非只算法 | 组合目标/权重改变也解释增益；long-term标签来自同一ItemLTV，易自我验证。需同奖励GRPO/同标签排序loss，查真正成熟订单而非仅teacher Recall；真实长期指标无增益即失败 |
| 【分析推断】CIW提高罕见SID奖励→头部概率优势减弱→更多高潜长尾入围→合法beam和轻排执行→可能改善增长覆盖 | 稀疏小众新品被热门SID挤压；【原文事实】Table4去CIW all-net R@1000−0.0038、long-term−0.0060 | 一般逆热度/熵奖励也可能奏效；低概率也可能是垃圾商品。查按热度与quality分层、权重clip敏感性；若只是低相关曝光增加或普通热度校正持平则不需复杂CIW |
| 【分析推断】异步预取/缓存/动态beam→降低在线等待与无效候选→保证召回真正到达展示→增加有效执行覆盖→可能保留离线收益 | query解析同时触发生成；【原文事实】A.2命中99%，B动态beam | 缓存命中非增量收益；也可能用更旧/更窄候选牺牲quality。查P99、miss、陈旧率、实际重排曝光；若执行率/质量下降，不可将离线Recall等同业务提升 |

每条最后一步仍受真实流量预算、其他通道挤占与用户体验约束。ItemLTV的预测分数随新品天数下降（Fig6）只是模型输出一致性，不是“每次点击真实效应随天数下降”的独立证据。

## 4. 结果审计：原表而非宣传口径

### 4.1 离线强基线和消融

【原文事实】Table1有2.4B uplift交互与5.0B全漏斗交互；DR为当前生产dense召回（40B sparse+10M dense），生成模型统一0.5B。参数量、稀疏/稠密计算和训练数据不能简单等同；全文未给统一FLOPs与调参预算。

| 原表 | 数字与重算 | 证据能到哪里 |
|---|---|---|
| Table2 ItemLTV | MSE1.348→1.329，下降约1.41%；NDCG0.842→0.853，增加0.011（约1.31%相对） | 事实结果拟合，非PEHE或随机uplift校准；原文“confirm impact”过强 |
| Table3 单阶段GrowthGR对DR | search Recall@10 0.3419 < 0.4115；all-net R@1000 0.7147 > 0.6194；long-term NDCG0.3820 < 0.4119 | 不是全部指标胜；long-term标签来自ItemLTV，是teacher一致性 |
| Table3 两阶段 | GrowthGR top2000后DR重排，all-net R@1000=0.7578；long-term NDCG=0.4801 | 增加重排器/候选预算，不能把整段差归生成器；search R@1000=0.8820与DR相等，并非严格全胜 |
| Table4 去ItemLTV | all-net R@1000 **+0.0004**；长期R@10 −0.0532、R@1000 −0.0165 | [PDF p7](https://arxiv.org/pdf/2605.17994v1#page=7)表为正号，正文却说“下降0.04pt”，保留冲突，不能复述全指标下降 |
| Table4 去MoPO | all-net R@1000 −0.0368；长期R@1000 −0.0325 | 是百分点差3.68/3.25，不是相对百分比；无CI/seed误差 |
| 附录C.2 Table5 | beam all-net R@10 0.2722 > top-p0.2568，但R@1000 0.7138 < 0.7147 | 训练rollout存在取舍；不能说beam全优 |

【分析推断】去ItemLTV后模型对ItemLTV定义的长期标签Recall降低，是预期的训练目标变化，不能独立证明长期因果效果。需要不依赖teacher的成熟真实结果与随机干预作为最终裁判。0.5B/3B/7B三点变好仅支持该区间的容量趋势，不足以给出普遍scaling law。

### 4.2 线上系统效果

【原文事实】§4.5用户ID哈希分桶报告新品GMV **+5.39%**、PVR **+1.54%**、整体搜索GMV **+0.31%**。PVR是新品曝光占比，原文以lift百分号报告，不能自行改成+1.54个百分点。未给其原始分母、CI、具体p值和曝光/费用绝对量。对照生产检索可推测，但完整线上配置、比例与同预算条件未充分披露，不能填作已核同流量成本。

商品侧用item ID哈希，并把item桶与用户桶耦合以减少交叉策略污染，报告TI@30 **+20.0%**，目标是新品期后7天日GMV。随机化单位与用户AB不同，两个提升不能相乘。是否后续仍持续额外流量、存活商品选择/退款、共享排序模型污染和其他商品挤占未充分说明；耦合桶降低某类污染，不证明不存在干扰。

【分析推断】整体搜索GMV+0.31%是搜索口径净结果的正向证据，但不能推出“没有任何蚕食”，更不能推出全平台净利润增加；可能同时有商品间/场景间挤占与新增。附录C.3 Table6甚至报告Food & Fresh −0.67%、Automobiles −0.81%、Pets −2.62%、Toys −5.48%的新品GMV变化，不能描述为所有行业受益。没有模块级线上随机消融，不能把+5.39%拆为ItemLTV/CIW/MoPO的收益贡献。

## 5. 与已有方法的关系

| 现有方法或论文（身份） | 共同问题 | 本文具体改动 | 可替换/组合 | 不能替换 | 接口与假设对齐 | 公平比较实验 |
|---|---|---|---|---|---|---|
| DR（实比，Table3） | 生产召回 | 新品语义生成与多价值目标 | 可增加新品通道/组合DR重排 | 不等于替换全站召回或预算器 | 同候选量、轻排、混排曝光预算与延迟 | 单阶段同预算；两阶段给DR等价候选与重排算力 |
| TIGER（实比，Table3） | SID生成召回 | 增加ItemLTV/MoPO/CIW | 复用语义ID/decoder，替换训练目标 | 不是因果控制组 | 同0.5B、SID、上游信息和数据 | 同容量SFT、同奖励GRPO、完整MoPO |
| Item-only Base（实比，Table2） | 新品后续结果预测 | 加用户/query与点击塔 | 双塔可局部替换 | 事实MSE不识别点击效应 | 无点击结果也可依赖上下文，不能默认item-only足够 | 同输入预测MLP+双头；商品簇拆分/RCT校准 |
| Vanilla GRPO（实比消融，§4.3.3） | group-relative学习 | 多价值/长期奖励+CIW | 可拆奖励与优化器 | 不能以奖励换型证明算法本身优 | 相同rollout/clip/KL、目标标签、搜索预算 | 目标×CIW×优化器分步控制 |
| CanniUplift（分析补充） | 局部与平台整体增量 | 本文是点击/召回，Canni是发券/平台监督 | 平台总量评价可借鉴 | 不能把点击双塔当券效应模型 | 单位/可干预动作/其他优惠背景不同 | 固定流量预算检测全平台总量及挤占 |
| DCEO（分析补充） | 用户/商品长期目标进入搜索 | 本文召回+新品商品结果；DCEO用户日代理排序 | 可在不同阶段组合 | 目标窗/因果量不等价 | 商品31—37天与用户4天分开；防奖励重复计价 | 召回×排序2×2，独立成熟真值与总量护栏 |

## 6. 可执行最小验证

| 项目 | 可执行约定 |
|---|---|
| 适用症状 | 新品语义相关却长期进不了召回，单纯增加曝光没有成熟期净增长。 |
| 数据前提 | 商品生命周期、完整曝光/点击/其他流量、处理前用户query、成熟订单与GMV、退款；商品簇时间外留出和小流量随机曝光。 |
| 最小改动 | 先固定召回器和曝光槽位，用简单成熟价值/候选ItemLTV做排序对照；之后单独加入MoPO/CIW。 |
| 固定项 | 同新品池、候选数、容量、重排/混排、曝光/延迟预算、成熟窗、上游信息、调参算力。 |
| 对照组 | DR、同SID SFT、同奖励GRPO、纯成熟结果预测、ItemLTV；CIW与普通热度权重独立对比。 |
| 中间诊断 | 处理/支持与商品重复标签、随机曝光响应校准、teacher标签依赖度、头尾覆盖/相关性、P99和实际执行率。 |
| 最终指标 | 固定曝光预算下全搜索/全平台净GMV与贡献、成熟31—37天交易、商品存活/覆盖、用户体验与其他商品损失。 |
| 失败判据 | 只有teacher Recall提高、真实成熟净值不增；效果由额外曝光/重排算力解释；点击因果分数不能通过随机校准则降为预测分数使用。 |
| 后续投入条件 | 预测/因果角色分清、强对照与公平预算下系统增益稳定，再扩生成训练；因果识别不足时不使用CATE收益宣传。 |
