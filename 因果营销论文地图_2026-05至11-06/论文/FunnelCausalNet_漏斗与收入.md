# FunnelCausalNet：从“转化×客单”到多档券净收入分配

论文：[Funnel-aware Joint Conversion-Revenue Uplift for Multi-tier Coupon Allocation](https://arxiv.org/abs/2608.11675) · [全文v1](https://arxiv.org/html/2608.11675v1) · [PDF](https://arxiv.org/pdf/2608.11675v1)。Yu Zhang、Zhihan Wang、Guanlin Chen、Min Jiang、Shuai Li，五人均署名AMap Alibaba Group（高德）。

**独立审计2026-11-07。采用结论：可开展最小验证。** 可以先在多档券RCT上验证硬漏斗与独立均值校准，保留现有分配器；完整conformal模块和论文工业结果尚不能独立复现。**证据状态：全文及附录已核**（v1，11页，§3—6、附录A、Table1—11；PDF p4/p6/p8逐式逐表核对）。首次公开2026-08-12，未见修订；arXiv作者注明CIKM 2026录用，具体会议日期与正式出版日期未核。工业日志日期、结果归因窗和内部在线试验日期未披露。

**范围：多档离散券的转化/GMV因果估计与预算分配。** 不插值连续券强度，不识别跨商品蚕食或长期效应；与ReAlloc的固定渠道预算调配不是同一稿。

## 1. 旧流程、因果对象与漏斗识别

旧流程直接回归包含大量零值的GMV，或分别预测转化与客单后粗略相乘；再按单一uplift排序分配券。问题在于不同券档可能提高转化、同时改变购买者构成与客单，转化排名不等于GMV排名，GMV排名也不等于预算下净价值排名。【原文事实】§1/3说明这些目标差异；Table3显示高AUUC不保证ATE校准，Table7显示最高GMV不保证最高ROI。这不意味着直接GMV模型在所有场景都较差。

一条记录为用户曝光/优惠分配记录，$T\in\{0,1,\ldots,K\}$是随机分配的离散券档，0为对照；$Y^c$是转化，$Y^g$是非负GMV，未转化时GMV必须为0。目标为同一处理前人群的$\tau^c_t(x)=E[Y^c(t)-Y^c(0)\mid X=x]$与$\tau^g_t(x)$。论文只主张RCT条件下识别，不能直接迁移到纯观测日志；还需一致性、各档overlap及恰当处理用户重复曝光/干扰。券是否仅分配还是必须展示、归因窗口、退款和跨订单口径需补齐。

关键是**每个档位内先乘，档位间再相减**：

$$
p_t(x)=P(Y^c(t)=1\mid X=x),\qquad v_t(x)=E[Y^g(t)\mid X=x,Y^c(t)=1],
$$

$$
\mu^g_t(x)=p_t(x)v_t(x),\qquad \tau^g_t(x)=p_t(x)v_t(x)-p_0(x)v_0(x).
$$

【分析推断】这不是$\tau^c_t\times(v_t-v_0)$。在RCT且转化概率为正时，$v_t$可由该券档的实际转化者估计，乘积恢复该档总体GMV均值；但$t$和0的转化者是不同的处理后子群，$v_t-v_0$不能解释成“同一批会购买用户的因果客单提升”。主分层客单效应需要额外条件。例：大券新增大量低客单买家，$v_t$下降但$p_tv_t$仍可能上升，既不说明原买家客单被压低，也不允许丢弃新增买家。

## 2. 输入、训练、分配与部署

`处理前用户X+随机券T+成熟转化/GMV → 共享表征与每档转化/条件客单头 → 各档GMV水平 → 独立RCT档均值锚定 → 对照差值+预计补贴成本 → LP或拉格朗日分配 → 每用户一档或不发券`。conformal与冲突screen走监控支路，不能默认进入最终求解器。

- **硬漏斗（§4.1）**：全样本BCE学$p_t$；仅转化者的归一化$\log(1+GMV)$回归学客单，经LogNormal式均值修正回货币单位，再取非负乘积。总loss可另含一致性与单调项，但原文未完整公开各实验权重/结构；可选项不等于所有结果启用。重变换须检验离散度/残差分布，直接指数化log预测一般不等于GMV均值。soft版本适用于标签缺失、异步等使漏斗关系不精确的场景；不能用硬关系掩盖日志错误。
- **RCT锚定（§4.4）**：用held-in切片的档位实际均值估计加性修正，再构造分配奖励，避免对照GMV被低估而虚增uplift。它校准档平均水平，不保证每个用户CATE校准。原文未详述锚定折与训练/区间校准折的全部关系，实施时需留独立数据并禁止用最终评估结果选择修正。
- **分配（§3/4.4）**：预算内最大化总增量GMV；拉格朗日思想是每用户选$\arg\max_t[\hat\tau^g_t(x)-\lambda\hat c(x,t)]$，含0档，通过调节$\lambda$满足预算；整数化后仍要核实际预算。工业主结果用LP-relaxation KKT建议，不能把它归为拉格朗日线上收益。MT7成本为$d_t\hat\mu^g_t$，需要本地券核销、封顶、折前/折后金额及平台承担比例一致；预测成本不是实际支出保证。
- **双结果conformal与冲突screen（§4.3）**：分离校准集、两边Bonferroni，再标记转化/GMV排名不同、近阈值或区间宽的用户。它提供风险审查线索，不解决多目标偏好，不是精确冲突分类器。点估计进入分配器，LCB方案在本文实验中全部退回control。

训练需要成熟结果和已知RCT分配概率；部署只需处理前X、券档、成本及预算，不需要实际核销或未来转化。全文无公共代码，工业微观数据不开放，网络宽度、优化完整参数和校准残差构造仍不足；“统一框架”不等于外部复现成功。

【原文事实】§4.2/附录A的方差比依赖：正确设定转化模型以$\sqrt n$收敛，金额头和直接回归非参数有效样本率$r_n=o(n)$，偏差可忽略，跨头协方差受控。比值$[1+(1-p)\mu_v^2/\sigma_v^2]^{-1}$是单档点态GMV均值MSE的理想渐近比较，不保证共享神经头、CATE差值或预算策略收益。两头同速估计时收益可消失；极少转化者使金额头噪声变大。【待验证假说】按转化率、客单变异系数和档样本量分层，比同信息hurdle/direct强对照，检验何时硬耦合真正有利。

## 4. 原表、最强对照与证据边界

**估计与消融。** [PDF p6 Table3—5](https://arxiv.org/pdf/2608.11675v1#page=6)并不支持全面领先。MT7是Criteo特征上的半合成、8个券档+control，10K训练/评估；Table3三seed均值：EFIN的AUUC_GMV=.615、PEHE_GMV=26.70，本文=.613/31.18；转化PEHE最佳DualHeadNet=.048，本文=.058；ATE误差最佳Causal Forest=4.62，本文=21.67。AUUC“一个seed标准差内”不是等效性检验。Hillstrom合并两种邮件为二值鼓励，RERUM=.747、DualHeadNet=.739领先，本文未给可核精确AUUC，明确承认不占优。

Table4固定框架比较direct/soft/hard/ZILN，10K的PEHE由25.94到20.26（下降21.90%），20K由25.48到15.29（39.99%），100K由25.80到15.97（38.10%）。Table3的31.18与Table4同10K hard=20.26不是同一结果，seed数和实验配置不同，不能拼接当相同设置。Table5五seed均值±SD：转化率4.6/11.9/24.3/45.4%时收益18.1/38.0/48.3/44.6%，不是“零膨胀越高收益严格越大”；§5.1声称monotone与该表不一致。SD不是置信区间，PEHE下降也不是业务增长。

**预算。** Table7在预算比例.05时，anchored ROI=3.92，对random=3.07是+27.7%，但更强top-k=3.66仅+7.1%；anchored实际成本2315低于top-k的2409/LP的2910。预算比例.50时anchored ROI=3.00反低于top-k3.05/LP3.03，增量GMV也更低。不能把一个tight-budget点称所有预算胜出；锚定与求解变化同时发生，不能拆出纯模块贡献。MT7按oracle结果算实际收益/成本是半合成评估特权，生产不可拿oracle值做训练/选择。

**工业RCT上的离线策略评估。** [PDF p8 Table11](https://arxiv.org/pdf/2608.11675v1#page=8)：约498万曝光、279万独立用户；每seed按记录随机打散取5万训练、约493万评估，重复用户可跨训练/评估，论文§6承认需user-group split和cluster不确定性。3次打散复用同一个RCT，不是3个独立实验；E7训练30epochs，不是前面一般设置25epochs。预测建议与实际随机券相同的子集按Hájek IPW评估，得到相对control的增量GMV/补贴成本前沿；应检查每档已知概率、匹配ESS、用户聚类及同一留出集挑前沿点的乐观性。

| 固定增量GMV目标 | 最强其他均值 | 本文ΔROI | 重算差距与解释 |
|---|---:|---:|---|
| 10% | EFIN 4.84 | 4.94 | +0.10 ROI单位，+2.07%；配对95%CI[-.42,.35]含0 |
| 30% | RERUM 4.08 | 4.30 | +0.22 ROI单位，+5.39%；不是收益+22% |
| 60% | RERUM/EFIN 3.50 | 3.60 | +0.10 ROI单位，+2.86%；配对95%CI[-.07,.38]含0 |

7/7个相关前沿点均值最好只说明方向一致；不能把$2^{-7}$当显著性。§5.8称25—60%点均高“.18—.21”与30%+.22、60%+.10不一致，按表保留。不同方法能到达的最大GMV目标不同，不能只挑可达点宣布全面胜出。ΔROI分母是构造的补贴成本，不是净利润；佣金率.2—.3是敏感性假设，不是核实的平台实际佣金。内部线上只称方向一致，没有数值、分桶或消融公开，因此**没有可核线上收益量**。

**区间证据。** Table8是实际outcome层coverage，Table9才是MT7 oracle效应覆盖，不能用前者当工业CATE置信区间已验证。§4.3没有完整给出效应校准标签/残差构造；真实个体反事实差不可观测，需说明如何从结果层构造目标及其保证。Bonferroni只组合已有有效边际覆盖，不自动创造CATE覆盖，更不提供给定每个X的条件覆盖或整个人群同时覆盖。Table9的转化效应宽度始终2.000，覆盖率100%可只是覆盖整个[-1,1]；GMV宽8748—11741也使LCB全部control。Table8差值列+.037等是概率差，即+3.7个百分点，原脚注“in pp”不能照抄成+.037个百分点。

**可重复性与公平性。** 作者统一PyTorch框架、训练计划和评估接口；CFRNet/DragonNet被扩成多头，DESCN/ECUP/RERUM为重实现版本，不等于原作者最优配置。未给完整公共代码/配置/硬件及总调参算力；Lagrange百万用户约.127秒是特定配置，不是端到端延迟承诺。完整模型×锚定×求解×监控的因子消融未完成。

## 6. 可执行最小验证

| 项目 | 可执行约定 |
|---|---|
| 适用症状 | 多档券RCT中转化排序与净GMV排序冲突，直接GMV模型重尾/零值误差大，且每档有足够转化者。 |
| 数据前提 | 用户级分组RCT、各档概率、处理前X、同窗转化/成熟GMV、退款与实际平台补贴；用户隔离训练/校准/最终评估。 |
| 最小改动 | 固定现有网络/solver，先直接GMV对比每档硬漏斗；第二步单独加独立档均值锚定。 |
| 固定项 | 同人群/券档/成熟窗/预算、相同log损失与重变换选择、参数/调参算力、同分配与舍入规则。 |
| 对照组 | 当前收入uplift、EFIN或RERUM同信息重实现、direct/soft/hard、各自有无锚定；不先加conformal动作。 |
| 中间诊断 | 每档p与转化者样本量、GMV水平/重变换/分群校准、漏斗数据违例、cost校准、政策匹配ESS和实际支出。 |
| 最终指标 | 用户聚类的IPW/DR配对策略差值CI；新用户RCT实际增量GMV/佣金净补贴、成本、转化、退款、平台挤占。 |
| 失败判据 | 极少转化者、硬支持关系不成立、收益仅来自成本变化/测试集锚定、同solver强基线持平，或长尾人群净损失超阈值。 |
| 后续投入条件 | 多窗口同实际成本下稳定超强对照，再补代码/效应区间构造；监控是否影响动作需另做固定回退率试验。 |
