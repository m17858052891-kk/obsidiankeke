我们这个项目最终关注的核心指标是 Call AUCC。AUCC 本质上是一个因果排序指标：对于每一个补贴档位，我们希望把真正能够被补贴激励、呼叫增量更高的用户排在前面，而不是简单地把本身就容易呼叫的用户排在前面。

但是，我在分析原有线上模型时发现，原模型的训练目标和最终评估目标之间存在一定偏差。

原模型采用 CFR 架构，主要通过 factual loss，也就是事实响应损失，预测用户在不同补贴档位下的呼叫概率。对于用户 \(x\)，模型会分别输出十个档位下的呼叫概率。以 100 档作为对照组，第 \(m\) 个档位的 uplift score，就是该档位的预测呼叫概率减去 100 档的预测呼叫概率。

这种建模方式能够保证模型具备较好的呼叫概率预测能力，但 factual loss 优化的是“用户是否呼叫”，并没有显式要求 uplift score 的排序与真实增量排序一致。

因此，一个用户即使不发券也会呼叫，只要他的基础呼叫概率很高，模型仍然可能把他排在前面。但从 uplift 的角度看，这类用户并不一定值得优先触达。

所以，我的第一个核心改动，就是在原有响应预测目标之外，引入一个直接面向 AUCC 的排序目标。

不过，这里会遇到一个因果推断中的基本问题：对于同一个用户，我们只能观察到他接受某一个 treatment 后的结果，无法同时观察他在 treatment 和 control 下的结果。因此，我们无法直接得到单个用户的真实 uplift。

为了解决这个问题，我先构造了一个用于排序学习的因果伪标签。

对于每一个非 100 档的 treatment，我只取这个 treatment 和 100 档 control 的样本，然后根据用户实际进入的组别、呼叫结果以及 treatment 分配概率，构造 IPW 形式的伪标签。

这里我没有直接使用原始的零一标签，而是将标签从 \(y\) 转换成 \(2y-1\)，也就是把未呼叫编码为负一，把呼叫编码为正一。

这个改动非常重要。

因为如果直接使用零一标签，那么所有未呼叫样本的伪标签都会等于零。这样一来，无论一个用户是在 treatment 组未呼叫，还是在 control 组未呼叫，排序损失都无法区分这两种情况。大量未呼叫订单的信息就会被丢弃。

改成 \(2y-1\) 以后，四类样本会对应四种不同的排序信号。

第一类是 treatment 组呼叫的用户。这类样本提供正向信号，模型倾向于把他们排在前面。

第二类是 treatment 组没有呼叫的用户。这类样本提供负向信号，说明用户接受补贴以后仍然没有响应，模型倾向于把他们排在后面。

第三类是 control 组呼叫的用户。这类用户即使没有补贴也会自然呼叫，因此他们不应该被当作高 uplift 用户，伪标签会给出负向信号。

第四类是 control 组没有呼叫的用户。这类用户在没有补贴时没有响应，理论上仍然存在被 treatment 激活的空间，因此会提供相对正向的排序信号。

当然，这个伪标签并不等于单个用户真实的个体处理效应。它本身仍然存在方差和噪声。但是在随机分流或者经过倾向校正的前提下，它能够在总体意义上为模型提供因果排序方向。

构造伪标签以后，下一步就是让模型预测的 uplift score 与伪标签的排序方向保持一致。

我首先引入的是 PU-Corr Loss，也就是伪 uplift 相关性损失。

它的做法是，在每一个 treatment 与 control 的样本子集中，计算模型预测 uplift score 与因果伪标签之间的相关系数，然后用一减相关系数作为损失。

这个损失关注的不是模型预测值和伪标签的绝对数值是否相等，而是它们在一批样本中的高低变化是否一致。

也就是说，如果某些用户的伪 uplift 更高，模型就应该给这些用户更高的 uplift score；如果伪 uplift 更低，模型给出的分数也应该更低。

我选择相关性损失，而不是 MSE 或者 Huber Loss，主要是因为 AUCC 本身关注的是排序，不要求预测值与伪标签在数值尺度上完全一致。相关性损失对平移和整体尺度变化相对不敏感，因此与最终的排序目标更加一致。

从实验结果看，PU-Corr 对 AUCC 的提升非常明显。随着 Corr Loss 权重从 0.01逐渐提高到0.03和0.05，AUCC也呈现出逐级上升的趋势。这说明原有模型中确实缺少足够强的排序监督。

但是，PU-Corr 也带来了新的问题。

相关性损失是一个全局统计目标。它会同时利用一个 batch 内大量样本的信息，因此提升排序能力很强，但也容易利用数据中的结构性偏差。例如，某些 treatment 下高频冒泡用户出现得更多，或者某些特征能够明显预测 treatment assignment，模型就可能把这些特征当成 uplift 信号。

这时候，AUCC 可能会提高，但是 QINI 图中的 treatment-ratio 曲线会出现明显下凸。也就是说，模型排序头部的 treatment 和 control 样本比例发生了异常偏移。

因此，我又加入了第二个排序目标，也就是 Matched Pairwise Loss。

Pairwise Loss 不再只看整体相关性，而是构造具有明确排序方向的局部样本对。

例如，treatment 组中呼叫的用户，与 control 组中未呼叫的用户构成一类正向样本对。模型应该让前者的 uplift score 高于后者。

反过来，treatment 组中没有呼叫的用户，与 control 组中呼叫的用户构成负向样本对。模型应该让前者的 uplift score低于后者。

为了避免把完全不同的人随意配成一对，我没有使用全局随机配对，而是在模型表征空间中寻找相近的 treatment 和 control 用户，通过 Top-K 软匹配构造样本对。

Pairwise Loss 的作用，是对局部的排序错误进行更精细的修正。

Corr Loss 和 Pairwise Loss 实际上都在优化 uplift 排序，但两者的作用尺度不同。

Corr Loss 是全局、稠密的监督，它能够快速建立整体排序方向，因此对 AUCC 的提升更明显。

Pairwise Loss 是局部、相对稀疏的监督，它关注具体样本之间谁应该排在前面，因此能够补充 Corr Loss 对局部错序约束不足的问题。

实验中，单独使用 Pairwise Loss 时，AUCC 一般达不到 Corr Loss 的高度。这是因为 Pairwise 只使用满足条件的匹配样本，而且每个档位、每个 batch 中能够构造出的有效 pair 数量有限。

所以，在最终方案里，我没有用 Pairwise 替代 Corr，而是让 Corr 作为主要排序目标，让 Pairwise 作为辅助约束。简单来说，就是由 Corr 负责拉开整体排序，再由 Pairwise 修正局部顺序。

在继续实验的过程中，我还发现，不同 treatment 的 uplift score 分布存在明显的均值和尺度差异。特别是深折扣档位，score 的方差和长尾现象会更加明显。如果直接将原始 score 输入 Corr 和 Pairwise Loss，少量极端样本可能产生过大的排序梯度。

因此，我又在 rank loss 内部加入了 score calibration。

具体来说，首先按照 treatment 档位对 uplift score 做 Z-score 标准化，也就是减去该档位的均值，再除以标准差。这样可以降低不同档位之间的尺度差异。

然后，再使用带温度参数的 Tanh 函数压缩长尾。

当前 H2 方案的温度参数设置为2。温度太高时，Tanh 接近线性，长尾压缩不够；温度太低时，大量样本会迅速饱和到正一或负一，反而损失中间区域的排序信息。实验表明，温度等于2在排序区分度与稳定性之间取得了相对更好的平衡。

需要强调的是，这个校准只作用于排序损失内部看到的 score，不会修改模型最终输出的 factual probability。因此，模型仍然能够输出具有业务含义的各档位呼叫概率。

在完成这些 loss 的设计之后，我遇到的另一个关键问题是：如果从训练一开始就同时加入 factual loss、Corr Loss 和 Pairwise Loss，噪声较大的排序梯度会直接进入 Shared Bottom。

这样虽然可能快速提升训练集上的 AUCC，但也可能破坏模型原本稳定的响应预测能力，甚至让 Shared Bottom 学到 treatment assignment、高频冒泡或者自然呼叫率等捷径。

因此，我最终采用了 TwoStage，也就是两阶段训练架构。

第一阶段是 Anchor 阶段。

在这个阶段，模型只使用 CFR 原有的 factual objective，学习用户在十个补贴档位下的呼叫概率。这个阶段不加入 Corr Loss，也不加入 Pairwise Loss。

第一阶段的目标不是追求最高 AUCC，而是先学习一个稳定的多档位响应模型，得到可靠的用户共享表征、各档位响应概率，以及 treatment 相对于 control 的初始 uplift anchor。

第二阶段是 Rank 阶段。

第二阶段从第一阶段的 checkpoint 初始化，在保留 factual loss 的基础上，加入校准后的 PU-Corr Loss 和 Matched Pairwise Loss。

保留 factual loss 的原因是，它可以作为一个锚点，限制模型不要为了提高排序指标而完全偏离原有的响应概率结构。

在当前 H2 Soft T2 方案中，PU-Corr 的权重是0.015，Matched Pairwise 的权重是0.003，score calibration 的温度是2。

也就是说，Corr 是主要的 AUCC 优化项，Pairwise 是辅助的局部排序约束，而 factual loss 负责维持响应预测的基本盘。

不过，第二阶段还存在一个问题：Shared Bottom 应该完全冻结，还是全部解冻？

如果完全冻结 Shared Bottom，排序损失只能调整输出 Head，模型虽然比较稳定，但 AUCC 的提升空间有限。

如果完全解冻 Shared Bottom，Corr 和 Pairwise 的梯度又可能大幅改变第一阶段已经学好的用户表征，导致 treatment-ratio 再次恶化。

因此，我采用了 Progressive Soft-Unfreeze，也就是渐进式软解冻。

具体来说，第二阶段首先冻结 Embedding 和 Shared Bottom，只训练 treatment heads，让 Head 先适应新的排序目标。

随后，继续冻结 Embedding，只小幅解冻 Shared Bottom。Shared Bottom 的学习率设置为 Head 学习率的百分之一。

这样做相当于在第一阶段的 Anchor 周围建立了一个信任域。Head 可以获得较大的自由度去提升 AUCC，而 Shared Bottom 只能进行非常温和的调整，从而避免排序损失把整个响应模型带偏。

最终，当前模型的整体训练目标可以概括为三部分。

第一部分是 CFR 原有的 factual response loss，保证模型首先是一个可用的多档位呼叫概率模型。

第二部分是权重为0.015的校准后 PU-Corr Loss，用于建立全局的 uplift 排序方向。

第三部分是权重为0.003的校准后 Matched Pairwise Loss，用于修正局部样本之间的排序错误。

整个建模过程可以总结为六步。

第一步，从 Call AUCC 出发，识别出原有 factual objective 与最终排序指标之间的目标偏差。

第二步，通过 \(2y-1\) 和 IPW 构造因果伪标签，让呼叫和未呼叫样本都能够提供排序信息。

第三步，使用 PU-Corr Loss 让预测 uplift 与伪 uplift 的整体排序方向保持一致。

第四步，加入 Matched Pairwise Loss，对局部样本顺序进行补充约束。

第五步，使用 Z-score 和 Tanh 对不同 treatment 的 score 做校准，控制尺度差异和长尾极值。

第六步，通过 TwoStage Anchor 和 Progressive Soft-Unfreeze，把稳定响应学习与 AUCC 排序优化分开，在提升排序能力的同时，尽量保护 QINI treatment-ratio 的稳定性。

所以，这个模型最终并不是简单地用一个 rank loss 替换原来的 factual loss。

它的核心思想是：先通过 CFR 学习一个稳定、可信的多档位呼叫响应模型，再以 \(2y-1\) 的因果伪标签作为排序监督，在校准后的 uplift score 上联合优化全局相关性和局部 Pairwise 顺序。最后，通过两阶段训练和渐进式软解冻，限制排序损失对底层因果响应表征的污染。

最终希望实现的效果是，在保持 QINI treatment-ratio 相对稳定的前提下，提高 Call AUCC，把真正具有呼叫增量的用户优先排在前面。
