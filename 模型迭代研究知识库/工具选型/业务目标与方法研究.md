## project-solution-paths

给“加了特征、转化没动”写一张问题卡。让负责人先给出决策对象、业务分母、可改的动作、已知覆盖与约束。Skill 起草竞争假设、需要的观测以及各结果对应的实验，由负责人确认目标。

**接入与成本**　本地指令型 Skill，无额外计算服务。主要投入是整理业务上下文和工程师评阅。

**验收与换路**　给它同样的背景，分别放入一次特征错接、一次真实冗余、一次只有总 AUC 的案例。与工程师的问题卡盲比，看它能否区分前两种情况、在第三种情况下点出缺失字段。若每次都给相同的调参建议，沿用人工模板。

**示例任务**　“使用 project-solution-paths。加入特征 F 后 AUC 持平，线上可用率未知，目标是提高完成转化。请列出区分管线、冗余与优化问题的最小检查，以及每种结果对应的下一步。”

## hypothesis-generation

老任务退化时，把“样本配比改变”和“共享层梯度冲突”写成在同一固定采样条件下预测不同结果的假设。Skill 生成预测矩阵，Python 检查字段和引用，输出错误列表。跨记录检查需传入 `--record` 并查看 `record_cross_check_performed`。

**接入与成本**　带脚本的 Skill 2.4，Python 3.11+。维护预测矩阵需要人工时间，已有问题卡时可以只借用表结构。

**验收与换路**　向矩阵植入重复 ID、无效引用、相同预期和两条相反的中文预期。2.4 版的归一化函数会把纯中文预期都化为空串，中文比较须人工判读或修复后重测。结构检查通过后仍由研究者判断这次实验能否区分机制。

> [!example]- 展开调用示例（待试）
> ```bash
> python3 scripts/validate_prediction_matrix.py matrix.csv
> # 需要验证跨对象ID存在性时，再提供通过schema的记录
> python3 scripts/validate_prediction_matrix.py matrix.csv --record hypothesis_record.json
> ```

## paper-search 与 GitHub

按主题和年份取候选论文，再从论文的作者链接定位仓库、固定代码版本。每个候选应留下强基线、额外标签、训练预算、模块入口和独立消融，作为下一次实验的输入。

**接入与成本**　本机检索 Skill 加 GitHub 连接器。开销在 API 限流、全文获取与读代码。GitHub 的最小实测仅覆盖公开读取。

**验收与换路**　用已知相关论文、同名无关论文、跨年记录和一个超时来源，与人工检索比较应命中论文召回率、误收率和耗时。聚合脚本可能把来源失败返回为空列表，须逐源确认。只有摘要时，把收益来自哪个模块留作待证。

> [!example]- 展开调用示例（待试）
> ```bash
> python3 /Users/didi/.codex/skills/paper_search/scripts/search_papers.py \
>   --query "delayed feedback conversion prediction" \
>   --start-year 2014 --end-year 2026 --max-papers 5 \
>   --sources arxiv open_alex crossref
> ```

## research-tech-broadcast

团队反复讨论同一模块时，将原文位置、代码入口、输入输出张量、耦合依赖和部署约束写入方法卡。已有模块协议把记录存为 JSONL，与项目接口清单对齐后才编制消融实验单。

**接入与成本**　本地带脚本的 Skill。适配默认业务配置、维护项目接口和原文锚点是主要投入，模块查询采用关键词匹配。

**验收与换路**　拿独立模块、强耦合模块、只有整模型结果和缺代码各一例，和人工模块表比较。校验脚本能发现缺字段，工程师需要拦住把整模型收益归给子模块的结论。一次性比较可直接用表格。

> [!example]- 展开调用示例（待试）
> 将 <project-root> 替换成已有协议项目目录。
>
> ```bash
> python3 /Users/didi/.codex/skills/research-tech-broadcast/scripts/validate_protocol.py --project <project-root>
> python3 /Users/didi/.codex/skills/research-tech-broadcast/scripts/query_modules.py "延迟反馈" --project <project-root> --json
> ```

## PaperQA

有一小批合法取得的全文时，问“哪些实验在同样负采样和预算下单独消融了这个模块”。导入 PDF、建立索引、提问，输出答案和引文。将支持结论的原文、表格和实验条件交给写实验单的人。

**接入与成本**　独立 LLM 应用 v2026.08.12。模型服务可能收到文本片段，先选合适的解析、embedding 与问答环境。重建索引和多轮问答会增加费用。

**验收与换路**　固定同一批论文和专家问题，混入无答案、文献相互矛盾和表格取数题。逐条比对原文，计引用支持率、错误数、总人工分钟和调用费。定位不到表格或编造消融时，保留检索到的段落，由人读原文。

> [!example]- 展开调用示例（待试）
> 在可用的 Python 异步上下文中运行，先准备本地论文和获准的模型后端。
>
> ```python
> from paperqa import Docs
> docs = Docs()
> await docs.aadd("papers/method_a.pdf")
> await docs.aadd("papers/baseline.pdf")
> session = await docs.aquery("哪些实验分别控制了数据、模型容量和训练预算？找不到则明确说明。")
> print(session)
> ```

## Hugging Face 语义召回与重排训练

文本召回或重排漏掉相关候选时，用 query/document 正对或相关性标签训练，将 checkpoint、逐 query 得分和调用延迟接回原评测。按 query 或时间隔离训练与测试，单独预留最终评测集。

**接入与成本**　带参考材料和脚本的 Skill。成本来自标注、难负例、GPU 和索引重建。常规模板会尝试上报和推送模型，smoke 模式也可能下载、训练和评测，注意两种运行共享的缓存。

**验收与换路**　固定候选、语言、预算和检索基线，加入重复 query、假负例和无相关文档的 query。比较 Recall@K、NDCG 和重排延迟。模板按样本对切分可能泄漏 query，重复用于早停的 NanoBEIR 结果只用于开发选型。

> [!example]- 展开调用示例（待试）
> ```bash
> SMOKE_TEST=1 python scripts/train_cross_encoder_example.py
> ```
