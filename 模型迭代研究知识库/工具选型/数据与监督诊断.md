## Pandera

在训练前对曝光键、特征可见时点、标签截止时间和权重做确定性检查。给 DataFrame 声明规则，用 lazy 校验一次收集违规样本，按 row_id 回到取数任务修正。

**接入与成本**　传统库 0.35.0，本地小表适合 Python，海量曝光交给现有仓库做 join 与聚合。规则维护和全量扫描是持续成本。

**验收与换路**　在同一小表中植入重复曝光、未来特征、未成熟标签和空值，保留同一用户合法的多次曝光。与手写 SQL 逐行比对，统计漏报、误报和扫描成本。列缺少可用时点就先补血缘。已有全量 SQL 能覆盖所有规则时直接复用。

> [!example]- 展开调用示例（待试）
> ```python
> import pandas as pd
> import pandera.pandas as pa
>
> df = pd.DataFrame({
>     "impression_id": ["a", "b", "c"],
>     "event_s": [100, 200, 300],
>     "feature_available_s": [90, 190, 310],
>     "label_deadline_s": [400, 500, 900],
>     "snapshot_s": [800, 800, 800],
>     "conversion": [0, 1, 0],
> })
> schema = pa.DataFrameSchema(
>     {
>         "impression_id": pa.Column(str),
>         "event_s": pa.Column(int),
>         "feature_available_s": pa.Column(int),
>         "label_deadline_s": pa.Column(int),
>         "snapshot_s": pa.Column(int),
>         "conversion": pa.Column(int, pa.Check.isin([0, 1])),
>     },
>     unique=["impression_id"],
>     checks=[
>         pa.Check(lambda d: d.feature_available_s <= d.event_s,
>                  name="feature_visible_at_impression"),
>         pa.Check(lambda d: d.label_deadline_s <= d.snapshot_s,
>                  name="label_window_mature"),
>     ],
>     coerce=False,
> )
> try:
>     schema.validate(df, lazy=True)
> except pa.errors.SchemaErrors as exc:
>     print(exc.failure_cases)
> ```

[DataFrame Schema 文档](https://pandera.readthedocs.io/en/stable/dataframe_schemas.html) · [后端 container.py](https://github.com/unionai-oss/pandera/blob/v0.35.0/pandera/backends/pandas/container.py)

## Deepchecks

输入声明了曝光键和日期列的 train/test，计算跨集键交集和日期重叠。先明确用“不同 ID 数”还是“受影响行数”衡量泄漏，再解释报告。

**接入与成本**　传统库 0.19.1。内存、抽样漏检和依赖适配是主要成本。已有两条精确 SQL 即可解决时，增设报告层的价值有限。

**验收与换路**　固定 seed、抽样上限和时区，与 SQL 全量交集对账，植入重复 ID、跨窗 session 和恰好相同的时间。0.19.1 的日期检查只标早于训练最大时刻的行，索引泄漏的分子是不同重叠 ID 数、分母是测试行数。严格等时规则另写 SQL。

> [!example]- 展开调用示例（待试）
> ```python
> import pandas as pd
> from deepchecks.tabular import Dataset
> from deepchecks.tabular.checks import (
>     DateTrainTestLeakageOverlap, IndexTrainTestLeakage,
> )
>
> train = pd.DataFrame({
>     "event_id": ["a", "b"],
>     "event_time": pd.to_datetime(["2026-01-01", "2026-01-03"]),
>     "x": [1.0, 2.0],
> })
> test = pd.DataFrame({
>     "event_id": ["b", "c"],
>     "event_time": pd.to_datetime(["2026-01-02", "2026-01-04"]),
>     "x": [3.0, 4.0],
> })
> tr = Dataset(train, index_name="event_id", datetime_name="event_time",
>              features=["x"], cat_features=[])
> te = Dataset(test, index_name="event_id", datetime_name="event_time",
>              features=["x"], cat_features=[])
> n = max(len(train), len(test))
> date_check = DateTrainTestLeakageOverlap(n_samples=n)
> date_check.add_condition_leakage_ratio_less_or_equal(0)
> id_check = IndexTrainTestLeakage(n_samples=n)
> id_check.add_condition_ratio_less_or_equal(0)
> for check in [date_check, id_check]:
>     result = check.run(train_dataset=tr, test_dataset=te, with_display=False)
>     print(result.value)
> ```

[DateTrainTestLeakageOverlap](https://github.com/deepchecks/deepchecks/blob/0.19.1/deepchecks/tabular/checks/train_test_validation/date_train_test_leakage_overlap.py) · [IndexTrainTestLeakage](https://github.com/deepchecks/deepchecks/blob/0.19.1/deepchecks/tabular/checks/train_test_validation/index_leakage.py) · [Dataset.sample](https://github.com/deepchecks/deepchecks/blob/0.19.1/deepchecks/tabular/dataset.py)

## Evidently

对照参考期与当前期，固定渠道、列类型、季节性窗口和样本权重口径，产出每列或每个切片的漂移统计。再与成熟标签的实际误差连接，决定警报是否值得处理。

**接入与成本**　传统库 0.7.23，可从本地两份快照开始。逐列扫描、参考窗维护和处理误报比报告生成更值得计费。

**验收与换路**　加入同分布对照、只改变渠道占比、只改变条件标签关系三类案例。对照手算统计，量误报率和告警处置工时。0.7.23 的 PSI 对一定基数的数值列按两期合并数据分箱，团队固定分箱的历史值需另外复算。传入权重列本身不会让统计量自动加权。

> [!example]- 展开调用示例（待试）
> ```python
> import pandas as pd
> from evidently import DataDefinition, Dataset, Report
> from evidently.presets import DataDriftPreset
>
> ref = pd.DataFrame({"device": ["app"] * 50 + ["web"] * 50})
> cur = pd.DataFrame({"device": ["app"] * 90 + ["web"] * 10})
> definition = DataDefinition(categorical_columns=["device"])
> reference = Dataset.from_pandas(ref, data_definition=definition)
> current = Dataset.from_pandas(cur, data_definition=definition)
> report = Report([
>     DataDriftPreset(columns=["device"], method="psi", threshold=0.1)
> ], include_tests=True)
> result = report.run(current_data=current, reference_data=reference)
> print(result.dict())
> ```

## Cleanlab 与 Datalab

用已成熟标签、类别顺序明确的时间外预测概率，以及可选 embedding，把可能错标或重复的样本排成人工审阅队列。保留 row_id、采样率和校准来源，便于回到原曝光验证。

**接入与成本**　传统库 2.9.0。时间外推理、多折训练、近邻索引和专家标注通常占主要成本。负采样后须检查校准与类别先验。

**验收与换路**　在同一标注预算下，将候选与随机、按 loss、按 1−p(y) 排序的样本混合盲审。包含延迟正例、罕见人群、合法困难负例。比较确认率、切片覆盖和每个确认问题的成本。低分样本先审阅，只有胜过最强简单基线才保留这一步。

> [!example]- 展开调用示例（待试）
> ```python
> import numpy as np
> import pandas as pd
> from cleanlab import Datalab
>
> ## 仅构造接口 smoke-test 数据；这些手工概率不是实际 OOF 证据。
> labels = np.array([0] * 10 + [1] * 10)
> pred_probs = np.array([[0.95, 0.05]] * 10 + [[0.05, 0.95]] * 10)
> labels[[0, 10]] = 1 - labels[[0, 10]]
> data = pd.DataFrame({"row_id": range(20), "conversion": labels})
>
> lab = Datalab(data=data, label_name="conversion")
> lab.find_issues(pred_probs=pred_probs, issue_types={"label": {}})
> issues = lab.get_issues("label")
> print(issues.sort_values("label_score").head())
> print(lab.issue_summary)
> ```

## 数易 DataTools

能获得相应内部数据源时，用元数据和已审核的查询生成成熟标签 cohort、渠道配比或曝光计数。为下游保留来源、SQL、时间窗、分子分母和行数。文档中的 queryTableMeta 可查字段，datainfer 仅接受受支持的数易来源。

**接入与成本**　本机 Skill 1.4.0 已查技能与路由脚本，远端仅核到接口文档。成本含扫描、导出、等待和口径复核，调用前核对环境、只读身份、下载与遥测设置。

**验收与换路**　用同一数据源与日期，对照手写 SQL，加入错 ID、跨源、越权字段及无变化案例。聚合值或权限边界对不上时，退回元数据查询和固定 SQL。nl2data 同次生成并执行 SQL，返回 SQL 只支持事后审阅，路由脚本也会识别写语句。

**示例任务**　“给定已授权的测试表，先取字段元数据，再用固定 SQL 按曝光日统计第 1 天和第 7 天累计的转化数。”产物应包含表来源、查询口径和 cohort 计数，可直接与仓库基准对账。

## 多行为与延迟反馈

把未曝光、已曝光未点、点后未买和转化尚未成熟分别编码。按标签年龄做回补曲线，在同一批曝光上对比成熟前后的标签，按任务统计覆盖率、采样率和分母。只有构造出时间外的成熟对照集后，才能验证重加权、采样或纠偏模型是否改善最终误差。

亿级曝光的精确去重、切分交集和 as-of join 优先在仓库执行。保留违规行键和聚合摘要，再用 Python 查具体案例。
