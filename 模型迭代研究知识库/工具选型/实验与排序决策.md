## MLflow

将 code commit、数据快照、时间切分、候选集、指标分母和预算随 run 保存。从实验 ID 找出可比较的运行，导出配置与指标明细供统计程序复算。

**接入与成本**　传统实验平台 3.18.0，官方 MCP 属实验功能。experiments/runs 类别含写操作，只读控制依靠服务端身份。自托管还要维护数据库与对象存储，已有账本可直接导出。

**验收与换路**　把同名指标不同分母、重复/失败 run 和缺失配置混入样本，与原平台逐项对账。不能还原口径的运行单列。确认查询能减少人工定位时间再保留连接器。

> [!example]- 展开调用示例（待试）
> ```jsonl
> {"name":"get_experiment","arguments":{"experiment_id":"<已知测试实验ID>","output":"json"}}
> {"name":"describe_run","arguments":{"run_id":"<已知测试run ID>"}}
> ```

[Tracking 原文](https://mlflow.org/docs/latest/ml/tracking/) · [官方 MCP 文档](https://mlflow.org/docs/latest/genai/mcp/) · [MCP server.py](https://github.com/mlflow/mlflow/blob/v3.18.0/mlflow/mcp/server.py)

## Optuna

把调参写成可复现的 objective，预先确定搜索空间、预算、种子、约束和最终留出集。Optuna 执行 trial、记录失败和可行值，候选再到独立样本验证。

**接入与成本**　传统库 5.0.0，可选官方 MCP 0.2.0。多并发需要共享存储，训练预算占主要成本。MCP 选择已有 study 的路径可能建新 study，只读分析优先 SDK 导出。

**验收与换路**　在固定预算下与随机搜索比，包含无信号、失败和无可行候选案例。比较有效 trial 成本、耗尽预算时的表现与留出集结果。若提升来自更多尝试，或优势未复现，沿用随机搜索。

> [!example]- 展开调用示例（待试）
> ```python
> import optuna
> def objective(trial):
>     x = trial.suggest_float("x", -10, 10)
>     return (x - 2) ** 2
> study = optuna.create_study(direction="minimize",
>     sampler=optuna.samplers.TPESampler(seed=7))
> study.optimize(objective, n_trials=100, n_jobs=1)
> print(study.best_params, study.best_value)
> ```

[core v5.0.0](https://github.com/optuna/optuna/releases/tag/v5.0.0) · [最小二次函数例](https://optuna.readthedocs.io/en/v5.0.0/tutorial/10_key_features/001_first.html) · [MCP源码](https://github.com/optuna/optuna-mcp/blob/v0.2.0/optuna_mcp/server.py)

## GrowthBook

从已有快照读取实验阶段、随机化单位、主指标的分子分母、护栏、效应和区间。统计程序按实验设计计算，负责人结合最小有意义效应和上线风险作决定。

**接入与成本**　统计平台 5.2.0，另有官方 Skill 与 MCP 2.2.0。先用导出 JSON，接服务时计入仓库计算、平台授权和统计审查。下面的 JSON 每行是一个请求。

**验收与换路**　固定 A/A、已知效应、分流不符（SRM）、迟到转化、过期快照和主指标涨但护栏恶化等案例，与原平台复算。事件数当作用户数或日志不全时停止判胜。结果接口能读旧快照，分析 Skill 遇缺失或过期会 POST 刷新并触发计算，只读流程只取已有结果。

> [!example]- 展开调用示例（待试）
> ```jsonl
> {"name":"growthbook_list_skills","arguments":{}}
> {"name":"growthbook_read_skill","arguments":{"name":"experiments"}}
> {"name":"growthbook_read_skill","arguments":{"name":"experiments/references/experiment-analyze"}}
> {"name":"growthbook_api_read","arguments":{"path":"/api/v1/experiments/<测试实验ID>/results"}}
> ```
>
> ```python
> from dataclasses import asdict
> from gbstats.models.statistics import SampleMeanStatistic
> from gbstats.frequentist.tests import FrequentistConfig, TwoSidedTTest
> a = SampleMeanStatistic(sum=1396.87, sum_squares=52377.9767, n=3407)
> b = SampleMeanStatistic(sum=2422.7, sum_squares=134698.29, n=3461)
> r = asdict(TwoSidedTTest([(a, b)],
>     FrequentistConfig(difference_type="relative")).compute_result())
> print(r)
> ```
>
> 统计示例的上游预期为相对差 0.70732、区间 (−0.03526, 1.44989)、p 值 0.06191。

## EconML

已有随机实验，或处理前协变量、重叠与混杂控制有可信依据时，用成熟结果 Y、处理 T 和处理前 X/W 估计各人群的处理效应与区间。先报告预注册分层的简单均值差。

**接入与成本**　传统因果估计库 0.17.0。交叉拟合与重复模拟消耗 CPU，人工成本集中在混杂、干扰和聚类设计。groups 参数的存在并不保证所有区间都能处理任意聚类。

**验收与换路**　和分层均值差、线性基线在独立样本对照，加入真值已知、零效应、处理后变量和缺重叠等案例。比较效应误差、区间覆盖和维护成本。后验筛出的人群需要独立实验，确定性排序日志无法据此识别未曝光策略价值。

> [!example]- 展开调用示例（待试）
> ```python
> import numpy as np
> from scipy.special import expit
> from econml.dml import CausalForestDML
> rng = np.random.default_rng(123)
> X = rng.normal(size=(1000, 5))
> T = rng.binomial(1, expit(X[:, 0]))
> y = (1 + 0.5 * X[:, 0]) * T + X[:, 0] + rng.normal(size=1000)
> est = CausalForestDML(discrete_treatment=True, random_state=123, n_jobs=1)
> est.fit(y, T, X=X, W=None)
> print(est.effect(X[:3]), est.effect_interval(X[:3]))
> ```

## 排序回放与约束

先固定请求、候选、位置、模型分数、融合规则和预算，重算两版的 Top-K 重合、交换与动作变化。仅用预测值最大化收益且带配额时，可用 OR-Tools 在小问题上和穷举最优解比对，检查不可行、超时和尾延迟。[OR-Tools CP-SAT](https://developers.google.com/optimization/cp/cp_solver)

要估计未执行策略的回报，还需要真实日志策略的动作概率、充分覆盖、可比候选集和成熟奖励。先在已知策略价值的数据上比 IPS、SNIPS 和 DR，检查极端权重、有效样本量以及截断敏感性。候选缺失或新策略覆盖到历史概率为零的动作时，补探索日志或做受控实验。整页排序另需与位置和列表匹配的假设。[Open Bandit Pipeline 入门](https://zr-obp.readthedocs.io/en/latest/quickstart.html)
