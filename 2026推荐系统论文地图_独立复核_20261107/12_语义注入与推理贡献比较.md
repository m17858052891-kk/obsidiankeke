# 语义注入与推理部署：跨论文机制比较

[总索引](00_总索引.md) · [模块替换与组合关系](03_Baseline与Pipeline替换关系.md) · [模型迭代实验设计](07_模型迭代实验设计.md)

同样是给推荐系统加语义，可能要换掉物品描述，更新商家向量，改变头尾物品共享参数的方式，或为每次请求增补一批候选。这几种改动需要的日志、对照组和服务预算各不相同。下面先比较四种语义注入方法，再按推理产物在系统里的去向比较部署方案。

## 四种语义注入，改变的对象不同

| 方法 | 从哪里取得监督 | 线上消费什么 | 最有区分力的证据 |
|---|---|---|---|
| [AKT-Rec](论文/P1_语义表征与稀疏泛化/AKT-Rec_2605_23310.md) | 图文、行为统计和共现关系参与学习语义簇；排序标签训练簇表示和独立 ID 表示。迁移损失让尾部向头部靠拢的更新更强。 | 排序器按目标语义 ID（SID）读取历史，融合簇与个体表示。语义码在请求前生成。 | 移除簇表示伤及尾部，移除个体表示伤及头部。尾部 GAUC 单项上，TailNet 为 0.6448，AKT 为 0.6397。现有消融能支持两支分工，非对称迁移独自贡献多少仍待比较。 |
| [GALA](论文/P1_语义表征与稀疏泛化/GALA_2607_29213.md) | 购买查询与商家图文先做对齐，再以是否选中实际购买候选训练生成模型。 | 排序器查询冻结的商家向量，与 ID 支路按门控融合；另设辅助损失训练内容交互支路。 | 整体线上订单增加 0.55%，但 L2 商家离线 CVR AUC 从 0.8382 降至 0.8377，排序 P99 从 15.9 升至 17.6 毫秒。整体实验同时包含向量对齐、融合和辅助监督。 |
| [RecoReward](论文/P1_语义表征与稀疏泛化/RecoReward_2607_25901.md) | 冻结双塔推荐器，按描述区分目标受众与非目标受众的能力给生成器打分。非目标组指活跃且未留下正反馈的用户，曝光与否未必已知。 | 针对同一物品生成一份共享描述，再用新描述训练下游双塔。 | 原文诊断中，两组的亲和度都下降，目标组从 0.3108 到 0.2969，非目标组从 0.1596 到 0.1354。差距扩大是选择性改善的证据。检验迁移时，应换用未参与奖励的推荐器。 |
| [SARA](论文/P1_语义表征与稀疏泛化/SARA_2609_17639.md) | 问卷收集喜欢或厌恶的理由，按作者和正负极性聚合，经筛选后训练理由生成模型。 | 正向理由为用户—作者匹配提供监督和特征；负向理由编码为 SID，进入负反馈历史分支。线上消费作者级理由。 | 表 4 的理由质量评估用 **5,000 条样本**，评估作者与 SFT、DPO 训练作者均无重叠。正向、负向支路分别开展 1% 流量实验；观看与负反馈的变化各自对应不同处理组。 |

如果已有物品描述管道，RecoReward 可以先在相同字段和长度预算下替换描述；如果已有可替换的内容向量，GALA 可以先只换向量，随后单测门控和辅助损失。AKT 需要在排序器中增加簇与个体两支，SARA 需要获得作者级理由监督。接入成本取决于这些新增数据和模块。

**两个用于判断方法能否组合的实验。** 以下是跨论文实验设计，组合效果有待实际测量。

1. **购买对齐向量 × 簇迁移。** 把“原内容向量／购买对齐向量”和“无迁移／AKT 式迁移”交叉成四组。固定排序器底座、码本容量、数据时点与训练预算；另用等大小的随机簇检验是否只因共享参数变多。分别看新店、老店和头尾物品的 GAUC、曝光后转化，以及两项改动的交互效应。要专门检验梯度方向，再在同一簇结构内比较对称与非对称迁移。
2. **理由监督 × 推荐器奖励。** 把“普通描述／由用户理由监督的描述”和“无奖励／受众区分奖励”交叉。固定生成模型、描述长度、下游编码器和作者隔离划分；加入等长但作者错配的理由作对照。若训练所用评分器更偏爱新描述，而独立评分器、人工事实性判断和真实负反馈均无改善，先排查生成器迎合评分规则。这个实验借用 SARA 的监督来源，另外需要验证理由生成、正向匹配和负向 SID 三者各自的贡献。

## 推理发生在哪里，比“是否有CoT”更重要

| 方法 | 何时计算、产出什么 | 实时请求中的实际用途 |
|---|---|---|
| [RecGPT-Mobile](论文/P3_意图推理与召回接口/RecGPT-Mobile_2605_04726.md) | 高意图事件或兴趣漂移触发端侧 0.6B 模型，根据近期行为生成查询。 | 查询发往服务端，沿用既有检索和排序。适合检验“刚发生的行为能否赶上下次请求”；需同时记录设备覆盖和触发延迟。 |
| [RecGPT-V3](论文/P3_意图推理与召回接口/RecGPT-V3_2607_15591.md) | 结构化记忆约每两个月整理一次，推理时还读近期增量；模型生成标签和 SID。 | 标签与 SID 驱动召回，候选交给原排序器。训练时用生产排序器预测的 CTR 作为奖励，因此还要查真实曝光后的反馈。 |
| [DREAM](论文/P7_探索多目标与增量价值/DREAM_2608_09408.md) | 近线 M1 归纳意图，M2 从有限策略中规划，实时 M3 将策略编译为通过约束的参数。 | 原召回、精排、重排按新配额、权重或过滤规则执行。评估增益要拿相同动作空间的规则或监督策略作对照。 |
| [RPORec](论文/P3_意图推理与召回接口/RPORec_2605_21967.md) | 近线生成推理文本（CoT）和答案，将这两段写入键值存储。 | 服务时才把 CoT 标记嵌入为向量，作为工业排序器的辅助用户特征；公共数据实验另训练轻量推荐头。可比较“仅答案／等长摘要／完整推理”在同一接口的价值。 |
| [OneReason](论文/P3_意图推理与召回接口/OneReason_2606_06260.md) | 一条支路近线生成候选并缓存；另一条把推理输出的表示作为 Thinking Token 输入实时 OneRec。 | 两条支路分别改变候选覆盖和实时模型特征。应分别开启、同时开启并保留原基线，测候选重合、保留率和组合收益。 |
| [OneLatent / WhisperRec](论文/P3_意图推理与召回接口/OneLatent_WhisperRec_2610_30675.md) | 将多视角教师监督对齐到三个潜在标记。课程按高、中、低用户活跃度推进；有价值的行为触发异步生成候选 SID 并写入 Redis。 | 既有多路召回融合后进入同一精排。表 10–11 的 +9.6% 是后验估计收入，曝光和广告消耗另有观测指标。 |
| [ConnectionMind](论文/P3_意图推理与召回接口/ConnectionMind_2608_10187.md) | 大模型沿社交图中允许的边扩展路径，生成候选；用这些信息蒸馏图神经网络（GNN）。 | 重度用户中的一部分走直接推理，其余由 GNN 学生服务。检验路径监督时，同时看采样子图外的召回缺口及完整用户群的服务成本。 |
| [R2QRec](论文/P3_意图推理与召回接口/R2QRec_2610_39984.md) | 训练时对整组查询给奖励；推理时逐条生成 K 个查询，用冻结检索器检索后融合。 | 公共数据实验测的是查询改写带来的召回变化。附录的 K 次生成要计入成本；论文未报告工业线上实验。 |

做系统选型时可先看缺口在哪一环：召回里缺少刚出现的兴趣，可对比 Mobile 的触发查询与 V3 的长短期记忆；候选已覆盖但精排没有利用意图，可小规模接入 RPORec 的特征支路；希望在不同意图下调整已有策略，可测 DREAM。不同接口组合时，必须在同一流量上观察前一环多出的候选或特征是否被下一环实际采用。

## 怎样证明推理本身有用

| 要排除的替代解释 | 最小对照和判读 |
|---|---|
| 收益来自教师数据、模型容量或更长的输入 | 固定教师样本、骨干、总训练 token 与算力，交叉比较“有无理由监督”和“直接输出／显式 CoT”。潜在标记另比同教师、同预算下的无标记、随机标记和已对齐标记。OneReason 的等 token 对照在广告域出现负向；OneLatent 的推理时干预显示标记会影响 SID 命中，训练阶段各种监督的贡献还需上述对照辨别。 |
| 收益来自更快刷新或多拿了一份候选配额 | 做“旧／新模型”×“旧／新刷新策略”四组，固定总候选数和下游排序器，允许候选身份变化。同一刷新策略内比较模型时匹配缓存年龄；比较刷新策略时让缓存年龄随策略变化并记录。Mobile 可加入人为延迟行为的对照。分别记录触发覆盖、缓存命中和端到端 P99。 |
| 收益只出现在训练用评分器，或候选在精排前已被淘汰 | 按“新增候选→与原渠道重合→精排保留→实际曝光→转化”记录同一批请求，再在相同配额下随机分组。RecGPT-V3 的排序器奖励、DREAM 的列表评估器都可换成独立评分器复测；DREAM 再拿同动作空间的简单策略比较。若只有原评分器提升，仍缺少真实用户收益的证据。 |
