# ATLAS：从只评最终答案，转向可定位错误的推荐Agent诊断

[ATLAS: Dual-Horizon Diagnostic Evaluation for Tool-Use Agents in Meituan Xiaotua](https://arxiv.org/abs/2608.30685)，首次公开2026-08-31，阅读2026-10-29 [v2全文](https://arxiv.org/html/2608.30685v2)。abs题名末尾缺n，正文为Xiaotuan；来自美团与中国科大，小团本地生活助手为生产场景。

## 动机、解决的问题与位置

用户说“不要辣，附近，今晚能用”，错误可能出在意图改写、工具筛选、过期商户信息或多轮纠正遗失。最终答案打一个总分无法定位：回答可能忠实概括了工具结果，但工具检索本身已经偏离用户意图。仅优化表面文案可能保留根因。

ATLAS是**日志诊断、评测与Agent策略迭代层**，不是新的商品召回模型，也不是线上每次都加41个judge再返回结果。其产物是分维度错误信号、可校准judge、便宜诊断模型及受这些反馈训练的Agent；原有工具和业务供给仍在。

## 具体数据流与训练/推理

请求、对话上下文、推理轨迹、工具输入/输出、供给事实、最终回答→两种时间视角。单轮生命周期按“思考/反思、工具/技能执行、回答生成”×“相关性、事实性、时效性、可靠性、意图规划”组织，另有规范约束；跨轮评估指代、前轮纠正、约束延续、矛盾/重复等6项。

每项信号明确可用证据、检查对象、豁免条件及输出schema；确定性格式/ID规则用程序，复杂语义用LLM。对局部对象先判再归一化到[0,1]；无适用对象时剔除，防止把“没机会犯错”当高质量。

**校准：**41个LLM信号，每项约1000条滚动6个月日志，按场景、请求复杂度、多轮需求分层。回答类多人标注，长工具轨迹用3强模型一致判定加人工抽验；按原对话1:1拆校准/测试，通常校准F1≥.90才冻结interface上测试。不能把这些近似平衡样本F1直接当真实流量错误率。

**蒸馏：**选17个高频信号按维度/任务/输入输出形式分组，Qwen3.5-9B学多教师决策；过滤格式异常和学生已高置信正确的低收益样本，若有think字段降低其loss权重。目标是部署成本可控，不是证明小模型具有通用同等推理能力。

**本次策略更新：**约1万请求、Qwen3.6-35B-A3B、每请求16轨迹，诊断信号加权构成GRPO奖励；规范信号任一失败时训练reward归零。主要回答相关性/事实性权重每项.2，其余执行/时效/跨轮信号每项.1。最终仍是正常Agent调用工具，训练门控不等于推理阶段硬保证。

## 收益链路：证据逐环对照

1. 【论文证据】§3和Figure4给出回答忠实但查询改写已错的例子，表明最终答案评测无法唯一定位根因。
2. 【论文证据】41个LLM信号及规则明确字段/豁免，Table1同DeepSeek-V4-Pro骨干控制了judge模型差异；17信号蒸馏支持该范围保真。
3. 【作者解释】作者把诊断定位作为选择策略干预的依据。【我的推断】更正确的局部奖励使策略把优化量投向真实工具约束和供给事实，减少仅修辞上的自评分提升；依赖参考标签不共享盲点。
4. 【论文证据】Table3独立盲评相关性+6.2pp、P0幻觉−6.9pp、ID幻觉−2.0pp支持可观测质量改善；【证据缺口】没有完整因果中介实验分离每个诊断维度。
5. 【论文证据】Table4较少早退、更多卡曝光与订单方向一致；GTV CI跨0，不能说交易额显著增长。A/B检验完整优化后Agent。
6. 【我的推断】只有用户能实际完成交易、供给及时可用、训练奖励可迁移且护栏不过度拒绝，才可能变成业务收益；训练gate=0不保证在线永不违规。

**目前最可信来源：**绑定各信号允许读取的证据字段，逐对象诊断；滚动校准judge并蒸馏，选诊断项作为带规范门控的GRPO奖励。

**可观测中介：**独立人标根因F1、同证据下事实性/约束符合率、有效工具结果与可执行商户卡、错误修复率。

**机制证据强度：**中：同骨干接口对照、人评与用户AB三层证据；诊断框架对等预算普通RL的独立优势缺对照。

**仍不能排除：**新增GRPO训练量、奖励目标/权重、数据筛选、模型教师一致偏好；更好的诊断不自动等于更好策略。

**强弱场景预测【我的推断】：**适合可追溯工具输入输出、硬约束多、供给经常变动的本地生活助手；无工具证据或任务全靠主观风格时字段诊断价值弱，标签噪声会训练出judge捷径。

**证伪与替代解释对照【我的推断】：**先同judge/同token预算测完整真实证据、最终回答、打乱工具证据的根因F1；再同Agent/工具/RL数据及更新步数比较单一结果奖励与诊断奖励。允许检索候选随策略变化，不能把该中介锁死。

## Pipeline关系的复核结论

与Spotify可共用轨迹诊断但优化对象不同；与NOVA仅思想相似；与原推荐召回排序为上下游工具关系，不取代底层模型。 跨论文提升不作排名或相加；组合无增益也可能源于优化冲突、预算拥挤、数据质量或统计功效，不单归因信息冗余。

## 七问迭代卡


### 1. 什么现象值得考虑

最终回答总分把上游工具错误和下游表述错误混在一起，难以定位该修哪些数据、工具或决策。

### 2. 在哪里改动

绑定各信号允许读取的证据字段，逐对象诊断；滚动校准judge并蒸馏，选诊断项作为带规范门控的GRPO奖励。 参考教师与judge接口冻结后进入留出评测；诊断student训练其参数，策略Agent另用GRPO更新。未来对话标签不进入当前工具输入；评测使用的完整轨迹是事后证据。在线跑优化后Agent，41个judge并非每请求的串行服务组件。

### 3. 为什么可能有效

中：同骨干接口对照、人评与用户AB三层证据；诊断框架对等预算普通RL的独立优势缺对照。 重点观测：独立人标根因F1、同证据下事实性/约束符合率、有效工具结果与可执行商户卡、错误修复率。

### 4. 最小实验与数据工程条件

先选‘工具ID可追溯、地点约束、过期供给、跨轮约束保持’四项，分离对话校准/测试并盲人评；诊断可靠后再用同量日志做小规模策略更新。原文9B蒸馏8 H20、Agent RL32 H20只是原配置，不是必须门槛。

### 5. 中间量和护栏

中介：真实流量基率下precision/recall、工具错误到回答的传播率、可下单卡占比；护栏：过拒绝、无适用对象误计高分、P99/工具成本、隐私/规范、人工与自评差距、GTV CI。

### 6. 无效后怎样诊断

实现：字段越界、缺工具结果却猜标签、gate连错；数据：同对话泄漏、事件时刻供给未恢复、教师共同盲点；机制：自评分涨但盲评不涨；场景：主要损失在供给库存/价格而非Agent动作。

### 7. 何时扩量或停止

【我的推断】独立时间/新schema测试诊断可靠、盲评与小流量订单过门槛且硬护栏通过才扩；GTV目标需以GTV自身功效与CI决策，不能借订单显著替代。若额外RL的简单奖励同效则缩减复杂信号。
