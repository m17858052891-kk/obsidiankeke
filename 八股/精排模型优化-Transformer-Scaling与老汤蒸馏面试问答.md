# 精排模型优化、Transformer Scaling 与老汤蒸馏面试问答

## 0. 一分钟总回答

> 如果给我一个简单 MLP 精排模型，我不会一上来只改网络，而会从五层排查：数据与标签是否可靠、样本分布是否匹配线上、特征是否包含有效信号、模型是否能表达这些信号、训练与评估是否能真实反映业务目标。
>
> 架构侧可以引入 Embedding、显式特征交叉、候选感知序列建模、多任务结构，再考虑 Transformer 的深度、宽度、FFN、中间 Token 数和序列长度 Scaling；特征侧关注用户、物品、上下文、交叉、统计和行为序列，并严格防止穿越；样本侧处理负采样、曝光偏差、延迟反馈、难负样本和时间分布；评估侧同时看 AUC/GAUC、LogLoss、校准、分桶和线上业务指标，也要约束时延与资源。
>
> Scaling 后效果不好时，我会用训练集拟合能力、验证曲线、学习率与训练步数重调、小数据过拟合实验来区分“模型上限不够”还是“模型没有训好”。对于积累很久的老汤模型，新模型冷启动很难直接击败它，我会用老模型做蒸馏和 warm start，但让真实标签始终保留主导地位，并逐步衰减蒸馏权重，避免教师上限限制学生。

## 1. 给你一个简单 MLP 精排模型，如何系统提升效果？

### 面试逐字稿

> 我会先建立一个完整的问题树，而不是直接堆网络。精排效果大致由数据标签、样本、特征、模型、训练和评估共同决定。很多时候模型结构不是主要瓶颈：如果训练样本与线上候选分布不一致、标签有延迟或特征发生穿越，换更复杂模型也不会有稳定收益。
>
> 第一，我先确认任务定义。模型到底优化 CTR、CVR、时长还是 GMV？预测时点是什么？样本空间是曝光、点击后还是召回候选？正负样本和线上决策对象必须对齐。
>
> 第二看特征。基础 MLP 只能在输入上隐式学习交叉，所以我会补齐用户、物品、上下文、统计与序列特征，检查新鲜度和覆盖率；对明确的组合关系可以使用 FM、DCN 一类显式交叉，对用户历史则用 DIN 或 Transformer 做候选感知建模。
>
> 第三看样本。我要处理随机负采样带来的分布偏移、曝光选择偏差、转化延迟、难负样本比例、用户活跃度偏置和时间漂移。训练集、验证集最好按时间切分，避免未来信息泄漏。
>
> 第四才是架构。可以从 MLP 升级到带 Embedding 和残差归一化的深层网络，再加入显式交叉、序列塔和多任务学习；但每次只改变一个主要因素，保证收益可归因。
>
> 最后是评估。离线不能只看总 AUC，还要看 GAUC、LogLoss、校准、关键人群分桶、不同流量和时间切片；线上看 CTR、CVR、GMV、留存等业务指标，同时约束推理时延、吞吐、显存和稳定性。只有离线、在线和工程成本共同通过，才算真正提升。

### 1.1 第零步：先确认预测问题是否定义正确

先回答五个问题：

1. 样本单位是什么：一次曝光、一次点击、一个用户—候选对，还是一次请求？
2. 预测时点是什么：曝光前、点击后还是支付前？
3. 标签窗口多长：即时点击、1 天转化、7 天转化？
4. 线上候选从哪里来：召回、粗排还是其他规则？
5. 最终业务决策是什么：单目标排序，还是 CTR、CVR、价格、成本的组合？

如果预测时点不清楚，很容易把未来才产生的特征加入模型，形成数据穿越。若训练样本来自“全量物品随机负采样”，线上却是在“召回后的困难候选”里精排，也会产生训练—服务偏差。

### 1.2 模型架构：从简单 MLP 往哪里升级

#### 路径一：先把 MLP 本身训稳

- 类别特征使用独立 Embedding，连续特征做合适的归一化、分桶或变换；
- 加入 Residual、LayerNorm/RMSNorm，改善深层训练；
- 调整层数、隐藏宽度、激活函数和 Dropout；
- 检查输入维度是否被第一层过早压缩，形成信息瓶颈；
- 对稀疏 Embedding 与稠密网络使用合适的分组优化器和学习率。

#### 路径二：增强特征交叉

简单 MLP 能学习高阶交互，但学习效率未必高。可以增加：

- FM/DeepFM：显式建模稀疏二阶交叉；
- DCN/DCNv2：显式、逐层学习有界阶数的交叉；
- AutoInt/Attention：自适应学习字段间交互；
- RankMixer/MLP-Mixer：在 Token 与特征子空间之间做结构化交互。

选择依据不是模型名气，而是当前任务是否确实存在没有被 MLP 高效捕获的交叉关系。

#### 路径三：加入行为序列建模

如果用户历史被压成点击次数、近 7 天类目分布等统计量，就会损失顺序、时间和候选相关性。可以逐步尝试：

```text
Mean/Sum Pooling
→ DIN 候选感知池化
→ DIEN/RNN 兴趣演化
→ SASRec/Transformer 序列建模
→ 多域、多兴趣、长序列模型
```

#### 路径四：多任务建模

若有点击、转化、时长等相关目标，可以使用 Shared Bottom、MMoE、PLE 等共享数据和表示。但要处理：

- 任务梯度冲突；
- 标签空间不一致，例如 CVR 只在点击样本上可观察；
- 主次目标 Loss 权重；
- 负迁移和死专家。

#### 路径五：大模型化与 Scaling

当数据量、训练预算和线上资源足够，可以增加：

- Embedding 维度与词表容量；
- Transformer 层数；
- `d_model`；
- FFN 中间维度；
- Attention Head 数；
- 序列长度；
- 行为域、Query/兴趣 Token 数；
- 预训练数据与训练步数。

但 Scaling 是“模型容量、数据量和训练算力的协同增长”，不等于单独把一个参数调大。

### 1.3 特征构造：模型到底能看到什么

#### 用户特征

- 用户 ID、画像、地域、设备；
- 活跃度、生命周期、消费能力；
- 长短期兴趣分布；
- 不同窗口下的曝光、点击、转化统计。

#### 物品特征

- item、类目、品牌、作者/商家；
- 价格、质量、热度、新鲜度；
- 内容和多模态表示；
- 供给状态、库存、履约能力。

#### 上下文特征

- 时间、地域、网络、设备；
- 页面、入口、场景、请求意图；
- 当前候选集结构和召回来源。

#### 交叉特征

- 用户 × 类目；
- 用户 × 价格带；
- 地域 × 时间；
- 候选 × 历史行为；
- 当前场景 × 用户长期偏好。

#### 序列特征

- 行为对象与动作类型；
- 行为发生时间、间隔、位置；
- side information；
- 候选感知相关性；
- 多行为域与长短期窗口。

#### 统计特征的三个检查点

1. **时间窗**：1 天、7 天、30 天是否互补？
2. **分母**：CTR 的曝光分母是否与点击分子同口径？
3. **预测时点**：统计是否只使用预测时点之前的数据？

统计特征通常很强，也最容易穿越。

### 1.4 样本选取：模型在什么分布上学习

#### 负采样

随机负样本容易过于简单，模型离线 AUC 很高，线上却分不开相似候选。可以混合：

- 随机负样本：保证覆盖；
- 曝光未点击负样本：贴近线上；
- 同请求难负样本：学习精细区分；
- 模型挖掘 hard negative：针对当前错误。

改变负采样率后，训练先验发生变化，若输出用于概率估计，需要采样率修正或校准。

#### 曝光偏差

日志只记录旧策略展示过的物品，训练数据不是随机暴露。可考虑：

- 随机流量或探索流量；
- propensity score/IPW；
- doubly robust；
- 对召回源、位置、旧模型分数做分层分析。

#### 延迟反馈

CVR 标签可能在曝光或点击后很久才回流。过早把“尚未转化”当成负样本会污染标签。可采用：

- 等待完整标签窗口；
- delayed feedback 模型；
- 生存分析/时间到事件建模；
- 对未成熟样本降权或剔除。

#### 样本权重与去重

- 防止高活跃用户支配训练；
- 防止同一请求或重复曝光被过度计数；
- 对业务重要人群、长尾物品合理加权；
- 对噪声标签和异常流量降权。

#### 数据划分

推荐按时间切分：过去训练、较新时间验证、未来测试。随机切分可能让同一用户、物品和相邻事件同时出现在训练与验证中，高估泛化能力。

### 1.5 训练方式：不是换了模型就结束

- 对稀疏与稠密参数分别调学习率；
- 新增层使用合适初始化，避免残差分支一开始扰乱旧表示；
- 使用 warmup、学习率衰减和足够训练步数；
- 监控梯度范数、激活分布和不同层更新量；
- 对大模型重新搜索 batch size、学习率、正则和训练周期；
- 检查训练吞吐下降后，是否导致相同 wall-clock 下实际更新步数变少；
- 大 batch 需要考虑学习率调整与泛化变化，不能只机械线性放大。

### 1.6 评估方式与指标

#### 排序能力

- AUC：全局正负样本排序能力；
- GAUC：先在用户或请求内部计算，再加权平均，更接近个性化排序；
- NDCG/Recall@K：关注 Top-K 排序质量；
- Pairwise Accuracy：关注同请求内正负候选次序。

#### 概率质量

- LogLoss：概率是否准确，高置信错误惩罚大；
- Brier Score；
- Calibration/ECE；
- 预测概率分桶后的实际发生率。

AUC 提升不代表概率一定更准，尤其在出价、收益预估和多目标融合中，校准很重要。

#### 分层评估

至少按以下维度切片：

- 新老用户；
- 头部与长尾物品；
- 活跃度与序列长度；
- 城市、场景、流量入口；
- 召回来源；
- 时间段与日期；
- 正负样本成熟度。

总体指标可能被头部流量主导，切片能发现“整体涨、关键人群跌”的情况。

#### 工程指标

- P50/P95/P99 推理延迟；
- QPS 和吞吐；
- GPU/CPU 利用率；
- 显存、参数量与 FLOPs；
- 特征覆盖率、超时率和模型稳定性。

#### 线上指标

最终通过 A/B Test 看 CTR、CVR、时长、GMV、留存、成本、用户体验和生态指标。实验需要检查显著性、实验周期、样本量、SRM、护栏指标和长期效应。

### 1.7 优先级怎么排

建议顺序：

```text
任务与标签口径
→ 数据泄漏和训练服务一致性
→ 强特征与样本质量
→ 训练稳定性
→ 与问题匹配的结构
→ Scaling
→ 线上实验与系统优化
```

原因是越靠前的问题越可能让后续所有复杂优化失效。

## 2. Transformer 精排架构如何做 Scaling？

### 面试逐字稿

> Transformer 精排的 Scaling 不只包括加深和加宽。我会沿六个轴考虑：序列长度、隐藏维度、层数、FFN 宽度、Attention 容量、Token 或兴趣容量，同时还要增加数据量、训练 Token 数和优化预算。
>
> 加长序列主要增加历史覆盖，但 Attention 成本按长度平方增长，而且旧行为可能带来噪声；加宽 d_model 提升每个 Token 的表示容量，同时会让大量线性层的参数和计算近似按宽度平方增长；加深层数增加多步交互和组合深度，但更依赖归一化、残差、初始化与训练步数；加宽 FFN 增加逐 Token 非线性容量，但若瓶颈在历史检索或特征质量，只加 FFN 不一定有效。
>
> 所以我不会一次把所有维度都放大，而是做受控 scaling matrix：固定训练数据和预算逐轴实验，再在相同 FLOPs、相同参数量或相同延迟下公平比较，同时监控训练 Loss 是否充分下降。最终要找到数据、参数和算力之间的匹配点。

### 2.1 序列长度 L

收益来源：覆盖更长期兴趣、低频行为和周期性偏好。

代价：标准 Self-Attention 主要复杂度为：

$$
O(L^2D+LD^2)
$$

显存中的 Attention Matrix 也随 $L^2$ 增长。

风险：旧兴趣、误触、重复行为和 padding 同时增加。长序列不是免费的信息增量。

配套措施：

- 时间衰减或时间桶；
- 行为去重与质量筛选；
- target-aware retrieval，先选与候选相关的历史；
- 层次化、分块或稀疏 Attention；
- 近端精细、远端压缩的多尺度建模。

### 2.2 隐藏维度 D，也就是模型加宽

将 `d_model` 从 128 增加到 256，会提高：

- Token 表示容量；
- Q/K/V 投影容量；
- FFN 输入输出容量；
- 多头子空间总容量。

但 Transformer 大量参数来自 $D\times D$ 线性层，因此参数与计算常近似按 $D^2$ 增长。宽度翻倍，相关部分可能接近四倍，而不是两倍。

配套调整：

- Head 数或 head dimension；
- FFN ratio；
- 学习率和 warmup；
- 初始化与残差缩放；
- Embedding 输出投影是否形成窄瓶颈；
- GPU Tensor Core 友好的维度倍数。

### 2.3 层数 N，也就是模型加深

更深层数能够进行多轮信息交互。例如第一层发现局部兴趣，第二层结合候选，第三层再做跨域组合。

主要开销近似随层数线性增加：

$$
FLOPs\propto N.
$$

风险包括：

- 梯度不稳定；
- 表示过平滑；
- 训练步数不足；
- 延迟线性增长；
- 后几层学习量很小，成为“空层”。

配套措施：Pre-LN/RMSNorm、合理初始化、Residual Scaling、stochastic depth、梯度裁剪、warmup 和更长训练。

### 2.4 FFN 中间维度 $D_{ff}$

标准 FFN：

$$
FFN(x)=W_2\phi(W_1x+b_1)+b_2
$$

参数量约为：

$$
2DD_{ff}
$$

忽略 bias 时，若 `D_ff=4D`，FFN 参数约为 $8D^2$。在很多 Transformer 中，FFN 是主要参数和 FLOPs 来源。

可以从 2D、4D、8D 做受控实验，也可以尝试 GLU/SwiGLU、MoE，让模型增加条件计算容量，而不是所有样本都通过同一个超宽 FFN。

### 2.5 Attention 容量

- 增加 Head 数：提供更多关系子空间，但 head dimension 太小会限制单头表达；
- 增大 head dimension：增强每头容量，但计算变大；
- 增加 Query/兴趣 Token：提高多兴趣承载能力；
- 增加跨域交互层；
- 使用 GQA/MQA、稀疏注意力或线性注意力控制成本。

Head 数增加不等于总参数一定大幅增加：当 D 固定时，Q/K/V 大矩阵大小基本不因 Head 数改变，变化主要是切分方式。

### 2.6 Embedding 与词表 Scaling

推荐模型的大量参数可能在 Embedding 表而不是 Transformer Block。可以考虑：

- 提高重要字段 Embedding 维度；
- 减少哈希冲突；
- 为高价值字段独立建表；
- 对低频 ID 做共享、压缩或动态维度；
- 预训练或长期增量更新 Embedding。

参数量大不代表 FLOPs 大。一个巨大 Embedding 表每个样本只查少量行，参数和显存很大，但计算可能不高；FFN 参数虽可能更少，却会被每个 Token 密集执行。

### 2.7 数据和训练计算 Scaling

只扩大模型、不增加数据或训练步数，可能让大模型处于欠训练状态。Scaling 应同时问：

- 训练样本是否增加？
- 用户和物品覆盖是否增加？
- 总训练 Token 数是否增加？
- 每个参数获得的有效更新是否足够？
- 大模型吞吐下降后，是否仍然训练了同样多 step/epoch？

### 2.8 三种公平对比口径

1. **同训练步数**：看架构在相同更新次数下的能力，但大模型计算更多。
2. **同 FLOPs/wall-clock**：看计算效率，大模型可能只能训练更少 step。
3. **各自充分调优**：看最终上限，但成本最高。

面试中最好说明使用哪一种，不能混在一起解释。

## 3. FFN 加宽，是直接改大就可以了吗？

### 短回答

> 不是。代码上改大 `D_ff` 很简单，但要获得收益必须确认瓶颈确实在逐 Token 的非线性容量，同时重新匹配初始化、学习率、训练步数、正则、残差稳定性和硬件效率。否则只是增加参数和 FLOPs，甚至因为欠训练或过拟合而回退。

### 3.1 先问：瓶颈是不是 FFN

如果当前问题是：

- 行为序列太短；
- 候选信息没有进入历史建模；
- 标签噪声大；
- 特征缺失；
- Attention 没有找到相关行为；

那么加宽 FFN 很可能无效。FFN 负责对已经聚合到每个 Token 的信息做逐位置非线性变换，它不能自动补回不存在的特征，也不能替代正确的 Token 交互路径。

### 3.2 参数和计算会怎样变化

从 `D_ff=4D` 加到 `8D`，FFN 参数与乘加量近似翻倍。若 FFN 原本已经占 Block 大部分 FLOPs，整体训练和推理成本会显著上升。

要同时检查：

- GPU 显存是否允许；
- batch size 是否因此下降；
- 吞吐下降是否导致训练 step 变少；
- 线上 P99 延迟是否超预算；
- 维度是否适合硬件矩阵乘法。

### 3.3 优化参数需要重新调

加宽后通常要重新搜索：

- learning rate；
- warmup steps；
- weight decay；
- dropout；
- gradient clipping；
- 训练 epoch/总 Token 数。

旧模型的最优超参数不是新模型的最优超参数。

### 3.4 初始化与残差稳定性

新增宽层若输出尺度过大，会扰乱残差主干。可使用：

- Xavier/Kaiming 等匹配激活函数的初始化；
- Pre-LN/RMSNorm；
- 输出层小初始化或残差缩放；
- 从窄模型做 Net2Wider 式函数保持初始化；
- 先 warm start 再逐步放开新参数。

### 3.5 数据是否足够

训练集 Loss 继续下降、验证集变差，通常表示容量增加后过拟合，需要更多数据或正则；训练和验证都不改善，则可能是瓶颈不在 FFN，或者优化没有匹配。

### 3.6 更聪明的增容方式

除直接加宽外，还可以考虑：

- SwiGLU/GEGLU：改善门控非线性；
- MoE：只激活部分专家，实现条件计算；
- 低秩增量分支；
- 在高价值层加宽，而非所有层统一加宽；
- 根据 Token 类型使用不同 FFN。

## 4. Scaling 后效果不好：模型 bound 还是训练方式不对？

这里的 model bound 可以理解为模型的表达能力或可达到的近似上限。要区分它与优化失败、欠训练、过拟合和数据上限。

### 4.1 最关键的诊断矩阵

| 现象 | 更可能原因 | 下一步 |
|---|---|---|
| 新模型训练 Loss 明显低于旧模型，验证更差 | 过拟合、分布偏移、正则不足 | 加数据/正则，查切片与时间漂移 |
| 新模型训练 Loss 都降不下去 | 优化失败、LR 不合适、梯度问题、实现 Bug | 小样本过拟合、LR sweep、查梯度与数值 |
| 新旧训练 Loss 接近，新模型验证也接近 | 新增容量没有作用或数据/特征成瓶颈 | 换信息路径、特征或任务，不只加参数 |
| 新模型继续训练还在稳定变好 | 欠训练 | 增加 step，调整 scheduler |
| 新模型前期更慢，最终超过旧模型 | 大模型收敛更慢 | 用充分训练预算公平比较 |
| 新模型所有超参都充分调优后，训练集仍欠拟合 | 表达瓶颈或输入信息不足 | 改结构/特征；先确认不是数据不可分 |
| 训练离线都涨，线上不涨 | 指标错位、训练服务偏差、校准/时延问题 | 查线上候选、特征一致性和业务指标 |

### 4.2 小数据过拟合测试

取一个很小的数据子集，例如 1～10 个 batch，关闭强正则，尝试把训练 Loss 降到很低。

- 如果做不到，优先怀疑实现、标签、mask、loss、学习率、梯度或数值问题；
- 如果能轻松记住小数据，说明基本表达与反向链路存在，再看大规模优化和泛化。

这是区分“代码/优化没通”和“泛化问题”的高价值检查。

### 4.3 看完整学习曲线，不只看最终点

同时画：

- train loss vs step；
- validation loss/AUC vs step；
- 学习率；
- 梯度范数；
- 参数更新范数；
- 各层激活均值、方差；
- 不同序列长度和人群切片指标。

如果大模型在训练结束时曲线仍明显向好，就不能据此说模型无效，只能说当前训练预算不足。

### 4.4 重新做超参数搜索

至少做：

- learning rate × warmup；
- batch size × gradient accumulation；
- 训练步数；
- weight decay/dropout；
- 初始化/Residual scaling；
- 梯度裁剪阈值。

宽度和深度改变后，最优学习率及正则通常会改变。

### 4.5 同预算与充分训练两套对照

建议同时报告：

1. 相同 wall-clock 或 FLOPs 下谁更好；
2. 各自充分训练后谁的上限更高。

前者回答效率，后者回答能力上限。大模型如果必须花十倍计算只涨万分之一，可能不具备业务价值。

### 4.6 判断是否到数据/特征上限

可以尝试：

- 增加训练数据，看收益是否恢复；
- 增加高质量强特征；
- 用 oracle 特征或更强标签做上限实验；
- 按人群切片，看是否只有信息稀疏人群无提升；
- 比较 ensemble 是否还能明显提高。

如果多个不同大模型都饱和，而新增有效特征能立刻提升，瓶颈更可能在信息而不是参数。

### 4.7 面试中的严谨结论

> 单次加宽失败不能证明模型已经到达 bound。只有在数据、实现、训练预算和超参数都充分控制后，大模型训练集拟合、验证泛化与各切片仍无改善，才有资格怀疑当前结构或输入信息形成上限。

## 5. 如何让新架构打败“老汤模型”？

### 5.1 什么是老汤模型

这里的“老汤”通常指长期在线迭代的成熟模型。它的优势不只在网络结构，还包括：

- 训练过更多历史数据；
- Embedding 已经积累稳定语义；
- 超参数被反复打磨；
- 特征和样本口径高度适配线上；
- 可能经历长期增量训练或多轮蒸馏。

因此，新架构随机初始化，即使理论容量更大，也可能短期打不过老汤。

### 5.2 推荐方案：warm start + 蒸馏 + 真实标签训练

#### 第一步：保证公平与兼容

- 特征、样本窗口、负采样和评估口径一致；
- 旧模型和新模型使用相同可用数据；
- 能复用的 Embedding、输入投影或底层参数先 warm start；
- 新增层使用稳定的小残差初始化，避免一开始破坏旧函数。

#### 第二步：教师蒸馏

让老模型输出 teacher logit $z_t$，新模型输出 student logit $z_s$。二分类软标签蒸馏可以写成：

$$
p_t^T=\sigma(z_t/T),\qquad p_s^T=\sigma(z_s/T)
$$

$$
L_{KD}=T^2\cdot BCE(p_s^T,p_t^T)
$$

总损失：

$$
L=L_{hard}+\lambda(t)L_{KD}
$$

其中 `L_hard` 使用真实标签，`L_KD` 学习老模型的平滑知识。

蒸馏价值在于：真实标签只有 0/1，而教师分数包含样本难度和相对关系。例如两个负样本真实标签都是 0，但教师可能给 0.01 和 0.35，学生由此知道第二个更接近正类边界。

#### 第三步：排序蒸馏

精排不只关心点式概率，还可以在同一请求候选内蒸馏顺序：

$$
L_{rankKD}=\sum_{(i,j)}
\log\left(1+\exp(-(z_{s,i}-z_{s,j})\cdot sign(z_{t,i}-z_{t,j}))\right)
$$

也可以蒸馏 listwise 分布、Top-K 关系或中间表示。

#### 第四步：分阶段训练

一种实用流程：

```text
阶段1：高蒸馏权重，快速继承老模型能力
阶段2：蒸馏 + 真实标签联合训练
阶段3：逐步降低蒸馏权重，重点优化真实目标
阶段4：必要时去掉蒸馏，在新数据/新目标上微调
```

### 5.3 为什么蒸馏能帮助新模型

- 减少随机初始化的冷启动；
- 继承老模型长期积累的排序边界；
- 软标签比 0/1 标签信息更密；
- 对长尾和噪声样本提供平滑监督；
- 新模型可以先复制旧函数，再利用新增容量学习残差。

### 5.4 还可以用函数保持式扩容

若只是加宽 MLP，可以用 Net2Wider 思路复制旧神经元并分摊后续权重，使新网络初始化时近似保持旧函数；若加深，可以把新增残差层初始化为近似恒等映射。

这比完全随机初始化更容易做到“起点不低于旧模型，再逐步超过”。

## 6. 如何避免蒸馏限制新模型上限？

这是最关键的追问。

### 面试逐字稿

> 蒸馏的作用应该是给新模型一个更好的起点和训练先验，而不是让它永久复制教师。为了避免教师成为天花板，我会让真实标签 Loss 始终存在，并把蒸馏权重随训练逐步衰减；对于教师明显错误或低置信的样本降低蒸馏权重；让新增层或新增特征保留不受强蒸馏约束的残差通路。训练后期可以完全去掉蒸馏，只用真实目标和线上新数据微调。这样学生先继承、再纠错、最后超越。

### 6.1 真实标签不能被教师替代

不要只优化：

$$
L=L_{KD}
$$

而应保留：

$$
L=L_{hard}+\lambda L_{KD}.
$$

真实标签是学生纠正教师错误的来源。

### 6.2 蒸馏权重退火

训练早期教师权重大，帮助稳定；后期逐渐减小：

$$
\lambda(t):\lambda_0\rightarrow0.
$$

这样学生后期能够离开教师函数邻域，利用新增容量优化真实目标。

### 6.3 置信度或正确性加权

教师低置信、与真实标签冲突或在某些人群表现较差时，降低其权重：

$$
L=L_{hard}+\lambda w(x)L_{KD}.
$$

`w(x)` 可以由 teacher confidence、teacher correctness、样本成熟度或人群可靠性确定。

注意：高置信不等于一定正确，权重策略仍需验证。

### 6.4 残差学习

让学生表示为：

$$
z_s=z_t+\Delta z_{new}(x)
$$

或者让新分支学习教师无法解释的残差。这样旧能力有明确保底，新容量专门负责改进。

但如果推理时不能调用 teacher，需要把 teacher 部分参数复制进 student，或在训练结束后将其整体固化到学生结构中。

### 6.5 只蒸馏一部分能力

可选择：

- 只蒸馏底层表示，输出头自由学习；
- 只对老特征/老流量蒸馏；
- 新特征和新分支不做强约束；
- 只蒸馏排序相对关系，不要求概率完全一致；
- 只在训练早期做 feature distillation。

### 6.6 多教师或集成教师

单一旧模型有自身偏差。使用不同时间、不同结构或不同目标的多个教师，可降低学生被单一教师错误限制的风险。但教师集成成本更高，而且学生仍需真实标签纠错。

### 6.7 用更新的数据训练学生

教师在旧分布上成熟，不代表在新分布上最优。学生可以在更近时间窗口、探索流量和新增特征上训练，这些是超越教师的重要信息来源。

### 6.8 判断学生是否真的超越

不能只比较学生与教师 logit 的相似度。需要看：

- 真实标签上的 AUC、GAUC、LogLoss、Calibration；
- 同请求排序；
- 教师错误样本上的纠错率；
- 新用户、长尾物品和新分布切片；
- 线上 A/B Test 与工程成本。

如果学生与教师相关性越来越高，但真实指标没有提高，说明蒸馏可能过强。

## 7. 一套可以落地的实验方案

### 7.1 MLP 优化实验表

| 实验 | 只改变什么 | 目的 |
|---|---|---|
| B0 | 原始 MLP | 基线 |
| B1 | 训练参数重调 | 判断基线是否欠训练 |
| F1 | 新增强统计/交叉特征 | 判断信息瓶颈 |
| S1 | 改进负采样/难负样本 | 判断样本瓶颈 |
| A1 | 加 DCN/DeepFM | 显式交叉收益 |
| A2 | 加 DIN | 候选感知历史收益 |
| A3 | 加 Transformer | 序列演化收益 |
| M1 | 多任务结构 | 辅助监督收益 |

### 7.2 Transformer Scaling Matrix

不要同时把 L、D、N、D_ff 全部增大。可以先做：

```text
长度 L：     128 / 256 / 512
宽度 D：      64 / 128 / 256
层数 N：       2 / 4 / 6
FFN ratio：    2 / 4 / 8
Query 数：     1 / 2 / 4
```

第一轮单轴扫描找敏感方向；第二轮只组合有正收益的轴；第三轮在同延迟和同 FLOPs 下选 Pareto 最优点。

### 7.3 老汤迁移实验

| 组别 | 初始化 | 蒸馏 | 目的 |
|---|---|---|---|
| T0 | 随机 | 无 | 新架构纯能力 |
| T1 | warm start | 无 | 参数迁移收益 |
| T2 | 随机 | 固定蒸馏 | 软标签收益 |
| T3 | warm start | 固定蒸馏 | 快速追平教师 |
| T4 | warm start | 蒸馏退火 | 是否突破教师 |
| T5 | warm start | 置信加权+退火 | 减少教师错误约束 |

报告时同时给：最终上限、达到教师水平所需 step、线上延迟和资源。

## 8. 高频追问与短答

### Q：模型效果不好，为什么不直接加特征？

> 可以加，但先要验证新增特征在预测时可用、覆盖稳定、无穿越，并确认线上能低延迟获取。特征有信息增益才有价值，堆大量相关或噪声特征可能增加过拟合和系统复杂度。

### Q：AUC 涨了就能上线吗？

> 不能。还要看 GAUC、LogLoss、校准、关键切片、线上业务指标和推理成本。AUC 只衡量全局排序，不保证同请求排序、概率准确或线上收益。

### Q：为什么长序列反而下降？

> 更长历史同时引入过期兴趣、误触和重复行为，且 Attention 竞争与训练难度上升。如果没有时间建模、相关性检索和足够训练预算，信噪比可能下降。

### Q：加深和加宽优先选哪个？

> 没有统一答案。宽度增强单层表示容量，深度增加多轮组合。应根据训练曲线、数据规模、时延预算做同 FLOPs 实验；序列交互不足可能更需要深度，单层形成明显信息瓶颈可能更需要宽度。

### Q：大模型训练 Loss 更低但 AUC 不涨，说明什么？

> 优先怀疑过拟合或目标错位，而不是优化失败。需要看验证 LogLoss、切片、校准、时间分布，并增加正则、数据或更贴近排序的监督。

### Q：蒸馏和直接用教师伪标签有什么区别？

> 伪标签常把教师输出当主要甚至唯一标签；蒸馏通常把教师软分布作为辅助监督，与真实标签联合。后者更容易让学生纠正教师并超过教师。

### Q：学生比教师小，能超过教师吗？

> 可以，若教师软标签起到去噪和正则作用，学生结构更适配任务，或学生使用更新数据和更强特征。但容量过小仍会形成表达上限，不能保证超越。

### Q：学生比教师大，为什么还需要蒸馏？

> 大模型容量高但更难优化。老模型提供成熟决策边界和密集软监督，能减少冷启动；训练后期再降低蒸馏约束，释放大模型上限。

## 9. 最终背诵框架

遇到“怎么优化精排模型”，按下面顺序说：

```text
任务口径：预测什么、预测时点、样本空间
数据标签：延迟、噪声、穿越、训练服务一致性
样本：负采样、hard negative、曝光偏差、时间切分
特征：用户、物品、上下文、交叉、统计、序列
架构：MLP → 显式交叉 → 候选感知序列 → 多任务 → Scaling
训练：初始化、优化器、LR、训练步数、正则、梯度
评估：AUC/GAUC + LogLoss/校准 + 切片 + A/B + 时延
```

遇到“为什么 Scaling 没效果”，按下面顺序说：

```text
先查实现和小样本过拟合
→ 看训练/验证完整曲线
→ 重新调 LR、warmup、训练步数和正则
→ 做同预算与充分训练两套比较
→ 再判断模型、数据还是特征上限
```

遇到“如何打败老汤”，按下面顺序说：

```text
公平数据与特征口径
→ warm start / 函数保持式扩容
→ 真实标签 + 教师软标签蒸馏
→ 蒸馏权重逐步退火
→ 对教师错误样本降权
→ 新分支学习残差
→ 后期去蒸馏，用新数据和真实目标突破上限
```
