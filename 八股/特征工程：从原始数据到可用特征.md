# 特征工程：从原始数据到可用特征

特征工程的目标不是“尽量多拼字段”，而是让模型在**预测时刻**获得稳定、可解释、训练与服务一致的信息。一个特征是否有价值，要同时看信息增益、可用性、覆盖稳定性和线上获取成本。

## 1. 一条完整特征链路

$$
\text{原始事件/维表}
\rightarrow \text{样本锚点与预测时刻}
\rightarrow \text{特征计算窗口}
\rightarrow \text{清洗与编码}
\rightarrow \text{训练/服务一致的特征值}.
$$

最先确定两件事：

1. **样本锚点**：预测哪一次曝光、请求、订单或用户状态？
2. **预测时刻**：在该时刻模型实际能看到哪些信息？

没有这两个定义，就无法判断一个累计统计、行为序列或标签衍生字段是否穿越。

## 2. 四类基础特征及常见处理

| 类型 | 例子 | 常见处理 | 风险 |
|---|---|---|---|
| 类别 / ID | user_id、city、品类、设备 | vocab + embedding；低频归 OOV | 新 ID、长尾稀疏、词表漂移 |
| 连续数值 | 价格、距离、时长、金额 | 缺失标记、截断、log1p、z-score、分桶 | 长尾、量纲差异、异常值 |
| 统计特征 | 近 7 天点击率、均价、活跃天数 | 明确窗口、分母平滑、按时间回填 | 用到当前/未来标签、冷启动 |
| 序列特征 | 最近点击、下单、搜索行为 | 按时间排序、截断、行为/时间 embedding | 顺序错乱、padding、未来行为泄漏 |

类别与连续值的处理不能一概而论。高基数 ID 直接 one-hot 会带来巨大稀疏参数，通常使用 embedding；金额、次数等重尾连续值常在截断后做 log 变换或分桶，但变换规则必须在训练与推理一致。

## 3. 缺失值、异常值与低频值

### 缺失值

缺失本身可能有业务含义，例如“从未下单”和“数据没回传”不同。常见做法是数值填充加缺失指示位、类别使用专门的 `MISSING` token。不要只把所有缺失填 0 后假设模型自然能理解。

### 异常与长尾

先区分真实长尾和脏数据。对明显非法值可修复或过滤；对真实重尾可做 winsorize/clip、log1p、robust scaling 或分桶。处理阈值应由训练集统计量生成，不能混入未来测试数据。

### 低频类别与冷启动

低频 ID 可合并为 OOV/UNK，或结合层级特征（如 item 的品类、城市、内容标签）提供回退信息。新用户/新物品不应被训练词表外的随机初始化完全主导，应在离线评估中单独切片。

## 4. 交叉、统计与序列：各自解决什么

- **显式交叉**：例如城市 × 时段、用户等级 × 品类；适合已知、稳定的业务规律，LR/FM/DCN 可直接利用。
- **统计特征**：将长历史压缩为计数、均值、比率、最近一次间隔等；高效但可能损失顺序和上下文。
- **序列特征**：保留“发生了什么、以什么顺序发生、相隔多久”，适合兴趣迁移、重复消费和状态变化；DIN/SASRec/Transformer 等负责建模。
- **候选交叉/候选感知**：历史行为是否相关取决于当前候选 item，交互应在候选已知后进行，而不是先把全部历史粗暴压成一个固定用户向量。

特征交叉不是越高阶越好。强相关、冗余或统计口径不稳定的特征可能增加过拟合和线上复杂度；优先通过消融和分桶确认新增信息是否真实有效。

## 5. 最重要的红线：时间穿越与训练服务不一致

### 时间穿越自查

对每一个特征问四个问题：

1. 它的原始事件发生时间是否早于预测时刻？
2. 聚合窗口的右边界是否严格截在预测时刻之前？
3. 它是否直接或间接使用了标签、结果状态或未来统计？
4. 归一化、词表、目标编码是否只由训练期数据拟合？

例如预测一次发单是否成交时，不能使用发单后的应答、取消、完单字段；预测当前点击时，不能把本次点击写入“近 7 天点击数”。

### Train-serving 一致性

训练与线上必须使用同一口径的：字段含义、默认值、词表/OOV、归一化参数、时间窗口、分桶边界与序列截断规则。离线把全量数据 `fit` 出的均值方差、线上实时更新的统计量，或两边不同的时区/去重规则，都可能造成静默退化。

## 6. 特征选择与验证

特征价值不应只看相关系数。推荐采用：

1. 先保证预测时可获得、覆盖率足够、口径稳定；
2. 做单特征质量检查：缺失率、分布、漂移、与标签的粗分桶关系；
3. 做增量消融：在固定样本、训练预算下比较 AUC/GAUC、LogLoss、校准和关键切片；
4. 检查线上延迟、存储、特征新鲜度与故障回退；
5. 上线后继续监控覆盖率、分布漂移、缺失率与业务效果。

树模型的 gain、线性模型权重、Permutation importance、SHAP 都可以辅助诊断，但不等于因果贡献；尤其在共线特征中，重要性会在特征之间重新分配。

## 7. 面试中的通用回答

“我先确定样本锚点和预测时刻，再设计用户、物品、上下文、统计、交叉和序列特征。类别 ID 用 embedding 并处理 OOV，连续值按分布做缺失标记、截断、变换或分桶；统计和序列都严格按预测时刻截断。新增特征不只看离线 AUC，还看 LogLoss、校准、关键人群切片、覆盖稳定性与训练服务一致性。对效果回退，我优先排查时间穿越、样本分布变化和冗余/噪声特征。”
