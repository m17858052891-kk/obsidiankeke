花小猪用这个模型估计一笔订单最终完单的概率。模型把订单和司乘信息切成小段（token），每段交给几个小网络（专家）处理。原文做了一个很有用的对照：**每层都存 4 个专家，每段从调用 3 个改为调用 2 个**。总参数仍是 550 万，每条样本的矩阵乘加少了 **18.82%**，两次验证的完单 AUC 都是 **0.8302**。顺着这个结果就能提出扩容问题：每次仍只用 2 个，如果给它 8 个可选，能否预测得更准？

这篇技术分享为下一轮留下了一个可复跑的基线、一份按模块拆开的成本表，以及几次足以提醒人谨慎看待小收益的重跑结果。**§1–4 是原文实验及其解读，§5 是基于这些结果设计的后续对照。** [Cooper 原文《PEPNet vs ModuleMixer：司机完单预估模型的结构升级》](https://cooper.didichuxing.com/knowledge/2199610335356/2210516076344)

## 1. 下一轮从哪个模型起跑？

两个版本都评估一笔订单最终完单的概率。旧版同时区分司机取消、乘客取消和完单，新版直接学习“完单 / 未完单”。因此可以对照完单排序，但训练损失的绝对值口径不同。下文五位数字均为原文的实验组件号。

| | 91207 · PEPNet 旧基线 | 15161 · ModuleMixer 扩容基线 |
|---|---|---|
| 表示怎样加工 | 六路拼成 16×96，2 层，各 token 用自己的前馈网络 | 双路拼成 24×48，4 层，跨 token 混合、共享专家 |
| 训练 | 三分类，1 轮，约 38,800 步，固定学习率 | 二分类，3 轮，116,400 步，余弦衰减 |
| 总参数 | 6,574,357 | 5,501,621（−16.32%） |
| 完单 AUC | 0.8282 | 0.8302（绝对 +0.0020） |
| logloss / 平均预估偏差 | 缺可比记录 | 0.3945 / −0.65% |
| 每样本 MAC（矩阵乘加数） | 缺全模型同口径总数 | 10,173,856 |

**15161 适合做起点，是因为结构、成本、完整验证指标都找得到。** 另一版 36049 的 AUC 为 0.8305，logloss 也为 0.3945，但训练日志缺参数总数。从 91207 到 15161，结构、任务、训练步数和学习率一起变了。省下 107 万参数可以精确拆账，AUC 的 +0.0020 只能算这整套方案的观测差值。

> [!info]- 复跑时用哪套配置？（原文 §1、附录 A–C）
> 15161 用 `bilinear_pdnet` 双分支、24 个 48 维 token、4 层、每层 4 专家、Top-2。预测头为 1,152 → 256 → 128 → 1，head dropout 为 0.2。训练用 Adam、FP32、batch 4,096（验证 10,240），实际起始学习率 0.003，余弦衰减至 0.00003，负载均衡损失权重 0.01。
>
> 标签取 `dc_oc_finish` 的第三项 `is_finish`。附录 A 可按组件 UUID 查运行，附录 B 给出 11 月 11 日的代码快照及文件校验值。训练脚本把 seed 写死为 100，做多种子对照时要核对实际生效的值。原文共查 98 个训练目录，18 个取得完整验证指标；同一目录可能混有多次运行，需要同时核对结构配置和指标。

## 2. 550 万参数花在哪？一次预测又算在哪？

顺着一条样本看，从原始字段到完单概率，模型做了三步。

1. **读订单和人。** 4 个类别、36 个订单上下文字段、90 个司机画像字段、16 个乘客画像字段，共 146 个，各编码成 16 维。
2. **用两种视角看同一组字段。** PSENet 根据订单上下文给全部字段加权，计算 10,585 个字段对的交叉，生成 16 个 token。PdNet 根据司乘画像给同一份原始字段另算权重，压缩成 8 个 token。这样，司机历史可以按当前订单条件被重新加权，订单信息也可以按司乘历史被重新加权。
3. **混合信息，再选专家。** 每层先把 24 个 token 切成小段并交叉重排，让每个新 token 都拿到其他 token 的信息。这一步无可训练参数。路由器再根据订单上下文和当前 token 选择 2 个专家。重复 4 层，预测头给出完单概率。原文把这样的一层叫作 RankMixerBlock。

| 15161 的模块 | 参数量及占比 | MAC/样本及占比 |
|---|---:|---:|
| 显式二阶交叉 FastBilinearInteraction | 3,506,176 · **63.73%** | 3,882,816 · 38.2% |
| 画像压缩层 pdnet_compress | 898,176 · **16.33%** | 897,024 · 8.8% |
| 4 层 ModuleMixer 主干（参数含输入归一化） | 577,648 · **10.50%** | 4,895,744 · **48.12%** |
| 字段编码、两路字段门控、预测头 | 519,621 · 9.44% | 498,272 · 4.9% |
| **全模型** | **5,501,621** | **10,173,856** |

**显式交叉和画像压缩这两个模块，合计用了约 80.1% 的参数。** 单是把 12,921 维交叉输入投到 256 维，就约需 331 万参数。**计算最多的却是主干**：24 个 token 各选 2 个专家，一条样本在每层形成 48 个 token–专家配对，同一套权重会重复参与计算。这张表能定位存储和计算的大头，哪个位置再加参数最能涨点，要由实验回答。

> [!example]- 从旧版到新版，具体省掉了哪 107 万参数？（原文 §4–5）
> 其余五路 token 生产和旧主干换成画像分支及共享专家主干，**−1,106,016**；交叉分支输出从 256 加宽到 768，**+131,584**；预测头输入从 1,536 收窄到 1,152，**−98,304**。合计 **−1,072,736**。旧模型第一项按总量倒推。
>
> 原文还报告两个容易混读的量。① **+19.79%** 是两个端点的“AUC ÷ 百万参数”相对变化，无法据此外推出下一百万参数能换多少 AUC。② **4.58 倍**是主干 MAC 占比除以参数占比，描述权重复用程度。旧主干的 MAC 只有依赖宽度假设的粗估，旧模型总 MAC 和新旧端到端时延都缺少可比实测。

> [!info]- 查输入、形状和显存时看这里（原文 §2–3）
> 4 个类别字段分别为订单类型、派单类型、城市、呼叫小时，采用 embedding。36 个订单字段包含 24 个实时供需指标；90 个司机字段含 22 项行为指标 × 4 个回溯窗口及 2 项出车诱导计数；16 个乘客字段按自营、三方各取 8 项。142 个数值字段分别投影到 16 维。分位数离线写入配置，换数据要重新统计。
>
> 订单门控读前 40 个字段，画像门控读后 106 个字段，各输出 146 个权重。交叉一路输出 768 维，画像一路输出 384 维，合计 1,152 = 24×48。调整两路宽度要保持这个形状约束。显式交叉还会生成 146×146 的中间矩阵，batch=4,096、FP32 时，这一块约 **333 MiB**。

## 3. 哪些改动值得带进下一轮？

**① 每次少算一个专家，能省多少？** 28703 → 15161，每层可选专家数 **E=4** 固定，每个 token 实际选择的专家数 **K 从 3 降到 2**。两组 AUC 都是 0.8302，logloss 都是 0.3945，平均偏差都是 −0.65%。按原文矩阵乘口径，全模型每样本 MAC 从 **12,533,152 降到 10,173,856（−18.82%）**。计算节省可以复算；质量只观测到这两次在报告精度下打平，线上时延另需测量。

**② 扩专家前，已有的 4 个都用上了吗？** 早期路由把长的订单上下文与短的 token 直接拼接，不同 token 容易选中同一组专家。90252 → 01462 改为两路分别编码、归一化后再选，只加 **1,280** 个参数，AUC 从 **0.8282 到 0.8292**，logloss 从 0.3969 到 0.3955，偏差从 −1.26% 收窄到 −0.13%。

原文还给了**实际命中量**。15161 训练末期的一次末层记录中，4 个专家分别拿到约 **24.8%、24.4%、25.0%、25.7%** 的路由分配。原文另记，曾有未加负载均衡损失的运行只有两个专家被选中，另两个命中为零。因此，把专家从 4 个加到 8 个时，除了看 AUC，还要看新专家有没有接到足够的 token。命中均衡本身也只说明使用量，要知道不同专家学到了什么，还得按订单场景或 token 来源继续看。

**③ 给画像分支多 18 万参数，换来了什么？** 01462 → 94525，新增 PdNet，同时把 token 形状从 16×32 改成 24×48。参数 **+183,537（+3.45%）**，AUC **0.8292 → 0.8294**，logloss **0.3955 → 0.3956**，偏差 **−0.13% → +0.46%**。三个指标方向不同，分支和形状又同时变化，留下的问题是画像这一路的独立贡献有多大。

**④ 历史上 920 万参数的版本表现如何？** 三路结构 81735 有 **9,197,133** 个参数，AUC **0.8297**，logloss **0.3952**，平均偏差 **+0.32%**。相较 15161，它的排序略低，整体偏差却更接近零。两者结构不同，单靠这两个点画不出容量收益曲线。

> [!info]- 其他结构与训练对照（原文 §6.1–6.5）
> **画像分支加非线性并降维**（94525 → 37204）：少 33,952 个参数，AUC 0.8294 → 0.8292，logloss 0.3956 → 0.3962，偏差 +0.46% → +1.07%。这组同时动了非线性与维度。
>
> **改恒等残差**（94525 → 79496）：原结构把重排结果与输入相加，1,152 维线性映射的秩为 600。给原输入一条恒等通路后，AUC 0.8294 → 0.8290，logloss 0.3956 → 0.3963。作者推测原投影起正则作用，这一次对照尚难确定原因。
>
> **训练从 1 轮增至 3 轮**（94525 → 66867）：同时把 Top-2 改成 Top-3，因此无法从两组差值单独计算多训两轮的收益。66867 每轮第 35,000 步的训练损失依次为 0.3958、0.3921、0.3911。
>
> **去掉预测头 dropout**（66867 → 47272）：AUC 0.8291 → 0.8289，logloss 0.3961 → 0.3960，两项略向相反方向移动。**换余弦学习率**（66867 → 28703）：参数量相同，AUC 0.8291 → 0.8302，logloss 0.3961 → 0.3945。结合下一节的重跑才看得出这次改善有多稳。
>
> **早期标量门控 36049** 先用一个权重合并两路表示，再切成 16×32，取得 0.8305 AUC。值得用同预算复跑，原文日志不足以比较它的参数效率。其他变体的逐项指标见原文 §6.2。

## 4. 排序涨了多少，概率可信多少？

| 同一 Top-3、余弦衰减、3 轮配置 | 完单 AUC | logloss | 平均预测 | 相对偏差 |
|---|---:|---:|---:|---:|
| 28703 | 0.8302 | 0.3945 | 75.20% | −0.65% |
| 57392 · 重跑 | 0.8291 | 0.3961 | 76.35% | +0.87% |

**怎么看涨点？** 相同配置两次训练的 AUC 相差 **0.0011**。新增画像分支的改善是 +0.0002，改双塔路由是 +0.0010，换余弦学习率是 +0.0011。这个参照解释了为什么三项都值得再跑。两次运行只能给出一次观测极差，还不足以估计稳定的噪声水平或设显著性门槛。作者根据训练损失趋平判断继续扩容收益有限；要检验容量上限，还缺同一架构、多个规模、相同预算的验证集曲线。

**怎么看概率？** 二分类验证集有 **155,494,639 条**，真实完单率 **75.69%**。15161 平均预测 **75.20%**，按相同比例折算，每 10 万单会少估约 **490 单**。这是低 **0.49 个百分点**，除以真实完单率后相对偏差为 **−0.65%**。AUC 看排序，logloss 对每笔单的概率打分，平均偏差只反映总体高估或低估。

**如果概率要用于派单或补贴分档，还需看每一档。** 全局偏差很小，也可能是低概率段高估、高概率段低估后抵消。原文说 15161 日志有十档校准表，但文中没列逐档数据，尤其是预测低于 0.1 和高于 0.9 的两端，校准好坏仍待核实。作者认为训练收敛程度可能解释偏差的方向；同一余弦配置在重跑时也出现过由低估转为高估，这个解释还需要验证。

## 5. 下一轮 scaling up 怎样接着做？（待验证）

1. **先量重跑波动。** 固定数据切分、完单标签、训练步数和学习率计划，用同一批实际生效的种子复跑各组。保留每次 AUC、logloss、整体与分档校准，再看组间的配对差。
2. **只扩大专家池。** 从 4 专家、Top-2 改为 8 专家、Top-2，保持输入分支、token 数、专家宽度和层数。看新增专家各接到了哪些 token，再量吞吐、显存和时延。
3. **用相近的新增参数试另一处。** 加宽显式交叉分支的内部投影，保持输出 token 形状。与加专家的方案并排记录新增参数、每样本 MAC、实测时延与验证指标，回答同一笔预算给哪一边更划算。
4. **有可重复的改善后，再补规模曲线。** 在有收益的方向加中间档位，先固定训练样本数，再补等训练算力或不同数据量的对照，观察验证 logloss、AUC 和校准如何随规模变化。

> [!example]- 8 专家、Top-2 预计会多出多少参数？
> 按 15161 的结构，一个 48 → 256 → 48 的专家含偏置共 24,880 个参数。4 层各加 4 个专家，专家权重增加 398,080；每层路由器输出从 4 扩到 8，再加 1,040。合计 **+399,120（约 +7.25%）**，预计总量 **5,900,741**。每个 token 仍跑两个专家，路由打分与分发开销可能变化。这是按结构推算的预算，效果和时延还需实测。
