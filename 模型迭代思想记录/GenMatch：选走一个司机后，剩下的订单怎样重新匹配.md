花小猪的一笔乘客需求可能进入多家商家的分单系统。**商家分单**决定给哪位司机派这笔单、采用什么派单模式。商家向聚合平台上报候选司机叫“举手”，**平台 PK** 则在上报的候选中选优。下面讨论的逐步选边发生在商家内部，影响商家会把谁送入后续竞争。

假设 B 单可以给乙或丙，两人的接驾条件很接近。另一笔 C 单原本可以找甲或乙，但甲刚被 A 单选走。此时把乙给 B，C 就失去了最后一位可选司机。B 和乙之间的距离没变，乙承接 B 的概率也可以没变，变化的是**把乙留给另一笔订单的价值**。GenMatch 研究怎样让分单模型看到这种变化。对花小猪，最值得验证的是：沿用 V2 方案的三种派单模式打分和商家 PK 胜率估计，仅在同一批内更新选边顺序，能否改善最终履约？


**第一步怎么验证？** 先从商家 TP 一对一日志重建当时可见的候选，数出首选之后仍争抢同一司机的批次。若这部分流量很小，就没有必要先训练重排模型；有足够竞争时，再做[[#花小猪待验证（尚无收益数字）|冻结原分与逐步重排的同批回放]]。（本地验证未运行。）

## 1. 论文怎样从一批候选生成匹配？

GenMatch 研究滴滴国际网约车业务中的一对一匹配。一次分单的输入是上游召回并过滤后的订单、司机，以及允许配对的关系。下文把一条可行的「订单—司机」配对称为一条边。输出是一组预匹配，每笔订单、每名司机在这组里至多出现一次。

| 模块 | 输入与输出 | 它解决的问题 |
|---|---|---|
| 批次编码器 | 把订单、司机和可行边组成二部图，通过注意力把邻居与竞争信息编码进每条边的向量 | 评估 B→乙时能看见 B 还有哪些司机，以及其他哪些订单也在争乙 |
| 业务价值模型 | 多任务预测司机应答、应答后乘客取消、应答后司机取消，再把这些概率与接驾时间、平台收入、未来价值等送入神经网络，得到每条边的固定业务分 | 即使两对候选应答概率相近，接驾成本和其他业务价值也可能不同 |
| 逐步选边解码器 | 汇总初始、已选、剩余候选和匹配进度，计算每条可行边与当前状态的匹配分，加上固定业务分后选出一对 | 每选一对，屏蔽占用同一订单或司机的边，并更新下一步排序。整个过程都在播单之前完成 |

**从历史记录里学什么？** 假设一批历史上最终完单的配对为 A→甲、B→丙。训练时随机排列这组完单配对。若本次顺序为先 A→甲、再 B→丙，模型就在给定 A→甲后学习提高 B→丙的选择概率。所有仍可选的边都参与这一轮比较。若 B→乙从未播出，它没有应答或取消标签，仍会作为候选与 B→丙竞争。因此历史偏好给谁播单会影响模型；这条记录无法回答换成乙是否也会完单。[论文方法及训练，第 4 节](https://arxiv.org/html/2608.19751v1#S4)

### 论文已有结果（滴滴国际业务）

| 滴滴国际业务实验 | 实验怎样做 | 能得出的结论 |
|---|---|---|
| 离线仿真，A12 | 用 GenMatch 第一步生成的原始分数作为固定边权，交给 KM（最大权重一对一匹配）求解。相对完整 GenMatch，三个城市的完单率分别低 1.79%、1.17%、3.07% | 对这套已学出的分数，逐步更新并选边在仿真中更好。这个对照同时改变了后续打分和求解方式 |
| 线上，替换预测 | 用论文模型预测的应答和司乘取消概率，沿用生产价值公式和 KM。相对滴滴国际原生产基线（原预测、原价值公式、KM），三城总体完单率提升 1.93%，平均接驾时间下降 4.85% | 改善单对候选的预估本身就有业务价值 |
| 线上，替换整套匹配 | 使用完整 GenMatch。相对同一生产基线，完单率提升 3.86%，平均接驾时间下降 1.84% | 完整系统在线上取得更高的完单率增幅；仅替换预测的版本，接驾时间降幅更大 |

线上实验覆盖三个城市，持续 14 天，按一小时时间片交替。表中数字是相对变化。两组线上增幅都以原生产系统为对照。完整模型还同时替换了价值计算和匹配方式，因此不能把两项增幅的差额单独归给逐步重打分。**论文未在线上单独测出“每选一对后重新打分”贡献了多少。** [离线消融，附录 A.2](https://arxiv.org/html/2608.19751v1#A1.SS2) · [线上对照，表 3](https://arxiv.org/html/2608.19751v1#S5.SS4)

## 2. 花小猪商家分单怎样做？

### 文档记录的线上基线

商家召回候选后，用 XGBoost 预测司机取消风险，结合阈值或模式占比划分全指派、半指派和抢单。文档还单列了订单对司机的打分，沿用平台 PK 环节的打分规则。之后由 TP（TopSpeed 贪心）快速选司机，或由 GS（稳定匹配）结合订单侧和司机侧排序做轮次匹配。[商家匹配重构 V2 · §1.2 线上现状](https://cooper.didichuxing.com/knowledge/2199610335356/2209500732798)

### V2 重构方案（全量上线状态未确认）

1. **为每对候选分别估计三种动作。** 对同一笔订单和同一司机，按全指派、半指派、抢单分别取得动作所需的抢单概率、PK 胜率和胜出后的结果概率，包括履约、司取消、乘取消等。
2. **先在同一对候选内部择优。** 将概率、接驾距离、城市时段参数代入业务公式。保留允许动作中的最高分，以及取得该分的派单模式。目标是在完单量与司乘取消约束下，降低 PK 胜出后的平均接驾距离。
3. **再在不同候选之间匹配。** TP 按边分从高到低选，跳过已占用的订单或司机。V2 正文中的 GS 只替换订单对司机的打分，司机对订单的打分保持原口径。选中的边带回已保存的派单模式，进入后续业务链路。

V2 是本文用于比较的设计版本。配套进展记录列有模型训练、离线测算和工程事项，其“测试上线”和“线上实验”栏未填实际完成时间，现有资料不足以确认全量状态。[V2 · §3.2–3.3 模型与在线决策](https://cooper.didichuxing.com/knowledge/2199610335356/2209500732798) · [匹配算法优化 · 规划与进展](https://cooper.didichuxing.com/team-file/2199582756311/2210256066732)

## 3. 两套架构的差异在哪里？

| 观察点 | 花小猪 V2 | GenMatch |
|---|---|---|
| 对每笔候选做什么决策？ | 比较给同一司机采用三种模式的价值，输出司机及模式 | 从可行边里选出下一对司机和订单，论文的动作空间没有区分小猪三种模式 |
| 对竞争建模到哪一步？ | 显式估计商家候选的 PK 胜率；商家内部由 TP 或 GS 处理多个订单争同一司机 | 编码整批候选间的竞争，并在每次选边后估计剩余边与当前状态的匹配程度 |
| 谁决定最终组合？ | 模型输出概率，业务公式形成边权，匹配算法按分数或双方排序组出结果 | 固定业务分与动态状态分共同指导模型逐步生成一组预匹配 |
| 优化效果怎样判定？ | 有明确的距离目标、完单与取消约束，还要观测商家候选经平台 PK 后的履约 | 用历史完单组合和服务行为训练，再在线上看应答率、完单率、接驾时间和 GMV |

**全批竞争**和**平台 PK**是两层不同的决策。前者关心“乙给了 B，商家还能给 C 找谁”；后者关心“商家给 B 提供乙，能否胜过平台收到的其他候选”。两者可以同时进入决策，不能把“乙成了 C 的唯一备选”解读成“乙给 B 的 PK 胜率下降”。

## 4. 花小猪可以怎样借鉴，怎样验证？

本节是花小猪拟议实验，目前没有业务收益数据。两组均以 **V2 的 TP 一对一设计**为起点，使用相同的候选、三模式原分、择优模式和 PK 胜率。**对照组（V2 固定分 TP）**全程按原分选边；**实验组（V2 动态重排 TP）**从第二步起根据剩余候选更新排序。两组首步选择、占用后删除冲突候选的规则均相同。

### 同一张分数表，三种匹配方式

以下数字是构造的业务分，已对三种模式择优。空格表示不可匹配。假设所有列出的边都满足 TP 的选择条件。

| 订单 | 甲 | 乙 | 丙 |
|---|---:|---:|---:|
| A | 99 | | |
| B | | 84 | 82 |
| C | 81 | 80 | |

| 匹配方式 | 在这个例子里怎样选 | 最终配对及原分之和 |
|---|---|---|
| 对照组 · V2 固定分 TP | 先选 A→甲（99），再选 B→乙（84）。甲和乙都已占用，C 无司机可配 | A→甲、B→乙，共 2 对，99 + 84 = **183** |
| 实验组 · V2 动态重排 TP | 同样先选 A→甲。此时乙是 C 的唯一备选。假设将 B→乙的本步排序分从 84 调到 80，B→丙（82）便先被选中，乙留给 C | A→甲、B→丙、C→乙，共 3 对，99 + 82 + 80 = **261** |
| 算法参照 · 固定分 KM | 直接在原分表上最大化整批总分。让 B 从乙换到丙只损失 2 分，却腾出乙给 C，新增 80 分，整批净增 78 分 | 同样配出 3 对，183 − 2 + 80 = **261** |

本例说明动态修正可以帮助贪心 TP 避免过早占用乙。KM 用固定分也能找到这组三对，因为它比较整套分配的总分。表中的 KM 只用于解释算法；花小猪拟议实验比较前两行，以便单独测量重打分。4 分是演示用的排序修正，后文给出算法。从两对到三对多出的是一次预匹配机会，真实完单还取决于播单、举手、平台 PK 和履约。

### 拟议改动：在 TP 一对一匹配中增加动态修正

保留每条边的三模式打分、择优模式和 PK 胜率。在相同原分上增加一个可解释的修正项：

$$
\text{本步排序分}=\text{原始业务分}-\lambda\,\bigl(\text{当前占用代价}-\text{轮初占用代价}\bigr).
$$

一种待验证的占用代价算法是：评估 B→乙时，找出同样可以配给乙的其他订单。对每笔订单，计算“配乙的原分减去失去乙之后的最好备选分”，取最大的正差；没有受影响订单时代价为零。没有其他司机时，使用预先设定、与原分可比的本轮未匹配价值。以示例为例，若未匹配价值取 0，C 在轮初还有 81 分的甲，所以占用乙造成的损失取 0；甲被选走后，损失变成 80。仅作演算，取 λ = 0.05，就得到上述 4 分修正。首步与轮初状态相同，修正天然为零。实际参数和未匹配价值需在留出批次验证。**这是针对花小猪提出的规则，论文使用的是学习式解码器。**

### 花小猪待验证（尚无收益数字）

| 阶段 | 怎么做 | 怎样读结果 |
|---|---|---|
| 判断覆盖面 | 从真实 TP 日志重建决策当时可见的完整候选，统计首选后仍有竞争的批次占比，以及有订单失去重要备选的频率 | 若大多数批次只有一笔订单或剩余边互不争抢，可改善的流量有限。只有已播记录时，需先补候选日志 |
| 同批回放 | 两组使用相同的候选、原分、模式、同分规则、冲突删除和停选规则。对照组冻结原分，实验组更新排序分。记录首选一致率、首次分歧、受影响的备选、最终匹配集合和额外耗时 | 首选须一致。区分“只是选择顺序变化”和“最终配对变化”。回放能核对机制，历史未播候选的真实履约仍未知 |
| 线上时间片实验 | 在共享司机池内交替运行上述两种 TP，对同一城市和时段做好分层，按全部实验流量和分配时间片评估不确定性。预先约定完单、取消的可接受边界及延迟预算 | 主看 PK 胜出后平均接驾距离是否下降，同时核对整体完单量、司乘取消和匹配耗时。结合 PK 胜出量、匹配量检查距离改善是否主要来自少匹配或少胜出 |
| 决定是否学习状态分 | 若动态修正确实改变最终配对，且线上业务结果满足目标，再用同样的 TP 对照比较“规则修正”和“学习式修正” | 可以区分逐步重排本身的价值，以及用模型学习修正项的额外价值 |

第一轮选择 TP 一对一，是因为这里原本就逐对贪心选择，容易只改变一个条件。GS 同时使用两侧排序，抢单一播多又允许一笔订单面向多名司机，直接套用上例会改变实验问题。推广这种方法的前提是：确实存在共享且稀缺的候选，先做的决定会改变后续机会，而且这些变化在决策当时可以观测。[花小猪的业务约束与时间片实验设计](https://cooper.didichuxing.com/knowledge/2199610335356/2209500732798)
