# 搜广推全链路：从日志到一次决策

> 这篇不是某个模型，而是一张系统地图。面试系统设计时，先用它定位：**数据在哪里产生、候选怎样生成、哪层模型在做什么、结果怎样回流与验证。**

## 1. 一次请求的在线链路

~~~text
请求（用户、Query/场景、设备、时间、地域）
  → 合规/库存/定向过滤
  → 多路召回
  → 合并、去重、配额与粗排
  → 精排预估（CTR/CVR/价值/风险）
  → 重排（多样性、预算、体验、生态约束）
  → 广告拍卖 / 推荐展示 / 搜索结果返回
  → 曝光、点击、转化、取消、停留等日志
~~~

推荐、搜索、广告共享这条大骨架，但当前请求和最终决策不同：

| 场景 | 当前请求核心 | 最终决策 |
|---|---|---|
| 推荐 | 用户、场景、上下文 | 排哪些内容/商品 |
| 搜索 | Query、用户、意图 | 哪些文档/商品最相关 |
| 广告 | 用户、广告位、广告主约束 | 哪个广告展示、以什么价格/节奏投放 |
| 营销 | 用户、活动、预算、券档 | 是否触达、给哪种激励 |

## 2. 离线数据：训练样本不是把日志直接拼起来

离线样本要先定义四个锚点：

1. 样本单位：一次曝光、一次请求、用户—候选对，还是一次发券机会；
2. 预测时点：所有输入必须在这一刻可观察；
3. 标签窗口：点击、1 日转化、7 日完单等；
4. 候选空间：线上进入精排的候选，而不是任意全量物品。

### 2.1 典型表与 join 原则

~~~text
行为日志：曝光、点击、转化、订单
实体维表：用户、物品、广告、商家、司机/乘客
上下文快照：时间、地域、供需、页面、Query
策略日志：召回源、旧模型分、位置、实验桶、出价
~~~

join 的第一原则是 as-of join：特征记录的产生时间必须不晚于样本预测时刻。未来统计量、最终履约字段、后续策略结果不能回填进历史特征。

## 3. 特征平台：离线与在线为什么经常不一致

同一个“近 7 天点击数”若离线按自然日聚合、线上按滚动 168 小时计算，模型离线再好也可能失效。一个完整特征定义至少包括：

- 实体主键与事件时间；
- 窗口、聚合方式、去重规则；
- 缺失值与默认值；
- 分桶/词表/归一化版本；
- 新鲜度 SLA；
- 离线回放与在线服务的实现位置。

上线前应用同一批请求做逐字段对账：覆盖率、空值率、均值/分位数、top 类别、序列长度和最终模型分数都要比较。

## 4. 多路召回、粗排与精排的分工

| 层 | 典型候选规模 | 目标 | 常见方法 |
|---|---:|---|---|
| 召回 | 百万/亿级 → 千级 | 高覆盖、低延迟 | ItemCF、双塔、MIND、倒排、热门 |
| 粗排 | 千级 → 百级 | 低成本过滤明显无关项 | 轻量 DNN、LR/GBDT、蒸馏模型 |
| 精排 | 百级 → 数十级 | 精细估计用户—候选价值 | DeepFM、DIN、Transformer、MMoE |
| 重排 | 数十级 → 展示位 | 全局列表价值与约束 | 多样性、配额、预算、规则/优化 |

每层不应重复做完全相同的事：召回优先 coverage，精排优先精度，重排处理列表级和业务约束。若精排再强却收不到正样本，先要查召回。

## 5. 重排：为什么逐 item 分数不等于最终列表

精排通常输出每个候选的独立分数，但首页/搜索页/广告位是一个列表。直接按分数取 Top-K 可能导致同类目扎堆、同商家过多、预算快速耗尽或用户体验下降。

常见重排目标可抽象为：

$$
\max_{S\subseteq \mathcal C}
\sum_{i\in S} v_i
\quad
\text{s.t. }
\text{budget},\ \text{diversity},\ \text{inventory},\ \text{policy constraints}.
$$

实现可以是规则、MMR、贪心、整数规划近似、拉格朗日调权或 RL；关键不是算法名称，而是要说明约束谁定义、怎样监控、不可满足时怎样降级。

## 6. 反馈回流：日志不是天然真相

曝光、点击、转化、取消等日志要做到 request ID / trace ID 可串联，并明确：

- 曝光是否真的送达、是否被可见；
- 点击/转化的去重与归因窗口；
- 位置、旧策略分和实验桶是否被记录；
- 延迟标签何时成熟；
- 失败、超时、过滤是否有日志。

否则无法区分“模型没效果”“候选没到”“服务超时”或“标签口径变了”。

## 7. 线上实验与监控

离线筛选后，常见验证链路是：

~~~text
时间外离线测试
 → 关键人群切片与概率校准
 → shadow / 回放对账
 → 小流量 A/B
 → 扩量与长期指标
~~~

线上既要看主指标，也要看护栏：

| 类别 | 例子 |
|---|---|
| 业务 | CTR、CVR、GMV、完单、增量收益 |
| 用户体验 | 停留、跳出、投诉、重复/多样性 |
| 商业约束 | CPA、ROI、预算消耗、广告主覆盖 |
| 系统 | P50/P95/P99、QPS、超时、特征空值、回退率 |
| 数据 | 标签延迟、特征新鲜度、分布漂移、SRM |

## 8. 常见故障如何定位

### 离线 AUC 涨、线上无收益

按顺序查：预测时点/泄漏 → 特征线上线下一致性 → 候选与流量分布变化 → 概率校准 → 价值函数/重排/预算策略 → 实验统计功效。不能跳过前几步直接否定模型。

### 精排指标差

先拆分成：召回是否覆盖正样本、标签是否成熟、负样本是否贴近线上候选、特征是否缺失、模型是否训练充分。精排只能在进入它的候选上工作。

### 新模型时延过高

分解特征读取、Embedding lookup、模型计算、序列化、RPC；若主要耗时在特征服务，压模型可能收效有限。可考虑缓存、batch、量化、蒸馏、减少候选/序列长度和多级级联，但必须重新评估业务损失。

## 9. 一分钟系统设计回答

> 我会把系统拆成离线数据、在线候选、分层排序、列表决策和反馈闭环。离线先以预测时点构造样本，保证特征可见性；线上由多路召回保证覆盖，粗排控制成本，精排估计 CTR/CVR/价值，重排处理多样性、预算和体验约束。最后用曝光到转化的全链路日志做时间外评估、线上线下一致性对账和 A/B 验证，并同时监控业务、系统和数据护栏。
