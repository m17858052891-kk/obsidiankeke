# 深度解析：MIND 多兴趣召回网络与动态路由

在 MIND 诞生之前，业界主流的召回模型（如 YouTube DNN, DSSM, GRU4Rec）都有一个固有的执念：**不管用户的行为多复杂，最后都要把用户压缩成“一个” D 维向量。**

# 1. 痛点：单向量表达的“四不像灾难”

假设一个用户在淘宝上既是个“硬核数码控”，又是个“美妆达人”。 他的历史行为序列是：`[机械键盘, 显卡, 口红, 粉底液]`。 如果强行用 Average Pooling 或者是普通的 Attention 把这些商品向量融合成**一个** User 向量，这个最终的向量在多维空间中，会落在“数码”和“美妆”这两个完全不搭边类目的中间地带。 去线上向量库（如 Faiss）检索时，模型会拿着这个“中间态”向量去算距离，结果召回了一堆莫名其妙的商品（比如：带有键盘图案的化妆盒？）。**单一向量严重抹杀了用户兴趣的多样性。**

MIND 的核心思想就是：**用** $K$ **个不同的向量（兴趣胶囊），去分别代表用户的** $K$ **个独立兴趣面。**

# 2. 核心魔法一：动态路由机制 (Dynamic Routing - B2I)

MIND 借用了 Geoffrey Hinton 提出的胶囊网络（Capsule Network）中的动态路由算法。MIND 将其改造为 **B2I (Behavior-to-Interest)** 路由。

**目标：** 将 $N$ 个散乱的用户历史行为向量 $e_i$，通过一种可导的、无需真实标签的“聚类”方式，分配到 $K$个兴趣胶囊 $v_j$ 中。

**迭代流程（通常迭代 3 次）：**

1. **初始状态：** 假设行为 $i$ 和 兴趣桶 $j$ 之间的路由权重（Logits）为 $b_{ij} = 0$。
2. **计算分配比例 (Softmax)：** 对每个行为，计算它分配给各个桶的概率 $c_{ij}$：

    $$c_{ij} = \frac{\exp(b_{ij})}{\sum_{k=1}^K \exp(b_{ik})}$$
3. **桶内加权求和 (聚合)：** 每个桶收集分配给自己的行为，计算出一个临时的向量状态 $z_j$：

    $$z_j = \sum_{i=1}^N c_{ij} \cdot W \cdot e_i$$

    _(注：_$W$ _是一个可学习的线性映射矩阵，用于把行为空间映射到兴趣空间)_

4. **Squash 激活 (胶囊的灵魂)：** 这是普通神经网络里没有的。胶囊网络认为，**向量的方向代表特征（是什么兴趣），向量的长度代表概率（这个兴趣有多强）**。因此必须用 Squash 函数把向量长度压缩到 $(0, 1)$ 之间，而不改变它的方向：

    $$v_j = \operatorname{Squash}(z_j) = \frac{\vert{}\vert{}z_j\vert{}\vert{}^2}{1 + \vert{}\vert{}z_j\vert{}\vert{}^2} \frac{z_j}{\vert{}\vert{}z_j\vert{}\vert{}}$$
5. **更新路由权重 (反馈)：** 既然兴趣桶 $v_j$ 的状态更新了，我们回头看看哪些行为 $e_i$ 和当前的桶最相似。用点积计算相似度，并累加到 $b_{ij}$ 上：

    $$b_{ij} = b_{ij} + e_i^T \cdot W \cdot v_j$$

    _(直觉：如果某个商品和 1 号桶特别像，下一轮它分配给 1 号桶的权重就会猛增。)_

**经过 3 轮循环，原本杂乱的序列，自动完成了“物以类聚”，变成了 3 个纯粹、互相正交的兴趣胶囊。**

# 3. 核心魔法二：Label-Aware Attention (靶向训练)

前向传播搞出了 $K$ 个向量，但在反向传播算 Loss 时，模型遇到了麻烦：**我该拿哪个向量去和 Target 商品（用户真实点击的下一个商品）算 Loss？** 如果把 $K$ 个向量加起来去算，那又退化成了“单向量平均值”，之前的动态路由就白做了。

MIND 提出了极其巧妙的 **Label-Aware Attention (标签感知注意力)**： 在训练阶段，直接拿 **Target 商品的 Embedding (**$e_{target}$**)** 作为 Query，去和 $K$ 个兴趣胶囊（Keys/Values）做 Attention。

$$p_j = \operatorname{softmax}(v_j^T \cdot e_{target})$$$$v_{user} = \sum_{j=1}^K p_j \cdot v_j$$

**物理意义与“赢者通吃”效应：** 假设目标商品是“显卡”。它去和 3 个桶算相似度，发现 1 号桶（数码桶）相似度极高，2 号桶（美妆）和 3 号桶（零食）极低。 那么 $p_1 \approx 1$。反向传播时，**计算 Loss 的梯度会几乎全部顺着 1 号桶回传**。 这就是靶向训练：**“谁最匹配，谁就主导学习”**。这逼迫 1 号桶更加专注地学习数码特征，2 3 号桶完全不被干扰，从而保证了多个向量真正做到了“术业有专攻”。

# 4. 线上工程落地 (Serving)：如何用多向量查库？

训练完了，用户现在真的来了，线上系统是怎么用这 $K$ 个向量的？ 在线上推理（Inference）阶段，是没有 Target 商品的（因为这就是我们要预测的东西）。

**做法：**

1. 用户一登录，模型立刻根据他的实时历史，跑完动态路由，吐出 $K$ 个（比如 3 个）兴趣向量：$V_1, V_2, V_3$。
2. **并发请求 Faiss：** 线上召回系统**同时**拿着这 3 个向量，去商品向量库（如 Faiss / HNSW）里做 Top-N 近邻搜索。
    - $V_1$ 搜出了 50 个数码产品。
    - $V_2$ 搜出了 50 个美妆产品。
    - $V_3$ 搜出了 50 个零食产品。
3. **合并打分与去重 (Merge & Deduplicate)：** 将这 3 路召回的 150 个商品合并。如果有重复商品，可以取最高分或者分数相加。最后截断取 Top-100 送给下游的粗排/精排模块。

**总结：** MIND 不仅在算法层面打破了单向量瓶颈，在工程架构上也极其优雅地契合了分布式向量检索的范式。它的诞生，直接开启了推荐系统“多兴趣召回（Multi-Interest Retrieval）”的新纪元。
