# 搜索相关性、混合召回与 Query 理解

> 推荐是在“系统主动找内容”，搜索是在“用户带着显式 Query 找结果”。两者可共用召回—排序架构，但搜索必须额外回答：Query 表达的意图是什么、结果为什么与 Query 相关、词不完全一致时怎样找回。

## 1. 搜索的一次请求怎样走

~~~text
Query 规范化
  → 意图识别 / 改写 / 拼写纠错（可选）
  → 词法倒排召回 + 语义向量召回 + 规则召回
  → 合并、去重、过滤
  → 粗排与精排：Query-Doc 相关性 × 个性化 × 业务价值
  → 重排：多样性、时效性、地域/库存、广告规则
  → 展示与点击日志回流
~~~

Query 是实时输入，不能只依赖用户历史。即使同一用户过去偏好某类商品，本次搜索“儿童安全座椅”时，Query 意图通常应是强信号。

## 2. Query 理解：先确定用户可能在找什么

基础处理包括：

- 规范化：大小写、全半角、单位、同义写法；
- 分词/实体识别：品牌、品类、地点、型号、人名等；
- 拼写纠错：把明显错误映射到候选 Query；
- Query 改写/扩展：补充同义词、别名、上位/下位概念；
- 意图识别：导航型、信息型、交易型，或具体业务类目意图。

每一步都有风险。例如把“苹果手机壳”错误改写为“苹果水果盒”，会提高某些 lexical 匹配却伤害真实相关性。改写应有置信度门槛，并保留原 Query 通道，不能不可逆地覆盖原始输入。

## 3. 词法召回：BM25 为什么仍然重要

倒排索引记录每个词出现在哪些文档/商品中，因此能在高吞吐下做精确匹配。BM25 是经典词法相关性函数：

$$
\operatorname{BM25}(q,d)
=
\sum_{t\in q}
\operatorname{IDF}(t)
\frac{f(t,d)(k_1+1)}
{f(t,d)+k_1\left(1-b+b\frac{|d|}{\operatorname{avgdl}}\right)}.
$$

其中 \(f(t,d)\) 是词频，\(|d|\) 是文档长度。直觉是：稀有词更有区分力；同一词多次出现有收益但会饱和；过长文档不能仅因词多就占优。

词法召回优势是可解释、精确匹配强、更新快；不足是无法自然处理同义词、语义相似和词序变化。

## 4. 语义召回：Query 与 Doc 也可用双塔匹配

语义双塔分别编码 Query 与文档/商品：

$$
q=f_\theta(\text{Query},\text{context}),
\qquad
d=g_\phi(\text{Doc fields}),
\qquad
s(q,d)=q^\top d.
$$

训练可使用点击、购买、人工标注相关性或 query-document 对比学习。线上将文档向量建 ANN 索引，对实时 Query 向量检索近邻。

它能找到“无线耳机”与“蓝牙耳塞”这类词面不同、语义接近的结果；但也可能召回语义相近却交易意图不符的内容。因此搜索一般不是用语义召回替换倒排，而是做混合召回。

## 5. 混合召回与融合

常见做法：

1. 倒排召回保证精确词/品牌/型号覆盖；
2. 语义 ANN 召回补足同义、长尾和改写不足；
3. 热门、地域、库存、垂类规则提供业务覆盖；
4. 候选合并、去重，保留每一路来源和分数；
5. 交给 Query-Doc 精排模型做最终判断。

融合不是机械加分。倒排分数、向量相似度和业务热度尺度不同，应归一化、作为特征交给 ranker，或通过学习到的 gate 按 Query 类型决定各路权重。

## 6. 精排相关性：相关不等于点击，也不等于商业价值

精排输入通常包括：

- Query 特征：词、实体、长度、意图、改写置信度；
- Doc/Item 特征：标题、类目、品牌、价格、库存、时效；
- Query—Doc 交叉：词匹配、BM25、语义相似度、类目一致性；
- 用户与上下文：历史兴趣、地域、设备、时间；
- 反馈/质量：点击、转化、停留、投诉、商家质量。

可用 pointwise CTR/CVR 预估、pairwise 排序损失或 listwise 目标。若训练标签只有点击，模型容易把位置、标题党或旧排序偏好当成相关性，因此要记录位置、曝光策略并结合人工相关性标注或去偏流量。

一个常见而不应被误读的最终分数形式是：

$$
\operatorname{final\ score}
=
\operatorname{relevance}
+\lambda_1\operatorname{personalization}
+\lambda_2\operatorname{business\ value}
-\lambda_3\operatorname{risk}.
$$

这里权重代表产品取舍；不能只因 CTR 高就牺牲强 Query 相关性。

## 7. 搜索广告的特殊性

搜索广告至少有两层相关性：

1. 广告是否与 Query/意图相关；
2. 在相关广告中，结合 bid、预估点击/转化、质量和预算如何竞价。

因此广告 rank score 不能只用 bid × pCTR；Query—Ad 相关性与质量通常也应成为约束或因子。否则高价但不相关广告短期可能赢得展示，长期会损害用户体验和点击质量。

## 8. 搜索评估

离线相关性常看人工标注的 NDCG、MRR、Recall@K；行为指标可看 CTR、长点击、停留、转化。它们回答不同问题：

| 指标 | 更接近什么 |
|---|---|
| NDCG / MRR | 相关结果是否排在前面 |
| Recall@K | 召回是否覆盖标注/未来正样本 |
| CTR | 用户是否点击，受位置与样式影响 |
| 转化/GMV | 业务价值，受价格、库存、履约影响 |

一个搜索模型若 CTR 涨、人工 NDCG 跌，应警惕标题党或位置偏差；不能仅凭点击结论认定相关性更好。

## 9. 高频面试问答

### 为什么搜索不能只用推荐模型？

推荐可主要依赖用户历史和上下文，搜索还必须满足用户当前明确表达的约束。推荐模型可能把“用户平时爱看什么”排得很高，却忽视本次 Query 的品牌、型号或地点要求。

### BM25 和向量召回谁更好？

不是替代关系。BM25 对精确实体、型号和可解释性强；向量召回对同义、语义泛化和长尾 Query 更强。通常用混合召回，再由精排学习取舍。

### 如何判断 Query 改写是否值得上线？

离线看改写覆盖率、人工语义正确率、对召回和 NDCG 的增益；线上看 Query 改写触发人群的 CTR、长点击、改写后再次搜索率和负反馈，并设置回退到原 Query 的机制。不能只看改写后召回量变大。
