# ItemCF：协同过滤召回

> ItemCF 根据“被同一批用户共同交互过”的程度计算 item 相似度，再用用户最近交互的 item 为种子召回相似 item。

## 1. 基本思想与公式

对物品 $i,j$，常见共现相似度可写成：

$$
\operatorname{sim}(i,j)=\frac{\sum_{u\in U(i)\cap U(j)}w(u,i,j)}{\sqrt{|U(i)|\cdot|U(j)|}}.
$$

其中 $w$ 可加入时间衰减、行为类型权重等。对用户 $u$ 的候选物品 $j$：

$$
\operatorname{score}(u,j)=\sum_{i\in\mathcal H(u)}w_{u,i}\operatorname{sim}(i,j).
$$

## 2. 热门污染与常见修正

热门物品会与很多 item 共现，可能把所有候选都带向热门。常见处理包括：

- 用户活跃度惩罚：高活跃用户的一次共现权重更低；
- 时间衰减：近期行为权重更高；
- item 热度平滑/惩罚；
- 类目多样性重排，避免候选被同类热门 item 挤满。

## 3. 边界

ItemCF 便宜、可解释、适合短期兴趣召回，但不直接理解候选上下文、长程兴趣或冷启动语义；通常与向量召回、内容召回、序列召回并行使用。

## 4. 离线相似度表怎样构建？

```text
行为日志 → 按用户/会话排序 → 生成同窗口 item 对 → 按行为、时间、活跃度加权共现
→ 聚合得到 co-occurrence → 热度归一化/截断 → 每个 item 保留 Top-K 相似邻居
```

不是把一个用户全历史中的任意 item 两两配对：长历史用户会产生 $O(n_u^2)$ 对并放大热门污染。常见做法是限制时间窗口、最大序列长度或会话边界，并给超活跃用户较低权重。

线上对用户近期种子 item 查 Top-K 邻居、累加分数、过滤已交互和不可用 item、做去重/多样性重排。相似度表按天或更高频增量更新；新 item 没有共现时需回退到内容、热门或探索召回。

## 5. 召回如何评价？

离线可按时间切分，用未来真实交互验证 Recall@K、HitRate@K、Coverage、类目多样性和分人群表现。只看 Recall 可能让热门 item 占满候选，因此需要同时监控新颖性、长尾覆盖和后续粗排/精排的承接收益。

## 6. 面试回答

> ItemCF 用用户/会话内共现计算 item 相似度，再从用户最近交互的种子 item 扩展邻居召回。工业上关键不是公式本身，而是离线共现窗口、热门与高活跃用户惩罚、Top-K 相似表、增量更新、已购过滤与多路召回合并。它强在便宜和短期相似兴趣，弱在冷启动、上下文和长程语义，所以通常作为多路召回之一。
