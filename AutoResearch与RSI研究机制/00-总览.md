# AutoResearch 与 RSI 研究机制

整理日期：2026-11-18

这组思考面向未来可能建设的自动模型研究与迭代系统，借鉴前人的经验，明确哪些问题需要先解决：下一轮实验由什么决定，经验如何影响决策，错误经验如何被纠正，以及离线研究怎样服务线上目标。

## 定位与用途

这里分析的 AutoResearch Skill 是他人在因果推断方向上的参考案例，不是我正在使用或准备直接改造的项目基础。阅读它的目的，是从具体做法、局限和验证缺口中提炼未来需要做的事情，而非把修补这份仓库当作自己的建设任务。

未来系统的业务问题、技术框架、模型类型和评估指标仍需独立确定。六档券额、MTAUCC、特定网络及目录规范属于这个案例的具体选择，不自动继承；因果推断也是参考案例的方向，不预设未来系统只能研究因果模型。

当前判断是：这个 Skill 最有价值的地方，是要求实验前提出可证伪假设，实验后用完整结果修正下一步；主要不足是这些要求仍大量依赖 LLM 执行，尚未通过独立行为评估证明它能稳定提高研究效率。仓库已有知识资料，问题更集中在知识的适用判断、实验选择和经验纠错。

## 六个问题对应的判断

1. **怎样避免沿已有方案持续优化**：已有多分支搜索和候选档案等公开研究；需要让不同机制的假设竞争，不能只增加同一路线的实验次数。
2. **研究计划从哪里来**：Codex 根据用户目标、数据和基线填写模板；主计划相对稳定，状态、逐轮结果和经验增量更新。
3. **复盘和先验错误怎么办**：区分观察事实、机制解释和行动建议；经验必须带条件、证据与撤销机制，其作用也需要对照验证。
4. **怎样在模型模块之间切换**：先判断可用信息与实验有效性，再用对照实验区分编码、交互、表示、输出头和损失等瓶颈，不能靠指标变化直接归因。
5. **知识应该限制还是参考**：数据定义和评估协议约束当前实验；论文方法提供候选；项目经验是有条件、可被新证据推翻的依据。
6. **离线迭代怎样避免偏离线上目标**：训练损失、离线选模指标与线上业务目标可以不同，但需要建立并检验它们之间的联系；还要核对决策、样本、特征和约束的一致性。离线改善不能自动视为线上收益。

## 未来需要明确的事情

先界定业务目标和模型实际参与的决策，再建立可信的离线评估与线上反馈联系；在这个基础上，确定可探索的模块、候选假设的选择方式、知识和经验的更新规则，以及如何验证研究机制本身有效。

这是一组需要逐步回答的问题，不是已经选定的实现方案。受控线上验证可以用于校准离线选择，并不要求 Agent 直接在生产环境持续修改模型。
