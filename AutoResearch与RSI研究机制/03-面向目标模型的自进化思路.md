# 面向目标模型的自进化思路

整理日期：2026-11-18

[返回总览](00-总览.md) · [自动研究的关键问题](02-自动研究的关键问题.md)

面向某个明确目标的模型，自进化可以理解为：把“诊断问题—提出方案—训练验证—决定下一步”形成由证据驱动的循环，持续改进模型方案和实验选择。研究器本身可以先保持固定。

这里提炼的是未来自动模型研究系统可以借鉴的思想，不预设模型类型、业务指标或实现框架，也不把参考 AutoResearch Skill 当作自己的项目基础。以下方向尚未据此实施实验。

## 1 先明确进化对象

常规训练负责学习模型权重；自动研究需要进一步选择特征、结构、损失函数和训练方案。模型在任务上变好，与负责研究它的系统变得更会研究，是两个层次。

| 层次 | 改变什么 | 怎样判断成功 |
|---|---|---|
| 目标模型迭代 | 特征、结构、损失、训练方法及学习得到的权重 | 在约定约束和独立评测下，目标模型获得可靠改善 |
| 研究机制改进 | 问题诊断、候选生成、实验选择、预算分配和经验使用 | 相同研究预算下，更稳定地找到好模型，或以更低成本达到同样效果 |

目标模型预测更准，通常不会自动使研究器更擅长提出下一轮方案。可以先用固定研究器改进模型，等实验选择或研究流程成为明确瓶颈，再检验修改研究机制是否值得。无需先实现 Agent 的递归自我改进。

## 2 六个可以借鉴的思想

| 思想 | 在目标模型迭代中怎么用 | 必须保留的条件 |
|---|---|---|
| **目标固定，方案可变** | 明确业务目标、模型用途、评估口径和资源约束；允许探索特征、结构、损失与训练方法 | 协议变化后重新建立可比基线，不能为了让当前候选通过而修改指标 |
| **用诊断产生假设** | 根据误差切片、学习曲线、特征覆盖和实现检查定位问题，再提出候选修改 | 每个假设说明支持证据、竞争解释和证伪条件；技术失败不等于方法无效 |
| **保留多个研究方向** | 保留不同机制的候选，根据进展和成本调整预算；允许从历史分支继续研究 | 不同超参数组合未必代表不同研究方向，暂时未胜出的分支也可能有后续价值 |
| **用低成本实验筛选方向** | 先做小规模训练、诊断和关键消融，再投入完整训练 | 检验小实验能否预测完整训练的结果；缩小数据或训练预算可能改变方案排序 |
| **用独立证据决定保留** | 搜索使用开发验证数据，最终确认使用未参与选择的数据；检查随机波动、关键切片和约束 | 完整保留失败和全部种子；最终评测反复用于调方案后，就不再是独立确认 |
| **让经验影响下一轮选择** | 记录“什么条件下，什么修改有效或无效”，据此调整候选和实验顺序 | 区分观察、解释和建议；保留反证与撤销机制，避免把一次失败变成永久禁用规则 |

这六个思想可以连成一个循环：

> 目标与约束 → 问题诊断 → 可证伪假设 → 候选模型与对照 → 分层实验 → 判断证据 → 更新模型、经验与下一轮选择。

实验没有涨分也可能有研究价值，例如排除一种解释或发现实现错误；但这些信息最终需要帮助更有效地找到可靠改进，不能只以实验数量、复盘长度或方向数量评价研究质量。

## 3 新架构的思路从哪里来

可以把候选思路的来源概括为：**已有方法知识与当前模型的失败证据相结合，实验再负责筛选和修正。**

已有论文和实现提供结构、归纳偏置及训练方法；当前数据和诊断决定哪些机制值得尝试。单个总指标很难直接指向一种新架构。

例如，某类样本误差偏大，可能来自输入信息缺失、样本稀疏、标签问题、分布变化、训练不足或表达能力不足。需要用检查和对照区分这些解释，再判断是否修改结构。若先入为主地增加模块，即使指标变化，也难以知道改动为什么有效。

新结构的研究价值在于：它针对哪个已识别问题，为什么比其他解释更值得试，以及怎样证明关键机制起作用。生成听起来新颖的模块组合，本身不足以支持模型能力或研究能力提升。

具体诊断、模块切换和知识适用性，见[自动研究的关键问题](02-自动研究的关键问题.md)。

## 4 从 Agent 自改进研究中迁移什么

可迁移性需要按层次判断：实验组织、候选搜索和独立验证有较直接的借鉴价值；具体提示词、工具和记忆实现需要适配；“能够自动发现适合某项业务的新模型架构”仍需任务内证据。以下是方法层面的借鉴判断，不是已经测得的业务收益。

| 参考工作 | 值得借鉴的部分 | 不能直接推出的结论 |
|---|---|---|
| [AIDE² 2026](https://arxiv.org/html/2609.26457v1) | 在受限预算下优化研究搜索与上下文管理，并在独立机器学习工程任务上评估 | 轻量基准上的收益不能直接外推到长周期、大规模训练；流程收益也不等于自主结构创新 |
| [Hyperagents 2026](https://arxiv.org/pdf/2603.19461v2) | 将产生后续改进的方法纳入可修改范围，并检验元层面机制的迁移 | Agent 任务或元机制改善，不直接证明特定目标模型一定改善，也不证明无限加速 |
| [Flex-RSI 2026](https://arxiv.org/html/2611.08946v1#S5.SS4) | 在相同起点和预算等条件下，对照固定流程与允许修改流程的运行，隔离流程修改的额外贡献 | 任务分数上升不能单独归因于研究机制进步，仍需相应对照 |

对训练成本占主导的任务，减少上下文或模型调用不一定带来明显总收益。更值得检验的是能否减少无效训练、提前排除错误方向，以及用更少完整实验获得足够的决策证据。成本应按当前任务实际瓶颈计算。

## 5 怎样验证借鉴是否有效

首先比较模型，再比较研究方法，两种随机性也要分开处理。

| 要验证什么 | 比较方式 | 关注结果 |
|---|---|---|
| 候选模型是否变好 | 固定数据与评估口径，在独立复核数据上与基线比较，检查训练种子和关键切片 | 目标指标、稳定性、推理成本及业务约束 |
| 新研究方法是否更有效 | 从可比基线出发，固定基础 LLM、数据、工具权限和主要预算，多次独立运行完整搜索 | 固定预算内的可靠模型效果、达到约定效果所需成本、无效实验比例 |

同一个最终模型多跑几个训练种子，只能检查训练波动，不能代替多次独立搜索来验证实验选择策略。开发数据上的持续涨分，也不能代替未参与选择的数据上的确认。

如果模型最终服务线上决策，还需检验离线选模依据与实际业务目标的联系。离线改善不能直接记为线上收益；这部分对应关系见[离线与线上目标对齐](02-自动研究的关键问题.md#6-离线迭代怎样避免偏离线上目标)。

建设顺序可以先从可信诊断和评估开始，再引入多方向搜索与成本分配，最后根据瓶颈决定是否研究研究器自身的修改。验收始终围绕一个问题：**同样预算能否得到更好的目标模型，或用更少预算达到同样效果。**
