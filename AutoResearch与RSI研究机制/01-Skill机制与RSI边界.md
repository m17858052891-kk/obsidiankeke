# 因果推断 Skill 的机制与 RSI 边界

[返回总览](00-总览.md) · [继续阅读关键问题](02-自动研究的关键问题.md)

这份因果推断 Skill 是前人经验的参考案例，不是自己的项目基础。本篇核查其做法与证据，是为了辨认未来自动研究系统需要具备的能力；其中的代码缺陷不等于自己的开发待办，特定模型和指标也不构成未来方案的默认选择。

这份 Skill 将因果模型研究组织成一个由证据推动的实验循环。它已经覆盖研究设计、训练评估、复现、经验记录和部署交接；但说明文件规定的流程、参考代码直接具备的功能、实际项目完成的实验，需要分别判断。

核查版本为 `3c42f88d5f93be1fb63bd067aecbaf83ba0829a0`。这份笔记中的仓库结论只对应这一版本。

## 实验循环怎样运行

Skill 要求先确定业务问题、目标和基线，确认数据与环境，锁定评估协议、种子和预算，再进入循环：

> 恢复状态 → 提出当前假设 → 创建独立版本 → 执行训练评估 → 核对全部结果 → 判断假设 → 更新经验和下一步。

实验前要记录触发证据、为何优先、对照、主要改动、固定项、预期、证伪条件与成本。实验后在原记录追加结果，不能事后改写出发点。科学判断区分实现失败、假设被反驳、证据不足和改进得到支持。候选达到目标后，还要重新执行全部种子的训练评估，验证复现后再进入人工选模与归档。[自主实验循环](https://git.xiaojukeji.com/bwh_stg/casual_autoresearch_skill/blob/3c42f88d5f93be1fb63bd067aecbaf83ba0829a0/references/autoresearch.md#L9)

这是一套由 Codex 执行的工作规范。仓库中的训练、推理和部署脚本提供业务参考，并没有把整个研究循环都实现成独立运行、自动检查状态迁移的控制程序。

## 规范落实到了什么程度

| 要求 | 仓库中已有的内容 | 证据边界 |
|---|---|---|
| 多种子完整比较 | 文档要求确认种子列表、固定同版条件、保留失败，不允许挑选最好 seed | 参考训练入口仍固定 `SEED=2222`，项目需适配；现有单种子示例不能证明多种子流程完成 |
| 独立评估与防止反复选择过拟合 | 明确区分训练、开发、候选复核和最终集，要求冻结目标与口径 | 参考入口使用 `test_loader` 选择 checkpoint，随后在该数据上预测评估；该用途属于开发选择，不能据名称视为独立最终检验 |
| 异常指标判无效 | 规范要求保存异常原因，不能填零伪装有效 | 小型检查发现参考指标函数可能正常返回 NaN，需要在实际接入中落实有效性检查 |
| 候选达标后完整复现 | 规定备份首次达标权重，重新运行完整训练和评估，核对容差 | 仓库没有提供完成新任务全部种子复现的证据 |
| 经验影响下一轮 | 提供研究计划、逐轮复盘、经验模板及方向选择规则 | 没有独立 Agent 行为评估证明这些记录能够持续改善实验选择 |

## 最值得借鉴的设计

它最好的地方，是把下一轮实验与上一轮证据绑定起来。一次运行的价值不只在于是否涨分，也在于它能否区分解释、缩小不确定性，或者推翻原来的判断。

尤其值得借鉴三条要求：

1. 假设在实验前形成，预先说明什么结果会使它站不住脚。
2. 实现错误、假设失败和证据不足分开记录，避免把代码没写对记成方法无效。
3. 经验包含适用条件、反对证据和复核条件，被推翻时保留引用关系。

这些要求比单纯增加自动训练次数更接近科学研究。能否发挥作用，仍取决于 Agent 是否实际遵守，以及评估是否可靠。[经验如何改变后续动作](https://git.xiaojukeji.com/bwh_stg/casual_autoresearch_skill/blob/3c42f88d5f93be1fb63bd067aecbaf83ba0829a0/references/autoresearch.md#L37)

## 模型改进与研究机制改进

需要区分三种变化：

| 层次 | 改变的对象 | 可以支持什么结论 |
|---|---|---|
| 业务模型优化 | 特征、网络结构、损失、训练配置、学习得到的参数 | 某个模型在约定数据和评估条件下得到改善 |
| 研究机制优化 | 如何诊断、生成候选、选择实验、调用工具、检索和修正经验 | 相同资源条件下，研究过程更有效率或更可靠 |
| 基础 LLM 改进 | 基础模型的参数、架构或训练过程 | 需要另外的训练与能力评估证据 |

当前 Skill 主要组织第一层，并通过经验记录尝试影响第二层。没有证据表明它在第三层训练或修改 Codex 的基础模型。

研究机制并不只能依赖基础模型参数更新。工具实现、提示、记忆、实验选择策略和工作流的可验证改进，也可能改变一个 Agent 系统的能力。但业务模型指标提高，不能直接证明研究者自身变得更会研究。

RSI 通常指递归自我改进，其术语口径并不完全一致。这里采用一个实际可检验的区别：系统是否修改了产生后续改进的方法，而且后续改进是否由修改后的机制继续产生，并在独立任务或数据上显示更好的研究表现。单纯把总结写进记忆，还不足以证明这种循环成立。

[DGM](https://sakana.ai/dgm/)通过修改 Agent 代码和维护候选档案探索系统改进；[Hyperagents](https://arxiv.org/abs/2603.19461)进一步将完成任务的 Agent 和修改它的元 Agent 放在可编辑程序中，并报告元层面改进的迁移。这些是研究机制本身参与改进的例子，不构成当前 Skill 已达到同样能力的证据。

## 新架构的想法从哪里来

LLM 提出模型结构，一般结合基础模型学到的方法知识、当前提供的论文与实现、业务问题和实验反馈。Skill 内置的模型指南提供 TARNet、CFR、DragonNet、DESCN、OFA、XTNet 和业务 DomainExtractTrans 等参考，但明确不把这些名称当作候选边界。[深度模型指南](https://git.xiaojukeji.com/bwh_stg/casual_autoresearch_skill/blob/3c42f88d5f93be1fb63bd067aecbaf83ba0829a0/references/deep-models.md)

例如，某些券档样本少，可以产生“跨档共享能够降低估计方差”的候选解释；论文提供共享响应曲线或多头结构的实现线索；当前数据则决定这种共享是否带来偏差、是否值得尝试。想法来源于知识和当前证据的组合，实验才判断它是否成立。

因此不能把“生成了一个听起来合理的新架构”直接当作研究能力提升。更重要的是它为什么优先于其他解释，准备怎样证伪，以及失败后会如何改变后续选择。

## 对这个参考案例的不足判断

- **实验选择主要依赖 LLM 判断。** 规范要求有依据的实质改动，也允许低成本区分竞争解释，但缺少经验证的分支保存、探索分配和停滞识别机制。
- **经验是有条件的文本记录。** 模板要求反证与适用条件，但没有证明错误经验会被稳定识别、撤销，或不会在后续摘要中变成硬规则。
- **有效性要求尚未全部变成可执行检查。** 参考代码的边界问题说明，提示规范不能自动替代实际入口中的检查。
- **业务参考有迁移边界。** 六档券额、既定输出和辅助损失、预处理方式，需要结合新任务重新判断适用性。
- **缺少研究机制的对照评估。** 尚不能判断固定 LLM、数据、工具和预算后，Skill 是否比更简单的研究流程得到更多可靠改进。

“容易陷入局部优化”在这里是风险判断，不是已测得的行为结论。仓库明确鼓励结构、损失和表征等实质改动，不能把它描述成只会小幅调参的流程。
