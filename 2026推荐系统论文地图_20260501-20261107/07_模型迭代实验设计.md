# 把论文变成模型迭代实验

[返回总索引](00_总索引.md) · [逐篇收益链路](02_逐篇收益链路与证伪矩阵.md)

以下是基于本库论文提出的实验设计，不是已在你的模型运行的结果。没有现有baseline与业务数据，不能替你设定通用收益门槛或实验天数；先做可识别的最小改动，再按业务最小可接受提升和流量计算样本量。

## 一份可以直接复制的实验单

```text
问题：在哪一步、哪类用户或物品上失败？给出现有诊断数据。
机制假设：改动A → 可测中介M → 排序/候选变化S → 业务结果Y。
来源：论文名、所读版本、表/节；哪些是论文证据，哪些是自己的推断。
替换位置：输入、输出、保留组件、上线边界、回退方式。
对照：旧方案；同容量/同预算简化方案；用于推翻机制的负对照。
固定条件：除本轮主动改变的因素外，控制候选池/数量、标签时间、数据量、参数、训练GPU小时、刷新、业务权重。
离线验收：主任务指标 + 中介指标 + 关键人群反例 + 时间外/物品外划分。
在线验收：系统总业务指标、分母、护栏、随机化单位、实验周期、CI和停止规则。
资源验收：模型推理 + 特征/检索 + 缓存miss + 离线刷新摊销，不只算FLOPs。
否定条件：出现什么结果就承认机制不成立或不值得继续？
记录：全部尝试、失败和未上线结果，避免只留下最优版本。
```

## 实验1：先证明长历史分支确实在学习

关联：[ReST](论文/P5_排序训练与跨阶段协同/ReST_2609_01240.md)、[SequenceO1](论文/P2_时间长历史与记忆/SequenceO1_2609_08443.md)、[UxSID](论文/P2_时间长历史与记忆/UxSID_2605_09040.md)、[DTE](论文/P2_时间长历史与记忆/DTE_2608_16274.md)。

**假设：**当前强统计特征使历史分支梯度不足；辅助监督可以带来独立的转化信息。先固定主干、历史长度、样本和参数，只加训练期序列辅助头。记录每层梯度范数、序列shuffle造成的测试退化、仅近期/仅远期输入的增量，而不是只观察总loss下降。

若梯度变大而时间外GAUC、校准和序列敏感度没有改善，停止把问题归为序列饥饿。若远历史信号确实有效但成本太高，再分别试目标组缓存或user sketch；用真实远历史/跨用户置换远历史对照，确认新增容量不是全部原因。时间模块另做错相位日/周周期，不把更多参数的收益归为时间理解。

**业务桥梁：**在候选不变时，记录哪些候选因长期证据改变次序，分“长期与近期兴趣不一致”用户看有效观看、负反馈及长期活跃。缓存试验必须同时按年龄和miss分层，避免只对命中请求报P99。

## 实验2：确认截断损失，再考虑跨阶段统一

关联：[UniRec](论文/P5_排序训练与跨阶段协同/UniRec_2609_11052.md)、[OneTrans-V2](论文/P5_排序训练与跨阶段协同/OneTrans-V2_2609_28589.md)、[CC Retriever](论文/P5_排序训练与跨阶段协同/CC_Retriever_2609_22441.md)、[UNIQUE](论文/P5_排序训练与跨阶段协同/UNIQUE_2609_23718.md)。

**假设：**好候选在粗排被错误淘汰。现有日志只包含存活候选的精排分，会低估问题。先对被丢弃候选按概率抽样补算精排分，保留抽样概率，估计精排高分候选的粗排覆盖；必要时用有限随机曝光验证精排分本身是否可靠。

第一轮固定召回池和各层K，比较独立融合、联合融合、仅蒸馏，再考虑共享底座。观察“高价值候选存活率”与Kendall/Spearman一致性同时变化。若顺序一致性提高，但真实价值覆盖不变或负反馈变差，很可能只是共同复制了偏差。

**业务桥梁：**固定总流量，分上游来源记录候选→精排→曝光→有效消费/订单。统一服务的收益另记用户编码复用、FP8、融合核、batch变化；以同硬件/P99可承载的模型质量比较，而不是把模型FLOPs下降当成本下降。

## 实验3：区分RL学不动和beam搜不到

关联：[DASO](论文/P4_生成目标对齐与解码/DASO_2608_20611.md)、[RGD](论文/P4_生成目标对齐与解码/RGD_2607_25344.md)、[UniVA](论文/P4_生成目标对齐与解码/UniVA_2605_05803.md)、[OxygenREC-v2](论文/P4_生成目标对齐与解码/OxygenREC-v2_2607_24255.md)。

**诊断A：**按用户统计rollout组内奖励方差、全零组比例、有效梯度覆盖、SID前缀命中。若有广泛全零组，先比较随机引导、静态引导、自适应引导，固定rollout数与训练tokens；监控SFT锚点移除后的遗忘。

**诊断B：**固定生成器，画概率与业务reward二维分布并追踪高值目标在哪层被删。固定最终候选数，比较普通beam、扩大beam、末端重排、前缀价值引导；先在相同端到端算力/时延预算下比较，再报告额外预算的质量曲线，单列reward调用次数与开销。若简单增宽即可追平，复杂value head的收益链应改写为搜索预算补偿。

**业务桥梁：**独立时间窗校准reward，再验证增量候选能否通过既有ranker和产生真实反馈。对训练期未来teacher，学生推理前缀必须只有请求时可见信息，train/validation切分应覆盖特权前缀；不能只证明teacher预测更好。

## 实验4：证明语义信息增量，避免只增加文本和参数

关联：[AKT-Rec](论文/P1_语义表征与稀疏泛化/AKT-Rec_2605_23310.md)、[GALA](论文/P1_语义表征与稀疏泛化/GALA_2607_29213.md)、[RecoReward](论文/P1_语义表征与稀疏泛化/RecoReward_2607_25901.md)、[SARA](论文/P1_语义表征与稀疏泛化/SARA_2609_17639.md)。

**假设：**收益来自内容中的偏好差异。固定编码器、文本长度、特征维度和ranker，比较普通caption、真实理由、随机理由、推荐reward优化描述。对照用户/作者隔离和未来时段，防止记住热门ID或问卷人群。

再做“行为对齐向量×簇迁移”2×2，观察头部保护、尾部估值及交互项。评价不能只用同一个给reward的双塔：A训练、B评估，并用人工grounding检查描述没有为讨好scorer而编造。

**业务桥梁：**匹配曝光类别、作者频次及候选配额后，看新作者/低频作者的有效观看和Hate；若只在老作者有效，不能声称跨作者负反馈泛化。若随机簇同样有效，应优先解释为统计平滑。

## 实验5：把推理、知识、执行成本和刷新分开

关联：[OneReason](论文/P3_意图推理与召回接口/OneReason_2606_06260.md)、[OneLatent / WhisperRec](论文/P3_意图推理与召回接口/OneLatent_WhisperRec_2610_30675.md)、[RPORec](论文/P3_意图推理与召回接口/RPORec_2605_21967.md)、[RecGPT-V3](论文/P3_意图推理与召回接口/RecGPT-V3_2607_15591.md)、[KuaFu](论文/P2_时间长历史与记忆/KuaFu_2609_31045.md)。

至少做两组对照。第一组同教师数据、同训练tokens：直接输出、同长度摘要、显式CoT、latent标记；第二组同执行方式：无理由监督、有理由监督、打乱配对理由监督。这样能区分知识蒸馏与推理时计算。只删latent token看退化，证明token参与任务，不足以证明人类式推理过程。

服务再做模型×刷新频率2×2，记录缓存年龄、触发覆盖、候选配额、同ranker的独占命中。压缩省下的资源若主要用于更频繁刷新，应明确写为成本赋能收益。对端侧意图，把同样输入人为延迟5/30分钟，可以直接检验及时性。

**否定条件：**固定数据、长度和刷新后简单摘要追平，则优先用摘要；训练reward涨而独立ranker/真实曝光不涨，则考虑奖励过拟合。estimated revenue与直接观测消耗分开，不以估计指标代替最终结算收益。

## 实验6：让列表模型证明自己在学交互

关联：[OGR](论文/P6_列表混排与生成架构/OGR_2608_17613.md)、[UGR](论文/P6_列表混排与生成架构/UGR_2610_39426.md)、[OneTrans-GSR](论文/P6_列表混排与生成架构/OneTrans-GSR_2611_04720.md)、[Amazon Playlist Curation](论文/P6_列表混排与生成架构/Amazon_Playlist_Curation_amazon_playlist.md)。

先固定候选集合，比较点分加总RM与列表RM；对列表做换位、同类重复、广告插入、替换一个item等受控扰动，看模型响应是否符合业务。再比较独立Top-K、列表planner、单业务生成后混排、统一混排。这样把“集合更好”和“同集合顺序更好”分开。

如果只需过滤，必须同最终列表长度比较规则、LLM gate和随机等量删除；否则把列表变短带来的收益误归LLM判断。对新slate的RM奖励，用独立时间窗或探索数据复核；训练RM、holdout RM和真实业务三条曲线应同时保存。

**论文已有警示：**GSR的单RM离线奖励更高，但对应线上收益低于ensemble方案。这支持代理分数不是充分验收标准，尚不能单独识别LCB惩罚的因果贡献。长期复购标签必须成熟后评估，不把尚未观察完的用户记为未复购。

## 实验7：探索与多目标控制，先拆量、质和增量

关联：[URED](论文/P7_探索多目标与增量价值/URED_2611_05997.md)、[Uncertainty Calibration](论文/P7_探索多目标与增量价值/Uncertainty_Calibration_2605_17788.md)、[PRL-PUTS](论文/P7_探索多目标与增量价值/PRL-PUTS_2605_16344.md)、[DREAM](论文/P7_探索多目标与增量价值/DREAM_2608_09408.md)、[DragonBandit](论文/P7_探索多目标与增量价值/DragonBandit_2608_10182.md)。

候选回收先匹配池大小与配额，对照1/7/30天，区分供给数量和时间覆盖；风险调分匹配直播年龄和降权数量，做真实risk与桶内打乱risk，区分不确定性与压低新内容。个性化效用权重要与相同全局平均权重比较，避免整体权重漂移伪装成个性化。

跨阶段Agent控制使用相同动作空间、预算和限制，对照规则、分群查表、监督策略器和LLM。若简单策略等效，保留策略接口价值，不把收益归于多Agent智能。

对营销触达，以预测响应和因果增量策略做同预算随机对照，关注原本就会转化的人与可被改变的人。报系统总价值、每千曝光价值、订单、客单价、触达成本和未被触达群的机会成本，不只报某条通道的归属GMV。

## 实验8：评估与研发流程也要有独立验收

关联：[NOVA](论文/P8_评估研发与推荐Agent/NOVA_2606_27243.md)、[Spotify Agent](论文/P8_评估研发与推荐Agent/Spotify_Agent_2609_30297.md)、[ATLAS](论文/P8_评估研发与推荐Agent/ATLAS_2608_30685.md)、[GPBM](论文/P8_评估研发与推荐Agent/GPBM_amazon_gpbm.md)。

NOVA式流程固定GPU训练次数与LLM tokens，对照通用review和语义规则review，分母包含失败轮次；留出新骨干与新schema，检验记忆是否真能迁移。Agent诊断要使用不参与reward的人工留出集，按真实问题基率报告precision/recall，避免在近似平衡测试集上过度乐观。

OPE方法拿已完成AB的策略做盲测：隐藏线上结果选模型，再看符号准确率、排序相关和错误上线率。学习权重/选择超参的日志不能同时作为最终测试；日志不覆盖的动作无法通过更漂亮的估计公式获得事实证据。

最终把“诊断F1”“离线pass”“有效实验率”“入选产物线上收益”分列。它们构成一条研发收益链，不是四个可以互相替代的指标。

## 怎样判断已经足够清楚

读完一篇后，应能不看摘要回答：**改哪一处、输入输出是什么、为什么可能有用、哪个中间指标应变化、最强替代解释是什么、哪一个实验能推翻它。** 若仍只能说“LLM更懂语义”“统一优化更好”“强化学习对齐业务”，说明还没达到可执行层面，应回到该篇具体数据流与证伪段。
