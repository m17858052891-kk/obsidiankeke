# UxSID：按目标语义组缓存长期兴趣

论文：**UxSID: Semantic-Aware User Interests Modeling for Ultra-Long Sequence**。快手，Hongwei Zhang、Qiqiang Zhong、Junfeng Shu、Jiangxia Cao 等；首次 arXiv 2026-05-09，本文依据 v4（2026-10-09）。[日期与版本](https://arxiv.org/abs/2605.09040)；[全文](https://arxiv.org/html/2605.09040v4)。分类：超长行为建模与成本；位置：排序中的长历史特征支路。

## 问题与旧方案

对每个候选都遍历万级历史，target-aware 但成本随候选数和历史长度相乘；SIM/TWIN 先搜 Top-K 再精建模，检索时漏掉的兴趣无法补回；C-Former 把全历史压成少量兴趣，能缓存，但所有候选共用同一份压缩结果，弱兴趣可能被主流兴趣覆盖。UxSID 的关键取舍是把“每个物品独享”的表示降为“同一语义组共享”，同时保留比单个用户向量更细的条件化。

## 方法与数据流

`多模态物品→SID；用户长历史→兴趣锚点；目标SID查询原历史→global→门控SID再查询锚点→local；[global,local]→(UID,SID)缓存→线上排序`。

第一步以多模态业务语义编码、量化获得 SID；工业线上主要用第一层 code。第二步 IAIC 用 K 个可学习查询对全历史作 cross-attention，每个锚点有独立 PFFN，并以正交约束抑制锚点塌缩。第三步显式 semantic probe 用目标 SID 查询全历史得到 global；global 经两层门控网络控制目标 SID 的各维度，再查询压缩锚点得到 local。两支拼接，和用户画像、上下文、候选、短行为共同优化 BCE 加正交损失。公共实验 16 个锚点；全历史不是在线重算。

训练后预计算 user×SID 表征，线上从 Embedding Server 点查，再与具体候选轻量交互。O(1) 指相对历史长度的在线查表，不能解释为整个系统不消耗长期历史计算、存储和刷新资源。附录 A 称约 4 亿用户、每用户 100 个活跃 SID、2.56 TB；附录同时给缓存向量形状[2,32]；按全覆盖、64维逐元素存储计算，2.56 TB隐含约1字节/维，而BF16/FP32裸值分别约5.12/10.24 TB，文中未明确对应的量化或压缩条件。因此仍须按真实精度、副本、key和稀疏覆盖重新预算，不能直接复抄。该附录给出的刷新周期为每周一次。

## 收益链路：事实与推断

**事实**：目标SID条件化、两级probe消融与AUC改善；缓存把长历史计算移出在线；上线收入提升。**机制推断**：共享语义组让低频候选复用同类长期兴趣，而门控避免不同用户对同一SID产生相同激活→候选转化概率估计更有区分度→有限曝光下高价值候选上移→收入提高。收入增幅超过曝光增幅与此一致，但不是对“高精度转化”机制的单独因果证明，也可能含出价、广告组合和曝光结构变化。

## 迭代与可证伪实验

1. 假设收益来自目标条件化而非额外缓存容量。固定SID、参数、缓存字节及刷新频率，对比user-only、随机组、真实SID组；测长尾/跨兴趣请求的AUC、精排Top-K命中和组内方差。若随机组同样有效，语义条件化解释受否定。
2. 假设离线共享不会吃掉快速兴趣变化。把缓存年龄分桶，在同预算下比较每日/小时/行为触发刷新；实时短历史单独关开。若收益只在新缓存且新兴趣人群下降，应优先做增量更新与miss回退，而非继续扩长历史。
3. 最小接入：仅替换现有长序列分支，保留短期序列、排序头、融合和候选集；记录缓存命中率、p99、每千请求离线成本，再做小流量收入与负反馈联合检验。

## 关系、局限与核验

与SIM/TWIN/C-Former是同位置替换；与SARA、RecoReward是不同信息来源，可先以附加特征互补；与OneReason、R2QRec候选生成不可直接按AUC/Recall比较。关键局限是SID质量、组内异质性、缓存时效、未命中组和容量计算。**doublecheck**：已核v1/v4日期、机构、表1/2/3/4与附表8；已区分绝对AUC差和相对业务增幅、1k主实验和10k扩展；容量与5300 GPU仅论文口径，未独立复现。
