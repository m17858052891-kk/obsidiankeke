# Beyond Item IDs：语义表示与长序列计算一起改

论文：[Beyond Item IDs: Scaling Short-Form-Video Recommendation via Semantic-Native Long Sequence Modeling](https://arxiv.org/abs/2606.07546)。Google 作者团队；SIGIR 2026。日期按 arXiv 页面提交记录 2026-05-04，阅读 v1。编号前缀与页面日期不同，保留原站记录，不自行用编号推导月份；2026-11-07独立重新访问abs仍显示同一v1日期，但不据此做日级优先权判断。这一五月/六月元数据疑点不影响其位于本次时间窗口。[全文](https://arxiv.org/html/2606.07546v1)。

## 解决的问题与旧 pipeline

短视频排序既需要很长的行为历史，又有两种瓶颈：独立 Video ID 难以向新视频迁移且 embedding 表随视频库增长；完整自注意力的成本随序列长度平方增长。SIM/TWIN 类方案先检索或压缩历史，能控制成本，但筛选会丢失信息，离线聚类还增加维护成本。

本工作改的是**排序体系中的行为表示与长序列编码器**，不是用生成式检索替代整条推荐链路。系统保留同步短期模块与异步长期模块，长期向量通过共享骨干和目标与排序空间对齐。

## 方法：输入、模块与输出

1. 上游 RQ-VAE 把视频多模态向量量化为从粗到细的语义码。历史序列只保留前两层组成 bigram，候选及关键非序列特征保留更细层级。历史 embedding 规模由码本组合控制，而非全部视频数量。
2. Temporal Folding 将相邻 $k$ 个历史 token 沿通道拼接，把形状从 $(L,d)$ 改为 $(L/k,kd)$。拼接操作本身不丢输入数值，但会改变后续注意力能区分的时间粒度；不能据此说整个网络“信息无损”。
3. 加入与用户静态画像无关的可学习 Global Query Token，经压缩 Transformer 后与序列输出做带 mask 的平均池化，得到长期用户表示。
4. 同步短期信号仍负责即时兴趣变化，异步长历史负责长期偏好。压缩释放的计算预算可用于增加历史长度和模型容量。

**直观理解：**历史里先用“视频属于哪类语义”代替“某个从没见过的号码”，再把相邻事件打包，让有限算力能看到更远的过去。

## 收益链路：证据与我的判断

**链路A（较强模块证据）：**共享语义前缀 → 新视频可复用已学到的类别偏好 → 新内容打分不再完全依赖孤立ID的曝光积累 → 新内容获得更有效曝光。Table 1 的Freshness支持这一解释；但它不证明全部新视频均受益，也不排除流量分配变化。

**链路B（工程—建模联合）：**缩短注意力序列、缩小表 → 同预算可承载更长历史和更大模型 → 覆盖低频但稳定兴趣 → 满意观看时长提高。成本下降和整体AB均有证据；“低频兴趣覆盖”属于我的中介机制推断，论文没有按该变量做完整因果分解。

**链路C（待验证）：**局部拼接既保留邻近事件又扩大特征维度 → 可能减少局部噪声并改善交互表达。作者有此解释；不能仅由AUC上升断言已证明去噪。

## baseline、替换与互补关系

与 TIGER 共用RQ-VAE/SID思想，但TIGER以SID生成物品，这里主要以SID编码历史；两者不是同一任务的直接替换。与SIM/TWIN可在长期编码入口形成替换；与短期实时序列、候选交叉注意力、下游多任务头可互补。与长序列系统论文比较时必须对齐长度、宽度、算力和特征集。

## 如何迭代及证伪

- **假设1：收益主要来自冷启动泛化。**固定序列长度与网络，比较Video ID、SID、ID+SID；按物品年龄和曝光桶报告AUC、满意观看、召回覆盖。若收益仅集中于高频老物品，冷启动解释不成立。
- **假设2：长历史而非加参数贡献了主要线上收益。**做历史800/2000 × 原容量/扩容量的2×2实验，固定总训练token或同时报告计算差异；观察远期历史被遮蔽后的衰减。
- **假设3：Folding不依赖破坏时间分辨率。**固定预算比较$k=1,2,4,6$，加入相邻事件打乱对照。若短期意图突变场景显著变差，应保留高精度短序列分支。

最小落地先做同长度表示替换，再做Folding，最后把省下的预算用于更长历史。不要一步全部更换，否则难定位收益来源。
