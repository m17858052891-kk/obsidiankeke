# RecGPT-V3：记忆、混合标识与潜在推理共同降低意图召回成本

- 论文：RecGPT-V3 Technical Report；Alibaba淘宝团队。
- 日期/版本：2026-07-17首发，本文依据07-24 v2。
- 一手来源：[版本](https://arxiv.org/abs/2607.15591)、[全文](https://arxiv.org/html/2607.15591v2)。
- 分类/pipeline：长历史重复计算、意图到商品信息损失、推理成本。处于用户理解与意图召回，不是替换全链路排序器。

## 三个旧瓶颈

RecGPT-V2已有多agent意图推理，但每次重复读全历史，无法积累理解；自然语言tag到商品检索是有损接口，同一宽泛标签覆盖大量商品；显式长CoT逐token生成成本高。因此V3不是只增大LLM，而是把“用户状态、商品接口、推理表示”一起改变。

## 方法数据流

**Memory Hub。** 初次把历史聚成记忆单元，每个单元包含行为模式ID、偏好摘要、原行为索引、品牌、时间分布及更新时间。之后仅对新行为涉及的单元重写，保留无新证据单元，为新兴趣建立单元，避免简单追加造成新旧偏好混杂。推理读取记忆+近期行为增量。注意§2.2披露生产增量整理每两个月一次，所以“持续演化”不代表逐请求重写；近期变化由增量输入补足。

**混合词表。** CN-CLIP分别编码图、文及文本化侧信息，经Q-Former融合；共现正对先过滤语义不相似项，再以融合和单模态InfoNCE学习协同表示。两层RQ-VAE，每层32768码字，向Qwen3-14B扩展65536个token。持续预训练用“SID↔商品属性”文本把新符号落地；指令训练做title/tag与SID双向转换、SID序列预测。分别混入约10%/20%通用数据，保护语言能力。生成文本tag和SID结合后进入召回，提高精确落地与开放语义覆盖。

**潜在意图推理。** 先蒸馏teacher显式解释，再以单片段、多片段、全链路重建任务，将长解释内化为最多10个latent token；部署生成紧凑状态和输出，必要时能重建可读解释。随后RLRF用生成tag召回商品、调用现网排序器，取top100预测CTR均值作稠密奖励，并用对齐、多样性和长度门限约束，通过GRPO更新。该奖励是排序预测代理，不是真实CTR、GMV或长期满意度。

## 收益链路与可反驳解释

【事实】记忆带来计算节省，SID混合召回提高命中，压缩保持相近离线质量，整体系统提升线上交易。

【推断】记忆降低每次全历史噪声与计算 → 稳定长期需求仍保留；SID减少tag映射歧义 → 同意图下更细粒度商品进入候选；RLRF将生成候选向现网可接受区域移动 → 更容易通过排序截断 → 转化提升。三者共同上线，不能把3.97%拆成各模块独立贡献；排序模型代理还可能被策略利用其过估区域。

1. **假设：记忆节省来自压缩且不损需求。** 固定总输入token，对照原历史截断、自由摘要和带溯源结构记忆；分兴趣快速转变用户评估漏记/过期偏好、Recall@K及后续订单。若等长自由摘要等价，结构化机制贡献不成立。
2. **假设：SID提供新的商品信息。** 固定总召回数与流量，tag、SID、hybrid互换，计算新增命中、重叠率、曝光后转化；若hybrid只因额外配额获益，则“接口带宽增加”解释不足。
3. **假设：RLRF改善真实相关性而非过拟合排序器。** 用冻结排序器A训练，独立排序器B和人工/小流量真实反馈评估；若A分数涨而B及真实转化不涨，停止扩张代理奖励。

## 接入关系与局限

Memory Hub可先单独接用户理解服务，latent推理适合已有teacher任务，混合SID须管理码本和线上索引版本。与Mobile实时意图互补；DREAM可消费其意图并调整策略；TSGR的query-aware SID针对显式搜索，与V3面向用户状态生成SID不可直接互换。主要限制是私有训练流程、多模块因果归因、两月记忆维护时滞、代理reward偏差和总成本核算口径。已复核日期、版本、表6/8/10/11/13、200倍与3.46倍区别、表9算术疑点。证据质量：A−。
