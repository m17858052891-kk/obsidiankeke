# PAIR：从画像相似改成职业意图互补

[PAIR: Preference-Aligned Intent Retrieval for Premium People Recommendation at LinkedIn](https://arxiv.org/abs/2610.30941)，2026-10-22 v1。[全文](https://arxiv.org/html/2610.30941v1)。

## 动机：相似用户不等于有价值的推荐对象

求职工程师需要招聘者，创业者可能需要投资者。通用画像embedding把相似履历靠近，不能直接表达角色互补。召回一旦漏掉这些人，后续ranker无力补救。本文替换Premium Browsemaps的**人员召回embedding**，同一次线上AB的处理组与对照组使用同一下游排序器。

## 方法：主要变化在监督语义

用历史曝光会话构造“点击候选优于曝光未点击候选”的偏好，每个正例配3个负例；曝光负例不足时补随机活跃用户。目标是多负例对比交叉熵，形式与InfoNCE相同；**不是带reference model的标准DPO**，历史曝光也不能自动消除选择偏差。

画像tower与候选tower共享0.6B编码器，离线生成向量；history tower聚合最近10次点击对象的预计算embedding，采用与query无关的位置注意力。画像和历史分别归一化，再用可学习权重相加并归一化，形成用户检索向量。固定历史窗口更新是$O(Kd)$向量操作，避免重新跑LLM，不是任意历史长度下数学意义的$O(1)$。

Matryoshka联合训练200/256/512/1024维前缀，部署可按成本截断。线上主实验用1024维与历史增强。

## 实验结果及一个必须保留的疑点

| 位置 | 论文报告 |
|---|---|
| Table 1 | Holistic-171 MAR@100 0.288；通用0.6B 0.192；PAIR无历史0.436；加入P-ATT后0.450 |
| §5.3 | 历史带来的增量为0.436→0.450，约3.2%相对；主要提升来自偏好微调 |
| Table 3 | 256维MAR@100 0.432，存储为1024维的25% |
| Table 4，固定下游ranker的AB | CTR相对+7.5%；Premium retention +2.1%，作者标显著；页面延迟+0.1%，覆盖-0.2% |

**离线定义审计：**§5.1称MAR@k在固定100候选池测量，又报告MAR@100仅0.450。若把它理解成“池内含正例的普通Recall@100”，应为1。因此其命名、分母或聚合协议说明不足，不能直接把0.450当作全库召回45%，也不能用来横比别篇Recall@100。这里保留原数值及矛盾，迁移需从原实现补清定义；不影响将线上AB作为独立证据阅读。

线上§5.5披露按用户随机、按会员档位和活跃度分层，但没有公开实验天数、各组流量比例、留存观察窗口或数值置信区间。+2.1%限于作者定义的Premium retention，不应自行改称续费率或长期订阅收入；页面延迟+0.1%也不是P99延迟结果。

## 收益链路与我的判断

**监督链路：**曝光内偏好训练 → 共享语义空间转向实际跨角色需求 → 候选集包含更多职业上互补的人 → 相同ranker从更好集合选择 → profile CTR增加。无历史版本已有大部分离线提升，与“监督语义比更复杂history更关键”一致。

**动态链路：**近期点击对象向量进入用户表示 → 画像长期身份不变时仍可更新当前意图 → 适应求职/招聘/合作目标变化。聚合消融支持小幅增量，但不能将整个7.5%归于注意力结构。

**长期链路（推断）：**更有价值的profile访问可能加强曝光反馈和Premium使用价值，帮助留存。AB观察到留存改善，但没有把“互补匹配→访问→通知→留存”的每段中介单独识别。

## 关系与最小实验

与标准双塔是兼容替换，不需要把召回改成LLM在线生成；与互补推荐、曝光hard negative训练同类。与CC Retriever可互补：PAIR改向量召回的目标，CC在较大候选集合上加入pair特征。它不是证明“所有语义相似召回都应该废弃”。

- **假设A：偏好标签而非模型尺寸主导。**同0.6B模型比较通用embedding、随机负例微调、曝光负例微调；固定维度和候选池，补充全库检索指标。
- **假设B：互补意图确实是收益来源。**定义可审计的角色对，例如求职者—招聘者，分桶测覆盖、点击及成功互动；若只提高同角色高活跃用户曝光，应修正解释。
- **假设C：动态history有独立价值。**比较无history、均值、P-ATT，按意图切换用户分组；同时控制用户活跃度和新近数据，以免活跃用户选择偏差。
