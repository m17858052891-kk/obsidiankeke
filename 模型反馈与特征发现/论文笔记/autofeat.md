# The autofeat Python Library for Automated Feature Engineering and Selection

> [!summary] 为什么读这篇

**版本与发表状态：** ECML PKDD 2019；arXiv v4 2020  
**实际阅读范围：** 核心：全文§2；README+featsel.py  
**本研究定位：** 互补搜索与可微构造；补充阅读。未运行算法。

## 反馈怎样进入搜索

**反馈内容：** 线性模型系数/稳健选择反馈；候选构造主要规则驱动。

**搜索单位：** 表达式候选池→集合选择；先扩展后缩减。

**机制：** 先交替一元变换与二元组合扩展较大候选池，SymPy化简/Pint单位约束，再多轮子采样稀疏线性选择与noise filtering。

## 对两个关键问题的意义

**互补组合：** 较少依赖每一步构造必须立刻有收益，降低过早删中间项风险；仍受最大构造步数、相关性筛选和线性readout限制。

**跨模型或跨任务：** fit_transform可把结果交给其他模型是API能力，不能推出跨模型保持收益。

## 已核的验证与效果

**设置：** 本次研究读方法与实现，不引用未逐表核实的实验增益。

**结果：** §2.1例子：3原始变量扩展到约20→750→4000候选，说明组合爆炸；非算法普适复杂度常数。

以上保留论文实际设置。若只读摘要或定向段落，不从未读表格补写数值；作者报告与本研究是否复现是两件事。

## 局限与取舍

内存随枚举迅速增长；默认构造步数有限；预先生成操作字典限制。

**可以支持的判断：**

先扩展后筛选保护部分暂时无效中间项

**不能据此推出：**

穷举了无限表达式

所有互补组必然幸存
