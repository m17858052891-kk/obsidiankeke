# HyFormer 与 PEPNet 的实现问题及待验证取舍

| 问题 | 改法 |
|---|---|
| 1）第一层的 14 个静态输出 FFN（约 184.4 万个参数）计算结果被丢弃，收不到预测损失的梯度。 | 保持基础 HyFormer 结构时跳过首层这 14 个 FFN，把逐层传递更新后静态 token 的方案留作需要重训验证的架构实验。 |
| 2）计算损失前截断预测概率会产生零梯度区间，落入该区间的高置信度错判样本无法给对应任务头提供纠错梯度。 | 训练时按派单类型选出原始 logit，用 `BCEWithLogitsLoss(reduction="none")` 计算逐样本损失，推理时再用 `sigmoid` 输出概率。 |
| 3）三个任务头都用整批样本数作分母，导致各任务的实际权重随批内有效样本占比变化。 | 每个任务头只对自己的有效样本求平均损失，当批没有有效样本就跳过该头，再按设定的任务权重加总。 |
| 4）PEPNet 门控占全模型约 57.5% 的参数，这部分开销带来的预测收益还需验证。 | 先把 EPNet 门控的隐藏层从 2048 维缩到 256 维并保持输出维度，再根据各任务的 AUC、LogLoss 和推理 P99 延迟决定是否也缩窄 PPNet 门控。 |
| 5）161 个通用数值特征被压成一个 token，后续层只能用这份汇总表示与其他 token 交互。 | 把四个二值开关合成一个 token，腾出三个位置，将这 161 个特征按当前订单、实时供需、天气和历史统计拆成四个 token，保持总数为 16。 |

**第 1、2 项是仅凭当前代码即可确认的实现问题。** 第 1 项始终多算第一层 14 个无效静态输出 FFN，属于效率问题。第 2 项的损失函数确实存在零梯度区间，实际有多少训练样本落入其中仍需统计。第 3 项的任务权重是否合适取决于业务目标，第 4、5 项的效果与成本取舍需要对照实验。

基础 HyFormer 论文描述了 query 逐层更新、每层重新拼接非序列 token 的结构。第 1 项对应无效 FFN 计算，让静态 token 也逐层更新是一种可对照验证的架构改动。以下行号已按 2026 年 11 月 12 日 EVE 两个训练节点 `pytorch_learning_14506` 和 `pytorch_learning_02904` 的源码核对，两份 `hyformer.py` 相同。[HyFormer 论文第 3.3、3.6 节](https://arxiv.org/html/2601.12681)，[EVE 实验 15807](https://ether.intra.hongyibo.com.cn/labs/new/15807)

## 1 第一层静态输出 FFN 的计算结果被丢弃

### 现在传的是什么

静态特征先被编码成 14 个 token，记为 `S0`。每个 token 有 128 维。另外还有 1 个司机 query 和 1 个乘客 query，用来提取各自的历史信息。`HyFormerBlock.forward` 在 `hyformer.py:428` 将它们按「司机 query、乘客 query、14 个静态 token」的顺序交给 `QueryBoosting`。输出 `boosted` 的形状是 `[批大小, 16, 128]`。

| `boosted` 的位置 | 第一层产生的内容 | 当前第二层实际收到 | 接通静态 token 的实验分支收到 |
|---|---|---|---|
| 0 和 1 | 更新后的司机、乘客 query | 更新后的两个 query | 更新后的两个 query |
| 2 至 15 | 更新后的 14 个静态 token，记为 `S1` | 初始的 `S0` | 第一层的 `S1` |

外层循环从 `hyformer.py:547` 开始逐层调用 block。每次调用都会更新 `driver_query`、`passenger_query` 和 `boosted`，第 557 行传入的 `static_tokens` 始终指向 `S0`。第二层返回时，`boosted` 被第二层输出覆盖，第 563 行只将这次输出交给后续网络。

### 为什么恰好这 14 个前馈网络的梯度为 0

`QueryBoosting.forward` 先混合各 token 的通道，再在 `hyformer.py:319` 给每个输出位置使用各自的前馈网络（FFN）。在第一层，位置 2 至 15 的 14 个 FFN 各自只写入 `S1` 的一个位置。随后 `LayerNorm` 在每个 token 内沿 128 个通道计算，不会把这些位置的输出写回两个 query。

于是，任意改变这 14 个 FFN 的权重，只会改变 `S1`。当前第二层读取 `S0` 和两个更新后的 query，三个任务的预测和损失都不随这次改权重而变化，反向传播给这 14 个 FFN 的梯度就是 0。原始静态特征 `S0` 本身仍参与 query 生成和第二层计算。受影响的是第一层这 14 个 FFN，共 **1,843,968 个参数**。

### 保持基础结构时怎么处理

论文第 3.3 节说明更深层沿用上一层的 query，第 3.6 节把每层解码后的 query 与非序列 token 再拼接。由这两个描述推断，基础结构允许非序列 token 每层保持原输入。当前模型正是更新 query、重复使用 `S0`，所以这里的问题是第一层计算了随后被丢弃的静态输出。[HyFormer 论文第 3.3、3.6 节](https://arxiv.org/html/2601.12681)

如果保持这套结构，在第一层的 `QueryBoosting` 中仍把两个 query 和 14 个 `S0` 一起做通道重组，但只执行位置 0、1 的 FFN，并把更新后的两个 query 传给第二层。最后一层仍计算全部 16 个位置，因为其完整输出会进入预测头。删掉第一层 14 个 FFN 后，需在加载旧 checkpoint 时忽略这 14 组多出的权重，或者先按原模型加载，再裁剪已加载的分支。其余权重可以复用，预测函数不变。

### 可选实验：让静态 token 也逐层更新

如果要比较更新静态 token 是否带来收益，可在训练组件的 `hyformer.py` 中找到 `HyFormerEncoder.forward`，按原文件行号加两行。第一行放在第 546 行 `boosted = None` 后，计算 query 总数。第二行放在第 562 行 `block(...)` 后、循环内，更新下一层的 `static_tokens`。

### 接通静态 token 实验分支的合成样本检查

在本地源码副本应用上述补丁，用相同的随机初始化权重、4 条合成样本和 EVE 的三头掩码 BCE 做反向传播。测试关掉 dropout 以便逐项比较，保留梯度计算。

| 检查项 | 原实现 | 两行补丁后 |
|---|---:|---:|
| 第一层有非零任务梯度的静态 FFN | 0 / 14 | 14 / 14 |
| 第一层有非零任务梯度的 query FFN | 2 / 2 | 2 / 2 |
| 仅随机改写第一层 14 个静态 FFN 的权重，三个预测分数的最大绝对变化 | 0 | 0.01062 |

这个测试验证了层间传递和梯度，无法证明接通静态 token 会提高业务指标。旧 checkpoint 中这 14 组参数此前没有得到任务梯度。评估接通方案需要重新训练，并与保持基础结构的模型在同一留出集上逐头比较 AUC 和 LogLoss。

## 第 2 项与其余待验证的取舍

| 事项 | 当前模型的行为 | 具体建议 |
|---|---|---|
| **2 高置信度错判可能得到零梯度** | `model.py:143` 先做 `Sigmoid`，`loss.py:54` 再把概率截到 `[1e-6, 1-1e-6]`。实测标签为 1、logit 为 −20 时，当前损失对 logit 的梯度是 0。 | 训练时先按连环派或非连环派选出对应的 logit，再用 `BCEWithLogitsLoss(reduction="none")` 保留逐样本掩码。在同一例子中梯度约为 −1。推理输出概率时再做 `sigmoid`。 |
| **3 三个任务的有效权重随批次变化** | `main.py:688` 定义任务掩码。O 头仅在 `d_is_finish=1` 时学习，D 头仅在 `o_is_finish=1` 时学习，OD 头要求两者至少一个为 1。`loss.py:64` 把掩码后的损失除以整个批次大小。某头只有 1/8 样本有效时，其损失就是有效样本均值的 1/8。 | 如果希望任务权重由业务明确指定，每头先算 `sum(mask × loss) / max(1, sum(mask))`，再乘任务权重。分别在各头对应的人群上解读其概率。 |
| **4 门控占全模型 57.5% 的参数** | `model.py:233` 将 16 个 128 维 token 对应的表示展平为 2048 维。EPNet 门控有 8,433,664 个参数，三套 PPNet 门控合计 41,608,704 个。全模型共 87,041,266 个参数。 | 固定 HyFormer 和任务头，比较原门控与使用较窄隐藏层的门控。记录各任务 AUC、LogLoss，以及目标硬件和线上批量下的 P99 延迟。 |
| **5 161 个通用数值特征只占 1 个 token** | `hyformer.py:227` 将 161 列通用数值作为一组，经一个 MLP 压为单个 token。组内关系由这个 MLP 学习，后续 token 交互只看到一份汇总。10 个离散字段则各有一个 token。 | 可合并部分二值开关，腾出位置分别表达当前订单、实时供需和历史统计。首轮保持总数为 16，满足当前 `QueryBoosting` 对 128 维通道的整除要求。 |
