# EVE 非序列特征的数值变换与分桶

## 为什么按字段选择变换

EVE 对 255 个静态数值输入先减基准，再**直接除以配置的尺度**，最后截到 `[0, 1]`。`main.py:410` 原样读取 `config.yaml` 的 `scale_numeric`。`model.py:187` 的除法和下一行的截断合起来是 `clip((x - base_numeric) / (scale_numeric + 1e-6), 0, 1)`。线上可以复用随模型保存的这组参数。[EVE 实验 15807](https://ether.intra.hongyibo.com.cn/labs/new/15807)

**与标准 Min–Max 的区别在分母。** 标准 Min–Max 用训练集极差 `max - min`。项目同事说明，配置中的“max”由训练集统计后填入。在 `base_numeric=min` 的前提下，若 `scale_numeric` 填的是这个 `max`，当前除法就是 `(x - min) / (max + 1e-6)`。若填的是预先算好的极差，同一段代码就实现了带截断的 Min–Max。EVE 训练入口只加载这两组常量，每列是否取了原始训练样本的绝对极值，还需以生成配置时的统计逻辑为准。

- **起点经度 `flng`** 的 `base=101.51`、`scale=126.64`。输入 `126.64`，实际缩放结果是 **0.1984**。若把这两个数当作最小值和最大值，标准 Min–Max 会得到 **1**。若 `101.51°` 是最小经度，把 `126.64°` 当极差会推出 `228.15°` 的上界，超出常用经度范围。
- **起点温度 `coord_start_temperature`** 的 `base=-8.93`、`scale=26.77`。按现公式，到达上限 1 的输入约为 `base + scale = 17.84`。输入 `20` 和 `25`，结果都是 **1**。
- **起点近 5 分钟订单数 `coord_last_5min_start_order_cnt_kf`** 的 `base=0`、`scale=29`。此时按上界或按极差计算，分母数值相同。假设两次请求分别有 60 单和 100 单，当前截断后都得到 **1**。

| 首轮处理 | 适用字段 | 选择理由 |
|---|---|---|
| `log1p`，140 列 | 区域供需量、司机多日接单和完单数、历史距离和时长统计 | 统一单位后，直接对每个非负值计算 `ln(1+x)`，无需估计训练集最大值。上例的 60 单和 100 单分别得到 4.11 和 4.62，既保留大小差异，也减弱极大值对输入幅度的影响。 |
| 非均匀分桶，70 列 | 乘客取消次数、司机短窗拒单次数、当次接驾距离、等待时间和 ETA | 小计数可以分清 0 次、首次和重复发生。等待和距离可在近端分得更细。同桶内的小幅波动得到相同表示，代价是丢失桶内差异，跨过边界时表示会跳变。 |
| 原值或固定单位换算，36 列 | 有明确分母的比率、温度、湿度、经纬度等 | 量纲本身有意义。例如完成率确认采用百分制时，除以 100 即可，同时区分零分母和真实的 0%。 |

**当前订单的四列经纬度无需按训练集做 Min–Max。** `flat/flng` 是起点，`tlat/tlng` 是终点，它们与其他数值一起进入静态 MLP。新模型可以直接用原始度数，也可以用固定范围缩放。我建议重训时先试纬度除以 90、经度除以 180，替换这四列的旧缩放。这样输入落在 `[-1, 1]`，量级更接近其他特征，也不用按训练日期重算极值。是否提升预测效果，可与原始度数在同一留出集上比较。

**已有 checkpoint 的接口传原始度数。** 模型内部会再减去纬度基准 21.47、经度基准 101.51。如果上游先除以 90 或 180，传进来的四个数都小于各自的基准，旧模型会把它们全部截成 0。司机和乘客的历史坐标走 GeoHash，这一路也直接传原始度数，编码器据此确定地理网格。

另有 1 列天气状态码适合按类别编码，8 列要先确认含义，包括两个 PK／举手时间字段和六个 `driver_online_*_cnt`、`driver_charging_*_cnt` 字段。如果近一小时的值表示累计秒数，除以 3600 就是该状态的时间占比。

**线上仍要监控分布变化。** 如果高峰期大量请求挤进等待时间的末桶，等了 10 分钟和 30 分钟的请求就会得到相同表示。可按城市、时段跟踪末桶占比，升高时回看对应任务的预测效果。

## 非均匀分桶怎么做

**先定单位和缺失规则。** 从旧模型缩放前的值开始。缺失单独成桶，有业务意义的真实 0 单独成桶。若上游把缺失填成了 0，需要同时传缺失标记。

| 字段 | 第一版候选切点 | 业务含义 |
|---|---|---|
| `passenger_ziying_answered_pas_cancel_cnt_7d` | 按整数分为 `0 / 1 / 2 / 3–4 / 5–7 / 8–15 / 16+` | 保留前几次取消的差异，高次数合并。 |
| `order_waiting_period` | 确认单位为秒后，正值切在 `15、30、60、120、180、300、600` | 前一分钟细分，十分钟以上进入末桶。 |
| `lumian_dis`、`dropoff_order_distance` | 确认单位为米后，正值切在 `250、500、1000、2000、3000、5000、8000` | 取数 SQL 已将超过 8000 的值截到 8000，末桶包含等于和超过上限的全部样本。 |

**用训练期定稿。** 上表是待验证的业务切点。缺少明确业务阈值时，可在训练期有效正值上取 P10、P25、P50、P75、P90、P95、P99，去除重复点。逐桶查看样本数和对应任务的标签数，样本不足时合并相邻桶。用相同新特征重训现有缩放和分字段方案。若核实现有分母是训练集 `max`，再加一组按 `max - min` 缩放的基线，在同一后续时段比较 AUC 和 LogLoss，区分改分母与改编码各自的收益。当前 SQL 只保留约一半司机拒单，线上桶占比用未抽样流量核对。

**线上按字段查桶。** 对表中连续量，缺失取 ID 0，真实零取 ID 1。正值的桶 ID 等于 `2 + 小于等于当前值的切点数`，所以恰好等于切点时进入右桶。等待 29 秒落在 `[15, 30)`，ID 为 3。等待 30 秒落在 `[30, 60)`，ID 为 4。桶 ID 接该字段的 embedding 或 one-hot。

重训时，对选中字段替换原有缩放。司机近期特征同时进入 HyFormer 静态输入和 PPNet 门控，两条路径要用同一套编码规则。把单位、缺失规则和切点随新 checkpoint 发布，线上每条请求直接查同一份配置。
