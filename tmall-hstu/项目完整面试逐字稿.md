## 1. 三分钟完整项目逐字稿

>
   这个项目想解决的是大规模商品推荐中的两个问题。第一，商品数量很大，如果直接把 Item ID 作为分类标签，输出空间会随着商品数增长，计算和参数规模都比较大。第二，原始 Item ID 只是一个索引，没有商品之间的语义结构，模型不能自然地利用相似商品之间的共享信息。
>
> 我的整体思路是先学习商品的协同表示，再把连续表示离散化成 Semantic ID，最后让序列模型生成 Semantic ID。具体来说，我先按照用户的行为时间对日志排序，在用户行为序列中构造局部 item-item 共现关系。不同的行为类型、行为之间的时间间隔、序列位置距离以及用户活跃度会影响共现关系的强弱，所以我给共现边加入行为权重、时间衰减、位置衰减和用户活跃度惩罚，形成稀疏的加权共现样本。
>
> 然后我用 Weighted Item2Vec 学习商品 embedding。它的输入不是完整的稠密共现矩阵，而是带权的中心商品和正样本商品对，同时通过负采样构造负样本。训练目标是让共现强的商品向量更接近，让负样本向量更远。训练完成后，每个商品都有一个连续的协同向量。
>
> 接下来，我把商品协同向量输入 RQ-VAE 的残差量化自编码器。Encoder 先把商品向量映射到 latent 空间，然后用多个 codebook 对 latent 的残差逐级量化：第一级表达比较粗的语义，后面的级别逐步补充前面没有表达的细节，最后由 Decoder 重构原始商品向量。由于不同商品可能被量化成相同的基础 code，我再对冲突组追加 collision token，形成能够唯一映射回商品的完整 Semantic ID。
>
> 在序列建模阶段，我先把用户历史中的每个商品替换成它的 Semantic ID，并保持行为发生的时间顺序。对于每个历史事件，我把 SID code embedding、行为类型 embedding 和时间间隔 embedding 融合起来，再输入 HSTU-style 序列编码器。HSTU 部分参考了 Q、K、V、U、pointwise activation、门控残差以及相对位置和时间偏置，用来建模用户近期行为、长期行为和不同类型行为之间的关系。
>
> 训练目标是预测用户下一个商品的完整 SID。由于一个商品由多个 code 组成，我采用 Teacher Forcing：预测后一级 code 时输入前一级真实的 code，并对每一级 code 的输出计算交叉熵，再将各级损失加权求和。这样就把原本在百万级 Item 空间的一次性分类，转成了多个较小 code 空间中的自回归生成。
>
> 推理时模型没有真实前缀可用，所以我先根据商品库中所有有效 SID 建立前缀索引，只允许 Beam Search 沿着存在于索引中的合法前缀扩展。生成完整 SID 后，再通过 SID-to-Item 映射还原成商品，并做去重、过滤用户已经交互过的商品，以及库存和上下架等业务过滤。前缀约束可以保证生成的 SID 在结构上能映射到已登记商品，但不等于推荐质量一定正确，也不自动解决库存和业务约束。
>
> 这个项目的核心不是简单地替换一个序列模型，而是把协同过滤信号、连续商品表示、离散 Semantic ID、用户多行为序列和结构化生成连接起来。


## 3. 四种行为序列怎么融合：面试逐字稿

> 这四种行为在当前项目中不是完全独立训练四个推荐模型，而是先按照时间统一放回同一个用户行为流中。对每个用户，我把 click、collect、cart、purchase 都看成带有行为类型标签的事件，并按照时间排序形成一条统一序列。每个事件保留商品的 SID，同时加入对应的行为类型 embedding；因此相同商品发生 click 和 purchase 时，商品 SID 可以相同，但行为 embedding 不同，模型能够区分行为意图。之后再通过 HSTU 的序列交互和时间偏置，让模型学习不同类型行为之间的转化关系，比如浏览之后收藏、收藏之后加购、加购之后购买。这样做的好处是保留了完整的行为顺序和跨行为转化信号，而不是把不同动作简单计数后丢失时序信息。

如果面试官问“为什么不拆成四路序列”，可以回答：

> 四路序列也可以做，适合分别建模浏览兴趣、收藏兴趣、加购意图和购买偏好，再用 Cross-Attention、门控或 pooling 做融合。但当前项目采用一条统一的事件序列，主要原因是行为本身具有自然时间顺序，统一序列更容易直接建模行为之间的转化过程，也能控制模型和数据管道的复杂度。为了避免不同事件混在一起，我通过行为类型 embedding、事件边界信息和相对时间偏置保留行为类型与时序信息。

如果面试官问“行为权重和行为 embedding 是不是一回事”，可以回答：

> 不是一回事。加权共现阶段的行为权重主要用于构造 Item2Vec 的训练信号，例如购买共现可以比点击共现贡献更大的 pair weight；序列模型阶段的行为 embedding 则作为输入特征，让 HSTU 区分当前事件是点击、收藏、加购还是购买。前者影响商品协同向量怎么学，后者影响用户序列兴趣怎么建模。

## 4. RQ-VAE 面试逐字稿

> RQ-VAE 的输入是 Item2Vec 学到的连续商品协同向量。Encoder 先把它映射到 latent 空间，随后使用多个 codebook 对 latent 的残差逐级量化，第一级表示主要语义，后续级别逐步补充量化误差，最终多个 code 组合成 Semantic ID。量化向量再经过 Decoder 重构原始 Item2Vec 向量，训练时优化重构损失、codebook loss 和 commitment loss。当前实现是确定性的 RQ-VAE 风格残差量化自编码器，不包含标准 VAE 的高斯后验、随机采样和 KL loss。

如果被问“为什么用残差”，可以回答：

> 如果只做单级量化，一个商品只能选择一个 code，codebook 容量和商品冲突率之间会有直接矛盾。残差量化让不同层的 code 逐步表达粗粒度到细粒度的信息，多个较小 codebook 的组合可以形成更大的地址空间，同时每一级仍然可以作为一个小分类空间被生成。它还保留了从连续 embedding 到离散 SID 的重构目标，因此比随机编码更能保留商品协同结构。


## 5. 行为序列转换成 SID：五句话逐字稿

> 我先按用户和时间对原始行为日志排序，每个事件保留商品、行为类型和时间戳。然后通过离线的 `item_id → SID` 映射，将每个商品替换成多级 Semantic ID，并按原顺序展开成 SID token 序列。对于同一商品的 SID code，我叠加对应的 click、collect、cart、purchase 行为 embedding，以及按时间差 bucket 查表得到的时间 embedding。这样模型既知道用户看过什么商品，也知道用户对商品做了什么行为以及行为之间隔了多久。最终得到的序列 embedding 输入 HSTU，并通过相对位置和时间偏置进一步建模行为间的时序关系。

## 6. Teacher Forcing 和多级交叉熵逐字稿

> 我把一个商品的 Semantic ID 看成一个短序列，而不是一个单独类别。例如一个商品可以表示成三个量化 code 和一个 collision token。训练时采用 Teacher Forcing，预测当前 code 时输入前面真实的 code，并对每一级 SID code 的输出计算交叉熵，再将各级损失加权求和。这里的交叉熵加在 HSTU 或解码器的 SID 输出头上，不是加在 RQ-VAE 的 codebook 中。它的作用是让模型学习用户历史到各级 SID 的条件概率，从而把百万级 Item 分类分解为多个较小词表上的自回归生成。

如果被问“为什么要加交叉熵”，可以回答：

> 每一级 code 都是一个离散分类目标，如果没有对应的交叉熵监督，模型没有办法直接学习该级 code 的条件概率。多级交叉熵能够分别约束第一级、第二级和后续 code 的预测，使模型学会从粗到细生成完整 SID；同时输出的 log probability 可以在 Beam Search 中逐级累加，用于比较不同商品路径。它不负责训练 RQ-VAE，也不负责保证生成的 SID 一定存在，这两件事分别由量化器和前缀约束完成。

## 7. SID 前缀索引与约束 Beam Search 逐字稿

> 多级 code 的笛卡尔积中，大量组合并不对应真实商品，所以我先根据商品库中所有完整 SID 建立前缀索引。索引记录每个已有前缀允许的下一步 token，解码时每一步只从这些合法下一跳中扩展，而不是从完整词表随便生成。Beam Search 会保留多条候选前缀，累加每一步的 log probability，并在最终得到完整 SID 后映射回商品。只要有效 SID 表完整、前缀索引正确、解码严格遵守索引，就可以保证生成的 SID 能映射到已登记商品，结构映射合法率理论上是 100%。但这不等于推荐质量 100%，库存、上下架、地域、用户已看过滤和新商品覆盖还需要后处理或回退策略。

如果被问“为什么不用 Greedy”，可以回答：

> Greedy 每一步只保留局部概率最高的 code，局部最优不一定形成整体概率最高的完整 SID，也可能走到没有合法后缀的路径。Beam Search 保留多条前缀，既能在合法空间中继续搜索，也能降低早期单次预测错误对最终结果的影响。

## 8. HSTU 部分怎么讲

> HSTU 部分我会比较谨慎地称为 HSTU 序列编码器。它接收融合了 SID、行为类型和时间信息的用户历史序列，参考 HSTU 的 Q、K、V、U 投影、pointwise activation、门控残差以及相对位置和时间偏置来建模行为之间的交互。Q 和 K 用于计算历史事件之间的关联，V 负责传递信息，U 用于控制当前位置接收多少更新；相对位置和时间偏置让模型能够区分近期行为和较远行为。训练时使用 causal mask 防止看到未来，输出隐藏状态再接 SID 的多级分类头进行自回归预测。

## 10. 最后一段总结

> 这个项目的核心是把大规模 Item 推荐改写成结构化 Semantic ID 生成。前面用加权共现和 Weighted Item2Vec 学习商品协同表示，中间用 RQ-VAE 风格残差量化生成多级 SID，后面把用户多行为历史融合成带 SID、行为类型和时间信息的序列，用 HSTU-style 模型通过 Teacher Forcing 和多级交叉熵生成下一个 SID，最后用前缀约束 Beam Search 把生成空间限制在可映射商品集合内。这样各模块的分工很清楚：Item2Vec 学商品关系，RQ-VAE 学商品编码，HSTU 学用户兴趣变化，交叉熵学 SID 生成概率，前缀约束保证结构合法。
