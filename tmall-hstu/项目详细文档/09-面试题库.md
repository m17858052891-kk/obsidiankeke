# 09 面试题库

## A. 项目总览类

### Q1：请介绍一下这个项目

**参考回答：**

我在天池 Tmall 行为日志上实现了一个生成式推荐原型。针对商品数量大、直接 item 分类输出空间过大的问题，我先按行为类型、时间距离、行为位置和用户活跃度构造稀疏 item-item 加权共现图，再用 Weighted Item2Vec 学习协同 item embedding。接着使用 RQ-VAE 风格的残差量化，将每个 item 编码为 3 级 code，并用 collision token 处理冲突。推荐阶段把用户历史 SID、行为和时间特征输入 HSTU-style 序列编码器，通过 teacher forcing 逐级预测目标 SID，推理时使用 prefix-constrained beam search 生成合法商品候选。评估上会和 ItemCF、item-ID 序列模型、metadata SID 等 baseline 比较，并同时关注 HR/NDCG、coverage、diversity 和 SID collision rate。

### Q2：这个项目最核心的难点是什么？

有三个难点：第一，13 亿行原始日志不能直接做稠密共现，需要稀疏化和分片；第二，如何把 item embedding 变成既有压缩能力又可生成的多级 SID，需要处理 codebook collapse 和 collision；第三，多级 SID 的生成空间中大量组合无效，需要用前缀约束 beam search 保证生成结果可以映射回真实商品。

### Q3：为什么叫生成式推荐？

因为模型不是在固定候选集上只输出一个 item 分类分数，而是自回归地产生商品的结构化 SID token 序列，再将 token 序列映射回 item。它和语言模型生成 token 的形式相似，但 token 不是词，而是商品的离散 Semantic ID；因此不能直接说它是 LLM。

## B. 数据与样本

### Q5：为什么用下一个行为作为标签？

下一个行为预测与用户实时推荐场景一致，能保持时间因果顺序；随机抽样历史 item 会破坏时序并造成未来信息泄漏。若要预测购买而不是任意行为，应进一步构造购买目标、行为间隔和多任务标签。

### Q6：click、collect、cart、purchase 怎么处理？

作为两类信号处理：一类是输入特征，用 behavior embedding 区分行为类型；另一类是共现权重，购买和加购给予更高权重。这个权重表示建模先验，不等于严格的用户因果偏好强度，需要通过消融和验证集确定。

### Q7：如何避免时间泄漏？

用户序列严格按时间排序，target 在 history 之后；训练期的共现图、Item2Vec 和 SID tokenizer 不能使用验证/测试未来数据。正式实验会采用 temporal OOT split，并对 SID 版本按训练时间窗口生成。

### Q8：为什么不能全量 pandas 读取？

13 亿行会远超普通机器内存，而且中间 pair 数量还会进一步膨胀。应该列裁剪、类型压缩、按用户/时间分片处理，先聚合成可训练序列或稀疏 pair，再保存 Parquet 等列式中间产物。

## C. 共现与 Item2Vec

### Q9：共现窗口为什么不是越大越好？

窗口越大，pair 数和计算量增加，远距离行为的语义相关性也可能下降。短窗口更偏短期兴趣，长窗口可能混入多个兴趣主题。需要通过窗口消融、时间衰减和用户序列长度分析选择折中。

### Q10：为什么给不同 Action 加权？

同一个 item 被点击和被购买，意图强度通常不同。如果全部计为 1，会丢失行为质量信息。但权重可能放大噪声或热门商品，所以要做无权重、不同权重和 purchase-only 等对照。

### Q11：为什么要惩罚超活跃用户？

超活跃用户产生的 pair 数更多，可能让共现图被少数用户主导。用 `1/log(1+sequence_length)` 做温和归一化可以缓解这个问题；更严格的做法还可以按用户采样固定数量行为或使用 TF-IDF/BM25 风格权重。

### Q12：为什么不用 dense 共现矩阵？

商品数为 `N` 时 dense 矩阵是 `O(N²)`，百万商品无法承受。实际只保留观察到的边和每个 item 的 top-N 邻居，使用稀疏字典、分片聚合或图存储。

### Q13：ItemCF 和 Item2Vec 有什么区别？

ItemCF 直接使用共现分做邻居召回，解释性强、训练简单；Item2Vec 通过正负 pair 学习低维 embedding，可以继续供 RQ-VAE 量化、相似度计算和神经模型使用。两者都利用协同信号，但一个直接打分，一个学习参数化表示。

### Q14：负样本如何采样？

当前是均匀负样本和热门池负样本混合。均匀采样覆盖长尾，热门池采样提高区分难度。改进时应排除已知正样本，控制热门采样概率，并增加同类目 hard negative；否则会有 false negative 和 popularity bias。

### Q15：为什么使用 SparseAdam？

Item2Vec 的 embedding table 很大，但每个 batch 只访问少量 item。稀疏 embedding 只更新被访问的行，SparseAdam 避免 dense optimizer state 和 dense 梯度更新，节省内存。

## D. RQ-VAE 与 SID

### Q16：RQ-VAE 如何生成 SID？

先由 encoder 得到 item embedding `z`，第一级 codebook 找到最接近的 code，计算残差；第二级再量化残差，重复多级。最终把每一级 code 的索引拼起来，形成 SID。decoder 用量化向量重构 `z`，通过 reconstruction、codebook 和 commitment loss 训练。

### Q17：为什么用多级 code，而不是一个大 codebook？

一个大 codebook 的参数和学习难度都高；多级残差量化可以用小 codebook 的组合表达更大的地址空间，并让前缀具有一定的粗到细结构。代价是解码器更复杂，需要处理无效组合和 collision。

### Q18：codebook collapse 怎么看？

统计每一级 code 的使用数量、使用熵、top code 占比和残差范数。如果绝大多数 item 使用少数 code，说明 collapse。可以用 EMA 更新、dead-code replacement、均衡采样或调整 commitment 权重。

### Q19：为什么要 collision token？

有限 codebook 下不同 item 可能量化到相同的前三级 code。如果不额外区分，它们会共享同一个地址，无法一一映射回 item。collision token 是地址消歧机制，但碰撞率过高说明 codebook/embedding/量化层级需要优化。

### Q20：Semantic ID 一定是语义相似吗？

不一定。SID 的“语义”取决于输入 embedding。如果 embedding 来自 Item2Vec，它主要编码协同和行为相似；如果融合标题、类目、图像，才会增加内容语义。当前项目应称为 collaborative Semantic ID 更准确。

### Q21：为什么不直接用 itemCF 共现矩阵训练 SID？

共现矩阵本身是高维稀疏关系，不是适合逐级生成的离散 code。项目先用它学习连续 embedding，再量化为 SID。这样可以让共现信号进入 item 表征，同时保留 codebook 的压缩和组合表达能力。

## E. HSTU 与序列建模

### Q22：HSTU-style block 和 Transformer 的区别是什么？

项目参考 HSTU 的 Q/K/V/U 交互、pointwise SiLU 和 gated residual 思路。它不使用传统 Softmax 注意力和标准 FFN 的完全相同结构，并显式加入相对位置/时间偏置，更偏向推荐行为序列。当前是简化原型，不声称与官方实现逐算子一致。

### Q23：为什么加入时间偏置？

用户兴趣有新鲜度和周期性。两个行为的相对位置和时间差比绝对位置更有解释力。时间 bucket embedding 可以让模型学习近期行为权重大、长期兴趣仍保留等模式。

### Q24：历史序列为什么要同时放 SID、行为和时间？

SID 提供商品身份和协同结构，行为 token 表示意图强度，时间 token 表示新鲜度和周期。三者相加或融合后，模型才能区分“同一个商品被点击”和“同一个商品被购买”。

### Q25：序列越长效果越好吗？

不一定。过长历史含有多个兴趣主题和噪声，且自注意力成本近似随长度平方增长。当前做序列长度消融；进一步可以做兴趣聚类、长期/短期双塔或局部 attention。

## F. 生成和评估

### Q26：为什么用 teacher forcing？

它能在训练早期提供正确 prefix，优化稳定，且每个 code level 都能获得明确监督。缺点是训练和推理 prefix 分布不同，产生 exposure bias。后续可以加入 scheduled sampling 或 sequence-level loss。

### Q27：为什么用 beam search？

greedy 只保留局部最大概率，早期选择错误会导致后续没有好路径。beam 保留多个 prefix，能提高整体序列概率和有效候选率；但推理成本随 beam size 和分支数增加，需要前缀树和 top-k 控制。

### Q28：prefix constraint 解决什么问题？

多级 code 的笛卡尔积中大部分组合不对应真实商品。前缀约束只允许生成 SID 表中存在的下一跳，保证完整 code 可以映射回商品，并减少无效生成。

### Q29：为什么同时看 HR、NDCG、coverage？

HR 看是否命中，NDCG 看命中位置，coverage 看是否只推荐少数热门商品。生成式推荐尤其需要关注 coverage、长尾召回、invalid SID 和 collision，因为单独的 HR 可能掩盖候选空间退化。

### Q30：baseline 怎样保证公平？

共享用户切分、历史长度、target 定义、seen filter 和 top-K 评估逻辑；只替换待比较的模块。例如比较 Semantic ID 时，item-ID HSTU 和 SID HSTU 应尽量保持相近的 encoder 深度、训练步数和候选后处理。
