# 07 评估与实验设计

## 核心指标

- `HR@K`：真实下一商品是否出现在 Top-K；
- `NDCG@K`：命中位置越靠前得分越高；
- `Coverage@K`：推荐列表覆盖的不同商品比例；
- `Tail Recall`：长尾商品分桶后的召回；
- `Diversity`：列表内类目或商品相似度多样性；
- `Invalid SID Rate`：无法映射到登记商品的生成比例；
- `Collision Rate`：基础 SID 冲突比例；
- `Code Usage`：各级 code 使用数和熵；
- `Latency`：解码时间、beam 分支数和过滤后候选数量。

不能只看 HR：HR 上升但 Coverage 和 Tail Recall 下降，可能只是更强地推荐热门商品。

## Baseline

至少比较 Popularity、ItemCF、item-ID HSTU/Transformer、metadata/category SID + HSTU、collaborative SID + HSTU。各模型共享时间切分、历史长度、target 定义、seen filter 和 Top-K 评估逻辑。

## Ablation

建议逐项移除行为权重、时间衰减、活跃度惩罚、Item2Vec、残差级别、collision token、行为 embedding、时间 bias、HSTU-style block、prefix constraint 和 Beam Search，每次只改一个模块。

## 数据切分和结果解释

正式实验优先使用 temporal/OOT split，且共现、Item2Vec、SID tokenizer 遵守训练时间边界。按热门/中频/长尾、短/长历史、新老用户报告分桶结果，并报告 target SID 覆盖率、过滤前后候选数和多次随机种子的均值/方差。生成式推荐需要同时回答命中、排序、覆盖和结构合法四个问题。
